## 3. 新发现并已修复的 P0 / P1（定位链）

全部在 `onboard/dzpx4_patch/px4_odom_convert.cpp` / `.hpp`。
每一条都是**读了实际代码确认的**，不是照摘要下的结论。

### P0-A：一帧 NaN 永久废掉 37~62 m 跳变防护，且 `quality` 仍报 100

jump guard 两级判据都是 `gate_dp > 阈值` 的形式。C++ 里 **`NaN > x` 恒为 false**，
所以一帧 NaN 位姿：

- 不算 L1 疯跳，也不算 L2 大位移
- 一路落到最后的 `else` 分支，被写进 `gate_prev_pos_` / `gate_out_pos_`
- 此后每次 `norm()` 都是 NaN，两级比较**永远为假**

结果：你实测过 37~62 m / 9.11 m 跳变才建起来的防护**静默失效**，而
`vio.quality` 仍然写着 **100**。飞控看到的是"高质量视觉里程计"。

**修法**：在**碰任何 guard 状态之前**加有限性门，非有限就整帧丢弃 + 计数 + 告警：

```cpp
if (!std::isfinite(p.x) || !std::isfinite(p.y) || !std::isfinite(p.z)) {
  ++total_nonfinite_drops_;
  RCLCPP_ERROR_THROTTLE(..., "SLAM pose non-finite (...) - frame dropped, "
    "jump-guard state untouched (drops=%d)", ...);
  return;
}
```

四元数同样处理（`q_norm` 非有限或 < 0.5 判退化），协方差也加了
`std::isfinite(slam_cov_trace)` 前置。计数进健康行 `nan_drop=`，**非零即上游
FAST-LIO 在吐 NaN，这是比跳变更早的告警信号**。

### P0-B：`enable_auto_align:=false` 会静默删掉两层安全防护

`sub_status_` 和 `sub_local_pos_` 两个订阅原先都裹在 `if (enable_auto_align_)` 里。
但它们是**安全件，不是自动对齐功能的附件**：

- `sub_status_` → `fcu_armed_`：armed 时 jump guard 永不接受大位移
- `sub_local_pos_` → `ekf_pos_ned_.z()`：z 换源，隔离 SLAM z 的 5.56/8.9 m 漂移

把一个听名字只关乎"要不要对齐航向"的参数设成 `false`，会连带删掉这两层，
而且 `fcu_armed_` **永远停在初始值 false**。

**修法**：两个订阅无条件创建（提到 `if` 外面），`else` 分支日志改成
`"Auto-align disabled: fixed ENU rotation only (armed gate + z-source isolation remain active)"`。

### P0-C：z 换源判据用错标志位，SLAM z 漂移实际进了飞控

原代码用 `ekf_pos_valid_` 判断是否可以用 EKF z 替换 SLAM z。但
`ekf_pos_valid_` 是"**最新一帧** EKF 是否有效"的单帧标志，每帧被覆盖。
EKF 一帧无效就回落到 SLAM z —— 于是代码里那句"SLAM z 漂移不再影响飞控"的注释
**在这些路径上是假的**，5.56 m / 8.9 m 顺着 `vio.position[2]` 直接进飞控。

**修法**：新增 `ever_had_ekf_z_`（一旦拿到过有效 EKF z 就置位，不再回落），
判据改用它；从未拿到过时发节流 WARN 明说"高度隔离未生效"，
并进健康行 `z_src=`。**降级可以，但不许静默。**

### P1-A：墙钟回跳会让 L2/L3 永久锁死

三处 `const double now_s = this->now().seconds();` 走的是节点时钟，默认
`RCL_SYSTEM_TIME` = **系统墙钟**。墙钟会往回拨（NTP 校时、手工改时间、机载无 NTP
时开机后首次同步）。一旦回拨，所有 `now_s - t0 > 窗口` 形式的判据**永远为假**：

- `reset_times_` 永不裁剪 → `ekf_storm_` **永久冻结重锚**（L3 锁死）
- `bump_ok` 永不为真 → **L2 重锚节流永久不放行**

两者叠加 = jump guard 在飞行中彻底不可恢复，正是它要防的那种事故。

**修法**：新增 `steadyNowS()`（`std::chrono::steady_clock`，单调），三处算时长的
地方全部换用；黑匣子/健康行里**给人看的** `t=` 仍用墙钟（数值要对应真实时刻）。
`l1_age` / `bump_age` / `storm_age` 三个年龄量改用单调钟。

> 换之前确认过：`localization_watchdog.py` 的 staleness 是用**它自己的墙钟**算的，
> 不依赖健康行的 `t=`；也明确不依赖 `position delta` 行。所以本次两处改动都安全。

### P1-B：`arming_state == 4`（ARMED_ERROR）没算作 armed

原代码只判 `== 2`（ARMED）。但 **ARMED_ERROR 状态下电机仍可能转**。

**修法**：`fcu_armed_ = (msg->arming_state == 2 || msg->arming_state == 4);`

### P1-C：Eigen `toRotationMatrix()` 不归一化四元数

退化/未归一化四元数直接进旋转矩阵会放大成姿态误差。
**修法**：`q_slam.normalize();` 前置（并配合 P0-A 的 `q_norm < 0.5` 退化门）。

### P1-D：`int32 sec` → `uint64_t` 负值回绕

时间戳未设置/为负时强转 `uint64_t` 会回绕成一个巨大值。
**修法**：`if (odom.header.stamp.sec > 0)` 才走原式，否则节流 WARN +
`vio.timestamp_sample = vio.timestamp` 兜底。

### P1-E：43 Hz 热路径上每帧 `std::endl` 刷盘

`std::endl` 会 flush。43 Hz 每帧一次阻塞 flush 在回调里是隐患。
**修法**：`position delta` 行改成 0.5 s 节流 + `'\n'`（确认过 watchdog 不解析此行）。

### 健康行新增可观测项

`nan_drop=` / `z_src=` / `armed=` 三个键，让上面三类降级**在现场能被看见**，
而不是等炸了回头翻日志。
