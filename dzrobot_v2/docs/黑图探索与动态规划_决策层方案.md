```

                    │                      field_verify{+coverage} / target_zone│

   ┌─────────────────────────── 车侧 dzbrain ─────────────────────────────────┐

   │ ② 台账层 IntelLedger(新)  逐格状态机 UNKNOWN→ABSENT/MINE/OBS/TARGET       │
```

**分层铁律（与现有设计一致，不许破）**：
1. **B 通道永远不是完赛必要条件**：无人机全哑 ⇒ 车按 `cross_*_default`（现役 `K9`/`K5`）+ `route.tokens` 完赛（`空地指挥链路_协议与运行手册.md` §7）。

3. **台账不改地图文件**：Ledger 是**运行时对象**；写回 `config/map.yaml` 只允许赛前（t4 §6.4 ②）。

### 4.2 逐片报告的报文（additive，车侧未知键安全）

```json
{"type":"field_verify",
 "mines":["C1","A3"], "obstacles":["A1"], "targets":["E5","F5"],
 "coverage":{"cells":["C1","C2","C3","B1"],"complete":true,"mode":"strip"},
 "slice":{"id":"S1","index":1,"of":7,"route":"N8>M8>L8>K8"},
 "scan_id":"20261017T0930_a1b2c3","confidence":{"C1":0.82},
 "ts":1792331234.5,"seq":7}
```

- **兼容性**：`drone.py` 只读 `type/mines/obstacles/blocks/seq/half`，新增键**不报错**（`drone.py:236-240` 未知 type 只记日志；字段读取是 `payload.get`）。
- **`complete` 语义（关键，不许含糊）**：`complete:true` = **这片的 `coverage.cells` 已被判读完毕**，其中未出现的要素视为 **ABSENT**；`complete:false` = 只报看得见的，**其余仍是 UNKNOWN**（不得当 ABSENT）。
- **`targets` 进 `field_verify`**：现役 `target_zone` 是独立 type，为了「一片一报文」建议合并到 `field_verify`（可选项，需队长裁 R3）。

### 4.3 「U 形」到底指谁（避免歧义）

- **U 形 = 无人机的俯瞰航线**（起飞列 → 西扫 → 竖穿 → 东扫 → 降落，`docs/无人机拟真与动态规划_方案.md` §1.2）。
- **车不负责探索**：车按已确认情报循迹（车端 MINE/障碍感知是另一条线，属 `tasks/safety.py`，本方案不涉及）。
- ⇒ 「黑图探索」= **无人机把图点亮 → 车把点亮的图变成路线**。车自己不做视觉探索。

## 5. 情报台账（Intel Ledger）与锁存

### 5.1 逐格状态机（14×11 = 154 格）

```
UNKNOWN ──(片内 complete 且未报)──▶ ABSENT      ← 唯一的"空"来源
   │
   ├──(报 mine)────▶ MINE      (latch: 不可回退)
   ├──(报 obstacle)▶ OBS       (latch)
   └──(报 target)──▶ TARGET    (latch; 可多格并板)
```

**五条锁存规则**：
1. **单调升级**：`MINE/OBS/TARGET` 只能从 `UNKNOWN/ABSENT` 进入，**永不被后来的片改回 ABSENT**（只有当后续片 `complete:true` 且**显式**报「该格不在本类集合内」且 `conflict_policy=allow` 时才降级 —— 默认 `deny`）。
2. **ABSENT 也要 `complete` 授权**：`complete:false` 的片**只能**升 `MINE/OBS/TARGET`，**不能**写 `ABSENT`（防「半张图当全空」）。
3. **版本单调**：每格记 `(state, scan_id, ts)`；`ts` 早于现值 ⇒ **丢弃**（复用 Mission 现役「同半场不倒退」语义，`mission.py:1531-1545`）。
4. **`scan_id` 一致性**：同一 `scan_id` 的重发（BEST_EFFORT 必须周期重发，`空地指挥链路_协议与运行手册.md` §5 坑③）**幂等**：已消费的 `(scan_id,slice.id)` 直接忽略，不重复触发重规划。
5. **冲突降级为 UNKNOWN + 告警**：同一格先后被报 `MINE` 与 `OBS` ⇒ 取先到者锁存，另一类记 `conflict`，**不自动改路线**（改由人裁决/告警）。

### 5.2 与现役 `P_DRONE` / 事件的关系

| 现役对象 | 本方案用法 | 为什么不能替代台账 |
|---|---|---|
| `P_DRONE: DroneState` | 心跳/在线/桥洞结论 | 单槽覆盖式赋值，`field_diff` ≤8 条环形缓冲（`drone.py:104,346-349`），**不留格表** |
| `EV_BRIDGE_INFO` | 桥洞（B3）唯一真源，**继续用** | 只有 half/block，不含雷障靶 |
| `EV_FIELD_VERIFY` | **零订阅**（✅ §11 E5），本方案把它接成台账输入 | 现役只进遥测 |

> **建议新增事件**：`EV_FIELD_SLICE = "FIELD_SLICE"`（`core/events.py`），载荷 = 片级汇总（`scan_id/slice/coverage/cells_counts`），**台账订阅它**；`EV_FIELD_VERIFY` 保持现状（逐类差异），互不替代。见 §10。

### 5.3 台账的落盘（现场可复盘）

- 内存对象 + **每次变更追加一行 JSONL**（`log/field_ledger_<boot>.jsonl`），字段：`ts, scan_id, slice, cell, old, new, src`。
- **不给车控用**（车控只读内存），纯复盘；写入走现有 `core/logging.py` 的日志目录，**不新增依赖**。⚠️ 写盘 IO 在 5~10 Hz 下需限流（每片一条汇总 + 变更才写）。

## 6. 重规划触发闸门（ReplanGate）

### 6.1 触发源 × 影响面矩阵（**这是决策层的核心判据**）

| 情报事件 | 影响面 | 是否重规划 | 理由 |
|---|---|---|---|
| **桥洞变化**（本半场洞口未过） | 路线**拓扑** | ✅ 必须 | 现役 `_reroute_at_decision` 已做，次数上限 1 → 建议 2 |
| **桥洞变化**（该半场洞口**已过**） | 无 | ❌ 只记遥测 | 过了洞再改 = 让车回头，违反「不回车起点」 |
| **新雷**（落在**未走过**格 → 强制必压） | 覆盖约束 | ✅ 必须 | 现役路线不含该格 ⇒ 漏压 1 雷 = 丢分 |
| **新雷**（落在**已走过**格） | 无（补不回） | ❌ 只记 `missed_mine` | 只能赛后复盘 |
| **新障**（落在未走区域且**阻断**当前路线） | 可达性 | ✅ 必须 | 硬碰撞风险 |
| **新障**（不阻断） | 无 | ❌ | 避免抖动 |
| **删障/删雷**（本地有、无人机说没有） | 路线可更短 | ⚠️ 可选（建议**不触发**） | 收益小、风险大（一次误检就改线） |
| **靶变化**（未打靶） | 射击停站 | ✅ 必须（若靶格变） | 停站点/射击窗口跟着靶走（`mission.py:2343-2360`） |
| **片内全 ABSENT**（无事发生） | 无 | ❌ | 绝大多数片都走这条 |

### 6.2 六条 AND 闸门（缺一不触发）

```
T1 有影响面    ：命中了 6.1 里「✅必须」的行（且非幂等重发）
T2 未封口      ：无人机未降落封口（scan 未 close）/ 未超 info_stale_s
T3 剩余预算够  ：race_budget_s 余量 ≥ 重规划耗时 + 最小行驶余量（建议 15 s）
T4 次数未用尽  ：replans < mission.replan_max（建议 3；桥洞 2 + 要素 1）
T5 间隔够      ：距上次重规划 ≥ mission.replan_min_interval_s（建议 1.0 s，覆盖 1.5 s 的 checkpoint 节奏）
T6 不劣化      ：新路线 ① validate_route 0 error ② 剩余长度 ≤ 旧剩余长度 × 1.25 ③ 仍满足 K 列行段硬门
```

- **T6 是防抖核心**：情报抖动（同一格反复出现/消失）会让路线来回跳；`1.25` 是「宁可少优化不改线」的阈值，建议现场可调。
- **T3 的预算来源**：`mission.race_budget_s`（`config.py:273`，缺省 **180 s**）；重规划耗时取实测量级（✅ §11 E7：tracker-safe 整线 **269 ms**，`plan_route/tour` **515 ms**）——**按 0.6 s + 0.5 s 下发余量**估算。
- **T4 的键**：`mission.replan_max`（**新增 SCHEMA**，缺省 3，范围 0~5）。
- ⚠️ **不要在 Mission tick（10 Hz）里同步跑规划**：269 ms ≈ 2.7 拍，会推迟停站/终点判定。建议**工作线程算 → 结果回队列 → 下一拍装线**（A5 的 5 Hz DroneTask 也可以承担算线，见 §7 L0）。

### 6.3 触发后不许做的事（不变量，写进代码注释也用）

1. **永不产生空路线**：任何一步失败 ⇒ **保留旧路线**（与 `_reroute_at_decision` 现役语义一致，`mission.py:1795-1836`）。
2. **永不回起点**：只能用 `keep_progress=True`；`reset:` 是人工动作，**台账/闸门不许发**。
3. **已过区域不重算**：`_passed` 为真的航点区间不可变（现役 `_decision_point` 用「洞口未过」判据，`mission.py:1698-1720`）。
4. **封口后冻结**：无人机降落/心跳停 ⇒ 台账只读，不再触发（对应 `无人机拟真与动态规划_方案.md` §3.3 第 5 步）。
5. **未知 ≠ 不存在**：`ABSENT` 必须由 `complete:true` 的片授权（§5.1 规则 2）。

### 7.1 L0 过渡：机侧算整线 + 前缀裁剪（**零车侧代码**，⚠️ 有 2 个待现场验的假设）

**做法**（全部在无人机侧/机侧进程完成）：
1. 用 `car_state{block}`（`drone.py:413-432`，1~2 Hz）知道车当前格 `C`；

4. 把整线 **裁掉 `C` 之前的前缀**，得 `C → 剩余航点…`；
5. 经 A 通道 `/nav/waypoint` 下发（RELIABLE）。

**为什么可行**：A 通道在 DRIVE 中**照收**（`_drain_commands` 每拍，`mission.py:1970/3089-3102`），`_load_tokens` 会把首点装成 `P_ROUTE_INDEX=0`，`_next_wp=1` ⇒ 车按「首点=当前格」直接走第 2 点，**理论上不掉头**。机侧也是**唯一写者**（须先确认 `start_path_executor` / `send_waypoint` 没在跑，手册 §6 警告）。

**待现场验证的 2 个假设（⚠️ 未验证，必须 bench 先跑）**：

| # | 假设 | 风险 | 验证方法 |
|---|---|---|---|
| H1 | 首点 = 车当前格时，Tracker 不会「倒车去首点」 | 现役 `_install_route` 会 `Path(route)` 重编译、`P_ROUTE_INDEX=0`；首点若与 belief 有偏差（车不在格心），纯追踪可能先"回正" | bench：belief 设在格心 + 偏 0.1 m 两种，看 `pursuitAngle` 首 20 拍 |
| H2 | 已压过的雷被重新纳入整线不会要求「回头压」 | 规划器**没有**「已压集合」参数（`plan_route` 签名 `planner.py:2258-2269` 无此入参）⇒ 若某雷在 `C` 之后但新线把车带回东侧，会**真的回头** | bench：造一个「雷在 C 之前」的用例，看裁剪后是否残留回头段 |

> **结论**：L0 **能打通链路**（对 B3 足够），但**对 B1/B2 不严谨**——因为它拿不到「已压雷/已过区域」的语义。所以 L0 是**过渡**，不是终局。

### 7.2 L1 小改：A 通道 `replan:` 前缀（**车侧小改**）

- 新增 A 通道命令：`replan:<跳过航点数> <token...>`，语义 = `_install_route(..., keep_progress=True)` + 跳过前 N 个航点。

> ★ **现役与你想要的「情报先导」不是同一件事**（本次实读 `robot.yaml`）：

> · 现役真正的情报消费点是 **L10 桥前 HOLD**（`mission.bridge_wait_max_s` 缺省 12 s，`config.py:271`）。
> ⇒ **决策 #3「等第一批情报才首次规划+出发」目前*没有*生效**；L2 主方案第一步就应把它打开（`bridge_wait_at_start=true` 或专用 `replan_at_start`），否则「首批情报 → 首次规划」这条链在车上不存在。

```
t=0.0   起飞，车 IDLE（auto_start_delay 10 s 窗口内等首批；★需先把 bridge_wait_at_start 打开，见上）
t=1.5   S1 片到达 → 台账 +15 格 → 桥洞 lower 定 → 首次规划（≈0.6 s）→ 发车 DRIVE

```

**判读**：现役航线对雷/障/靶是 **0 覆盖**；S3 带状 28 点 14 s 即可 **154/154**（与 t4 §6.3 同结论，本次独立复算）。

### E7 规划耗时（重规划预算的依据）

```
plan_route/tour (full map, allow_reverse=False)   ≈ 515 ms
plan_route_tracker_safe (full map)                ≈ 269 ms   → 50 token / 17.15 m（历史 1.00 档；现役 44 token / 15.05 m，双停站 `D3*`+`G3*`）
```
**判读**：单次重规划 0.27~0.52 s ⇒ 3 次重规划 ≈ 1.6 s，**不构成预算风险**；但 **10 Hz Mission tick 内同步跑会阻塞 3~5 拍** ⇒ 必须工作线程（§6.2 ⚠️）。
