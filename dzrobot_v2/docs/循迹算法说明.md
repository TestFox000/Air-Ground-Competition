## 0. 一页总览：数据流与一句话每步

```
底盘（里程计/舵机；1s 指令看门狗）
   ▲ publish_command(v, steer) ──────────────────── TrackerTask@50Hz（唯一底盘指令写入者）
   │ odom                                            读 P_POSE/P_SAFETY/P_MISSION_PHASE/P_ROUTE
   ▼                                              → project() → 纯追踪/PIVOT/ALIGN → 发布
LocalizationTask@20Hz  odom → P_FIX 修正 → 投影 → 到位吸附
   ▼ 写 P_POSE / P_POSE_RAW / P_ODOM_AGE / P_ROUTE_S / P_ROUTE_INDEX / P_FIX
SafetyTask@20Hz（唯一强制停车者，safety.py:126）
   ▼ 写 P_SAFETY ──拦──► Tracker 前置门（不安全 → 零 Twist 保活）
MissionTask@10Hz（读 P_ROUTE_S/P_POSE）
   ▼ 写 P_MISSION_PHASE（IDLE/DRIVE/APPROACH/STOP/SHOOT/…）──放行/拦──► Tracker
```

| 线程 | 频率 | 一句话职责 | 出处 |
|---|---|---|---|
| Localization | 20 Hz | odom → 修正 → 信念位姿 + 路线进度 + 到位吸附纠偏 | localization.py:1-35 |
| Safety | 20 Hz | 定位失联/越界/任务停滞判据，**唯一有权强制停车** | safety.py:126 |
| Tracker | 50 Hz | 投影 → 纯追踪/桥洞直行/PIVOT/倒车入口 → 底盘指令 | tracker.py:1-30 |
| Mission | 10 Hz | 到点推进 → 射击停站三段式 → 终点锁存 → 绕圈兜底 | mission.py:1-33 |
| Aim / Fix / Drone / Telemetry | 50/10/5/2 Hz | 云台开火、误差估计、无人机情报、上报 | 报告:45 |

**一拍数据流（时序示意，各任务跑自己的线程、经黑盒解耦）**：
1. odom 帧到 → Localization 校验 age → `FixState.corrected()` → 带 hint 投影 → 到位吸附 →
   写 `P_POSE` / `P_ODOM_AGE`（localization.py:135-185）；
2. Safety 下一拍读 `P_POSE`+`P_ODOM_AGE`+任务心跳 → 判据 → 写 `P_SAFETY`（safety.py:226-301）；
3. Tracker 下一拍读 `P_POSE/P_SAFETY/P_MISSION_PHASE/P_ROUTE` → 前置门 → `project()` →
   `compute_command()` → `publish_command(v, steer)`（tracker.py:284-465）；
4. Mission 读 `P_ROUTE_S`（先与现算投影做一致性校验）→ 到点推进/停站/终点 →
   写 `P_MISSION_PHASE`（mission.py:225-245、408-437）；
5. 底盘 1s 看门狗只认「50Hz 有没有指令」——任何拦停都靠**持续发零 Twist**，不是「不发」。

**三个黑盒键的写入者**（「谁写了就写同一个投影结果」，tracker.py:27-29）：

| 键 | 写入者 |
|---|---|
| P_POSE | Localization（每拍，localization.py:179/185）；Mission（`reset:` 复位信念，mission.py:296） |
| P_ROUTE_INDEX / P_ROUTE_S | Localization（localization.py:164-165、182-183）；Tracker（tracker.py:448-449）；Mission（一致性校验后写回，mission.py:430、371-372） |
| P_ODOM_AGE | 只有 Localization（缺位姿写 inf，每拍都写，localization.py:144-151） |

**一句话每步**：
1. 路线 = 一串 token（`N10 M10 … G10* … R:F11 … N5`），`route/parser.py` 把它编译成不可变 `Route`；
2. `pursuit/path.py` 把 `Route` 一次编译成折线段表 + 弧长前缀（`Path`），之后只读；
3. 每拍把信念位姿 `project()` 到路径上，得到「我在第几段、沿程多少米、离路多近」；
4. `pursuit/controller.py` 按纯追踪公式把投影换算成（速度，舵角）；
5. Tracker 把指令发给底盘；Mission 判断到点/到站/到终点并切换阶段；Safety 全程兜底。

## 1. 路线层：route/parser.py —— token 编译成 Route

**输入**：token 字符串列表 / 路线文件（整行一个 token，`#` 注释，parser.py:239-254）。
**输出**：不可变 `Route`（Waypoint 序列，含 x/y/yaw/reverse/shoot/scan/group）。

**语法总表**（parser.py:7-18）：

| 写法 | 含义 |
|---|---|
| `K9` | 普通航点，直线连到下一个点 |
| `G10*` / `G10:SHOOT_STOP` | 射击停站：到站停车、找靶、稳定后放行开火（`*` 是归一形态） |
| `F2:SCAN_STOP` / `F2:SCAN` | 纯扫描停站，**不射击** |
| `R:B5` / `R:B5*` | 倒车到位（该段线速度为负，车尾朝目标）；`R:` 在前、`*` 在后 |
| `SHOOT@G11` | **指令非坐标**：调 shoot_planner 算候选链整链插入，共享组号 |
| `N5,y` / `N5,x` | 终点朝向，只允许最后一个 token 带（parser.py:340-343） |

**关键规则**（每条都有对应测试）：
- 非法 token 一律抛 `ValueError`，绝不静默忽略（parser.py:23-24、128-136；test_route）。
- 相邻同格合并时 shoot/scan **取并集**、`reverse` 不同**绝不合并**——否则倒车段丢失（parser.py:366-389）。
- `SHOOT@G11` 由 `MissionTask._shoot_planner` 展开成靶标 4 邻格中落在 0.20~0.45 m 射击窗口的
  候选（mission.py:377-403）。
- 穿洞格从路线自身推断（K 列按半场分：row 7~11 = lower、row 1~6 = upper，parser.py:392-418）。

**现场 34 点路线**（`tests/fixtures/route_field.txt`，与使用手册:169-170 一致）：
`N10 M10 L10 L9 K9 J9 J10 I10 H10 G10* F10 F11 E11 R:F11 F10 F8 B8 B6 A6 R:B6 R:D6 C6 C4 C2 G2 H2 H1 I1 J1 J4 K4 L4 L5 N5`
——1 个射击停站 `G10*`、3 段倒车 `R:F11 R:B6 R:D6`；K9/K4 只是本局默认穿洞格，每局由无人机情报
在 `route.cross_lower/upper_candidates` 里选（robot.yaml:423-428）。配置迁移：`route.tokens` 由
旧 `path_executor.mission_blocks` 迁移（config.py:424）。

**已知坑**：中间点带朝向后缀报错（parser.py:340-343）；`format_route` 必须可往返（parser.py:444-448）。

## 2. 路径层：pursuit/path.py —— 段表 + 弧长 + 转角几何

**输入**：`Route`。**输出**：`Path`（构造后所有字段只读、`project()` 无副作用，可多线程并发，
path.py:74-78）。

- 编译一次得：段表 `(x0,y0,x1,y1,len,heading)`、弧长前缀 `_s_start`（bisect 定位，O(log N)）、
  停站索引 `stop_indices`（射击/扫描点 + 末点，path.py:80-108）。
- `Projection` 字段：`seg_index / t / x / y / s / dist / seg_length / seg_heading / passed_end`
  （path.py:49-61）。`s_vertex`/`dist_to_vertex` 是到本段末端顶点的弧长距离（path.py:63-71）。
- 段索引 `i` = 航点 `i → i+1`；**倒车标记挂在终点航点上**（path.py:17-19、189-193）。
- `s` 恒为**沿路线首点算起的弧长**，`t ∈ [0,1]` 是段内参数——三条不变量见 path.py:14-19。

**倒车段建模与「车头 vs 行进」**（这是本项目一个真 bug 的来源，path.py:215-241）：

| 现场 `F10→F11→E11→R:F11→F10` | 行进方向 | 车头朝向 |
|---|---|---|
| seg（F11→E11 正向） | +90° | +90° |
| seg（E11→R:F11 **倒车**） | −90° | **+90°** |
| 顶点处夹角 | 180° | **0°**（车头一度都不用转，倒着原路退回） |

- `corner_angle_deg`（path.py:203-213）= **行进方向**夹角；
- `corner_turn_deg`（path.py:228-241）= **车头实际要转的角度**，
  `abs(normalize(car_heading(i+1) − car_heading(i)))`；
- `car_heading_on`（path.py:215-226）= 倒车段时 `h + π`（车头与行进相反）。
- **PIVOT 判据必须用 `corner_turn_deg`**：旧代码用 `corner_angle_deg`，把 0° 车头转角误判成
  180° 折返 → PIVOT 转反 180° → 纯追踪自己跟自己打架（bench 实测 F11 簇：v 在
  +0.150/−0.080 反复翻、每 12s 触发一次绕圈跳点，path.py:231-237；报告 §6.5）。
- 段限速系数取两端点 `speed_scale` 的较小值（失败偏安全，path.py:195-201）。

**已知坑**：零长度退化段投影时跳过（path.py:21-22）；`segment_is_reverse` 越界防御式返回
False——控制环不能因索引错位停摆（path.py:191-192）。

## 3. 投影层：Path.project() —— 整条链路的灵魂（path.py:246-454）

**输入**：`(x, y)` + 可选的 `s_hint / window_m / back_m / s_min / motion_heading / allow_backward`。
**输出**：`Projection`（见 §2）。

### 3.1 窗口搜索（不是全局最近点）

给 `s_hint` 时只在 `[s_hint−window, s_hint+window]` 内搜；`allow_backward=False` 时下界收到
`s_hint`，并在首段做 `t_floor` 钳制（path.py:292-333）。复杂度只与窗口内段数有关——路线自交时
不会误锁到另一条边；每拍代价从旧版 O(N) 全扫降到 O(窗口)（tracker.py:21-22）。实测数字：
窗口投影 ≈2.5 µs，全路线 33 段全扫 ≈104 µs（localization.py:289）。

### 3.2 等距裁决的四级顺序（path.py:368-393，顺序很关键）

两条候选段几何等距（d² 差 ≤ `_TIE_D2_M2 = 1e-6`）时：
1. **连续性优先**：取 `|s − s_hint|` 更小的候选；
2. 连续性也分不出 → 比 `motion_heading`（车正在往哪边走，倒车时是车头反向）；
3. 无 hint → 取更靠后的段；
4. 全并列 → 保持先找到的（稳定的旧行为）。

注释里的血证：旧顺序「方向优先」在自重叠折返（B6→A6→R:B6）形成闭环振荡——命令符号 →
选哪条重叠段 → is_reverse → 命令符号，24s 内 601 次翻转、车毫米级抖动（path.py:374-379）。

### 3.3 三个关键机制（每个都对应一次实车/bench 事故）

| 机制 | 参数/常量 | 作用与由来 |
|---|---|---|
| `back_m` 单拍最大回退 | `pursuit.projection_rewind_m = 0.15` | 折返压线两条共线段等距、s 相差整整一段（0.0 vs 0.70），不限住就倒带。正常运动每拍仅 2.4 mm（0.12 m/s×0.02s），15 cm 只挡「一拍跳一整段」的病态（path.py:258-266；config.py:109-114） |
| `s_min` 弧长地板 | `pursuit.vertex_floor_m = 0.05` | 已走过的顶点不许再退回。断「倒车段↔正向段交界」（F11）的自指环：两候选 s 都在顶点附近、Δs 几乎相同 ⇒ 连续性分不出 ⇒ 落到方向 ⇒ 方向由命令符号决定 ⇒ 自指环（探针 30s 内 715 次符号翻转，path.py:300-307；config.py:123-127） |
| 顶点前视重投影 | `_VERTEX_STEP_M = 1e-3` | 最优点正好贴在当前段末端（t≥1）且还有下一段 → 内部 hint 推到 `顶点+1mm` 再投一次（最多一次），**只采用不比第一遍更差的结果**。否则纯追踪在顶点上用上一段算前视 → 前视点塌缩到车身 → 舵角恒 0 → 车直行漂出走廊（path.py:410-439；现场 F10 实测） |

### 3.4 倒车段的「符号翻转」

倒车段 `R:` 本身不改变投影几何（投影只看位置），真正翻转的是下游：
投影落到倒车段 → `segment_is_reverse=True` → 控制器 `v<0`、舵角 × `reverse_steer_sign`
（controller.py:157-159、185-187）；而「换到倒车段」靠的是 `motion_heading` 实测位移方向
+ Tracker 的「倒车段入口推一把」（tracker.py:392-422，见 §5）。

### 3.5 现场 F11 折返簇走一遍（弧长锚点可复核）

路线片段 `F10 F11 E11 R:F11 F10`（route_field.txt:14-18）。以首点为 0 累计弧长
（格距 0.35 m，geometry.py:30）：

| 弧长锚点 | 值 | 出处 |
|---|---|---|
| F10（wp10） | s = 3.500 | path.py:411 |
| E11（wp12，倒车段起点） | s = 4.200 | sim.py:1166（`s_floor = 4.200`） |
| R:F11 顶点（wp13） | s ≈ 4.55 | = 4.20 + 0.35（单格） |
| F10（回程，wp14） | s ≈ 4.90 | = 4.55 + 0.35 |

车先正向开 F11→E11（行进 +90°），在 E11 顶点**不停**直接倒回 F11（行进 −90°、车头恒 +90°，
一度不转），再正向去 F10。卡死吸引子 `(12, 4.41)`（段 12 = E11→R:F11，s=4.41 正是段中，
localization.py:263）说明冻结点就悬在倒车段**中段**；Tracker 的跟丢自愈日志里「s 冻在 7.70、
车实际 16.30」则是另一处（B6→A6→R:B6 重叠折返，tracker.py:344-351；path.py:260-262）。

### 3.6 已知坑

- `passed_end` 只能由第一遍投影裁决，二次投影不许改写（path.py:406-408）。
- 带 `s_hint` 的窗口投影有**结构性吸收态**（不动点）：垂足落到窗口之前时，返回的 s 恒等于
  hint。上层两处自愈兜底：Localization 卡死自愈（localization.py:250-314）、Tracker 跟丢自愈
  （tracker.py:343-368），见 §5/§7。

## 4. 控制层：pursuit/controller.py + lookahead.py —— 公式与速度剖面

**输入**：`(pose, path, proj, cfg)` + `reverse/last_steer_deg/dt`。
**输出**：`PursuitCommand(linear_x, steer_deg, curvature, speed_reason, reverse)`
（controller.py:38-46）。

### 4.1 纯追踪公式（从代码逐字读出）

- 前视距离：`ld = clamp(k_v · |v_巡航|, [lookahead_min_m, lookahead_max_m])`
  （config.py:585-590）。**用巡航速度算，不随瞬时速度变化**——否则「减速 → 前视变短 → 转向变猛」
  正反馈，低速贴站时摆头（controller.py:126-127）。
- 前视点：从投影点**沿弧长**前进 `ld`（可跨段），路径不足则瞄准终点（lookahead.py:91-100）。
  沿弧长而不是直线取点是「贴着路线走」的关键——直线取点过弯会把目标切到路线内侧抄近道
  （lookahead.py:15-16）。
- 转角顶点钳制：本段与下一段夹角 > `lookahead_corner_angle_deg(20°)` 且距顶点 <
  `vertex_clamp_m(0.04)` → 前视点钳到顶点，防最后一刻切角（lookahead.py:62-89）。
- 退化保护：车**正好站在顶点上**（dist_to_vertex=0）时不做钳制，把前视目标抬到顶点之后
  1mm——否则前视点=车自己 ⇒ 弦长 0 ⇒ 舵角恒 0（lookahead.py:65-83；现场 F10 二道防线）。
- 舵角（controller.py:136-149）：
  ```
  α  = atan2(rel_y, rel_x)        # 前视点在车体系下的方位角
  δ  = atan(gain · 2L · sinα / ld)， L=wheelbase_m
  curvature = 2·sinα / ld          # 目标几何曲率，不含 gain（调 gain 不改限速）
  ```
  `gain = curvature_gain = 1.0` 是教科书式；**0.5 逐位等于旧行为**（旧代码缺因子 2，
  controller.py:5-8）。分母下限 `lookahead_floor_m(0.10)` 防目标贴脸增益爆炸；目标贴在车上
  （chord < 1e-6）时取舵角 0 而不是急刹（controller.py:143-145）。

### 4.2 速度剖面（controller.py:52-85，取 min，理由可观测）

`v = min(巡航×段scale, 曲率限速, 停站减速, 转角减速) × 量化补偿`，下界 `min_speed_mps`：

| 层 | 公式 | 参数 |
|---|---|---|
| 巡航 | `v = cruise × speed_scale` | cruise_speed_mps=0.15 |
| 曲率限速 | `v = sqrt(lat_acc / |κ|)` | lat_acc_max_mps2=0.35（config.py:593-599） |
| 停站减速 | `v = min(v, max(min_speed, gain×d))` | stop_approach_speed_gain=0.30，只扫 stop_indices 且跳过已过点（controller.py:88-104） |
| 转角减速 | 距尖角顶点 < 0.45 → 压到 0.12 | corner_angle_deg=45°、corner_slow_dist_m=0.45 |

### 4.3 限幅与倒车

- 舵角硬限幅 ±30°（底盘侧再 clamp 到 [25,95] 含 +60 偏置，config.py:67-68）；
- **舵角速率限幅** ±120°/s 作用在最终输出上（含倒车符号翻转，controller.py:161-174）；
- 倒车：`v = −max(min_speed, v × reverse_speed_ratio(0.6))`，舵角 × `reverse_steer_sign(1.0)`
  ——**该系数注释明说「无实车依据，偏了改 −1」**（config.py:135-136）；
- 刹车 = **零 Twist**（v=0 且 steer=0；steer 必须也为 0，否则轮子保持打死姿态，
  controller.py:193-200）。底盘 1s 看门狗：零 Twist 即停，不需要额外停机协议（报告:502）。

## 5. 追踪层：tasks/tracker.py —— 50Hz，底盘指令的唯一写入者

**每拍分支优先级**（tick，tracker.py:284-465）：
`前置门（_hold 零 Twist 保活）→ PIVOT → 倒车段入口推一把 → 桥洞直行 ALIGN → 纯追踪`

- **前置门**（tracker.py:251-266）：无位姿 / 无安全状态或安全不 OK / 遥控接管 / 阶段不在
  `(DRIVE, APPROACH)` 白名单 / 无路线 → `publish_brake()` 后 return。旧实现在「无定位」时
  连零 Twist 都不发，靠底盘看门狗自己停——新版一律显式刹车（tracker.py:8-10）。
- **行进方向裁决**（tracker.py:309-335）：折返压线时同一物理点落在两条共线段上等距，必须告诉
  投影「车正往哪边走」。方向**只能取实测位移**（|位移| ≥ `motion_heading_eps_m(0.001)` 才更新，
  否则锁存上次可信值）；取「上一拍命令的速度符号」是自指环——命令符号→选哪条重叠段→is_reverse
  →命令符号，bench 实测 601 次翻转。**仿真不中招是因为它用真值速度算方向（tools/sim.py:555）——
  仿真与实车代码在这一点的语义不一致，仿真绿曾掩盖实车卡**（tracker.py:313-320）。
- **投影调用形状**：`window_m=approach_m(0.60)`、`back_m=rewind(0.15)`、`s_min=地板`、
  `motion_heading=实测方向`（tracker.py:337-341）。s_hint 优先本任务上一拍 `_seg_s`，其次
  读 Localization 写进黑盒的值（tracker.py:303-307）。
- **投影跟丢自愈 relock**（tracker.py:343-368）：窗口内最近点离线 > `projection_release_m(0.30)`
  → 丢掉 hint 与地板全路线重投影；**只接受向前的修正**（s 不许退到地板之前）。没有这个出口，
  tracker 的 s 冻在 7.70 而车实际在 16.30（差 8.6 m），追幻影目标开出路线、最大横向偏差
  4.101 m（tracker.py:344-351）。「只向前」的取舍见 test_tracker 第 9 组（注释 355-358）。
- **弧长地板更新**（tracker.py:371-380）：投影贴到顶点 ≤ `vertex_floor_m(0.05)` 就把
  `floor = 顶点弧长`。为什么「贴到」就抬而不是「越过」：越过的这一拍投影可能已被另一条
  共线段抢走，再抬就晚了（tracker.py:371-375）。

### 5.1 PIVOT 原地转向（PivotPhase：IDLE/SETTLE/TURN，tracker.py:53-66、484-565）

**状态转移表**：

| 当前 | 条件 | 动作/下一状态 |
|---|---|---|
| IDLE | `corner_turn_deg > 135°` 且距顶点 ≤ 0.25 且不在桥洞保护段 且该顶点未被标记「已处理」 | 记目标航向 `car_heading_on(下一段)`，进 SETTLE（tracker.py:500-520） |
| SETTLE | 已等 `pivot_wait_s(0.5)` | 进 TURN；否则发零速（惯性消失再蠕转） |
| TURN | 航向误差 ≤ `pivot_yaw_tol_deg(15°)` | ✓ 完成：标记「该顶点已处理」，回 IDLE 交还纯追踪（tracker.py:542-553） |
| SETTLE/TURN | 用时 > `pivot_timeout_s(14)` | ⚠️ 超时放行：标记已处理，回 IDLE（tracker.py:523-530） |

- TURN 期指令：速度 `pivot_speed_mps(0.08)` 蠕动，舵角 = `err_deg × pivot_kp(1.0)`
  （限幅 30° + 速率限幅与纯追踪同一条契约，tracker.py:555-564）。
- **硬超时取值不是随手填的**：偏航率上限 v/L·tan30° = 0.294 rad/s ≈ 16.9°/s ⇒ 135° 需
  8.01s、180° 需 10.68s；旧值 8.0s 比触发阈值还短（config.py:92-100）。
- 完成/超时**都要**标记 `abandon_until_s`——漏掉成功分支会「完成→下一拍再触发」无限循环，
  bench 整场卡在 s≈4.4/34m（tracker.py:159-165、547-551）。
- 目标航向用 `car_heading_on(下一段)`（车头），**不是** `heading_at`（行进方向）——
  下一段是倒车段时两者差 180°（tracker.py:470-482）。

### 5.2 倒车段入口「推一把」与桥洞直行

- **倒车段入口**（tracker.py:392-422）：已贴到顶点（≤ `reverse_entry_m(0.06)`）且下一段是
  倒车段且本段不是 → 直接给 `−min_speed` + 航向保持，并把 `_seg_s` 显式推进到顶点。
  没有它「鸡生蛋」卡死：换段靠实测位移，实测位移靠先发 v<0，v<0 靠先换段（bench 实测 s 冻在
  4.20、yaw 一直转，tracker.py:393-396）。两条折返段在顶点处代表同一物理点（差 <1mm），
  显式推进不是「跳变」而是把「这段已走完」告诉投影（tracker.py:416-422）。
- **桥洞直行 ALIGN**（tracker.py:193-226、423-433）：穿洞格 ±2格/±1格
  （`align_straight_before/after`，单位**格**）的航段集合**只在路线变化时重建**；命中时关掉
  纯追踪只做航向保持：`steer = err_deg × align_kp(12) / 10`（限幅 8°）、速度 0.10。判据用
  航段索引而不是「离 K 列近」的几何判据——后者会 K 列 ±2 格全域锁航向（旧「循迹僵直」坑，
  tracker.py:11-14）。
- 回写 `P_ROUTE_INDEX/P_ROUTE_S`（三个写入者之一，与 Localization 写同一投影语义，
  tracker.py:27-29、447-449）。

**已知坑**：`_last_linear_x` 字段已删除且注明「别再加回来」（tracker.py:118-121）；teardown
发零指令收尾（tracker.py:580-585）。

## 6. 任务层：tasks/mission.py —— 到点、停站、终点、兜底

**阶段机**（MissionPhase，白名单之外一律不动车）：`IDLE → DRIVE →（距停站点 < approach_m
时 APPROACH）→ STOP（三段式）→ DRIVE → … → FINISH（锁存）`；安全接管时进入 SAFE_STOP，恢复
后回 DRIVE（不重来，mission.py:853-859）。

- **auto_start**（mission.py:250-265）：`auto_start=true` + 延时 10s（robot.yaml:432）→
  `parse_reset("N10,y")` 复位信念 → `parse_mission(route.tokens)` 写 P_ROUTE → 阶段 DRIVE；
  配错**停在 IDLE 绝不带病发车**（mission.py:260-263）。
- **到达判定 `arrival_m`**（mission.py:439-489）：航点 i 到达 ⟺
  `s + arrival_m ≥ s_wp`（「刚越过」窗口）**且** 在附近，或 距格心 ≤ arrival_m；
  「在附近」= 横向偏差 ≤ 0.30 **或** 距格心 ≤ 2×arrival_m(0.24)。
  为什么不是「单用弧长」：投影跳变时 s 会一次性跨过几个从未走到的点（假到点）；
  为什么距离门槛放宽到 2×/横向 0.30：纯追踪正常切角时离线心 0.288 m（bench 实测 L9），
  旧判据恒假 ⇒ 每个点都等 12s 兜底补跳（mission.py:451-477）。
- **`_current_s` 一致性校验**（mission.py:408-437）：读黑盒 `P_ROUTE_S` 前必须与「当前位姿现算
  的投影」比对，差 > arrival_m 就丢掉用现算值并写回——该键可能是上次任务的残留旧值。
- **射击停站 G10\* 三段式**（mission.py:645-791，旧四段里的 STABLE 归 AimTask）：
  - 触发：`s + stop_radius_m(0.17) ≥ s_stop` 或 距格心 ≤ max(0.17, arrival)，取或互补
    （mission.py:629-640）；
  - SETTLE（0.8s 停稳：Δ≤0.02 或 v≤0.02）→ ACQUIRE（`aim_status==TRACK` 且有目标；18s 超时）
    → FIRE（开 fire_gate，发数增量 ≥ shots_per_stop(3)；30s 超时）。**每段独立超时、超时即
    放行，放行前一定关 fire_gate**——铁律「宁可漏打，不可卡死」（mission.py:12-13）。
  - 扫描停站 `:SCAN` 走简化版（只保证到位停稳，mission.py:749-761）。
- **拐角绕圈兜底**（mission.py:491-558）：s 在 `stall_timeout_s(12)` 内前进不足 arrival_m，
  或停滞期间累计转满 `stall_yaw_deg(360°)` → 把下一个未到达航点强制跳过（宁可漏点不可卡死）。
  ★ **Tracker 正在 PIVOT 时整个停滞窗口重置**（读遥测 `pivot_phase`）——180° PIVOT 实测
  ~10.8s、累计转 ~180°，与绕圈判据数值正面撞车，修完 PIVOT 后看门狗把每次正常折返都当绕圈
  （mission.py:560-576）。
- **终点**（mission.py:871-905）：末点到达 → FINISH **锁存**、刹车、停扫、结束横幅。
- 外部命令 `/nav/waypoint`：`reset:` / `load:` / 单点 / 多点全支持，未知只告警不崩
  （mission.py:915-977）。

**已知坑**：属性名避开 `_stop`（与 `threading.Thread._stop` 冲突，mission.py:142-144）；末点
绝不进三段式停站（mission.py:584-599）；持续扫描期间绝不再发 `scan_request=1`（会被降级成
单趟，mission.py:828-834）。

## 7. 定位层：tasks/localization.py —— 信念位姿与路线进度

**流水线**（localization.py:135-185）：`bridge.pose()` → age 校验（拿不到就**不写 P_POSE**，
宁愿下游看到「没有位姿」也不冒充新值；P_ODOM_AGE 每拍都写，Safety 检查①直接读它）→
`FixState.corrected()` → 带 hint 投影 → 到位吸附 → 写 `P_POSE/P_ROUTE_*`。

- **投影调用形状是试出来的**（localization.py:203-219）：`window_m=arrival_m(0.12)` +
  `allow_backward=False`。`allow_backward=True` 且窗口大于每拍位移时，投影点每拍都被夹回
  s_hint ⇒ s 恒为 0（实测整条 0.35m 路线走完 s=0）；0.12m 前向窗口覆盖 20Hz×0.6m/s 的
  0.03m/拍，且保证 P_ROUTE_S 单调。代价：倒车段要回退时本任务只报最小 s（那是 Tracker 的活，
  localization.py:215-216）。
- **投影卡死自愈**（localization.py:250-331，2026-10-07 补）：上述形状有吸收态（§3.6）。
  三条判据**同时成立**才做一次全路线重投影：s 前进 < `stuck_eps_m(0.01)` 持续 ≥
  `stuck_ticks(5)` 拍 **且** 位姿移动 > arrival_m **且** `proj.dist > stuck_dist_m(0.20)`。
  bench 实证冻结值 `(12,4.41)(15,6.78)(19/20,9.10)(14,4.9)(10,3.73)(17/18,8.05)`，
  上报投影点离线 0.5~3.5m 占 20~37% 拍，把 fix.py 的段比值污染成物理不可能的 0.12~0.23
  （localization.py:261-264）。全扫**保留 s_hint**（传 None 会按「取更靠后的段」误锁共线
  折返另一支，实测 +1.15m，localization.py:296-300）；不做「只向前」限制——切角后回退一点
  时真值本来就在身后（localization.py:277-285）。代价：最多每 stuck_ticks 拍一次全扫，
  不会退化成每拍全路线扫描（localization.py:287-291）。
- **到位吸附**（localization.py:333-366）：距「当前段末端航点/其后最近未完成航点」<
  arrival_m → 把信念位姿**锚回格心**（yaw 不动），偏差记进 P_FIX
  （anchor_count/last_anchor/drift_m/max_drift_m）。每过一个已知航点就是一次误差归零机会；
  同一航点只锚一次（防越锚越偏）。候选用段索引判据，不是「离最近格心<阈值」——后者会让 K 列
  附近任何位置都被吸（旧僵直坑，localization.py:368-378）。
- **漂移告警**（localization.py:399-421）：与吸附**独立**——吸附半径 0.12 远小于告警阈值
  0.30，漂了 0.5m 的车永远进不了吸附半径 ⇒ 既不纠偏也报不出漂移。所以用**弧长闸门**
  `drift_seg_gate_m(0.18)`（走到离顶点 ≤0.18m 才进判定窗），与横向偏差无关——「漂得越狠越
  报不出来」的结构性死角由此消除。每航点至多一条告警（localization.py:443-462）。
- **与 Safety 的关系**：Localization 是 P_ODOM_AGE 的唯一常规写入者（缺位姿写 inf），Safety
  检查① 把它与桥的 pose_age 双来源对照；Localization 不写 P_POSE → Tracker 前置门直接刹车。

## 8. 安全层：tasks/safety.py —— 循迹的边界（现场实事③的归属）

- Safety 是**唯一强制停车者**（safety.py:126），Tracker 的 `P_SAFETY` 门只是执行（tracker.py:258）。
- 检查① 定位失联（safety.py:226-294）双来源：桥的 `pose_age` + `P_ODOM_AGE`（Localization 心跳），
  另有「Localization 心跳停滞」判据（>2×pose_timeout_s）。
- **pose_lost 启动竞态**（safety.py:238-289）：启动顺序是顺序 start，Localization 先 tick 一拍
  却还没拿到里程计（ROS2 发现未完成）→ 把 P_ODOM_AGE 写成 inf → 旧判据「任一来源 inf 即致命」
  直接 pose_lost → **安全刻意不自动恢复 ⇒ SAFE_STOP 锁存 ⇒ 车一动不动**（实车 2026-10-09 19:05
  血证，safety.py:240-245；阶段总结_出车就绪.md:21 提交 b349fc5）。修复三件套：
  ① 启动宽限 `startup_grace_s(3.0)`——「从未收到定位」≠「跑着跑着丢了」；
  ② `never_had_pose` 判据 =「桥没有帧 且 P_ODOM_AGE 缺失或为 inf」（两种写法都算没数据）；
  ③ `P_ODOM_AGE=inf` 要**持续** > pose_timeout_s(1.0) 才是真故障（单拍 inf 是必然竞态）。
  日志特征：只有一条「启动宽限（0.02/3.0s）」、没有「宽限期已过」却出现 pose_lost
  （safety.py:100-101）。
- 越界急停收敛到 Safety 一处（safety.py:296-300），Tracker 的 PIVOT 分支不自己查边界
  （tracker.py:494-495）。

## 9. 为什么这么设计

- **纯追踪 vs MPC/DWA**：新核沿用旧 `path_executor.pure_pursuit_control` 的血统（controller.py:4）。
  底盘固件里 DWA 分支因 `cmd_vel` 无发布者恒空转、双源仲裁是纯负担（survey_chassis_vision.md:132、315），
  新架构只保留单一速度入口。代码与文档里**没有** MPC 相关的讨论——选择理由就是「移植旧实现 +
  单一速度入口」，不是最优控制层面的比较。
- **弧长地板**：倒车段↔正向段交界（F11）的自指环——连续性分不出 → 落到行进方向 → 方向由命令
  符号决定 → 环闭合。探针 30s 内 715 次符号翻转（config.py:124-126；path.py:300-307）。
- **跟丢自愈 relock**：地板/窗口把真最近点排除后，错误 s 变自洽不动点，车走多远拉不回来
  （tracker s 冻 7.70 vs 实际 16.30、横向偏差 4.101m，tracker.py:344-351；config.py:128-134）。
- **Localization 卡死自愈**：同源吸收态的另一条链（fix.py 段比值污染，localization.py:261-264）。
- **PIVOT**：F11 180° 折返纯追踪画大弧 0.37~0.41m 横向偏差，而 E11/F8 是必须压过的雷——偏差
  0.4m 就可能漏压；9 组参数扫描证明几何结构性无解，只能「停下 + 低速蠕动转向」（config.py:81-84）。
  但注意 §11.2 的推导：现场路线车头转角 ≤ 90° < 135° ⇒ **PIVOT 在本路线一次都不触发**，折返
  全部由倒车段完成；PIVOT 是为「真正的正向调头」备着的（报告:441-462）。
- **零 Twist = 刹车**：底盘 1s 看门狗，零指令即停；「不发指令」等于等它自己停，新版一律显式
  发零并限流记原因（tracker.py:8-10；报告:502）。

**「事故 → 机制 → 代码位置 → 测试」总表**：

| 事故（实测） | 对应机制 | 位置 | 测试 |
|---|---|---|---|

| tracker s 冻 7.70 vs 实际 16.30，横向偏差 4.101m | 投影跟丢自愈 relock | tracker.py:343-368 | test_tracker 第 9 组 |
| Localization 上报投影离线 3.5m、fix 比值 0.12~0.23 | 投影卡死自愈 | localization.py:250-331 | test_localization 卡死用例 |
| PIVOT 把车头转反 180°、v 每拍翻 | corner_turn_deg + 倒车段入口推一把 | path.py:228-241；tracker.py:392-422 | test_pivot §7 |

## 10. 现场三件实事的代码映射

**①「倒车」与「掉头」**——先如实说明：当前代码与报告给出的结论和「倒车不生效→改 PIVOT 掉头」
的方向**相反**：现场路线的三处折返全部标记为 `R:` 倒车段（route_field.txt:17、23、24），由
parser（R: 前缀）→ path（segment_is_reverse/car_heading_on/corner_turn_deg）→ controller
（v<0 ×0.6、steer×sign）→ tracker（倒车入口推一把）四层协同完成；PIVOT 因 `corner_turn_deg
≤90° < 135°` 在本路线 0 次触发（报告:453-454），实车日志段12 `v=-0.080` 证明底盘执行了倒车
（报告:571）。如果现场底盘确实不能倒车，报告给出的预案是**去掉路线里的 `R:` 标记，PIVOT 会自动

## 11. 调参指南

**0.15 m/s vs 0.3 m/s 分别影响什么**：

| 参数 | 0.15 m/s 时 | 0.3 m/s 时 | 说明 |
|---|---|---|---|
| `lookahead_k_v(1.2)` | ld=0.18（恰为下限） | ld=0.36 → 被 `lookahead_max_m(0.24)` 截断 | yaml 把上限压到 0.24 的理由：0.36 超过格子边长 0.35，会「越格致切角失控」（robot.yaml:409；SCHEMA 默认 0.45，config.py:74） |
| `lookahead_max_m` | 不起作用 | **起作用**：超 0.24 一律截断 | 前视上限必须 < 0.35m 格长 |
| `lat_acc_max_mps2(0.35)` | 曲率限速较少生效 | 曲率限速频繁生效：0.3m/s 要同样横向加速度，转弯必须更缓 | `v=sqrt(a/|κ|)`，config.py:593-599 |
| `corner_speed_mps(0.12)` / `stop_approach_speed_gain(0.30)` | 与巡航差 0.03，几乎无感 | 减速幅度大、停站更平滑但更慢 | controller.py:52-85 |
| `speed_quant_comp(1.0)` | 默认不动 | 底盘量化 `|v·23/0.33|` 截断丢约 4.3%，可填 1.043 | config.py:115-116 |
| PIVOT 到达判定 | 正常 | **yaml 注明「0.3 使 PIVOT 掉头到达判定失控，先回退」** | robot.yaml:412——速度调高前先看这条注释 |

**PIVOT 掉头卡「不可达」该看哪些键**：
- 黑盒：`P_TELEMETRY[tracker_cmd].pivot_phase`（IDLE/SETTLE/TURN）、`.speed_reason`、
  `.seg_index/.s`；`P_ROUTE_S`（谁把它冻住了）；`P_SAFETY.reasons`（是不是安全在拦）；
  `projection_relocks`（投影跟丢自愈次数）。
- 触发链参数：`pivot_angle_deg(135)` / `pivot_dist_m(0.25)` / `pivot_timeout_s(14)` /
  `pivot_yaw_tol_deg(15)` / `pivot_kp(1.0)`；先确认 `corner_turn_deg` 真的 >135°（车头转角，
  不是行进夹角——用 §2 的方法对路线现算）。
- 超时与绕圈：`mission.stall_timeout_s(12)` / `stall_yaw_deg(360)`——PIVOT 期间已被豁免
  （mission.py:560-576），若发现跳点日志里同时有 PIVOT，查豁免判据的遥测键名
  `TRACKER_CMD_KEY="tracker_cmd"`（tracker.py:70）。
- 排查顺序建议：① 看 `pivot_phase` 有没有进 SETTLE（没进 = 触发条件不满足，逐条核
  `corner_turn_deg/dist/桥洞段/已处理标记`）；② 进了 TURN 但 14s 超时 = 航向差算错（目标航向
  必须用 `car_heading_on`）或 `pivot_kp` 太软或速度被别处压住；③ 完成又重入 = `abandon_until_s`
  标记被绕过。

**其他敏感键**：`curvature_gain(1.0)`（0.5=旧行为等价，controller.py:5-8）；
`max_steer_rate_deg_s(120)`（防一帧跳 60°）；`reverse_steer_sign(1.0)`——**无实车依据，
倒车偏了先怀疑它**（config.py:135-136）；`motion_heading_eps_m(0.001)`、`projection_rewind_m
(0.15)`、`vertex_floor_m(0.05)`、`projection_release_m(0.30)`、`reverse_entry_m(0.06)` 五个
投影/换向参数互为因果，动一个要整套 bench 重验（test_tracker、test_path_overlap、test_pivot）。
