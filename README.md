## 场地与任务

| 项 | 值 | 出处 |
|---|---|---|
| 场地 | 4 m × 5 m，无四周围挡 | 规则 p3–4〔档〕 |
| 单元格 | **0.35 m**；14 列（A~N）× 11 行 = **154 格** | `core/geometry.py:27-43`〔实〕 |
| 隔板 | 恒在 **第 6/7 行之间**，横跨 **D~N** ⇒ 只有 A/B/C 列能上下穿行 ⇒ 赛道被迫 **U 形** | 规则 + `geometry.py:37-43`〔实〕 |

| 雷 | 随机 8 格，直径 12 cm 彩图**平贴**格中央，**只能靠视觉**识别（可能用训练集没有的同类图 ⇒ 考泛化） | 规则 p5–6 |
| 障碍 | 随机 8 个装水彩桶，位于格中央，有高度、遮挡视线 | 规则 p6 |
| 打击区 | 相连两格，单局仅 1 处，内含红/蓝面移动靶 | 规则 p7 |
| 桥洞 | 2 处，均在 **K 列**，35 cm 架空；**每局随机指定可通通道**，通行状态标在**桥顶箭头** | 规则 p8 |
| 赛时 | **180 s**（⚠️ 队内口径：官方 PDF 只有场地布置、没有计分表） | `core/config.py`〔档〕 |
| 计分 | 蓝面得分、红面扣分（队长澄清 + 代码默认，同样非官方赛规原文） | 〔档〕 |

**车端任务分解**：读布局 layout（已知格 + 要素，known=154 为完整）→ 规划经过压雷格、避开障碍、穿桥洞、停射击站的路线 → 纯追踪循迹 → 到停站执行动作（压雷 / 射击 / 普通停）→ 抵达 N5。

## 系统架构

```text
        无人机 dzsmartscout（Jetson Orin Nano + PX4 + Livox MID-360）
          FAST-LIO → 定位；相机 → 格号/箭头感知；uXRCE-DDS @921600 → PX4
                                  │ ROS2 DDS（域号：车 118 / 机 0）
          /nav/waypoint（RELIABLE）│ /dzlink/*（BEST_EFFORT）
                                  ▼
        小车 dzrobot_v2（RK3588S · ROS2 Humble · 域 118）
          dzbrain 单进程 8 线程：定位 / 安全 / 循迹 / 任务 / 云台 / 修正 / 无人机 / 遥测
          dzactuator（底盘）· dzrknn_dataprocess（云台+开火判据）
          dzjudgment（激光/裁判串口）· det_node（RKNN 检测）
```

### 车端 8 线程（频率已对源码核实）

| # | 线程 | 频率 | 职责 | 唯一性 |
|---|---|---:|---|---|
| 1 | LocalizationTask | 20 Hz | 定位投影、到位吸附、漂移/边界护栏、航向守卫 | 写 `P_POSE` |
| 2 | SafetyTask | 20 Hz | 五道看门狗 + `SAFE_STOP` 故障闩锁 | **唯一强制停车者** |
| 3 | TrackerTask | 50 Hz | 纯追踪 → `pursuitAngle`；PIVOT/倒车/ALIGN | **底盘指令唯一写入者** |
| 4 | MissionTask | 10 Hz | 阶段机、路线装载、停站三段式、桥洞择格 | 任务编排 |
| 5 | AimTask | 50 Hz | 云台扫描/跟踪、提前量、开火门 | 出 `/aim/fire_ready` |
| 6 | FixTask | 10 Hz | 系统性误差/尺度估计 | 只估计不改位姿 |
| 7 | DroneTask | 5 Hz | `/dzlink` 收发、ack、布局、覆盖账本 | 链路唯一出入口 |
| 8 | TelemetryTask | 2 Hz | 遥测快照（面板/复盘） | 只读 |

> `dzbrain` 是**一个进程 + 8 个任务线程 + 4 个 ROS executor 线程**，不是 8 个节点。布局模式（StepLoop）下会额外先起一个 DroneTask（实际 8+1）。

### 空地链路（两条语义相反的话题）

| 话题 | 类型 / QoS | 方向 | 用途 |
|---|---|---|---|
| `/nav/waypoint` | `std_msgs/String`，**RELIABLE** depth 10 | 机 → 车 | 路线 token 与段目标 |
| `/dzlink/drone_to_car` | JSON，**BEST_EFFORT** VOLATILE | 机 → 车 | 情报、布局版本、心跳 |
| `/dzlink/car_to_drone` | JSON，**BEST_EFFORT** | 车 → 机 | 车态、ack、覆盖账本 |

**铁律**：BEST_EFFORT 发 → RELIABLE 收 = **静默 0 条**（两端端点计数各为 1，只有 `ack` 是硬证据）。心跳超时 3.0 s、情报过期 30.0 s。

### 视觉模型

| 模型 | 体积 | 用途 / 指标 |
|---|---|---|
| `hbb_detector_d13_20261016.onnx` | 36.67 MB | 无人机主检测器（13 类）：mine R98.3% / arrow R88.9%+P100% / cell R98.5% / obstacle R94.3% |
| `cell_classifier_v4d_20261015.onnx` | 4.13 MB | 格号分类（字母 14 + 行 11），joint_acc **0.8701** |
| `target_pose_v2_20261016.onnx` | 10.49 MB | 车端靶标 pose（4 bbox + 红/蓝 + 3 关键点），P0.985 / R0.999 |


## 工程纪律

1. **先查账，再动手** —— 已裁决事项不得重开；翻案先答三问（新证据 / 影响面 / 不重开的代价）。
2. **先复用，再造轮子** —— 新建脚本前查复用清单与能力索引，新增未登记 = 门禁红。
3. **冻结区不碰** —— `src/dzbrain/dzbrain/**`、`src/dzrknn_dataprocess/**`、`config/**`、`tools/deploy_to_car.py`；实验进 `_tmp_session/` 或 feature flag。
4. **写域独占** —— 一卡一 owner；共享文件（`robot.yaml`、`目录索引.*`、`AGENTS.md`）单写者 + 评审。
5. **证不出来 = 没完成** —— 交付必须带可复跑命令、关键输出、回滚点、影响面。
6. **一次只改一个变量** —— 一轮一个假设；连续 2 轮无提升即停并写清停因。
7. **文档只存 `docs/` 一处** —— 库外新建 .md = 红线；新文档必须登记索引（册级 + 全库 + 入口三层）。

多人 / 多 agent 并行时按**命名空间（ns）**隔离写域：读任意 ns，只写自己的 ns；任务树单写点；收口必须把结论提炼进库并写反向指针。
