## 2. 必须先知道：`velodyne_localization.launch.py` 会拉起 3 个必死的节点

实测死亡记录（`/tmp/fastlio_launch.log`）：

```
[ERROR] [global_localization.py-2]:  process has died [exit code 1]
[ERROR] [global_map_publisher.py-4]: process has died [exit code 1]
[ERROR] [transform_fusion.py-3]:     process has died [exit code 1]
```

原因（机上实测 import 复现）：

| 缺失模块 | 谁因此死亡 |
|---|---|
| `open3d` | `global_localization.py`、`global_map_publisher.py` |
| `tf_transformations` | `transform_fusion.py`、`global_localization.py`、`publish_initial_pose.py` |

`transform_fusion.py` 的报错原文：

```
ImportError: cannot import name 'transformations' from 'tf2_ros'
```

**后果**：`transform_fusion.py` 是 `/localization` 的**唯一**发布者，它死了 ⇒ `/localization` 不存在
⇒ 若按原手册用 `mode=localization` 启动 `px4_odom_convert`，它订阅的是一个不存在的话题，
**永远不会向 PX4 发出任何外部视觉**。

**影响面**：FAST-LIO 本体不受影响（`fastlio_mapping` 活着，`/Odometry` 正常）。
所以点云、建图、RViz 显示都正常 —— 现场观感与"一切正常"几乎无差别，这是它长期没被发现的原因。

## 3. 完整启动顺序

### 阶段 A：感知层（无执行能力，随时可跑）

```bash
# A1 激光雷达驱动
ros2 launch livox_ros_driver2 msg_MID360_launch.py

# A2 FAST-LIO 定位/建图（rviz:=false 表示不在远程终端开 RViz）
ros2 launch fast_lio_localization velodyne_localization.launch.py rviz:=false
```

**前置检查**（A1 失败时看这两条）：

```bash
cat /sys/class/net/eno1/carrier      # 必须是 1
ping -c2 192.168.3.105               # 雷达本体，必须通
```

> 若 `carrier=0`：雷达航插没插好或雷达没供电。驱动会报 `bind failed` → `Init lds lidar fail`。

### 阶段 B：飞控链路（**需要飞控板插上 USB**）

```bash
# B1 uXRCE-DDS 桥，把 /fmu/* 暴露成 ROS 2 话题
MicroXRCEAgent serial --dev /dev/ttyACM0 -b 921600

# B2 外部视觉 → PX4    ← 注意 mode:=odom，见 §4
ros2 launch px4_odom_convert px4_odom_convert.launch.py mode:=odom

# B3 PX4 SensorCombined → ROS Imu
ros2 launch px4_imu_bridge sensor_combined_to_imu.launch.py
```

**B1 的前置检查**：

```bash
ls -l /dev/ttyACM*          # 必须存在；不存在就是飞控板没插/没上电
lsusb | grep -i -E "3dr|px4|pixhawk|hex"
```

### 阶段 C：验证（你原手册的第 6~10 行）

```bash
ros2 topic echo /fmu/in/vehicle_visual_odometry    # B2 的输出，应有 42 Hz 左右
ros2 topic echo /fmu/out/vehicle_control_mode
ros2 topic echo /fmu/out/vehicle_local_position
ros2 topic echo /fmu/out/vehicle_odometry
ros2 topic echo /fmu/out/vehicle_status
```

更快的判断方式：

```bash
ros2 topic list | grep fmu          # 有 /fmu/out/* ⇒ uXRCE 通了
ros2 topic hz /fmu/in/vehicle_visual_odometry
```

### 阶段 D：控制层（**有执行能力，注意**）

```bash
# D1 控制节点（只订阅命令，自己不看键盘）
ros2 launch px4_control px4_control.launch.py

# D2 键盘遥操（必须在真终端里跑，要 raw mode 读键盘）
ros2 run px4_control px4_teleop_node --params-file ~/dzpx4/install/px4_control/share/px4_control/config/params.yaml

# D3 路径录制 / 跟随（由 YAML 里的 record_mode 决定跑哪个）
ros2 launch px4_path px4_path.launch.py
```

> **D2 必须在真实 TTY 里运行**（VNC 桌面的终端即可）。
> 用 `setsid`、`nohup` 或管道启动会 `tcgetattr failed`，键盘无效。

**D2 按键表**（来自 `px4_teleop_node.cpp:24-35`）：

| 键 | 作用 |
|---|---|
| `0` | 切 Offboard |
| `1` | ARM + 自动起飞 |
| `2` | DISARM（仅落地时） |
| `3` | LAND |
| `W/S` | ±X 0.5 m（NED 北） |
| `A/D` | ±Y 0.5 m（NED 东） |
| `Q/E` | 上 / 下 0.1 m |
| `L/R` | yaw ±0.15 rad（HOVER 下；GOTO 使能时忽略） |
| `4` | 使能外部 GOTO（交给 px4_path） |
| `5` | 撤销 GOTO 并保持当前位姿 |
| `Ctrl+C` | 退出 |

## 4. 与原始 `1.txt` 的三处差异（都是实测得出的）

### 差异 1：B2 必须加 `mode:=odom`

原手册：`ros2 launch px4_odom_convert px4_odom_convert.launch.py`（默认 `mode=localization`）

- `px4_odom_convert.launch.py:35` 的 launch 默认是 `localization`
- 而 `/localization` 从来不存在（§2）
- `px4_odom_convert.cpp:12` 里 **代码默认值本来就是 `odom`**，是 launch 把它改掉的

**为什么 `mode:=odom` 在数值上等价**：`transform_fusion.py:54` 在没收到 `/map_to_odom` 时用 `np.eye(4)`，
于是 `/localization = T_map_to_odom @ T_odom_to_base = /Odometry`，
再经同一套 `R_enu_slam` + ENU→NED 转换 —— **两者逐位相同**，区别只是一个是死的、一个是活的。

> 想彻底不再打这个 flag，就把 `fc-audit/fixes/01-odom-source/files/px4_odom_convert.launch.py` 替换过去（需重装 share 目录）。

### 差异 2：D3 跑哪个节点由 YAML 决定，不是命令行

`px4_path.launch.py` 读 `config/params.yaml` 里的 `record_mode`：
`true` → `path_record_node`，`false` → `path_follow_node`。
**没有同名 launch 参数**，改了 YAML 就要重装（`config/` 会装到 `install/`）。

### 差异 3：`/fmu/out/*` 全部依赖 B1

飞控板没插时，`/fmu/out/*` 一个都不存在，阶段 C 的 5 条 echo 会全部卡住不输出。
这不是软件故障。

## 5. 停止 / 清理

```bash
# 单杀
pkill -f livox_ros_driver2_node
pkill -f fastlio_mapping
pkill -f px4_odom_convert
pkill -f sensor_combined_to_imu
pkill -f px4_control_node
pkill -f px4_teleop_node
pkill -f path_follow_node
pkill -f path_record_node

# uXRCE-DDS 桥
pkill -f MicroXRCEAgent
```

> 用 `pkill -f`（不是 `pkill -x`）：`livox_ros_driver2_node` 超过 15 字符，`-x` 永远匹配不到。

**注意**：`path_record_node` 是**析构时才落盘**的 —— 必须 `Ctrl+C`/`SIGTERM` 正常退出才会保存路径文件。
`kill -9` 会丢掉整段录制。
