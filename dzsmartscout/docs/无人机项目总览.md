## 一、技术架构概览

### 1.1 这套系统是什么

**不是**"无人机自己会规划并飞"。它是一个 **"人先飞一遍录轨迹 → 机器照着飞"** 的 **回放式路径跟随系统**：

```
人手动飞（遥操） → FAST-LIO 记录轨迹 → 存成 txt → 之后飞机自动沿该轨迹回放
```

外加一条**向小车发航点 / 情报**的链路。**没有**自主避障、**没有**自主建图决策、**没有**视觉识别算法。

### 1.2 硬件清单

| 部件 | 型号 / 参数 | 接口 | 状态 |
|---|---|---|---|
| 机载电脑 | NVIDIA Jetson Orin Nano Dev Kit | — | ✅ 在线 |
| 激光雷达 | **Livox MID-360**（360°×59°，10 Hz，19968 点/帧，序列号 `47MCN850037605`） | eno1 以太网（雷达 `192.168.3.105` ⇄ 主机 `192.168.3.189`） | ✅ 已跑通 |
| 相机 | **LRCP AR0234** USB 相机（`32e4:0234`，UVC 免驱） | USB2，`/dev/video0`（取流）+ `/dev/video1`（metadata） | ⚠️ 已接出图 29 Hz，但**画面糊**（定焦镜头，软件修不了） |

### 1.5 三条独立链路（判断"我卡在哪一步"）

```text
① 感知定位  Livox → FAST-LIO → /Odometry ────────┐        ✅ 已通 42 Hz
                                                 │
② 飞控通信  MicroXRCEAgent ⇄ 飞控板 → /fmu/*  ←──┘        ❌ 飞控板未插
```

## 三、完整启动顺序

### 3.0 每个新终端都要先做（环境）

```bash
source /opt/ros/humble/setup.bash
source ~/dzpx4/install/setup.bash
```

> 少任何一句都会 `Package 'px4_control' not found`。

### 3.1 阶段 A：感知层（无执行能力，随时可跑）

```bash
# A1 激光雷达驱动
ros2 launch livox_ros_driver2 msg_MID360_launch.py

# A2 FAST-LIO 定位 / 建图（rviz:=false 表示不在远程终端开 RViz）
ros2 launch fast_lio_localization velodyne_localization.launch.py rviz:=false
```

**前置物理检查**（A1 失败时看这两条）：

```bash
cat /sys/class/net/eno1/carrier      # 必须是 1（雷达航插插好 + 雷达上电）
ping -c2 192.168.3.105               # 雷达本体，必须通
```

> 若 `carrier=0`：雷达航插没插好或雷达没供电。驱动会报 `bind failed` → `Init lds lidar fail`。

### 3.2 阶段 B：飞控链路（⚠️ 需要飞控板插上 USB，出现 `/dev/ttyACM0`）

```bash
# B1 uXRCE-DDS 桥，把 /fmu/* 暴露成 ROS 2 话题
MicroXRCEAgent serial --dev /dev/ttyACM0 -b 921600

# B2 外部视觉 → PX4    ← ★★★ 必须加 mode:=odom，见 §六坑1
ros2 launch px4_odom_convert px4_odom_convert.launch.py mode:=odom

# B3 PX4 SensorCombined → ROS Imu
ros2 launch px4_imu_bridge sensor_combined_to_imu.launch.py
```

**B1 前置检查**：

```bash
ls -l /dev/ttyACM*          # 必须存在；不存在就是飞控板没插 / 没上电
lsusb | grep -i -E "3dr|px4|pixhawk|hex"
```

### 3.3 阶段 C：验证

```bash
ros2 topic list | grep fmu                       # 有 /fmu/out/* ⇒ uXRCE 通了
ros2 topic hz /fmu/in/vehicle_visual_odometry    # 期望 ~42 Hz
ros2 topic echo /fmu/out/vehicle_local_position  # 飞控板没插时会卡住，不是故障
```

### 3.4 阶段 D：控制层（⚠️ 有执行能力，人在座时再跑）

```bash
# D1 控制节点（只订阅命令，自己不看键盘）
ros2 launch px4_control px4_control.launch.py

# D2 键盘遥操（★ 必须在真 TTY 里跑，VNC 桌面终端即可；setsid/nohup 会失效）
ros2 run px4_control px4_teleop_node --params-file ~/dzpx4/install/px4_control/share/px4_control/config/params.yaml

# D3 路径录制 / 跟随（由 YAML 里的 record_mode 决定跑哪个，无 launch 参数）
ros2 launch px4_path px4_path.launch.py
```

**键盘遥操按键表**（`px4_teleop_node`）：

| 键 | 作用 |
|---|---|
| `0` | 切 Offboard（需已发够 20 个心跳，约 1 s） |
| `1` | ARM + 自动起飞（到 0.5 m 悬停） |
| `2` | DISARM（仅落地时） |
| `3` | LAND |
| `W/S` | ±X 0.5 m（NED 北） |
| `A/D` | ±Y 0.5 m（NED 东） |
| `Q/E` | 上 / 下 0.1 m |
| `L/R` | yaw ±0.15 rad（Goto 使能时被忽略） |
| `4` | 使能外部 Goto（交给 px4_path） |
| `5` | 撤销 Goto 并固化当前位置 |
| `Ctrl+C` | 退出 |

### 3.5 停止 / 清理

```bash
pkill -f livox_ros_driver2_node      # 用 -f 不是 -x：名字超 15 字符，-x 永远匹配不到
pkill -f fastlio_mapping
pkill -f px4_odom_convert
pkill -f sensor_combined_to_imu
pkill -f px4_control_node
pkill -f px4_teleop_node
pkill -f path_follow_node
pkill -f path_record_node
pkill -f MicroXRCEAgent
```

> ⚠️ `path_record_node` **析构时才落盘**——必须 `Ctrl+C`/`SIGTERM` 正常退出才保存路径文件，`kill -9` 会丢掉整段录制。

### 4.2 典型飞行流程（当前**无法执行**，因无飞控板；插上后从这开始）

```text
① 装飞控板 → 起 A/B 段 → 验证 C 段（42 Hz）
② 遥操起飞：按 0 → 按 1 → 飞到 0.5 m 悬停
③ 录路径：YAML 改 record_mode=true → 重编译 → 重启 px4_path
   → 手动飞完整条航线 → Ctrl+C 正常退出（★ 只有正常退出才落盘！）

```

> ⚠️ 路径只在节点构造时读一次，按 `4` **不会**重新加载文件。

### 4.3 向小车发航点 / 情报（已真机验证，当前唯一完整闭环）

**前提**：无人机与小车接到**同一个 WiFi AP**，且都 `source` 了域号环境（`ROS_DOMAIN_ID=118`）。

```bash
# 环境（域号唯一真相源）
source ~/dzlink_tools/dzlink.env          # export ROS_DOMAIN_ID=118

# A 通道：裸文本路线（RELIABLE）—— 车立即出发
python3 ~/dzlink_tools/dz_send_waypoint.py route "N10 M10 L10 L9 K9 J9 J10 I10 H10 G10* F10 F11 E11 N5"

# B 通道：JSON 情报（BEST_EFFORT）—— 桥洞/靶区/雷障
python3 ~/dzlink_tools/dz_send_waypoint.py bridge lower=K9 upper=K4 --seq 1
python3 ~/dzlink_tools/dz_send_waypoint.py heartbeat
python3 ~/dzlink_tools/dz_send_waypoint.py target G10 H10
python3 ~/dzlink_tools/dz_send_waypoint.py field  --mines A3 B4 --obstacles K9
# ★ 格名用空格分隔是标准写法；逗号/分号写法也认（发送器会自动拆开）：
#   target --blocks G10,H10  /  field --mines A3,B4 --obstacles K9
#   历史坑（2026-10-12 t4 真机验证抓到、t12 已修）：以前 `--blocks` 不是合法参数（argparse exit 2），
#   而 `--mines A3,B4` 会被原样当成**一个**格名 "A3,B4" 发出去，且不报错。

# 听车回传（证明车收到了）
python3 ~/dzlink_tools/dz_send_waypoint.py listen --duration 30

# 先干跑验证报文（不发）
python3 ~/dzlink_tools/dz_send_waypoint.py route "..." --dry-run
```

发送器会**打印订阅者匹配数**：≥1 才算真配上，=0 别怀疑车、先查域号。

**报文语法速记**（A 通道）：`N10` 棋盘格号 · `*` 该点停车打靶 · `R:` 前缀倒车 · 空格/分号/竖线分隔。
**情报时效**：30 s 过期；车侧等情报窗口只有 **2 s**（且只管「两半场相隔 ≤2 s 到达」，超时那半场只进遥测、路线已冻结），所以要**赶在发车前发** —— 情报必须在车起栈前备好（`--cmd-file` 预置或 `once`）。车侧真值：`mission.bridge_info_wait_s=2.0`、`auto_start_delay_s=45.0`、默认穿洞格 **K10**(下)/**K5**(上)。

## 五、快速 SSH 连接指南

### 5.1 三种连法（按推荐顺序）

#### 方式 ① —— DeepSeek Harness 侧栏插件（最省事，推荐）

本机已装插件 `dsh-dzdrone-ssh`（`dsh-plugin-dzdrone-ssh/`），在 DSH 侧栏点无人机图标即进入**无人机面板**，提供四个工具：

| 工具 | 打开为 | 用途 |
|---|---|---|
| **SSH 终端** | DSH 内置终端标签页 | 回显 / Tab 补全 / Ctrl-C 都是原生的，免密自动登录 |
| **文件目录** | `dzd-files` 标签页 | 浏览 / 预览 / 下载 / 上传无人机文件（走同一条 SSH 通道） |
| **VNC 桌面** | `dzd-vnc` 标签页 | noVNC + WebSocket 隧道直连无人机 5901（见 §六） |
| **状态浮窗** | 帧级浮层（不占标签页） | 温度 / CPU 占用两条动态曲线，5 秒一刷，可拖动 / 调透明度 |

**排错**：
- 侧栏图标是**红点** → 无人机不可达，确认上电 + 同一 WiFi + `ping dzsmart.local`。
- **黄点 / "需要密码"** → 能连但免密不成立，装公钥：`ssh-copy-id -i ~/.ssh/id_rsa.pub duzhong@dzsmart.local`。
- 面板点了没反应 → 看 `~/.dsh/dzdrone-ssh/diag.jsonl`，或在设置页复制等价命令直接粘到终端。

设置页（Settings → 无人机 SSH）可改：主机/IP、用户名、端口、ssh 别名、ssh 参数、VNC 主机/端口/通道/密码、文件浏览起始目录。默认值取自 `~/.ssh/config`：`dzsmart.local` / `duzhong` / 22 / `~/.ssh/id_rsa` 免密。

#### 方式 ② —— 命令行 SSH（最直接）

```bash
# 推荐：强制 IPv4（dzsmart.local 会先解析出 IPv6 导致挂起）
ssh -4 duzhong@dzsmart.local

# mDNS 抖动时直接用 IP（IP 随 WiFi DHCP 变，历史出现过）：
#   10.240.174.104（旧 AP）/ 10.226.211.104（赛场 AP）/ 10.158.138.104（换网后）/ 10.200.61.104
ssh -4 duzhong@10.226.211.104

# 用仓库内 known_hosts，不动你自己的 ~/.ssh/known_hosts
ssh -4 -o UserKnownHostsFile=D:\User\Desktop\dzsmartscout\tools\drone\known_hosts_dz duzhong@dzsmart.local
```

免密已配置（本机公钥在无人机 `~/.ssh/authorized_keys`），无需输密码。

#### 方式 ③ —— 找不到无人机时先定位 IP

mDNS 间歇性失败是已知现象。找不到时用仓库里的扫描脚本：

```bash
python3 D:\User\Desktop\dzsmartscout\find_drone.py        # 局域网扫描
python3 D:\User\Desktop\dzsmartscout\sweep_current.py     # 扫当前网段
python3 D:\User\Desktop\dzsmartscout\verify_new_ip.py     # 验证新 IP
```

```bash
# 然后本机 VNC 客户端连 localhost:5901
```

### 6.3 能看到什么 / 注意事项

- **XFCE 桌面**：可开终端跑 ROS 命令、开 RViz（`export DISPLAY=:1 && rviz2`）、看 FAST-LIO 建图。
- **ROS 进程不自启**：VNC 起来了不代表雷达 / FAST-LIO 在跑，要在桌面终端里手动起（§三阶段 A）。
- **`px4_teleop_node` 必须在真 TTY 里跑**：VNC 桌面的终端**可以**；但用 `setsid`/`nohup`/管道启动会 `tcgetattr failed`，键盘静默失效。
- **改分辨率**：改 `/etc/systemd/system/vncserver@:1.service` 的 `-geometry` 与 `~/.vnc/config` 的 `geometry=` 两处，再 `systemctl restart vncserver@:1`。⚠️ 重启会把 `:1` 上所有 X 客户端杀掉，需重新拉起。或用无人机侧脚本 `scripts/restart-vnc-1080p.sh`。

### 6.4 ⚠️ TigerVNC 黑名单（必知）

TigerVNC `UseBlacklist` 默认开：**一个连上却没完成认证就断开的客户端会被拉黑**（输错密码、或连上后没登录就关掉都会）。本机实测约 1 分钟恢复，重复违规翻倍。

- 所以插件面板**不自动连接**，必须点一下。
- 想彻底避免：在无人机 VNC 单元加 `-BlacklistThreshold=0` 或 `-UseBlacklist=0`（降低安全性，需你决定）。

## 七、常见问题与已知坑

### 坑 1 · `px4_odom_convert` 默认 `mode=localization` 静默不发数据 ⭐⭐⭐

`ros2 launch px4_odom_convert px4_odom_convert.launch.py`（不带参数）默认订阅 `/localization`，而该话题**从不存在**（3 个 Python 定位节点因缺 `open3d` / `tf_transformations` import 即崩）→ **永远不发外部视觉，且不报错**。

**解法**：**必须加 `mode:=odom`**，订阅活着的 `/Odometry`。两者数值逐位相同（`transform_fusion.py` 没收到 `/map_to_odom` 时用 `np.eye(4)`）。

### 坑 2 · 飞控板从未连接 ⭐⭐⭐

机载电脑**没有 PX4 固件**，PX4 跑在单独飞控板上，经 USB 串口 + MicroXRCEAgent 暴露 `/fmu/*`。**飞控板不插 ⇒ 无 `/fmu/*` ⇒ 所有 Offboard 控制无法进行**。2026-06 至今从未插过。

**解法**：插上飞控板 USB，`ls /dev/ttyACM*` 能列出来后从阶段 B1 继续。

### 坑 3 · USB-C 口 gadget 模式（插飞控板时注意）⭐⭐

Jetson Orin Nano 的 **USB-C 端口默认可能是 device/gadget 模式**（用来当 USB 以太网网卡从主机烧录 / 登录），不是 host 模式。**插 PX4 飞控板前要确认该口在 host 模式**，否则飞控板插上也不会出现 `/dev/ttyACM0`。

**排查**：
```bash
ls /sys/class/udc/                       # 有条目 = 该口在 gadget 模式
cat /sys/class/udc/*/state               # "not attached" / "configured"
ls -l /dev/ttyACM*                       # 插上飞控板后必须有
```
若处于 gadget 模式，需切到 host 模式（具体取决于哪个 USB-C 口；40-pin 边的 Type-C 通常是 OTG，需拔掉任何 gadget 绑定）。这是 Jetson 平台特性，**不是本项目代码问题**。

### 坑 4 · mDNS 抖动 / IP 随 DHCP 变 ⭐⭐

`dzsmart.local` 间歇性解析失败（Avahi 在多网卡 / docker0 广播时会抖）。IP 随 WiFi DHCP 变化，历史出现过 `10.240.174.104` / `10.226.211.104` / `10.158.138.104` / `10.200.61.104`。

**解法**：mDNS 失败时直接用 IP；脚本里**写 IP 兜底**，别只靠 `.local`。已禁止广播 docker0 地址缓解。

### 坑 5 · 跨机 ROS 域号不一致 = 静默失联 ⭐⭐⭐

`ROS_DOMAIN_ID` 不一致时：**ping 通、SSH 通、网页台通，ROS 死活看不见对方，且一个错都不报**。全车唯一真相源：
- 小车 `~/dzrobot/dzros.env`
- 无人机 `~/dzlink_tools/dzlink.env`
- 本地副本 `tools/link/dzros.env`、`tools/link/dzlink.env`

**都是 118**。交互式终端读 `~/.bashrc` → 118；但 `systemd` / `cron` / `ssh host 'cmd'` **不读** → 0。**起 ROS 命令前一定先 `source` 对应的 env 文件**。

### 坑 6 · `px4_teleop_node` 必须在真 TTY ⭐⭐

用 `setsid` / `nohup` / 管道启动会 `tcgetattr failed`，键盘静默失效（你以为按键没反应，实际是启动方式错）。**VNC 桌面的终端可以**。

### 坑 7 · `path_record_node` 只在正常退出时落盘 ⭐⭐

`kill -9` / 断电 = 整段录制丢失。必须 `Ctrl+C` 或 `SIGTERM`。

### 坑 8 · 录了新路径却飞旧路径（契约断裂）⭐⭐

跟随读 `recorded_path_2.txt`、录制写 `recorded_path.txt`，且 `overwrite_existing=false` 会自动改名 `_1/_2/_3`。补丁 02 已修但**未应用**。

### 坑 9 · VNC 黑名单 ⭐

见 §六-6.4。输错密码 / 连上不登录就关 → 被拉黑约 1 分钟。

### 坑 10 · 相机画面糊（软件修不了）⭐⭐

`v4l2_camera` 不支持 MJPG（只能 YUYV）；同一 UVC 节点同时只能一个进程取流；定焦镜头对焦控制是 no-op，`focus_absolute` 全扫无改善。**只能物理排查**：撕镜头保护膜 / 检查镜头装正 / 退到最小对焦距离外。

### 坑 11 · 雷达 `xfer_format` 不能改 ⭐

`msg_MID360_launch.py` 的 `xfer_format=1`（CustomMsg）是 FAST-LIO 必需，改成 PointCloud2 会直接断链。要给小车发 PointCloud2 走另一条线：`dzlink_pc2_bridge`。

### 坑 12 · 白色无特征地垫 + 无围挡 → FAST-LIO 漂移（未实测）⭐⭐⭐

场地是白色刀刮布、几乎无几何特征、**没有四周围挡**，`blind: 0.8` 又丢掉 0.8 m 内点。低空飞到场上空时可用特征只剩场外环境与立体障碍物。**实飞前必须做漂移实验**（手持 1.5 m 高平移 3–5 m，回到起点漂移应 < 5 cm）。

## 十一、相机 / VNC 快捷工具（2026-10-18 新增）

> 目的：这些操作以后不需要再现场试错。Agent 侧同一份内容已固化为 DSH skill `dz-drone-cam`（下次会话自动出现在技能目录）。

### 11.1 一键脚本（Windows 侧，首选）

```powershell
cd dzsmartscout\tools\drone
.\dzcam.ps1 ip                        # 找无人机当前 IP（SSH 前的第一件事）
.\dzcam.ps1 status                    # 预览/录制状态
.\dzcam.ps1 preview on|off|status     # VNC :1 上开/关实时画面
.\dzcam.ps1 record start|stop|status  # 录制（cam_record.sh 的封装）
.\dzcam.ps1 shot  [out.png]           # VNC 桌面截图 → PC
.\dzcam.ps1 snap  [out.jpg]           # 相机单帧 → PC（相机需空闲）
```

### 11.2 三个必须知道的约束

1. **`dzsmart.local` 会解析到过期 IP**：SSH 超时先 `arp -a` 找当前地址，别怀疑无人机坏了；
2. **`/dev/video0` 独占**：预览、录制、抓单帧三者不能同时进行；
3. **VNC 无 XVideo**：预览必须用 `ximagesink`（旧脚本用的 `xvimagesink` 在 VNC 上打不开窗口，已修）。

### 11.3 机端没有 ffmpeg / ImageMagick

录制只能走 `~/tools/cam_record.sh`（GStreamer + x264enc）；
截图只能 `xwd` + `tools/drone/xwd2png.py` 转换。
