# src/history 项目资料索引

**本目录用途**：存放项目进展与资料，分两类：
- `log/` —— **进展快照（时间线）**：每次"总结项目 / 生成 log"产出的日志，按时间顺序反映项目演进。
- `book/` —— **技术文档**：面向接手/开发者的系统性技术手册（架构、算法、参数、命令等），与日志互补。

---

## 1. 阅读顺序（新 agent 接手）

1. 先看本文件 `INDEX.md`，了解资料分布。
2. 看 `book/` 下的**技术文档**建立系统认知（架构/算法/参数/命令）。
3. 看 `log/` 下**最新一份**日志了解当前状态、待办、坑清单。
4. 需追溯某决策原因时，翻 `log/` 对应日期的日志。

---

## 2. 文件命名与存放规范

```
src/history/log/log_YYYY-MM-DD_HHMM.md     # 日志：log_ + 生成日期(精确到分钟)
src/history/book/<主题>[_YYYY-MM-DD].md     # 技术文档：主题名（可带日期）
```

- 日志文件**只新建不覆盖**——历史是不可变的进展记录。
- 统一 `.md`，便于结构化展示。

---

## 3. 新增资料的操作规范

**新增日志（"总结项目 / 生成 log"时）**：
1. 在 `log/` 下新建 `log_YYYY-MM-DD_HHMM.md`（HHMM 取生成时刻，精确到分钟）。
2. 内容含固定六项：项目概述 / 主要模块 / 当前完成情况(带证据) / 最近运行状态 / 待办(P0~P2) / 关键说明（坑清单）。
3. 补一节"相对上一份的变化"（只写增量）。
4. 在本 `INDEX.md` 的「日志清单」表追加一行。

**技术文档（"写技术文档"时）**：
- **定位**：**唯一权威文档**，**全面概括整个项目**（物理/组成/代码结构/命令/更新/问题）。
- **更新方式**：**就地覆盖上一版**——直接修改 `book/` 下现有文档，**不另起新文件、不整篇重写**。
- 仅在首次建立或文档定位变化时才改动下方「技术文档清单」对应行。
