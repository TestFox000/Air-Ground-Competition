## 1. 项目概述

智能车自主竞速系统。小车需自主沿规划路线穿越场地，途中经过"雷区"（需压点）、"桥洞"（可通行）与"障碍物"（需避让），并用**云台自瞄**搜索/锁定/击打红蓝靶标，最终抵达终点 `N5`。

**三条硬约束（决定了路线形状）**：
1. 场地为 **A~N 列 × 1~11 行** 的格点地图（`config/map.yaml`），格子边长 0.35 m。
2. **中部绿线挡板**位于第 6 行与第 7 行之间、**横跨 D~N 列** → 上下半场**只能从 A/B/C 列缺口穿过**。
3. 部分格点有障碍物（障），不可穿越。

**当前运行策略**：
- 扫描模式 `continuous` —— 云台**边走边扫，循迹全程不停车**（区别于到点停车开火）。
- 巡航速度 `LINEAR_SPEED = 0.15 m/s`。
- 桥洞保护：K1~K11 列为桥洞走廊，进入前 2.0 格起**锁航向直行**，防止在桥洞内偏航刮蹭。

## 3. 核心数据流（话题图）

```
[相机]/image_raw ──┬──► [det_node] ──offset_center──► [云台自瞄] ──► /shoot_count,/voice_switch
                   │                                      ▲              │
                   │                                      │              ▼
                   ├──► [cam_viewer] 网页画面        /nav/scan_request  [path_executor]
                   │                                      │              ▲      │
[编码器/IMU] ──► [serial_reader] ──/odom/localization──────┴──────────────┘      │
                                                                                ▼
                                                              /pursuitAngle ──► [底盘] ──► 电机
```

| 话题 | 类型 | 发布者 → 订阅者 |
|---|---|---|
| `/image_raw` | Image | 相机 → det_node, cam_viewer |
| `offset_center` | Int32MultiArray | det_node → 云台自瞄, cam_viewer |
| `/odom/localization` | Odometry | serial_reader → path_executor |
| `/nav/waypoint` | String | send_waypoint → serial_reader, path_executor |
| `/pursuitAngle` | Twist | **path_executor** → 底盘 |
| `cmd_vel` | Twist | 遥操作 → 底盘 |
| `/nav/scan_request` | UInt8 | **path_executor** → 云台自瞄 |
| `/shoot_count` | Int32 | 云台自瞄 → path_executor |
| `/aim_status` | — | 云台自瞄 → path_executor |
| `/voice_switch` | UInt8 | 云台自瞄 / path_executor |
| `/odom` | Odometry | 底盘 → serial_reader |

> **握手机制**：path_executor 用 `/nav/scan_request` 通知云台开始/停止扫描；云台回 `/shoot_count` + `/aim_status` 形成闭环（打完再走）。代码中仍保留旧 `stop_signal` 发布器（兼容过渡），**新流程以 `/nav/scan_request` 为准**。

## 7. 关键说明 / 接手必读（坑清单）

1. **挡板约束是路线设计的第一约束**：D~N 列在第 6/7 行之间被封死，过界点必须落在 A/B/C 列。改路线后**必须**用 `tools/route_check.py` 校验。
2. **改 C++ 必须 `colcon build` 并 `source install/setup.bash`**；改 Python 直接生效（无需编译）。
3. **两个同名 `dzactuator_node`**：底盘在 `dzactuator` 包，云台在 `dzrknn_dataprocess` 包。
4. **视觉窗口 `DISPLAY=:1`**（VNC），物理 HDMI 是 `:0`，两者隔离不可跨屏；`start_all.sh` 已自动设置。
5. **不要用 `pkill` 手动清进程**（实测在某些执行环境会漏杀，已出过两次事故）；用 `./start_all.sh stop`，必要时 `kill -9 <pid>`。
6. **网页弹窗占 8080**，端口冲突时换端口或先清旧进程（`ss -lntp | grep 8080`）。
7. **参数只改 `config/robot.yaml`**，不要在代码里散改常量；改完跑 `tools/healthcheck.sh` 验证参数确实被节点声明（否则"改了不起作用"）。
8. **模型换版**走"版本号 + SHA256"流程，软链指向 `src/rknn_pt/model/light_det.rknn`，勿直接覆盖散文件。
9. **不要删除 `.codebuddy/`**（项目数据，非缓存）。
10. **共享代码注意脱敏**：`/image_raw` 抓帧、标定表、`.bash_history` 可能含场地信息；只带源码+文档，勿带模型/标定/日志/帧。
