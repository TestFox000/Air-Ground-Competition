## 6. 坑清单（本轮新踩）

1. **PowerShell 把 git 的 stderr 当异常报**：`git push --mirror` / `git bundle verify` 明明 exit 0，却因 git 往 stderr 写正常进度信息而使 PowerShell 抛 `NativeCommandError` 并显示 `[exit code: 1]`。**判别真伪的方法**：`cmd /c "git ... > %TEMP%\x.txt 2>&1 & echo EXIT=%errorlevel%"`，再读文件。不要被 PowerShell 的假 exit 1 骗了（本项目历史上多次因此误判"失败"）。
2. **PowerShell 的 `$t^{commit}` 会被解析坏**：在 `foreach($t in git tag -l)` 里写 `git log $t^{commit}`，PowerShell 把 `$t^{commit}` 当基名/转换运算符吃掉了，报 `fatal: ambiguous argument 'YwBvAG0AbQBpAHQA'`。**改用 `git rev-list -n1 $t`**。
3. **不要 `git add -A`**：本轮 `git status` 出现 4 个非我产出的 `M`（并发写入者，mtime 19:40~19:48 全在 v3.0 提交之后）。若用 `-A` 会把云台 +1403/−1332 的大改卷进"版本号整理"的提交，重蹈 `e906e6c` 覆辙。**只 `git add` 自己的文件路径**，提交后 `git show --stat` 核对文件数。
4. **版本号顺序与提交顺序可能倒挂**：方案 A 保留了 `v3.0` 的里程碑地位，但它提交于 10-14，晚于 v3.1/v3.2 的 10-12 ⇒ **v3.0↔v3.1 之间版本号顺序倒挂一次**。已在台账 §1/§3.2 与本快照 §9 如实记录。今后一律按提交时间递增编号。
