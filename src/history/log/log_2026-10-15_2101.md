### 裁决 ② · commit `4b610d1` 的 message 乱码 —— **不 amend**

- **现象**：提交 `4b610d1` 的 commit message 在 git 对象里是真乱码（`git log -1 --format=%B` /
  `git cat-file commit HEAD` 读出的字节经 UTF-8 解码仍是乱码）。
- **成因（已定位到具体环节）**：提交时用 `write` 工具生成 UTF-8 **无 BOM** 的消息文件，随后
  **PowerShell 5.1 的 `Get-Content -Raw` 按 ANSI/GBK 解码**它，再以 UTF-8 写回临时文件后交给

  - **文件名无损** —— `git diff-tree --no-commit-id --name-only -r HEAD` 解码后 18/18 正常，
    含中文名 `docs/sim-bench-improve_交接清单_20261014.md`；

  - **仅 commit message 文本受损**，且该文本是纯注释性内容，不含任何机器读取依赖。
- **补偿措施**：完整要点已用 `git tag -a v3.6 -F <UTF-8 文件>` 写入 **tag 注释**（`git tag -F`
  由 git 直读字节、**不经过 PowerShell 解码**），已用 `git cat-file tag v3.6` 逐字节验证无损。

## 4. ⚠ commit message 乱码的根因与教训（PowerShell 5.1 编码坑，新增第 5 条）

1. **根因**：`Get-Content` 在 PS 5.1 下**默认按 ANSI（GBK）解码**，不是 UTF-8。
   ⇒ 「`write` 写 UTF-8 文件 → `Get-Content -Raw` 读 → `-replace "`r`n" → 写回 → `git commit -F`」
   这条链**必然双重编码**。
2. **正确做法（本次 tag 已用对）**：把消息交给 **`git` 自己读文件**，不经 PowerShell 文本层：
   ```powershell
   git tag -a v3.6 -F %TEMP%\msg.txt      # ✅ git 直读字节
   git commit -F %TEMP%\msg.txt           # ✅ 同样可行，但本卡当时多走了一次文本层转换 ⇒ 中招
   ```
   若必须用 PowerShell 处理内容，显式指定编码：
   ```powershell
   $m = [System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)   # ✅
   ```
3. **验证手段（务必照做）**：提交后**读 git 对象字节**判真伪，不要靠控制台回显（控制台也可能乱码）：
   ```powershell
   cmd /c "git cat-file commit HEAD > %TEMP%\raw.bin"
   [System.Text.Encoding]::UTF8.GetString([System.IO.File]::ReadAllBytes("$env:TEMP\raw.bin"))
   ```
4. **文件名与内容要分开验**：`git diff-tree --name-only` 正常 **不代表** message 正常，反之亦然。
5. **Windows 通用**：控制台/文件两处都可能是 GBK。凡是要进 git 的中文，一律 `-F` + 对象字节验证。
