## 6. 关键说明（本轮踩到的坑）

**坑① ★ 两份工作副本"同名异体"**：
`D:\User\Desktop\比赛存档\v1\dzrobot_v2`（现役，`mission.py` SHA256 `6FAF1FD5C54F47BC`）
与 `D:\User\Desktop\dzrobot_v2`（旧副本，10-11 19:53 / `8F004907…`，**不含 t6 桥洞情报接线**）。
两份 `config/robot.yaml` **完全相同**（`ACA310FC…`）⇒ 跑错副本**不会**自己暴露。
**收口/复跑一律用 `比赛存档\v1` 这份，并注明哈希。**

**坑② ★ 编码：不加 `-X utf8` 会把绿色测试判成红**
Python 在 Windows 默认 GBK stdout，装不下断言文案里的 `✅/⚠️/❌` → `UnicodeEncodeError`
→ 脚本**直接崩**（不是"字打不出来"）。表现：整套 exit 1、结果行都没打出来。
本轮实例：`test_route` 在队长那轮被判红，实际 `python -X utf8` 复跑 **161/161 exit 0**。
**口径：全量回归统一 `python -X utf8`。**

**坑③ 情报必须在"出发前"到达**
`MissionTask` 只在出发前用情报换洞；出发后晚到的情报**只更新遥测**、不改已装路线（设计如此）。
所以 bench 里"心跳 + 情报"要一起发再让任务出发；真机里顺序见手册 §4（先机侧、后车侧）。

**坑④ 感知产物里没有 `bridge_passable` 是**对的
图纸口径不画桥顶箭头，感知管线**拒绝凭空产出**（`tools/perception/tests/test_pipeline_e2e.py:129-141`）。
bench 里换洞场景因此改用**管线自己的构造器** `build_bridge_passable()` 造报文（不手写字面串）。

**坑⑤ git 收口不能"冻住在制改动"**
收口时工作树有 t12/t13 的**未完成**改动（t13 还在改 `mission.py`）。
本卡只提交**本卡产物**（新测试 + 手册 + 日志 + 指针），不 `add -A`：
否则会把别的卡跑一半的版本冻进历史。边界已记在提交说明里。
