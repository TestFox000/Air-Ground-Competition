## 1. 项目用途：这个系统做什么

一套**智能车自主竞速 + 云台自瞄打击**系统。小车在格点化场地上**全自主**完成：

1. **循迹行进**：从起点出发，沿规划路线穿越场地，途中
   - 压过所有**"雷"**格点（8 个，必须覆盖）
   - 穿过**"桥洞"**格点（可通行窄道，需锁航向直行）
   - **避开"障碍物"**格点（8 个，不可穿越）
   - 跨越**中部绿线挡板**（只能从 A/B/C 列缺口通过）
2. **云台自瞄打击**：行进途中云台扫描搜索**红/蓝靶标**，锁定后击发（`continuous` 模式：边走边扫，全程不停车）。
3. **抵达终点** `N5` 完成任务。

**场地模型**（`config/map.yaml`，格点 A~N 列 × 1~11 行，格边长 **0.35 m**）：
- 中部**挡板**位于第 6/7 行之间，横跨 **D~N 列** → 上下半场**仅 A/B/C 列可通行**。
- 要素分四类：雷(mines)、障(obstacles)、桥洞(bridges)、靶(targets)。

## 2. 核心特征（项目设计亮点）

| 特征 | 说明 |
|---|---|
| **分层解耦** | 感知(相机+检测) / 决策(定位+路径) / 执行(底盘+云台) 三层，靠 ROS 话题松耦合，可单独调试任一环 |
| **统一参数中心** | `config/robot.yaml` 是全车**唯一**改参数处（不散落在 .h/.cpp/launch 三处），改完无需编译，重启节点即生效 |
| **参数不变量自动校验** | robot.yaml 定义三条硬性不变量（见 §5.4），`healthcheck.sh` 自动校验并比对"参数是否被节点真正声明"，杜绝"改了不起作用"的静默失败 |
| **场地约束建模** | 挡板穿越列判定、桥洞保护（K 列洞前 2.0 格锁航向直行）、障碍绕行中转点，均在路线与校验器中显式建模 |
| **走-打闭环** | path_executor 用 `/nav/scan_request` 通知云台扫描，云台回 `/shoot_count`/`/aim_status`，形成"打完再走"的协同 |
| **完善可观测性** | 浏览器实时画面(带标注) / 终端数值监控 / 出车体检 / 路线几何校验 / 端到端事件记录器，五层观测手段 |
| **工程化运维** | 一键 7 步启停、`setsid` 进程组精确回收（防残留抢设备）、模型版本化(SHA256)、日志分节点落盘、全量存档 |

## 3. 整体逻辑架构

### 3.1 三层结构

```
┌─ 感知层 ────────────────────────────────────────────┐
│  usb_cam ──/image_raw──► det_node(RKNN) ──offset_center──┐ │
│  (640×480 yuyv 30Hz)      (红/蓝靶+关键点)              │ │
└──────────────────────────────────────────────────────┼─┘
                                                       │
┌─ 决策层 ────────────────────────────────────────────┼─┐
│  编码器/IMU ─► serial_reader ──/odom/localization──► path_executor │
│                                                     │  (2476行核心) │
│  path_executor ◄──/shoot_count,/aim_status──────────┘              │
│  path_executor ──/pursuitAngle──► 底盘    ──/nav/scan_request──► 云台 │
└──────────────────────────────────────────────────────────────────┘
                    │                                   │
┌─ 执行层 ──────────┼───────────────────────────────────┼─┐
│  底盘 dzactuator_node（电机）        云台 dzactuator_node（瞄准+击发）│
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 话题图

| 话题 | 类型 | 发布者 → 订阅者 |
|---|---|---|
| `/image_raw` | Image | 相机 → det_node, cam_viewer |
| `offset_center` | Int32MultiArray | det_node → 云台, cam_viewer（含类别/偏移/框/关键点/置信） |
| `/odom/localization` | Odometry | serial_reader → path_executor |
| `/nav/waypoint` | String | send_waypoint → serial_reader, path_executor |
| `/pursuitAngle` | Twist | **path_executor** → 底盘（运动指令） |
| `cmd_vel` | Twist | 遥操作 → 底盘 |
| `/nav/scan_request` | UInt8 | **path_executor** → 云台（扫描握手） |
| `/shoot_count` | Int32 | 云台 → path_executor |
| `/aim_status` | — | 云台 → path_executor |
| `/voice_switch` | UInt8 | 云台 / path_executor（语音提示） |
| `/odom` | Odometry | 底盘 → serial_reader |

### 3.3 云台状态机
`IDLE(0)` → `SCAN(1)` 左右大幅扫描搜索 → 识别到目标 → `TRACK(2)` 锁定并小幅跟随 → 满足条件开火 → `/shoot_count` 递增 → 通知 path_executor 继续行进。

## 5. 使用方法

### 5.1 环境
```bash
source /opt/ros/humble/setup.bash
source ~/dzrobot/install/setup.bash
```

### 5.2 构建（改 C++ 后必须；Python 改完直接生效）
```bash
cd ~/dzrobot
colcon build --packages-select dzactuator rknn_pt dzrknn_dataprocess car_localization
# 或全量 colcon build
```

### 5.3 一键启停（7 步）
```bash
./start_all.sh              # 启动
./start_all.sh stop         # 停止
./start_all.sh restart      # 重启
```
顺序：**底盘 → 相机 → 定位 → 视觉检测 → 云台自瞄 → 循迹 → 网页弹窗+开浏览器**（每步间隔 2~3 s）。
- 循迹节点启动后约 `AUTO_START_DELAY`(默认 8 s) **自动出发**。
- 调试静态链路时先把 `path_executor.py` 的 `AUTO_START` 改 `False`，否则车会自己冲出去。
- `GUI_DISPLAY=:1 ./start_all.sh restart` —— 识别画面输出到 VNC（默认 :1）。
- `ROBOT_CONFIG=/path/other.yaml ./start_all.sh` —— A/B 配置对比。

### 5.4 参数中心三条硬性不变量（`healthcheck.sh` 自动校验）
1. `track_deadzone_px < fire_dz_far_px` —— 否则目标停在死区永远进不了开火框，**一发打不出**。
2. `fire_dz_far_px > 机械精度(约 12px)` —— 否则"时而打中时而打不中"。
3. `lost_frames_to_rescan` 覆盖视觉抖动周期(约 60 帧/2 s) —— 太短会误判"目标脱离视野"。

### 5.5 监控手段（五层）
```bash
tools/healthcheck.sh            # ① 出车体检（改完参数必跑）
http://<板子IP>:8080            # ② 浏览器实时画面（带检测框/关键点/偏移）
~/dzrobot/monitor_aim.sh        # ③ 终端自瞄数值
python3 tools/route_check.py    # ④ 路线几何校验
python3 tools/e2e_monitor.py    # ⑤ 端到端事件记录
tail -f ~/robot_logs/{5_gimbal,6_path,4_det,1_chassis}.log
```

### 5.6 停止 / 急停
`./start_all.sh stop`；**急停直接按底盘电源开关**。

## 7. ⚠️ 关键风险与待办（交接必读）

### P0-1 路线与 `config/map.yaml` 不一致（**最高优先级，可能导致撞障碍/漏雷**）
- `path_executor.py` **不读取 map.yaml**（全文 0 处引用），路线为硬编码 `MISSION_BLOCKS`：
  ```
  K7 → K9 → J9 → D10 → B9 → E7 → B7 → B5 → C5 → B3 → B1 → A1 → D2 → E4 → F4 → J5 → K1 → N5
  ```
  其覆盖的雷 = {J9, D10, B9, E7, C5, A1, F4, J5}，桥洞 = {K7, K1}。
- 但 `config/map.yaml`（"Map-C 第三次测试图"）声明：
  - 雷 = {H1, G2, A3, C4, B5, G6, E7, I10}
  - 障 = {B1, I2, F7, C8, E8, A9, H9, D10}
  - 桥洞 = {K2, K8}，起点 N10，终点 N5
- **冲突点**：路线途经的 `B1`、`D10` 在 Map-C 中恰为**障碍**；路线覆盖的雷与 Map-C 雷集合**几乎不重合**。
- **必须现场确认当前物理场地对应哪套要素**。若为 Map-C：用 `tools/global_planner.py` 依 map.yaml 重新生成路线，再用 `tools/route_check.py` 校验（后者**确实读取 map.yaml**）。
- 注：路线的起终点(N10→N5)与挡板约束(D 列起、行 6/7)与 map.yaml 一致，说明两者同源但**要素版本不同步**。

### P0-2 云台持续扫描但识别不到目标
实测 `5_gimbal.log` 连续"一轮扫描结束未发现目标"，`offset_center` 的 `data[2]=0`（无类别），检测链路本身健康（30 Hz 不掉帧）。排查顺序：
1. 浏览器看画面确认赛道是否真有靶纸；
2. **垂直扫描层数不足**（当前 8 点 × 1 层，靶若偏高/偏低扫不到）；
3. 靶太小/太远低于 `BOX_THRESH`；
4. `robot_color` 与模型输出类别是否匹配（1=蓝/2=红）；
5. 曝光/逆光。
验证法：拿靶纸在相机前慢晃 → 出现框 → `data[2]≠0` → `/aim/status` 跳 2(TRACK) → 云台停止大幅摆动改跟随。

### P1
- 相机清晰度是**镜头光学问题**（实测锐度 22，调 sharpness/对焦无效；驱动不支持高分辨率 MJPEG）→ 擦镜头/手动旋焦/确认目标在 0.5~2 m。
- 落地实跑验证两个最紧点：`B5` 过挡板缺口、`B3` 绕障（首次建议架空或降速）。

### P2
- **初始化 git 仓库**（当前无版本控制，风险高）。
- 填充 `docs/`（空）、清理 `archive/`（空）。
- 确认 `A8` 是否真为障碍（影响里程优化空间）。

### 其他必读
1. 改 C++ 必须 `colcon build`；改 Python 直接生效。
2. 参数只改 `config/robot.yaml`，改完跑 `healthcheck.sh`。
3. 视觉窗口 `DISPLAY=:1`（VNC）与 `:0`（HDMI）隔离，不可跨屏。
4. 不要手工 `pkill` 清进程（实测会漏杀，已出两次事故），用 `./start_all.sh stop` 或 `kill -9 <pid>`。
5. 网页弹窗占 8080，冲突时换端口。
6. 换模型走"版本号 + SHA256"，软链指向 `src/rknn_pt/model/light_det.rknn`。
7. **不要删除 `.codebuddy/`**（项目数据，非缓存）。
8. 共享代码脱敏：勿带模型/标定表/抓帧/日志（含场地信息）。
