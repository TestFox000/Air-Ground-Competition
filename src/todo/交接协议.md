# 协作交接协议（武将 ↔ 文官）

> 本文件是**最高约定**，冲突时以本文件为准。两方每次动手前必读。

## 1. 分工

| 角色 | 职责 | 产出 |
|---|---|---|
| **武将**（写代码/做项目） | 改代码、改配置、跑构建、自测、修 bug | 代码变更 + **本目录交接文件** |
| **文官**（审阅/写日志） | 代码审阅、核对真实状态、写日志与技术文档 | `src/history/log/*.md` + `src/history/book/*.md` + **本目录交接文件** |

## 2. 交接文件（各一份，覆盖式更新）

```
src/todo/交接_武将.md    ← 武将写，文官读
src/todo/交接_文官.md    ← 文官写，武将读
```

- **覆盖式**：只保留**当前最新状态**，不写流水账（历史在 `history/log/`）。
- **文件名固定**，不要带日期后缀，避免出现多份导致读错。

## 3. 铁律（双方都必须遵守）

1. **动手前必读对方交接文件**；读不到（不存在/为空）就先问，**不要靠猜**。
2. **干完活必须更新自己的交接文件**，哪怕这次只改了一行。
3. 交接必须写清四件事：**改了哪个文件 / 为什么改 / 验证了什么 / 还差什么**。
4. **有 P0/P1 风险必须显式点名**，并写清影响面（会不会撞车、会不会负优化）。
5. **不确定的写"待确认"**，不要替对方下结论，也不要擅自改对方的产出
   （武将不改 `history/`，文官不改代码与 `config/`）。
6. **改完必自测**并在交接里贴出**证据**（命令 + 关键输出），不要只写"已修复"。
7. 交接末尾**明确提醒对方**：请阅读并回写你的交接文件。

## 4. 边界（避免互相覆盖 / 负优化）

| 归谁 | 不要碰 |
|---|---|
| 武将 | `src/history/**`（文官的产出）、`config/*.yaml` 之外的既有数据文件 |
| 文官 | `src/**` 代码、`config/**`、`tools/**`（武将的产出） |

- `config/robot.yaml` 与 `config/map.yaml` 由武将改；文官只**核对**并在日志里记录其状态。
- 文官发现代码/配置有问题时：**写进交接文件提给武将**，不要自己改。

## 5. 交接文件统一格式

```markdown
# 交接 · <角色> → <对方>
- 更新时间：YYYY-MM-DD HH:MM
- 本次一句话：...

## 1. 改动清单（文件级）
| 文件 | 改了什么 | 为什么 | 风险/影响 |

## 2. 验证证据（命令 + 关键输出）

## 3. 未完成 / 需对方处理

## 4. 坑与注意（给对方审阅的提示）

## 5. 给对方的请求（请回写你的交接文件）
```

## 6. 典型协作节奏

```
武将：读 交接_文官.md → 干活 → 自测 → 写 交接_武将.md
                                      ↓
文官：读 交接_武将.md → 审阅/核对 → 写 log + 技术文档 → 写 交接_文官.md
                                      ↓
                                   循环
```
