## 2. 各瓶颈详细分析与改进方案

### 2.1 🔴 无人车画圆问题

**根因**（已定位）：`reset:N10,y` 盲目断言车朝向=90°，与真实朝向存在固定 68.6° 偏差。
车只有航位推算、没有绝对朝向参考，无法自己知道真实朝向。

**已实施的解决方案**：align 模式
- 用无人机 0x4002 帧的真实 yaw 闭环原地转向到 `start_heading` 断言方向
- 零残差根除画圆
- `path_executor` 无路线时不占 `/cmd_vel`，可直接发角速度控制底盘

**实车验证前置条件**：
1. ✅ align 模式代码完成
2. ⚠️ 无人机需广播 0x4002 车位姿帧（依赖 Orin 在线）
3. ⚠️ 确认 `path_executor` 无路线时不占 `/cmd_vel`

**🔄 绕过方案（如果 0x4002 帧不可用）**：
- **方案 A（人工摆位）**：人工将车摆到朝向与地面格线严格平行（目视校验），然后 `reset`。缺点：依赖人眼精度，误差可能 ±10°。
- **方案 B（车载相机辅助）**：用车端相机识别地面格线，计算车与格线的夹角，修正朝向。缺点：需要额外开发，时间紧。
- **方案 C（开环转向补偿）**：在 reset 后，固定向左/右转 68.6° 补偿。缺点：偏差可能因摆位不同而变化，不通用。
- **推荐**：优先用 align 模式；如果时间来不及，用方案 A 人工摆位 + 抓帧目视校验。

### 2.2 🔴 Orin 不在线

**现状**：Orin 10.136.36.104 未连接到 WiFi 网段（10.136.36.0/24），网段内只有路由器和本机。

**可能原因**：
1. Orin 未连接 WiFi（SSID: win, 密码: 12345678）
2. Orin 用 Type-C NCM 连接，IP 不同
3. Orin 未开机

**解决步骤**（需用户操作）：
1. 确认 Orin 已开机
2. 在 Orin 侧连接 WiFi（SSID: win, 密码: 12345678）
3. 或用 Type-C NCM 连接，查看分配的 IP
4. 确认后通知经理，Agent-4 立即启动编译部署

**🔄 绕过方案（Orin 短期无法上线时）**：
- 用 `fake_udp_sender.py` 模拟无人机 UDP 广播，先验证车端链路
- 用训练好的模型在本机做离线推理验证
- **但真机联调无法绕过**，必须 Orin 上线

### 2.3 🟡 7cls 检测模型未收敛

**现状**：epoch 21/75，mAP50=0.771，val loss 仍波动。

**对完赛的影响**：
- 即使模型未完全收敛，只要能检测到主要目标（地雷、靶标），就能完赛
- 得分会受影响，但不完赛失败

**改进方案**：
1. **继续训练至收敛**：预计 5-8 小时，Modern Standby 已禁用防中断
2. **用当前 best.pt 先验证**：如果时间紧，可以用当前模型先上真机验证链路，后续再替换
3. **TTA 增广推理**：测试时用多尺度+翻转提升召回率

**🔄 降级方案**：
- 如果训练在比赛前未完成，用 v2 模型（Recall=0.731，已在官方74张上验证）作为备份
- v2 模型已入库 `models/release/aerial_field_detector.pt`

### 2.4 🟡 格号识别跨批次泛化差

**根因**：v4a/v4b 过拟合训练批次的低层成像特征（特定高度的模糊模式、色温、噪点纹理）。

**现状**：v4c 训练中（含新帧原图+增广+v4b成分）。

**对完赛的影响**：
- 格号识别失败 → PnP 定位失败 → 无人机无法自定位 → 情报无坐标 → 无法完赛
- **这是比检测模型更关键的瓶颈**

**改进方案**：
1. **v4c 继续训练**：含更多批次数据，减少单帧过拟合
2. **强域增广**：模糊、色温、噪点、尺度变化
3. **多帧融合**：用连续多帧的格号识别结果投票，提升鲁棒性
4. **格号几何约束**：利用格号排列的规律性（相邻格号连续）纠错

**🔄 降级方案**：
- 如果 v4c 泛化仍差，用**已知格号的位置先验**：格号世界坐标已知，只要识别出部分格号就能定位
- 用 RANSAC 剔除异常识别结果

### 2.5 🟢 桥洞通行剐蹭风险

**现状**：桥洞仅在 L 列，路径规划已约束正交贴门。

**改进方案**：
1. 路径已避开 K 列（桥洞占整列）
2. 停靠射击位选择正对轨道端点的正交相邻格
3. 路径点压缩，保留拐点和必经点

**🔄 降级方案**：
- 如果担心剐蹭，可绕行（增加里程但更安全）
