# 循迹回报与续轮模板

每轮只有 Lead 汇总一份 `REPORT.md`；Reviewer 单独写 `review.md`。`MANIFEST.json` 列出本轮交付文件的哈希，但不包含自身。用户向本会话转交摘要即可开始复核，有争议时再补最小原始证据。不要把长日志全部贴进聊天。

## 1 可转交摘要

复制以下模板填实值，控制在约 700 字。没有证据的字段填写“未验证”并写原因，不能留成默认成功。

```text
【循迹团队回报】
卡号/日期/轮次：
结论：已收口 / 未收口 / 需现场配合
本轮唯一假设：
本轮实际改变的变量：R0应为“无生产改动”

基线：
工作区/车仓HEAD/脏文件：
本地与车端源码哈希：
配置/地图/路线来源与SHA256：
证据等级：源码 / 离线复现 / 仿真 / 实车 / 历史

核心结果：
普通对照：
ALIGN（进入分支证据、限速输入、最终v）：
PIVOT TURN（进入分支证据、限速输入、最终v）：
Safety非OK对照：
复现结论：已复现 / 本用例未复现 / 无效或阻塞

既有测试：运行N套，通过N，非零退出N，未运行N；失败ID及归因：

完整REPORT/探针/日志/review/MANIFEST绝对路径：

```

## 2 完整 REPORT 结构

### 本轮任务卡

- 目标与范围；owner 和 reviewer。
- 读过的台账条目。
- 复用检索及唯一权威实现。
- 新增脚本/模块及理由；没有则写无。
- 验收命令和预期；回滚点。
- 开始/结束时间与现场操作状态。

### 基线和来源

记录根仓与车仓 HEAD、开始/结束 git status、已有改动清单、本轮 diff、被测文件及探针 SHA256、Python 路径/版本。测试加载文件路径须与被测哈希对应。

现场配置分“文件值”和“运行时值”，不要混写。地图分仓库回归图、车端文件、现场实物；本轮没有路线就写不适用，不虚构路线哈希。

### 逐项复现

| case ID | 基线/候选 | 分支进入证据 | 限速输入 | 最终发布 v/steer | 预期 | 断言/退出码 | 原始输出行号 |
|---|---|---|---|---|---|---|---|
| 待填 | 待填 | 如TURN且未完成 | 待填 | 待填 | 待填 | 待填 | 待填 |

每项注明事实、解释、替代解释和置信度。正常运行、分支覆盖、契约通过分别记录。R0 的缺陷探针失败不要被写成“测试全部通过”。

### 复跑命令

| ID | cwd绝对路径 | 完整命令及环境变量 | 退出码 | 原始输出文件 | 关键输出 |
|---|---|---|---|---|---|
| 待填 | 待填 | 不含凭据 | 待填 | 待填 | 待填 |

日志保留实际失败与标准错误。不要只保留最后一条命令的退出码。新一轮使用新日志名/目录，不能覆盖历史基线。

### 既有测试与门禁

分别列相关测试、缺陷探针、工作流门禁，三个分母不能混用。红项按失败 ID 和基线证据归因，不能因套件已在 known-red 就忽略新的失败。未执行的全量回归、仿真、实车明确列为未执行。

### 变更和回滚

逐文件 owner、变更理由、冻结登记、影响面、回滚备份哈希。只有生产修补轮需要生产 diff。不要在回滚建议中使用全仓 reset、clean 或覆盖别人的文件。

### 独立审阅

Reviewer 是否检查了最终发布值、分支前提、导入版本、原始失败、无信号对照、写域和声明范围；有争议就列出未决证据。

### 下一轮建议

最多一个主目标：新证据是什么、拟改哪些文件、唯一变量、验收/停止/回滚标准、是否需要现场配合。建议不等于获准执行。

## 3 转交哪些内容

- 同机：转交摘要和本轮 `REPORT.md`、`review.md`、`MANIFEST.json` 的绝对路径，本会话按需读取。
- 复现争议：再提供 `control_probe.py`、命令、原始输出及相关源码哈希；不是只给截图或口头结论。
- 异机或网页：只传经检查的必要文档/证据片段，不发 `.git`、整份 `_tmp_session` 或完整历史包。不要声称本模板已经替实际附件完成脱敏。

## 4 下一轮派工格式

```text
reviewer及只读范围：
冻结登记要求：
复用实现与测试：

```
