## 1 执行原则

1. **先证定位和控制，再调前视与速度。** 规划器决定走哪条路，循迹负责实际运动；本轮范围是后者。保留现有纯追踪、投影、PIVOT 和测试框架。
2. **每轮一个假设、一个主改动。** 左右弯、不同速度是同一假设的验证样本，不代表可以同时修改多个参数。连续两轮无改善或无新增证据，停止该方向并说明原因。
3. **证据分级。** 使用〔源码〕〔离线复现〕〔仿真〕〔实车〕〔历史〕〔未验证〕；读到代码、跑通仿真、实车通过是不同结论。
4. **按文件分工。** 一个文件一个写者；共享治理文件由 Lead 单写，Reviewer 只审阅。已有脏文件归原 owner，禁止顺手清理、暂存、覆盖或提交。
5. **只认已核对的运行对象。** HEAD 不能代表脏工作树；磁盘源码不能代表运行中的 import 路径；配置文件不能代表进程实际加载值。缺哪层证据就保留哪层未知。
6. **使用实际可用的团队工具。** 不假设特定模型上下文长度、并发数或 API 名称。建议 Lead 加 3 名子智能体；并发不足则排队，不编造 spawn 成功。

### 5.2 最终限速契约复现

只读审阅发现一个待证假设：普通控制器处理了 `P_MOTION_LIMIT`，但 Tracker 后续 PIVOT 和 ALIGN 分支可能覆盖速度。R0 只复现，不修补。

复用 `test_tracker.Rig` 与 `test_pivot.Rig`，只用 FakeBridge、FakeClock。不得实例化 RosBridge。每个 case 独立初始化，明确导入文件路径和 SHA256。

| 场景 | 必须先成立的前提 | 限速输入 | 检查对象 |
|---|---|---|---|
| 普通纯追踪对照 | DRIVE、安全 OK、位姿有效，基线速度非零，不在 ALIGN/PIVOT | 缺失或 None、0、低于基线的正上限 | `bridge.commands[-1]` |
| ALIGN | 真正命中桥洞保护段，`align=True`，未被 PIVOT 接管 | 同上 | 最终发布速度和 reason_tag |
| PIVOT | 必须进入 TURN，持续航向误差大于完成容差；SETTLE 不算覆盖 | 同上 | 最终发布速度、pivot_phase |
| 门控对照 | 同一有效场景改为 `SafetyState.ok=False` | 维持既定限速输入 | 最终停车；该对照不替代上述限速测试 |

零限速：最终发布速度绝对值不超过 `1e-9`；正限速：`abs(v) <= limit + 1e-9` 且数值有限；正上限可取基线实际速度的一半。每例写明分支进入证据、注入前后状态、最终命令。撤回限速另作恢复对照。

`speed_reason` 可能仍来自普通控制器的中间结果，不能据此宣称实际已限速。记录最终命令、`reason_tag`、`align`、`pivot_phase`。

探针必须完成全部 case 再汇总非零退出，或逐例独立运行。单例断言失败不能让剩余矩阵静默漏跑；异常另记“无效”，保留 traceback，不吞成 PASS。

结果只能是：

- **已复现**：目标分支成立，契约断言失败，保存原始非零退出码。
- **本用例未复现**：目标分支成立，断言通过；不能推广为所有场景正确。
- **复现无效或环境阻塞**：分支没进入、没有最终发布、版本不符、依赖失败；不能算 PASS。

维持 `SafetyState.ok=True` 是为了隔离 Tracker 的限速契约，不是在证明整车 Safety 失效。不得把整车尚未发生的后果写成实车事故。

### 5.3 定位和底盘审阅

motion-auditor 输出短表：原始 pose、IMU、左右轮增量、指令速度/舵角、物理观测，各自来源、单位、时间戳、现有记录手段与缺口。

必须保留两条区别：

- 平移速度近零不等于没有原地旋转；架空、人手转车和航向链异常需要不同证据。不能先放宽守卫。
- 信念吸附到格心不等于物理车到格心；标定用原始定位和外部物理测量，避免用校正后的信念自证。

| 仿真退出码 | `sim_cli.py:221` 可能在结果失败时仍返回 0 | 检查 completed、diverged、轨迹与真值误差；碰撞结论还必须证明 `field_modeled=1` |
| PIVOT 仿真 | `sim.py:108` 明确不建模 PIVOT，pivot 参数在该仿真无效 | `test_pivot.py` 验状态机，随后人工配合实车验证；不能拿普通仿真证明换向 |
| `plan_route.py` | 校验异常可能被转为字符串，退出 0 不保证所有检查完成 | 审核 plans、route_check 和 validate[].issues；异常字符串或检查缺失均不算通过 |
| `deploy_to_car.py all` | 默认推送不只本卡文件，含配置与其他模块；all 为 backup/push/build，不自动 verify | 部署前核对清单和车端差异，保护现场配置；最终替换由人执行，之后单独 verify 与实车验收 |
| `cam_viewer.py` | 历史上曾竞争发布零速到 pursuitAngle | 发车前确认命令写者和订阅者；R0 不 kill 进程或改变现场状态 |

后续静态规划命令形状，仅供被派到相应轮次时使用：

```powershell
python -B -X utf8 tools/plan_route.py --config "$roundDir/robot.yaml" --map "$roundDir/map.yaml" --engine tour --check --validate --emit json
```

临时 robot 配置必须记录来源哈希、精确改动键和解析后的生效值；不得直接改仓库/车端默认值。不能假设 YAML 命名空间下的键已被 Config 正确加载。

## 9 回报与停止

使用 [32 回报模板](32_循迹回报模板.md)。Lead 的聊天回复只放可转交摘要和本机证据路径，完整输出留本卡目录。

R0 结束条件：基线、复现矩阵、既有测试结果、motion 审阅、独立 review、工作流门禁和写域核对均已交付；阻塞项必须明确。证据不全可以交“未收口报告”，不得伪装已完成。

下列情况停止相关支线，其余独立工作可继续：

- 冻结区或既有源码意外变更、其他任务正在写同一文件、测试加载了错误版本。
- 探针接触真实 ROS/硬件、需要启动设备才能继续、需要超出本卡的部署或运动。
- 配置/地图来源不明，或不能证明目标控制分支已进入。
- 缺依赖、无法获取证据、连续两轮无新增证据。不能为绕过阻塞而扩大写域或安装替代框架。

人工现场动作另有异常运动时，按已确认的停机手段先 stop 再报告。R0 不会执行现场运动，不能把这条当成可自行发车的授权。

用户把 `REPORT.md`、`review.md`、探针源码和关键原始输出转回后，本会话将给出：证据是否成立、哪些结论需降级、下一轮唯一目标、允许写域、复跑命令、通过标准及回滚条件。报告中不要包含口令、密钥或完整历史仓库。
