# 飞控链域号统一切换单（0 → 118）

> **一页纸 · 现场执行版**。对象：PX4 的 `UXRCE_DDS_DOM_ID` 与 Orin 上全部 ROS 启动点的 `ROS_DOMAIN_ID`。
> **本单不改代码、不改车**；机端改动由现场按本单手工执行。回滚 = 两侧一起回 0。
> **背景**：现网 `/fmu/*` 在域 **0**（`autostart_agup.sh` / `start_drone.sh` 都没 export），而 dzlink 与小车在 **118**。后果是"在 118 的终端里永远看不到 `/fmu`"，被误判成飞控通信断了（见 [无人机架构总览.md](无人机架构总览.md) §6 审计）。

---

## 0. 一句话原则

**PX4 的域号决定 uXRCE 代理参与者的域，Orin 上每个 ROS 节点的 `ROS_DOMAIN_ID` 决定它加入哪个域；两者必须相等。**
只改一侧 = `/fmu/*` 与机侧节点分居两个域 = **静默失联**（不报错、不超时，就是互相看不见）。

| 侧 | 开关 | 现值 | 目标 |
|---|---|---|---|
| PX4 飞控 | 参数 `UXRCE_DDS_DOM_ID` | 0（默认） | **118** |
| Orin 全部 ROS 节点/代理/看门狗 | 环境变量 `ROS_DOMAIN_ID` | 未设 = 0 | **118** |
| 小车（不动） | `dzros.env` / `start_all.sh` | 118 | 118 |

执行顺序（**不可颠倒**）：**① PX4 参数（飞控在线时） → ② Orin 脚本 → ③ 重启 agent → ④ 验证**。
总耗时约 10 min，其中飞控断电 5 s + 上电枚举 ~20 s。

## 1. 前置检查（2 min）

```bash
# 1) 飞控在不在
ls -l /dev/ttyACM0 && udevadm info -q property -n /dev/ttyACM0 | grep ID_MODEL   # 期望 HKUST_UAV_NxtPX4

# 2) 现在是不是域 0（基线）
echo "shell ROS_DOMAIN_ID=${ROS_DOMAIN_ID:-<unset=0>}"
ros2 topic list | grep '^/fmu/out'          # 若能看到，说明当前在 0 且 agent 活着

# 3) 记下现有 agent/看门狗 PID（回滚要用）
pgrep -af "MicroXRCEAgent|orin_agent_watchdog"
```

**工具准备**：能改 PX4 参数的一条通道（QGC 数传 / USB-TTL 接 TELEM / MAVLink Console）。
**如果没有这条通道 → 本单不能执行**（改不了 PX4 侧，切一半比不切更糟）。

### 1.1 现场排查线索：14:59:38 是否发生过供电/插拔扰动（**未验证，待查**）

两条互相独立的现象落在**同一秒**：

| 现象 | 时刻 | 来源 |
|---|---|---|
| 飞控 uXRCE 客户端最后一次 `create_publisher`（此后会话再未建立） | **14:59:38**（epoch 1792220378） | `~/drone_logs/agent_watchdog_agent.log` |
| 小车侧投影轨迹跳变 | **14:59:38.2 ~ 14:59:39.2** | 车侧日志（本轮未登车核实） |

两台机器**独立供电**，理论上不该相关；但同一秒的耦合不能靠"理论上"排除。执行本单前/排查时请确认：

```bash
# 1) 当时有没有掉电/重启（Orin 侧）
last -x | head -8                       # shutdown / reboot 记录
journalctl --list-boots | tail -3       # 引导次数与时间
journalctl -b -1 -k | grep -iE "usb|power|brownout|Undervoltage" | tail -20

# 2) 有没有 USB 重枚举（飞控/相机/雷达）
dmesg -T 2>/dev/null | grep -iE "cdc_acm|ttyACM|usb .*disconnect|reset" | tail -20
#   若 dmesg 被内核权限挡住，用：journalctl -k --since "2026-10-17 14:50" | grep -iE "usb|acm"

# 3) 人为动作回忆/记录：14:59 前后是否拔过线、插过电池、动过 USB hub、开关过电源排
```

**判读**：
- 若确认当时有掉电/拔插 → 视为**供电/接插件可靠性问题**，本单可继续，但要同步做"防松动/独立供电"整改；不要把它当域号问题的解释。
- 若没有任何供电事件 → 两次"同一秒"更可能是巧合或共同上游（如同一个 WiFi AP 重启、同一条 12V 母线），记录到执行记录里供后续复盘。
- **本项不阻塞切换单执行**（切换单本身不依赖它），但现场记录必须留痕。

## 2. 步骤 ①：改 PX4 参数（飞控在线时做）

### 方式 A · QGC（推荐）

1. QGC 连上飞控 → **Vehicle Setup → Parameters**；
2. 搜索 `UXRCE_DDS_DOM_ID` → 改为 **118**；
3. 搜索 `UXRCE_DDS_CFG`，确认它是当前接线对应的串口（**不要在这里改**，只确认）；
4. 点 **Tools → Reboot Vehicle**（或断电重启）。

### 方式 B · MAVLink 控制台（QGC → Analyze Tools → MAVLink Console）

```text
param show UXRCE_DDS_DOM_ID
param set UXRCE_DDS_DOM_ID 118
param save
reboot
```

> `param set` 后必须 `param save`（写 FRAM），再 `reboot` 让 `uxrce_dds_client` 用新域号重建会话。
> 命令语义来自 PX4 官方文档；**本板（NxtPX4）未实测**（当前没有可用的 MAVLink 通道）。

**此步完成后**：PX4 侧在 118，Orin 侧还在 0 ⇒ **链路此刻是断的**（正常，继续步骤 ②）。

---

## 3. 步骤 ②：改 Orin 的三个启动点（各一行）

> 三个点必须同时改，否则"看门狗在 0、agent 在 118"会互相误杀。

### ②-1 `~/dzuav_deploy/air_ground/tools/autostart_agup.sh`

在第 25 行（`source /home/duzhong/dzpx4/install/setup.bash …`）之后、`cd $REPO` 之前插入：

```bash
export ROS_DOMAIN_ID=118
export ROS_LOCALHOST_ONLY=0
```

效果：**agent 与看门狗都继承 118**（`setsid nohup` 在同一个 shell 里，第 28/31 行）。

### ②-2 `~/start_drone.sh`

在第 21 行（`source "$WS/install/setup.bash"`）之后插入同样的两行：

```bash
export ROS_DOMAIN_ID=118
export ROS_LOCALHOST_ONLY=0
```

效果：一键栈的 7 个节点 + 两个终端里的 teleop/path 全部落在 118。

### ②-3 `~/dzuav_deploy/air_ground/tools/orin_agent_watchdog.py`

**如果只改 ②-1，这步可以不改**（看门狗继承 118，拉起 agent 时自动带上）。
若要加固（防止有人绕过 autostart 直接跑看门狗），FC_OFFLINE 补丁已包含：`restart_agent()` 会把本进程的 `ROS_DOMAIN_ID` 显式前置到 agent 启动命令里：

```python
env_prefix = f"ROS_DOMAIN_ID={domain} " if domain else ""
cmd = f"{env_prefix}setsid MicroXRCEAgent serial --dev {dev} -b 921600 ..."
```

见 `_tmp_session/drone_arch/orin_agent_watchdog_fc_offline.py`（本单不含部署动作）。

## 4. 步骤 ③：重启 agent（让新域号生效）

```bash
# 先停看门狗，避免它按旧节奏插一脚
pkill -f orin_agent_watchdog
pkill -f "MicroXRCEAgent serial"
sleep 2

# 用与 autostart 相同的方式拉起（模拟开机路径，验证脚本改动本身）
bash ~/dzuav_deploy/air_ground/tools/autostart_agup.sh start

# 确认三个进程都在 118
for p in $(pgrep -f "MicroXRCEAgent|orin_agent_watchdog"); do
  echo -n "$p "; tr '\0' '\n' < /proc/$p/environ | grep '^ROS_DOMAIN_ID=' || echo '<unset=0>'
done
```

**期望**：agent 与看门狗两行都打印 `ROS_DOMAIN_ID=118`。

## 5. 步骤 ④：验证（命令写死，逐条对照）

```bash
# V1 域 118 下必须看得到飞控侧话题
ROS_DOMAIN_ID=118 ros2 topic list | grep '^/fmu/out'
#   期望：/fmu/out/vehicle_local_position、/fmu/out/vehicle_status 等（>=2 行）

# V2 域 0 下必须看不到（证明没有残留进程还在 0）
ROS_DOMAIN_ID=0 ros2 topic list | grep '^/fmu/out'
#   期望：空（0 行）

# V3 118 下确实有发布者 + 数据流
ROS_DOMAIN_ID=118 ros2 topic info -v /fmu/out/vehicle_local_position | grep "Publisher count"
#   期望：Publisher count: 1（或 >=1）
ROS_DOMAIN_ID=118 timeout 10 ros2 topic hz /fmu/out/vehicle_local_position
#   期望：稳定频率（PX4 的 vehicle_local_position 通常 10~50 Hz）

# V4 机侧节点与飞控同域（例：control 节点起来后）
ROS_DOMAIN_ID=118 ros2 node list | grep -E "px4_control|fast_lio|px4_odom"
```

### 判读矩阵（V1 × V2）

| 118 下 `/fmu/out` | 0 下 `/fmu/out` | 结论 |
|---|---|---|
| 有 | 无 | ✅ 两侧都在 118，切换成功 |
| 无 | 有 | ❌ **只有 Orin 切了**：PX4 参数没生效/没重启 → 回步骤 ① |
| 无 | 无 | ❌ agent 没起来 / 串口被占 / PX4 掉电 → 按 uXRCE 手册 L0/L4 |
| 有 | 有 | ❌ 有残留进程还在 0（双 agent 或另一个看门狗）→ `pgrep -af` 清干净 |

> ⚠️ 只 grep `fmu` 会把 `/fmu/in/vehicle_visual_odometry`（本机 px4_odom_convert 发布的本地话题）也算进来，**必须用 `'^/fmu/out'`**。

## 6. 回滚（同样两步，顺序相反）

1. **Orin**：删掉 ②-1 / ②-2 里加的 `export ROS_DOMAIN_ID=118`（或改成 0），`pkill -f orin_agent_watchdog`、`pkill -f "MicroXRCEAgent serial"`，再 `autostart_agup.sh start`；
2. **PX4**：`param set UXRCE_DDS_DOM_ID 0` + `param save` + `reboot`（或 QGC 参数页改回 0 重启）；
3. 复验：`ROS_DOMAIN_ID=0 ros2 topic list | grep '^/fmu/out'` 有输出、`ROS_DOMAIN_ID=118 …` 无输出。

**回滚判据**：若切换后 24 h 内出现"飞控链路偶发不可见"，优先整体回滚到 0 再做二分；不要单侧回滚。

## 7. 风险与注意

| 风险 | 说明 / 处置 |
|---|---|
| **只改一侧** | 直接失联且零报错；本单要求三步一起做，做完立刻跑 §5 |
| **忘了重启飞控** | `UXRCE_DDS_DOM_ID` 只在客户端启动时读一次；改完必须 reboot/断电 |
| **看门狗在 0、agent 在 118** | 看门狗永远收不到遥测 → 每 60 s 误杀 agent。②-1 必须让两者同域 |
| **车机同域后的可见性变化** | 小车会看到机侧 `/livox/*`、`/fmu/*` 等；机侧会看到车侧 `/aim/*`、`/nav/*`。这是**预期**，不是污染；带宽增加有限（点云桥本来就要发） |
| **话题名撞车** | 车侧已有 `/imu_data`；机侧 IMU 桥发的是 `/fmu/out/imu_data`，不冲突 |
| **旧脚本按域 0 写死** | 现场所有诊断命令都要显式带 `ROS_DOMAIN_ID=118`；建议把 export 写进 `~/.bashrc` |
| **PX4 域号参数不可用** | 若固件未编译 uXRCE 域号支持 / 无 MAVLink 通道 → 本单不执行，保持 0 并另行裁决车侧域号 |
| **切换窗口内飞行** | **禁止**。切换期间飞控与机载失联，必须在桌面/地面完成 |

## 8. 与"飞控恢复三步卡"的关系

- 现在（19:2x）链路是**会话死**状态，先按《飞控恢复三步卡》把会话救回来；
- 救回来之后**再**决定是否切 118（切 118 会让飞控再重启一次，等于再走一遍"断电重启 → 验会话"）；
- 顺序建议：**先在域 0 把会话救活并验一遍（证明硬件链没问题）→ 再切 118 → 再验一遍**。这样出问题时能立刻区分"是切换错"还是"链路本身坏"。
