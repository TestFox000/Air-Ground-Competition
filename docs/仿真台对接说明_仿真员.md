## ③ 官方 tools/sim_map_render.py 与本页车身疏密不同的口径说明

官方工具 `:276-283` 的实现：
```python
for i, row in enumerate(reader):
    if i % 4 == 0:                 # 50Hz→12.5Hz 抽样，够平滑
        ...
        if i % 125 == 0:           # 注释写「每 2.5 s 画一个车身」
            car_poses.append(...)
```
`i % 125 == 0` **嵌在** `i % 4 == 0` 里面，而 125 % 4 = 1 ⇒ 只有 `i % 500 == 0` 才命中
⇒ 实际**每 500 数据行 = 10 s** 才画一个车身，与其自身注释不符（嵌套相位 bug）。

本页（sim.html）按注释**声明的意图**实现：独立抽样、每 125 数据行（2.5 s）一个车身、首行必画。
⇒ **同一份 traj.csv，本页车身比官方 PNG 密 4 倍是预期行为**，不是画错。
该 bug 已留档上报工具属主裁决（不在仿真队写域，未修）；官方工具修复后本页无需改动。

## ④ GPU 口径（重要，防止误报）

- 仿真链路（bench / sim 跑分、地图渲染、轨迹图）是**确定性 CPU 计算**：无推理、无模型加载、无 GPU 任务。
- 因此**不加任何 GPU 开关/监控字段**——加了就是假开关。仿真台指标里没有 GPU 利用率属正常。
- GPU 只在**真机无人机 YOLO 检测阶段**使用（dzrknn 侧），与仿真台无关。
- 若有人要求"仿真台显示 GPU 占用"，正确回应是引用本节，而不是实现一个恒 0 的假字段。

## ⑤ 改点位流程（config 零写入）

想试不同雷/障/桥布局时：
1. 在**运行目录**写 override（`src/simbench.js` 支持的 override 目录，内放改过的 `map.yaml`；它与同目录的 run 产物一起构成"这次跑的是哪张图"的完整证据）；
2. 或直接在仿真台页面表单里改点位（ mines/obstacles/bridges 文本框 + 靶朝向 select），页面只在改了点位时才把 `field` 带进请求体；
3. **绝不直接改 `config/map.yaml`**——它是唯一地图真源，被 route_check/规划器/真车共用；绕过工具链手改会破坏行号钉与回滚语义。

靶朝向（select：跟随地图/横向/竖向）只影响渲染与台账（`run_meta.jsonl` 记 `targetYaw`），**不改仿真物理**（宿主 `sanitizeParams` 挡非 h/v 值，不进 overrides）。
