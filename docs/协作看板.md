# 双机协作看板

> 两台电脑同时推进一个项目，最怕的是**同一件事两边各做一遍**，或者**改了同一处互相覆盖**。
> 这个文件就是为了避免这两件事。每次开工前花 30 秒看一眼第 2 节和第 4 节。

---

## 1. 机器分工

| 机器 | 定位 | 负责 | 不负责 |
|---|---|---|---|
| **A 机**（本机 / 现场机，Windows + Python 3.10） | 现场联调 + 算法 | `ag_core` 算法、单元调试、车端命令（`car-rehearse` / `car-fetch` / `car-camera`）、单应标定、复盘报告、文档 | 训练、导出模型 |
| **B 机**（模型机） | 训练 + 导出 | 数据集标注、`tools/ml/train_pose.py`、ONNX→RKNN 导出、`verify_contract.py` / `verify_decode.py` 参数标定 | 车端联调、现场操作 |

**A 机已装**（不装 torch，跑不动也不必跑）：
`numpy` `pytest` `paramiko`（SSH 连车）`PyYAML` `pyserial` `opencv-python`

**B 机需要装**：
```bash
pip install -r requirements.txt          # numpy + pytest
pip install -r requirements-train.txt    # torch / ultralytics / onnx / onnxsim
```
⚠️ `rknn-toolkit2` 只有 Linux x86 wheel —— **转 RKNN 那一步必须在 Linux 上做**（B 机或直接在车端）。
Windows 上只能做到导出 ONNX。

---

## 2. 开工三步（拿起任何一台机器都先做这个）

```bash
git pull                    # ① 拿到对方的最新进展
# ② 看下面第 4 节「🟡 进行中」里有没有人已经领了同一件事
# ③ 把你要做的事改成 🟡 并写上自己，再开始动手
```

## 3. 收工两步

```bash
git add -A && git commit -m "..."
git push
```

改了进展就顺手更新第 4 节的状态，**别攒着**——攒一天对面就白干一天。

## 6. 防冲突规则

1. **一个任务同时只能有一个人领**。看到 🟡 就别重复动手，去领 🔵 的。
2. **`src/ag_core/` 两边都可能动**：改前先 `git pull`，改完立刻 push。
3. **`config/params.yaml` 是高频冲突点**，按参数归属分治：
   - 现场量出来的（终点格号、朝向、单应 H、激光偏置）→ **A 机填**
   - 模型解码参数（`cls_activation` / `kpt_unit` / `input_layout`）→ **B 机标定后告诉 A 机填**
   - 谁改了都在群里/看板说一声，别闷头改
4. **测试基线 477 项**：push 前必须本地全绿。把红的推上去，对面一 pull 就跟着红，还以为是自己改坏的。
5. **`.sh` 脚本一律 LF**（`.gitattributes` 已锁死）。Windows 上千万别开 `core.autocrlf=true` 覆盖它，
   否则 shebang 变成 `#!/bin/bash\r`，车端直接 `bad interpreter`。
