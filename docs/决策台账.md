# 决策台账（DECISIONS · 薄索引）
> **唯一作用**：防止已裁决的事被反复重开（「开倒车」）。
> 规则：① 动手前按本文「查账四处」查；② 要推翻某条，必须写「新证据 + 影响面 + 代价」，由 Lead 裁决后把旧条标「已推翻」并追加新条；③ **不得删除旧条目**。

## 分流说明（一条 D 只在「主人家」写全，别处只留指针）
- **数**（现状参数/口径）→ 本表速查区一行 + `docs/20_资料索引库/数字速查.yaml`（有代码锚点才进 yaml＝机器校验；无锚点留附录并标「无锚点」）；布尔/枚举禁进「值」（false 会被静默算成 0.0=假绿，D-059）；无锚点但被大量引用的数进 yaml 走 manual+现场出处（D-059，例：靶速 target_speed_field_mps）
- **方法/现象**（怎么干、怎么判）→ `docs/20_资料索引库/` 对应分册，本表只留 D 号 + 一句
- **否决/翻案**（否了什么、取代链）→ 本表速查区 + 附录 A 原文（论证不搬走、不压缩）
- **操作流水**（谁何时推了什么、哪轮跑了什么）→ `docs/20_资料索引库/历史/` 或 `dzrobot_v2/src/history/log/`
## 查账四处（动手前按此序；四处都不命中 = 新事项，按「新条目格式规则」落账）
1. **本表速查区 → 查否决与现行口径**：已裁决不重开；要重开先答文末「翻案三问」，结论写回本表。
2. **`数字速查.yaml` → 查数**：参数真源；`python docs/_工具/check_numbers.py` 机器校验，与代码锚点漂移即判红。
3. **`20_资料索引库/` 分册 → 查方法/现象**：怎么干、怎么判；从对应分册 `00_索引.md` 进。
4. **`20_资料索引库/历史/` + `src/history/log/` → 查操作**：谁何时推了什么、哪轮跑了什么；只增不改，不复述进本表。
## 新条目格式规则（防再次变厚）
一行裁决（日期｜主题｜结论｜指针）+ 论证进附录段，不复述过程；落笔必答「**进不进速查区**」——有代码锚点的数必须同时登记速查区。
