## 说明

把「车能不能真跑」变成规划层的硬约束，并用真实底盘尺寸建模。

**底盘标定（现场）**：轴距 0.17m、前轮满舵 35° → **R_min = 0.243m = 0.694 格**；车宽 0.20m（半宽 0.10m）；格边长 0.35m。

**为什么是硬约束**：官方 path_executor 过弯 = 拐点停车→打满舵→满舵圆弧（`cmd.angular.z=±MAX_STEER_DEG` 保舵到朝向到位），所以最小转弯半径是物理边界而非代价偏好。R_min 0.694 格 > 0.5 格，满舵圆弧必然越出拐点格、扫到相邻格与对角格。

**三类实体建模（关键，取代原「一律按整格」）**
| 实体 | 实测 | 扫掠判据 |
|---|---|---|
| 桥墙 | 占满整格 | 与格方块相交 |
| 障碍桶 | 上口 φ0.25m | 弧-圆心距 < 半宽+0.125m |
| 移动靶 | 0.65m×0.025m 薄板 | 弧-圆心距 < 半宽+0.0125m |

**效果对比（cam_20261017_205245 构型）**
| | 路线 | 雷覆盖 | 跑不了的弯 |
|---|---|---|---|
| 约束关（原行为） | 35 格 | 8/8 | 2 处（J4→K5 桥墙、C8→B7 桶）|
| 约束开（新） | 51 格 | 8/8 | 0 处 |
多绕 16 格 = 车能真跑的代价，由规划器自行权衡。

**4 段结果**：全部落在「转弯约束开」档，转弯可行性全部**通过**；排雷 8/8、零穿障。205245=39格、205411=51格、205906=39格、091746=51格。

**交付物同时给出独立第二意见**：`turn_violations()` 复核每个拐点的满舵扫掠，渲染图底部打印「规划模式 + 转弯可行性」，违规处画红圈 ✗弯。

**过程中修正的两处误判（还原真实根因）**
1. 初判「`ensure_mine_center_pass` 插入过心点制造违规」——**错**：该函数输入已含违规，非元凶。
2. 真因是**射击停靠格的停靠转身口径不一致**：车在停靠格会原地转向正对靶心（executor 对 >45° 拐角有 PIVOT 支持），规划器按转向后朝向算出向，复核器按路线原始来向算 → 把「停靠转身」误判成 135° 路线急转。已对齐口径。

**已知残留（未闭环，需后续处理）**
- 原地 pivot 自身扫掠圆未纳入检查（当前只查转向弧）。
- 过心补点可能形成 180° 调头（如 G9 处 H9→G9→H9），阿克曼车物理上须三点掉头执行；该情形不撞实体故复核不报，但执行层需确认掉头方式。

**回归**：148 项测试全绿（`turn_clearance` 默认 None，机上实时规划行为零变化，属显式 opt-in）。
