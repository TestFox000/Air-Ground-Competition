## 1. 车端代码是"另一套版本"（先说清口径）

车端 `/dzrknn_dataprocess` 与本地「走直角」副本**不是同一份代码**：
- 车端现役控制是**增量式 PID**（`track_mode: pid`，`pid_kp/ki/kd=10/1/1.5`，增量同时给位置与速度）；
- 本地副本是 PD + `px_per_tick` 伺服（`inc = eff/px_per_tick`）；
- 车端**没有** `px_per_tick`/`vision_latency_ms`/`momentum_*` 等键（v1 参考实现才有）；
- 车端 lead 链路：`/aim/lead_x` 由 **dzbrain** 发布（非本会话的 target_motion_predictor）。
→ **所有结论以车端口径为准**；本地副本的工具（aim_tune_once 等）中依赖 px_per_tick 结构的部分**不适用**。

## 6. 最终行动清单（合并车端体检 §6 + 本会话补充，按优先级）

**改配置即可（秒回退，无重编）——出车前必做：**

2. `use_external_fire_gate: true` + `lead_apply_gain: 0.5`（治移动靶打不出去）
3. `gyro_ff_gain: 0.8` + 用 `gimbal_ff_calib.py` 标 `gyro_ff_sign`（治"车一转靶就飞"）
4. `patrol_speed_ratio: 0.25`（锁定率 76%→89% @p=0.7）
5. 建议 `target_confirm_frames: 4`（10 发预算防误检浪费，分歧项见 §4）

**现场标定（需靶/弹，一次性）：**
6. `laser_offset_x/y`：用 `laser_offset_calib.py`（截激光点 → 算 offset）——治"瞄得正也打偏"
7. `pid_kp` 若要动，只在 10~12 内微调；**滞后全靠 lead**，加 kp 只会换来震荡

**规程（防状态坑）：**
8. 每次改参/换靶/打满后**重启 `5_gimbal`**（`shots_fired_` 打满即永久禁火）
9. 横幅口径注意：pid 模式下横幅仍打印旧 `Kp 20/Kd 15`（不生效），看参数以 dump 为准

**验证判据（改完一次实测）：**

- 前馈开后行进间锁靶：目标不再持续向画面一侧漂，微找/重扫次数显著下降
