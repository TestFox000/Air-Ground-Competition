# 现场症状诊断与落实清单（瞄准 PID：各种转 / 放不在中心 / 打不到）

> 症状：小车云台"各种转"、打不到靶子、连移动靶都不能稳定放中心。
> 结论：**不是算法缺，是这些参数在车上没落实（多数仍停在代码默认值）**。
> 工具：`aim_param_audit.py`（对 `ros2 param dump` 一条命令出体检表）。

## 1. 症状 → 机制（按可能性排序）

| 症状 | 机制（代码级） | 对应参数 |
|---|---|---|
| **放不在中心 / 锁不住** | 伺服增量 `inc_x = aim_px / px_per_tick`，`px_per_tick=2.0` 但真实 ≈0.94 → 每帧只修正 **~47%** 偏差 → 永远欠修、收敛不到中心 | `px_per_tick` |
| **各种转（车一动就飞）** | `gyro_ff_gain=0` → 车体一转，目标整幅漂出视野 → 丢帧 → 微找/重扫 → 又高速掠过 → 又甩出，循环往复 | `gyro_ff_gain` |
| **各种转（锁定瞬间甩靶）** | 动量抑制刹车外推方向若反（`momentum_sign` 填错），会把云台**继续往扫描方向推** → 目标被甩出 | `momentum_sign` |
| **移动靶永远追不到中心** | `ema_alpha=0.3` → 滞后 78ms → 以 12°/s 移动的目标稳态偏差 ~10px | `ema_alpha` |
| **打不到靶子（瞄上了打不出去）** | ①**开火框实际只有 ±3.5px**（`fire_dz_far/near=3.5`）②`use_external_fire_gate=false` 走"画面静止≤1.5px/帧"判据，移动靶几乎不可能满足 ③`lead_apply_gain=0` → 延迟 0.26s 的 ~33px 飘移全落到靶外 | `fire_dz_*` / `use_external_fire_gate` / `lead_apply_gain` |
| 锁定概率低 | `patrol_speed_ratio=0.3`（97.6°/s）单趟可见帧少 | `patrol_speed_ratio` |

## 2. ⚠️ 重要发现：代码默认值与注释/文档不一致

现场若按注释调参会被误导——**实际生效的是 `declare_parameter` 的默认值**：

| 参数 | 注释/补丁文档写的 | **代码实际默认** | 差异后果 |
|---|---|---|---|
| `track_deadzone_px` | 12 | **2** | 实际更紧，问题不大 |
| `fire_dz_far_px` / `fire_dz_near_px` | 6 / 18 | **3.5 / 3.5** | **开火框只有 ±3.5px，极难打出去** |
| `target_confirm_frames` | 8 | **4** | 确认更快（好事） |
| `scan_yaw_min/max_deg` | ±90 | **∓160** | 扫描范围大 56% |
| `patrol_speed_ratio` | 0.35 | **0.3** | 略慢 |
| `scan_passes` | 2 | **3** | 每轮多一趟 |

> 这些差异本身可能是历次调试留下的，但**与文档口径不符会让整定跑偏**，建议对齐成单一真源。

## 3. 落实清单（按优先顺序，每步可单独回退）

```powershell
# 0. 先体检（车端）
ros2 param dump /dzrknn_dataprocess > dump.yaml
python aim_param_audit.py dump.yaml        # 一条命令列出"该改的没改"
```

| 顺序 | 动作 | 治什么 | 回退 |
|---|---|---|---|
| 1 | **`px_per_tick` 现场标定**（转 100 刻度量画面像素÷100，约 10 分钟） | 收敛命门：放不在中心/锁不住 | 改回 2.0 |
| 2 | ⚠️ **标定完必须重整 `track_kp`/`track_kd`** —— `px_per_tick` 从 2.0→0.94 会让**环路增益翻倍**，原本不振荡的增益可能开始振荡（这是"各种转"的一个隐患） | 防止修好收敛又开始振荡 | 保留旧值 |
| 3 | `gyro_ff_gain: 1.0` + 用 `gimbal_ff_calib.py` 标 `gyro_ff_sign` | 车体一转靶就飞 / 各种转 | `gyro_ff_gain: 0.0` |
| 4 | `momentum_sign`：看 `[lock#1 刹车]` 日志——**第 2 帧 `raw` 应显著变小**；若反而变大/丢靶 → 改 `-1.0` | 锁定瞬间甩靶 | 保持 1.0 |
| 5 | `use_external_fire_gate: true` + `lead_apply_gain: 0.6→1.0`，并同步 `predict_gain: 0.0` / `vision_latency_ms: 0.0` | 移动靶打不到 | 改回 false/0 |
| 6 | `fire_dz_far_px: 6.0` / `fire_dz_near_px: 18.0`（按现场距离标定） | 开火框太紧 | 改回 3.5 |
| 7 | `ema_alpha: 0.3 → 0.5`（两键开火后可 0.7） | 移动靶追不到中心 | 改回 0.3 |
| 8 | `patrol_speed_ratio: 0.3 → 0.25` | 锁定概率低 | 改回 0.3 |

> **顺序很重要**：先 1→2（把"能不能对准"解决），再 3→4（把"车一动还准不准"解决），
> 最后 5→8（把"准了能不能打出去/打得中"解决）。**不要一次全改**，否则分不清哪项起效。

## 4. 建议 robot.yaml 片段（完整版见《提前量启用与标定流程》）
```yaml
dzrknn_dataprocess:
  ros__parameters:
    px_per_tick: 0.94            # ★第1步现场标定后填真实值
    track_kp: 4.0                # ★第2步：px_per_tick 改小后重整定
    track_kd: 1.5
    gyro_ff_gain: 1.0            # ★第3步
    gyro_ff_sign: 1.0            # ★用 gimbal_ff_calib.py 标定
    momentum_sign: 1.0           # ★第4步按日志确认
    use_external_fire_gate: true # ★第5步
    lead_apply_gain: 0.6
    predict_gain: 0.0
    vision_latency_ms: 0.0
    fire_dz_far_px: 6.0          # ★第6步
    fire_dz_near_px: 18.0
    ema_alpha: 0.5               # ★第7步
    patrol_speed_ratio: 0.25     # ★第8步
```

## 5. 第 1/2 步「一键整定」工具 `aim_tune_once.py`

```powershell
# 现场量：把云台水平轴转 100 刻度，量画面里参照/靶移动的像素数（例 94px）
python aim_tune_once.py --compute --pixels 94 --ticks 100
# 车上实时量（需 ROS）：让云台锁一个可见靶，用遥控把水平轴转 ≈100 刻度
python aim_tune_once.py --measure --ticks-turned 100
```

输出（示例 px=94 / ticks=100）：
```
px_per_tick：2.0 → 0.940      每帧修正比例：47% → 100%（死拍）
匀速靶稳态滞后：9.1px → 4.3px   环路增益变化：×2.13
kp/kd：先保持 8.0 / 3.0；若振荡 → 下调 3.76 / 1.41
```

**原理一句话**：伺服每帧修正量 = `eff_px / px_per_tick`。`px_per_tick` 偏大（2.0 而真实 0.94）
会让**每帧只修正 47%** 偏差，对匀速靶留下 `每帧像素位移/0.47 ≈ 9px` 的**稳态滞后**；
标对后变"死拍"（100%/帧）⇒ 这段滞后≈归零。
但标对后**下发的刻度增量会 ×2.13**，所以**必须连带看 kp/kd**——这就是"第 2 步"不可省的原因。

## 6. 开火链路专项（兑现率仿真 `fire_commit_sim.py`）

**先给结论：开火链本身没坏——静止靶现在就能打（19 发/10s）；移动靶打不出的唯一根因是"没有提前量"。**

| 场景 | 静止靶 10s发数 | 移动靶 10s发数 | 移动靶 3s内≥1发 |
|---|---|---|---|
| 现状（框 3.5 / hold 5 / 两键关 / 无超前） | 19 | **0** | **0%** |
| 只放大开火框（3.5→5→6→10→18） | 19 | 0 / 0 / 0 / 6 / 6 | — |
| 两键开、仍无超前 | 20 | **0** | 0% |
| **两键开 + 超前（框 6）** | 20 | **20** | **100%** |
| 仅超前（两键关，框 6） | 20 | 19 | 100% |

**可操作结论**
1. **移动靶的开关就是"超前"**：超前生效后目标在画面里相对静止 → 移动靶 **3 秒内必能开火（100%）**，
   而且连"画面稳定 ≤1.5px/帧"判据都**自然满足**（两键开不开都能打）。这与补丁说明 §5.2 的"优雅之处"一致。
2. **只调开火框对移动靶无效**（3.5→6→10 全 0 发）；仅当**拿不到超前**时才需把框放到 ≥10px 兜底（6 发/10s）——下策。
3. `fire_hold_frames` / `shot_cooldown_ms` 在条件稳定成立时影响很小（20 vs 20）；只在**条件闪烁**时才关键
   → 先保持 5，配合 `fire_stable_px_per_frame: 2.5`。
4. ⚠️ **`laser_offset_x/y` 仍为 0**：激光与相机不同轴时开火零点不是画面中心 → 即使"中心对准"也会打偏。
   **必须标定**（代码已有 `compute_comp_pixel_0` 查表口子，可做动态视差补偿）。

## 7. 10 发弹量预算专项（`shot_budget_sim.py`）

**硬约束：全程只有 10 发**（`max_shots=10` 代码硬上限）、`max_shots_per_target=3`、冷却 500ms，
且**无命中反馈**（只上报已发射数 `/shoot_count`）⇒ 每个锁定都会把 k 发打满，不管中没中。

| 每靶 k 发 | 可交战目标数 | 弹匣耗光时间 |
|---|---|---|
| 1 | 10 | 2.0 s |
| 2 | 5 | 4.0 s |
| 3 | 3 | 5.0 s |

打全 N 个目标的概率（命中即停；p = 单发命中率）：

| p | k | N=2 | N=3 | N=4 |
|---|---|---|---|---|
| 0.3（未标 offset / 无提前量） | 3 | 43% | 28% | 28% |
| 0.6 | 3 | 88% | 82% | 82% |
| **0.9（超前 + offset 标定到位）** | 3 | **100%** | **100%** | **100%** |
| 0.9 | 2 | 98% | 97% | 96% |
| 0.9 | 1 | 81% | 72% | 65% |

**结论**
1. **决定成败的是单发命中率 p，不是打几发**：p=0.3 时每靶 3 发也只有 43% 打全；p=0.9 时
   **几乎必中**。→ **杠杆仍是"提前量 + `laser_offset` 标定"，把 p 从 0.3 抬到 0.9**。
2. **每靶改成 2 发**：k=3 只换来 3 个交战额度；k=2 有 5 个额度，且 p≥0.9 时打全 4 个目标仍有 **96%**。
   （k=1 虽然额度最多，但单发无补射，打全率掉到 65~81%——不划算。）
3. **冷却 500ms → 1200ms**：现冷却会让弹匣在 **4~5 秒内打光**；拉长可把 10 发**分摊到整场多个停点**，
   而不在一个停点倾泻，同时给伺服从后坐/抖动恢复的时间。
4. `target_confirm_frames` 4→6：10 发不允许把机会浪费在**误检**上。
5. ⚠️ **若能拿到裁判系统的命中反馈**，应接入并改成"打中即停、未中补射"策略——那可以把 k 提到 3
   而不浪费；否则只能靠预留补射。**这条值得先去确认赛制是否提供命中回报。**

## 8. `laser_offset` 标定工具（`laser_offset_calib.py`）

**为什么必须标**：开火判据 `aim_err_x = |dx_filt + lead - laser_offset_x| ≤ fire_dz`，
而 `laser_offset_x/y` 代码默认 **0** —— 等于假设"激光与相机同轴"。
真实不同轴时，**即使靶稳稳在画面正中，弹着也固定偏一段**（开火框才 6px！），
表现为"瞄得很正却总打偏"。标掉这段系统偏差，单发命中率 p 才能从 ~0.3 抬到 ~0.9
（§7 已证：10 发预算下 **p 是唯一决定性因素**）。

**用法**（不依赖 ROS）：
```powershell
# ① 离线标注（推荐）：截一张【能看到激光点】的相机画面
python laser_offset_calib.py --image shot.png     # 鼠标点一下激光点 → 出 offset + yaml
# ② 纯计算：
python laser_offset_calib.py --compute --dot-x 340 --dot-y 250 --img-w 640 --img-h 480
```
约定（与 C++ 一致）：x 右为正、y 下为正；`laser_offset = 激光落点 − 画面中心`。
示例：dot(340,250) / 画面 640×480 → **offset (+20, +10)px** → 判定"20px > 开火框 6px ⇒ **必须标定**"。
回退：`laser_offset_x/y` 改回 0.0。

⚠️ 现场要点：① 让激光**常亮**并对准画面/墙面再截图；② 标完**复核**——把靶放到画面中心开一发，
弹着应落在靶心；若仍偏，把 offset 再补一个残差量。
