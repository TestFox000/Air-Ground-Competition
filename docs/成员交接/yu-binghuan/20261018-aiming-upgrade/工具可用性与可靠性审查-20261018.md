## 2. 关键验证证据

不是"逢参必报"。剩余 5 项均为"标定类"（§3.3）。

### 2.2 预测器回归（最重要的一件）
`test_predictor_offline.py` **12/12 全 PASS**：速度拟合 11.76 vs 真值 11.76°/s、超前 68.8px vs 期望
69.6、端点误差 0.02°/0.13°、折返 6/6——EKF 替换 LS 后**零回归且指标更紧**。

### 2.3 冒烟复现一致性
7 个仿真/计算工具重跑输出与历史**逐字一致**（fixed seed + 确定性算法），包括三个"出厂默认=扫掠最优"
的自洽验证（EKF/CTE-PID）与符号规则 4 组合匹配 + 错误符号翻倍反例。

### 2.4 交叉印证（意外收获）

切角弧几何等），与"4 段全持平或更短"的 G1-α 结论**互相印证**。

## 3. 发现的问题与使用限制

### 3.1 ⚠️ 操作警告：`det_recall_ab.py` 结果覆盖隐患（P1）
默认 `--out-root=检测召回AB`。历史两轮 A/B（3 预设版/4 预设版）结果都在其下——**直接重跑会覆盖
baseline 并混淆两轮预设结构**。本次审查用隔离 out-root 冒烟未受影响。
**规程：重跑必须带 `--out-root <新目录>`**（本次已验证该参数可靠生效）。

### 3.2 已修复：`aim_tune_once.py --measure` 报错友好化（P1，本次修复并验证）
修复前：无 rclpy 的机器上 `--measure` 会裸抛 ImportError traceback。
修复后：打印明确指引（"车上运行 / 离线用 --compute"）并以 exit 2 退出；`--compute` 路径复验不受影响。

### 3.3 设计语义说明（非 bug，但须知）
- `aim_param_audit.py` 对 **px_per_tick / gyro_ff_sign / laser_offset_x/y** 永远显示
  "★需标定/复核"——即使已填入标定值。这是刻意的 **fail-safe 提示**（标定类参数需每次上车复核），
  不代表"永远不符"。
- **track_kp** 的建议是"4.0(标定 px_per_tick 后重整定)"，与任何数值比较都报"★不符"——语义是
  **"需人工定夺"**（kp 与 px_per_tick 强耦合，标定后按 `aim_tune_once.py` 的软值指引调整），
  不是"必须改成 4.0"。
- `det_recall_ab.py` 的**路线输出会随规划器版本漂移**（检测口径不受影响）——复现历史 A/B 时
  需记录当时 `mission_router.py` 的版本（当前为 G1-α 版）。
- `laser_offset_calib.py --image` 需要 cv2 + GUI 显示环境（cv2 5.0.0 在系统 Python 与
  .venv_dml 均可用；无屏环境请用 `--compute`）。
- rclpy 类工具（#4/#6/#2-measure/#16）**本机不可运行是预期**（车上节点/代码），本机以
  py_compile + 离线被测件（stub/仿真）覆盖验证；上车前按项目规范备份→推送→重启，
  C++ 相关改动须过 `orin_build_verify.sh`。

## 4. 结论

- **可用性**：16/16 文件存在、语法全通过；离线工具（12 件）本机全部可直接运行，
  车上件（4 件）依赖明确且隔离正确。
- **可靠性**：7 个仿真工具**确定性复现**；3 个"出厂默认=扫掠最优"自洽闭环成立；
  审计工具通过反向验证；预测器 12 项回归零失败；检测 A/B 口径可复现。
- **遗留动作**：① 重跑 det_recall_ab 必须带隔离 out-root（规程）；② 上车部署时
  `target_ekf.py` 与 `target_motion_predictor.py` 必须同目录推送；
  ③ 全部结论仍属**离线验证**，实车标定值（px_per_tick/laser_offset/gyro_ff_sign/p）只能现场获得。
