## 新发现（审查未说清）

### A. `205ffba` 无法定位
审查自称核验到「最新分支 205ffba」——该 SHA 在 Gitee 全分支（main@0bc2196、snapshot/orin-20261023@310558e 等 31 分支）与前 300 条提交中**均不存在**；无人机 git HEAD=310558e。审查行号（mission_router L1275）实际匹配**无人机收编基线 8cbfbb3**。205ffba 可能在**车端仓库**（192.168.137.79 离线无法核）。**需确认底本**——否则「最新分支」口径存疑，合并补丁时可能对错版本。

### B. 部署反向差距（重要，影响修复优先级）
「已修 14 条」里的 **F1（steadyNowS 时钟域）与 nan_drop/z_src 前兆信号只在 Gitee main 的 `onboard/dzpx4_patch/` 里，无人机 `~/dzpx4` 仍在跑旧版**（实测：无 steadyNowS、`arming_state==2` 无 `==4`、健康行无前兆字段）。即：**定位链咽喉件的修复从未上机部署**——「已修」≠「已部署」。
连带风险：若按 main 补丁整体部署无人机，会把 7 号的 `==4` 判据一并带上去——部署前必须先对 7 号拍板。

### C. 机上又一起新漂移（收编后第一起）
`git status` 显示 `video_recon.py` + `tools/export_recon_dataset.py`（--sahi 批次）**已修改未提交**。需提交或说明，否则收编即失效。
