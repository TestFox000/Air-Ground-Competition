# 机载自主规划 · 差距核实与移植清单

> 口径纠正：**规划在无人机（机载）**，不在车端。本文只列「已核实事实 + 差距 + 移植项」，
> 不含实现动作。所有结论均可按「来源」列复核。

## 0. 结论（一句话）

- 官方硬要求：无人机「定位 / 建图 / 识别 / **规划** / 控制」须**由机载平台自主完成**。
- 机上现状：13 类感知栈只做到 **检测 → PnP 定位 → UDP 广播**，**没有任何落格/规划/规划产物**。
- 规划栈现状：唯一有版本控制的规划实现是 **Python 包 `src/ag_integrate`**，但被仓库文档明确定位为
  **车端（香橙派）薄集成包**，且**没有一键启动链把它拉起来**。
- 因此差距 = 「规划算力在车端」↔「官方要求规划在机载」；移植 = 把规划层搬到机上，
  车端只保留「薄接收 + 官方 path_executor 执行」。

## 3. 目标态（机载自主规划）

```
机上：相机/视频 → dzuav 13 类检测+PnP ──本地 UDP──→ 机载规划进程
                                                     ├─ world_model   态势归并（含红靶粘性否决）
                                                     ├─ field_matrix  11×14 落格矩阵（滑窗投票）
                                                     ├─ mission_router 朝向感知 Dijkstra + TSP 必经点
                                                     └─ car_commands   reset+路线（含射击格）
                                                     ⇒ 落盘 route_plan.json / cell_matrix.json / planned_path.txt
                                                     ⇒ 下发车端（薄接收→官方 path_executor）
车端：只保留「收命令 + 执行 + 禁火保险执行侧」——不再承担规划算力
```

### 由此派生的一项接口新增（已定稿）

机上规划产出的车命令此前只走**本机 ROS 话题** `/nav/waypoint`（车端消费）。
规划搬到机上后，机载进程与车端不再同机，需要一条**空中命令通道**。
最小改动方案：沿用现有空地 UDP 广播链路，新增 `msg_id=0x4003 = 车命令帧`
（`reset:<格,朝向>` + 格号序列 + 射击格），由机载广播、车端薄接收转 `/nav/waypoint`。
除新增该 msg_id 外，0x4001/0x4002 契约不变。

### 感知侧瓶颈（**非代码缺陷**，等相机）

机上现成 4 段视频均为**近距窄视野**：单帧只读到 **1~6 个格号地标**
（369 帧 3 个 / 252 帧 2 个 / 218 帧 1 个），而 `MapLocalizer` 的 PnP 内点下限是
`max(4, 30%)`——4 个地标必须**全部**为内点才过关，实测 431 帧只有 **5 帧**定位成功。

> 为什么旧口径下"视频侦察 35 格"能成：那条 Python 管线（`video_recon.py`）把**整段视频的标签
> 跨帧聚合**做穷举一致性仿射；机上 `dzuav` 是**单帧 PnP**。两者机制不同，机上这条对近距视野
> 天然吃亏。相机装上后需按真实飞行高度/视野重新标定，并按地标密度复核门槛。

### 6.10.2 「这航点缺雷」：均值置信度门卡掉真雷 + 缓存沿用旧门控（`fa9a515`）

**现象**：通用入口跑 `cam_20261018_091746.mp4`（stride 15）只出 `A2,C3` 两颗雷，
路线里没有 `G9`；终端与 `check` 仍显示「排雷覆盖 ✓」，用户当场指出「这航点缺雷」。

**根因（两件事叠在一起）**：

1. **参数联动副作用**。上一轮把 paper 单框阈值 `0.22 → 0.15` 以提高召回，单框
   置信度降低后命中格的**均值**置信度也被拉低：`G9` 拿到 3 帧独立票，均值
   `0.336 < PAPER_MEAN_CONF_MIN(0.35)` → 被均值门丢掉。同一段视频上一版（0.22）
   反而检得到。**放宽单框阈值与收紧均值门互相打架**。
2. **缓存沿用旧门控**。通用入口命中缓存时只重跑规划层（`orin_replan_from_state.py`），
   用的还是旧 `field_state.json`——门控修好了，缓存仍然吐旧结论。

**修复（`fa9a515`）**：

| 改动 | 内容 |
|---|---|
| `confirmed_cells(..., strong_votes)` | paper 传 `3`：**≥3 帧独立同意**的格不再受均值置信度门约束；均值门只拦 2 票的弱格（人体/阴影视检） |
| `aggregate_state()` | 把"投票→门控→幻影→单格裁决"从 `recon_video()` 抽成独立函数，`--reaggregate DIR` 与完整跑共用**同一份**门控代码 |
| 缓存复用 | 命中缓存改为 `--reaggregate`：用 `frames_meta.json` 按**当前**门控秒级重算，门控修过不会继续拿旧结论；缺 `frames_meta` 才退回只重跑规划层并告警 |
| 漏检显式化 | `check["排雷覆盖"]` 与终端摘要都对官方基线 `field_rules.MAX_MINES=8` 负责：不足时输出「仅检出 N/8 颗雷：漏检风险」，不再只打「覆盖 ✓」 |

**实测对照（同一段视频 `cam_20261018_091746.mp4`，官方基线 8 雷）**：

| 配置 | 网格拟合帧 | 雷 | K 列箭头 |
|---|---|---|---|
| stride 15 + 旧门控 | 93/148 | `A2,C3`（2） | `K10` |
| stride 15 + 新门控（重算） | 93/148 | `A2,C3,G9`（3） | `K10` |
| **stride 5 + 新门控** | **288/444** | **`A2,B1,C3,E2,E3,G3,G9,I2`（8 = 基线）** | `K10,K4` |

**stride 5 的票数支撑**（`votes_detail.paper`）：`C3 18 / A2 13 / I2 5 / G9 4 /
B1 4 / E3 4 / G3 3 / E2 2`；`B2 3 票`被幻影消除判为 `C3` 的误归属（同帧不共现、
票期被强格夹芯），剔除留痕。8 颗各自都有跨帧独立证据，不是靠降阈值堆出来的。

**结果**：路线 41 格覆盖全部 8 雷（`N10→…→G9→…→A2→…→E2→E3→…→I2→…→N5`），
压缩 32 点 / 转向 22 次；`射击停靠 D8`（移动靶确认位，两段式）、避障通过。
渲染图：`Trae-CN\验收_stride5_路线图.png`，态势：`验收_stride5_field_state.json`。

**守护测试**（`tests/test_video_recon_plan.py`，共 20 例）新增 3 条：
`≥3 票低均值必须留`、`2 票低均值仍须拦`、`--reaggregate 与完整跑态势一致`。

> 口径提醒：`stride` 只有"采样漏检"一种含义，没有"快一点的同结果"。默认 **stride 1
> 逐帧**（测试环境不拿时间换召回，2220 帧约 80 分钟）；同一段视频实测 stride 15 只剩
> 2~3 颗、stride 5 出 8 颗。赶时间要对照片段暂用 `--stride 5`，正式结论一律逐帧；
> 已有缓存要套新门控时用 `--reaggregate`（秒级），不必重跑识别。
