## C. 感知口径分叉：机上 C++ 与 Python 复现不是同一套后处理

### C1 [high] C++ 先 argmax 再阈值，Python 逐类阈值
- C++ `onboard/dzuav/src/HbbDetector.cpp:102-121`：每个 anchor 取 13 类里分数最大者 → 只用该类的阈值过滤（**每 anchor 最多 1 个检出**）
- Python `src/ag_integrate/ag_integrate/video_recon.py:320-330`：**逐类** `s > th` + 逐类 `cv2.dnn.NMSBoxes`
- 后果：`paper` 阈值 0.25、`cell_label` 阈值 0.50（`main.cpp:48-62`）。一个 anchor 若是 paper=0.30、cell_label=0.35，argmax 取 cell_label → 0.35 < 0.50 **被丢弃**，而 paper 本已过阈 ⇒ **机上漏检雷/箭头**（主得分目标），且"视频复现验证过"的结论不能直接外推到机上
- 修法：C++ 改为逐类阈值 + 逐类 NMS（与 `video_recon.py` 同口径），或明确记录"机器上故意更严"的取舍
- 核实：两处原文都读了

### C2 [high] `MapLocalizer` 内参按轴独立缩放 → 非 1920×1080 时相机模型物理不成立
- 位置：`onboard/dzuav/src/MapLocalizer.cpp:15-22`
  ```cpp
  K.row(0) *= double(sz.width) / 1920;
  K.row(1) *= double(sz.height) / 1080;
  ```
- 后果：640×480 → fx=331.7 / fy=443.4（fx/fy **0.748**，标定值 0.997）；1920×1200 → **0.898**。PnP 用这组假内参必超中位重投影门 ⇒ **永久退回"无内参单应"**（作者注释自承精度更低），`undistort()`（`:36`）同一组 K ⇒ 整帧各向异性拉伸。**这不是边界情况**：`orin_bringup.sh:28` 的默认标定分辨率就是 `1920x1200@30`
- 修法：只用一个等比 `s = min(w/1920, h/1080)`，或按实际分辨率重标定
- 核实：读了源码；`K_.row(0)=(fx,0,cx)`、`K_.row(1)=(0,fy,cy)`，两轴缩放率不同必致各向异性

### C3 [high] UVC 采集管线缺 `jpegdec`，默认又要 1080p30
- 位置：`onboard/dzuav/src/main.cpp:238-245` `v4l2src … ! video/x-raw,width=…,height=1080,framerate=30/1 ! videoconvert ! …` 直接进 `cv::VideoCapture(..., CAP_GSTREAMER)`
- 后果：USB2 相机跑 1080p 只能是 MJPG，协商 raw 必失败 ⇒ `isOpened()==false` ⇒ `exit 3`，**整场无情报**（相机只支持 640×480 同样失败）。注意这与机上另一套 `orin_run_dzuav_d13.sh`（MJPG 修复版路径 `onboard/dzuav_mjpg`）是同一问题的两个版本
- 修法：`v4l2src ! image/jpeg,width=… ! jpegdec ! videoconvert`；默认分辨率对齐相机实际能力
