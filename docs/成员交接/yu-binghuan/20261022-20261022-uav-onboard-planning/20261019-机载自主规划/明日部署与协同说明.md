## 二、无人机"启动全部功能"是什么操作

**机上一条命令**：

```bash
cd ~/dzuav_deploy/air_ground && tools/orin_bringup.sh up
```

它在一个 tmux 会话 `agup` 里**按依赖顺序**拉起 9 个窗口 —— 这就是"全部功能"：

| 窗口 | 作用 |
|---|---|
| `dzuav` | **我们的侦察栈**：相机 → TRT 推理（检测+读格号）→ PnP 自定位 → **UDP:50000 广播** |
| `livox` | 激光雷达驱动（MID360） |
| `fastlio` | FAST-LIO 定位/建图 |
| `px4` | MicroXRCEAgent（飞控串口桥，依赖 `/dev/ttyACM0`） |
| `odom` | `px4_odom_convert`（SLAM → NED 喂 EKF，**我们的 v2 韧性版**） |
| `imu` | 飞控 IMU → ROS 桥 |
| `control` | `px4_control` 状态机（起飞/返航） |
| `path` | `px4_path` 航点跟随 |
| `teleop` | 键盘遥控（人工接管；`up --no-teleop` 可省） |

配套操作：
`tools/orin_bringup.sh status` 看各窗口死活；`tools/orin_bringup.sh down` 全部停止；
`tmux attach -t agup` 接入观察（Ctrl+B 再按数字/名字切窗口）。

⚠️ **开机自启的现状**：机上 autostart 是 **v3（flight-link only）——只起 agent/wdog，
定位栈不自启**。所以"启动全部功能"必须跑上面这条 `orin_bringup.sh up`（或把自启恢复到 v2 全栈版）。
若开机后发现定位栈自己已经在跑，**不要**再 `up`（会造双实例，见第四节）。

## 三、空地协同：比赛时怎么自动联动

职责边界（官方 vs 我们）：

```
[机载 Orin Nano]
  官方 dzpx4（直接用、不改）：MID360 → FASTLIO2 → PX4；px4_control / px4_path 执行航线
  我们的 dzuav（C++ 侦察栈）：相机 → 去畸变 → HbbDetector(检测) → CellClassifier(读格号)
                              → MapLocalizer(PnP 自定位) → UdpBroadcaster(UDP:50000)
                 │  UDP :50000（广播）
                 ▼
[车端]  官方 dzrobot：path_executor / dztrack / Nav2 负责开车
        我们的 ag_integrate：收 :50000 → 世界模型 → 官方车命令 + 禁火保险
```

**比赛时的自动协同链路（全自动，无需人手介入这一步）**：

1. **机上侦察**：dzuav 单帧跑完
   `去畸变 → HbbDetector 检测 → 格号 ROI → CellClassifier 读格号 →`
   `MapLocalizer.solvePnP（需 ≥4 个格号且凸包 ≥2% 画面）→ 定位成功才投影非格号目标 → UdpBroadcaster 广播`。
   **定位失败就不广播**（`localized=0`）——这是"无人机要飞到能看到 4 个以上分散格号的高度"的原因。
2. **车端收包**：`integrate_node` 后台线程收 UDP:50000 → `intel_protocol.parse`（魔数/CRC16/后缀校验）
   → `world_model` 把 13 类目标落格成态势（雷 / 障碍 / 靶 / 桥洞；含**障碍多帧确认**与**红靶粘性否决**）。
   队列容量 1：**决策慢时自动丢旧帧，永远用最新态势**。
3. **车端决策**：ROS timer 回调里跑门控 → `plan_route`（阿克曼可跑性约束的路线规划）
   → `car_commands` 生成车端命令（`reset:<格>,<朝向>` + 路线串 + 朝向 token 翻译）
   → 发布到 **`/nav/waypoint`**（先发一次 reset、再发路线）→ 官方 `path_executor` 消费执行。
4. **安全件**：`fire_guard` 禁火守卫（未辨靶一律禁火、靶格本身不是停靠格）；
   `dry_run=True` 时**只算不发**，上车验证后才置 false。
5. **中途变化**：`replan_on_update` —— 态势相关变化（雷/桥洞/靶面集变化、路线 ±1 格内障碍增删）
   触发**重规划并重发路线**，path_executor 按"最近航段"从当前位置接续。

一句话：**无人机只负责"看"并广播；车负责"看懂 + 决策 + 开"，两侧靠 UDP:50000 这一条 13 类协议自动接起来。**

## 五、已知坑（明天会遇到的，先记着）

1. **Type-C 掉租约** → 见 §0 续租；SSH 超时先查本机有没有 `192.168.55.x`。
2. **双实例是真事故**：10-16 实测双 FAST-LIO 同发 `/localization` 406s、双 odom 同发 VIO 93s，
   EKF 被两路测量撕扯出 reset 风暴。**`up` 之前先 `check_stack_health.py --kill-dup`**；
   若已有栈在跑，先 `down` 再 `up`。
3. **引擎必须机上转换**：`.engine` 与 TRT 版本 + GPU 型号绑定，本机无法预生成；
   换机/刷机/换模型后必跑 `orin_convert_engines.sh`。若机上引擎比仓库模型更新，**别再转换**（会静默降级）。
4. **`DZUAV_DIR` 口径**：`tools/orin_run_dzuav.sh` 默认找 `~/ag_test/dzuav`，
   而部署把二进制放在 `~/dzuav_deploy/air_ground/onboard/dzuav/build/dzuav`
   —— 所以 `up` 前要 `export DZUAV_DIR=~/dzuav_deploy/air_ground/onboard/dzuav`（否则 dzuav 窗口起不来）。
5. **uXRCE 卡死**：飞控断电 5 秒重上电才能复位客户端；Orin 侧重启 Agent 无效。
6. **定位补丁回滚**：`python tools\patch_deploy.py --host 192.168.55.1 --user duzhong --rollback`
   （机上 `.bak_patch_*` 备份 + md5 指纹校验）。

### C. 注意事项（今晚实测）

1. **不要跑 `orin_convert_engines.sh`** —— 会按 7 类 ONNX 覆盖掉与 GPU 绑定的 13 类引擎，**不可逆**。
2. **不要推模型**（`orin_deploy.py` 必须带 `--skip-models`）—— 仓库 `models/release` 指针是 7 类。
3. **Type-C 链路不稳** → 掉租约就 `release`+`renew`；重活（部署/拉起）一断就重试，或改机上直连。
4. **相机没插** → dzuav 起不来；`/dev/video0` 是 UVC 路径，CSI 相机要用 argus。
5. **`dry_run=true` + 未做相机标定** → 比赛前两项必办（标定：`python tools/calibrate_camera.py board`）。
6. **机载落格/规划层仍缺** → 现状只有 检测+PnP+UDP，下阶段移植。
