## 二、靶向对齐 + 重规划基于最新进度（本会话主体）

**需求原话**：标靶打击时小车朝向正对标靶（可一次到位、可逐渐调整）；规划的
基础一定得是最新的进度；不要犯之前就出现的问题。

### 2.1 事实勘察（先对齐"最新"）

- **漂移实锤**：机上 `~/dzuav_deploy/air_ground/src/ag_integrate` 与本地
  `路径规划交接_20261017` 副本**全部共同文件 md5 不同**，机上多 7 个新文件
  （field_rules / evidential_map / ortools_solver / turn_feasibility_v2 /
  ground_projection / anchored_registration / cjk_font），且机上 NO_GIT、无 tests
  目录——**最新血缘在机上**。完整拉回 `baseline/` 存证，在其上改。
- 基线测试：**81 过 / 15 失败**（15 全为旧套件对新血缘的既有失配：
  ObjectType.MINE×11、config 路径×3、route_time×1）——以"零新增失败"为门槛。

### 2.2 实现

| 改动 | 文件 | 内容 |
|---|---|---|
| 靶向对齐 | `mission_router.py` `_assemble` | 停靠段**强制先试**终点态约束 Dijkstra（到达朝向=正对朝向，一次到位；进段可绕/曲进=逐渐调整的几何形态）；物理不可行才退回"代价择优+停靠转身"，格名记入 `align_degraded`，`plan_route` 选定后**一次性 RuntimeWarning** |
| 进度底座 | `route_progress.py`（新增，纯算法无 ROS） | 0x4002 车位姿 × 当前路线折线 → 当前格 / 真实朝向最近轴 / 已扫格集。落格用包围盒+最近格吸附（**不用** world_to_cell 残差防线——那是给检测分类用的，车跨格边界离两格心各 0.5 是正常行驶） |
| 车端重规划 | `integrate_node.py` | 存车 x/y（`_car_xy`）+ `_fresh_car_pose()`；中途重规划起点=车当前格、朝向=最近轴、剔除已扫雷（`filter_swept_mines`，保守：当前格不算已扫、只剔雷）。守卫签名仍用全量快照（防每帧重规划风暴）；reset 不重发 |
| 机上 sidecar | `orin_plan_sidecar.py` | 同口径；`route_plan.json` 记录实际起点（`last_start_used`） |

**根因记录**：官方 path_executor 只跟折线、不知道靶在哪——开火瞬间车头朝向
只能由进段几何保证；旧实现只把对齐当"更便宜"（朝向零转向准则），实测出现
`E9→D8*` 斜进 45°；而 135° 原地转身按 turn_feasibility_v2 物理上"单段绝无可能"。

**机上日常用法**：改前 `git diff` 看漂移；回滚 `git checkout --`（部署脚本
`.bak` 锚仍兼容）；二进制核对走 manifest。
