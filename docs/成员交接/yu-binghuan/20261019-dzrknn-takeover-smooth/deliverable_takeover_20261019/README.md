## 0. 背景与结论

现场症状：云台转到后面、靶侧持续提示上靶、自瞄明显卡顿无法稳定追踪。经 12s 三路全速率探针（视觉/指令/反馈）量化定位：

- **卡顿 = 冻结态**：旧代二进制（18:53 编译、19:01 起进程）585 条指令 584 条完全相同（12s 零变化），反馈 yaw 纹丝不动，视觉 100% 帧有靶却 dy=-64px 不修——控制环是复读机。
- **根因链**：18:52 代把"已锁定跳过扫描"守卫放在 enterScanPhase() 内部 ⇒ 视觉静默触发的 startScan 一进来就 return ⇒ 状态永钉 TRACK、扫描永远进不去、静默计数涨到 47.5s（19:19 代已由原操作者把守卫挪到调用点，本接管确认该修复成立）。
- **结构性卡顿**：旧律"30Hz 视觉帧→一个位置台阶"，两帧视觉之间目标估计零前进 + 267ms 链路延迟 ⇒ 停-走-过冲的标准顿挫形态。

接管后的处置（4 处外科手术 + 验证门）：

| # | 修复 | 位置 | 内容 |
|---|---|---|---|
| 1 | **单写者原则** | callback_offset_center 旧伺服三步（PID/位置台阶/速度）整段包进 `if (!smooth_track_)` | 平滑律启用时回调只喂数据（EMA/lead/EKF），下发权唯一归主循环 100Hz `smoothTrackStep()`。旧律台阶每 33ms 覆盖平滑斜坡=两律打架，此为卡顿残余主因 |
| 2 | **TRACK 进入即作废归位段** | TRACK 入口置 `scan_homing_ = false` | 否则陈旧 homing 在后续回 IDLE 时"超时兜底"直接重启扫描（停止请求后云台自己开扫的怪象） |
| 3 | **停止请求作废归位段** | callback_scan_request data==0 分支 | 同上，双保险 |
| 4 | **车体前馈接入平滑律** | smoothTrackStep 增加 `ff_gyro_x` 通道 | 旧律的 gyro_ff 在回调里生效，平滑律此前没有该通道（开平滑= gyro_ff 静默丢失）。增益 0 时零影响；现场标符号后开 0.8 即在此生效 |

平滑律本体（EKF α-β 0.6/0.2 + 267ms 前瞻 + 100Hz 斜坡 k_sp 8.0/ff 1.0/slew 2000）为 19:19 代已有实现且 `smooth_track: true` 已启用，接管工作为审查 + 上述集成修复，不重复造轮子。
