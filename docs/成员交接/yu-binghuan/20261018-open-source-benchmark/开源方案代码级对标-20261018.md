## 1. 总览结论

- 我们的核心链路（RKNN 检测 + 网格 A*/TSP + 纯追踪/开环弧 + 自研状态机）**在 Gitee 上无完全对应实现**，方案具备独创性。
- **真正的差距只有 2 处**：① 检测**召回策略**（我们已知漏检痛点）；② 控制律的**抗饱和/抗抖动机制**。二者都可低成本吸收。
- 其余（NAV2 全栈 / TEB / SpireCV 整库 / BT）与我们的硬件假设不匹配，**不宜整体替换**。

## 2. 逐模块量化对标

### 2.1 视觉感知（SpireCV vs 我们的 RKNN）

| 维度 | SpireCV | 我们（dzrknn_dataprocess / target_motion_predictor） |
|---|---|---|
| 平台分支 | Jetson / x86-CUDA / x86-Intel（**无 RKNN/瑞芯微分支**） | **RKNN（Rockchip NPU）** |
| 检测模型 | YOLOv7(CUDA/TensorRT)、YOLOv11（`imgsz=640`） | RKNN 自训模型 |
| 检测阈值 | **`confidence=0.001`、`nms_thresh=0.60`** | 未对齐（偏低召回） |
| 多目标跟踪 | **SORT**（`iou_thres/max_age/min_hits`）或 **ByteTrack**（`frame_rate/track_buffer`，可选 ReID） | 单帧检测 + 运动预测 |
| 云台跟踪 | 比例式（bbox 中心→角速率），`trackDef=50`、`tracked_id=4` | gimbal scan（打靶） |

**判定**：SpireCV **无 RKNN**，硬件不适配 → **不整库引入**。
**但两个点可直接吸收**（见 §3 P0-1 / P1-3）。

### 2.2 循迹 + 控制律（Line_Follower vs 我们）

| 维度 | Line_Follower | 我们 |
|---|---|---|
| 感知 | 摄像头，灰度/二值 `line_threshold=200`，双线内巡 + 缺线补线 | RealSense D435IF 640×480@30，HSV/灰度(80)，`SCAN_ROWS=10` |
| 控制律 | **自适应 PID** `Kp=.005 / Ki=5e-6 / Kd=.009` | 车载：纯追踪 + CTE **纯P**(`CTE_GAIN=115 °/m`) + 开环满舵弧 |
| 抗饱和/抗抖动 | **6 重**：输入滤波(`0.7`)、死区(`30px`)、积分分离(`60px`)、积分限幅(`±0.06`)、微分先行、软限幅(`±1.0`) | **无**（CTE 仅比例项） |
| 速度 | `v=0.25 m/s`、`ω≤1.0 rad/s` | 直道 `0.32` / 弯道 `0.14 m/s` |

**判定**：我们**不做车载视觉循迹**（走网格航点），所以吸收点是**控制律增强**：Line_Follower 的 6 重机制可直接搬到我们的 CTE 修正项上，把纯 P 升级为带保护的 PI。

### 2.3 路径规划 + 跟踪（pb2025 vs 我们）

| 维度 | pb2025_sentry_nav | 我们 |
|---|---|---|
| 全局规划 | **NavFn（Dijkstra）** @20Hz，`tolerance=0.5`，`use_astar=false` | 自研**网格 A* + TSP**（mission_router） |
| 路径跟踪 | **OmniPidPursuit**：PP + 双 PID（平移/旋转 `Kp3.0 Ki0.1 Kd0.3`） | PP（`AIM_DRIVE=0.35m`）+ CTE-P + 开环弧 |
| 前瞻 | **`lookahead_dist=2.0m`，速度自适应 `[0.5,1.0]`，`lookahead_time=1.0`** | 固定 `0.35m` |
| 速度上限 | 平移 `±2.5 m/s`、旋转 `±3.0 rad/s` | `0.32 / 0.14 m/s` |
| 分辨率/避障 | `0.05m`，`robot_radius=0.2`，**`inflation_radius=0.7`(≈3.5×半径)** | `0.35m` 格，障碍格**硬墙**（无膨胀） |
| 定位 | point_lio + small_gicp 重定位 | 里程计(Block) + 位置/偏航**吸附** |
| 平滑 | `SimpleSmoother`(`max_its=1000`) | 离线 DP 简化（AGV 工具），机载无平滑 |

**量化**：前瞻 `2.0m` vs `0.35m`（**5.7×**）；但我们是 **0.35m 格网短腿**，长前瞻会**切角**。
**关键判断**：我们的**开环满舵弧 + 位置/偏航吸附**是针对**里程计偏航漂移**的正确设计（pb2025 靠激光雷达闭环，前提不同）→ **不替换**。
**可吸收**：速度自适应前瞻（把固定 `AIM_DRIVE` 改成 `clamp(k·v, min, max)`）、路径平滑以减少转弯数（我们现 **14 转弯**）。

### 2.4 决策编排 + 避障融合（JunLin vs 我们）

| 维度 | JunLin_navigation2025 | 我们 |
|---|---|---|
| 决策 | **BehaviorTree.CPP XML**（`rm_bt_RMUC2.xml`） | 自研 **dzbrain 状态机**（679 测试绿） |
| 局部规划 | **TEB** @**50Hz** | 开环弧 + PP @20Hz |
| 传感融合 | 3D mid360 + 2D 雷达，避障范围限定 **[0.1,1.5]m** | 以里程计为主（无雷达） |

**判定**：BT 与 TEB 前提不同（我们无雷达、任务链固定）→ **暂不替换**（与我们既有结论一致）。值得记一笔的是**控制器频率 50Hz** 与**限定避障距离带**的思路。

## 6. 吸收落地结果（实测，2026-10-18）

### 6.1 P0-1 检测召回策略 —— ❌ 被实测**否决**
工具：`det_recall_ab.py`（导入 `video_field_recon` 后替换其模块级全局 `CONF/NMS_IOU/VOTE_MIN` 再调 `main()`，在 **4 段真机视频**上对拍，对照官方固定 8 雷基线）。

| 预设 | conf | NMS | 投票门槛 | 平均雷召回 | 平均检出障碍数 |
|---|---|---|---|---|---|
| baseline（现状） | 原值 | 0.45 | 2 | **22%** | **2.0** |
| balanced | ×0.5 | 0.55 | 1 | 22% | 5.5 |
| recall（SpireCV 式） | ×0.25 | 0.60 | 1 | 25% | **6.5** |

**结论**：降阈几乎不涨召回（22%→25%），**误检倍增**（2.0→6.5，个别视频检出 10~12 个障碍）。
→ **不采纳** SpireCV 的激进降阈策略。实测反而定位出**真正瓶颈**：**网格拟合成功率仅约 50~62%**
（如 091746：148 帧仅 96 帧 `grid_ok`），且落格投票有「锚点 1.5 格 + 残差 ≤0.35 + 最少票数」三重门控
→ 漏检主要发生在**几何拟合/投票环节**，不在检测器阈值。下一步应投向**提高网格拟合帧率 / 放宽投票门控**，而非调 conf。
