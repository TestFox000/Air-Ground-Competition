## 2. 车端优化（`src/ag_integrate/`）

### 2.1 `intel_protocol.py` — CRC16 查表 + memoryview 零拷贝

- **改前**：`crc16` 逐位计算，`parse` 切片校验会产生字节拷贝。
- **改后**：
  - 模块加载时生成 256 项查表 `_CRC_TABLE`（多项式 `0xa001`，与机上 UdpBroadcaster 逐位算法数学等价，`"123456789"→0x4B37`）。
  - `crc16(data)` 接受 `bytes | memoryview`；`parse` 用 `memoryview(data)[4:body_end]` 零拷贝校验。
- **证据**：`tests/test_integrate_protocol.py` 新增逐位参考实现 + 随机交叉验证 + memoryview 兼容测试。

### 2.2 `integrate_node.py` — 线程模型重构

- **改前**：收包线程里直接做 parse → 态势归并 → 门控 → 路由 → 发布，重活堆在 UDP 线程。
- **改后**（三段式）：
  1. **UDP 后台线程**：只做 收包 → `parse` → `WorldModel.update` → `_submit()`。
  2. **交接队列**：`queue.Queue(maxsize=1)`，满了先丢旧帧再放新帧（态势数据只要最新，决策慢于到达率时自动跳帧）。
  3. **ROS timer 回调**（executor 线程，`create_timer(0.1, _on_tick)`）：取最新帧 → `_handle()` 做门控/路由/发布。后台线程**不碰** ROS API。
- **证据**：`tests/test_integrate_node.py`（4 个测试：最新帧语义、门控 hold 记一次/dry_run 不发布、路线去重）。

## 3. 机载端优化（`onboard/dzuav/`，C++）

### 3.1 `HbbDetector` / `CellClassifier` — TRT 推理热路径

- **pinned 主机缓冲**：`cudaMallocHost` 分配 `h_input_/h_output_`，H2D/D2H 走 DMA 直传，免驱动 staging 中转（NVIDIA TRT 官方建议，提速 30~50%）。Orin 是 I/O coherent，CPU 访问 pinned 无额外代价。
- **张量地址一次绑定**：构造期 `setTensorAddress` 一次，每帧只 `enqueueV3`。
- **去每帧分配**：`blob_` 用 `cv::Mat(4, sizes, CV_32F, h_input_)` 包住 pinned 内存；`blobFromImage` 对同形状 OutputArray 不重新分配（Mat::create 契约）。即使个别 OpenCV 版本内部重分配，后续拷贝也从 `blob_.ptr()` 取址，正确性不受影响。

### 3.2 `MapLocalizer` — 畸变映射预计算

- **改前**：每帧 `cv::undistort` 内部重新计算映射。
- **改后**：`cv::undistort` 等价分解为 `initUndistortRectifyMap`（unity R）+ `remap`（INTER_LINEAR）。同分辨率只算一次 map，每帧只 remap，输出逐位等价。
- **实现**：hpp 加 `mutable cv::Mat map_x_, map_y_; mutable cv::Size cached_size_{};`；首次或分辨率变化时计算，之后复用。

### 3.3 `UdpBroadcaster` — CRC 查表 + 缓冲复用

- `crcTable()` 匿名 namespace 内 lambda 静态初始化 256 项查表，`crc()` 查表实现。
- 新增 `std::vector<uint8_t> buf_` 成员，`send()` 中 `buf_.clear()` 复用容量，免每帧重新分配。
- 仍用 `put<T>` 小端拼接，协议字节布局不变（magic/version/ts/msg_id/length/count/objects/crc/suffix）。

### 3.4 `TensorRtEngine.hpp` — 前向兼容 TRT 10

- 析构 `destroy()` → `delete context_/engine_/runtime_`。`destroy()` 在 TRT 8.x 起废弃、10.x 移除；`delete` 在 8/10 均合法。

### 3.5 `main.cpp` — 相机实时模式免绘制

- `const bool annotate = !output.empty();`：相机实时模式（`processFrame(frame, ..., {})`）跳过 `clone`/画框/`putText`/`imwrite`，省每帧 ~6MB 分配与绘制耗时。
- **UDP 发送无条件保留**：`objects` 构建与 `udp.send` 仍执行，保证链路不断。
- `std::endl` → `"\n"`：省 30fps 下的流刷新。

## 4. 新增工具

### 4.1 `tools/orin_build_verify.sh` — Orin 一键编译+分层验证

**为什么在 Orin 上跑**：`UdpBroadcaster.cpp` 用 POSIX socket 头、CMakeLists 硬编码 `aarch64-linux-gnu` 的 TensorRT 路径、`argus:` 相机依赖 Jetson 专有 `nvarguscamerasrc`——Windows 本机配不出。

**分层验证**：

| 层级 | 内容 | 失败行为 |
|---|---|---|
| L0 | arm64 / TensorRT / CUDA 自检；apt 装 `build-essential cmake libopencv-dev gstreamer1.0-tools`；**apt 源默认换清华 ubuntu-ports 镜像**（幂等、备份 `.bak`、只换域名保留代号 focal/jammy，NVIDIA L4T 源保持官方） | TRT/CUDA 缺失 → 提示"只随 JetPack 刷机提供，apt 装不了" |
| L1 | `cmake Release + --parallel $(nproc)` 编译 `onboard/dzuav/build/dzuav` | 编译错误直接暴露 |
| L2 | 无参数运行应打印 usage（退出码 2 属预期） | 输出+退出码全打印 |
| L3 | `--run <engines目录> <测试图>`：自动发现 `*hbb*`/`*cell*` 引擎跑真实推理；后台 Python 监听 UDP:50000，**用车端 `intel_protocol.parse` 做 magic/CRC16/后缀全量校验**——机上编码↔车端解析闭环 | `localized=0` 时提示换含 ≥4 个清晰格号的图 |

```bash
tools/orin_build_verify.sh                                   # L0~L2
tools/orin_build_verify.sh --run ~/engines ~/test/field.jpg  # 追加 L3
tools/orin_build_verify.sh --no-mirror                       # 不动 apt 源
```

### 4.2 `tools/fake_udp_sender.py` — 假机载 UDP 发送器

**用途**：无人机未上线时，在任何机器上模拟 dzuav 的 UDP:50000 广播，驱动车端 `integrate_node` 跑通"收包→解析→态势归并→门控→路线"全链路。

- 复用 `intel_protocol.build()`，**字节级对应机上 UdpBroadcaster**。
- 用 `field_frame.cell_to_world` 把格号换算成世界坐标，保证车端 `world_to_cell` 能反算回原格号。
- 默认场景 `B3:mine,H7:target_blue` 满足门控（`min_mines=1`, `require_face=True`）。

```bash
tools/fake_udp_sender.py                                  # 默认场景，5Hz 循环
tools/fake_udp_sender.py --scenario B3:mine,D5:obstacle,H7:target_blue --once
tools/fake_udp_sender.py --port 50000 --rate 10
```

## 8. 环境与提交注意事项（接手必看）

- **私人令牌**：仅存储在凭据存储文件（`.git-credentials`），**禁止**拼入 push URL/命令行。
- **提交**：按文件名 `git add <file>`，**禁止** `git add -A`。
- **commit message**：中文用 Python 写 UTF-8 临时文件 + `git commit -F <file>`（PowerShell 直接传中文会乱码）。
- **push 后核实**：`git rev-parse HEAD origin/main` 必须一致。`post-commit` 钩子存在静默失败风险（`|| true`），失败不影响提交但可能没推送。
- **`.codebuddy/automations/air-ground/memory.md`**：外部工具自动改的，勿 add 勿碰。
- **`build/` 已 `.gitignore`**：`onboard/dzuav/build` 编译产物不会入 git。
- **CRLF 警告无害**：仓库用 `.gitattributes` 保证 LF 行尾。
- **PowerShell 5 无 `&&`**：链式命令用 `;`。
