## 4. 根因（代码级）

### 4.1 tracker-safe 无解：设计硬约束与现役图直接冲突

- `planner.py:3113-3137`：**禁 180°**（顶点转角 ≤90°）、**禁紧凑 U**、pivots 恒空；
- `planner.py:4102-4130`：`allow_reverse=False`、`pivots=()` 固定；
- 现役第六图 68-token 路线有 **3 个 `:PIVOT`**（I4/G4/A1），第七图 57-token 也有 3 个；
- ⇒ tracker-safe 不是“随机失败”，是**结构上不可能**产出与现役路线同构的解。要启用它，必须二选一：扩引擎支持 PIVOT，或把现役路线改成无 180°（这是产品决策，不是仿真台能改的）。

### 4.2 global_planner 的四个硬缺陷

1. **起点可能被插到桥洞后面**：`plan_tour()` 用 `greedy_insert()`，而 `greedy_insert` 允许插到索引 0（`global_planner.py:441-459`，`range(len(cur)+1)`）⇒ 第六图/随机 pilot 0 的输出以 **K7** 开头（N10 在第 4 个 token），第六图换 `--start-heading w/e` 都一样。
2. **射击候选只有 8 邻域**：`candidate_shoot_points()` 只取靶格周围 8 格（`global_planner.py:463-488`，距离 0.35/0.495 m），而现配置射击窗口是 **0.78~1.02 m**（`config/robot.yaml:397-398` 与 `:685-686`）⇒ 永远找不到合法候选，`_rank_shoot_points()` 只好回退到 0.35 m（`:539-543`），route_check 报“靶覆盖 0/2、射击点距离超范围”。
3. **靶板不是障碍**：`Grid(obs_s)` 只把障碍格设为不可通行（`global_planner.py:147-156`、`:824`），A* 可以穿过靶板格；输出里出现 `E7*`/`D5`/`J2` 等压靶 token，route_check 报“航点压过靶板/车体压靶板”。
4. **无 route_check 门禁、无测试、未接入车端**：CLI 直接打印路线（`:884-886`），不跑校验；`planner.engine` 白名单只有两项（`tasks/mission.py:271-280`、`tools/plan_route.py:264`）；`grep global_planner src/dzbrain/tests` = 0。

### 4.3 tour 的边界

- 第六/第七图均通过 route_check；随机图 1/3。失败 1 是“无解 H1→L3”（可能是生成器给的障碍/桥洞组合导致连通性不足，未单独证明）；失败 2 是 tour 自己结构自检拒绝“下半场穿洞 2 次”——**tour 会产出被自己门禁拒绝的路线**，用 `--check` 时表现为失败，属预期门禁行为。

## 5. 建议（按优先级）

1. **车端引擎裁决（需 Lead/用户拍板，D-008 冻结区）**：现配置 `planner.engine=tracker-safe` 对第六/第七图均无解；若打开 auto_plan，会直接无解。二选一：
   - 切 `tour`（立即可用；代价是放弃 tracker-safe 的硬约束）；
   - 或扩 tracker-safe 支持显式 `:PIVOT`（工程量大，但“真车能跟住”的目标不变）。
2. **global_planner 不建议上车**：5/5 合法率 0；若保留为工具，先修 4.2 的 1/2/3，并接 route_check 门禁 + 至少 1 个带牙测试。
3. **执行层优先于扩量**：T19 已证 3/3 tour sim diverged；D-005 的“pilot 全绿”未达成，**不要铺 30+10**。先修 T27/sim 的倒车/PIVOT/锚定执行模型，再扩量。
4. **仿真台补第三引擎适配**：当前 stress 的 `engine` 只透传 `plan_route.py` 的两个值；global 只能用 CLI 代跑。若要长期审计三引擎，应给 stress 加 `engine=global` 适配（或独立 plan-only 适配器），否则口径不可完全对齐。

## 7. 限制（如实）

- 随机图 **3 张**（D-005：pilot 全绿前不铺 30+10），统计意义有限；扩量被“执行层 sim 全部 diverged”阻塞。

- global_planner 未在仿真台链路内执行（无适配），因此“执行层”只对 tour 做了 1 次 track 模式；它的轨迹安全性未验证。
