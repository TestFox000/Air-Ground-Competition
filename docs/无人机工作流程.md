# 无人机工作流程

> 本文档梳理机载端（Orin Nano）从起飞到广播情报的完整流水线，以及与车端的对接。
> 源码位置：`onboard/dzuav/`（C++ 侦察栈）、`reference/onboard/dzpx4`（官方飞控栈，归档）。

---

## 0. 职责边界：哪些是官方的，哪些是我们的

```
[机载 Orin Nano]
  ┌─ dzpx4（官方，直接用，不改）────────────────────────────┐
  │  MID360 激光 → FASTLIO2 建图/定位 → PX4 飞控              │
  │  px4_control / px4_path 执行航线（起飞/巡航/航线/返航）     │
  └──────────────────────────────────────────────────────────┘
  ┌─ dzuav（我们维护的侦察栈，C++）──────────────────────────┐
  │  AR0234 下视相机 → 去畸变 → HbbDetector(7类检测)           │
  │    → CellClassifier(格号识别) → MapLocalizer(PnP 自定位)   │
  │    → UdpBroadcaster（二进制 UDP :50000 广播）              │
  └──────────────────────────────────────────────────────────┘
                          │ UDP :50000
                          ▼
[车端香橙派] 官方 dzrobot：path_executor / dztrack / Nav2 负责开车
            我们的 ag_integrate：收 :50000 → 世界模型 → 官方车命令 + 禁火保险
```

- **飞的部分**（起飞、航线、返航、避障）：全归官方 `dzpx4`，我们不碰。
- **看的部分**（相机→检测→定位→广播）：`dzuav`，是我们的代码。
- **车的部分**：全归官方 `dzrobot`，我们只做一层薄集成（`ag_integrate`）。

## 1. dzuav 单帧处理流水线

每帧相机图像经过以下步骤（[onboard/dzuav/src/main.cpp](../onboard/dzuav/src/main.cpp) `processFrame()`）：

```
相机帧 (BGR, 1920x1080)
    │
    ▼
① MapLocalizer.undistort(frame)        去畸变（映射预计算，同分辨率只算一次）
    │
    ▼
② HbbDetector.infer(image)             TensorRT 推理，1280x1280 输入
    │                                    输出 7 类目标的像素框 + 置信度
    ▼
③ 遍历检测结果：
   ├─ CellLabel 类 → 裁剪 ROI → CellClassifier.infer(roi) → 得到格号 CellId
   │  （收集 landmarks: (CellId, 像素中心点)）
   │
   └─ 其它类暂存，等定位成功后再投影
    │
    ▼
④ MapLocalizer.solve(landmarks, size)  PnP 自定位
    │  需 ≥4 个有效格号，且格号凸包面积 ≥ 2% 画面
    │  solvePnPRansac 求相机外参 (rvec, tvec)
    │  成功后计算 Hinv（像素→世界的单应逆）
    ▼
⑤ 定位成功 → 对每个非格号目标：
   MapLocalizer.project(像素中心) → 场地世界坐标 (米)
   构建 WorldObject(type, position, length, width)
    │
    ▼
⑥ UdpBroadcaster.send(timestamp, objects)
   二进制 UDP 广播到 :50000
    │
    ▼
⑦ stdout: "localized=1 landmarks=N [{...}]"
   （相机实时模式不画框、不落盘，省每帧 ~6MB 分配）
```

### 1.1 各模块关键参数

| 模块 | 输入 | 输出 | 关键参数 |
|---|---|---|---|
| **HbbDetector** | 去畸变后图像 | 7 类检测框 | 输入 resize 到 1280×1280，confidence=0.25，NMS=0.45 |
| **CellClassifier** | CellLabel 的 ROI | 格号 (A~N, 1~11) | 输入 96×96，置信度阈值 0.55 |
| **MapLocalizer** | landmarks + 图像尺寸 | 相机位姿 + Hinv | 需 ≥4 格号，凸包面积 ≥ 2% 画面 |
| **UdpBroadcaster** | WorldObject 列表 | UDP 帧 | 端口 50000，广播地址 255.255.255.255 |

## 2. PnP 自定位原理（核心，无 H 标定）

**为什么不需要单应矩阵 H 标定**：地面格号是天然地标，每个格号的世界坐标已知。

### 2.1 格号的世界坐标

[onboard/dzuav/src/MapLocalizer.cpp](../onboard/dzuav/src/MapLocalizer.cpp) `world()`：

```
world_x = 0.065 + (column - 'A') × 0.35     // column: 'A'=0 .. 'N'=13
world_y = 0.295 + (11 - row) × 0.35          // row: 1..11
world_z = 0                                    // 地面平面
```

格间距 0.35 m，场地 14 列 × 11 行。

### 2.2 定位流程

1. 检测到 ≥4 个格号，得到每个格号的 **(世界坐标 3D, 像素坐标 2D)** 对应
2. `cv::solvePnPRansac` 求相机外参 `(rvec, tvec)`（旋转 + 平移）
3. 由旋转矩阵 R 和平移 t 构造地面平面单应 `H = K × [r1 r2 t]`
4. 求逆 `Hinv`，之后任意像素点 `(u, v)` 投影到世界坐标：

```
[X, Y, 1]^T = Hinv × [u, v, 1]^T
world_x = X / Z,  world_y = Y / Z
```

### 2.3 定位失败的情况

- 格号 < 4 个 → `solve()` 返回 false，不广播（`localized=0`）
- 格号凸包面积 < 2% 画面（格号挤在一角，PnP 病态）→ 失败
- RANSAC 内点 < 4 → 失败

> 这意味着无人机必须飞到能看到 **4 个以上分散格号** 的高度和位置才能定位。

## 3. UDP 广播协议（:50000）

字节布局（全部小端），严格对应 [onboard/dzuav/src/UdpBroadcaster.cpp](../onboard/dzuav/src/UdpBroadcaster.cpp)：

```
偏移  长度  字段        说明
0     4     magic       0xef 0xef 0xef 0xef
4     1     version     0x10
5     8     timestamp   uint64，机上毫秒时间戳
13    2     msg_id      0x4001
15    4     length      uint32 = 2 + 25 × count
19    2     count       uint16，目标数量
21    25×N  objects     每目标 25 字节：
                        type    uint8   (0=mine,1=car,2=arrow,3=target_red,
                                          4=cell_label,5=target_blue,6=obstacle)
                        x       float64 世界坐标 x（米）
                        y       float64 世界坐标 y（米）
                        length  float32 像素语义：检测框宽（并非米；车端暂不使用）
                        width   float32 像素语义：检测框高（并非米；车端暂不使用）
21+25N 2   crc16       uint16，CRC-16/Modbus，覆盖 version 到最后一个目标
+2    4     suffix      0xfe 0xfe 0xfe 0xfe
```

**CRC 校验值**：`"123456789"` → `0x4B37`。车端 `intel_protocol.parse()` 做 magic/version/msg_id/length/crc/suffix 全量校验，任一不一致抛 `ValueError`。

## 4. 完整任务时序（起飞 → 情报下发 → 车执行）

```
t0   人工/地面站指令起飞
     │
     ▼
t1   dzpx4 起飞，爬升到任务高度（能看到 ≥4 个格号）
     │
     ▼
t2   dzuav 开始处理相机帧：
       - 检测格号 → PnP 定位成功（localized=1）
       - 检测目标（雷/箭头/障碍/红蓝靶）→ 投影到世界坐标
       - 每帧 UDP:50000 广播（约 30 fps）
     │
     ▼
t3   车端 ag_integrate.integrate_node 收 UDP:
       - parse() 解析
       - WorldModel 归并态势
       - 门控评估（雷 ≥1 且 有靶面）
       - build_mission() 生成路线
       - 发 /nav/waypoint（先 reset 断言位置+朝向，再发路线）
     │
     ▼
t4   官方 path_executor 执行路线（纯追踪）
     │
     ▼
t5   任务完成，dzpx4 返航
```

## 5. 与车端朝向问题的关系

车端 `reset:N10,y` 盲目断言朝向 = 90°，但车被搬到起点时真实朝向可能不同（实测差 68.6°），导致绕圈。

**无人机根除方案已落地为 0x4002 车位姿帧**：dzuav 定位有效且检测到车（`ObjectClass::Car = 1`）时：
1. 检测车的像素框 → `project()` 得到车的世界坐标
2. `estimateCarYaw()` 用红色方向标记估计车头朝向 → 车的真实朝向
3. `UdpBroadcaster.sendCarPose()` 以 `msg_id=0x4002` 广播 (x, y, yaw) —— 协议已扩展，45 字节
4. 车端 `heading_bias_source=align` 用它闭环原地转向到断言朝向（零残差），详见 `车朝向根除方案.md`

> 本节早前版本写的"当前协议只广播目标位置、不广播车的朝向"已过时（2026-10-14 修订）。
