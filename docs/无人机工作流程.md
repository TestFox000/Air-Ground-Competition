# 无人机工作流程

> 本文档梳理机载端（Orin Nano）从起飞到广播情报的完整流水线，以及与车端的对接。
> 源码位置：`onboard/dzuav/`（C++ 侦察栈）、`reference/onboard/dzpx4`（官方飞控栈，归档）。

---

## 0. 职责边界：哪些是官方的，哪些是我们的

```
[机载 Orin Nano]
  ┌─ dzpx4（官方，直接用，不改）────────────────────────────┐
  │  MID360 激光 → FASTLIO2 建图/定位 → PX4 飞控              │
  │  px4_control / px4_path 执行航线（起飞/巡航/航线/返航）     │
  └──────────────────────────────────────────────────────────┘
  ┌─ dzuav（我们维护的侦察栈，C++）──────────────────────────┐
  │  AR0234 下视相机 → 去畸变 → HbbDetector(13 类检测)         │
  │    → CellClassifier(格号识别) → MapLocalizer(PnP 自定位)   │
  │    → UdpBroadcaster（二进制 UDP :50000 广播）              │
  └──────────────────────────────────────────────────────────┘
  ┌─ 机载自主规划（我们维护，Python，无 ROS）────────────────┐
  │  orin_plan_sidecar 收 :50000 → 世界模型 → 落格矩阵         │
  │    → 任务路由 → route_plan.json / cell_matrix.json        │
  │    → 广播 0x4003 车命令                                    │
  └──────────────────────────────────────────────────────────┘
                          │ UDP :50000（0x4001/0x4002 同机消费，0x4003 下车）
                          ▼
[车端香橙派] 官方 dzrobot：path_executor / dztrack / Nav2 负责开车
           我们的 ag_integrate（薄接收）：收 0x4003 → 转 /nav/waypoint + 禁火保险
```

- **飞的部分**（起飞、航线、返航、避障）：全归官方 `dzpx4`，我们不碰。
- **看的部分**（相机→检测→定位→广播）：`dzuav`，是我们的代码。
- **规划的部分**（世界模型→落格矩阵→任务路由→车命令）：**在机上**跑
  （`tools/orin_plan_sidecar.py`），依据官方控制要求「无人机的定位、建图、识别、
  规划与控制等实时任务须由机载平台自主完成」。
- **车的部分**：开车执行全归官方 `dzrobot`，我们只做薄接收（吃 0x4003 → 转
  `/nav/waypoint`），不再在车端做规划。

## 1. dzuav 单帧处理流水线

每帧相机图像经过以下步骤（[onboard/dzuav/src/main.cpp](../onboard/dzuav/src/main.cpp) `processFrame()`）：

```
相机帧 (BGR, 1920x1080)
    │
    ▼
① MapLocalizer.undistort(frame)        去畸变（映射预计算，同分辨率只算一次）
    │
    ▼
② HbbDetector.infer(image)             TensorRT 推理，1280x1280 输入
    │                                    输出 13 类目标的像素框 + 置信度
    ▼
③ 遍历检测结果：
   ├─ CellLabel 类 → 裁剪 ROI → CellClassifier.infer(roi) → 得到格号 CellId
   │  （收集 landmarks: (CellId, 像素中心点)）
   │
   └─ 其它类暂存，等定位成功后再投影
    │
    ▼
④ MapLocalizer.solve(landmarks, size)  PnP 自定位
    │  需 ≥4 个有效格号，且格号凸包面积 ≥ 2% 画面
    │  solvePnPRansac 求相机外参 (rvec, tvec)
    │  成功后计算 Hinv（像素→世界的单应逆）
    ▼
⑤ 定位成功 → 对每个非格号目标：
   MapLocalizer.project(像素中心) → 场地世界坐标 (米)
   构建 WorldObject(type, position, length, width)
    │
    ▼
⑥ UdpBroadcaster.send(timestamp, objects)
   二进制 UDP 广播到 :50000
    │
    ▼
⑦ stdout: "localized=1 landmarks=N [{...}]"
   （相机实时模式不画框、不落盘，省每帧 ~6MB 分配）
```

### 1.1 各模块关键参数

| 模块 | 输入 | 输出 | 关键参数 |
|---|---|---|---|
| **HbbDetector** | 去畸变后图像 | 13 类检测框 | 输入居中 letterbox 到 1280×1280，按类别 confidence（见 `main.cpp` kDeployConf），NMS=0.45 |
| **CellClassifier** | CellLabel 的 ROI | 格号 (A~N, 1~11) | 输入 96×96，读数阈值 0.65（`main.cpp` kCellMinConf） |
| **MapLocalizer** | landmarks + 图像尺寸 | 相机位姿 + Hinv | 需 ≥4 格号，凸包面积 ≥ 2% 画面 |
| **UdpBroadcaster** | WorldObject 列表 | UDP 帧 | 端口 50000，广播地址 255.255.255.255 |

## 2. PnP 自定位原理（核心，无 H 标定）

**为什么不需要单应矩阵 H 标定**：地面格号是天然地标，每个格号的世界坐标已知。

### 2.1 格号的世界坐标

[onboard/dzuav/src/MapLocalizer.cpp](../onboard/dzuav/src/MapLocalizer.cpp) `world()`：

```
world_x = 0.065 + (column - 'A') × 0.35     // column: 'A'=0 .. 'N'=13
world_y = 0.295 + (11 - row) × 0.35          // row: 1..11
world_z = 0                                    // 地面平面
```

格间距 0.35 m，场地 14 列 × 11 行。

### 2.2 定位流程

1. 检测到 ≥4 个格号，得到每个格号的 **(世界坐标 3D, 像素坐标 2D)** 对应
2. `cv::solvePnPRansac` 求相机外参 `(rvec, tvec)`（旋转 + 平移）
3. 由旋转矩阵 R 和平移 t 构造地面平面单应 `H = K × [r1 r2 t]`
4. 求逆 `Hinv`，之后任意像素点 `(u, v)` 投影到世界坐标：

```
[X, Y, 1]^T = Hinv × [u, v, 1]^T
world_x = X / Z,  world_y = Y / Z
```

### 2.3 定位失败的情况

- 格号 < 4 个 → `solve()` 返回 false，不广播（`localized=0`）
- 格号凸包面积 < 2% 画面（格号挤在一角，PnP 病态）→ 失败
- RANSAC 内点 < 4 → 失败

> 这意味着无人机必须飞到能看到 **4 个以上分散格号** 的高度和位置才能定位。

## 3. UDP 广播协议（:50000）

字节布局（全部小端），严格对应 [onboard/dzuav/src/UdpBroadcaster.cpp](../onboard/dzuav/src/UdpBroadcaster.cpp)：

```
偏移  长度  字段        说明
0     4     magic       0xef 0xef 0xef 0xef
4     1     version     0x10
5     8     timestamp   uint64，机上毫秒时间戳
13    2     msg_id      0x4001
15    4     length      uint32 = 2 + 25 × count
19    2     count       uint16，目标数量
21    25×N  objects     每目标 25 字节：
                        type    uint8   ObjectClass（13 类）。
                                        ⚠️ 枚举值**不在本文档维护**：唯一真源是
                                        `docs/interface_contract.md` §2.4，它与
                                        `onboard/dzuav/include/dzuav/types.hpp`
                                        的 ObjectClass 及 `intel_protocol.py` 的
                                        ObjectType 三处逐项对齐（有测试守）。
                                        本机载端写的是 `uint8_t(x.type)`
                                        （UdpBroadcaster.cpp），即 types.hpp 的原值。
                                        此处曾长期抄着一份 7 类旧表（把 0 当作
                                        mine、1 当作 car、2 当作 arrow…），与真源
                                        逐位错位：按那份表解析会把 5=OBSTACLE 读成
                                        "target_blue" 直接开火、把 4=TARGET_BLUE
                                        读成 "cell_label" 直接丢掉。
                        x       float64 世界坐标 x（米）
                        y       float64 世界坐标 y（米）
                        length  float32 像素语义：检测框宽（并非米；车端暂不使用）
                        width   float32 像素语义：检测框高（并非米；车端暂不使用）
21+25N 2   crc16       uint16，CRC-16/Modbus，覆盖 version 到最后一个目标
+2    4     suffix      0xfe 0xfe 0xfe 0xfe
```

**CRC 校验值**：`"123456789"` → `0x4B37`。车端 `intel_protocol.parse()` 做 magic/version/msg_id/length/crc/suffix 全量校验，任一不一致抛 `ValueError`。

## 4. 完整任务时序（起飞 → 情报下发 → 车执行）

```
t0   人工/地面站指令起飞
     │
     ▼
t1   dzpx4 起飞，爬升到任务高度（能看到 ≥4 个格号）
     │
     ▼
t2   dzuav 开始处理相机帧：
       - 检测格号 → PnP 定位成功（localized=1）
       - 检测目标（雷/箭头/障碍/红蓝靶）→ 投影到世界坐标
       - 每帧 UDP:50000 广播（**实测约 5 fps**，不是 30）
         ⚠️ 启动脚本请求的是 1920x1080@30，但 AR0234 走 USB2 YUY2 实测上限
         约 200ms/帧 = 5fps（2026-10-14 实测，见 `docs/执行层深优化-20261016.md`
         「相机帧率」行）。扫场速度 ≤0.4-0.5 m/s、每格 ≥2-3 帧冗余这些预算
         全是按 5fps 推的；把这里当 30fps 读会把整条时序预算算错 6 倍。
     │
     ▼
t3   机载自主规划 orin_plan_sidecar 收 UDP（同机回环）:
       - parse() 解析
       - WorldModel 归并态势 + MatrixFusion 落格矩阵
       - 门控评估（雷 ≥1 且 有靶面）
       - build_mission() 生成路线
       - 落 route_plan.json / cell_matrix.json / planned_path.txt
       - 广播 0x4003（reset + route）
     │
     ▼
t3.5 车端 ag_integrate.integrate_node（car_command_source=onboard）收 0x4003:
       - parse_car_command() 校验
       - 转 /nav/waypoint（不再在车端做规划）
     │
     ▼
t4   官方 path_executor 执行路线（纯追踪）
     │
     ▼
t5   任务完成，dzpx4 返航
```

## 5. 与车端朝向问题的关系

车端 `reset:N10,y` 盲目断言朝向 = 90°，但车被搬到起点时真实朝向可能不同（实测差 68.6°），导致绕圈。

**无人机根除方案已落地为 0x4002 车位姿帧**：dzuav 定位有效且检测到车（`ObjectClass::Car = 1`）时：
1. 检测车的像素框 → `project()` 得到车的世界坐标
2. `estimateCarYaw()` 用红色方向标记估计车头朝向 → 车的真实朝向
3. `UdpBroadcaster.sendCarPose()` 以 `msg_id=0x4002` 广播 (x, y, yaw) —— 协议已扩展，45 字节
4. 车端 `heading_bias_source=align` 用它闭环原地转向到断言朝向（零残差），详见 `车朝向根除方案.md`

> 本节早前版本写的"当前协议只广播目标位置、不广播车的朝向"已过时（2026-10-14 修订）。

## 7. 快速命令

### 7.1 机载端（Orin Nano）

```bash
# 0. 部署（笔记本上执行；远端统一布局 ~/dzuav_deploy/air_ground）
set AG_ORIN_PASS=******
python tools/orin_deploy.py --host <Orin IP> --user <用户> [--verify]

# 1. 机上：编译 + 分层验证（L0~L3）
cd ~/dzuav_deploy/air_ground
tools/orin_build_verify.sh                    # L0~L2
tools/orin_build_verify.sh --run ~/dzuav/engines ~/test/field.jpg   # 追加 L3（真实推理 + 协议闭环）

# 2. 引擎转换（ONNX -> TRT FP16，换机/刷机后必跑；引擎目录约定 ~/dzuav/engines）
#    ⚠️ 机上已有 13 类引擎时**不要**跑：会按 models/release 的指针重转并覆盖，不可逆
tools/orin_convert_engines.sh -o ~/dzuav/engines

# 3. 全栈启动（tmux 会话 agup，11 个窗口：hold/dzuav/plan/livox/fastlio/px4/odom/imu/control/path/teleop）
#    看门狗不在这个会话里（orin_watchdog / orin_agent_watchdog 各自单跑）
tools/orin_bringup.sh up

# 手动单跑 dzuav（二进制与引擎路径按 orin_deploy 约定布局）
# ⚠️ 引擎文件名务必用 canonical 名（下方 HBB/CELL）：hbb_detector_fp16.engine /
#    cell_classifier_fp16.engine 是 9 月的 **7 类**命名。2026-10-22 实测机上这两组
#    名字下的**内容相同**（md5 d9779a7b… / eb46548d…，是人工别名维持的），所以照旧名
#    敲当下不会错；但一旦重转引擎或换机，旧名要么缺文件、要么（指针过期时）真的产出
#    7 类引擎——那时类别索引会与 13 类协议错位（索引 5 文档写 target_blue、实际是
#    obstacle），车端朝障碍物开火而界面上看不出异常。真源是 tools/orin_run_dzuav.sh
#    的 HBB_ENGINE/CELL_ENGINE。
BIN=~/dzuav_deploy/air_ground/onboard/dzuav/build/dzuav
ENG=~/dzuav/engines
HBB=$ENG/hbb_detector_d13_fp16.engine
CELL=$ENG/cell_classifier_v4d_fp16.engine
# 相机实时模式（不画框不落盘，只广播）
$BIN uvc:/dev/video0 "$HBB" "$CELL" 50000 1920x1080@30
$BIN argus:0         "$HBB" "$CELL" 50000 1920x1080@30

# 离线图片模式（第 5 个参数是输出目录；**省略**它就别写空串，见 main.cpp 注释）
$BIN test.jpg "$HBB" "$CELL" 50000 output_dir/
```
