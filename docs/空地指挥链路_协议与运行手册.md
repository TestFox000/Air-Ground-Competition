## §1 架构（两层链路，别把它们混成一层）

```
                    ┌───────────────── 无人机 10.29.122.104 ─────────────────┐
                    │  dzuav 视觉程序 / tools/perception 俯瞰感知管线        │
                    │     网格注册 → 雷/障/靶 → 车位姿 → 桥顶箭头            │
                    │                    │                                  │
                    │              protocol.build_*()  →  JSON              │
                    │                    ▼                                  │
                    │      tools/link/dzlink_supervisor.py（常驻）           │
                    │      · 1 Hz 心跳   · 情报转发（bridge/2 s，其余变了才发）│
                    │      · ack 台账    · 路线/复位下发（RELIABLE）         │
                    └──────┬──────────────────────────────┬─────────────────┘
       /dzlink/drone_to_car│(JSON,BEST_EFFORT)   /nav/waypoint│(路线命令,RELIABLE)
                           ▼                              ▼
                    ┌──────────────── 小车 192.168.137.241 ─────────────────┐
                    │  DroneTask(5 Hz)                    MissionTask(10 Hz) │
                    │   解析 JSON → P_DRONE + EV_BRIDGE_INFO   订阅情报事件   │
                    │   心跳判在线 / 车状态回传 / ack         → 选穿洞格     │
                    │                     │                        → 规划/换洞 │
                    │                     └── /dzlink/car_to_drone ──┐        │
                    │  TrackerTask(50 Hz) ← 路线 ←──────────────────┘        │
                    └───────────────────────────────────────────────────────┘
```

**两条链路的角色完全不同，现场排障别串**：

| 链路 | 用途 | 丢了会怎样 |
|---|---|---|
| **A 通道** `/nav/waypoint`（RELIABLE） | 把**路线/复位**交给车（`route` / `reset:格,朝向`） | 车没有新路线 → 停在原地（`auto_start=false` 时本来就不动） |
| **B 通道** `/dzlink/*`（BEST_EFFORT） | **情报 + 心跳 + 车态回传**，即"指挥" | 车按 `robot.yaml` 的默认穿洞格走（K10/K5），**照样能完赛**（这就是降级设计） |

> **设计铁律**：B 通道**永远不是**完赛的必要条件 —— 无人机全掉线时车按默认洞走。
> 所以联调时"没换洞"先查 B 通道，"车不动"先查 A 通道。

## §2 双向报文契约（字段级，逐条对照车侧源码）

### 2.1 无人机 → 车（`/dzlink/drone_to_car`）

四种 `type`，**未知 `type` 只记日志不崩**（`drone.py:236-240`）—— 所以**新增字段安全、新增类型不安全**。

| `type` | 必填字段 | 可选 | 车侧行为 | 出处 |
|---|---|---|---|---|
| `heartbeat` | `type` | `seq` | 刷新心跳；>3 s 无心跳 → `online=False` + 一次告警 | `drone.py:228,244-253`；`robot.yaml:671` |
| `bridge_passable` | `half`∈{`lower`,`upper`}、`block` | `confidence`、`ts`、`seq` | 写 `P_DRONE` + 发 `EV_BRIDGE_INFO`；Mission 据此**换穿洞格** | `drone.py:273-289` |
| `target_zone` | `blocks`（**非空** list） | `ts`、`seq` | 与本地 `map.yaml:targets` 差集 → `field_diff`（只报差异，不改路线） | `drone.py:292-304` |
| `field_verify` | `mines` 或 `obstacles`（至少一个） | `ts`、`seq` | 同上（雷/障） | `drone.py:307-326` |

**样例（照抄，注意 `ts` 可省）**：

```json
{"type":"heartbeat","ts":1791805124.744,"seq":1}
{"type":"bridge_passable","half":"lower","block":"K9","confidence":0.9,"ts":1791805124.7,"seq":2}
{"type":"target_zone","blocks":["B11","C11"],"ts":1791805124.7,"seq":3}
{"type":"field_verify","mines":["A4","B1"],"obstacles":["A5","B7"],"ts":1791805124.7,"seq":4}
```

**归一化规则（车侧做的，发之前不用自己改）**：`half` → `.strip().lower()`；`block` → `.strip().upper()`。
**格名是否在地图内：车侧刻意不校验**（`drone.py:280-281` 明写"穿洞格每局随机，无人机才是权威"）；
真正兜底的是 Mission 侧的候选集合校验（见 §7 降级矩阵）。

### 2.2 车 → 无人机（`/dzlink/car_to_drone`）

| `type` | 字段 | 何时发 | 出处 |
|---|---|---|---|
| `car_state` | `type,block,yaw_deg,phase,ts,seq` | **1~2 Hz 周期**（`drone.car_state_period_s` 默认 0.7 s）＋`phase` 变化即刻 | `drone.py:403-431` |
| `ack` | `{"type":"ack","of":<seq>,"ts":…}` | 收到**带 `seq`** 的消息时回 | `drone.py:255-270` |

**`ack` 是"车真的收到了"的唯一硬证据**：BEST_EFFORT/VOLATILE 链路上，"发出去了"≠"收到了"。
t4 真机实测（`dzsmartscout/tools/reports/t12-evidence/s3_drone_listen.txt`）：
`[listen] 收到 13 条（ack 1 / car_state 12）`、`LISTEN_EXIT=0`。

### 2.3 路线命令（`/nav/waypoint`，RELIABLE）

| 命令 | 语义 | 出处 |
|---|---|---|
| `N10 M10 L10 …` | 一串格名（可带标注：`G10*`=射击停站点、`R:`=倒车段、`N5,y`=终点带朝向） | `mission.py:870-943`（外部命令解析） |

## §4 启动顺序（谁先谁后决定你看到什么）

**铁律：车侧栈必须最后起，而且起之前无人机侧已经在线。**
理由：车侧 `MissionTask` 只在**出发前**用情报换洞；出发后晚到的情报只更新遥测（`mission.py` 模块 docstring）。

```
① 无人机侧（先）
   1. 起 domain + RMW 环境：source 好 `dzlink.env`（ROS_DOMAIN_ID=118）
   2. 起常驻节点：  python3 ~/dzlink_tools/dzlink_supervisor.py run --domain 118
      —— 看到 `[domain] ROS_DOMAIN_ID=118 (来源: envfile)` 与心跳行才算起好
      ★ 域号 118 **仅车端交互 shell 生效**；**非交互 SSH 下两端默认域 0（t4 实测）** ⇒ 发命令内联域号最稳（见坑①）。
   3. 自检：        python3 ~/dzlink_tools/dzlink_supervisor.py selftest      # 25 项应全 PASS
   4. 可选：先手动发一条情报看车收不收
      python3 ~/dzlink_tools/dz_send_waypoint.py bridge lower=K9 --wait-match 15

② 车侧（后）
   5. 摆车：把车放到 N10，车头朝图上"左"（M10→L10 方向）  ← 必须**起栈前**摆好
   6. 起栈：cd ~/dzrobot && ./start_all.sh start
   7. 起完**看横幅**（这是第一份证据）：
         Mission 等情报 2s → 等不到用默认 K10/K5
         穿洞格来源：lower=无人机情报(K9) upper=未收到情报(K5)
      横幅里出现"无人机的格" ⇒ B 通道通了；只有"默认" ⇒ 见 §6 排障

③ 发车（本阶段**不做**）
   8. `mission.auto_start` 现役 = `true` ⇒ **`auto_start_delay_s` = 10 s 到点自动出发**
      （旧文"45 s"是 `path_executor` legacy 段的值，见 §3 事实更正①）；
      也可外部下发 `route` / `reset:` 走手动档。
```

> **顺序反了会怎样**：先起车栈、后起无人机 → 车 **10 s 后就发车**（起点**不会**等情报，
> 见 §3 事实更正②③）→ 这一局用的是**默认洞**（`K9`/`K5`）→ 你会误判"情报没生效"。
> 这不是 bug，是顺序问题；想改成起点等情报必须显式加 `mission.bridge_wait_at_start: true`（本轮未加）。

## §5 三个必须记住的坑（都实测过，别背错）

**坑① 域号：不看环境变量会静默收不到**
两端默认域号**都是 0**（非交互 ssh 下 `~/.bashrc` 的域号声明被守卫挡住；无人机 `.bashrc` 压根没有域号声明）。
118 只活在 `dzrobot/dzros.env` 与 `dzlink_tools/dzlink.env` 里（**118 仅车端交互 shell 生效；非交互 SSH 下两端默认域 0（t4 实测）**）。
⇒ 发命令**内联域号**最稳（仅交互 shell 生效；非交互 SSH 下默认 0）：`ROS_DOMAIN_ID=118 python3 ~/dzlink_tools/dz_send_waypoint.py route "…"`。
报错形态是"什么都没发生"（BEST_EFFORT 静默丢包），**不是**报错。

**坑② `订阅者匹配数=0` ≠ "没发出去"**
发送器在匹配数为 0 时**仍然照发**。所以：
- 看到 0 **不要**重发同一份（会变成车收到两遍）；
- 正确动作：等 `--wait-match`（机侧默认 3 s，**建议现场用 15**）后看匹配数，
  0 就停下来查车侧，而不是连发。
- 匹配数采样要取**最后一个**（历史上把 2 报成 1 就是采样时机问题，`dz_send_waypoint.py:190-203`）。

**坑③ 载荷里的 `ts` 车侧不用：车用的是"收到时刻"**
`drone.py:284` 是 `self.bridge_ts = now`（本拍时钟）。后果有两条，都要记牢：
1. "情报 30 s 过期"是从**车收到**算起 ⇒ **周期性重发同一结论 = 有效续期**；
2. 反过来：**一次都不重发**，30 s 后车就判 stale 回落默认洞。
⇒ 机侧转发节奏 `bridge_period_s=2.0 s`（`dzlink_supervisor.py:939`）远快于 30 s，
   这就是"为什么情报要重复发"的答案（t4 实测 VOLATILE **无补发、首包必丢一**，39/40）。
