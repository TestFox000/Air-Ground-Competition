# 官方环境修复记录 · 2026-09-28

> 当天解决的问题：**`det_node` / `dzactuator` 一直装不上，相机起不来、底盘也起不来。**
> 本文记录根因、改了什么、怎么还原、以及怎么验证修好了。
>
> ⚠️ 这次**动了官方目录**（经授权）。所有改动都在下面列清楚，**每一处都给了还原命令**，
> 且**没有修改任何一行的官方源码**（指纹见 §5）。

## 1. 症状与根因

### 症状

| 现象 | 后果 |
|---|---|
| `ros2 pkg list` 里没有 `det_node` | 相机链跑不起来（`camera.launch.py` 能起，`det_node.launch.py` 报包找不到） |
| 没有 `dzactuator` | **底盘执行器起不来 → 车根本动不了** |
| 没有 `dzrknn_dataprocess` | 云台 / 瞄准不可用 |
| `~/install/det_node` 只有 `share/`，没有 `lib/`、没有 ament 索引 | 看着像装了，实际是个空壳 |

### 根因（关键）

```
colcon build: Duplicate package names not supported:
- det_node:          src/rknn_pt              与  src_4/rknn_pt
- dzactuator:        src/dzactuator           与  src_4/dzactuator
- dzrknn_dataprocess: src/dzrknn_dataprocess  与  src_4/dzrknn_dataprocess
（共 10 个包重复）
```

`~/dzrobot` 下有**三份源码目录**：`src`（正主）、`src_1`（已被 COLCON_IGNORE 标记）、
`src_4`（**是 `src` 的整份副本，连它自己的 build/install/log 一起复制过来的**）。

colcon 从工作区根目录递归扫包，撞到重名**直接拒绝构建** ——
所以**任何人在 `~/dzrobot` 里跑 `colcon build` 都会失败**，`install/` 于是一直是残缺的。

另一个容易绕晕的点：**`det_node` 不是独立源码包**，它的源码是
`src/rknn_pt`（`CMakeLists.txt` 里 `project(det_node)`、`package.xml` 里 `<name>det_node</name>`），
所以构建目录叫 `build/det_node`、包名也叫 `det_node`。
证据：`~/log/build_2026-08-24_22-04-57/det_node/command.log` 里那条
`cmake /home/duzhong/dzrobot/src/rknn_pt -DCMAKE_INSTALL_PREFIX=/home/duzhong/install/det_node`。

## 3. 怎么修（以后的复现命令）

标准做法是 `tools/car_restore_official.sh`（缺什么补什么，会自动跳过已装的）：

```bash
python tools/remote_run.py --host <车IP> --user duzhong --script tools/car_restore_official.sh
```

它内部执行的就是这一条（**必须在 `~/dzrobot` 里、且带 `--base-paths src`**）：

```bash
cd ~/dzrobot
colcon build --base-paths src --packages-select det_node dzactuator dzrknn_dataprocess
```

两个要点，缺一个就会失败或留下隐患：

1. **`--base-paths src`** —— 只扫正主那份源码，绕开 `src_4` 的重名（加了 `COLCON_IGNORE` 之后
   不带它也行了，但显式写着更稳）
2. **不要加 `--symlink-install`** —— 加了会让可执行文件变成指向 `build/` 的**软链接**，
   一旦有人清理 build 目录，装好的包就全失效。**装出来必须是真实文件**（已验证）

## 6. 给下一个人

- **别再手动 `cd ~/dzrobot && colcon build`**：除非你清楚 `src_4` 那件事，
  否则请用 `colcon build --base-paths src ...`（或直接跑 `tools/car_restore_official.sh`）
- **装完一定 `ls -l` 看一眼可执行文件是"真实"还是"软链"** —— 软链在 build 被清理后会静默失效
- 车是公用的：手上有活之前先 `ros2 node list` 看有没有别人在跑；
  `~/dzrobot`、`~/src_save_backup_*`、`~/backup` 里的东西**默认别动**
