# 循迹诊断 · 现场手册

> 工具：`tools/track_diag.py`（"信念 vs 真实"对照诊断）
> 一键启动：仓库根目录双击 **`循迹诊断.bat`**
> 一句话：SSH 抓小车**自认为的状态**，相机看**场上真实状态**，两边逐帧对照，
> 自动报警指出嫌疑模块（画圈/定位停更/执行器未动……）。

---

## 一、赛前一次性准备（约 15 分钟，做完不用再动）

### 1. 打印并贴标记（PNG 已生成好，直接打印）

标记文件在 `docs/track_diag/markers/`（无需运行任何命令）：

| 文件 | 贴哪 | 要点 |
|---|---|---|
| `marker_id0_car_roof.png` | **车顶** | **打印品的上边对准车头方向**；贴歪了就记住歪了多少度，启动时加 `--car-marker-yaw-offset <度>` 修正 |
| `marker_id1_corner1_bottom_left.png` | 场角：相机画面**左下** | 标记中心对准场角，打印 ≥14 cm |
| `marker_id2_corner2_bottom_right.png` | 场角：相机画面**右下** | 同上 |
| `marker_id3_corner3_top_right.png` | 场角：相机画面**右上** | 同上 |
| `marker_id4_corner4_top_left.png` | 场角：相机画面**左上** | 同上 |
| `marker_id5_center_check.png` | （可选）场地正中心 | 贴上后工具会自动打印投影自检误差，cm 级正常 |

打印后**核对白边完整**（ArUco 需要安静区），覆膜防反光，平贴不翘边。
标记打丢了随时可重新生成：`python tools/track_diag.py print-markers docs/track_diag/markers`

### 2. 架相机

- RealSense 景深相机直接 USB 插笔记本（自动识别，不用装驱动之外的软件）；
  普通 USB 相机也行（自动回退，或用菜单启动后在命令行加 `--camera N` 指定）。
- 视野要**完整覆盖 4 个场角标记 + 车的活动区域**，越高越正越好；
  架好后不要再碰（碰了投影就偏，需重跑菜单 [2] 自检确认）。

### 3. 笔记本与小车同一 WiFi

和小车连同一个比赛 WiFi。小车 IP 不用记：启动器会按车上无线网卡 MAC
（`28:2d:06:23:d0:6e`）自动在 ARP 里找，换网段也能认出来。

## 二、场上启动（车到场地后 30 秒）

1. 双击 **`循迹诊断.bat`** → 菜单选 **[1] 开始诊断**
2. 第一次会要两样东西（之后自动记住 IP；密码每次开机输一次、不落盘）：
   - 小车 IP：自动找，找不到会让你手输
   - SSH 密码：输入不回显（车端默认用户 `duzhong`）
3. 出现画面和状态表就正常了：
   - 画面：**蓝箭头 = 小车自认位置/朝向**，**绿箭头 = 相机看到的真实位置/朝向**
   - 状态表 2Hz 刷新：信念 vs 真值 vs 偏差（Δpos 米/格、Δyaw 度）

菜单其余项：**[2] 只开相机**（贴标记/调机位时用，画面里看到检测框即正常）；
**[3] 只连小车**（验 SSH 与话题）；**[4] 改小车 IP**；**[5] 打开本手册**。

> 与比赛启动的关系：本诊断只做"看"，不发任何车控命令，可与
> `tools/car_match_bringup.sh`（两阶段比赛启动）同时跑，互不影响。

## 三、报警怎么看（重点）

命中规则会打印 `[诊断]`，每条都指向嫌疑模块：

| 报警 | 含义 | 先查什么 |
|---|---|---|
| `HEADING_BIAS` | 信念朝向与真实差 >10° 持续 2s（**画圆前兆**） | align 是否真跑过：两阶段启动顺序对不对（path_executor 不能在 align 前启动）、0x4002 帧通不通；临时处置：重跑 align 或人工摆车 |
| `CIRCLING` | 净转角 >300° 且位移 <1 格（**画圈实锤**） | **立即停车**，回到朝向对齐流程；事后翻日志 |
| `ODOM_STALL` | 车在动但信念位置不更新 | serial_reader 是否活着、`/odom/localization` 是否有数据（菜单 [3] 可看信念流） |
| `ACTUATOR_DEAD` | 信念在变但车实际不动 | dzactuator 模式仲裁/命令通道（pursuitAngle vs cmd_vel）、底盘串口、电机使能 |
| `POS_DRIFT` | 信念位置与真实差 >0.6 格持续 2s | 定位漂移累积；看是否过弯后变大（DR 漂移），靠 reset/到点吸附修正 |
| `NO_TRUTH` | 相机 3s 没看到车顶标记 | 标记被遮挡/反光/出视野；调机位或擦拭标记 |
| `NO_BELIEF` | SSH 3s 没有信念帧 | WiFi 断、车上节点挂了；重连后工具会自动续传 |

历史事故对照：`HEADING_BIAS` + `CIRCLING` 组合就是 2026-10-01 画圆事故
（reset 盲目断言朝向差 68.6°）的早期信号——align 跑成功后两者都应消失。

## 四、数据回放（赛后复盘）

全程记录在 `logs/track_diag/<时间戳>.jsonl`，每行一条：

```json
{"t": 12.34, "belief": {"x": 0.52, "y": 0.18, "yaw": 1.571},
 "truth":  {"x": 0.55, "y": 0.21, "yaw": 1.49},
 "delta":  {"pos_m": 0.043, "pos_cell": 0.12, "yaw_deg": 4.6},
 "alerts": []}
```

退出（Ctrl+C）时自动打印全程统计：Δpos/Δyaw 的 mean / p95 / max 与各报警命中次数。
要逐帧细节就把 jsonl 发给分析工具/队友，或直接喂给 Kimi Code 做复盘。

## 五、故障排查 FAQ

| 现象 | 处置 |
|---|---|
| 双击 bat 提示缺依赖 | `python -m pip install opencv-contrib-python numpy paramiko`（RealSense 支持已内置，没有也不影响） |
| 找不到小车 | ① 确认笔记本和小车同一 WiFi（SSID 一样也要看网段）；② 菜单 [4] 手输 IP；③ 车上 `hostname -I` 查 IP；④ `arp -a` 里搜 MAC `28-2d-06-23-d0-6e` |
| 相机打不开/黑屏 | 换 USB 口；确认没被其他程序占用；命令行加 `--camera 1` 试别的索引 |
| 标记检测不到 | 菜单 [2] 自检模式看画面：光线太暗补光、反光换哑光、标记太小换更大的打印（≥14cm）；全套字典工具会自动尝试，常规打印都能认 |
| 画面里两个箭头差一截但车跑得正常 | 场角坐标映射错（`tools/track_diag_field.json` 的四个角与场地米制坐标对应关系）或车顶标记贴歪（加 `--car-marker-yaw-offset`） |
| 场地不是标准 3.85×4.90 | 编辑 `tools/track_diag_field.json` 改成实际四角米制坐标，或命令行 `--corners "1:x,y 2:x,y 3:x,y 4:x,y"` |
| 报错提示密码/认证失败 | 密码输错：关窗重开菜单再输（密码不落盘，每次会话重新输）；用户名不是 duzhong 时命令行 `--car-user` |

## 六、技术口径（给想看原理的人）

- **真实位姿**：4 场角 ArUco → `findHomography`（图像→场地米制平面），车顶标记中心
  投影得 (x,y)，顶边方向经单应变换得朝向；合成场景端到端验证误差 <1cm / 1°
  （`tests/test_track_diag.py` 锁定）。
- **信念位姿**：车上 `/odom/localization`（block 单位×0.35 化米）+ 最近 `reset:<格>,<向>`
  命令复算 path_executor 的 snap 后信念（其内部精确 snap 值不在话题上，
  取断言向为口径——对"对齐是否成功、定位是否漂移"的诊断足够）。
- **场地坐标**：x 沿行指向第 1 行、y 沿列指向 A 列（与官方 path_executor 同架），
  yaw 0=+x、逆时针为正。场角与米制坐标的对应关系在 `tools/track_diag_field.json`。
- **命令监听**：`/pursuitAngle`、`/cmd_vel` 为 BEST_EFFORT QoS（采样器已适配）；
  采样器在车上只订阅不发布，对比赛节点零侵入。
