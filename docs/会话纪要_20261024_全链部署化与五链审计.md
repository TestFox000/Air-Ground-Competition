## 3. 缺雷根因（四条，全修）

1. **`route_cells_of` 不认连写朝向后缀 `N5,y`**（无人机端，"机制从未生效"级）：抛 CommandError → 上层静默退回摆位起点+全量雷——10-23"重规划基于最新进度"在所有标准路线上从未生效。修复后 13 航点解析/剔雷链烟测全对。
2. **`replan_on_update` 默认关**：车端 `_install_route(keep_progress=False)` 语义=进度清零从头执行，配 route_progress 起点换当前格闭环安全——源码级验证后翻开（integrate_node + sidecar 双线）。
3. **车端 R005 无 already_covered 口径**：增量段 `--validate` 必假红"雷覆盖 1/8"，三处同契约补齐，整线口径逐字节不变（回归验证）。
4. **vendor 树停在第五图**：操作机侧规划/校验天然压错雷，重同步（16 文件 sha256 + 68 token 逐 token 一致）。

## 4. 第六图 K7"无解"裁决（不放宽规则）

逐层插桩 + 仿真裁决的证据链：K7 桥室北壁与隔板中心线**精确共线**（1.75m）——"别的桥洞是独立桥室，K7 是贴着隔板修的"。两条实测硬规则（隔板相邻行禁 90° 转向 + 进洞邻格禁换行）联合构成结构性死锁；**现役 68-token 路线硬走 M7 转弯，仿真隔板余量 1.2mm / 113 拍穿渗（且挡板判据只算半宽不算半长——113 是下界）**。落地的不是放宽，是**无解归因诊断**（legs0=0 时自动输出"哪条规则杀了哪些边+死锁提示"，换图不再人肉排查）。

## 5. 五链精度审计（含一次重要的诚实回退）

时间总账 130s/180s 富余 50s——时间不是约束，精度才是。识别达标（D13：雷 R98.3%/箭头 R88.9%+P100%/格 R98.5%/障 R94.3%；靶类无离线指标=待实机验证）。

**循迹主嫌排除与回退**：斜坡假设被对照实验证伪（无差异）→ 真主因=前视过长（0.36~0.40 超一整格）→ 短前视 0.26~0.28 初测全面占优（RMS −44%/越界 74→0/射击 6→10）→ **修正矩阵补 `completed` 判定后发现与 A1:PIVOT 折返段不完赛绑定（终点差 5.06m）**→ PIVOT 仿真不建模无法裁决实车 → 按工程纪律回退维持 0.36/0.40，收益数据留档为现场实验项（实车 PIVOT 若为原地转向即可兑现）。教训入档：**矩阵必须带完赛标志**。

**保住的有效改进**：`use_external_fire_gate: true`（两键开火，前两趟 0/10 的最大单点杠杆；test_aim 131/131 无破坏）。瞄准链路账：延迟 0.5~0.9s × 靶速 16.8px/s = 落后 8.4~15.1px vs 死区 14px——零提前量下命中是掷硬币；lead_time 按 t53 裁决保持 0 待现场标定。
