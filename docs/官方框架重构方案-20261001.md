# 面向官方技术总框架的重构方案（2026-10-01）

> 依据：`reference/onboard/`（Orin Nano 机上 dzpx4 + dzuav 全套源码）与官方规则。
> 原则：**飞的/看的/跑的都以官方栈为准，我们只做"官方没给的集成胶水"；不自造平行轮子。**
> 方法：不搞一次性大删大改，分阶段、每阶段测试全绿、逐次提交。

## 一、官方总框架（对齐目标）

```
[机载 Orin Nano]
  dzpx4：MID360 → FASTLIO2 建图/定位 → PX4 飞控（px4_control/px4_path 执行航线）   ← 官方，直接用
  dzuav：AR0234 下视相机 → HbbDetector(7类) → CellClassifier(格号) → MapLocalizer(PnP自定位)
                                                                       → UdpBroadcaster
                                                                          二进制 UDP 广播 :50000
                                                                                    ↓
[车端香橙派/笔记本]  官方 dzrobot：path_executor/dztrack/Nav2 负责开车，det_node 负责瞄准   ← 官方，直接用
                  ▲ 我们的唯一职责：接收 :50000 → 世界模型 → 调用官方车接口 + 红蓝禁火保险
```

官方 7 类：`mine 雷 / car / arrow 桥顶箭头 / target_red 友 / cell_label 格号 / target_blue 敌 / obstacle 障碍`。
定位靠格号 PnP，**无 H 人工标定**；通信是**二进制** UDP :50000（魔数 `0xefefefef`、CRC16）。

## 二、对我们现有代码的取舍（逐包）

| 包 | 模块 | 处置 | 理由 |
|---|---|---|---|
| ag_perception | vision_node 及 Dummy/RKNN 后端 | **抛弃** | 侦察由 dzuav HbbDetector 承担 |

| ag_core | link_protocol（JSON UDP） | **抛弃** | 被二进制 :50000 取代 |
| ag_bridge | air/ground_link、fake_intel、udp_link（JSON） | **抛弃** | 同上，协议层重写 |
| ag_mission | field_fusion、mission、target | **抛弃** | 自造规划/目标链，被薄"世界模型→官方车"取代 |
| ag_core | mission_planner、target_policy、referee_protocol、dz_referee、bridge_zone、postprocess | **抛弃/大幅裁剪** | 官方车自带规划/瞄准/裁判 |

`tools/` 中为旧 H/JSON/补丁链路写的探针在 Stage 4 清理；`remote_run.py` 等通用工具保留。

## 三、重构后的目标形态（我们只保留一层薄集成）

车端一个精简工作空间，职责 4 件事：
1. **binary_listener**：收 UDP :50000，按 dzuav `UdpBroadcaster` 字节格式解析（魔数/长度/CRC16 校验）。
2. **world_model**：维护雷/箭头(可通桥洞)/障碍/红蓝靶 的场地坐标与置信度。
3. **car_adapter**：把世界模型翻译成**官方车接口**（path_executor `/nav/waypoint` 或 Nav2 goal），不自己开车。
4. **fire_guard**：红色目标时禁止开火的薄安全层。

## 四、分阶段执行（每步测试全绿、可单独提交/回退）

- **Stage 2**：新增 world_model + geometry 复用，接解析结果；单测覆盖 7 类落点。
- **Stage 3**：新增 car_adapter（官方车命令）+ fire_guard；在仿真/桩上验证。
- **Stage 4**：重写 ag_bringup 与 `car.py`/`run.py` 入口，切到新链路。
- **Stage 5**：新链路达等效后，删除第二节"抛弃"的包/模块，同步改测试；逐次小提交。
- **Stage 6**：清理 tools/docs，更新接手说明与协作看板。
