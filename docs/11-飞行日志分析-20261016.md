## 2. 三个实锤问题

### ① OFFBOARD 退出 ×3（"失控感"的头号来源）

```
[WARN] px4_control_node: left OFFBOARD (nav_state=2), yielding control
```

nav_state=2 = POSCTL。出现它只有两种可能：
- **飞手拨了 RC 模式开关接管**（正常操作，但接管瞬间杆量若不在中位，飞机会"窜"）；
- **offboard 心跳丢失**（PX4 超过 ~0.5s 没收到设定点 → 按 COM_OBL_RC_ACT 回落 POSCTL）——
  这才是真失控前兆：Orin 上节点卡顿/DDS 抖动都会触发。

现有 ROS 日志分不出是哪一种——**必须拿 FC 里的 ulog 看 offboard_control_signal 断点**。
三次退出时间：16:49:39、17:01:32、17:02:19。

### ② 起飞 0.5 米要 11~12 秒，期间按键全被吞

- 三场起飞都是 ARM→HOVER ≈ 12s（16:47:40→52、16:59:43→55、17:01:37→48）。
- 期间操作员按键得到的是 `move ignored: state=TAKEOFF (must be HOVER)`（B 场连续 7 次）——
  主观体验就是"按了没反应，控制不了"。
- 节点侧无爬升斜坡（源码只等 |z−target|<0.15m），慢在 PX4 侧：查 `MPC_TKO_SPEED`
  （起飞爬升速度，默认 1.5m/s 不该这么慢——**疑似被推重比/油门裕度卡住，或参数被改过**）。
  飞机悬停油门高（重机）时会这样。

### ③ SLAM 位置跳变 9~14 米（精准控制的最大隐患）

```
path_record_node: SLAM position jump 9.29 m exceeds 5.00 m; sample ignored
path_record_node: SLAM position jump 14.53 m exceeds 5.00 m; sample ignored
（B 场还有 5.08m / 6.69m 两次）
```

四次跳变都发生在 **OFFBOARD 已交出控制权之后**（人工 POSCTL 操控 / 落地搬机时段，
SLAM 还在跑），没伤到人。
但如果发生在飞行中：FAST-LIO 位姿跳变 → EKF2 外部位姿拒收/跟跳 → offboard 定位失效
或位置环猛拉 → 真失控。path_record_node 有 5m 跳变拒绝，**但 px4_odom_convert→PX4
这条链路上没有等价防护**（待核实源码）。几何重复区（挡板阵列、桥洞）是跳变高发场景。

## 4. 对"能不能避免失控"的直接回答

能，而且路径不是"换更听话的控法"，是**把现有三层保险全部通电**：

1. **PX4 自身的 failsafe**（心跳丢失回落、低电、EKF 拒收）——一直在工作，今天下午 3 次
   OFFBOARD 退出不管哪种原因，飞机都安全悬停/被接管了，这就是保险起了作用；
2. **px4_control 状态机**（空中拒 DISARM、TAKEOFF 中拒 move、offboard 丢失自动 yield）——
   今天的日志证明它在正确拒绝危险动作；
3. **黑匣子留痕 + 复盘**——唯一缺席的就是它。今天下午如果开着黑匣子，①②③ 三个问题
   全部有逐毫秒证据，不用像现在这样从节点日志里倒推。

"最精准的控制"= offboard 设定点链路（20Hz）+ SLAM 位姿可信 + 每次飞行有黑匣子。
前两条今天暴露的慢起飞和跳变都能通过参数与防护代码收敛；第三条已经完全就绪，只差执行。
