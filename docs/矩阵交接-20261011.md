## 一、任务背景

教员要求：把识别出的各类目标（爆炸物/障碍/靶/桥洞/车）以**矩阵形式**
输出，每个目标带**精确坐标**（格号 + 世界坐标米制）。

已交付能力：
1. 11 行 × 14 列（A-N × 1-11）场地格矩阵，一格一目标
2. 每目标双坐标：格号（如 F6）+ 世界坐标 (x, y) 米
3. 三条链路：ROS 车端节点 / 独立 UDP 工具 / 离线渲染评估工具
4. 逆向反推：格号标签漏识别时，用已识别锚点反推缺失格号
5. 时序融合：多帧投票抗单帧漏检/误检，移动靶防拖影

## 四、核心算法与规则（重要决策都在这）

### 4.1 场地规则写死（field_matrix.py / render_field_matrix.py）

- **K1-K11 全部为桥洞**（绿），K 列 mine 检测一律过滤（挡板图案误检）
- **M2=无人机终点，N5=智能车终点，N8=无人机起点，N10=智能车起点**
- 7cls 模型 ARROW 类失效，桥洞靠先验；靶（蓝/红）依赖检测

### 4.2 一格一目标（场地硬规则）

同格出现多类检测 = 噪声，裁决规则：
- **渲染工具**（render_field_matrix.py）：取置信度最高的一个
- **运行时**（field_matrix.py fused_spots）：同格多类都过确认线时，
  **票数最高者胜；平票障碍优先**（安全：把桶当雷会导致规划穿格撞桶）

### 4.3 MatrixFusion 时序融合（运行时）

- `window=5, confirm=2`：滑窗内出现 ≥2 帧才上矩阵
- 同格同类合并为一格一目标，坐标取中值
- **静态类（雷/障碍/桥洞）确认后永久保留**（漏检容忍：单帧闪断不上抖）
- **移动类（蓝/红靶、车）超过 window 帧未复现自动清除**（防移动靶
  D8→E8 后旧格永久残留、整条轨道刷成蓝靶污染 fire_guard）
- 出界目标不落格，仅保留坐标报明细

### 4.4 逆向反推 fit_lattice（render_field_matrix.py L76-123）

原理：场地平面→图像 = 单应。已识别锚点 (col,row)↔(cx,cy) ≥8 个时，
RANSAC cv2.findHomography 拟合格网：
- **内点** = 真锚点；**外点** = 误读标签（重复 H5、错位 B7），自动剔除
- 任何像素 → 反推格号，**覆盖标签未识别的格子**（渲染为虚线边框）
- 自适应阈值 = 最近邻锚点间距中值 × 0.35；内点须横跨 ≥3 列 ≥2 行
- 反投影像素残差 > 3×阈值 拒绝（防边缘外推失真）
- 拟合失败回落 Voronoi 最近邻（旧逻辑兜底）

### 4.5 性能数据（GT 为 82 雷 + 5 障碍人工真值）

| 指标 | Voronoi 旧 | 格网反推 | 说明 |
|---|---|---|---|
| 00124 雷R/P | 0.671 / 0.932 | **0.805 / 0.943** | 剔 23 假锚点，反推 23 格 |
| 00124 障碍R/P | 0.40 / 0.40 | **0.80 / 0.80** | TP 2→4 |
| 00168 雷R/P | 0.439 / 0.800 | **0.524 / 0.827** | 剔 7 假锚点，反推 14 格 |
| 17帧融合(Voronoi) R/P | 0.805 / 0.815 | — | confirm=2 |
| 矩阵模块耗时 | — | 1.9ms/帧 | 纯CPU，非瓶颈 |

关键结论：**单帧反推（R=0.805）已追平 17 帧融合水平**——旧 Voronoi
错格是系统性的，融合救不了；归属修正后单帧即高质量，融合再叠加更优。

## 五、使用方法

```bash
# 虚拟环境（注意：不在项目目录，防 OneDrive 同步问题）
C:\Users\a\venvs\air_ground\Scripts\python.exe

# 链路C：离线渲染（单帧，检测 vs GT 对比图）
python tools/render_field_matrix.py --image capture/aerial_field/images/frame_00124.jpg --show-gt

# 链路B：UDP 实时矩阵（联调演示）
python tools/matrix_report.py            # 持续渲染
python tools/matrix_report.py --once     # 收一帧退出
python tools/matrix_report.py --json out.json  # 存 JSON

# 链路A：ROS 节点（比赛实战）
ros2 run ag_integrate integrate_node --ros-args -p matrix_log:=true
# dry_run 默认 true（只打日志不发车），联调确认后置 false
```

注意：7cls 训练进行中会占满 GPU，离线工具每帧 3-8s 是抢 GPU 所致；
训练结束后干净 GPU 约 0.1-0.3s/帧。机载 Orin 走 TensorRT 实时在线。

## 六、已知问题与下一步（按优先级）

1. **卡片持续误检**（A5-A8/B7-B8 等 ~10 格）：任务卡片图案每帧被
   检成雷，融合滤不掉（持续性误检）。解药就绪：两阶段雷分类器
   （`runs/distill_7cls/eval_two_stage.py`，YOLO conf=0.15 + 96×96
   分类器过滤），接入后 P 预计 0.81→0.95。**首选。**
2. **障碍样本不足**：train 里 obstacle 551 vs mine 6949，导致障碍
   P/R 仅 0.8（反推后）。需补标障碍样本。
3. **北边缘小目标漏检**（A2-A4/C1-C3/D1-D2）：画面最远处像素不足，
   物理极限。可试 conf<0.15 + 裁边放大重检。
4. **M 列卡线**：M2-M9 仅悬停帧可见，confirm=2 恰差一票。比赛建议
   无人机在北半场多悬停 2-3 秒。
5. **B9 桶 GT 待确认**：00168 画面顶缘有红桶（裁图 crop_B8_det.jpg），
   Voronoi 吸到 B8、反推正确到 B9，但用户 GT 障碍表无 B9——需现场
   确认桶真实位置后更新 GT。
6. **7cls 类缺失**：target_blue 训练样本 0、car 仅 23，这两类检测
   基本失效（矩阵里恒为空）。需补数据后重训。
