## 3. 版本号口径

### 3.1 基本规则

| 规则 | 内容 |
|---|---|
| **格式** | `vN.M`（短名，**不带中文后缀**）。中文主题写进 tag message 与本表，不写进标签名 |
| **递进** | 只数当前大版本系列（现为 `v3.*`）取 max +1 |
| **岔线** | `v1.1_多线程构造完毕` 是 `src_v1` 改造的岔线标签，**永不参与递进** |
| **备份点** | `backup-2026-10-09` 是备份快照，**永不参与递进** |
| **轻/注释标签** | v2.1~v2.4、v3.0~v3.2 是 annotated tag（带 message）；v2.2/v2.3 是 lightweight（历史遗留，**不补改**，只在表里标注） |
| **tag message 必写** | ① 主题一句话 ② 关键数字（token 数/测试结论/标定值）③ 执行成员 ④ 若为重命名，注明原名 |

### 3.2 2026-10-14 重整记录（为什么 v3.0 比 v3.1 新）

**背景**：用户指令「从 v2.4 开始，把以后的 git 都改成 v3.\* 的版本号，然后所有 git 版本按版本号重新排列」。

**执行前状态**：v2.4 之后有 `v2.5`(9dd022d, 10-12)、`v2.6`(2523845, 10-12)、`v3.0_官方重掷图实车跑通_空地协同落地`(c81584c, 10-14) 三个标签——**已出现 v3.0 且名字带中文后缀，不规范**。

**采用方案 A**（用户选定）：

| 原名 | 新名 | 指向提交 | 理由 |
|---|---|---|---|
| `v3.0_官方重掷图实车跑通_空地协同落地` | **`v3.0`** | `c81584c` | 该提交是"官方重掷图实车跑通"这一真正里程碑，**保留其 v3.0 地位**，仅去掉中文后缀 |
| `v2.5` | **`v3.1`** | `9dd022d` | 过程版本，改名后 v2.4 之后严格递增 |
| `v2.6` | **`v3.2`** | `2523845` | 同上 |

**产生的副作用（如实记录）**：`v3.0`(10-14) 的**提交日期晚于** `v3.1`/`v3.2`(10-12)。即版本号顺序与提交顺序在 v3.0↔v3.1 之间**倒挂一次**。这是"保留里程碑语义"与"严格按时间编号"不可兼得的结果，选定前者。**今后编号一律按提交时间递增，不再复现此现象。**

**回滚快照**：`backup/tagmap_before_v3rename_20261014_195150.txt`（改标签前的 标签→提交 全映射 + HEAD + status）。

## 4. 存档操作标准流程（以后每次照此执行）

```powershell
cd D:\User\Desktop\比赛存档\v1\dzrobot_v2

# ① 先看当前工作区——**只 add 自己的产物**，不要把并发写入者的改动卷进来
git status --porcelain

# ② 精确 add + commit（用文件路径，不要用 git add -A）
git add <自己的文件...>
git commit -m "vN.M_<主题>（关键数字）"

# ③ 打标签（annotated，message 四要素见 §3.1）
git tag -a vN.M -m "..."

# ④ 同步裸镜像（remote 为空，必须显式写路径）
git push --mirror backup\dzrobot_v2.git

# ⑤ 重建便携 bundle 并 verify
git bundle create backup\dzrobot_v2-vN.M.bundle --all
git bundle verify backup\dzrobot_v2-vN.M.bundle

# ⑥ 在本表 §1 追加一行 + 更新 §2「下一版」
```

**铁律（踩过的坑）**：
- **不要 `git add -A`**：本项目长期存在并发写入者，历史上 `e906e6c` 就因为混进别人暂存的删除（`cam_viewer.py/.html` −3248 行）而导致提交信息不实。提交前逐条核对 `git status --porcelain`。
- **提交前 `git diff --stat` 自查**：确认改动文件数与 commit message 描述一致。
- **`backup/` 与 `install/` 等被 `.gitignore` 排除**（见 §6），git 备份不含约 2.3 GB 资源；镜像与项目同盘，防误删不防磁盘坏，`.bundle` 应另拷一份到 U 盘/网盘。
