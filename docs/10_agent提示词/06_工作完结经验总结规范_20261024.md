# 06 · 工作完结经验总结规范（agent 必写）

## TL;DR（给 agent 看的）

- **每张卡归档前必须写一段「经验总结」**：现象 → 机制 → 位置 → 处置 → 证据等级 → 落点，六要素缺一不算写完。
- 最大坑：把「经验」写成「我做了什么」的过程流水——经验必须是**下次能直接用**的可迁移结论。
- 落点三选一：坑库（症状索引/十坑）/ 百科（20 库）/ 台账（D-xxx）；正文在卡里，判断值只留一行（细则 [12 §12.5](../20_资料索引库/赛事与治理/12_卡库命名空间与任务树细则_20261025.md)）。
- **没有证据的经验 = 过程记录，不进库。**

## 1 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 可迁移的教训：**现象 → 机制 → 位置 → 处置**，下次遇到同症状能直接查 | 本次做了什么的过程流水（那是执行记录，见 11 细则 §11.5「卡就是报告」） |
| 一句「怎么判断 + 怎么处置」，带 `路径:行号` 或命令 | 「已修复 / 已优化」这类无证据表述（`AGENTS.md` §1 铁律5「证不出来 = 没完成」） |
| 收口时写进卡正文，并落点到坑库/百科/台账 | 只在聊天里说一遍、不留卡（`AGENTS.md` §7「踩坑必须落盘」） |

| 产物 | 管什么 | 本规范怎么接 |
|---|---|---|
| [`05_回报模板.md`](05_回报模板.md) | 跨 agent 的 700 字可转交摘要 | 摘要里必须含「经验」一行 |

## 2 何时写

| 时机 | 动作 |
|---|---|
| 卡执行完、准备归档 | 在卡正文写「经验总结」段（§3） |
| 同一次会话收口 | 把可迁移结论落点到坑库/百科/台账（§5） |
| 只读诊断卡（无生产改动） | 也要写：诊断方法本身可迁移（判据、采样口径、易误判点） |
| 会话日志（dzrobot_v2/src/history/log/） | 一行索引「本条经验在卡 X 第几节」，不复制正文 |

## 2.1 归档动作四步（2026-10-31 增 · 机器门禁已落地）

> **为什么补这一节**：上面这张表只说「什么时候写」，没说「**怎么做、怎么证明做完了**」。
> 规则齐备但归档动作全靠人手搬文件 ⇒ 漏写只能事后补写 ⇒ 补写就是编造。
> 现在把判据**前移到搬卡之前**：第 ② 步跑不过，这张卡就还不该归档。

| 步 | 动作 | 判据 / 命令 |
|---|---|---|
| ① | 卡内写「经验总结」（§3 六要素）+ 落点**反向指针**（§5，指向具体文件 / D 编号 / §节号） | 落点那一行必须**同行**带指针；只写「坑库」两个字 = 读者追不到，不合格 |
| ② | 跑归档前置门禁 | `python docs/_工具/check_archive_ready.py <卡路径>` **必须 exit 0** |
| ③ | 移卡到 `归档/<ns>/YYYY-MM-DD_<卡号>.md`，`status` 改 `已归档` | 目录/命名见 [12 细则 §12.5](../20_资料索引库/赛事与治理/12_卡库命名空间与任务树细则_20261025.md) |
| ④ | 更新 `归档/00_索引.md` 的「教训」列 | 从卡内经验总结**摘一句**，不另起一行编 |

门禁跑出 FAIL 怎么办：**不许补写经验总结蒙过去**。没执行完的卡没有可迁移结论，硬写就是伪造证据（§1「没有证据的经验 = 过程记录」）。
正确做法是把卡做完 → 有了真结论再写 → 重跑 → exit 0 才搬卡。

门禁判四项（详见 `docs/_工具/check_archive_ready.py` 文件头）：经验总结段（与 Y10 同一套正则）、落点+反向指针、`status` 归档态、`文档变更` 段非空。
不带参数时它只扫 `在办/` 下 `status: 已归档` 的卡（即「声明归档却还没搬」的那批），并顺带打一份**在办全量普查**（只统计、不催办）。

> **不许对存量在办卡批量补写**：规范的时机是「执行完、准备归档」。给还在跑的卡补经验总结＝伪造证据，比缺段更糟。

## 3 六要素结构

```
### 经验总结（归档必写）
| # | 要素 | 写什么 | 反例 |
|---|---|---|---|
| 1 | 现象 | 看到什么（可复现的症状，带数字） | 「车不好」 |
| 2 | 机制 | 为什么（根因，一句因果） | 「可能和参数有关」 |
| 3 | 位置 | 代码/文档/命令落在哪（`路径:行号` 或章节） | 「记得在某处」 |
| 4 | 处置 | 下次怎么做（唯一命令/最小动作） | 「重新部署试试」 |
| 5 | 证据等级 | 〔实〕代码/命令实测 ｜〔档〕文档记载 ｜〔未〕未核实 | 省略 |
| 6 | 落点 | 坑库 ｜ 百科 ｜ 台账 D-xxx | 三选一，不许空 |
```

> 证据要求：每条经验至少一条可回查证据（`路径:行号` 或命令 + 退出码）。查不到就写〔未〕，**不编**。

## 4 证据等级与四条反模式

| 等级 | 含义 | 例子 |
|---|---|---|
| 〔实〕 | 代码/命令实测，有退出码或原始输出 | 「ros2 topic echo 会把订阅计数从 0 变 1」(2026-10-24 16:2x 实测) |
| 〔档〕 | 文档记载，未实测 | 「手册写的 :671 已漂到 robot.yaml:840」 |
| 〔未〕 | 未核实 | 「车端实际加载的 PID 未逐项读」 |

四条反模式（出现即退回）：

1. **过程流水**：把执行记录当经验 → 改写成「下次怎么判断 + 怎么处置」。
2. **无证据**：没有 `路径:行` 或命令 → 补证据或改判〔未〕。
3. **泛化**：n=1 说成「总是」 → 写明样本量与适用边界。
4. **落空**：写在卡里不落点 → 按 §5 落点，并写反向指针。

## 5 落点映射（三选一）

| 经验类型 | 落点 | 反向指针写法 |
|---|---|---|
| 可复用的工作法/观测假象 | 20_资料索引库/车端/11_工作法与经验.md §2~§5（或对应分册） | 卡 §5 写「已并入 车端/11 §x」 |
| 症状 → 处置 | 20_资料索引库/README.md §4 症状索引 | 症状行加「来源: <卡号>」 |
| 单点坑（>10 条不单开） | 对应分册的「坑」节（如 车端/05 坑7~9） | 篇内加「来源: <卡号>」 |
| 影响决策/已裁决 | dzrobot_v2/docs/决策台账.md D-xxx | 卡 §5 写「台账 D-xxx」 |

> 「坑库」不是独立目录：本项目把可迁移坑收在各分册的「坑/症状」节与 车端/11 十坑活页。**不要新建 坑库/**（唯一存放地见 11 细则 §11.1；副本即债见 §11.3）。

## 8 机器判据现状

- **已落地（2026-10-25）**：check_doc_policy.py 新增 **Y10** 判据——归档卡正文必须有「经验总结」段，至少含「现象」和「处置」两个要素。
- **已落地（2026-10-31）**：归档**前置**门禁 `docs/_工具/check_archive_ready.py`——把判据前移到搬卡之前，判四项（经验总结段 / 落点+反向指针 / status 归档态 / 文档变更），逐条 PASS/FAIL，exit 0 才许搬卡。自测 `test_check_archive_ready.py` 10 用例全绿（含与 Y10 正则的逐字节同源守卫）。执行清单见 §2.1。
- **已落地（2026-10-31）**：check_doc_policy.py 新增 **Y12 黄线**——`在办/` 里残留 `status: 已归档` 的卡（声明归档却没搬出）。这条与 **R4** 同时命中同一张卡，分工是：**R4 判「status 值域越界」（会把人引向「把 status 改回 in_progress」）；Y12 判「位置放错」，并点名该做的下一步（先过 `check_archive_ready.py` 再搬 `归档/<ns>/`）**。与 Y10 的关系：**Y10 判「归档了但没写经验总结」，Y12 判「写了归档却没归」**。（编号说明：原拟 Y11，但 Y11 早被「更新字段格式」占用，故让号用 Y12。）
- 实测（2026-10-25）：docs/30_任务卡库/归档/ 下 12 张单卡中 **12 张缺「经验总结」段**，全部标 Y10 提醒（不判红）。
- 实测（2026-10-31，`check_archive_ready.py` 在办普查）：在办在跑卡 **123 张**（另有 19 张 `00_树.md` 非卡面），有经验总结段 **26 张（21.1%）**、有落点+反向指针仅 **4 张（3.3%）**、四项全过 **0 张**。这组数是**时段快照**，不是「缺口 KPI」——在办卡大多还在跑，规范本就不要求它们现在写。
- **升级路径（2026-10-31 现状）**：归档前置门禁已落地（`check_archive_ready.py`，独立可跑工具）；**Y10 / Y12 仍为黄线**（不挡收口）。Y10 转 R 级仍按原口径：**连续两轮零告警后**转（归档卡缺经验总结 = 红线）。**不许跳级**——存量归档卡大量不达标，现在设红会让整库进不了收口。在此之前，新归档卡必须写「经验总结」段，否则归档索引的「教训」列取不到内容。
