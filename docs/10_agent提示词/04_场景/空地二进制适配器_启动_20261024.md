# 场景卡 · 起飞：机端二进制情报适配器

## TL;DR（给 agent 看的）

- 用途：把"机端 UDP 二进制情报 → 车端 JSON"这层补上。**这是三件套实测后唯一真正要写的代码**（不是把三个 demo 搬进仓库）。
- 先读哪篇：`docs/20_资料索引库/空地链路/04_教员三件套实测_20261024.md`（帧格式/类型表/坐标口径/坑全在里面，别重推）。
- 三条硬边界：① 类型表照 **13 类**；② 坐标反解用**机端帧常数**（0.065/0.295/0.35），别用车端 geometry；③ 不许写 `/nav/waypoint`。
- 判据：真帧重放 → JSON 字段逐项对；13 类全表对；A1~M2 往返换算不错格；5 类坏帧仍被拒。

## 2 为什么这么写（不是废话，是踩过的）

| 要求 | 来自哪次实测 |
|---|---|
| 照 13 类、不许照仓库 types.hpp | 机端已 13 类（部署 types.hpp + 二进制 strings + d13 模型），仓库仍是 7 类 |
| 坐标用 0.065/0.295 | 机端 field_frame 与车端 geometry 是两套帧，混用不报错只错位 |
| 不许写 /nav/waypoint | udp_bridge 第 266 行开关，开了就是第二个写者 |
| field_verify 不加 coverage | 二进制帧没有覆盖语义，加了等于伪造负证据 |
| 0x4003 只打印 | 路线帧 = 第二个路线下发者，必须单写者 |
