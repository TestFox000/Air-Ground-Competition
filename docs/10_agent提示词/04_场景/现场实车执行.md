# 场景卡 · 现场实车执行

## TL;DR（给 agent 看的）

- 用在「车能开、有人在场、要拿第一份可信基线数据」时；产出是**逐趟有效性表**，不是「跑完了」。
- 铁律：**一次只改一个变量**；本卡不调参、不部署、不进入整圈。
- 最大坑：把人工截停当自然 FINISH、把 `/odom/localization` 的「格」当米（×0.35）、用内部里程当外部精度。

## 1. 触发条件

| 条件 | 说明 |
|---|---|
| 车在线且有人能摆车/观察/物理停车 | 无人值守禁止发车（`36` §3 分工） |
| 已知车端实际版本与配置 | 版本不明只做只读取证 + 静止采样 |
| 已选定一条有净空的短路线 | 排除 ALIGN/PIVOT（含隐式）、倒车/推车、桥洞、射击停站 |

## 2. 前置检查（F0，缺一项不发车）

| # | 检查 | 判据 / 坑 |
|---|---|---|
| 1 | 版本身份 | `tracker` src+install 哈希、`robot.yaml`/`map.yaml`、`start_all.sh`、`dzros.env` 全采；**本地 `e9bff6f0…` ≠ 车端 `9e9766a1…`** |
| 2 | 单一指令来源 | `/pursuitAngle`、`/cmd_vel`、`/logicontrol` 各查发布者；**kill `cam_viewer`**（20 Hz 发全零 ⇒ 车收到但不动） |
| 3 | 域号 | 非交互 SSH 域号变 0 ⇒ 起栈前 `source dzros.env`；否则 ROS 互相看不见且零报错 |
| 4 | 不自动出发 | `mission.auto_start=false`；`start_all.sh` 会覆盖旧日志且默认带 `--force`，**先备份日志** |
| 5 | 布局/文件模式 | 要 StepLoop 时 `--map` 必须指向**不存在**的文件；`start_all.sh:220` 传的是 `config/map.yaml` |
| 6 | 停车手段 | 物理停机人在位；软件接管用 `/nav/manual_override`（`UInt8 data=1` 每拍刹车）——**不替代物理停机** |
| 7 | 外部相机 | 先录 5 s 回放，确认**整车在画面内**（机器人前视图不算）；放已知尺寸标记 |
| 8 | 话题非空 | 录 5 s 后查 `/odom`、`/odom/localization`、`/imu_data`、`/pursuitAngle` 计数与 QoS，空表不得当完整采样 |
| 9 | 初态一致 | 车摆真实 **N10 / +y** 再走既有初始化；核对 Start/pos、raw、belief 与实物；建议一致性目标 ≤2 cm / 5°（不是改软件阈值） |

## 3. 提示词正文（可直接复制，替换【】）

```
领取 TRACK-FIELD-【日期】-01。目标：在核验过的车端版本上，取得有初态、有外部画面、可重复的普通直线/单弯基线。不改控制/标定/安全阈值/终点判据，不部署、不进入整圈。

工作区 W=D:\User\Desktop\比赛存档\v1；车仓 C=W\dzrobot_v2；SSH=ssh duzhong@duzhong.local。
先读：W\docs\10_agent提示词\00_一页纸.md → W\docs\00_项目总览\现状快照.md → W\AGENTS.md
→ W\docs\10_agent提示词\03_角色\lead.md（若你是 Lead）→ 本卡场景卡。

分工：唯一 SSH/进程/运动操作者 1 人；采集者写 raw/ 与 RUN_CARD；分析者写 measure_*；独立 reviewer 只写审查段。现场人负责摆车、观察、物理停车；每趟 GO 是时序协调，不是重新授权。

A. 发车前（限时但不跳过）：
1) 采身份：源码/实际 import 副本哈希、进程命令与启动时间、配置与地图哈希及解析值、start/stop 脚本；缺失写缺失，不事后伪造。
2) 备份旧日志；确认 mission.auto_start=false；确认只有一个运动指令来源（kill cam_viewer）。
3) 外部相机试录 5 s 并回放，确认整车入镜与标尺可见；约定与日志的同步时间锚。
4) 关键话题 5 s 采样非空；人工停车人在位；车轮落地。
5) 初态：车摆 N10/+y，核 Start/pos、raw、belief 与实物。

B. 试跑顺序（候选速度【0.10 m/s】或现场更低可靠档）：
C0：低速短行程 1 次人工接管停车，外部实测「接管→停稳」时间与距离，作为后续停车余量依据。本趟不计自然 FINISH。
C1：同一条已验净空直线【3】趟；每趟人摆回同一起点/朝向，记录真实位移、横偏、停车距离、raw 与 belief 差值。
C2：C0/C1 无安全异常后再做真正普通 90° 单弯【2】趟（必须有进弯直道 + 实际 90° 转角 + 出弯收敛空间）。
若时限到达，只报已有效完成的趟数；收车留 10 分钟。

C. 每趟必交：run_id｜版本/配置/路线 hash｜速度生效值与实际发布范围｜真实位移/可测横偏/停车距离｜raw 与 belief 分列｜吸附或故障事件｜视频时刻与日志行号。
raw 与 odom 同源不能当两份独立真值；软件 FINISH ≠ 物理到位；无外部定量轨迹就把真实 P95 写成未测。

D. 禁止：现场调 PID/前视/标定、绕过启动门禁、`--force`、手动 scp、部署、边跑边改参数、用人工停车冒充自然 FINISH。
出现信号跳变、越界风险、SAFE_STOP 或意外进入特殊分支：先停、保留前后数据、不自动清锁继续。

E. 收口：卡面（docs/30_任务卡库/在办/<卡号>.md）追加逐趟表 + 证据路径 + 回滚点（恢复进程与配置选择，保留日志）+ 影响面；在 C 下跑 python -B -X utf8 tools/wf/check.py 并保存输出。交 ≤700 字摘要后停止，不自动进入下一轮。
```

## 4. 验收标准

| 项 | 判据 | 出处 |
|---|---|---|
| 趟数 | 直线 3 趟同条件、单弯 2 趟同条件，缺则写「部分完成」 | `36` §3 C1/C2 |
| 停车 | `d_stop + e + 5 mm < 35 mm`（10-21 R3B：22.0/24.2/23.3 mm，最差 34.2 mm，余量 0.8 mm） | `现状快照` §2.2 |
| 位移 | 外部量测与 `/odom` 分列；`/odom` vs `/odom/localization` 位移比 2.7–2.84× | `现状快照` §2.3 |
| 初态 | 每趟摆回同一起点，raw/belief/实物三方核对，误差 ≤2 cm/5°（诊断目标） | `36` §3 A5 |
| 数据完整性 | 关键话题非空、视频入镜、日志区间与 run_id 对应 | `36` §3 A4 |
| 车端门禁 | 车上重跑 G1/G2（本机无 `rclpy` 时 route_check 走内置副本，不是车端行为） | `发车门禁口径` §4 |

## 5. 常见翻车点

| # | 翻车 | 后果 | 规避 |
|---|---|---|---|
| 1 | 人工截停当自然 FINISH | 停点精度被伪造 | 人工截断趟次的终点误差写「不适用」 |
| 2 | 单位混用 | 把格当米，误差差 3 倍 | `/odom/localization` 位置单位是**格**（×0.35 才是米）；`pursuitAngle` 角量是**舵角度数** |
| 3 | 用 raw 当外部真值 | 内部里程自证 | raw、belief、外部量测三列分开 |
| 4 | 忘记 kill `cam_viewer` | 车「收到指令但不动」 | F0 第 2 项 |
| 5 | `--force` / 布局模式传存在的 map | 永远进不了 StepLoop | F0 第 5 项 |
| 6 | 起栈覆盖旧日志 | 上一轮证据丢失 | 先备份再 restart |
| 7 | 边跑边调参 | 无法归因 | 本卡不调参；下一卡只改一个变量 |
| 8 | 无外部录像就宣称横偏达标 | 结论无法复核 | 没有外部量测就写未测 |
