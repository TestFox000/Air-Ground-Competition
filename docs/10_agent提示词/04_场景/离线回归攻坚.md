# 场景卡 · 离线回归攻坚

## TL;DR（给 agent 看的）

- 用在「要收 13 套红 / 修 6 条真缺陷 / 补回归」时；目标是**分清哪条红该修、哪条是夹具过期**。
- 两条硬规矩：**真缺陷禁重钉**（改代码）；**夹具过期按现行图重钉**（不许改代码凑绿）。
- 最大坑：套件名相同就以为原因相同，或一句话「环境阻塞」把 9 套的计数缺口带过。

## 1. 触发条件

| 触发 | 先确认什么 |
|---|---|
| 有人说「全绿」/「已修好」 | 先问：哪棵树、哪张图、哪套清单（`AGENTS.md` §6） |
| 要动 `test_*.py` | 是否属 A 类真缺陷（禁重钉）还是 C 类夹具过期（重钉） |
| 新卡引入冻结区改动 | 是否要求全量回归（`33` §3 E） |

## 2. 前置检查

| # | 检查 | 判据 |
|---|---|---|
| 1 | 基线身份 | 「37 套 / 13 红」是 **2026-10-18 21:20 干净树**（D-023），**不含工作树改动** |
| 2 | 分类 | A 类 3 项真缺陷（压靶板/挡板触线/延迟鲁棒性）禁重钉；B 类仿真不建模 PIVOT 是假象；C 类按第六图重钉；D 类 3 套 CRASH 改调 `plan_route_tour()`（**不得回退 tracker-safe**） |
| 3 | 6 条真缺陷 | `test_autoplan` 的 12.3/12.4/12.7/12.8/12.9/12.10（tour 单停站）**必须改代码**，禁重钉 |
| 4 | 输出目录 | 旧 `_run_full_regression.py` 固定写 `_tmp_full_regression/` 并**覆盖**；先备份 |
| 5 | 统计口径 | harness 把每条 FAIL **打印两次**（46 行 ≠ 46 条）；`test_aim_probe` 0 断言也算「通过」 |

## 3. 提示词正文（可直接复制，替换【】）

```
领取 TRACK-REG-【日期】-01。目标：在【当前树/指定备份树】上重跑回归，把每一红归到"真缺陷 / 夹具过期 / 环境阻塞 / 未解释"四类之一，并只为确认的真缺陷立卡。不改期望值求绿。

工作区 W=D:\User\Desktop\比赛存档\v1；车仓 C=W\dzrobot_v2。
先读：W\AGENTS.md → W\docs\10_agent提示词\00_一页纸.md → C\docs\决策台账.md 的 D-023 → W\docs\10_agent提示词\03_角色\verifier.md。

步骤：
1) 固定基线：记录 HEAD、工作树 status、被测文件哈希、测试文件清单（当前 tests 顶层 test_*.py 数量）。基线必须与"测试树哈希"同绑。
2) 逐套独立进程运行（cwd=C，PYTHONIOENCODING=utf-8、-B -X utf8）；每套 stdout/stderr/退出码分文件保存；先备份旧 _tmp_full_regression/，不覆盖历史基线。
3) 只运行现有运行方式，不新建第二套测试框架，不改 _run_full_regression.py。
4) 红项归因：按失败 ID + 断言正文 + 数值与 10-18 日志逐条比对，输出"相同 / 新增 / 消失 / 未解释"。
   · 同名不等于同因：例如 test_planner 这次可能是写 tests 目录被拒（PermissionError），不是历史 PlannerError。
   · 中断前已有 FAIL 的套件（如 sim/sim_guard）不得写成"纯环境阻塞、无代码失败"。
5) 只在确认属 A 类真缺陷或 6 条 tour 单停站时立实现卡；C 类夹具过期按现行图重钉并在卡里写清"为什么不是改代码"。
6) 收口：python -B -X utf8 tools/wf/check.py 保存输出与退出码；卡内写"未解释项"清单。

禁止：改测试期望/skip/容差求绿；把仿真通过当实车通过；只跑 1~2 套就说全绿；用"套件名相同"替代逐条对照；覆盖历史基线目录；git 提交。
交付：逐套计数表 + 退出码 + 四类归因表 + 新增红清单 + 卡面（docs/30_任务卡库/在办/<卡号>.md）+ ≤700 字摘要。
```

## 4. 验收标准

| 项 | 判据 |
|---|---|
| 分母 | 每套写「N/N + exit」；未跑到汇总行的写「计数不可得」并说明原因 |
| 归因 | 每条红都有「相同/新增/消失/未解释」标签 + 对照依据（旧日志行号或断言正文） |
| 三态 | 「已复现 / 未复现 / 无效或阻塞」分清，INVALID 不算 PASS |
| 门禁 | `check.py` 退出码 + 原始输出；冻结区「仅本卡已登记文件」 |
| 结论 | 只写「离线通过/X 条未解释/需非受限环境复跑」，不写「全仓全绿」 |

## 5. 常见翻车点

| # | 翻车 | 例证 | 规避 |
|---|---|---|---|
| 1 | 套件名相同当同因 | `test_planner`：PermissionError ≠ 历史 PlannerError | 看失败 ID 与异常类型 |
| 2 | 「环境阻塞」一把梭 | 9 套无完整计数中，sim/sim_guard 中断前已有既有 FAIL | 分列「既有红 + 环境中断」 |
| 3 | 覆盖基线 | `_tmp_full_regression/` 固定目录覆盖写 | 先备份到本卡目录 |
| 4 | 把红改绿 | 改期望/skip/容差 | 真缺陷改代码，夹具过期改夹具 |
| 5 | 只跑相关套件就宣称全绿 | 旧文已列此为假绿形态之一 | 写清分母与「未运行」清单 |
| 6 | 用仿真代替实车 | PIVOT 在 `sim.py` 是 no-op | 结论标层（源码/离线/仿真/实车） |

## 相对旧版改了什么

1. 从「团队执行方案 §5」抽出成独立场景卡，补 10-21 的归因纪律（同名不同因）。
2. 明确 6 条真缺陷 ID 与「禁重钉」，并给出必须改代码的判据。
3. 产出路径改 `docs/30_任务卡库/在办/<卡号>.md`。
4. 新增「9 套计数不可得」的处理口径，替代旧文「环境阻塞」一句话。
