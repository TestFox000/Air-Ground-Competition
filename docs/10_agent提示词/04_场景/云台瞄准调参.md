# 场景卡 · 云台瞄准调参（打移动靶）

> **2026-10-24 更新**：本篇 §3 的 2000 帧实测（`fire_ready` 0/2000、提前量恒 0）**已被实车闭环推翻** —— 链路是通的，当天实车 2 发、裁判板射击 5→7 弹药 5→3（1:1 记账）。
> 现行状态、数字与下一步看 [打靶闭环接手_20261024.md](打靶闭环接手_20261024.md) 与 [交接手册](../../00_项目总览/交接_20261024_打靶闭环.md)。本篇保留的是**方法论**：先证链路与信号，再决定改哪个参数。

## TL;DR（给 agent 看的）

- 用在「停站 30 s 一发没打出去 / 打不中移动靶」时；**先证链路与信号，再决定改哪个参数**。
- 实测现状：2000 帧里 `fire_ready` **一次都没到 1**，提前量列 `lead` **恒 0**；水平误差中位 **59 px**。
- 最大坑：信号本身坏时调 PID（`工作流v2` §1 病灶 3：三轮调参全是无效功）。

## 1. 触发条件

| 现象 | 先看什么 |
|---|---|
| 停站 30 s 0 发 | `/LaserShot_Command` 订阅数是否 = 1；`fire_ready` 是否曾为 1 |
| 有发不中 / 命中未判定 | 裁判链路 `HpAndHitmsg` 是否在；"0 中"是内部计数还是裁判判定 |
| 移动靶误差稳定在一个靶宽 | 大概率是**延迟**，不是增益（见 §3） |
| 调 PID 后更抖 | 停手：先看误差是否随靶速线性增长 |

## 2. 前置检查（改任何参数前）

| # | 检查 | 判据 |
|---|---|---|
| 1 | 先钉 PID 口径 | 云台 PID 有 **5 套口径**并存（仓库/现状报告/10-19 车端/提交/自动整定方案），现场调参前必须 `deploy_car.py diff` |
| 2 | 链路完整 | 相机 → `det_node` → `/offset_center` → `dzrknn_dataprocess` → `/aim/status`、`LaserShot_Command` → `dzjudgment` → 激光；每段都要有发布者 |
| 3 | 检测在出数 | `det_node` 必须 `draw:false`（无 X 时 `cv::imshow` 抛 GTK 异常直接崩，静默 0 发布者） |
| 4 | 已有实现先核 | C++ 侧**已有**帧差预测/IMU 前馈；`AimTask` **已有**带时间戳运动估计与速度×延迟项；先查是不是没启用/没连通，而不是"没有" |
| 5 | 证据口径 | 延迟估计不能当严格上界；接收时间不冒充曝光时间 |

## 3. 本卡实测事实（可直接引用，别再猜）

数据：`_tmp_session/aim_step3/rec4.csv`，**2000 帧**、19 列（`t,dx,dy,cls,...,fire_ready,lead,laser,off_age`），本次实算：

| 指标 | 值 |
|---|---|
| 类别 `cls` | 全为 1（蓝面），无翻面样本 |
| \|dx\| 中位 / p90 / 均值 | **59 px** / **82 px** / **61.6 px** |
| \|dy\| 中位 | 7 px（高度锁得较准） |
| ±14 px 框内占比 | **4.5%**（89/2000） |
| `fire_ready` ≠ 0 的帧 | **0 / 2000** |
| `lead` ≠ 0 的帧 | **0 / 2000**（提前量列恒 0） |
| yaw 列范围 | 2114–2125（**内部刻度，不是度数**，勿直接当角度用） |

判读：误差大但 `fire_ready` 全 0 ⇒ **开火门根本没通过**，不是"打不准"；`lead` 恒 0 ⇒ 提前量通道没有值（可能是未配置或未接线，**属推断，需现场核**）。

## 5. 验收标准

| 项 | 判据 |
|---|---|
| 口径 | 5 套 PID 并列 + 指明哪套是实际加载值（文件值 ≠ 运行值） |
| 链路 | 每段有发布者/订阅数证据；`/LaserShot_Command` 订阅数 = 1 |
| fire_ready | 逐条件列「满足/不满足 + 实测值」，不是笼统「没通过」 |
| 提前量 | `lead` 通道是否为 0、配置解析值、增益是否生效，三者分清 |
| 变量 | 只给一个键，含旧值/新值/预期变化/回滚 |
| 数据 | CSV + 原始日志 + 外部视频时刻对齐 |

## 6. 常见翻车点

| # | 翻车 | 规避 |
|---|---|---|
| 1 | 拿文件值当运行值 | 现场 `deploy_car.py diff` + 读进程实际加载 |
| 2 | 加 kp 追移动靶 | 先算「靶速 × 延迟」是否已超开火框（59 px 中位远超框宽） |
| 3 | 把 yaw 列当度数 | rec4.csv 的 yaw 是内部刻度（2114–2125） |
| 4 | 只看 `speed_reason`/`fire_gate` 单列 | 要看最终发布值与门控最终输出 |
| 5 | 改冻结区默认值做实验 | 用实验配置副本，记来源哈希与逐键差异 |
| 6 | 用"没有预测"直接开工 | 37 文已证 C++/AimTask 都有预测与估计，先查连通性 |
