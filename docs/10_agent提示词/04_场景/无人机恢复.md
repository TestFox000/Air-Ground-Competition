# 场景卡 · 无人机恢复（域号 / uXRCE / 相机）

## TL;DR（给 agent 看的）

- 用在「无人机起不来、`/fmu/out` 没数据、机→车看不见」时；**先判活，再动手**。
- 两个静默杀手：域号机 0 / 车 118；uXRCE 会话每 ~61 s 被看门狗重启。
- 最大坑：`ros2 topic list | grep fmu` 看到话题就以为正常（看门狗自己订阅，Publisher 可能是 0）。

## 1. 触发条件

| 现象 | 指向 |
|---|---|
| `/fmu/out/*` 无数据或 `Publisher count 0` | uXRCE 会话死（常因 Orin 重启而飞控未断电） |
| ping/SSH 全通但 ROS 互相看不见、零报错 | 域号不一致（机 0 / 车 118） |
| 相机窗口黑 / `det=0` | `/dev/video0` 独占、VNC 渲染后端、P1-4 断流 busy-loop |
| 按 4 没反应（路径跟随） | P1-2：路径加载失败后按键不重载 |

## 2. 前置检查（只读边界，先看这条）

| # | 规则 | 说明 |
|---|---|---|
| 1 | 助手对无人机 SSH **只读** | 不改文件、不装包、不改配置；代码改动交用户手动替换与编译 |
| 2 | 禁止代执行有执行能力的节点 | `px4_control`/`px4_teleop` 的决定必须人在座；禁止解锁/起飞/改 PX4 参数/重启飞控 |
| 3 | 串口独占 | **禁止** `cat /dev/ttyACM*`（会把字节从 agent 抢走、制造故障）；禁止双 agent |
| 4 | 域号切换前置闸 | 无 MAVLink 通道（USB 被 uXRCE 占用）⇒ **不要切域**；切换窗口内禁止飞行 |
| 5 | 判活硬判据 | `ros2 topic info -v /fmu/out/vehicle_local_position \| grep "Publisher count"` ≥ 1 |

```
领取 TRACK-DRONE-【日期】-01。目标：把无人机从"起不来/看不见"恢复到"可判活、可定位、可录相机"；不做飞行、不改 PX4 参数、不重建代码。

先读：W\docs\10_agent提示词\00_一页纸.md → W\docs\00_项目总览\现状快照.md

只读纪律：对无人机 SSH 只允许 ls/cat/pgrep/ros2 topic|hz|info 这类只读命令；不改文件、不装包、不改配置、不重启飞控、不解锁不起飞。禁止 cat /dev/ttyACM*，禁止同时开两个 agent。

A. 判活（按硬判据，不看话题是否存在）：
1) ros2 topic info -v /fmu/out/vehicle_local_position | grep "Publisher count"（≥1 才算活）。
2) 记录 8 路 /fmu/out 的 topic hz 与 agent 日志最近 10 s 是否有 create_publisher。
3) 若 Publisher count = 0：按 uXRCE 恢复手册三步走（核心是给飞控断电后重来，不是反复重启 agent）。

B. 域号：
1) 机侧实测 echo $ROS_DOMAIN_ID（交互 shell）与 ssh host 'cmd' 下的值，两者常不同（非交互默认 0）。
2) 车 118、机 0 时，报错形态是"什么都没发生"；先对齐域号再谈链路。
3) 无 MAVLink 通道时不要执行域号切换单；切换单属未执行状态。

C. 定位与相机：
1) px4_odom_convert 必须用 mode:=odom（launch 默认 localization 会静默不发）。
2) VIO 频率应 42–44 Hz；EKF 接受 EV 时看 eph/epv 与 heading_good_for_control。
3) 相机：确认 /dev/video0 未被预览/录制占用；断流后不会自愈（P1-4 busy-loop），需重启进程。
4) 录一段 5 s 并回放确认整车/场地入镜；录包写 ~/drone_bags（eMMC），不要写 /tmp。

D. 禁止：解锁/起飞/发控制指令；改 PX4 参数；重启飞控；cat 串口；用"话题存在"当判活；把"从未飞过"写成"已验证"。

E. 交付：卡面追加：判活记录（时间/命令/输出）、域号两侧实测、VIO/EKF 数字、相机与录像证据、仍阻塞项 + 需要人做的事。≤700 字摘要后停止。
```

## 4. 验收标准

| 项 | 判据 |
|---|---|
| uXRCE | `Publisher count ≥ 1` 且 `/fmu/out` 8 路有频率（历史实测 102/133/142 Hz 等） |
| 定位 | `/Odometry` 43–45 Hz、`/localization` ~44 Hz、VIO 42–44 Hz |
| EKF | eph/epv 3 cm 级、`heading_good_for_control=true`（10-17 曾达 0.032/0.029） |
| 域号 | 机/车两侧实测值 + 是否已切换（含回滚） |
| 相机 | 5 s 录像回放确认入镜；`/dev/video0` 无并发占用 |
| 边界 | 报告明确「未飞 / 未验证飞行」 |

## 6. 常见翻车点

| # | 翻车 | 规避 |
|---|---|---|
| 1 | 用 `ros2 topic list \| grep fmu` 判活 | 看 `Publisher count` |
| 2 | teleop 用 setsid/nohup | 必须真 TTY，否则键盘静默失效 |
| 3 | 录制 `kill -9` | 录制只在正常退出落盘，整段丢失 |
| 4 | `mode` 用默认 | 必须 `mode:=odom` |
| 5 | 域号只改 .bashrc | `ssh host 'cmd'`/cron/systemd 不读 .bashrc |
| 6 | 相信 `dzsmart.local` | IP 会解析到过期地址，先 `arp -a` 现判 |
| 7 | 录包写 /tmp | 重启即清空（10-17 已因此丢过整套栈） |
| 8 | 把"程序能跑"当"感知可用" | live 窗口 `det=0`、画面糊 ⇒ 实拍帧上从未闭环 |

## 7. 口径冲突（未核实，必须现判）

| 冲突 | 两说 | 处理 |
|---|---|---|
| XRCE 在哪个串口 | `ttyACM0`（架构总览实测）vs `ttyACM1`（交接文档 0x7E 帧） | 上机 `lsusb` + `fuser -v /dev/ttyACM*` 现判 |
| 飞控板是否插过 | 「从未插过」vs 10-17 `lsusb` 见 NxtPX4 | 以一手 `lsusb` 为准 |
| auto_start_delay | `mission` 10.0 vs `path_executor` 45.0 两处同义键 | 发车前现场 grep |
