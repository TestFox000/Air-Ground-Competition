# 场景卡 · 文档收口归档

## TL;DR（给 agent 看的）

- 用在「有新的长期结论要落盘 / 旧文散在 8 处 / 要做一次收口」时；目标是**一处一版一条结论**。
- 三个动作缺一不可：**通读 → 定归属 → 必要时拆**；然后 front matter + 索引登记。
- 最大坑：只搬标题不写结论、把 `_tmp_session` 过程稿原样上库、忘登记索引（`AGENTS.md` §8.3）。

## 1. 触发条件

| 触发 | 说明 |
|---|---|
| 会话产生了「以后还要用」的结论 | 不该只留在 `_tmp_session/` 或会话里 |
| 同一结论出现两个版本 | 先定现行篇，旧文写「取代」 |
| 旧文分散在多个目录 | 一次性收口：迁入四库 + `_archive` 留档 |

## 2. 前置检查

| # | 检查 | 判据 |
|---|---|---|
| 1 | 存放地唯一 | 长期文档只能在 `v1/docs/`；其它目录**只出不进**（§8.1） |
| 2 | 归属正确 | 00 总览（是什么/现状）/ 10 提示词（发给 agent）/ 20 资料（查事实）/ 30 卡库（作业台） |
| 3 | 是否已有同主题篇 | 有则改现行篇，不新建第二份（§8.3「副本即债」） |
| 4 | 原文是否已通读 | 没读完不许写「已迁移」（§8.2 ①） |
| 5 | 例外路径 | `dzrobot_v2/docs/` 下 5 个被 `check.py` 读取的活文件保留原路径，正文收敛为指针（§8.1） |

## 3. 提示词正文（可直接复制，替换【】）

```
你是 doc-writer，负责把【主题/目录】的旧文收口进 docs/ 四库。只写【指派子目录】与 docs/_work/timeline_<角色>.md；不碰代码、不 git、不动旧文原件。

工作区 W=D:\User\Desktop\比赛存档\v1。
先读：W\AGENTS.md §8 全文 → W\docs\README.md → 目标库的 00_索引.md（避免重复建篇）→ W\docs\_工具\gen_index.py 的 FM_KEYS。

流程（缺一不可）：
1) 通读：每篇原文完整读一遍，写下「结论 / 关键数字 / 哪些已过期 / 与哪篇冲突」；只 grep 片段不算读。
2) 定归属：按"主题 + 生命周期"入库；同主题只留一篇现行，新篇 front matter 写"取代: <旧路径>"。
3) 拆分：一篇混多主题（架构 + 现场坑 + 卡面）就拆成多篇，并在原文件/回报里写"已拆为 X/Y/Z"。
4) 写篇：front matter 4 行（来源/取证/更新/取代）+ TL;DR 3~6 行 + 结论先行 + 每条结论带证据 + 表格优先 + 篇末「相关文件」；单篇 ≤180 行；不贴 >5 行源码。
5) 索引：目标库 00_索引.md 加一行（标题 / 一句话结论 / 关键数字 / 来源）；
   报给 Lead 重跑 python docs/_工具/gen_index.py（**不要手改 docs/目录索引.md**）。
6) 时间线：写 docs/_work/timeline_<你的角色>.md，一行一条（日期｜事件≤40字｜证据路径:行｜对现在还有什么用），≥10 条。

纪律：取证只用 实/档/未 组合；查不到写"未核实"，绝不编数字；口径冲突并列写" A 版 / B 版 + 各自出处"；
旧路径一律换成新库路径，并在篇末写「相对旧版改了什么」；过期内容明确写"历史，勿用"。

禁止：写 docs/ 以外任何长期文档；在 _tmp_session 另建副本；搬过程稿原文（必须先提炼）；重复建篇；手改自动索引；做 git 操作；调用 present。
交付：文件清单（带行数）+ 3 个最重要发现（带证据）+ 判为过期/重复/未核实的源文件清单 + 未覆盖主题（留给谁）。
```

## 4. 验收标准

| 项 | 判据 |
|---|---|
| 归属 | 每篇都在四库之一，且不是同主题第二份 |
| front matter | 4 行齐全，键名被 `gen_index.py` 识别（来源/取证/更新/取代） |
| 可读性 | 30 秒内能判断「要不要细读」（TL;DR 有效） |
| 证据 | 每条关键结论有 `路径:行号` 或「路径 + 章节」；无证据的写〔未〕 |
| 体量 | 单篇 ≤180 行；超长已拆 |
| 索引 | 册内 `00_索引.md` 已加行；`python docs/_工具/gen_index.py` 跑通且篇数对得上 |
| 冲突 | 多版本事实并列写（A/B 版 + 出处），未被合成一个假结论 |
| 旧文 | 被取代篇有「取代者」指向；原件仍在 `_archive/`（由 Lead 执行） |

## 5. 常见翻车点

| # | 翻车 | 后果 | 规避 |
|---|---|---|---|
| 1 | 只搬标题 | 索引里全是「关于 X 的文档」，等于没写 | 每篇必须有一句话结论 + 关键数字 |
| 2 | 过程稿直搬 | 库里出现半成品与临时脚本 | 先提炼，原文留 `_tmp_session` |
| 3 | 两处各存一份 | 下轮又分叉 | 只写指派目录；旧文写「取代」 |
| 4 | 忘登记索引 | 下次找不到 = 等于没写 | 写完立刻加 `00_索引.md` 行 |
| 5 | 手改 `目录索引.md` | 下次生成被覆盖 | 只跑生成器 |
| 6 | 旧路径没改 | 读者点开是 404 | 全文替换为新库路径，篇末列改动 |
| 7 | 数字凭记忆 | 一条错数污染整个库 | 一律回到源文件核；给行号 |

## 6. 与其他卡的分工

| 谁做 | 做什么 |
|---|---|
| doc-writer | 读、提炼、写篇、登记册索引 |
| Lead | 移动/归档旧文、改 `README.md` 与总览、重跑 `gen_index.py`、最终断链校验 |
| reviewer | 抽查 3 篇：是否一主题一篇、是否有证据、是否与代码冲突 |
