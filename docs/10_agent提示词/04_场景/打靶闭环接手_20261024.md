# 场景卡 · 打靶闭环接手（2026-10-24）

## TL;DR（给 agent 看的）

- 用在「换一个 agent 接着做自瞄打靶」时：**整段复制 §3 的提示词**发过去，它自己就知道读什么、写哪、做到哪停。
- 前提：**同一个工作区、同一个 git 仓库**。所以提示词里给的是**路径**，不发附件、不贴长文。
- 现状一句话：链路已通（裁判板 1:1 记账 2 发），瓶颈是 `/aim/lead_x` 无发布者 ⇒ 匀速段必然落后 33 px > 开火框 25~26 px。
- 最大坑：让新 agent 一上来就调 PID / 改 `fire_stable_px_per_frame` —— 顺序反了只是白耗剩下的 3 发弹药。


## 5 常见翻车

| 翻车 | 后果 | 规避 |
|---|---|---|
| 一上来调 `fire_stable_px_per_frame` | 白耗剩 3 发弹药，问题没解 | 提示词里已锁死「先做提前量」 |
| lead 符号反了直接发布 | 云台越推越偏，可能打出框 | 必须 dry-run 先验证符号 |
| 拿本地源码当车端事实 | 结论全文作废 | 手册 §4-5 已点名；要求它先 grep 再断言 |
| 把「打了没记账」当链路故障 | 浪费半天查链路 | 先查 `dzjudgment` |
| 顺手清理别人的未提交改动 | 破坏另一个会话的工作 | 提示词第一条就是 `git status` 只读 |
