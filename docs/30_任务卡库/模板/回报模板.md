# 回报模板（卡内回报 + 700 字可转交摘要）

## TL;DR（给 agent 看的）

- 一张卡只出**一份**汇报：写进卡正文的「结论」节；交给上级时另附 ≤700 字可转交摘要。
- 收口还必须写**经验总结**（独立第八块，六要素）：可迁移的「现象→机制→位置→处置」，落点坑库/百科/台账；见 [06_工作完结经验总结规范](../../10_agent提示词/06_工作完结经验总结规范_20261024.md)。
- 摘要的每个字段都要能落到 `路径:行`；没有证据的字段写"未验证 + 原因"，**不能留成默认成功**。
- 最大坑：把"命令 exit 0"当成"结论成立"。退出码只证明跑完，不证明判据成立。

## 1 可转交摘要（≤700 字，复制填空）

出处 `docs/agent_handoff/32_循迹回报模板.md:9-37`：

```text

卡号/日期/轮次：
结论：已收口 / 未收口 / 需现场配合
本轮唯一假设：
本轮实际改变的变量：（诊断卡应写"无生产改动"）

基线：
工作区/车仓 HEAD/脏文件：
本地与车端源码哈希：
配置/地图/路线来源与 SHA256：
证据等级：〔实〕/〔档〕/〔未〕

核心结果（每条后跟 路径:行）：
- 
- 

既有测试：运行 N 套，通过 N，非零退出 N，未运行 N；失败 ID 及归因：
门禁：tools/wf/check.py 退出码 + 关键输出：
文件变更：本轮清单；冻结区有无；他人改动是否保留：
Reviewer：通过 / 打回，理由：
经验：<现象→处置一行>（证据 路径:行；无则〔未〕）
未决问题与下一轮唯一建议：
回滚点：
完整 REPORT/证据/复核/manifest 绝对路径：
停止点：已停止，未自动进入下一轮。
```

## 2 卡内报告结构（七节，缺节即退回）

出处 `docs/agent_handoff/32_循迹回报模板.md:39-86`，21:00 后的新卡普遍压成 4–6 节，但要素不变：

| 节 | 必须回答 | 真实写法 |
|---|---|---|
| **① 任务与边界** | 目标 / 写域 / 禁止项 / 起止时间 | 写"未 SSH、未部署、未 commit"三连（`dzrobot_v2/_tmp_session/TRACK-PLAN-B1-20261021/REPORT.md:171`） |
| **② 基线与来源** | 改前哈希、配置/地图身份、Python 版本 | 给完整 SHA256，不给前 8 位（`_tmp_session/TRACK-FIELD-R3-20261020-01/review.md:19-31`） |
| **③ 变更摘要** | 逐文件 + 行数 + 改后哈希 | 表格：文件 / 改动 / +N−M / SHA256（B1 REPORT:12-16） |
| **④ 验收逐条** | 命令 + 预期 + 实测 + 原始输出文件 | 一条命令一行，退出码单列（R1 CARD:76-95） |
| **⑤ 判定** | 通过 / 附条件 / 不通过（三选一，不许模糊） | "本地离线验收通过，待人工部署"是合法判定 |
| **⑥ 未验证 / 阻塞** | 缺哪一路证据、下一个卡要补什么 | B5 列了 9 条（`_tmp_session/TRACK-FIELD-B5-20261021/REPORT.md:89-99`） |
| **⑦ 回滚与证据清单** | 备份哈希 + 只逆转本卡差异 | 禁止 git reset；备份文件带 SHA256 |

**独立第八块 · 经验总结（归档必写，见 [06_工作完结经验总结规范](../../10_agent提示词/06_工作完结经验总结规范_20261024.md)）**：现象 / 机制 / 位置 / 处置 / 证据等级 / 落点，六要素缺一不算写完。七节结构不变，老卡不追溯。

> **重量级卡（证据 >200 行）可加三张附表**：基线哈希表、复跑命令表（cwd / 命令 / 退出码 / 原始输出文件）、门禁分母表（相关测试 / 缺陷探针 / 全量回归，三个分母分开）。不加不影响合规。

## 3 质量卡的证据数组（机器读）

| 字段 | 一项对应 | 取值 |
|---|---|---|
| `acceptanceResults` | 一条 acceptance 判据 | `{criterion, status: passed|failed, evidence}` |
| `commandsRun` | 一条 verify 命令 | `{command, status, exitCode, evidence}` |
| `changedPaths` | 一个改过的文件（实现/修补卡必填） | 工作区相对 POSIX 路径 |
| `findings` | 一条复核发现（打回时必填） | `{id, severity, problem, requiredFix, file?, line?}` |
| `verdict` | 复核结论 | `pass` / `needs_revision` / `reject`（后两者必须带 findings） |

## 4 判定口径（避免三种假完成）

| 假完成 | 真相 | 正确写法 |
|---|---|---|
| "测试全绿" | 只跑了 7 套，或全量里 13 套红 | "7 套通过；全量 37 套 / 13 红沿用 D-023 基线，本轮未重跑" |
| "已修复，待验证" | 补丁在工作树，车端仍旧版 | "本地位于 tracker.py，候选 hash e9bff6f0…；车端 src/install 仍 9e9766a1…（未部署）"（`docs/agent_handoff/35_R1验收与R2实车派工.md:22-27`） |
| "实车通过" | 人工接管截停当成自然 FINISH | "人工截断窗口，终点自然停车误差=不适用"（`docs/agent_handoff/34_实车基线执行任务.md:71`） |

## 5 交给上级时的最小包

- 同机：摘要 + 卡路径 + 证据目录路径（上级自己读），不要贴整段日志。
- 争议项：再给探针脚本 + 命令 + 原始输出 + 被测源码哈希（`docs/agent_handoff/32_循迹回报模板.md:90-92`）。
- 异机/网页：只传经检查的必要片段，不发 `.git`、整份 `_tmp_session`。
