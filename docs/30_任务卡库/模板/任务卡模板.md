# 任务卡模板

## TL;DR（给 agent 看的）

- 卡 = 报告：所有执行记录、命令输出、结论都写进**同一张卡的正文**，不另起 REPORT.md（`AGENTS.md` §8.5）。
- 开工前必须有 **5 必填**；质量卡另需 objective/acceptance/verify/inScope/outOfScope 五项。
- 最大坑：把"跑通了"写进"结论"栏。结论栏只放**可复跑命令 + 真实退出码 + 失败ID**，其余进"观察"。

## 1 现在卡面实际长什么样（三种真实形态）

| 形态 | 真实样本 | 特征 |
|---|---|---|
| **全量卡**（大卡） | `_tmp_session/TRACK-R1-20261020-01/CARD.md`（103 行） | 表头 + 一句话目标 + 复用检索 + 新增轮子 + 改动范围表 + 验收命令 + 回滚点 + 影响面 |
| **压缩卡**（21:00 后新卡） | `_tmp_session/TRACK-VIS-20261021/CARD.md`（56 行） | 一句话结论 + 硬结论表（每条带证据）+ 口径修正 + 需 Lead 裁决项 |
| **方案卡**（只读分析） | `_tmp_session/TRACK-YAW-20261021/CARD.md`（75 行） | 五问速答 + diff 草案 + 证据索引表 + 未验证清单 |

共同点：**每条关键结论后面紧跟证据**（`文件:行号` 或章节名），没有证据就写「未核实」。

## 2 5 必填（A 版：仓库工作流 v2）

出处 `docs/agent_handoff/30_循迹团队执行方案.md:69`，措辞按真实卡面：

| # | 字段 | 写什么 | 反例（= 卡被退回） |
|---|---|---|---|
| 1 | **读过的台账条目** | `D-0xx` 编号 + 一句它约束了什么 | "已了解项目背景" |
| 2 | **复用检索结果** | 复用清单/能力索引命中项 + 「结论」列 | "打算自己写一个" |
| 3 | **新增轮子及理由** | 新增文件路径 + 为什么现有不够；没有就写「无」 | 新增脚本不登记 |
| 4 | **验收命令** | 可复跑命令 + cwd + 环境变量 + 预期 | "已测试通过" |
| 5 | **回滚点** | 备份路径/哈希 + 只逆转本卡差异的方式 | "git reset"（禁止） |

## 3 质量卡契约（B 版：平台口径）

| 字段 | 对应仓库说法 | 硬要求 |
|---|---|---|
| `objective` | 一句话目标 | 单数、可判定，不写"优化一下" |
| `acceptance` | 验收命令与预期/通过判据 | 每条可独立判定，禁止"整体感觉良好" |
| `verify` | 可复跑命令 | 命令 + 退出码 + 原始输出落盘路径 |
| `inScope` | 写域（一文件一 owner） | 精确到文件；目录级写域要说明边界 |
| `outOfScope` | 禁止写/禁止项 | 必须显式列出冻结区与共享治理文件 |
| 结论字段 | REPORT 的"判定" | review/requirements 需 `verdict=pass`；`needs_revision`/`reject` 必须带 findings（id/severity/problem/requiredFix） |

> 两版并存不是冗余：A 版防"没想清就开工"，B 版防"没证据就算过"。**冻结区文件必须先登记 `tools/wf/frozen.json`（owner+到期日）再动**（`docs/agent_handoff/33_循迹R0复核与R1任务.md:61`）。

## 5 常见退回原因（自查）

| 现象 | 修法 |
|---|---|
| 写了"已修复/已优化"但没有命令与原始输出 | 补 `logs/*.log` + 真实退出码；无证据就改判"未验证" |
| 结论里出现"大概/应该/经验上" | 改成"〔未〕，缺 X 一路信号" |
| 用内部估计当外部真值 | 分列 raw / belief / 外部量测三栏（`docs/agent_handoff/36_R2复核_R3补测与收尾计划.md:28`） |
| 一次改多个变量 | 拆卡；一轮一个假设（`AGENTS.md` §1.6） |
| 为了变绿改断言 | 真缺陷禁止重钉（D-023⑤，见 `dzrobot_v2/_tmp_session/t35/REPORT.md:86-90`） |
