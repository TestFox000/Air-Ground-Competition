# 00_命名空间与任务树（v1 · 2026-10-23 试行）

> 一句话：**一支团队 = 一个命名空间（ns）**；卡必挂树、树归 ns owner、归档必带落地指针。
> 试点期只对 `在办/lead-1023/` 生效；11 张旧卡暂无 ns，守卫对其只跳过不判红（迁移见 §8）。

## 1 为什么要有这层

10-23 一天内真实发生的三次抢写，都不是"卡文件互相覆盖"，而是**共享登记表**被多方重生成：

| 冲突点 | 事实 |
|---|---|
| `30_任务卡库/README.md` | 另一会话在改（加 AG-TEAM-PLAN 行），我一改就覆盖 |
| `docs/目录索引.*` | `gen_index` 全库重生成，谁跑谁把别人**未入库**的卡卷进去，导致无法提交 |
| `归档/00_索引.md` | 同时被另一会话修改 |

同期还有三张卡（`AIM-BASELINE`、`TRACK-C0EXT`、`TOOLS-PLUGIN-TERMGATE`）在我不知情时出现。
**结论：要隔离的是"登记与索引"，不是卡文件。** 只把卡放进不同目录、却仍共用一张 README，冲突会原样迁移。

## 2 命名空间

```
docs/30_任务卡库/
├── README.md                 # 全局：ns 注册表 + 规则（单写者：lead）
├── _模板/{任务卡模板,回报模板,树模板}.md
├── _设计/00_命名空间与任务树.md   # 本文件
├── 在办/<ns>/00_树.md         # 该团队的跟进树（ns owner 单写）
├── 在办/<ns>/<卡号>.md
└── 归档/<YYYY-MM-DD>/<ns>/<卡号>.md
```

- **ns 命名**：`<角色>-<MMDD>`，如 `lead-1023`。一支团队一个 ns，不按对话分——同一团队的多个成员写同一 ns 的不同卡，冲突面最小。
- **写权**：**读任意 ns，只写自己 ns**；全局 `README.md` 与 `_设计/` 只有 lead 写。
- **注册**：`README.md` 的「ns 注册表」一行一个 ns（ns / 团队或会话 / owner / 起止 / 状态）。
- **索引分片**：`目录索引` 按 ns 生成分片再合并，各会话只重生成自己那片 —— 这是消掉"索引提交不了"的唯一办法，见 §8 第 3 步。

## 3 卡面契约

front matter 在原四键（来源/取证/更新/取代）之外**必增四键**：

| 键 | 值 | 规则 |
|---|---|---|
| `ns` | `lead-1023` | 必须等于所在目录名 |
| `agent` | 团队 target / 会话 id | 一张卡**只有一个**绑定 agent；转手要改这一行并写一句原因 |
| `树节点` | `L-2`（可多个，逗号分隔） | 必须在 `00_树.md` 里存在且指向本卡 |
| `写域` | `docs/_工具/**；docs/30_任务卡库/**` | **分号（；）分隔**的路径前缀（路径里可能有逗号）；收口时与 `git diff --name-only` 对账 |

`status` 仍是三值：`pending | in_progress | 已归档`（§8.5），细节写正文。

## 4 任务树（N 叉）

节点格式（一行一个，缩进表示层级）：

```
L-0  根：本次会话/团队目标
├─ L-1  [卡] 卡号 · 一句话目标        ✔ 已完成 19:12（结论：0.3 m/s）
├─ L-2  [卡] 卡号 · 一句话目标        ↻ 进行中
│   ├─ L-2.1  [项] 尚未成卡的工作项    ⏸ 等窗口
│   └─ L-2.2  [项] …                  ✘ 否决（理由）
└─ L-3  [项] 待拆项                    ⏸
```

- **允许 N 叉**：一个节点可以有多个子节点（判定成立/不成立、A/B 方案、并列子任务）。
- **但每个 `[卡]` 节点只验证一个变量**：一张卡同时改两个变量时，必须拆卡或降级为 `[项]` —— 这条正好接上铁律"一次只改一个变量"。
- **节点类型**：`[卡]` 已建卡；`[项]` 尚未建卡的工作项（叶子，出现即说明"知道要做但还没开卡"）。
- **状态符号**：`✔` 完成 ｜ `↻` 进行中 ｜ `⏸` 阻塞/等待 ｜ `✘` 否决/撤销。
- **单写者**：树由 ns owner 写；成员只能在卡里写"请求新增节点 X"，由 owner 落树。否则树自己会成为新的抢写点。

## 5 归档契约（"完成即提炼"的硬约束）

`已归档` 不是"我说完了"，要同时满足三条：

1. 卡 §文档变更 非空：写清**新增/修改/归档**了哪几篇（§8.8 已有）；
2. **反向指针**：被改的那篇里加一行 `来源: <卡号>`，让读者知道这条结论是哪张卡挣来的；
3. **落地三选一**：结论必须落进 ① 百科篇（`20_资料索引库/`）② 坑库/症状索引 ③ 决策台账。三个都没有 = 这张卡的经验只活在一个文件里，**不许归档**。

## 6 孤儿与会话结束

ns 目录里还有 `pending`/`in_progress` 卡，但该 ns 超过 **24h** 无写入 → 树节点标 `⏸`，`docs/TEAM_STATUS.md` 记一行"孤儿 ns：<ns> / 卡 / 最后写入"。会话结束不等于卡结案。

## 8 迁移计划（分两段，试点先行）

1. **试点（本轮）**：只建 `在办/lead-1023/`，把 `DOC-FIX-20261023` 迁入 + 写 `00_树.md`，验证树/守卫/索引三件事是否真的顺。
2. **全量（待试点结论）**：11 张在办卡归 5 个 ns（`aim-1023`、`track-1022`、`tools-1022`、`drone-1022`、`lead-1023`），每 ns 一棵树；同步改 README 注册表与 `归档/00_索引.md` 链接。
3. **索引分片**：`gen_index` 支持 `--ns` 参数，只重生成指定 ns 的分片；合并由脚本做，人不手改。
4. 每步都要 `check_links` + `check_doc_policy` 全绿。

## 9 不做（防开倒车）

- 不上数据库/服务：全项目是 md + 脚本，加一层存储只增维护债。
- 不复制归档文件做"跨 ns 引用"：只写引用行，副本即债。
- 不改旧卡命名（只加目录层），避免 8 处外部引用同时断。
- 不把树做成"第二张状态板"：树只记结构与判定，进度细节仍在卡里。
