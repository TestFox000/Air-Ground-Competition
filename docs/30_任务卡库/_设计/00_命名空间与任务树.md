# 00 · 命名空间与任务树（agent 契约 v2）

> **给 agent 的读法**：本文件是**契约**，不是说明文。§2/§3 是格式，§5 是机器判据，§6 是命令。照 §6 做即可，不需要理解设计动机。
> 唯一约束一句话：**一支团队 = 一个 ns；卡必须挂树；写只写自己 ns。**

## 1 路径契约

| 对象 | 路径模板 | 谁写 | 说明 |
|---|---|---|---|
| ns 目录 | `docs/30_任务卡库/在办/<ns>/` | 该 ns owner | 卡文件平铺在此，不再套子目录 |
| 任务树 | `docs/30_任务卡库/在办/<ns>/00_树.md` | 该 ns owner（唯一） | 成员**不许**改树，只能在卡里提"请求新增节点" |
| 归档（单卡） | `docs/30_任务卡库/归档/<ns>/<YYYY-MM-DD>_<卡号>.md` | 该 ns owner | **按 ns 分层**（R9 强制）；跨 ns 只写引用不复制 |
| 归档（按日摘要） | `docs/30_任务卡库/归档/_按日摘要/<YYYY-MM-DD>.md` | lead | 10-21 前的多卡合并摘要，不是卡面 |
| 归档索引 | `docs/30_任务卡库/归档/00_索引.md` | lead | 全表 + 日期导航，永远在最外层 |
| ns 登记 | `docs/30_任务卡库/_设计/01_ns登记.md` | lead 单写 | 新 ns 先登记再建目录，否则 Y6 |
| 模板 | `docs/30_任务卡库/_模板/{任务卡模板,回报模板,树模板}.md` | lead 单写 | 只读引用 |
| 契约 | `docs/30_任务卡库/_设计/00_命名空间与任务树.md` | lead 单写 | 即本文件 |

**ns 命名**：`^[a-z][a-z0-9-]*\d{4}$`，形如 `lead-1023`、`aim-1023`、`track-1021`。数字是建 ns 的日期（MMDD）。

## 2 卡面契约（front matter 必填）

```yaml
---
来源: <源路径或"本会话现场记录">
取证: 实|档|算|未 的组合
更新: 2026-MM-DD
取代: 无 | <被本篇取代的卡号>
status: pending | in_progress
ns: <ns>
agent: <绑定智能体 team target 或角色名>
树节点: <树里该节点的 ID，如 A-2>
写域: <本卡允许改的路径，逗号分隔>
---
```

| 键 | 值域 | 缺了会怎样 |
|---|---|---|
| `status` | `pending` / `in_progress` | **R4 红** |
| `ns` | 必须 == 所在目录名，且已在 `01_ns登记.md` | **R7 红** |
| `agent` | 非空；一个卡只能绑一个 | **R7 红** |
| `树节点` | 非空，且卡号必须出现在 `00_树.md` | **R8 红** |
| `写域` | 非空 | 评审人工（机器不判） |

归档卡额外契约（R9）：必须落在 `归档/<ns>/` 层、`ns:` 与目录一致、且有 `## 文档变更` 段**非空**（写了没落点 = 等于没写）。
归档卡 `status: 已归档`；然后 §5 三选一落点必填：百科篇 / 坑库 / 台账条目。

## 3 树契约（`00_树.md`）

- 每个节点一行，缩进表层级；**N 叉允许**，但每个 `[卡]` 节点只能验证**一个变量**（一张卡一个假设）。
- 语法（机器按这两条正则解析）：

```
节点行： ^\s*[├└│─\s]*<节点ID>\s+(\[卡\]\s*<卡号>|<\[项\]>)\s*(.*)$
卡引用： \[卡\]\s*([^\s·|（(）)]+)      # 捕获组必须是同目录下的 <卡号>.md 文件名主干
```

- 节点 ID：`<ns 前缀>-<序号>`，子节点 `<父>-<n>`，如 `A-2.1`。
- 状态符号：`✔` 完成 ｜ `↻` 进行中 ｜ `⏸` 阻塞/等待 ｜ `✘` 否决。
- 叶子是 `[卡]` 时，该卡必须已归档或明确 ⏸；**不允许把已归档结论写成 `[项]`**（那是卡，不是项）。
- 树底必须有「节点变更记录」表：`| 时间 | 节点 | 动作 | 理由 |`，动作 ∈ {新增, 关闭, 改判, 否决}。

## 4 写权矩阵

| 目录/文件 | ns owner | 其他 agent | lead |
|---|---|---|---|
| `在办/<自己 ns>/**` | 读写 | 只读 | 只读 |
| `在办/<别人 ns>/**` | — | 只读 | 只读（裁决除外） |
| 全局 `README.md` / `_设计/` / `_模板/` | — | 只读 | 读写（单写者） |
| `归档/**` | 本 ns 追加，**已写不删** | 只读 | 只读 |
| 守卫脚本 `docs/_工具/**` | — | — | 读写 |

冲突时的机器兜底：守卫 R7/R8/R9 抓结构（Y6~Y8 已于 2026-10-23 转红线），`git diff --name-only` 对 `写域`（卡收口时人工核对，见 §6）。

## 5 守卫规则（`python docs/_工具/check_doc_policy.py`）

| ID | 级别 | 触发条件 | 修法 |
|---|---|---|---|
| R4 | 红 | 在办卡 `status` 不在 {pending,in_progress}；归档卡 ≠已归档 | 改值域，细节挪正文 |
| R6 | 红 | `20_资料索引库/README.md` 写"应为 N 篇"与实际 .md 数不符 | 改数字或跑 gen_index 后同步 |
| Y5 | 提醒 | 根目录出现 `_tmp*`/`_work_tmp*`/`_recover_tmp*` | 移 `_tmp_session/` 或 `_archive/` |
| R7 | 红 | ns 未登记 / 卡面 ns≠目录 / 缺 00_树.md / 缺 agent | 补 front matter 或先登记 ns |
| R8 | 红 | 缺树节点 / 卡号未出现在树 / 树指向不存在的卡 | 补节点或改卡号 |
| R9 | 红 | 归档平铺未按 ns 分层 / 归档卡 ns≠目录 / `## 文档变更` 为空 | 移进 `归档/<ns>/` 或补记录 |

升级路径：同一规则连续两轮零告警 → 由 lead 改判为红（改本表 + 改脚本，同一提交）。**Y6~Y8 已于 2026-10-23 22:0x 转 R7~R9**（迁移完成、三项负向测试 3/3 命中）。

## 6 命令（照抄）

**开场（新会话 4 条）**

```
# 1 看自己 ns 有没有卡、树长什么样
ls docs/30_任务卡库/在办/<ns>/ ; sed -n '1,60p' docs/30_任务卡库/在办/<ns>/00_树.md
# 2 领卡：改 front matter
#   status: pending -> in_progress ；agent: 填自己 target ；树节点: 挂到树上
# 3 只用增量索引，别跑全量（会把别人未入库文件卷进来 -> 幽灵条目）
python docs/_工具/gen_index.py --ns <ns>
# 4 体检
python docs/_工具/check_doc_policy.py
```

**收口（5 条，缺一不算完成）**

```
# 1 三选一落点：百科篇 / 坑库 / 台账（都没有 = 不许归档）
# 2 卡面补 ## 文档变更（新增/修改/归档了哪几篇）
# 3 归档：status: 已归档；git mv 到 归档/<ns>/<YYYY-MM-DD>_<卡号>.md（平铺 = R9 红）
# 4 树：把该节点改成 ✔ 并写结论，补一行节点变更记录
python docs/_工具/gen_index.py --ns <ns>      # 5 索引（增量；卡库整体用 --only 30_任务卡库/）
python docs/_工具/check_doc_policy.py && cd dzrobot_v2 && python tools/wf/check.py
```

## 8 不做（防开倒车）

- 不引数据库/服务/守护进程：这套是 md + 一个守卫脚本。
- 不做跨 ns 的卡复制存档（副本即债）；要引用就写一行指针。
- 不让成员直接改树（树是单写点，改了必冲突）。
- 不把归档区当工作区（归档只追加不修改）。
- 不因为"结构化"就拆卡：一张卡仍然是"一个变量 + 一份证据"。
