## 2 机制三连坑（本轮钉死，全部有负向证据）

1. **`blob:none` 部分克隆不能直推**：promisor 让「have 协商」失真，git 以为服务端有对象而少发 → 远端 `did not receive expected object → index-pack failed`（thin / `--no-thin` / `--no-reuse-delta` 同错）。**治法：`git clone --bare` 出无 promisor 的干净镜像仓（本轮 `v2full.git`），从镜像推**——换仓后 42 笔连推零该错。
2. **HTTP/2 × 本地代理 × 大请求体 = 流控僵局**：1 GB body 下 `git-remote-https` CPU 20 s 零增长、IOWriteBytes 增量为 0（假死，不是慢）。**治法：`-c http.version=HTTP/1.1`**——同链路 171 MiB 一笔过（650 KiB/s 级可见进度）。辅助：`-c http.lowSpeedLimit=1024 -c http.lowSpeedTime=45` 让残余假死能自断重试。
3. **逐笔推送可恢复**：42 笔按分支逐个 `git push`（`+refs/remotes/origin/<b>:refs/heads/dzrobot-v2/<b>`，本地分支用 `refs/heads/<b>` 作源——含未推 7 提交；**push 源不接受裸对象 ID**，dry-run 证实后改回 ref 源）。中断后重跑，已落 ref 自动 SKIP。

**过程自误两处（如实）**：① Python 在 Windows 写 refspec 文件带 CRLF → bash `read` 吞入 `\r` → 首轮 42 笔全 `invalid refspec` 拒（修：`newline="\n"` 重写 + LF 校验 `cat -A`）；② 首轮误把国内 gitee 回源也挂 7890 海外代理（25 MB/min，直连实测 2.5 s）——**代理只给 GitHub 用**。

## 经验总结（六要素）

- **现象**：dzrobot_v2 推 GitHub，首笔 13 分钟零字节「卡死」；换法后 42 笔全落。
- **机制**：部分克隆 promisor 协商失真 + HTTP/2 大 body 流控僵局 + CRLF refspec 三因叠加；「推不上去」从来不是 GitHub 拒大仓。
- **处置**：干净 bare 镜像 + HTTP/1.1 + 逐笔幂等重试 + lowSpeed 自断。
- **测试**：dry-run 先行验 refspec 语法；`ls-remote` 前后快照对账；IOWriteBytes 差分证伪「慢」、实为「死」。
- **教训（一句话）**：**报「推不上去」先分层定位——对象完整性、传输协议、refspec 卫生各查一遍，别拿体积当挡箭牌；「不可行」入库前必须限定其适用仓**。
- **落点**：06 §7.1（更正）+ 症-49 改写 + 台账 D-061 + 本卡（三选一全中：机制→百科篇，现象→症状索引，裁决→台账）。
