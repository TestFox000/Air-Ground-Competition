# WB-16 · 声明面 ≠ 可用面：探针说支持，实跑 exit 2

## 读过的台账条目

- WB-5 §执行报告·⚠️① 产品缺陷（写域外，只读记录）。
- D-063 硬判据③（指标带分级）；本轮已抓到的三条"空转绿灯"（WB-12）。

## 缺陷原文（wb-net 实测）

```
❌ --from-cell / --already-covered 只支持 --engine tracker-safe（增量续算 G4）
```
`plannerIncrementalSupport()` 探针报 **supported=2/2**（**声明支持**），但现役 engine（`tour`）下实跑 **exit 2**。

后果链：
1. 探针说支持 ⇒ 编排层传参 ⇒ 后端 exit 2 ⇒ 页面 **422**；
2. 运行台账记「参数已传」⇒ 排障的人以为"传过去了只是规划无解"；
3. 真相：现役引擎根本不支持。

## 为什么这是"假绿"家族的一员

与本轮 What's already caught 的三条同型：**开关/探针存在、声明可用、实际不通**。区别只在层：那三条在 **CLI 参数层**，这条在**声明层**（探针函数）。

⇒ 这条的价值在于它把"假绿"的搜索面从"参数有没有接上"扩展到"**声明有没有与实际能力对齐**"。以后任何 `xxxSupport()` 类探针都该有一条"声明=实跑"的负例。

## 处置原则

1. **声明服从能力**，不是能力服从声明。`tour` 不支持就不许报 supported（静态写死 2/2 是根源）。
2. 前端必须**能看见**这个不支持：不是后端 422、前端一脸茫然。
3. 不许为了测试绿而放宽断言；`test-sim-incremental.mjs`〔未入库〕 的 FAIL 变化要逐条归因。
4. 只改声明与编排，**不动 `planner.py` 的引擎能力**（那是另一条链）。

WB-5 还发现台账 `routeMd5` **从未存在**（`simbench.js`〔未入库〕 只写 `configMd5` / `mapMd5`）。留一个永远不存在的字段，和留一个永远 `0` 的字段一样有害——本线已在 WB-12 ⑩ 处理过 `task_health.ticks` 恒 0 的同类问题。

### 判据为什么这么写（这条是本卡最该记住的）

验收要求"正例：`tracker-safe` 下 supported 且**真能用**（有实跑证据）"。
**实测做不到"有解"**：`tracker-safe` 在现役四张图上**结构性无解**（我逐张跑过）：

```
map_field7_t24  → rc=1 tracker-safe 引擎无解
map_carloop     → rc=1 同上
map_sixth       → rc=1 同上
map_field       → rc=1 同上
```

这不是本卡能修的（`test_incremental_plan.py:16-33` 自己已写明"主体被显式 SKIP"、WB-4 记 0/30）。
⇒ 若把"有解"当正例判据，这条守卫**永远绿不了**，等于逼下一个人去放宽断言。

**改用 exit code 语义分级**（与"有没有解"解耦）：

| exit | 含义 |
|---|---|
| **2** | 参数被 CLI 引擎门**拒绝**（"根本没被接受"）← 本卡要消灭的状态 |
| **1** | 参数**被接受**、只是这张图无解（"进去了却没解"）← 正常 |
| **0** | 被接受且有解 |

⇒ 正例判据 = `exit !== 2` 且 `argv 真含增量开关`；负例 = 现役 tour 下 `argv 不含` 且 `dropped=reason=engine-unsupported`。
**顺带记一条给后续卡**：`--map` 改成 `map.start=M9` 也补不出解（我实测过），
`tracker-safe` 的"可解"前提是拓扑级的，不是"换起点"能绕的。

## 经验总结

- 现象：声明面声称 `plannerIncrementalSupport` 2/2 支持，但现役 tour 引擎实跑 **exit 2**——声明与可用不一致。
- 机制：探针**只读 argparse**，而能力其实有两道门（CLI 有没有 `add_argument` ∧ 运行时是否真能走通）；只看第一道门就会把「声明了」当「能用」。
- 位置：插件探针 `plannerIncrementalSupport()`；三层根因在 argparse / 引擎分发 / 产物契约。
- 处置：把探针改为覆盖两道门；删除 `routeMd5` 的造假值（按「不造假值」原则）。
- 证据：插件侧那张 incremental 台测从 7/9 PASS + 2 FAIL → **15/15 PASS + 4 SKIP（rc=0）**；五守卫全绿。
