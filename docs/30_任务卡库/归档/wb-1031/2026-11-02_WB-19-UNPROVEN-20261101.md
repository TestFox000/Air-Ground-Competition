4. legacy 模式必须显式标注 `LEGACY_UNCHECKED`，不许静默等同 PASS。

### 一、三分档的机器判据（不靠人读措辞）

```
PASS      rc == 0
UNPROVEN  rc != 0 ∧ 含 `not a proof of map infeasibility` ∧ --max-nodes 18000×11 仍 rc != 0
FAIL      rc != 0 ∧ 无免责声明 ∧ --sample-step 0.0005 仍 rc != 0
```

**为什么必须"换参数仍不变"才算**：只凭报错文本判档，等于把"机器当时多忙/参数多紧"
当成图的固有性质 —— 这与 WB-4 已修过的「墙钟超时 ≠ 无解」是同一类错误。
实测反例：`n017` 换 `--sample-step 0.0005` **和** `0.0010` 都 rc=0；
`n008` 提 `--max-nodes` 到 198000 就 rc=0。**这两类都不是图的固有属性。**

### 二、对照组与负例的真实输出

**对照组**（证明判据可用，不是见谁红谁）：
```
Map: src/dzbrain/tests/fixtures/map_field7_t24.yaml | STATIC GEOMETRY PASS
trajectory 0.638161  0.000000  0.493789  0.717850  7/8  8/8  8/8  0.069537
rc=0
```
与 captain 实测逐位相同。

**负例（legacy 不等于 PASS）**：不带 `--trajectory` 时 `state` 一律 `LEGACY_UNCHECKED`，
`artifacts/synth_maps/SELFCHECK.json` 的 `counts` = `{"LEGACY_UNCHECKED": N}`，**绝不静默变 PASS**。

### 三、`MANIFEST` / `SELFCHECK` 三桶

`unproven` 与 `deterministic_fail` **并列且不进可行率**；新增三个子桶
`budget_sensitive` / `sample_sensitive` / `retry_timeout`，与三档并列但**不进三档**——
换参数敏感性不是图的固有性质，塞进任一档都会歪曲结论；不单列则「执行了换参数判据」看不见。

> ★ 这一处是 captain 抓出来的：粗聚合（`startswith("UNPROVEN")`）会把
> `UNPROVEN_BUDGET_SENSITIVE` 算进 UNPROVEN，于是**判据执行了却看不见结果**，
> 报告仍显示笼统的 15/7/8，与"根本没执行"完全无法区分。已改为按精确状态名分桶。

### 四、分布结论的新口径

- **可行率只对 PASS 图成立**；UNPROVEN 与 FAIL **均不进分子分母**，两者单列。
- `tour` 可行率 **66.7%**（20/30），`tracker-safe` **0.0%**（0/30）—— 这两个数与 WB-4 一致，未变。
- **但这两个数的含义现在被限定了**：它们只说明"规划器出不出解"，**不说明"图能不能被证明"**。

### 五、★ 已知局限（卡面必须写明，不许声称三档已完全稳定）

**`UNPROVEN_RETRY_TIMEOUT` 与负载相关，同一张图可能得到两个标签。**

实测：`n000` 在**全量 30 张并排跑**时被判 `UNPROVEN_RETRY_TIMEOUT`，
而**单独复跑两次都是 `UNPROVEN`**（提预算 198000 仍 rc=1）。
根因：`_is_retry_timeout()` 判的是「重试那一次有没有算完」，而重试会不会超时取决于
**当时的机器负载**——全量跑并排时负载远高于单跑。

**已做的缓解**：三个子档单列、不进三档 ⇒ 负载只影响"归到哪个子档"，
**不污染 PASS/UNPROVEN/FAIL 的物理含义**。
**未做**：`retry_timeout` 与"确定性"的彻底解耦（需重试时也放宽墙钟，成本较高）。
⇒ **本卡判据覆盖的是「换参数不变性」，不覆盖「墙钟不变性」。**

### 六、成本警告（别把 `--trajectory` 放进常规门禁）

实测三档分类的成本是单次校验的 **约 12~15 倍**（30 张图从 20 秒变 **40 分钟**，
因为每张不利的图都要跑一次 `--max-nodes 18000×11` 重试）。
⇒ **只在 WB-19 收口时跑一次**，结果落 `artifacts/synth_maps/SELFCHECK.json` 供后人核对；不要进常规门禁。

## 经验总结

- 现象：30 张合成图里有 15 张被判「无解」，但其中一部分不是「不可行」，而是「**未证明**不可行」——两类含义不同，原文却都用同一措辞。
- 机制：求解器的报错文本本身就分三类措辞、两种含义；一刀切记 UNPROVEN 会给已知确定性失败的图发「待定」通行证，与「不许静默通过」相反向。
- 位置：`tools/track_sweep.py` 的 `--trajectory` 三档判据。
- 处置：改用机器可判的特征（报错含 `not a proof of map infeasibility` ⇒ 才配叫 UNPROVEN）+ 换参数不变性（提高预算仍不变才允许记 UNPROVEN）；FAIL 与 UNPROVEN 分列。
- 证据：严格按判据实测：PASS 15 / UNPROVEN 3 / FAIL 5；预算敏感 4 / 采样敏感 3 / 重试超时 0。
- 落点：`docs/20_资料索引库/车端/03_规划器与自动规划.md`
