## 2 D-026 翻案三问（铁律 1 要求的作答）

**新证据（本轮五份只读审计实测，非重述旧论）**

1. **出口归零**：`config/map.yaml` 与 `route.tokens` 随 D-062 一并消失后，仿真台三条路全断——`fieldSpec()` `ok:false`、改点位/无人机档 `readFileSync` 抛 ENOENT、连 OFF 档裸跑 `sim_cli` 都 **rc=2**。D-026 暂停时，台子还能跑；现在不能。
2. **发现结构性平行实现**（当年不知道）：`sim.py` 自带一套投影/推进/吸附（`_project_sticky`/`_clamp_forward`/`_advance_anchor`，`window=0.80/1.50`、`allow_backward=True`、滞回 `_SEG_STICKY_M`），与生产 `Localization`（`window=arrival_m`、`allow_backward=False`、`_heal_stuck`、150° 方向闸）**规则与常量都不同**（`tools/sim.py:109` 自述「sim 不 import tasks/」）。这不是"UI 不好看"，是判据失真。
3. **敏感度实测为 0**：变异探针把舵角增益反号、前视钉死 3.0 m，在直线/合成夹具上 **0 条红（全漏检）**；换现场 68-token 才抓出 6 条。D-026 担心的「未校准扫参」，实际形态是「扫了也测不出东西」。
4. **16 条现场循迹翻车案例中 10 条**需要「任务状态机 × 定位噪声」同场才暴露，今天两端各缺一半 ⇒ **0 条可测**。

**影响面**：只动 `dzrobot_v2/tools/`（新增件，非冻结区）、插件现行四文件、`docs/`；两处点名例外已在 `frozen.json` 登记（`route/parser.py` 的 `_read_token_file`、`config/robot.yaml` 的一行握手键）。**`sim.py`/`sim_cli.py` 保留为 tier-0 回归基线不改** ⇒ 既有基线哈希与台账千余条历史跑次继续可比。不碰车、不碰无人机、不部署。

**不重开的代价**：下一轮循迹改动仍然只能在实车暴露，而实车窗口比开发窗口稀缺得多；且这条平行投影实现会随每次调参继续分叉——正是 D-035「价值 = import 生产控制器本尊」想防的那个坑，现在它已经在仓内发生。

**限缩而非废除**：D-026 的三条子约束（不把仿真绿当实车绿、插件显示地图 ≠ sim_cli 传入 field、未校准扫参）**全部保留并入 D-063**；被解除的只有「暂停扩建/重写」这一条，且限定为"循迹工作台"这一范围。
