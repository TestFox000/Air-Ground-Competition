### 10.2 一个必须记下的坑：**带行号锚点不能指 `artifacts/`**

第一版我把行号按 +2 归正（`artifacts/maps/sixth_20261017_map.yaml` 第 33~35 行等），anchors 立刻判 **6 条新增红**：

```
   RED  docs/20_资料索引库/赛事与治理/01_赛题规则与场地.md

```

原因在 `check_anchors.py`：

```python
DATA_SEGS = {"artifacts", "drone_recordings", "vendor", "third_party"}   # :81
```

`artifacts/` 被**故意排除**在 basename 索引之外（注释原文：basename 唯一性会把代码锚点误吸进数据目录）。所以 **任何指向 `artifacts/` 的 `路径:行号` 必然判红**，即使文件真实存在。

⇒ 处置：**改引键名，不引行号**（`barrier_row_hi` / `start` / `end` / `bridges` / `obstacles`）。键名比行号稳定——这正好是上一轮 `px_per_m_rail` 行号错位两行的同一条教训。

**还有第二条坑（本轮现踩）**：引 `artifacts/` 下的文件**必须写全路径**。
`is_data()` 让数据区文件「算存在」但**不参与 basename 兜底**，所以写成裸名（不带 `artifacts/maps/` 前缀）时：

- 直接命中失败（当前目录没有它）
- 兜底被 `DATA_SEGS` 关掉
⇒ **判红「路径全盘不存在」，哪怕文件真实存在**。

本轮卡面两次踩到（把 `artifacts/maps/sixth_20261017_map.yaml` 写成不带目录的裸名），均改全路径后转绿。
