## 4 逐项修法

### F1 布局新鲜度：心跳也算"到达"

- **机制（已证）**：`main.py:844` 对 `version <= _seen_version` 直接 return，只有新版本才在 `main.py:854` 刷新 `_layout_rx_at`；`tasks/drone.py:861` 同版心跳分支在 `tasks/drone.py:874` 返回前**不更新**黑盒时间戳（`bb.set` 只在 `drone.py:881` 新版路径）。发射器 0.5 s 心跳因此被 TTL 判据无视 ⇒ 每版间隔 12 s > TTL 10 s，必等。
- **改法（三处，最小）**：
  1. `tasks/drone.py` 心跳分支 return 前：`self.layout_ts = float(now)` + `self.bb.set(P_FIELD_LAYOUT, self.field_layout, source=self.name, ts=now)`（注释：心跳也是"到达"，内容不变）。
  2. `main.py` `_layout_is_stale()`：优先用 `self.bb.age(P_FIELD_LAYOUT)`（`core/blackboard.py:138` 的 `age`；Entry.ts 由写侧给），无 entry 时回退旧 `_layout_rx_at`；`status()["layout_age_s"]` 同步同源。
  3. `core/config.py` 注册 `step.layout_ttl_s`（默认 4.0 s，范围 0~120）与 `step.done_replay_s`（默认 1.0 s）——当前两键**不在 SCHEMA**（`config.py:541-549` 只有 wait/pose_ready/odom_watch），这是漂移没被拦住的原因之一。
- **测试**：`test_stepper.py` 新增：同版心跳 0.5 s ×5 + 时钟前进 8 s ⇒ 不 stale；停发 5 s ⇒ stale；版本递增仍清零；心跳内容变更仍拒收（现有语义不得破坏）。
- **验收**：真车 ≥3 段，`layout_stale` 等待 0 次；每段 WAIT_INFO ≤2 s。
- **回滚**：三处小改，单文件 revert；TTL 配置回 10 s。

### F2 同格空段：目标不许等于当前格（合法停站除外）

- **机制（已证）**：发射器 `emit_step.py` 的 `on_car()` 每次收到 done 都 `version += 1` 并立即 `emit()`，**不判断目标是否变化**；而车端"同格停站"是合法段（`main.py:888-900`，mine→stop 形态），于是 I7 上出现"完成→换版→目标还是 I7→再完成"的空转（7_path L511/L543，done_seq 3→4）。
- **改法（复用 `LayoutStream`，不新写）**：
  1. 机端 `emit_step.py` 改用 `LayoutStream`：`feed()` 涨 known、`note_segment_done(block)` 推进、`observe_car_block()` 跟车；**返回 None = 目标没变 ⇒ 只发心跳、不换版**（`layout.py:643-656` 现成语义）。
  2. `scout/layout.py` `_recompute_target()`（`layout.py:574`）检查点循环加一条：`cp.block == car_block` 且 `cp.kind != "end"` ⇒ 跳过（继续找下一个可达检查点）；**end 允许同格**（到终点即 FINISH）。
  3. 车端兜底：`main.py:888` 同格分支保留；若 `stop_kind in ("path","frontier")` 且同一 target 在 60 s 内重复出现 ≥2 次 ⇒ 只记 WARN、**不再递增 done**（防版本空转；合法 mine/stop 不受影响）。
- **测试**：新增 `test_scout` 用例（车在 I7 / target I7 / known 不变 ⇒ `note_segment_done` 返回 None；known 新增 E8 ⇒ 返回新目标）；`test_stepper` 同格 path 重复 ⇒ done_seq 不增。
- **验收**：≥3 段内"同格停站"≤1（且仅 mine/stop 合法形态）；done_seq 与真实移动段数一致；版本不因空段跳号。
- **回滚**：发射器旧版另存 `_tmp_session/agc-1024/s2run/`；`_recompute_target` 的 skip 条件可关（配置或常量）。

### F3 桥洞：布局是唯一真源，v1 情报只做段前改道

- **机制（已证）**：`tasks/mission.py:2316` `_maybe_enter_bridge_hold` 只看 `_intel`（v1 `bridge_passable`）+ `_cross_default`（`mission.py:2165` `_intel_of`），布局 `bridges` 只在规划期进 `main.py:490` 的 map_cfg；因此布局给 K5/K7 时，车仍按默认 K10/K4 等 12 s（7_path L170）。
- **改法**：
  1. `MissionTask` 安装步进路线时记录 `self._route_from_layout = True` 与 `route.crossing`（已有）作为**规划期真源**；
  2. `_maybe_enter_bridge_hold` 开头：`_route_from_layout` 为真 ⇒ 直接 `_reroute_at_decision(half, why="布局已定洞")` 并 return（不等待）；`_intel_of` 的 default 改用 `route.crossing[half]`（若存在）；
  3. 迟到情报规则：段**开始前**收到且与布局冲突 ⇒ 允许改道一次（沿用 `bridge_reroute_max=1`）；段开始后到达 ⇒ 忽略并记日志。
- **测试**：`test_mission` 新增：布局 bridges=[K5,K7] + 无 v1 情报 ⇒ 不发 HOLD、crossing 保持；v1 在段前给 lower=K10 ⇒ 只改一次且 `reroutes=1`；段后给 ⇒ 不改。
- **验收**：步进模式桥前等待 0 次；实际穿洞 = 布局 `bridges`；v1 情报注入不改变已发车路线。
- **回滚**：`_route_from_layout` 默认 False（旧行为），配置开关控制。

### F4 里程标定：先量后改（遵 D-029）

- **机制（已证）**：今晚 FixTask 的原始比值 1.26871、吸附被拒 11 次（隐含尺度 +8.2%~+44.8%）、ds 丢弃 2.736 m（`tasks/fix.py:349` `_ds_limit`、`:368` `_settle_ds`、`:405` 日志）。`robot.yaml:937` `ticksPerMeter: 3280.0`，10-11 那次标定留下"信念虚增 17.9%"的历史（`robot.yaml:926-935`）。D-029 明确：先 2.10 m 推车实测再决定。
- **改法（全部用现有工具，不手改数字）**：
  1. 现场：车放直道，遥控 0.10 m/s 直行 6 格（2.10 m）或 10 格（3.5 m）；卷尺量**纵向残差**（`long_residual_cm`）与横向漂移（`lat_drift_cm`），`residual_measured_by: tape`。
  2. 填 `tools/calib_backfill_template.yaml` 的 r3 段 → `python tools/calib_backfill.py --values ...` 干跑（PENDING/REFUSE 就停，别硬改）→ 看预览 → `--apply-config --apply-tests`（工具自动备份 `robot.yaml.bak_<ts>` 并重钉断言）。
  3. 若工具判 REFUSE（log 侧残差），**必须重新量尺**——吸附会抹平 log 残差（工具 docstring 已写死）。
  4. 直行复验 3 次；再做一次原地转圈（r4）只记录、不本轮回填（ticksPer2PI 另卡）。
- **验收**：直行 3.5 m 残差 ≤1 cm ×3 次；`吸附被拒` 0；`段位移不可信` 0；FixTask scale 落 0.98~1.02。
- **回滚**：工具自动备份；`git checkout -- config/robot.yaml` + 断言回滚（第二次 `--apply-tests` 前先看 diff）。

### F5 拐角：12 s/360° → 6 s/120°，大角度折点走 PIVOT

- **机制（已证）**：`mission.py:1550-1551` 读 `mission.stall_timeout_s=12`、`mission.stall_yaw_deg=360`（`config.py:361/364`）；停滞判据只按 s 不前进，累计航向到 360° 才判绕圈 ⇒ 今晚 K7 停 12.2 s/转 14°、G8 停 12.1 s/**转 183°** 仍被强跳（7_path L239/L431）。
- **改法（两步，先配置后代码）**：
  1. 配置先行：`stall_timeout_s: 12→6`、`stall_yaw_deg: 360→120`（实车定位比仿真干净，12 s 是给仿真噪声的余量）。
  2. 代码：到点后若"下一段首航向 - 当前 yaw" > 60°，在 Tracker 侧触发既有 PIVOT 三段式（`tracker.py` 现成能力，只调用不改状态机）；规划期对 >90° 折点自动标 PIVOT（复用 `:PIVOT` 声明路径）。
- **测试**：`test_mission` 停滞用例：6 s 不前进 ⇒ 跳点，且累计 120° 提前判绕圈；PIVOT 触发用例（构造 90°/120° 折点）。
- **验收**：同场地单段 0 次"拐角绕圈兜底"；逐点到点率 ≥95%；单次转角 ≤3 s。
- **回滚**：配置回滚即恢复旧行为；PIVOT 开关默认 false。

### F6 静止 yaw：WAIT_INFO >5 s 强制重锚（最小版）

- **机制**：停车等布局时 yaw 无外部修正，慢漂（今晚 22:03 静止段仍有漂移；05 §5 P6 记录 -0.0705°/s 量级的历史）。跑动中航向守卫能抓尖峰，**静止漂移它抓不到**（v≈0 时阈值反而放宽）。
- **改法（最小版，不引入 yaw_epoch）**：`WAIT_INFO`/IDLE 且 `|v|<0.01 m/s` 持续 >5 s 时，把 belief yaw 重锚到当前 IMU yaw（记事件 `stationary_reanchor`，写遥测），每 30 s 至多一次；**不重锚位置**。
- **升级路径（另卡）**：若实测仍漂，按 TRACK-YAW 阶段一结论〔失效〕做 yaw_epoch + 静态零偏（Mahony 双更新根因）。
- **验收**：WAIT_INFO 静止 10 min，yaw 漂移 <5°（或日志明确记录为"人工挪动"）；期间无 `heading_untrusted` 误报。
- **回滚**：开关 `step.stationary_reanchor`（默认 false 上线，验证后开）。

### F7 通信可见性：在线 ≠ 新鲜

- **机制（已证）**：64.3 s 内 208 条（129 布局 + 79 心跳），`car_state` 105 条、ack 78、桥洞情报 **0 条**；但车端一直显示"无人机online"（心跳判据），布局/情报的新鲜度没有同屏可见（05 §6.2/§6.3）。
- **改法**：`car_state` 与遥测增加 `layout_age_s`、`layout_ver`、`intel_count`、`ack_count`、`last_msg_type`；在线判据拆成两列（心跳在线 / 布局新鲜 / 情报新鲜）。不新增话题。
- **验收**：拔掉机端桥接 5 s ⇒ 遥测显示 layout stale、intel 计数不变；恢复后 1 s 内回绿；一次完整跑能一眼看出"只有心跳没有情报"。
- **回滚**：纯加字段（旧消费方忽略未知键），单文件 revert。

### F8 配置漂移：把两个 step 键注册进 SCHEMA

- **机制（已证）**：`main.py:637` 读 `step.layout_ttl_s`、`main.py:657` 读 `step.done_replay_s`，但 `core/config.py:541-549` 的 step.* 只有 wait/pose_ready/odom_watch ⇒ 这两个键走默认值且不在自检范围。
- **改法**：SCHEMA 补两条 Spec（默认 4.0 s / 1.0 s），`config_selfcheck` 覆盖；`test_config` 断言两键存在且范围生效。
