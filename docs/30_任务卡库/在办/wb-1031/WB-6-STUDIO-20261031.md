## 本卡自己制造并修掉的问题（captain 2026-11-01 要求：事故卡式，四行一条）

> 为什么要这页：下一个人看到「parity 从 3 FAIL 回到 21/21」会以为"改好了"，
> 而**不会知道它曾经因为什么坏过**。不记录的话，同一种错下次还会犯。

### A1 · 把「缺失」替换成「替代值」⇒ 对账从 SKIP 变假红
```
现象：插件 scripts/ 下那张 parity 台测 22/25 → 3 FAIL（首个不同下标 1：plan='N9' vs 夹具='M10'）；
      同目录那张 incremental 台测 1 FAIL（68 vs 68 但逐 token 不同）
根因：把 routeTokens() 的语义从「车端配置的路线」改成「夹具快照路线」，
      而 parity 台测里拿 routeTokens() 当**车端对账基准**。
判定：车端现役无本地路线（布局模式）是**合法空状态**；用夹具快照填这个空，
      就把「无对账对象 ⇒ SKIP」变成「拿夹具冒充车端 ⇒ 假红」。
修法：拆两个函数 — routeTokens()（车端，现役空）/ scenarioRouteTokens(s)（夹具参考线）；
      /sim/map 同时给 route（参考线）+ carRoute（车端）+ routeSource:'fixture-snapshot'。
验证：**未改任何断言**，parity 自动回 21/21、incremental 回 15/15 ⇒ 证明修的是语义不是放宽判据。
对应判据：§12.10 **L14**「缺失」不是「等于某个替代值」。
```

### A2 · 修好一处防线 ⇒ 打开一片未测区，藏在里面的第二个缺陷暴露
```
现象：插件 scripts/ 下的 intel-route 台测 FAIL「ENOENT ... config/map.yaml」；
      同目录 map-render 台测 60/61 FAIL（0 token）
根因：fieldSpec() 从恒 ok:false 变 ok:true ⇒ test-intel-route 的 if(spec.ok) 分支
      **第一次被执行** ⇒ 里面 runDroneSim → runSim → readFileSync(MAP_FILE) 抛 ENOENT。
      同根：runSimJob 的 override 分支 fs.readFileSync(MAP_FILE)（改点位/无人机协同必经）。
判定：**「因为前置缺失而跳过」的分支 = 一片未测区**；修好前置后它从"静默跳过"变"静默崩溃"。
修法：override 分支改用 fieldSpecNamed(scenario).source；mapMd5 改按场景算
      （原 md5Of(已删文件) 恒空串 ⇒ 三哈希证据失真）；sanitizeParams 加 scenario（带键才挂）。
验证：七张台测 rc 全 0（见执行报告）。
对应判据：§12.10 **L15** 降级跳过会掩盖下游缺陷。
```

### A3 · 契约守卫自己的闭合锚点选错（守卫说谎比没守卫更糟）
```
现象：STEP_COLUMNS 契约守卫报「rig=45 本模块=26」
根因：用 `\n\s*\)` 作元组闭合锚点 ⇒ 贪婪跨到后面别处的 `)`，把注释里的引号也抽成"列名"。
判定：守卫本身假绿/假红比被测对象的假绿更危险 —— 它会让人对所有守卫失去信任。
修法：闭合锚点改为「第一个 ASCII `)`」+ 去行内注释（元组内字符串不含 ASCII 右括号）。
验证：rig=26 本模块=26 逐名相同；另测出真缺陷 WB-17 插入了 pivot_phase（25→26 列）。
```

### A4 · 变异作用在不足以区分的样本上 = 伪变异
```
现象："windowS=8 与 windowS=8000" 两条断言都等于"全留"，变异测不出方向（假红）
根因：挑到的产物 run_DRIVE_steps.csv 本身只有 8 s ⇒ 两种假设给出同一结果。
判定：样本不足以区分两个假设时，变异不是判据，是摆设。
修法：按**跨度**挑产物（优先 >20 s 且列集同代），判据改成"windowS=8000 == 总行数"。
验证：windowS=8 ⇒ 4001 行 / windowS=8000 ⇒ 59100 行（= 总行数）/ 总 59100。
对应判据：§12.10 **L7** 变异与负例必须"能区分"。
```

### A5 · 植入-还原必须用独立量证明真的还原了
```
现象：变异植入后"还原"的 sha256 从 21639fe8… 变成 f0b449e3…（内容看着没变、字节变了）
根因：用 Python `open(...,'w')` 做还原，Windows 默认把 LF 转 CRLF ⇒ 行尾被改。
判定：**"回到原状"不能靠"看起来一样"**；没有独立量（sha256）就会把"还原失败"伪装成"通过"。
修法：还原后核 sha256；并按插件仓的 `.gitattributes`（其中 js 族规定 `text eol=lf`）归一为 LF。
验证：MUTATION_RESULTS.txt 逐条记 植入sha/还原sha/还原一致=YES。
对应判据：§12.10 **L10** 观测链本身也要被验证。
```
