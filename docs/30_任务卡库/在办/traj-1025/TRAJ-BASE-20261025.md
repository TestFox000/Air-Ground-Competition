### 7.4 连续轨迹接线审计（只读建议，未实施）

1. **沿程坐标不可混用**：Tracker/Localization 都写 `P_ROUTE_S`；Mission 自己用原 Path 复算 s，再同缓存做 0.12 m 一致性比对。曲线长度一变，只在 Tracker 改路径会把两个弧长单位虽同为米、语义不同的值混进同一键。所有消费者应共享同一编译轨迹，或显式转换 `trajectory_s ↔ source_segment/source_fraction`；不得把采样点序号放进 `P_ROUTE_INDEX`。
2. **原航点索引是任务主键**：重复经过同格必须按 visit/index 区分。保留 P_ROUTE 的原 Route，轨迹必须提供每个原航点对应的 `waypoint_s`、停站位置与任务标签；Mission 的 `_stop_s`、到点事件、`handled_stops`、终点长度必须同轴。`keep_progress=True` 换洞重编译后不能原样拷贝旧曲线 s，需按原航点访问身份映射。
3. **内部换向不能借用原 R 标记**：当前 `segment_is_reverse(i)` 取原 waypoint[i+1].reverse。轨迹在一个原段中插入 cusp 时，这个标记表达不了其内部分段。控制器应取当前 trajectory primitive 的方向；在 cusp 的运动游标停留至实际停稳，再切到下一 primitive，不能依赖“上一拍命令为负→投影到倒车段→继续负”的自指环。
4. **位置吸附会破坏允许偏离格心的轨迹**：Localization `_anchor/_reanchor` 当前把信念拉回原格心，并以离原折线判漂移。若新轨迹合法绕行，这会伪造位置、误判漂移。完整接线必须改用轨迹上可核验的任务锚点或在显式候选模式中关闭原格心吸附；仅仿真无噪声不能证明该问题不存在。
5. **停站需双向交接**：离线速度剖面在起点、射击点、cusp、终点为0，纯 `v(s)` 在起点或停站重启可能永远输出0；应由通用时间游标/起步剖面推进，Mission STOP/HOLD 时冻结，恢复DRIVE后重新从静止加速。不能用蠕动下限越过真正的停车约束。
6. **最终输出约束保留**：所有通用推进/等待/倒车命令都走最终 steer rate + motion_limit 出口；实测速度停稳证据不能被 `last_cmd_speed==0` 代替。原 tracker 将 `_last_cmd_speed` 保存于特殊分支覆盖之前，这个历史含义不能直接当最终执行速度。
