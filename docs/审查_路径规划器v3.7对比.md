# 路径规划器 v3.7 vs 当前 审查报告（2026-10-18）

结论先说：**不是规划器代码变弱了**。同一份地图+配置下，v3.7（a8c500b）与当前 HEAD 的规划器输出**逐 token 相同**（tour）；v3.7 的 44 点/15.05 m 只出现在**第五张图**上。当前是**第六张图**，同一套代码在第六张图上只能给出 68 点/24.85 m（tour），tracker-safe 直接无解。换回 v3.7 的 planner.py 也救不回第六张图（已实测）。

## 3. 根因：第六张图的“现场几何”撞上 tracker-safe 的硬规则

1. **下桥 K7 就在隔板相邻行（第 7 行）**。tracker-safe 的 _barrier_turn_cell 硬规则禁止在 D~N 列的隔板相邻行做 90° 转向；要从东侧进入 K7 向西穿洞，必须先在第 7 行转向 → legs0 直接为空。
   - 复现：当前代码 _ts_leg(N10→K7) 返回 0；状态 BFS 只能到 M7（M7→L7 的转向被 turn_gate 拒）。
   - 结果：plan_route_tracker_safe() 报“无解”，auto_plan 若打开只能回退。
2. **A2 是角落雷、无法“直线穿心”**：A2 在 A 列边缘，北侧 A1 被 B1 障碍堵成死胡同，西侧是场地边界；tracker-safe 要求非口袋雷必须直线穿心，A2 在这个图上无路可穿。v3.7 代码（没有 K7 那条硬规则）能到 K7，但上半场 DP 仍在 A2 处失败（单雷子问题返回 0）。
   - 证据：v3.7 _ts_phase([A2], A6, →K5) 对 4 个进入朝向全 0；A2→K5 只有“从东往西进入”才可行，而 A6→A2 的到达朝向没有东向 → 无配对。
3. **不是 t24/t32/v3.9 的代码回退**：v3.8.0、v3.9.2、pre24（t24 前）与 current 在两张图上的 tour 产物**逐 token 相同**；tracker-safe 在第六张图上也**全部同样无解**。
4. 第六张图的靶 D5+D6（纵向板）在当前射击窗口下**第二停站无解**，auto tour 只落 B4* 一个；v3.7 的第五张图同样只有 1 个自动停站，所以这不是“变弱”，而是需求（2 停站）与当前图/窗口不匹配。
5. 现场配置 planner.auto_plan_enabled=false（第六张图），所以当前实际跑的是**手写 68 点路线**；即使打开自动规划，tracker-safe 也会失败并回退。

## 4. 结论与建议

- **不要回退 planner.py**：已实测 v3.7 代码在第六张图上产物与当前完全一样（tour 68 点；tracker-safe 无解），回退只丢后续的真实修复（t24 板面法向、t32 assert、双停站等）。
- 若目标是恢复“v3.7 那种 44 点/15 m 的干净路线”，根因在**场地**：
  1. 下桥 K7 在隔板相邻行是结构性冲突；把下桥移出第 7 行（例如 K8/K9）才有机会恢复 tracker-safe（实测试验：K9 + 去掉 A2 时，tracker-safe 可出 56 点/19.25 m、0 PIVOT）。
  2. 若场地不能改：需要为第六张图做 **map-specific tracker-safe 规则/tuning**（把 A2 加入口袋雷、为 K7 的进洞转向提供受控例外，并做真车净空验证），不是盲改。
  3. 短期可接受 tour 的 68 点路线（= 当前手写路线同长），但要知道它带 3 个 PIVOT，仿真不建模 PIVOT，不能拿它做“比 v3.7 强”的结论。
- 另：v3.7.0 tag 是坏基线（import 崩），建议补一个可运行的 v3.7.1 / 或把 tag 说明写清；对比历史请用 v3.8.0（第一个修好的基线）。
