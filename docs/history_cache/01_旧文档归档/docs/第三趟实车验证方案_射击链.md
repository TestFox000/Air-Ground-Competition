### ⚠️ 三条必须当场对齐的差异（与队长的口径不一致，以**生效值**为准）

1. **扫掠范围是 ±150°，不是 ±160°**；**扫腿是 2 趟，不是 3 趟**。
   `robot.yaml:68` `scan_passes: 2`；C++ 的 `declare_parameter("scan_passes", 3)` 只是**兜底默认**，YAML 覆盖它
   （`scan_yaw_min/max_deg` 同理：C++ 兜底 ±160，YAML 生效 **±150**）。
   ⇒ 一轮 = 左一趟 + 右一趟；**由横幅的 `俯仰偏置`／`速度比` 反查不了这个值**，要直接看 `scan_passes` 那两行日志行为（见 §2.3）。
2. **巡逻速度是 30%，不是 60%**（`robot.yaml:81`，注释里 60% 已被判为太快）。
3. **两键开火当前是关闭的**：`robot.yaml:181 use_external_fire_gate: false`，`robot.yaml:182 lead_apply_gain: 0.0`。
   后果（务必在跑车前决定，**本方案不代改**）：
   - 云台**忽略** `/aim/fire_gate` 与 `/aim/fire_ready` 的许可语义，仍按**旧"画面静止"判据**开火；
   - `/aim/lead_x` 被算出并发出来，但增益 0 ⇒ **不施加提前量**，云台瞄的是**当前**位置；
   - Python 侧的 `aim.fire_policy: moving_lead`（`robot.yaml:626`，含 `lead_time_s: 0.35`）**当前不参与开火**。
   - 若要让"移动靶预测落点"生效，需把 `use_external_fire_gate` 置 true（**需重新起栈**）。这是本轮 0/10 → 有命中
     的最大单点杠杆，见 §4。

## 3. 蓝面可见性闸门的预期行为（蓝面不可见 ⇒ 留证据、不开火、继续完赛）

**设计意图**：靶只有蓝面才允许打（`robot.yaml:156 fire_only_blue: true`；`cpp:246` `cls_fire_ok`）。
蓝面朝向每场随机固定（用户 2026-10-15 事实）⇒ **本趟可能出现"整站看不到蓝面"**。

**期望行为（照着验收，别误判成故障）**：

| 阶段 | 期望现象 | 证据留存 |
|---|---|---|
| 云台找靶 | 正常 `归位→SCAN→TRACK`（§2.1 全绿） | 1.1~1.4 日志 |
| 看到靶但类别不放行 | `锁定` 后**不打**；每 1 s 一条 `诊断(不放行开火)…locked_cls=2（1=蓝 2=红）… ⇒ 类别不允许(fire_only_blue)` | **截图/抄录该行 + 时间戳**；有条件就存一帧画面（画面里红面朝向即铁证） |
| 开火 | **一条 `pub_LaserShot_Command` 都不该有**（`cpp:288`） | 无该行 = 闸门正确工作 |
| 任务层 | **不阻塞**：ACQUIRE 6 s / FIRE 30 s 走完 → `到站硬死线 30.00s（发数增量 0/10）→ 强制离站` → 继续下一点位直到终点横幅 | 5.3 日志 + 终点横幅 |
| Python 侧 | 允许出现 `不开火：类别…` 类原因（`aim.py:1025`）；**不允许**出现 `安全` 类闭锁原因 | 3.4 日志 |

**判定口径（一句话）**：**"0 发 + 有类别诊断日志 + 有 30 s 硬死线离站 + 全程无异常"= 本趟在蓝面朝向不利时属"正确的不开火"，不算射击链故障**；反之若 0 发且**没有**任何类别诊断日志，才按 §5 当故障排查。

**要如实记录的**：本趟实际打靶机会有几次、其中几次是"蓝面不可见"、几次是"蓝面可见但没打出去"。
这两个数字是下一趟调参的唯一依据。

## 4. 移动靶 0.12 m/s 下的"静止判据"：还在不在？风险在哪？

**答案：判据本身仍在，但它的通过**不代表能命中**——真正的风险是"瞄的是过去的位置"。**

### 4.1 判据还算得过来

- 现行判据（`use_external_fire_gate=false` + `fire_use_image_stable=true`）：
  `aim_stable = |vx| ≤ 1.5 px/帧 且 |vy| ≤ 1.5 px/帧`（`robot.yaml:142,143`；`cpp:206-207`）。
- 靶速 0.12 m/s，轨道标定 `px_per_m_rail: 140.0`（`robot.yaml:634`）⇒ **16.8 px/s**；
  30 fps ⇒ **0.56 px/帧** < 1.5 ⇒ **余量 2.7×，判据仍能满足**（对照：旧 4 cm/s ⇒ 0.19 px/帧，余量 8×）。
- 但余量从 8× 降到 2.7×：`vx/vy` 是**滤波后残差的单帧变化量**，滤波滞后 + 伺服抖动 + 偶发掉帧都可能把它推过 1.5。

### 4.2 真正会打飞的是**链路延迟**，不是"稳不稳"

- 链路上的固有延迟在自家文档里写得明白：`aim.py:44`「链`路延迟 0.5~0.9 s`」；
  本靶标定值 `aim.lead_time_s: 0.35`（`robot.yaml:625`）。
- 换算成像素（0.12 m/s × 140 px/m = 16.8 px/s）：

  | 延迟 | 目标已走的像素 | 与开火框半宽 3.5 px 比 |
  |---|---|---|
  | 0.35 s（lead_time_s） | **5.9 px** | 1.7 个框宽 ⇒ 偏出 |
  | 0.70 s（实测中值） | **11.8 px** | 3.4 个框宽 ⇒ 必飞 |

- 而当前 `lead_apply_gain: 0.0`（`robot.yaml:182`）⇒ **C++ 不施加提前量**，云台把瞄准点压在"目标**当前**位置"
  上（`cpp:206` 的 `aim_err_x = |dx_filt_ + lead_applied - laser_offset_x|`，`lead_applied=0`）。
  ⇒ 就算 `in_fire_zone` 成立、弹也真的发出去了，**弹着点仍系统性落后目标 5.9~11.8 px**。
- 另一条同源风险：`in_fire_zone` 用的是**当前帧**误差，不含预测；移动靶的稳态跟随误差（PD 对斜坡输入的滞后）
  也可能把误差顶在框外 ⇒ 表现为"**看着瞄得很稳，就是不开火**"。

### 4.3 建议（**只给建议值，本方案不代改任何参数**）

| 优先级 | 建议 | 理由 | 生效代价 |
|---|---|---|---|
| ★★★ | 跑车前决定是否 `use_external_fire_gate: true` | 让 AimTask 的 `fire_policy: moving_lead`（`robot.yaml:626`）接管家门：它算的就是**预测落点在框内**，天然含 `lead_time_s=0.35` | 改 YAML + **重新起栈** |
| ★★ | 若不开两键：把 `lead_apply_gain` 从 0.0 抬到 **0.5~1.0** | 让云台物理上瞄向"目标未来位置"，直接消掉 §4.2 的系统性落后 | 改 YAML + 重新起栈 |
| ★ | 用实测延迟核对 `aim.lead_time_s`（0.35）与 `px_per_m_rail`（140） | 文档自己标注"全链路最关键的未标定值"（`notes`/历史 log），标错则提前量反成新误差 | 现场 1 分钟标定 |
| — | `fire_stable_px_per_frame` 1.5 → 2.0（**仅在 4.1 的余量被吃光时**） | 放宽 2.7× 余量；但会放宽"静止"语义 | 改 YAML + 重启栈 |

> ⚠️ 纪律：以上 4 条都是**别人的参数**（`robot.yaml` 属车端配置中心）。本方案只给建议值与判据，
> **不代改**；要改请在跑车前由队长/用户按配置流程改并重新起栈。

## 5. 若 0 命中：3 步现场定位（每步 ≤2 分钟，按此顺序做，不要跳）

**Step 1（30 秒判类型）— 搜一条日志**
```bash
grep -c "pub_LaserShot_Command" <栈日志>      # 或终端回滚搜
```
- **计数 = 0** ⇒ 一发都没发出去 ⇒ 进 **Step 2**（问题在"许可/几何"）
- **计数 > 0** ⇒ 发出去了但没命中 ⇒ 进 **Step 3**（问题在"弹着/回传"）

**Step 2（分三岔，看是哪把门没开）**

| 岔 | 现场问题 | 若"否"的结论与动作 |
|---|---|---|
| 2a | 有没有 `★ 收到【开火放行】`？ | 无 ⇒ Mission 没进 FIRE：查 §2.5 停站横幅（没到站/停站被判放弃）→ **不是云台问题** |
| 2b | 有没有 `==> 自瞄状态 -> TRACK`？ | 无 ⇒ 云台没锁上：查 §2.2 覆盖率 + §2.1 的丢靶/接续计数；**典型根因=扫得太快或俯仰没压够**（本轮已改 0.30 / -10°） |
| 2c | 有 TRACK，但只有 `诊断(不放行开火)…类别不允许/类别未确认`？ | 是 ⇒ **蓝面不可见**（§3 正常行为，留证据即可）；若诊断行都没有而仍不开火 ⇒ 看 Python `不开火：<原因>`（`aim.py:1025`）取原因码 |

**Step 3（发出去了但没中）**

| 岔 | 现场问题 | 动作 |
|---|---|---|
| 3a | `/shoot_count` 与裁判 `[3] 硬件发数` 是否同步增长？ | 不同步 ⇒ 硬件/激光链路（查 `LaserShot_Command` 是否被 dzactuator 消费）——**不是视觉问题** |
| 3b | 裁判 HP `[0]` 有没有下降？ | 有增长无下降 ⇒ **弹着偏移**：按 §4.3 处理提前量/`lead_time_s`/`px_per_m_rail` |
| 3c | 一条 `裁判回传：…` 都没有？ | 命中闭环**无数据**（`referee.py:10`）⇒ 先修裁判链路，否则永远无法判定命中 |
