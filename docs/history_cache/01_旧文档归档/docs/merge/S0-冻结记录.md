> ⚠️ **判据陷阱 2（PowerShell 中文路径，本轮实际踩到）**：
> `Get-Content ... | ConvertFrom-Json` 拿到的 `file:D:/…/比赛存档/…` 路径，再喂给 `Test-Path` 会**返回 False**，
> 于是在状态快照里打出 `src=MISSING files=0`，看起来像「依赖源没了」。
> **实际依赖完好**（机侧 98 文件 / 车侧 115 文件，`pnpm list` 正常识别）。
>
> 正确写法（本项目所有涉及中文路径的检查一律用这个）：
> ```powershell
> $raw = [System.IO.File]::ReadAllText($p, [System.Text.UTF8Encoding]::new($false))
> $m = [regex]::Matches($raw, '"dsh-dz\w+-ssh"\s*:\s*"file:([^"]+)"')
> foreach ($x in $m) { Test-Path ($x.Groups[1].Value -replace '/','\') }
> ```
> **根因**：`ConvertFrom-Json` 在某些代码页下对 UTF-8 中文的往返不保真；`[System.IO.File]::ReadAllText` + 显式 UTF8 编码则稳定。
> **教训**：这条误报和 §7.2 的子串误报是同一类——**判据写法本身会造假红/假绿**。凡「路径/文本是否相等」的检查，都要先问一句：这个比法会不会被编码或子串骗过？
