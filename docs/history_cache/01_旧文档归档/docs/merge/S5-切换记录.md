## 阶段一事故与回退（2026-10-18 16:2x，已回退）

用户实机反馈「状态浮窗插件几乎报废，什么都看不到」。取证（`~\.dsh\dzairground-ssh\diag.jsonl` 77 行）：

| 证据 | 含义 |
|---|---|
| `tool.float open:true` 后无任何渲染成功记录 | 浮窗打开了但画不出东西 |
| `terminal` 连接超时 4514ms、`tool.external coord ok:false` | 面板工具链多点失败 |
| 一小时内 **67 次 `client.load`** | 用户反复刷新自救 |

**根因：三包并存的客户端全局冲突**（路由层不冲突，但浏览器全局层冲突）：

1. 新包与旧车包 **64 个 CSS 类同名**（`.dzr_float`/`.dzr_fcell`/`.dzr_root`…）而定义已不同（S2/S3 浮窗改 5 格布局）→ 后加载覆盖先加载 → 旧包浮窗按新包结构渲染，错位/空白；
2. 两包都向 **`shell.overlay` 同名注册**浮窗卡片（`client.js:3135` `name:'shell.overlay'`）→ 同名座位互相顶掉。

阶段一「路由前缀不同即可并存」的判断**只验证了服务端层，漏了客户端 CSS/overlay 座位层**——与「验证对象≠运行对象」同类教训：并存冲突面必须按**每一层**枚举（路由/DOM id/CSS 类/全局座位/事件命名空间）。
