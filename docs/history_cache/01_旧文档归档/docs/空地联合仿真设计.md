## 1. U 形航线几何（航点序列）

49 个航点（全在格心连线上，总长 18.55 m，0.5 m/s = **37.1 s 侦察耗时**）：

```
N8 → M8 → L8 → K8                                     （起飞，与小车下半场同向）
K8 → K9 → K10 → K11                                   （K 列侦察腿·南向：2.45 s 内揭示 K9/K10/K11）
K11 → K10 → K9 → K8 → K7 → K6 → K5 → K4 → K3 → K2 → K1（K 列侦察腿·北向全列：K5 于 8.4 s、K1 于 9.45 s 揭示）
K1 → K2 → K3 → K4 → K5 → K6 → K7 → K8 → K9 → J9 → I9 → H9 → G9 → F9 → E9 → D9 → C9 → B9 → A9（下半场西向腿，行 9）
A9 → A8 → A7 → A6 → A5 → A4 → A3                     （西侧北向腿，沿 A 列）
A3 → B3 → C3 → D3 → E3 → F3 → G3 → H3 → I3 → J3 → K3 → L3 → M3 → M2（上半场东向腿，行 3 → 降落 M2）
```

设计要点（逐条有覆盖证据，见 §2）：

1. **U 形与小车同向**：下半场西向（N8→A9，行 9）、上半场东向（A3→M2，行 3），开口朝东。
2. **侦察腿南向先行**：入口格随机落在 K7~K11，其中 K11 离 K8 有 1.05 m（超出 2.5 格半径）——
   南向先行把 K11 的揭示时刻从 ~11.9 s（北向先行版）压缩到 **2.45 s**，直接决定"车到桥前等待"
   的最坏等待（自检 25 项里钉住 K11 ≤3.6 s）。
3. **下半场腿取行 9**：2.5 格半径覆盖行 7~11 → 下半场全部关键格（雷 D8/F9/I10/E11、障 B7/C9/E10/G11、
   靶 B11/C11、入口 K7~K11）——行 10 腿会漏 B7（3 行偏移 1.05 m）。
4. **上半场腿取行 3**：覆盖行 1~5 → 上半场全部关键格（雷 B1/G2/H3/A4、障 D1/F4/A5/H5、出口 K1~K6；
   K6 距行 3 有 1.05 m，由侦察腿北向段在 7.7 s 揭示）。
5. ⑤ 桥顶箭头 = YOLO 垫片：进入揭示圆即读到（K10 箭头 t=2.45 s、K5 箭头 t=8.4 s），
   不再需要旧口径"正下方 2.0~2.5 m 贴桥直飞"——侦察腿保留是为**快速确认全部 K 格通口**（每场随机）。

## 3. 延迟/丢包注入口径（dzlink 契约）

- 载荷逐条由 t2 协议构造（`dzsmartscout/tools/perception/protocol.py` **只读 import**）：
  `bridge_passable`（half/block/confidence）、`target_zone`、`field_verify`、`heartbeat` 1 Hz；
  空表不发（车侧会记 missing_fields）；未知类型不新增（车侧忽略）——箭头 H1 只进台账。
- 链路模型（`link.py`）：每报文 `recv = send + 起飞延迟 + 0.06 s + U(0, 0.02 s)`，独立同分布
  Bernoulli 丢包（A3 臂 drop=0.5）；**单发布者 FIFO**（BEST_EFFORT 真实语义）→ 不建模乱序。
- 车侧采纳门 = t6 `BridgeIntel` 镜像（`car_gate.py`，逐条 file:line）：no_link → offline（心跳超 3 s）
  → missing → stale（>30 s）→ rejected（列/行段/候选池三道校验）→ drone；桥洞情报**周期性重发
  每 5 s**（协议 README 的续期手段，丢包自愈证据见 A3：drop=0.5 下关键格缺口仍为 0）。

## 4. K 列侦察腿设计（桥洞每场随机 → 侦察是"必需"而非"校验"）

## 5. 车侧任务流（现车代码 vs 改进变体）

**现车代码事实**（镜像自 `tasks/mission.py`，file:line 出处见 `car_gate.py` 头注释）：
① 只在发车窗口（`mission.bridge_info_wait_s=2.0`）等情报，**执行中 token 永不改**；
② 采纳门第③道校验 = 情报格 ∈ `route.cross_*_candidates ∩ map.bridges`（mission.py:1391-1410）；
③ 规划器同样要求穿洞格在池内（planner.py:2159-2164）⇒ **桥洞每场随机后地图必过期，
现车代码在任何候选配置下都无法采纳与地图矛盾的无人机情报**（B2 证据：理想情报 K9 被
rejected → 车按默认 K10 直冲封死桥室，5.92 s 中断）。
**改进变体**（本包建模，台账显式标注非现车行为）：`authority_gate`（情报格只过列/行段两道校验，
规划器池 ∪ 情报格）+ `wait_at_bridge`（L10 桥前等两半场情报新鲜，齐后一次重规划覆盖两处穿洞，
上限 `wait_cap_s`）。

## 6. 双面移动靶模型（④）

- 面板 0.14 m 宽沿 0.7 m 轨道 0.1 m/s 三角波振荡（半行程 ±0.28 m、周期 11.2 s）；
  停站点候选 A10/B10/C10/D10（全在现役/重规划路线上；A11/D11 不在路线上 = 已知局限）；
  视角 θ(A10/B10/C10/D10) = +56.3°/+26.6°/−26.6°/−56.3°。
- 逐发按**命中时**车→靶连线扇区判（10 发 × 0.5 s 间隔，面板在动 → 每发有效性独立）；
  提前量 0.35 s × 0.1 m/s = 3.5 cm ≪ 面板宽 → 本几何下提前量不绑定命中（结论进报告）。
- 扇区敏感度（±30/±45/±60 × 朝向 0/±90/180）：
  φ=0 → B10/C10（±30 可打）；φ=+90 → 仅 A10（需 ≥±45）；φ=−90 → 仅 D10（需 ≥±45）；
  φ=180（蓝面贴墙）→ **场内无解**（0 发、驻留吃满 30 s，记为已知不可解场景）。
- 判读误差（受限臂旋钮）：+180°（蓝红翻转）→ 选点落在真红面侧 → 10 发红面命中 = 扣分账（B5/B6）。

## 10. 改进建议清单（≥5 条，每条带仿真证据）

1. **【mission/planner】打开"无人机权威"采纳通道**（最高优先）。现车采纳门第③道校验
   （候选∩地图桥洞）与 planner.py:2159-2164 的池校验使无人机**无法纠正过期地图**——
   B2 证据：理想情报 K9 被 rejected，车按默认 K10 直冲封死桥室 5.92 s 中断；
   桥洞每场随机（③）后地图必过期。改法：情报格只过 列/行段 两道校验；规划器对显式
   穿洞格放宽池校验（池 ∪ 情报格）。仿真验证：B3 同场景改后完赛 148.14 s、改道 1 次、全指标绿。
2. **【mission】把"等情报"从发车窗口移到桥前决策点**。mission.bridge_info_wait_s=2.0 窗口内

   5.92 s 直撞中断）。

   未采到 → 只换入口 → 上半场 136.9 s 撞 K5 封死。改法：上半场桥前（I5）再取一次出口情报

4. **【planner/route】把"预计揭示时刻"与路线长度一起纳入规划与速度档**。3 分钟预算下

   （185.48 s）；25% 场次预算不过。改法：抽到长路线组合时自动升巡航档（0.25~0.40 m/s），

   前置到 M10，或决策点前用"只朝当前航点"的投影约束（s_floor 语义已有，前视段切换加门）。

   φ=+90 需 A10、φ=−90 需 D10（±45 扇区下可行，±30 下 φ=±90 无解——扇区敏感度表）；

   A10/B10/C10/D10 按判读选点；判读置信度低 → 不开火（宁 0 发驻留 30 s 不扣分）。
7. **【drone/protocol】桥顶箭头 H1 结论进协议做双源交叉验证**。⑤ H1（箭头贴哪半场 = 通行格）

8. **【mission】贴墙不可打场景跳过射击点**。φ=180（蓝面贴墙）判读可知 → 0 发也吃满 30 s

## 11. 仿真局限清单（如实标注）

1. **PIVOT 不建模**（sim.py:109-113 刻意不做，`pivot_*` 恒 no-op）——凡涉及折返/PIVOT 的结论
   标"仿真无法裁决"，需实车/闭环 bench 验（本仿真全路线 0 折返，无此项依赖）。
2. **射击/驻留/云台不建模**：run_sim 无停站驻留；射击账由解析模型给出（命中确定性、无弹道
   散布、面板相位锚定 ±2 s 不确定）——B/C 世界红蓝命中数为模型口径而非实弹口径。
3. **车侧任务流是镜像**（`car_gate.py`，file:line 出处），不 import `dzbrain.tasks.mission`
   运行时状态机；改道变体（权威门/桥前等待）**非现车行为**，台账显式标注。
4. **改道 splice 伪影**：轨迹时间轴把桥前等待折叠掉（总时长 = commit+drive+wait+dwell 相加）；
   决策点前 ~0.4 m 存在预转向差（§10-5，0.5 s 量级）。
5. **2D 投影**：飞行高度 1.5 m 无几何效应（仅记录）；感知圆连续采样（帧率 ≫ dt）。
6. **链路**：单发布者 FIFO（BEST_EFFORT 真实语义）→ 不建模乱序；延迟 0.06+jitter、丢包 Bernoulli。
7. **多场次统计的行驶时长**用 6.883 s/m 标定估计（MV1~3 全仿真验证偏差 ≤0.9%）；L10 决策时刻
   用基线轨迹值（±0.5 s，见 §10-5）。
8. **换洞后路线的 route_check/validate_route 门禁未跑**（三连/重规划形状的 R009 等规则校验
   不在本仿真范围）——"换洞路线是否过车侧门禁"上交车侧复核（仿真无法裁决）。
9. 感知退化（模糊/噪声/分辨率）不在本联合仿真内建模（t2 已单独特征化：12 cm 雷与 0.20 m 箭头
   最先退化）——本仿真默认理想感知，受限要素只注入 晚到/丢包/判读翻转。
