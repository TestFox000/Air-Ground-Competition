# 实车基线执行任务

**R1 已完成并经独立离线复核，当前派工入口为 [35_R1验收与R2实车派工](35_R1验收与R2实车派工.md)。** 本文是该任务的现场操作与采样细则；按实际车端版本取得普通短段数据。R0 的限速缺陷结论和 R1 的离线修补证据均保留。

先取得普通循迹的短直线、单弯和停车数据，不必等历史 13 套红项全部清零。第一次现场卡不调算法、不改标定；下一卡依据这批证据选一个变量，再在同一路线、同一速度、同一初态复跑。

本地 `TRACK-R1-20261020-01` 已离线收口，tracker.py 冻结登记仍保留。车端安装状态须现场核验，一组重复跑中不切版本。若补丁已由人完成部署，则建立修补版基线；否则使用已核验旧版取得普通分支数据，两者不混算。现有部署工具无单文件推送能力，具体限制和处置见35文。

## 1 首批试跑与决策

| 顺序 | 实际做什么 | 得到什么 |
|---|---|---|
| F0 现场准备 | 确认实物布置、运行模式/版本/配置、唯一命令来源；核验现场物理停机手段与软件接管 | 一份真实生效的试验配置和可用的停车流程 |
| F1 静止 30 秒 | 车轮落地、车身不动、不搬车，持续采样 | 能否信任当前定位/航向；与此前架空日志区分 |
| F2 短直线 | 净空区约 1–1.4 m，候选 0.10 m/s；一次起步和人工接管停车，再同条件重复 2 次 | 真实位移、横偏、命令响应、停车距离；不是完整路线完赛 |
| F3 普通单弯 | F2 无异常后，选择不跨洞、不倒车、不含 PIVOT/ALIGN 的一个 90° 弯；同配置重复 2 次 | 内切/外摆、航向响应、定位连续性；不为了凑左右弯临时绕过门禁 |
| F4 回报停止 | 按下表选出最早出现且有证据的限制因素 | 下一卡唯一假设、对应代码/参数及复跑场景 |

0.10 m/s 是本次建议的诊断档，不是已证明的实车速度。若已有经验证的更低档，使用该档。预先写明速度上限、试跑边界和停车余量；从实际发布命令及外部位移核验，而非只读 YAML。若初始化就发现信号异常，仍完成静止记录，运动分支停止并回报；不强求把整个矩阵跑完。

| 实车证据 | 下一卡方向 |
|---|---|
| 车身静止而 yaw/位置漂移，或消息跳变/丢失 | 查 IMU、时间戳、坐标变换及定位链；不放宽安全阈值 |
| 真实直线距离与吸附前定位距离不符 | 查里程尺度、航向积分、打滑；先定位原因再改标定 |
| 吸附前轨迹合理，修正后突然跳点或提前判到达 | 查锚定/吸附/到达判据 |
| 命令正确而车体延迟、方向或转角明显不符 | 查底盘执行映射、串口、机械响应 |
| 信号与执行可靠，单弯仍反复摆动/切角 | 只调整一个循迹参数；前视、弯速等候选由误差形态选择 |
| 路线自身压障碍、净空不足或规划无解 | 先处理路线几何/规划问题，不用循迹参数补偿坏路线 |

第一批回报后再决定是否修标定、调前视或修状态机。单弯稳定后才逐步加入桥洞、换向和整条赛道；含 PIVOT/ALIGN 的整圈验收前，先完成已知最终限速缺陷修补、回归与人工部署。这个修补不阻塞普通分支短段数据的获取。
