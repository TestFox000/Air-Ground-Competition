### 当前部署入口的实际限制

`tools/deploy_to_car.py` 的 `push` 固定推送整棵 `src/dzbrain`、云台文件、`config/robot.yaml` 和工具；目录会整棵替换。`--packages dzbrain` **只限制构建包，不限制推送文件**。没有 `--files` 或保留配置的参数。车端配置与本地不同，不能把 `all --packages dzbrain` 当作“只上 R1”。地图未列入推送清单，也不等于其他现役文件不会变化。

本卡不执行整包部署、不手工 scp 绕过入口。需要部署 R1 时，另立部署能力小卡，在原工具上补文件范围选择、范围备份/对账及失败传播，再由现场人执行。它与普通短段采样可分开推进，不要求先完成才取得现场数据。

现有只读诊断入口（在车仓执行，保存输出和退出码）：

```powershell
Set-Location 'D:\User\Desktop\比赛存档\v1\dzrobot_v2'
python -B -X utf8 tools/deploy_to_car.py probe --ip duzhong.local
python -B -X utf8 tools/deploy_to_car.py verify --ip duzhong.local
```

`verify` 只检查包入口等，不能替代实际 Tracker 哈希、运行进程和构建产物核验。现有 `build` 的 `colcon | tail` 不能只凭最终 exit 0 判构建成功；单独 `push` 也不会自动先备份。具体证据见 [部署审查](../../_tmp_session/TRACK-R1-REVIEW-20261020/deployment_review.md)。
