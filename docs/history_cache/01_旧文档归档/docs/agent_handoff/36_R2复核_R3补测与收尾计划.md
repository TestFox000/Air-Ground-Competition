### 0.1 共享接口：先用现有格式，补清证据

不新建消息总线/协议或另一套地图。复用既有Config、地图、路线token、bag/CSV和RUN_CARD，每份产出必须带以下来源：

- **身份包**：run_id、源码/实际import路径与hash、实际配置解析值与hash、地图hash/布局版本、起始位姿与时间锚。配置写了某引擎不等于执行过它。
- **路线包**：原始token/hash、起终点/首段方向、生成入口与实际引擎、PIVOT/倒车/停站等已有语义、route_check原始输出；短测不适用的赛规项单列，物理碰撞不能豁免。
- **观测包**：指令、raw定位、belief、外部测量分列，注明坐标系/单位/时钟/误差；不把弧度、角度、格坐标、米混用，不改变生产协议。
- **判定包**：支持/不支持的场景、有效/无效样本、命令及退出码、关键输出、尚未解释的证据、下一步唯一变量。没有外测就写〔未〕，模型未建模就写unsupported，不能记PASS。

交接顺序：先保留一份实际发出的源码基线 → B/D/E各自在副本开发；与此同时主线A/C/F用当前已有工具核验净空、停车和短路线，不等待外组包。现场证据如需给外组，按run_id和输入hash补发副本。交回后由F逐包核对、合并、复测；同一组实车试验不换运行版本。

每名成员接卡只回报“收到的baseline_id、负责文件、输入缺口、首个交付时间”即可按范围开工，不等待主目录实时登记或其他组响应。冻结登记在自己的副本中完成，改回主副本时由F合并对应登记项；不得用旧管理文件覆盖主副本的新记录。

### 0.3 仿真台保留什么、暂停什么

已核当前插件与内核：`dsh-plugin-dzrobot-ssh/src/simbench.js`会设置ROBOT_MAP并调用sim_cli；但`sim_cli.py:182`未把field传入run_sim。**页面画出地图，不能说明这次执行仿真检查了该地图的碰撞。** `sim.py:108–112`明确不建模PIVOT，`:1209–1213`直接运行compute_command，不执行生产Tracker/ALIGN/R1最终限速/Safety闭环。

- 今晚保留：现有route_check/车身几何预筛、显式field的普通PP仿真、已有真实Tracker单元/契约回归。它们分层报告，不能拼成“整车仿真通过”。
- D模块第一交付是输入和覆盖矩阵；如修地图入口，必须让输出可核验地图身份、field_modeled=1、场景初态与不支持模式，并用同图一条已知违规/一条合法场景验证诊断有效。复用既有加载器及足迹判据，不新建碰撞器。
- 获得有效实车数据后，先用一趟标定尺度/转向响应/延迟等必要模型参数，再用另一趟未参与拟合的数据验证；冻结控制参数，只改模型的一项假设。不能用同一趟既拟合又证明预测成功，也不把相关性当底盘标定完成。
- 暂停：界面扩建、第二套控制器/仿真器、未校准大范围扫参、重复旧64图、以仿真排名直接改车。若模型连误差方向/舵角饱和时段都解释不了，暂停用它选控制参数，保留确定性的路线检查。

通用可靠性的目标是：在声明的地图结构、速度、初始偏差和测量误差范围内，路线可执行、信号可信、循迹稳定、遇异常能停车；复用既有PP、投影连续性、速度约束、状态机及Safety。后续按直线→左右弯/多弯→特殊分支→段接续/整路线扩展，再用留出路线检验，不能由某一张地图一圈成功推及所有地图。

C. 试跑顺序：
C0：低速短行程做1次人工接管停车，外部实测从接管到停稳的时间/距离；按该值和场地误差留停车余量。此趟不计自然FINISH验收。

E. 判断和停点：
本卡验收的是数据有效性与重复性，不能预设“外摆≤0.13m且FINISH≤5°”就算整车通过；按36文第5节预登记现场净空和下一层性能要求。所有自然FINISH均记录真实停点及航向，不把日志标签当实物到位，也不立即加航向门。

### 6.5 交回的“好东西”具体是什么

可以继续用文件夹/zip传递，无需先搭Git协作平台。每组交一个**改动包**，不是整个修改后项目覆盖主副本：

```text
交回包/
  REPORT.md           目标、基线、改了什么、测试命令/退出码、未解决项
  CHANGESET.json      相对路径、add/modify/delete、before_sha256、after_sha256
  before/             修改/删除文件的原始内容，保持项目相对目录
  after/              新增/修改后的文件，保持项目相对目录
  evidence/           测试输出、必要失败案例及输入身份
  management_notes.md 本地卡/冻结登记/索引等管理变化，主Lead择项登记
```

CHANGESET还需注明baseline_id、模块、负责人、依赖的其他包（无则写无）、测试所针对的最终内容；新增项before为空，删除项after为空。删除只列清单，不夹带自动清理脚本；改名按删除+新增或明确rename记录。生成清单后若再改文件，重新生成hash与测试证据。可附diff/patch方便审阅，但before/after已足够处理不使用Git的情况。

主DeepSeek逐文件处理：

| 当前主副本与交回项的关系 | 怎么做 |
|---|---|
| 当前hash=before，交回after校验匹配 | 备份当前文件后应用该项，再复测 |
| 当前hash=after | 已有该内容，跳过重复应用 |
| 当前和after都不同于before | 用before原件、当前文件、交回after做三方比较；合并双方需要的改动，不后到覆盖先到 |
| 新增但主副本已有同名文件；或删除对象已被主副本修改 | 当冲突处理，不覆盖/删除；已不存在的删除项记为已满足 |
| 缺原始基线、hash不符、越出任务写域、绝对路径/..、清单与文件不一致 | 暂缓该项，列明缺口；其余不依赖项可继续审查，不猜测基线 |

每包先审再合、主副本重跑相关测试和门禁，记录最终组合hash；上一包验收后再进下一包，按依赖顺序（无依赖则按风险/就绪程度）集成。为每批保留合入前原件、该批diff和删除/新增清单，回退只逆转该批。组员的TEAM_STATUS/frozen.json/目录索引/AGENTS等管理文件不整份复制回来。不要把外组新旧主线混合成同一实车组，最终部署仍由人执行。
