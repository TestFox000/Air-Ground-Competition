## 1. 系统边界

### 1.1 谁在哪跑

```
┌───────────────────────────── Jetson Orin Nano（dzsmart）─────────────────────────────┐
│  感知：livox_ros_driver2 → FAST-LIO(fastlio_mapping + 3 个 python)                      │
│  桥1：px4_odom_convert  → /fmu/in/vehicle_visual_odometry（外部视觉）                   │
│  桥2：px4_imu_bridge    ← /fmu/out/sensor_combined（PX4 IMU 回灌 ROS）                  │
│  控制：px4_control_node（Offboard 心跳/解锁/起降/Goto 闸门）+ px4_teleop_node（键盘）    │
│  路径：px4_path（path_record_node 或 path_follow_node，二选一）                          │
│  跨机：dzlink_pc2_bridge（点云→小车）、dzlink_supervisor / dz_send_waypoint（航点→小车） │
│  代理：MicroXRCEAgent（uXRCE-DDS Agent，串口 /dev/ttyACM0 @921600）                      │
└───────────────────────────────────────┬─────────────────────────────────────────────┘
                                        │ USB CDC（ttyACM0）
┌───────────────────────────────────────▼─────────────────────────────────────────────┐
│  PX4 飞控板（Matek HKUST UAV NxtPX4）：PX4 固件 + uxrce_dds_client + EKF2/控制律       │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

**关键边界**：机载电脑**没有** PX4 固件。PX4 跑在飞控板上，机载只是"外脑"（定位 + 坐标桥 + Offboard 指令）。所以**飞控板不在 = 所有 `/fmu/*` 不存在 = 控制层只能空转**。

### 1.2 四条链路（判断"我卡在哪一步"）

| # | 链路 | 组成 | 与飞控板的关系 | 本轮状态 |
|---|---|---|---|---|
| ① | 感知定位 | Livox → FAST-LIO → `/Odometry`（→ `/localization`） | 无关，可单独跑 | ⛔ 未启动 |
| ② | 飞控通信 | 飞控板 ⇄ MicroXRCEAgent → `/fmu/*` | **强依赖** | ❌ 会话死 |
| ③ | 飞控行为 | Offboard 心跳 → 解锁 → 起飞 → 悬停 → Goto 跟随 | 依赖 ② | 未验证 |
| ④ | 跨机协同 | 机 → `/nav/waypoint`、`/dzlink/drone_to_car`（JSON）→ 小车 | 无关 | 未运行（且域号不一致，见 §6） |

**①②③ 全通才能飞；④ 独立。** 这是排障时最省时间的结构性认知。

### 2.3 QoS 契约（跨机/跨进程最容易炸的地方）

| 话题 | 类型 | 发布者 QoS | 订阅者 QoS | 备注 |
|---|---|---|---|---|
| `/fmu/out/vehicle_local_position` | `px4_msgs/VehicleLocalPosition` | 由 uXRCE 代理代表 PX4 创建（默认 reliable） | `px4_control`/`px4_path`：`KeepLast(5)` **best_effort** | best_effort 订阅 reliable 发布**兼容**；反过来不兼容 |
| `/fmu/out/vehicle_status` | `px4_msgs/VehicleStatus` | 同上 | `KeepLast(5)` best_effort | 判解锁/Offboard 用 |
| `/fmu/in/vehicle_visual_odometry` | `px4_msgs/VehicleOdometry` | `SensorDataQoS`（best_effort, depth 5） | Agent | 42~44 Hz |
| `/fmu/in/offboard_control_mode` `/fmu/in/trajectory_setpoint` `/fmu/in/vehicle_command` | 对应 px4_msgs | 默认 reliable，depth 10 | Agent | 心跳 20 Hz |
| `/px4_control/goto_enabled` | `std_msgs/Bool` | `QoS(1).reliable().transient_local()` | 同上 | **锁存**：晚订阅也能拿到当前值，别改 |
| `/px4_control/command` `/px4_control/goto` | 自定义 msg | 默认 reliable depth 10 | 默认 reliable depth 10 | — |
| `/Odometry` | `nav_msgs/Odometry` | depth 20（reliable） | `px4_odom_convert`/`path_record`：`SensorDataQoS` | 订阅端 best_effort 可收 |
| `/localization` | `nav_msgs/Odometry` | `transform_fusion.py`（rclpy 默认 reliable depth 10） | `SensorDataQoS` | 只在 `transform_fusion` 活着时存在 |
| `/livox/lidar` | `livox_ros_driver2/CustomMsg` | reliable，depth 64（单雷达 32×2，`lddc.cpp:653`） | FAST-LIO `QoS(20)` | **不能改 xfer_format** |
| `/livox/imu` | `sensor_msgs/Imu` | reliable，depth 64 | FAST-LIO `SensorDataQoS.keep_last(500)` | 200 Hz |
| `/fmu/out/imu_data` | `sensor_msgs/Imu` | `SensorDataQoS` | 无（预留） | 目前机上没有消费者 |
| `/path_record/visualization` | `nav_msgs/Path` | `QoS(1)` reliable transient_local | RViz | 记录过程可视化 |
| `/livox/points` | `sensor_msgs/PointCloud2` | `KeepLast(10)` reliable volatile（`dzlink_pc2_bridge`） | 小车/其他 | 由 `CustomMsg` 转换而来 |
| `/dzlink/seq` | `std_msgs/Int64` | 同上，50 Hz | 小车 | 序号用于丢帧检测 |

> **QoS 静默失败**：订阅端要求 reliable 而发布端是 best_effort（或 durability 不匹配）时，**连接建立不了且不报错**。改任何一个话题的 QoS 前先查这张表。

### 2.4 `px4_control` 行为要点

- **状态机**：`DISARMED → ARMING → TAKEOFF → HOVER → LANDING → LANDED`（`px4_control_node.cpp:121-143`）。Offboard 丢失且未落地 → 回 `DISARMED`（`:235-245`）。
- **Offboard 闸门**：`heartbeat_before_offboard=20`（1 s @20 Hz）未满拒绝切模式（`:336-340`）。
- **ARM 条件**：离地/位置无效都拒绝（`:349-365`）；`takeoff_height=0.5 m`。
- **Goto 闸门**：只有 `HOVER` 且 `local_pos_valid_` 时按 `4` 才置 `goto_enabled=true`（`:159-167`）；按 `5` 关闸并把当前位置固化为悬停点。**Goto 使能期间 WASDQE/LR 被屏蔽**（`:438`、`:455`）。
- **Goto 超时**：`pursuit_goto_timeout=1.0 s` 没收到 `active=true` 目标 → 关闸（`:581`）。
- **降落**：`land_control=false` 用自管下降（触地判据 `land_touch_z=0.05`），P.X4 确认 disarmed 后才进 `LANDED`。

### 2.5 `px4_path` 双模式

| 维度 | 录制 | 跟随 |
|---|---|---|
| 选择方式 | `config/params.yaml` 的 `px4_path_launch.record_mode`（**不是** launch 参数） | 同左，`false` 时启动 `path_follow_node` |
| 输入 | `/localization`（`path_record_node.slam_topic`） | `/fmu/out/vehicle_local_position` + `goto_enabled` |
| 输出 | 文件 `<path_dir>/<output_file>`，每行 `x y z qx qy qz qw`（SLAM 原始坐标） | `/px4_control/goto`（`pursuit_rate` 20 Hz） |
| 落盘时机 | **析构时**（Ctrl+C/SIGTERM）；`kill -9` 丢整段 | — |
| 安全 | 跳变 > `max_neighbor_dist_m=5.0` 丢弃；`min_points>=2` | 跟踪误差 > `max_tracking_error_m` 中止；终端容差 `terminal_tol` |

跟随内部再分 `follow_mode`：

- `waypoint`：离散点，`switch_tol` 推进，`max_step_dist` 限单步；速度/加速度/yawspeed 前馈恒 0。
- `trajectory`：曲率感知 + 动力学受限（`max_speed_mps/max_accel_mps2/max_jerk_mps3`），支持急转弯分段（`segment_split_turn_deg`）、跟踪误差减速/暂停、`yaw_mode`=fixed/recorded/tangent。

> ⚠️ 机端 `params.yaml` 现为 `record_mode: true`、`path_file = output_file = recorded_path.txt`；本地仓库副本是 `record_mode: false`、`path_file: recorded_path_2.txt`（契约不一致，见 §8）。

### 2.6 `px4_odom_convert`（机端已加加固层，必须知道）

代码默认 `source_mode=odom`，但 **launch 默认 `mode=localization`**（`launch/px4_odom_convert.launch.py:35`）。三种模式：

| 模式 | 输入 | 频率 |
|---|---|---|
| `odom` | `/Odometry` | 跟输入（43~45 Hz） |
| `localization` | `/localization` | 跟输入（实测 44 Hz） |
| `tf` | `map → lidar` TF | 50 Hz 轮询，仅时间戳变化才发 |

坐标：位置 ENU→NED、姿态 ROS→PX4、角速度 FLU→FRD；`z_offset_m` 三模式通用。

机端 v2（**本地仓库没有**，2026-10-17 17:12~17:16 打的补丁）额外行为：

| 机制 | 参数（默认） | 作用 |
|---|---|---|
| 双实例拒绝 | — | 启动时 `count_publishers("/fmu/in/vehicle_visual_odometry")>0` → `FATAL: DUPLICATE INSTANCE` 并退出 |
| 自动对齐 | `enable_auto_align=true`、`align_yaw_to_ekf=false` | 首帧把 SLAM 系对齐 EKF 系（或用 `reset_counter` bump 让 EKF 重锚） |
| 跳变防护 | `slam_insane_m=2.0`、`slam_recover_n=86`、`slam_recover_m=0.1` | 大跳变 hold/锁定/确认恢复 |
| EKF 风暴熔断 | `ekf_storm_window_s=60`、`ekf_storm_max_resets=5` | 60 s 内 >5 次 reset 即熔断 |
| 节流 bump | `bump_min_interval_s=10` | 抑制频繁 reset |
| 健康行 | — | 每 3 s 打 `[px4_odom_convert_health] ... slam_hz=… hold_ratio=…` |

### 2.7 `px4_imu_bridge`

`/fmu/out/sensor_combined` → `/fmu/out/imu_data`（`sensor_msgs/Imu`），`SensorDataQoS` 两端一致；`convert_frd_to_flu=true`；`timing_log_period_ms=1000` 打转换耗时。**当前机上没有订阅者**，属于预留链路（飞控 IMU 回灌给 ROS 用）。

### 3.2 阶段 B：飞控链路

```bash

udevadm info -q property -n /dev/ttyACM0 | grep ID_MODEL   # ID_MODEL=HKUST_UAV_NxtPX4
```

### 3.3 阶段 C：验证（判据见 uXRCE 手册）

```bash
ros2 topic info -v /fmu/out/vehicle_local_position   # Publisher count 必须 >=1；=0 就是会话没建
ros2 topic hz /fmu/in/vehicle_visual_odometry        # 期望 42~44 Hz
```

> ⚠️ **不要再用 `ros2 topic list | grep fmu` 判断链路**：看门狗自己订阅 `/fmu/out/vehicle_local_position`，即使 0 个发布者，这个话题**也会出现在列表里**（本轮实测）。

### 3.4 阶段 D：控制层（有执行能力，人在座再做）


按键：`0` Offboard · `1` ARM+起飞 · `2` DISARM · `3` LAND · `WASD/QE` 平移 · `L/R` yaw · `4` 使能 Goto · `5` 撤销 Goto 并保持 · `Ctrl+C` 退出。

## 6. ROS_DOMAIN_ID 一致性审计（本轮重点）

### 6.1 结论（先纠正一个流传的说法）

**机上没有任何一处把域号设成 118。** 依据：

- `grep -n DOMAIN ~/.bashrc` → 无命中；`~/.profile` 无；
- `~/start_drone.sh` 第 20-21 行只 source ROS 与 `~/dzpx4/install`，**无 `export ROS_DOMAIN_ID`**；
- `~/dzuav_deploy/air_ground/tools/autostart_agup.sh` 第 24-25 行同样只 source，**无域号**；
- `crontab -l` 只有一行 `@reboot … autostart_agup.sh start`；
- `systemctl list-unit-files` 里与 ROS/无人机相关只有 `tigervncserver@.service`（VNC），**没有 ROS 服务**；
- `~/.bash_history` 中 `ROS_DOMAIN_ID` 出现次数 = **0**（说明操作者从没手动 export 过）；
- 唯一 `118` 在 `~/dzlink_tools/dzlink.env`，被 `dzlink_supervisor.py` 在 import 阶段读取并 `os.environ` 覆盖（`dzlink_supervisor.py:157-209`），`dz_send_waypoint.py` 同源。

> **作废旧说法**：旧 `tools/reports/t4-链路验证报告.md` 称"无人机交互式 shell 的 118 来自 `~/.bashrc:126`"。2026-10-17 实测：该 `.bashrc` 里**没有** `ROS_DOMAIN_ID`（只有 fishros 加的 `source /opt/ros/humble/setup.bash`），`~/.bash_history` 里也从未 export 过。**118 只活在 `dzlink.env`，交互式终端默认是 0。**

所以真实拓扑是：**机侧全栈 = 域 0；小车 = 域 118**。实测对照：

| 域 | `ros2 node list` / `topic list` 结果 |
|---|---|
| 0（默认） | 节点只有 `/fmu_agent_watchdog`；话题只有 `/fmu/out/vehicle_local_position`、`/parameter_events`、`/rosout` |
