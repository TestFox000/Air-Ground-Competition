## 4. 飞控四包逐包审查

### 4.1 `px4_control`（1 002 行）

**职责**：Offboard 心跳、解锁/起飞/悬停/降落、外部 Goto 闸门、TrajectorySetpoint 下发。

**状态机**：`DISARMED → ARMING → TAKEOFF → HOVER → LANDING → LANDED`（`:119-143`），落地由 PX4 的 `arming_state==STANDBY` 确认（`:214-227`）。离开 Offboard 时回 `DISARMED` 并关 Goto（`:235-246`）。

**闸门**：
- Offboard 需要 `heartbeat_before_offboard=20`（1 s @20 Hz）攒满（`:336-340`）；
- ARM 需要 `is_on_ground` + `is_offboard` + 位置有效（`:355-367`），起飞目标 `z=-takeoff_height`（NED，`:372`）；
- Goto 只允许 `HOVER` 且位置有效时按 `4` 打开（`:468-484`）；`pursuit_goto_timeout=1.0 s` 超时会自动关闸（`:579-586`）。

**发现**：

1. **文档与实现矛盾（P1）**：`handle_land` 注释写"Never touches velocity setpoints"（`:413-416`），但 `publish_trajectory_setpoint` 在 `LANDING && !land_control_` 时下发了 `{NaN,NaN,descent_vz}` 的 z 速度（`:514-522`）——与 R-07 同一类"位置+速度前馈"问题，自主降落时可能比注释意图更快。
2. **Goto 静默丢弃（P2）**：未使能/非 HOVER 时 `on_goto` 直接 `return`，无任何日志（`:293-299`），现场"按了 4 但目标没进来"时难定位（R-21 未修）。
3. **降落无超时兜底（P1）**：自管下降依赖 PX4 land detector + 自动 disarm，若 land detector 不触发会一直下发目标直到电量/人工介入（R-10 未修）。
4. 锁存闸门是安全核心：`goto_enabled` 用 `transient_local`，跟随节点晚启动也会立刻收到 `true`（这是 R-05 自动起飞的根因）。

### 4.2 `px4_path`（2 498 行）

**双模式**：`record_mode` 决定启动 `path_record_node` 或 `path_follow_node`；跟随再按 `follow_mode` 选 `waypoint`/`trajectory`（`launch/px4_path.launch.py` 读 YAML）。

**发现**：

1. **文件契约断裂（P1，本地仍存在）**：`path_file: recorded_path_2.txt`（`config/params.yaml:25`）vs `output_file: recorded_path.txt`（`:119`）——录了新路径，跟随时读的却是另一个文件。机端 10-17 已手工对齐（两处都是 `recorded_path.txt`），本地仓库未同步（补丁 02 未应用）。
2. **录制输入依赖 `/localization`**（`:103` `slam_topic: /localization`）：机端 10-17 起三个 python 节点可活（open3d/tf_transformations 已装），但若只跑 FAST-LIO（`/Odometry`）则录制静默无点。建议默认改 `/Odometry` 或显式报错。
3. **前馈矛盾（P1）**：waypoint 模式发 `v=a=yawspeed=0`（`:184-191`）而控制节点把 0 当真实前馈（`px4_control_node.cpp:523-543`）；控制节点自己在非追踪分支特意用 NaN（`:505-509`）。**两份代码对同一物理量采用相反语义**。
4. **自动开飞（P1）**：`activate_if_ready()` 在收到锁存的 `goto_enabled=true` + 第一帧位置有效时**直接开始跟随**（`path_follow_trajectory_node.cpp:393-403, 430-448`），没有"人工再次确认"的显式 start 闸门（补丁 03 未应用）。
5. **参数边界部分修复**：`1000.0 / std::max(1.0, pursuit_rate_)`（`path_follow_waypoint_node.cpp:40`）挡住了 0/NaN 周期，但 `pursuit_rate=1000` 仍会 1 ms 定时器；无上下限校验（R-13 部分关闭）。
6. **死代码仍在**：`CMakeLists.txt:73` `if(EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/path)`——实际目录是 `src/path`，条件恒假（R-22 未修）。
7. 两个 follow 节点约 150 行重复（状态名/距离/回调），建议抽 `PathFollowBase`（R-19）。

### 4.3 `px4_odom_convert`（1 035 行，v2 加固版）

**新增能力（相对旧版）**：

| 机制 | 关键行 | 说明 |
|---|---|---|
| 启动防双实例 | `:61-75` | 话题已有 publisher → `FATAL` 抛异常退出 |
| 运行期双实例/双 SLAM 监测 | `:183-209` | 10 s 一次 `count_publishers`，只告警不退出 |
| 自动对齐 | `:536-590` | 30 帧（约 0.7 s）后 `ev_reset_counter 0→1`，让 EKF 重锚；可选 yaw 对齐 |
| z 轴换源 | `:592-599` | EKF z 有效时用 EKF z 覆盖 SLAM z（"关闭 EV-z 融合"，高度交给气压计） |
| Jump guard v2 | `:601-823` | L1 insane 熔断（>2 m 或 >1.6 rad）、86 帧稳定恢复、armed 永不接受、L2 bump 10 s 节流、L3 EKF reset 风暴熔断（60 s >5 次） |
| 健康行 | `:400-450` | 3 s 一条 `[px4_odom_convert_health] … slam_hz=… hold_ratio=…` |
| blackbox | `:350-398` | 事件行（L1/L2/L3/ALIGN），便于事后归因 |

**发现**：

1. **z 换源与 jump guard 耦合（P1，新发现）**：z 在 `:597-599` 被 EKF 覆盖，随后 gate 用**含 z 的三维距离**判定（`:626-630, 727-731, 750`）。若 EKF z 阶跃 > `jump_hold_m_`(0.5 m)，`gate_dp` 持续超限；armed 时 `confirmed` 恒 false（`:755-756`），输出**永久 hold** 在旧位姿（`:806`），x/y 外部视觉同时被冻结，EKF 只能靠 IMU/气压计外推。EKF z 阶跃的典型来源：气压计重锚、`z_reset_counter` 变化（代码**没有**监听 z reset counter，只监听 xy/heading，`:269-271`）。
   - 建议：把 z 换源移到 gate 之后；或 gate 只用水平距离 + yaw，z 单独限幅/平滑；或监听 `z_reset_counter` 并在复位后跳过一帧。
2. **"幽灵参数"仍在（P2）**：launch 仍传 `max_position_jump_m`/`max_attitude_jump_rad`（`launch/px4_odom_convert.launch.py:18-19`），而节点从未声明它们；真正的新阈值（`slam_insane_m`/`slam_recover_*`）反而**没暴露到 launch**，且 `jump_hold_m_=0.5`/`jump_yaw_rad_=0.8`/`jump_confirm_n_=8` 硬编码在头文件（`include/px4_odom_convert.hpp:148-150`）。现场调参只能改代码重编。
3. **健康行 `slam_cov_trace` 可能是恒 0（P3）**：FAST-LIO 的 Odometry 协方差未必填充（`:483-488`），若为 0 则 `cov_max` 指标无意义；需要现场确认。
4. **质量恒 100（P3）**：`vio.quality=100` 恒定（`:881`），PX4 侧若按 quality 加权则无区分度。
5. **z 换源时 `position_variance[2]` 仍写 0.01/100（P3）**：z 已无信息量，方差却给小值，语义上不一致（实际 PX4 对 EV z 的融合由 `EKF2_EV_CTRL` 决定）。
6. 正向：L1/L2/L3 的注释把 10-16/10-17 的实测数据写进了代码（26~585 m 跳变、reset 每秒+1），可追溯性好。
