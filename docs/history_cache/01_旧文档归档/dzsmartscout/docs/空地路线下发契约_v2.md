## 0. 一句话架构（谁算、谁守门）

```
感知(无人机相机/雷达) ──► 无人机侧规划器(单源码同步自 dzbrain) ──► /nav/waypoint ──► 小车执行
                                     │                                                   │
                                     └──► /dzlink/drone_to_car(情报/心跳) ──────────────►┘
                                                                         车侧回传 car_state/ack
```

* **无人机 = 主脑**：把"场地地图 → 路线 token 串"这件事放在机上算（本卡打通）。
* **小车 = 执行 + 守门回退**：没有外部路线或外部情报时，车用**自己的板载规划**（`planner.auto_plan_enabled=true`，失败再回退 `mission_blocks` 落盘 **44 点**，即 `route.tokens` 别名；"手工 62 点"是历史口径）**照样完赛**（见 §7）。

## 1. QoS 与话题契约（**线对线，写错=静默丢**）

| 通道 | 话题 | 类型 | QoS（车侧真值，`contract.py`） | 方向 | 用途 |
|---|---|---|---|---|---|
| **A · 路线** | `/nav/waypoint` | `std_msgs/String` | **RELIABLE** / KEEP_LAST(10) / VOLATILE | 机 → 车 | 裸文本 token（路线 / `reset:` / `load:`） |
| **B · 情报** | `/dzlink/drone_to_car` | `std_msgs/String`(JSON) | **BEST_EFFORT** / KEEP_LAST(10) / VOLATILE | 机 → 车 | `heartbeat` / `bridge_passable` / `target_zone` / `field_verify` |
| **C · 回传** | `/dzlink/car_to_drone` | `std_msgs/String`(JSON) | **BEST_EFFORT** / KEEP_LAST(10) / VOLATILE | 车 → 机 | `car_state`（1~2 Hz）、`ack{of:<seq>}` |

**兼容性铁律**（t4 真机 8 格矩阵实测）：
- `RELIABLE 发 → BEST_EFFORT 收` = 兼容；**`BEST_EFFORT 发 → RELIABLE 收` = 不兼容，静默 0 条**。
- 不兼容时**两端"发现层"仍各显示对端 1 个端点** ⇒ **不能用 `ros2 topic info` 的计数判断"通"**，只能看**实收**。
- 订阅端会打一行 `New publisher discovered … offering incompatible QoS`，但只在订阅端进程日志里（重定向后基本看不见）。
- VOLATILE 无补发：首包必丢一（实测 39/40）⇒ **情报必须周期性重发**（机侧 supervisor 已做：每条 3 遍 + bridge 每 2 s）。

## 3. 路线 payload 契约（A 通道）

* **格式**：`std_msgs/String`，**裸文本 token 串**（不要 JSON 包装）。分隔符：空格 / 分号 / 竖线。
* **token 语法**（真源 `dzbrain/route/parser.py` + `validate.py`）：

| 写法 | 含义 |
|---|---|
| `N10` | 航点（列字母 A–N + 行号 1–11） |
| `G10*` | 该点**停车打靶**（`*` 后缀） |
| `N5,y` / `N5,x` | 朝向后缀，**只允许挂最后一个 token** |
| `R:F11` | `R:` 前缀 = 该段**倒车**（真车 `allow_reverse=false` ⇒ 规划器默认**不发** `R:`） |
| `K9:PIVOT` | 180° 折返声明（`allow_reverse=false` 时用以声明折返点） |
| `reset:N10,y` | 复位信念位姿 + 清路线 → IDLE |
| `load:文件名` | 读车侧路径文件并出发 |
| `SHOOT@G11` | 指令非坐标：车侧算候选链整链插入 |

* ★★ **引擎必须先对齐**（本卡收口轮实锤）：`tools/plan_route.py` 的 `--engine` **默认是 `tour`**，
  而实车自动规划入口 `tasks/mission.py:906 plan_route_from_config` 是**从 config 读** `planner.engine`
  （第五张图 = **`tracker-safe`**，`robot.yaml:586`）⇒ 走 `plan_route_tracker_safe()`。
  **两种引擎产出两条不同路线**（40 vs **44** token）且**都能过 route_check** ——
  不显式传 `--engine` 就会踩"机算 40 / 车跑 44"的静默错位。规划/下发一律**从 config 读引擎**。
* **本卡实测的"官方第五张图"整线（44 token，`tracker-safe`，双侧对拍 + 与板载 `mission_blocks` 逐 token 一致）**：
  ```
  N10 M10 M9 L9 K9 J9 J10 I10 H10 G10 F10 E10 E9 D9 C9 B9 B8 B7 B6 A6 A5 A4 A3 A2 B2 B1 C1 D1 D2 D3* E3 F3 G3* G4 G5 G6 H6 I6 I5 J5 K5 L5 M5 N5,y
  ```
  `route_check`：**0 error / 1 warn**（warn = 急转弯提示级；`:PIVOT` 声明 0 处，`allow_reverse=false` 下 90° 由循迹层完成）。
  > 对照（**不要用于实车**）：`--engine tour`（工具默认）→ 40 token
  > `N10 N9 M9 L9 K9 I9 I10 H10 G10 E10 E9 D9 C9 C7 B7 A7 A6 A5 A4 A3 A2 B2 B1 C1 D1 D3* E3 F3 G3 G4 G5 H5 H6 I6 J6 J5 K5 L5 M5 N5,y`，同样过 route_check。
* **下发前门禁（必须）**：`tools/plan_route.py --emit tokens --engine <config 里的引擎> --check`（内部子进程调用 `tools/route_check.py`，**0 error 才放行**）。
* **重复发送**：路线本身 RELIABLE 且**下发即生效**（车收到就会重排/出发），机侧 supervisor 默认 `x3`。
  ⚠️ 不要与车上的第二写者同跑：`~/dzrobot/src/car_localization/start_path_executor.sh:35`、`send_waypoint.py:20`。

## 4. 赛前整线下发（推荐主用法）

**时序（以车侧 `robot.yaml` 为唯一真值，发车前请现场 `grep` 确认）**

| 键 | 本卡快照值（`robot.yaml` sha256 `d824d1fba6df0f966a51…`，2026-10-17 16:46 工作区快照） | 含义 |
|---|---|---|
| `mission.auto_start` | `true` | 一键启动后自动出发 |
| `mission.auto_start_delay_s` | **`10.0`** | 起栈后 **10 s** 发车（⚠️ 本快照是 10.0；更早的 t16 快照是 45.0 —— **以现场文件为准**） |
| `mission.bridge_info_wait_s` | `2.0` | 等桥洞情报窗口；**只管「两半场相隔 ≤2 s 到达」**，超时那半场只进遥测 |
| `drone.info_stale_s` | `30.0` | 情报 30 s 过期 ⇒ 当"无情报" |
| `drone.heartbeat_timeout_s` | `3.0` | 3 s 无心跳判无人机离线（★ 车侧真名；`drone.heartbeat_offline_s` 是**死键**，机侧代码/文档里那份写法不生效） |

**流程**

1. **车起栈前**（越早越好）：机侧把**整线**备好（本轮实测 `tracker-safe` **44 token**；**引擎必须从 config 读**）。
2. 若还要发桥洞/靶区/雷障情报：**在车起栈前**就写入 supervisor 的 `--cmd-file`（`bridge_info_wait` 只有 2 s，不能指望发车后抢窗口）。
3. 起机侧常驻：`python3 ~/dzlink_tools/dzlink_supervisor.py run --cmd-file ~/dzlink_tools/cmd.jsonl --route "<整线>"`。
4. 起车栈（`./start_all.sh start`）→ 车侧横幅出现 `ROS_DOMAIN_ID=118` → 10 s 后自动出发（或按 `auto_start=false` 等指令）。
5. **判据**：机侧日志里 `/nav/waypoint` 的「订阅者匹配数 ≥1」；车侧日志出现路线解析/`任务开始`；车侧 1~2 Hz `car_state` 出现在机侧 `listen`。

## 5. 行驶中换线语义（谁触发 / 如何确认 / 失败怎么办）

| 项 | 口径 |
|---|---|
| **谁触发** | ① 机侧感知决策（桥顶箭头/雷障变化 → supervisor 的 `--cmd-file` 追一条 `{"type":"route","data":"…"}`）；② 人工（机上 `dz_send_waypoint.py route "…"`）。**两者不要同时常驻**（同一话题双写） |
| **下发内容** | 新**整线**（不是增量）；或用 `reset:N10,y` 先复位再发新线 |
| **车侧语义** | `mission.py:3060 take_waypoint_commands()` 消费 `/nav/waypoint`；已发车后收到新路线**会按新路线重排**（旧路线作废）；`reset:` 回 IDLE |
| **如何确认** | ⚠️ **`/nav/waypoint` 目前没有 ACK**。车侧的 `ack{of:seq}` 只覆盖 **B 通道情报**（`drone.py:241 _maybe_ack` 只在 `drone_in` 回调里调用）。所以路线的可用确认手段是：**(a)** 发布端 `get_subscription_count() ≥ 1`（发送器会打印「订阅者匹配数」）；**(b)** RELIABLE QoS 的 DDS 层送达；**(c)** 车侧日志（`~/robot_logs/7_path.log`）与 **`car_state.phase`** 变化（1~2 Hz，间接）。 |
| **换线确认缺口** | 想要"路线级 ACK"，需要**车侧**在 `on_waypoint` 里回一条 `{"type":"route_ack",…}` 到 `/dzlink/car_to_drone` —— 属车侧改动，**本卡不做**，列为建议（§8-③）。 |
| **失败回退** | 车侧**不会因为外部路线没来而停摆**：`planner.auto_plan_enabled=true` ⇒ 用板载 tracker-safe 自规划；失败（`PlannerError`/超时/坏图）⇒ `planner.fallback_to_tokens=true` ⇒ 回退 `route.tokens`/`mission_blocks`（现役 **44 点**；"手工 62 点"是历史口径）⇒ **仍出发**。见 §7。 |
| **反转/倒车** | `planner.allow_reverse=false`（真车底盘不支持倒车）⇒ 外部整线也应是 **0 段 `R:`**，180° 折返用 `:PIVOT` 声明。本卡 44 token 实测：`R:` 0 段、`:PIVOT` 声明 0 处（无 180° 折返）。 |

* 真源**永远**是 `dzrobot_v2/src/dzbrain/{core,route}` + `dzrobot_v2/tools/{plan_route,route_check,shoot_planner}.py` + `dzrobot_v2/config/{map,robot}.yaml`。

## 7. 小车回退路径（⑤：无人机主脑 + 小车守门回退）

```
外部路线(/nav/waypoint) 到达？──是──► 按外部路线执行
        │否
        ▼
planner.auto_plan_enabled = true ──► 车上 tracker-safe 自规划（只吃 config/map.yaml）
        │ 失败/超时/坏图（PlannerError）
        ▼
planner.fallback_to_tokens = true ──► 回退 route.tokens / mission_blocks（现役 44 点；62 点为历史口径）
        │
        ▼
仍出发（车侧守门：宁可自己跑，也不因为"无人机没来"停摆）
```
* 桥洞情报缺失时的兜底：`route.cross_lower_default="K9"` / `cross_upper_default="K5"`（第五张图现役真值，`robot.yaml`；`map.yaml` `bridges:["K5","K9"]`）。
  ⚠️ 机侧 `dzlink_supervisor.py` 里仍硬编码旧口径 `bridge_default_lower="K10"`（v4 审计 F-04，**机侧代码待修**；本条只纠正文档口径，未改代码）。
* ⇒ **指挥链路是"增强"而不是"必需"**：无人机挂了，车仍能按板载规划+默认穿洞格完赛（降级设计）。
