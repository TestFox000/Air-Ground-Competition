### 1.2 路线 token 语法（`follow_route_command` :1049-1246）

| 写法 | 含义 |
|---|---|
| `K7` | 普通途经点 |
| `R:K7` | **倒车到位**（车头朝向不变倒着退，非掉头） |
| `G10*` | **射击点**（到点停车开火） |
| `:SHOOT_STOP` / `:SCAN_STOP` | 停站标记 |
| `SHOOT@<靶>` | 自动选最佳射击点（:1087） |
| `M10,y` | 带朝向（`,x` / `,y`） |

处理链：`SHOOT@`展开 → `R:`解析 → 停站标记 → `*`标记 → 合法性 → 去重（R 标记不同不合并）→ 末点朝向 → 轴向接近段 → 逐点朝向回填四元数 → 装载 + 建 `shoot_groups`（:1225）。

### 1.3 主循环 `control_loop`（:1943-2530）优先级顺序

1. 无 odom → return（:1948）
2. `_update_chassis_speed()`（:1953）
3. **射击停站等待** `shoot_wait`（:1972-2131）
4. **扫描停站等待** `scan_wait`（:2138-2155）
5. 无路径 → **仍发零 Twist 保活**（:2160-2164）★否则 dzactuator 会切走 Pursuit 模式
6. 几何：`find_nearest_segment` → 回写 `current_target_idx` → `find_lookahead_point`
7. 扫描停站检测（:2183-2198）
8. 射击停站检测（:2203-2221，含过冲补触发）
9. **终点到达**（:2223-2301）：`arrived=True` **latch 永不再动**
10. **急弯 PIVOT**（:2303-2406）：转角>45° 且距顶点<0.25m → 停+满舵 → 保持 0.5s → 蠕行至航向误差<15°
11. **桥洞强制直行**（:2408-2442）：关纯追踪，用 `yaw_err*12/10` 限幅 ±8°，0.10 m/s 直冲
12. **普通纯追踪**（:2444-2530）：→ 越界急停 → 终点前限速 → 射击点前限速 → 急弯前限速 → 发布

**"推进下一点"没有显式 idx++**：每 tick 用 `find_nearest_segment` 从当前 idx 起**只向前搜**最近航段并回写 idx（:1573、:2172），天然实现"走过即推进、不回锁已走过段"。

### 1.4 打靶四段状态机（:1968-1971）

| 段 | 行为 | 退出条件 |
|---|---|---|
| **0 SETTLE** | 等 `chassis_speed < 0.02` 连续 0.8s | 满足进 1；兜底 `cand_t > 0.4*SHOOT_TIMEOUT` 也进 1 |
| **1 ACQUIRE** | 等视觉 `det_cls != 0 且 det_age < 1s` | 有靶进 2；扫满 `SHOOT_SCAN_ROUNDS=2` 轮无靶放弃；18s 超时 |
| **2 STABLE** | 连续 5 帧 `|dx|,|dy| ≤ 40px` 且静止 | 进 3；6s 超时**降级**进 3 |
| **3 FIRE** | 发 `stop_signal=1` 放行开火 | 等 `shoot_count - 到达时快照 >= 10` |

- 打满后**取消同组其余候选点**（:2095-2107）
- 兜底：硬超时 30s（yaml）/ 找靶 18s / 等稳定 6s —— 原则"**宁可漏打，不可卡死**"（:1962）
- 阶段 1 刻意**不再发 scan_request=1**（:1996-2004 注释）：会把云台持续扫描降级成单次，反而限制找靶。现在"停车归循迹、找靶归云台"双线程。

### 1.5 与云台/底盘的接口语义

| 话题 | 值 | 含义 |
|---|---|---|
| `/nav/scan_request` | 0 / 1 / 2 | 停 / 单次全向扫描 / **持续扫描** |
| `/aim/status` | 0/1/2 | IDLE / SCAN / TRACK |
| `/move_base/stop_signal` | 0/1 | 收回 / **放行开火** ★不是 voice_switch |
| `/pursuitAngle` | Twist | `linear.x`=m/s；`angular.z`=**舵角(度)**，有效 ±35° |
| `/nav/motion_state` | 0/1 | 前进 / 倒车 |

- `mission_scan_mode=continuous` → 全程发 `2`，`scan_flags` 全清（:1387）→ **全程不停车**，只在 `*` 射击点停。

### 1.6 关键坑（务必记住）

1. **频率**：`create_timer(0.02)` = **50 Hz**，但注释（:47、:1935-1941、:2522）多处写"20Hz/50ms"——注释错，按 50Hz。
2. **相位编号**：注释（:215-222）写三段，代码实为**四段 0/1/2/3**。
3. **单位**：`/odom/localization` 是**格单位**，`×0.35` 得米（:1540-1541）；原始 yaw 需 **+90°** 才是地图系（:123、:1549）。
4. **信念位姿 snap**（:689-701、:1540-1551）：到点后把信念位姿直接拉到格心，只改 `snap_*_off`，漂移不跨段累积。
5. **桥洞保护按航段索引而非几何距离**（:1864-1871）：否则会在 K 列附近任何位置误触发，表现为"循迹僵直"。保护区间 `[h-2, h+1]`；align 期间**禁止 PIVOT**。
6. **必须持续发零 Twist**（:1958-1960、:2160-2164、:2238）：QoS depth=1 BEST_EFFORT，停发超 1s 底盘看门狗会接管。
7. **`angular.z` 是舵角度不是角速度**，底盘侧 `+60` 后 clamp `[25,95]`；`linear.x` 经 `×23/0.33` 转 0~255 字节。
8. **yaml 与代码默认值不一致的关键项**：`shoot_stable_frames` 5(代码8)、`shoot_stable_offset_px` 40(25)、`shoot_timeout` 30(20)、`shoot_distance_target` 0.35(0.30)、`bridge_blocks` 整列 K1~K11(代码`['K7','K1']`)。**按 yaml 为准**。
9. `SHOOT_WAIT_TIMEOUT=150.0`（:633）已废弃；`bridge_order`（yaml:218-220）代码**完全不读**。
10. 注释中标注"无实车依据"的项：`REVERSE_STEER_SIGN`（:193-195）、`FINISH_VOICE_ID`（:182-184）。

## 2. 定位：`serial_reader.py`（271 行）

**注意：本节点不打开任何串口**——名字是历史遗留。`/odom`、`/imu_data` 实际由底盘 `dzactuator` 发布。

| 代码块 | 行 | 说明 |
|---|---|---|
| 订阅 | :96-105 | `/odom`(Odometry) 、`/imu_data`(Imu)、`/nav/waypoint`(String) |
| 发布 | :107-108 | `/odom/localization`(Odometry) |
| `imu_callback` | :146-154 | 首帧 raw_yaw 作基准，之后存**相对航向** `imu_yaw_rel` |
| `waypoint_callback` | :156-187 | **只处理 `reset:BLOCK,HEAD`**：重锚航向 `dr_yaw_off += target_yaw - cur` |
| `odom_callback` | :189-255 | 核心：航位推算 |

**核心算法（:218-223）**：raw 位姿的旋转框架与物理世界不符，但**相邻样本间的欧氏距离是旋转无关且准确的**。故：
```
step = 相邻原始位姿欧氏距离
if step >= MIN_STEP_M(0.0005): 沿 map_yaw = yaw_rel + dr_yaw_off 积分
```
- 航向：IMU 新鲜(<2.0s)用 IMU，否则回退 odom 四元数（:197-210）
- 输出 `position.x/y = dr_*_m / BLOCK_SIZE` → **单位是"格"**（:227-234）
- 四元数只写 heading（:238-242），刻意保留 `+90°` 约定交给 path_executor
- **位置不在这里重锚**（:100-103 注释）：位置锚定交给 path_executor 的 snap，避免两节点互纠

**坑**：
- launch 跑的是 **install 后的副本**，改源码不 `colcon build --symlink-install` 会跑旧代码；靠 `NODE_VERSION="v4-dr-reset"`（:59）日志标签识别版本。
- `dr_yaw_off` 初值 `pi/2` **假设开机车头朝 Y+**（:126-135），开机后被转动必须发 `reset:`。
- `localization.launch.py:6-9` 硬约束：**不要同时运行其它发布 `/odom/localization` 的节点**。

### 3.6 坑（重要）

1. **多目标时取的是"分数最低"的那个**：循环直接覆盖（:242-259），而 NMS 后是分数**降序**（`postprocess.cc:41-42`）→ 最后一个（最低分）胜出。**疑似 bug**，想取最高分应取 `dets[0]`。
2. **流水线固定延迟 ≈ thread_num 帧**（4 帧 ≈ 133ms）：`put` FIFO 入队、`get` 取队首（`rknnPool.hpp:91-111`）。
3. **前 4 帧完全不发布**（:234、:240）；热加载后 `frames_` 归零又静默 4 帧。
4. **`max_fps` 设 >30 无效**（周期被钳到 33ms，:67）。
5. **`draw=true` 时必须有 DISPLAY**，否则 imshow 异常；窗口名 `"src"`。
6. 相机 `brightness` 曾设 50 导致过曝、颜色特征崩掉 → 保持 0（yaml:165-166）。
7. `robot_color` 参数**已移除**（`launch/det_node.launch.py:8-10`：代码从未 declare，ROS 2 静默丢弃，是摆设）。
8. 按 `q` 会 `rclcpp::shutdown()` 结束进程（:266-269）。

### 4.2 状态机

```
enum AimState {AIM_IDLE=0, AIM_SCAN=1, AIM_TRACK=2}   (h:101)
```
| 转换 | 触发点 | 条件 |
|---|---|---|
| → TRACK | `callback_offset_center` **cpp:49** | 收到合格目标（cls∈{1,2} 且长宽比 OK）且未在 TRACK |
| → SCAN | `startScan()` **cpp:567** | `scan_request≥1`、目标脱离、视觉静默、一轮扫完继续 |
| → IDLE | `callback_scan_request` **cpp:585** | `data==0` |
| 开机 | 构造 **cpp:972-973** | **强制 `AIM_SCAN` + `continuous=true`（上电即扫）** |

- 已 TRACK 时 `scan_request` 直接 return（:577-580）；已 SCAN 时**只更新 continuous 标志，不重置进度**（:590-596）。
- 主循环频率：TRACK 100Hz，其余 50Hz（:1096）。

### 4.3 扫描逻辑

- **连续匀速左右往复**（`scan_yaw_dirs=8` 仅兼容保留，不参与计算）。
- 范围 **±90°**（=正前方 180°），1 层俯仰（`scan_pitch_levels:[0.0]`），俯仰偏移 **−26°**（下压）。
- 速度 `patrolSpeed = 3700 × 0.35 = 1295 刻度/s`。
- 推进（:648-696）：驻留 ≥300ms → 到位判定(|反馈−目标|≤30 刻度) → **超时兜底** `timeout = max(dwell×3, traverse×1.5)`（注释强调必须大于匀速扫完整个行程的时间，否则半路误判提前反向）。
- `advanceScanIndex`（:669）：立即反向 → `pass_done++` → 每 2 趟换层 → 满 `passes×levels` 判一轮结束。
- **一轮结束后**：continuous=true → 清零重来并打印 `==> 一轮扫描结束未发现目标，继续扫描`（**cpp:683 —— 就是日志里看到的那条**）；否则回 IDLE 打印"全向扫描结束，未发现目标"（:688-689）。
- IDLE 不是"不动"：主动归位到 yaw 中点（:634-645）。

### 4.4 跟踪与开火（`callback_offset_center` :24-304）

**云台增量计算**
```
EMA:      f += 0.55*(raw - f)                        (:79-80)
死区:     eff = |f|>4 ? f∓4 : 0    (死区内完全不动)   (:83-93)
预判:     vx = dx_filt_ - dx_prev_filt_               (:97-100)
前馈:     ff_x = -ωz*57.2958*11.378*dt*gyro_ff_gain   (:106-119)  ← gain=0 默认关闭
俯仰:     pitch_inc = -(eff_y/2 + vy*0.5)             (:128-131)   ★负号是关键
水平:     inc_x = eff_x/2 + vx*0.5 + ff_x             (:135-139)   ★eff_x==0 也要算(前馈)
PD速度:   Speed = Kp*err + Kd*Δ   (精调档 Kp×0.5,Kd×2.0) (:143-148, 433-465)
```
- **轴映射陷阱**：`Position_0`=**俯仰**，`Position_1`=**偏航**。
- 刻度：`center=2047`，`11.378 ticks/deg`(=4096/360)；硬件限 yaw 100-3995、pitch 950-2400。

**开火判据**（:210-213）
```
开火 = in_fire_zone && aim_ready && ammo_ok && cooldown_ok && target_confirmed
       且 fire_hold_count_ >= 5
```
- `in_fire_zone`：`|dx_filt - laser_offset| ≤ fire_dz` 且 y 同理（:173-175）
- `fire_dz` **动态**：框宽 `[30,120]` 线性映射到 `[14,26]` px（:469-493）
- `aim_ready`：默认用**画面稳定判据** `|v| ≤ 1.5 px/帧`（:164-170）→ **移动中也能开火**
- `ammo_ok`：`shots_fired_ < 10` && `shots_on_target_ < 3` && `fire_only_blue ? cls==1`（:201-206）
- `cooldown_ok`：≥500ms
- `target_confirmed`：连续 8 帧（:57）；未检出时**衰减而非清零**（:264-267）

**开火执行**：发 `LaserShot_Command=1` 后立刻发 `0`（:215-219）→ `dzjudgment` 转串口 → `/shoot_count` 发布累计值（:227-229）供 path_executor 判停。

**类别迟滞**：raw_cls 连续 5 帧才改 `locked_cls_`（:176-197）；目标丢失复位（:276）。

### 4.6 坑

1. **`declare` 与 `get` 必须成对** —— 本项目最隐蔽 bug：`scan_pitch_offset_deg` 长期只 declare 不 get，导致 `ros2 param get` 显示 −26 但代码用默认 −8（cpp:883-891）。healthcheck 已加静态检查。
2. **`rclcpp::Time` 默认构造是 SYSTEM_TIME**，与 `this->now()`(ROS_TIME) 相减会抛异常 SIGABRT（cpp:983-990）→ 所有时间戳必须显式 `= this->now()`。
3. **俯仰增量符号**（:129）：旧版写 `+`，进 TRACK 就把云台往反方向推，靶被顶到画面下沿出不来。
4. **俯仰只有 1 层时 min==max 会僵死**，靠 `tracking_pitch_margin_deg=12°` 撑开区间（:358-364）。
5. **水平不用硬件限而用扫描范围限**（`clampYawToScan`）：曾推到 3988(≈170°) 撞机械限位堵转，表现为"云台定住不动"。
6. **QoS 不对称**：`offset_center`/`camemo_feedback` 用 best_effort，但 `/nav/scan_request` **必须默认可靠 QoS**（:802-803），否则连不上 path_executor。
7. **`callback_offset_center` 没做 `data.size()` 检查**即访问 `data[2]`（:30）→ 长度<3 会越界 UB。
8. `offcenter_table.txt` **当前全 0 且未接入主流程**（h:264 注释"预留"）。
9. 主循环 `spin_some` + `Rate.sleep`（:1069/1096）→ 所有回调串行，回调里无锁但不并发。
10. **弹药打满后节点仍在 TRACK**，只是 `ammo_ok=false`，不回 IDLE。

以启动时刻 T0 记录：状态机跳变、开火事件（带完整上下文）、5 类心跳；心跳阈值 5.0s，只报一次；Ctrl+C 才打印 summary。

### 7.6 `p0_verify.py`（149 行）
四项判定：①云台 yaw 刻度 ∈[1023,3071]（±5 容差）②单目标连发 ≤3 ③越界（`MAP±0.60`）④仅打蓝靶。
- 坑：P0-3 是**监控不是触发**（真急停在 path_executor）；P0-2 的"同一目标"实为"同一类别连续开火"，跨两个蓝靶会**误报**。

### 7.7 `healthcheck.sh`（306 行）

### 7.8 `restart_node.sh`（114 行）

### 8.4 最危险的五个坑（按后果排序）
1. **`robot.yaml` 与 `map.yaml` 要素漂移** → 工具拿错图校验，路线可能与真实场地不符。
2. **底盘析构发旧协议** → Ctrl+C 可能停不住车。
3. **`declare` 不 `get`** → 参数"改了不起作用"（已修过一次，改参数后必须跑 healthcheck）。
4. **det_node 多目标取最低分** → 疑似 bug，靶多时可能锁错目标。
5. **串口断连 → 定位/IMU 全停** → 循迹失输入，靠看门狗兜底。
