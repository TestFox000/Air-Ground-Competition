## 6. 新发现（文档未覆盖，本次对比得出）

### 6.1 【P0】提前量只进开火判据，不进控制环

~~~cpp
// 控制环（cpp:213-225）：只用滤波后误差 + 速度前馈 + 陀螺前馈
const double u = pidStep(eff_x, dt, true);
yaw_delta = u * dt;
yaw_lead  = vx * predict_gain_;
const int inc_x = lround(yaw_delta + yaw_lead + ff_x);

// 开火判据（cpp:299-302）：lead 只出现在这里
const double lead_applied = lead_apply_gain_ * lead_px_;
const double aim_err_x = std::abs(dx_filt_ + lead_applied - laser_offset_x_);
const bool in_fire_zone = (aim_err_x <= fire_dz) && (aim_err_y <= fire_dz);
~~~

**后果**：控制环的唯一目标是把目标拉回画面中心（dx→0），而开火判据要求 |dx + lead_applied| ≤ fire_dz。两者在稳态下**互相拉扯**：

- dx→0 时判据退化为 |lead_applied| ≤ fire_dz，即"开火框必须不小于提前量本身"。
- lead = est.v × lead_time_s（aim.py:883-892，与 dx 同号），4.doc 口径下 ≈33px；lead_apply_gain=0.5 ⇒ lead_applied≈16.5px。
- 旧 fire_dz_far=14 ⇒ **16.5 > 14，稳态下开火条件恒不成立** ⇒ 开了提前量反而更打不出去（与现场"开 lead 后一枪不开"的现象一致）。
- 本地改成 fire_dz_far=25 ⇒ 16.5 < 25，恢复可开火，且留有到 gain≈0.75 的余量。
- ⚠️ 目标带速时伺服滞后会让 dx 与 lead **同号**（追同一方向），此时 |dx+lead| 比 |lead| 更大，判据更严 —— 因此实际能开火的窗口比"稳态估算"更窄。符号方向需实车上电验证（本报告只做静态代码推演）。

**这解释了 18:41 那次 "14→20→25" 的调整动机**，也说明它是"用放宽判据掩盖结构问题"：判据越松，命中精度越差。

**建议改法（未实施，需实车验证符号）**：让同一个误差同时驱动控制与判据 ——

~~~cpp
// 控制环：把 lead 并进误差，让云台物理上提前瞄
const double err_ctrl_x = dx_filt_ + lead_apply_gain_ * lead_px_ - laser_offset_x_;
const double u = pidStep(err_ctrl_x, dt, true);
// 开火判据保持原式（此时稳态 dx ≈ -lead_applied，判据自然 ≈0）
~~~

改完后 fire_dz_far 可以收回 14，命中精度回到"框内 14px"。

### 6.2 【中】动态开火框在实际配置下塌缩

~~~yaml
fire_dz_dynamic: true
fire_dz_far_px: 25.0   # 远处（框宽 30px）
~~~

fireDeadzonePx()（cpp:776-799）在 [box_w_far, box_w_near] 间线性插值 25→26，**全程基本恒等于 25~26px**，比机械抖动（≈12px）大一倍以上。等于放弃了"远严近宽"的设计意图。若 25 是为配合 lead 临时抬的，应随 §6.1 修复一并收回。
