# sim_v2 规格增补：硬约束 / 棋子槽 / 冗余同源 / 无人机入链

> 本文是《sim_v2 设计规格》的增补（用户 2026-10-17 四条需求），原规格正文不动。
> 基线含两项已落地修复：① 页面重规划引擎与车端同源（simbench.planRoute 按 robot.yaml
> `planner.engine` 传 `--engine`，台账落 `record.plan.engine`）；② 棋盘变更统一走
> `afterFieldChange` 清旧层（`invalidateStaleRun`），422 plan-failed 同样清 TRACE。
> 对应任务卡：t13（§H）· t14（§S）· t15（§R）· t16（§D）。

## §H 硬约束：任何情况下不得压障碍/隔板/桥洞（含冗余长度）

**H.1 实体与口径**
- 三类禁压实体：**障碍**（障格实体）、**隔板**（D6~N6 与 D7~N7 两道壁，不可触碰跨越）、**桥洞**（K 列桥室非通格壁 + 进洞侧冗余墙）。
- 车身足迹 = 0.28 × 0.135 m 矩形含拐角扫掠；几何判定**单一真源** `route/physics.py`（`bridge_entry_walls()` 等），规划器与校验器引用同一实现，禁止复制公式。
- 冗余墙设计值 **0.0875 m**（1/4 格，进洞侧虚拟延长）。`field.bridge_entry_redundancy_m` 是**设计值配置**（0.0 = 回到 t4 前行为），不属"放宽"——但置 0 时障碍/隔板/桥室壁三类仍必须硬。

**H.2 结构性要求（不可放宽）**
- 规划器对三类实体的判定是**硬失败路径**：不存在任何"容差/放宽/跳过"参数能让违规路线通过。
- 不可行 ⇒ 报不可行（exit≠0 或 failures 非空），**绝不产出违规路线**；通过性、效率、路径长度都不得作为放宽理由。
- `footprint_gate: warn/error` 只影响**诊断报告级别**，不得影响"违规路线不得产出"这一硬底线。

**H.3 验收（t13）**
1. 三类**必拒反例**各 ≥1 条（故意压障碍 / 蹭隔板 / 穿桥室壁+冗余墙的输入），规划必须失败；
2. 结构性证据：审计结论指出判定链上每一环（格级 → 足迹级 → 冗余墙级），并证明无旁路开关；
3. `tools/route_check.py` 用户侧判据**刻意不含冗余墙**的既有决策保留（现场实跑不判红），页面重规划口径含冗余（与车端 planner 一致）；
4. 回归：`test_planner.py` / `test_physics.py` / `test_bridge_gate.py` / 守卫 61/61 全绿不回退。

## §S 棋盘棋子槽：定容 8/8/2/1 + 靶板旋转 + 象棋观感

**S.1 定容硬顶**
- 障 **8** / 雷 **8** / 通 **2** / 靶板 **1**（占相邻两格）。落格层**硬拒**超出（与 §A.2 同机制）：第 9 枚障/雷、第 3 个通、第 2 块靶板 ⇒ 拒 + 消息明示"已满 N 枚"。修复"能点出 10 个"的现状。
- 现场默认图本身超容时（如现役 8/8/2/1 恰满）：不削减真源，只是**不能再加**。

**S.2 靶板：点击顺时针旋转 + 两色面**
- 两格一体（既有整对语义不变）。**点击靶板 = 顺时针旋转 90°**（横↔竖），不再触发移除。
- 旋转落点必须仍合法：旋转后的两格需相邻、同半场、不与他子/禁区冲突；不合法 ⇒ 拒转 + 提示原因，保持原状。
- **两色面**：一面蓝一面红；横态显示一色、竖态显示另一色（旋转即翻面），色值进台账（`record.targetFace: 'blue'|'red'`）。仿真物理不感知面色（与既有 targetYaw 结论同构）。
- `targetYaw` 通道复用：点击旋转即写 h/v，恢复默认仍回「跟随地图」。

**S.3 象棋观感**
- 棋子 = **圆形棋子**（圆饼 + 居中汉字 障/雷/通/靶），配描边与投影感；棋盘 = 深色边框 + 清晰格线 + 坐标标尺保留。
- 观感改造不得移动守卫锚点语义：`#map`/`#anim`/`#stress*` 锚点、`data-cell` 命中、61/61 断言全不回退。

**S.4 交互边界**
- 棋子**只**拖拽放置（palette pointer 链保留）；点击棋盘已有棋子：靶板=旋转、其余=移除（既有）。
- 拖放后 350ms 误点抑制（`lastDropAt`）复用；一切棋盘变更走 `afterFieldChange()`（清旧层咽喉，不许旁路）。

**S.5 验收（t14）**：硬顶三类反例（第 9/9/3/2 枚必拒）；旋转正反例（合法转 / 非法转拒且保持原状）；两色面切换可见且进台账；守卫 61/61 + `test-sim-overlay-fix.mjs` 30/30 不回退。

## §R 桥洞冗余长度：仿真器与规划器同源一致

**R.1 真源链（单一真源，禁双份硬编码）**
- 几何真源 `route/physics.py: bridge_entry_walls()`；兜底常量 `planner.BRIDGE_ENTRY_REDUNDANCY_M`；配置 `robot.yaml field.bridge_entry_redundancy_m`。
- sim.html **不得**再写一份 0.0875：`/sim/map` 响应新增 `bridgeEntryRedundancyM`（Host 从 physics/配置读出透传），页面渲染取该值。
- 验收（t15）：改 `robot.yaml` 该值 ⇒ 页面墙长随之变（同源证明）；渲染把进洞侧短墙画在 K 列通格进洞方向（row 7~11 向西、row 1~6 向东，与 `path_executor.bridge_order` 同口径）。

## §D 无人机选项：参与路径规划与约束判定

**D.1 选项与默认**
- UI 新增「无人机协同」开关，**默认关**：关闭时一切行为与现状逐字一致（含台账形状）。

**D.2 约束语义（开启时）**
- **硬约束**：车路线不得穿过无人机起降格 **N8 / M2**（规划层避让 + 页面校验层复核，双层）。
- **软约束**：无人机扫描走廊行（dronesim 既有推导：上半场 ≤6 缺省 5、下半场 ≥7 缺省 9）加规划代价，**非禁行**（走廊行本身是可通行格，只是绕行更优）。
- 规划器接口：`plan_route.py` 新增可选 `--drone`（或 config `planner.drone_aware: true`），实现走 `dzbrain/route/planner.py` 的避让集扩展，不另起引擎。

**D.3 判定与台账**
- 开启后 plan 的路线 token **不含 N8/M2**；台账 `record.plan.drone = { enabled, hardAvoid: ["N8","M2"], corridorRow: {top, bottom} }`。
- 校验：`route_check` 增加同口径检查（仅协同模式生效）。

**D.4 验收（t16）**：开启后路线避开 N8/M2（正例）+ 关闭时输出与现状逐字节一致（对照例）+ 台账字段落盘 + 守卫不回退。

## 边界与已知取舍

- 车身占位口径（0.28×0.135）沿用 t28 现役值；若现场量测更新，只改 physics 单点。
- 靶板两色面是**渲染与台账概念**，不进仿真物理、不进规划判定（规划仍只认靶格不可通行）。
- §D 软约束的走廊行推导依赖 dronesim 现有逻辑；若 dronesim 走廊规则变，`corridorRow` 台账随之，不另设第二真源。
