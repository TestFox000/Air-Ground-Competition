# 子智能体团队设计（文档收口专项）

## TL;DR（给 agent 看的）

- 本轮是**一次性文档收口**：583 篇旧文 → 4 个库。按**领域切片**并行，不按功能切。
- 6 个编纂子智能体 + 1 个 Lead 收口；**写域互不重叠**，Lead 独占 `README.md`、`00_项目总览/`、`_archive/`、`AGENTS.md`。
- 子智能体**只读原文、只写自己目录**；删除/归档/改工具链全部由 Lead 单线程执行。

## 2. 为什么这样切

- **按领域切而不是按文档类型切**：同领域的事实必须由一个人写，否则「循迹参数」在两个 agent 笔下会出现两个数字。
- **任务卡库单独一人**：卡是过程产物，格式统一才能当模板复用；混进资料库会再次变乱。
- **提示词库单独一人**：它面向「发给别的 agent」，与面向「自己查」的资料库读者不同、语气不同。
- **Lead 独占归档**：删除/移动是唯一不可并行的一步，必须单线程 + 可回滚。

## 3. 公约（对每个编纂者生效）

1. 每个新文件带 4 行 front matter：`来源 / 取证(实|档|未) / 更新 / 取代`。
2. 开头 3~6 行 **TL;DR**：这层做什么、当前状态、最大坑。
3. 结论先行；每条关键结论后给证据（`路径:行号` 或 `路径 + 章节`）；不确定写「未核实」。
4. 单篇 ≤ 180 行；超了按主题拆。
5. 表格优先；数字必须带出处；**口径冲突并列写 A 版/B 版，不二选一**。
6. 结尾列「相关文件」相对路径清单。
7. 只读原始资料：不修改、不删除、不 git、不 present。
8. 每篇写进所属库 `00_索引.md` 一行。

## 4. 时间线协作方式

每个编纂者额外写 `docs/_work/timeline_<角色>.md`，一行一条：

```
YYYY-MM-DD | 事件（≤40字） | 证据相对路径:行 | 影响（对现在还有什么用）
```

Lead 合并成 `00_项目总览/时间线.md` 后删除 `_work/`。
