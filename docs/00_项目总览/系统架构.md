# 系统架构（车 · 机 · 链路 · 模型 · 设施）

## TL;DR（给 agent 看的）

- 车端 = **单进程 8 线程**（不是 8 个节点）：`python3 -u -m dzbrain.main`，8 个任务线程 + 4 个 ROS executor 线程。
- 机端 = **回放式路径跟随**（人飞一遍录轨迹 → 机器照轨迹飞），外加上层「视觉侦察 → 向车下发」单向链；**从未真机自主飞行**。
- 链路 = 两条：`/nav/waypoint`（RELIABLE，机→车路线）与 `/dzlink/*`（BEST_EFFORT，情报/布局/心跳）。**BEST_EFFORT 发 → RELIABLE 收 = 静默 0 条**。
- 最大架构性坑：**域号**。车 118、机 0，ping/SSH 全通但 ROS 互相看不见，且零报错。

## 1. 车端 `dzrobot_v2`

### 1.1 平台与运行

| 项 | 值 | 证据 |
|---|---|---|
| 计算平台 | **RK3588S**（Orange Pi 5 Pro，aarch64），Ubuntu 22.04，ROS2 Humble，Python 3.10 | 〔档〕`dzrobot_v2/docs/项目现状_20261018.md:24` |
| 决策层形态 | `dzbrain` **单进程 8 任务线程 + 4 个 ROS executor 线程** | `src/dzbrain/dzbrain/main.py:1667-1700` |
| 域号 | `ROS_DOMAIN_ID=118`、`ROS_LOCALHOST_ONLY=0`，唯一真源 `dzros.env` | `dzros.env:16-18` |
| 车地址 | 随网络漂移（10-18 `192.168.137.79` → 10-19 `192.168.0.197`），以 `deploy_to_car.py probe` 为准 | `dzrobot_v2/docs/library/现场联调与部署.md:10` |
| 部署 | 唯一入口 `tools/deploy_to_car.py`（probe/backup/push/build/verify/all，sha256 对账）；**刻意不推 `config/map.yaml`** | D-019 |
| 起栈 | 车端 `~/dzrobot/start_all.sh`（7 步），`start_all.sh:168-220`；起栈后 `auto_start` 默认 **10 s 后自行出发** | `dzrobot_v2/docs/使用手册.md:14` |

### 1.2 八线程（频率已对源码核实）

| # | 线程 | 频率 | 职责 | 唯一性 |
|---|---|---|---|---|
| 1 | LocalizationTask | 20 Hz | 定位投影、到位吸附、漂移/边界护栏、航向完整性守卫 | 写 `P_POSE` |
| 2 | SafetyTask | 20 Hz | 五道看门狗 + `SAFE_STOP` 故障闩锁 | **唯一强制停车者** |
| 3 | TrackerTask | 50 Hz | 纯追踪 → `pursuitAngle`；PIVOT/倒车/ALIGN 入口 | **底盘指令唯一写入者** |
| 4 | MissionTask | 10 Hz | 阶段机、路线装载、停站三段式、桥洞择格 | 任务编排 |
| 5 | AimTask | 50 Hz | 云台扫描/跟踪、提前量、开火门、扫描请求 | 出 `/aim/fire_ready` |
| 6 | FixTask | 10 Hz | 系统性误差/尺度估计（只估计，不改位姿） | 不写位姿 |
| 7 | DroneTask | 5 Hz | `/dzlink` 收发、ack、布局、覆盖账本 | 链路唯一出入口 |
| 8 | TelemetryTask | 2 Hz | 遥测快照（面板/复盘），不做决策 | 只读 |

> 布局模式（StepLoop）下 DroneTask 会**先单独起一个**再起任务组（实际 8+1 线程），并强制 `mission.auto_start=false`（`main.py:1263-1270/2045-2068/2082`）。

### 1.3 硬件层与射击链

```
相机 → det_node(RKNN) → /offset_center[dx,dy,类别(1蓝2红),框宽,框高]
     → dzrknn_dataprocess(PID/开火判定) → /aim/status、/shoot_count、LaserShot_Command
     → dzjudgment → 激光
```

- `dzrknn_dataprocess` 编出的可执行文件叫 **`dzactuator_node`**（与底盘包同名，`CMakeLists.txt:91`）——查二进制时间戳时别认错包。
- `det_node` 必须 `draw:false`：SSH 无 X 时 `cv::imshow` 抛 GTK 异常直接崩（D-003）。
- `ros2 topic info /LaserShot_Command` 订阅数必须 = 1；少 `dzjudgment` 时开火指令进空话题，激光不亮且**无报错**。

### 1.4 现场会咬人的坑（精选，全量见 `20_资料索引库/车端/05`）

1. **布局模式启动坑**：`--map` 指向**存在的**文件 ⇒ 进文件模式，StepLoop 收布局也不规划；必须传**不存在的**路径。而 `start_all.sh:220` 恰好传 `config/map.yaml` ⇒ 车上有该文件时永远进不了布局模式。
2. **`cam_viewer` 抢 `/pursuitAngle`**：20 Hz 发全零，底盘每帧更新目标速度 ⇒ 车「收到了但不动」。跑车前必须 kill。
3. **非交互 SSH 域号变 0**：必须 `source dzros.env`，否则 ROS 互相看不见且零报错。
4. **`robot.yaml` 顶层裸键**会让相机/视觉/云台三节点同时 abort（地图必须放 `config/map.yaml`）。

## 2. 机端 `dzsmartscout`

### 2.1 定位（别误解）

**不是会自主规划的无人机，而是「人手动飞一遍 → 录轨迹 → 机器照轨迹回放」的回放式路径跟随系统**，外加「视觉侦察 → 向小车下发路线/情报」的单向指挥链。全仓**没有任何真机飞行/Offboard/自动起飞/路径回放记录**。

### 2.2 硬件与软件栈

| 层 | 事实 |
|---|---|
| 机载计算机 | Jetson Orin Nano（Ubuntu 22.04.5，kernel 5.15.185-tegra，6 核，RAM 7.6G） |
| 雷达 | **Livox MID-360**：10 Hz / 19968 点每帧；IMU 200.9 Hz |
| 相机 | LRCP AR0234 UVC（`/dev/video0`）；10-18 live **21 fps** 已验证 |
| 飞控 | Matek `HKUST_UAV_NxtPX4`；uXRCE-DDS **921600**（ttyACM0/1 有冲突） |
| 软件 | ROS2 Humble + PX4 + FAST-LIO + 4 个自研 C++ 包（`px4_control`/`px4_path`/`px4_odom_convert`/`px4_imu_bridge`，约 **4742 行**） |

### 2.3 数据流

```
livox → fastlio_mapping → /Odometry(43~45Hz) → px4_odom_convert
      → /fmu/in/vehicle_visual_odometry(42~44Hz) → PX4 EKF2
控制侧：px4_teleop / px4_path → px4_control_node
      → /fmu/in/{offboard_control_mode, trajectory_setpoint, vehicle_command} @20Hz
      （goto_enabled 是 transient_local 锁存闸门）
感知侧：相机 → dzuav(检测/格号/箭头) → UDP:50000 或 ROS → 小车
跨机：dzlink_supervisor / dz_send_waypoint → 118 域 → 小车
```

### 2.4 真机跑过 vs 从未做过

| 已真机验证〔实〕 | 从未做过〔实〕 |
|---|---|
| 雷达 10 Hz、FAST-LIO 43~45 Hz、`/localization` ~44 Hz、VIO 42~44 Hz；EKF 接受 EV（eph 0.032 / epv 0.029） | **真机飞行、Offboard、自动起飞、路径回放**——全仓无试飞记录 |
| 10-18 八路 `/fmu/out` 102~142 Hz；10-07 机→车 DDS 首闭环、10-12 双向全验 | 4 个 C++ 包 **0 测试** |
| 感知算法 **99/99 单测**；官方图桥顶箭头 −96° vs −90° | 实拍帧上的格级感知未闭环（live 窗口 `det=0`，画面糊） |
| 10-18 相机 live 21 fps | UDP:50000 端到端未验证；点云桥未在 118 域验证 |

## 3. 空地链路

### 3.1 话题契约

| 话题 | 类型/QoS | 方向 | 用途 |
|---|---|---|---|
| `/nav/waypoint` | `std_msgs/String`，**RELIABLE depth 10** | 机 → 车 | 路线 token（`load:`/`reset:`/多点）与段目标 |
| `/dzlink/drone_to_car` | JSON，**BEST_EFFORT depth 10 VOLATILE** | 机 → 车 | 情报、布局版本、心跳 |
| `/dzlink/car_to_drone` | JSON，BEST_EFFORT | 车 → 机 | 车态、ack、覆盖账本 |
| `/aim/fire_gate`、`/nav/scan_request` | — | 车内 | 开火/扫描闸门 |

**铁律**：BEST_EFFORT 发 → RELIABLE 收 = **静默 0 条**，但两端端点计数各为 1（t4 真机 8 格矩阵实测）。**ack 是唯一硬证据**。心跳超时 **3.0 s**、情报过期 **30.0 s**（`robot.yaml:840-841`）；桥洞窗口 2.0 s。

### 3.2 StepLoop（当前主线）

```
机：读布局/情报（/dzlink，10 批）→ 定段目标 → /nav/waypoint 下发
车：WAIT_LAYOUT → PLANNING → DRIVING → SEGMENT_DONE → 机侧消费后发下一段
机侧 1.4 Hz 读车态 → 决定下一段 → 再下发新版本
```

- D1 已实车验证：10-18 晚连续 6 段自动推进（含 1 个射击停站）。
- **D1b**：`SEGMENT_DONE` 窗口只有 1~2 拍，1.4 Hz 采样漏收率约 **86%**；代码已加「完成单闩锁 + 1 Hz 重发 + `done_seq`」，未实车复验。
- **D2**：到站后 `block` 与 target 差半格/一格，机侧 `block==target` 判据永久卡住。
- 布局过期（D-022）：过期只拦新规划 → `WAIT_INFO(layout_stale)`；**完整布局（known=154）例外**，视为静态场地信息。

### 3.3 赛时时间轴（180 s）

| 阶段 | 内容 | 依据 |
|---|---|---|
| T0–10 s | 系统级并行自检（车 6 + 机 4 + 跨 2，只读），**不输出 GO** | D-017 |
| T10–45 s | 无人机全场扫描（目标 ≤35 s，累积 layout 154/154） | D-017 |
| Go | **起点格 + 首段 6~8 航点 + 一格缓冲**可靠即发车 | D-020 |
| 段边界 | 等增量新版本 **≤10 s**；超时用最后完整布局继续，不跳点 | D-015 |
| 全场 layout | 约 37.1 s 的**运行中里程碑**，不是发车门票（等全场再发 = 188.6 s 超时） | D-020 |
