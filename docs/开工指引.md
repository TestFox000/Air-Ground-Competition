## 二、开工三步（任何智能体，每次开工）

```bash
cd C:\Users\29212\CodeBuddy\20260927120106\air_ground
git fetch origin
git status -sb        # 看 ahead/behind
```

判定：

- `## main...origin/main`（无 ahead/behind）→ ✅ 直接开工
- **behind** → `git pull --ff-only`；拉不动（有未提交改动冲突）→ **停下来问人**，别硬合
- **ahead**（有未推送提交）→ 先 `git push` 并验证（见第三节），再开工
- **有未提交改动** → 先搞清是谁的：`git diff --stat` 看一眼；像是别人没干完的活
  → **停下来问人**（可能另一个智能体还在里面干活，2026-10-15 撞车教训）

## 三、收工两步（每次收工）

```bash
git commit -am "..."
git push origin main
git rev-parse HEAD origin/main   # 两行输出必须一模一样，不一样就是没推上去
```

⚠️ 本仓库 post-commit 钩子带 `|| true`：**推送失败也显示"提交成功"**，不验证等于没推
（接手说明 §8.1 的血泪条款）。

## 四、目录里有另一个活跃会话时

1. 别动它的工作区文件，别开 rebase/merge
2. 你的成果可以：提交到自己的分支（`git branch <name> && git push origin <name>`），等对方收工再合
3. 参考 `merge-backup` 分支（2026-10-15）的寄存范式
