# 无人机操作手册（现场 SOP）

> 面向现场飞手/操作员，覆盖从一次性部署到每日起飞、降落、应急、收工的全流程。
> 架构原理见 [无人机工作流程.md](无人机工作流程.md)，比赛日逐项打勾清单见
> [preflight_checklist.md](preflight_checklist.md)，本文只讲"怎么操作、出问题怎么办"。
>
> 依据源码/工具（2026-10-21 核对）：`tools/orin_bringup.sh`、`tools/orin_run_dzuav.sh`、
> `tools/orin_deploy.py`、`tools/patch_deploy.py`、`tools/flight_console.py`、
> `tools/uav_link.py`、`onboard/dzuav/src/main.cpp`、`reference/onboard/dzpx4/`（官方栈）。

## 0. 速览：一次飞行要做的 6 件事

```
① 检查硬件/网络（5 分钟）
② 笔记本跑 preflight 防呆（1 分钟）
③ Orin 上 tools/orin_bringup.sh up 拉起全栈（1 分钟）
④ 逐窗口确认健康 + 笔记本 monitor_link 看到 UDP 帧（2 分钟）
⑤ 笔记本开 flight_console 地面台 → teleop 按键 0→1 起飞 → 4 放行航线
⑥ 任务完成按键 3 降落 → bringup down → 取回黑匣子
```

两条铁律：
- **先 bringup 后开地面台**：`orin_bringup.sh up` 会 kill 重建 tmux 会话，把
  黑匣子窗口一并清掉；先起全栈再开 `flight_console.py`，它会自动把黑匣子拉回。
- **teleop 必须在真实 TTY 里跑**（tmux 窗口满足，nohup 后台不行），否则键盘无响应。

### 0.1 向导模式（推荐入口）

本手册 §3 的每日流程已工具化为 **`tools/uav_wizard.py`**（双击根目录 `无人机向导.bat`
进中文菜单，菜单逻辑在 `tools/uav_wizard_menu.py`——bat 只是哑启动器，cmd 解析
中文批处理有分块缺陷，UI 全部收进 Python）：S0~S10 每步显示作用/命令/通过标准/排查
提示，Enter 一键执行+实时验证。

```bash
python tools/uav_wizard.py --host <Orin IP> --user <用户>   # 全屏面板（j/k 选步，a 全量自检）
python tools/uav_wizard.py --host ... --check               # 非交互全量自检（退出码可进冒烟/CI）
python tools/uav_wizard.py --rehearse                       # 无硬件彩排：假 SSH + 假 UDP 流走全流程
```

安全边界：面板内只做检查与 `orin_bringup up/down`（确认词）；**起飞/降落/KILL 不在
向导里**——S9 只显示该按什么键，交给 teleop 与 flight_console 的实战闸门。

## 1. 系统与前提

### 1.1 机载全栈 10 个进程（`orin_bringup.sh` 按此依赖顺序拉起；2026-10-22 起含 plan 机载规划 sidecar，teleop 可选）

| tmux 窗口 | 进程 | 作用 | 依赖 |
|---|---|---|---|
| dzuav | `onboard/dzuav`（独立进程，不走 ROS） | 相机→TRT 检测→格号 PnP 自定位→UDP:50000 广播 | 仅相机+引擎 |
| plan | orin_plan_sidecar.py | 机载自主规划 sidecar（2026-10-22 起新增，0x4003 给车端） | dzuav、ROS |
| livox | livox_ros_driver2 | MID360 激光雷达驱动 | 雷达 |
| fastlio | fast_lio_localization | SLAM 建图/定位，出 `/localization` | livox、imu |
| px4 | MicroXRCEAgent | 飞控串口桥 `/dev/ttyACM0` @921600 | 飞控 USB |
| odom | px4_odom_convert（**本仓补丁版**） | SLAM 位姿→PX4 EKF 外部视觉，带跳变三级防护 | fastlio、px4 |
| imu | px4_imu_bridge | 飞控 IMU→ROS Imu（喂 FAST-LIO） | px4 |
| control | px4_control 状态机 | Offboard 心跳/解锁/Goto 准入/设定值，**唯一 PX4 出口** | px4 |
| path | px4_path | 航线跟随，发 GotoTarget 给 control | control |
| teleop | px4_teleop_node | 键盘遥控（人工接管），可选 `--no-teleop` | control |

侦察链路（dzuav）与飞控链路（dzpx4）**互不依赖**：dzuav 自定位靠地面格号 PnP，
不用 SLAM；车端只消费 dzuav 的 UDP 广播。所以 bringup 把 dzuav 排在最前。

### 1.2 账号与环境

| 项 | 值 |
|---|---|
| 机载 SSH 账号 | 现场约定用户（历史部署为 `duzhong`），密码走笔记本环境变量 `AG_ORIN_PASS` |
| 机载目录 | 全栈工作区 `~/dzpx4`（colcon）；本仓部署 `~/dzuav_deploy/air_ground`（2026-10-16 起统一布局） |
| TRT 引擎目录 | `~/dzuav/engines/`（`hbb_detector_fp16.engine`、`cell_classifier_fp16.engine`） |
| 机载日志 | `~/drone_logs/`（odom 节点）、`~/ag_flight_logs/<会话>/`（飞行黑匣子） |
| 网络 | 无人机/车/笔记本连**同一台路由器同一网段**（UDP 广播不出路由器） |
| 笔记本依赖 | `python -m pip install paramiko`（orin_deploy/patch_deploy/flight_console/uav_link 共用） |

## 2. 一次性准备（仅换机/刷机/首次部署需要）

### 2.1 部署与编译（笔记本执行）

```bash
set AG_ORIN_PASS=******
# 源码+当前指针模型+orin 工具链 → ~/dzuav_deploy/air_ground；--verify 远程编译+L2 自检
python tools/orin_deploy.py --host <Orin IP> --user <用户> --verify

# 定位韧性补丁（px4_odom_convert v2 + localization_watchdog），可回滚
python tools/patch_deploy.py --host <Orin IP> --user <用户>
```

补丁部署/回滚细节（`tools/patch_deploy.py` 文件头）：

```bash
python tools/patch_deploy.py --host ... --no-restart   # 只推+编译，不动运行中节点
python tools/patch_deploy.py --host ... --rollback     # 按回滚索引恢复原版（指纹校验后重编重启）
```

### 2.2 机上编译与引擎转换（SSH 到 Orin 执行）

```bash
cd ~/dzuav_deploy/air_ground
tools/orin_build_verify.sh                        # dzuav 编译 + L0~L3 分层验证
tools/orin_convert_engines.sh -o ~/dzuav/engines  # ONNX→TRT FP16（换机必跑，引擎与 TRT 版本绑定）
```

### 2.3 SLAM 建图与航线录制（场地变化时重做）

定位依赖已建好的点云地图，航线依赖录好的路径文件，两者都住在 `~/dzpx4`：

```bash
# ① 建图（px4_odom_convert README 的方案一）
ros2 launch fastlio2 lio_launch.py
ros2 launch pgo pgo_launch.py
ros2 service call /pgo/save_maps interface/srv/SaveMaps \
  "{file_path: '<地图目录>', save_patches: true}"

# ② 定位模式启动改用 localizer（重定位到已有地图）
ros2 launch localizer localizer_launch.py
ros2 service call /localizer/relocalize interface/srv/Relocalize "{pcd_path: ..., x: ..., y: ..., z: ...}"

# ③ 航线录制：px4_path 参数 record_mode: true 后 launch，飞一遍，正常退出自动写
#    x y z qx qy qz qw 每行一点，存 src/path/recorded_path*.txt
# ④ 航线跟随：record_mode: false + follow_mode: waypoint|trajectory（config/params.yaml，
#    飞行中不可切换，改完要重新 colcon build + 重启）
```

验证一次性准备是否成功：`tools/orin_bringup.sh up` 起全栈后按 §4.2 逐窗口检查。

## 3. 每日飞行标准流程

### 3.1 赛前硬件与网络检查（上电前，对应 checklist A1/A3）

- [ ] 无人机电池 ≥80%，螺旋桨无破损装牢
- [ ] 下视相机（AR0234）镜头清洁、USB 牢固；MID360 无遮挡；Orin 供电灯正常
- [ ] 路由器开机，无人机/车/笔记本全部连上且**同网段**（`ping <Orin IP>` 丢包 <5%）

### 3.2 软件自检（笔记本，1 分钟）

```bash
python tools/preflight.py --match    # 比赛模式：退出码非 0 = 不得上场
```

核对机上关键件（checklist B1）：

```bash
ls ~/dzuav_deploy/air_ground/onboard/dzuav/build/dzuav   # 二进制存在
ls ~/dzuav/engines/*.engine                              # 两个引擎存在
ls /dev/video0                                           # 相机设备节点存在
```

### 3.3 拉起全栈（Orin 上执行）

```bash
cd ~/dzuav_deploy/air_ground
tools/orin_bringup.sh up
# 相机不是 /dev/video0 时：DZUAV_CAM=/dev/video1 tools/orin_bringup.sh up
# 不要键盘窗口：tools/orin_bringup.sh up --no-teleop
# 默认采集规格 DZUAV_SPEC=1920x1200@30（相机标定基准分辨率，勿随意改）
```

脚本逐窗口启动并留就绪间隔，全部起来约 15s。停止用 `tools/orin_bringup.sh down`，
看存活用 `tools/orin_bringup.sh status`。

### 3.4 健康确认（起飞前必须全绿）

| 检查点 | 命令/位置 | 通过标准 |
|---|---|---|
| 各窗口存活 | `tools/orin_bringup.sh status` | dzuav…path 均 [活] |
| 飞控链路 | `ros2 topic hz /fmu/out/vehicle_local_position` | 有稳定频率 |
| 侦察定位 | tmux 看 dzuav 窗口 stdout | 持续 `localized=1 landmarks=N` |
| 定位质量 | odom 窗口 `[px4_odom_convert_health]` 行（3s 一条） | 持续刷新、无 L1/L3 触发、reset 速率低 |
| UDP 出网 | 笔记本 `python tools/monitor_link.py`（Windows 可直接跑） | 收到 0x4001/0x4002 帧、CRC 通过、帧率正常 |
| 看门狗 | 机上 `localization_watchdog.log` 无 ERROR | 无告警 |

dzuav 未能定位时的判断顺序：① 高度/位置是否看不到 ≥4 个分散格号（PnP 硬条件）；
② 引擎文件是否在 `~/dzuav/engines`；③ 相机是否断流（dzuav 窗口会自动重开 3 次，
3 次失败才退出）。只想验证 UDP 链路不要求定位，可 `DZUAV_FORCE_UDP=1` 起进程。

### 3.5 地面台（笔记本，在 bringup **之后**开）

```bash
set AG_ORIN_PASS=******
python tools/flight_console.py --host <Orin IP> --user <用户>
```

黑匣子自动上机（tmux 窗口 agup:bb），遥测/指令 JSONL 落 `~/ag_flight_logs/<会话>/`，
同时 UDP 镜像给面板实时告警（模式翻转/电池低/定位失效/断流）。面板按键：

| 键 | 动作 | 备注 |
|---|---|---|
| `L` | 降落 | 按 `y` 二次确认 |
| `K` | 停 GOTO 并悬停 | 应急"冻结" |
| `O` | 切 Offboard | |
| `M` | 移动模式 | WASDQE+l/r，同 teleop |
| `1` | ARM 起飞 | `y` 确认 |
| `X` | DISARM | 空中会被 px4_control 拒绝（安全设计） |
| `!` | **KILL 电机停转** | 输入 kill 确认；空中=坠机，仅撞人前最后手段 |
| `Q` | 退出面板 | 黑匣子继续在机上录 |

只读巡检也可以用 `python tools/uav_link.py run --host <IP>`（2Hz 遥测面板+8 条告警，
不占 flight_console；调控命令走 `uav_link.py ctl ... --yes` 闸门）。

### 3.6 起飞与任务（teleop 窗口，tmux attach -t agup 后直接敲键）

| 键 | 动作 |
|---|---|
| `0` | 请求 Offboard（先于一切自主动作） |
| `1` | 解锁并起飞（爬升至任务高度；**需飞到能看到 ≥4 个格号的位置 dzuav 才有情报**） |
| `4` | 允许外部 Goto → 放行 px4_path 航线跟随（仅 HOVER 且本地位置有效时可开） |
| `5` | 禁止 Goto，把当前位置固化为悬停点（人工接管入口） |
| `3` / `2` | 降落 / 锁桨 |
| `W/S/A/D/Q/E`、`L/R` | 悬停目标位置 / yaw 微调（Goto 放行期间被屏蔽） |

任务时序（比赛 180s 硬顶，详见 preflight_checklist §D）：起飞→巡航侦察
（格号定位、雷/靶/桥顶箭头识别、UDP 广播）→ 车端发车执行 → 终点上空待命 →
155s 前后启动降落。无人机自主降落只提供下降目标，触地判断与自动锁桨由 PX4 完成。

### 3.7 收工

```bash
# 1. teleop 按 3（或面板 L）降落，确认 VehicleStatus=STANDBY 后按 2 锁桨
# 2. 停全栈
tools/orin_bringup.sh down
# 3. 笔记本取回黑匣子（复盘用）
python tools/flight_console.py --host <Orin IP> --user <用户> --fetch ./flight_logs
python tools/flight_console.py --host <Orin IP> --user <用户> --stop   # 停机上黑匣子
# 4. 离线复盘分级
python tools/uav_link.py report ./flight_logs/<会话>.jsonl
```

## 4. 应急处置

### 4.1 空中异常决策表

| 情形 | 判据 | 立即动作 |
|---|---|---|
| 要撞人/撞物 | 目视 | 面板 `!`（输入 kill 确认）——空中 KILL=坠机，仅最后手段 |
| 飞行异常需中止任务 | 目视 | 面板 `K` 停 GOTO 悬停 → 评估后 `L` 降落 |
| 悬停漂移/定位可疑 | health 行 L1 频发或 SLAM 跳变 | `K` 悬停观察；持续异常即 `L` 降落，勿赌 |
| 无人机失联（UDP 断） | 车/monitor 超 10s 无帧 | 目视确认是否在飞：在飞→手动降落；已落→查 WiFi。车端用最后一帧情报降级继续 |
| 需要人工接管航线 | 任意时刻 | teleop `5`（固化悬停）后用 WASDQE/L/R 手动 |
| 比赛超时自救 | 计时 ≥150s 任务未完 | 放弃剩余目标：机直接降落（保精准降落 10 分），车直驶终点 |

### 4.2 机载自动防护（不用人操作，知道它们会做什么）

- **orin_watchdog.py**（bringup 的 flight_wd 窗口）：断流/掉 OFFBOARD/位置跳变 → 机上**本地自动 LAND**。
- **px4_odom_convert v2 三级防护**：L1 单帧位移超 2m 判 SLAM 无效，输出锁死在最后可信位姿（恢复需 SLAM 稳定约 2s）；L2 真实大位移的 EKF 重锚最小间隔 10s；L3 60s 内 EKF reset >5 次即冻结一切重锚。armed 状态下跳变永不接受。
- **localization_watchdog.py**：只读日志告警不杀进程；`[px4_odom_convert_health]` 行停更本身就是告警（节点死/SLAM 断流）。
- **dzuav 相机断流**：自动重开管道 3 次（200/400/600ms 退避），3 次失败才退进程；单帧推理异常连续 30 帧才退出。
- **px4_control Goto 门控**：降落/锁桨请求/退出 Offboard/Goto 超时/目标含非有限数 → 自动关 Goto 并悬停。

### 4.3 车机联调（无无人机彩排）

```bash
# 笔记本假机载 UDP 发送器，驱动车端 integrate_node 全链路
# （2026-10-16 起 13 类，旧 mine→paper；本机自收彩排加 --to 127.0.0.1）
python tools/fake_udp_sender.py --scenario "B3:paper,H7:target_blue"
# 同时看空地链路看板（ASCII 场地格图 + 帧率/CRC/延迟）
python tools/monitor_link.py            # 可加 --plot、--car-log <车黑匣子目录>
```

## 5. 故障排查表

| 症状 | 大概率原因 | 处置 |
|---|---|---|
| bringup 报 "dzuav 未编译" | 机上没跑过 `orin_build_verify.sh` | 机上编译后重启窗口；二进制在 `~/dzuav_deploy/air_ground/onboard/dzuav/build/dzuav` |
| dzuav 窗口 "找不到二进制" | `orin_run_dzuav.sh` 的 `DZUAV_DIR` 默认指向旧目录 `~/ag_test/dzuav` | `export DZUAV_DIR=~/dzuav_deploy/air_ground/onboard/dzuav` 后重启 |
| dzuav "找不到引擎文件" | `~/dzuav/engines` 缺 `.engine`（换机后没转换） | 跑 `tools/orin_convert_engines.sh -o ~/dzuav/engines`；也可用 `HBB_ENGINE/CELL_ENGINE` 环境变量指到别处 |
| `localized=0` 一直不变 | 高度/位置看不到 ≥4 个分散格号；或格号凸包面积 <2% 画面（PnP 病态） | 升高/移动至格号分散视野；确认地面格号未被遮挡 |
| dzuav 有目标但车端无情报 | UDP 广播没到车（跨网段/路由器隔离） | 笔记本 `monitor_link.py` 分段定位：机上能收到→查车端网络；都收不到→查 dzuav 端口(50000)与网络 |
| teleop 按键无反应 | teleop 不在真实 TTY | 在 tmux 窗口内敲键；确认窗口没死（`bringup.sh status`） |
| 按了 `4` 但航线不动 | Goto 许可条件不满足（非 HOVER/本地位置无效） | 先 `1` 起飞稳定悬停后再 `4`；看 control 窗口 `goto_enabled` 日志 |
| odom 窗口 EKF reset 风暴告警 | SLAM 跟丢/双实例并行（v2 补丁会自动 L3 冻结并告警） | 悬停勿动；看 `[px4_odom_convert_blackbox]` 4 行归因；双实例 ERROR → `down` 后重新 `up`（补丁启动时会拒绝第二实例） |
| 起飞即漂/坐标跳 | 地图未加载或初值错（localizer 重定位失败） | 降落重起 fastlio/localizer，检查 relocalize 初值 |
| 面板黑匣子没数据 | bringup 在面板之后跑过，tmux 被重建 | 重开 `flight_console.py` 即自动恢复黑匣子 |
