## 1. 赛题：规则硬事实

### 1.1 场地与固定结构

| 要素 | 数量/形态 | 关键约束 |

| **障碍物** | 随机 **8 个**，装满水的彩色带盖塑料桶，格中央 | 有高度/体积，雷达可见；遮挡 LOS |
| **打击区** | **相连的两格**（横或纵），**单局仅 1 处**；内放**移动电子靶**（红/蓝面） | 打蓝得分、打红扣分（内部口径） |
| **桥洞** | 2 处，35 cm 挡板架空结构，各通道用隔板隔离；**K 列** | 每局由裁判**随机指定可通行通道**，**通行状态标在桥洞顶部箭头**上 |

### 1.3 赛制支点（整场比赛的设计根据）

> 规则原文（p8）：「**地面机器人由于视角限制无法直接识别桥梁顶部设置对应标识，必须由无人机完成高空侦察**」。

⇒ 无人机的存在意义被规则绑定在「读桥洞顶部箭头」上；车端必须能消费「哪个洞可通」这一条情报，否则无人机只是可选加分项。**任何削弱这条链的改动都是在拆赛制支点。**

### 1.4 计时与计分（口径要分清）

- **3 分钟总预算（180 s）**：来自队内澄清与代码默认 `mission.race_budget_s = 180`（`core/config.py:273`；`docs/黑图探索与动态规划_决策层方案.md:228`）。**官方 PDF 只有场地布置，没有计分表**〔未〕。
- 打靶计分（蓝面得分/红面扣分、有效命中 = 车→靶连线落在蓝面法线 ±45°）来自**队长两轮澄清**（`docs/空地联合仿真设计.md:13,15`）〔档〕，**不要当赛规引用**。
- 时间轴裁决：D-014/D-017/D-020——发车前只做 **10 s 系统自检**；**Go 条件 = 起点格 + 首段 6~8 航点 + 一格缓冲可靠**；全场 layout 是**运行中里程碑**（约 37.1 s），不是发车门票；等全场再发车反而 188.6 s 超时。

### 3.2 八线程（频率已对源码核实）

| # | 线程 | 频率 | 职责 |
|---|---|---|---|
| 1 | LocalizationTask | 20 Hz | 定位投影、到位吸附、漂移/边界护栏、**航向完整性守卫**（差速包络 + 可恢复闩锁） |
| 2 | SafetyTask | 20 Hz | **唯一强制停车者**：五道看门狗 + `SAFE_STOP` 故障闩锁 |
| 3 | TrackerTask | 50 Hz | 纯追踪 → `pursuitAngle`（底盘指令唯一写入者）；PIVOT/倒车/ALIGN 入口 |

### 3.8 现场会咬人的坑（精选）

1. **布局模式启动坑**：`--map` 指向**存在的**文件 ⇒ 进文件模式，StepLoop 收布局也不规划；必须传**不存在的**路径（`/tmp/__no_map_for_steploop__.yaml`）。而 `start_all.sh:220` 恰好传 `config/map.yaml` ⇒ 车上有该文件时永远进不了布局模式。
2. **`cam_viewer` 抢 `/pursuitAngle`**：以 20 Hz 发全零，底盘每帧更新目标速度 ⇒ 车「收到了但不动」。跑车前必须 kill（车端可能仍有残留）。
3. **非交互 SSH 域号变 0**：ping/SSH/网页全通，ROS 互相看不见且零报错；起栈/调试必须 `source dzros.env`。
4. **`robot.yaml` 顶层裸键**会让相机/视觉/云台三节点同时 abort（地图必须放 `config/map.yaml`）。
5. 云台 PID 三处口径不一：仓库 `12.0/0.5/2.4`、现状报告 `12/1.0/2.0`、10-19 车端 `10/0.5/2.0`——调参前先 `diff`。
6. `restart_node.sh path` 指向旧核；改路线/速度必须 `start_all.sh restart`。
7. `healthcheck` **不是起栈门禁**（自检已收敛到发车前 10 s 窗口）。

## 4. 机端 `dzsmartscout`

### 4.1 一句话定位

**不是会自主规划的无人机，而是「人手动飞一遍 → 录轨迹 → 机器照轨迹回放」的回放式路径跟随系统**，外加上层「视觉侦察 → 向小车下发路线/情报」的单向指挥链。全仓**没有任何真机飞行/Offboard/自动起飞/路径回放记录**（`无人机项目总览.md:22-28`、`无人机架构总览.md:48`；交接文档明写「端到端实战尚未跑过一次完整飞行」）。

### 4.2 硬件与软件栈

## 5. 空地链路与 StepLoop

### 5.1 话题契约

| 话题 | 类型/QoS | 方向 | 用途 |
|---|---|---|---|
| `/nav/waypoint` | `std_msgs/String`，**RELIABLE depth 10** | 机 → 车 | 路线 token（`load:`/`reset:`/多点）与段目标 |
| `/dzlink/drone_to_car` | JSON，**BEST_EFFORT depth 10 VOLATILE** | 机 → 车 | 情报、**布局/layout 版本**、心跳 |
| `/dzlink/car_to_drone` | JSON，BEST_EFFORT | 车 → 机 | 车态、ack、覆盖账本 |
| `/aim/fire_gate`、`/nav/scan_request` | — | 车内 | 开火/扫描闸门 |

**铁律**：BEST_EFFORT 发 → RELIABLE 收 = **静默 0 条**，但两端端点计数仍各为 1（t4 真机 8 格矩阵实测）。**ack 是唯一硬证据**。心跳超时 **3.0 s**、情报过期 **30.0 s**（`robot.yaml:840-841`）；桥洞窗口 2.0 s。

### 5.2 StepLoop（当前主线）

```
机：读布局/情报（/dzlink，10 批）→ 决定段目标 → /nav/waypoint 下发路线
车：WAIT_LAYOUT → PLANNING → DRIVING → SEGMENT_DONE → 机侧消费后发下一段
机侧 1.4 Hz 读车态 → 决定下一段 → 再下发新版本
```

- D1 已实车验证：10-18 晚连续 6 段自动推进（含 1 个射击停站），机侧首次消费 `SEGMENT_DONE`。
- **D1b**：`SEGMENT_DONE` 窗口只有 1~2 拍，1.4 Hz 采样漏收率约 86%；代码已加「完成单闩锁 + 1 Hz 重发 + `done_seq`」，未实车复验。
- **D2**：到站后 `block` 与 target 差半格/一格；机侧 `block==target` 判据会永久卡住。
- 布局过期语义（D-022）：过期只拦新规划 → `WAIT_INFO(layout_stale)`；**完整布局（known=154）例外，视为静态场地信息**，防无人机掉线后停半路。

### 5.3 赛时时间轴（180 s 内）

| 阶段 | 内容 | 依据 |
|---|---|---|
| T0–10 s | 系统级并行自检（车 6 + 机 4 + 跨 2，只读），**不输出 GO** | D-017 |
| T10–45 s | 无人机全场扫描（目标 ≤35 s，累积式 layout 154/154） | D-017 |
| Go | **起点格 + 首段 6~8 航点 + 一格缓冲**覆盖可靠即发车 | D-020 |
| 段边界 | 等增量新版本 **≤10 s**；超时用最后完整布局继续，不跳点/不完赛 | D-015 |
| 全场 layout | 约 37.1 s 的**运行中里程碑**，不是发车门票（等全场再发 = 188.6 s 超时） | D-020 |

## 12. 术语表

| 术语 | 含义 |
|---|---|
| **token / 点** | 路线上的一个航点（格心序列，可带 `R:` 倒车、`:PIVOT` 原地转、`*` 停站后缀） |
| **停站 / `D3*`** | 到点后停车执行动作（mine=压雷、shoot=射击、stop=普通停） |
| **双停站** | 靶板两侧各一个射击停站（防靶在背面时打不到）；当前 tour 只出单停站 = T35 缺陷 |
| **穿洞** | 穿过 K 列桥洞；U 形赛道要求上下半场各 1 次、方向相反 |
| **布局 / layout** | 无人机侦察得到的「已知格集合 + 要素」，带版本号，154 格为完整 |
| **StepLoop** | 机侧按段下发、车端逐段规划执行的闭环（WAIT_LAYOUT→PLANNING→DRIVING→SEGMENT_DONE） |
| **belief** | 车端对自身所在格的信念（定位投影结果） |
| **SAFE_STOP** | 安全闩锁：故障后强制停车，部分原因（如 `yaw_untrusted`）**永不复位，必须重启栈** |
| **known-red** | 已登记、已裁决的回归红项；名单外任何一红 = 新增红，不得放行 |
| **PIVOT** | 原地转向 token；tracker-safe 引擎禁 180°，tour 支持 |
| **三引擎** | `tour`（现役）/ `tracker-safe`（降级候选）/ `global_planner`（仅参考，不得转正） |
| **T-HEAD / task-44** | 10-19 航向闩锁修复（差速包络 + 可恢复 + 跳变/IMU 三闸） |
