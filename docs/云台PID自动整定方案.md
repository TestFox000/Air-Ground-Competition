# 云台自瞄 PID 自动整定方案

> 对象：`dzrknn_dataprocess`（C++，车端 `~/dzrobot/src/dzrknn_dataprocess/src/dzrknn_dataprocess.cpp`）
> 目标：不再"手工试参数"，用**先辨识、再算、后验证**的三段式把 kp/ki/kd 一次定稳
> 状态：方案 + 脚本已就绪，**未在实车跑过**（脚本已通过 Python 编译检查）

---

## 0. 为什么现在手工调参一直在原地打转

最近三组参数（12/1.1/1.8 → 12/0.5/2.4 → 12/1.0/1.8）反复换，但**换哪组都在振**。原因不是"没找到那组魔法数字"，而是缺一个量：

> **a = px/tick**（云台转 1 个刻度，画面里的目标移动几个像素）

这个数决定"Kp 能开到多大"，而它**没有人量过**。用源码里的控制律可以把它写成闭式条件（积分器 + 纯延迟，相位裕度 0）：

```
Kp_max ≈ (π/2) / (a · θ)        θ = 视觉端到端延迟 ≈ 0.26 s（源码注释实测口径）
```

同一个 Kp=12，a 不同结局完全相反（同一模型、同一初值，仅 a 不同）：

| a (px/tick) | Kp 上界 | Kp=12 的仿真结果 |
|---|---|---|
| 0.35 | 17.3 | 0.83 s 收敛，超调 15%（能用） |
| 1.20 | **5.0** | **振荡发散，稳态 RMS 658 px（废）** |

**所以第一步不是调参，是量 a。** 量完 a 和 θ，Kp 的上界就是一个数，而不是猜。

## 1. 可用的物理事实（全部来自源码/实测，不是假设）

| 项 | 值 | 来源 |
|---|---|---|
| 控制律 | `u = Kp·e + Kd·d(e)/dt + ∫Ki·e·dt`，u 单位 **ticks/s** | `pidStep()` L655-720 |
| 位置增量 | `Δθ = u·dt`，另有 `|Δθ|<1 tick` 不下发的 min_step 闸 | 同上 |
| 输出限幅 | `trackSpeedCap()` = 2000 tick/s（横幅实测） | L636 |
| 积分限幅 | `pid_i_clamp = 600`，且 PD 顶到 95% 限幅时**条件积分** | L697-706 |
| 微分滤波 | 一阶低通 `d_alpha = 0.3` | L689 |
| 死区 | `track_deadzone_px = 5`（误差先扣死区再进 PID） | robot.yaml L124 |
| 视觉 | `offset_center` **30 Hz**，端到端延迟约 **0.26 s** | 源码注释 L686 |
| 主循环 | TRACK 100 Hz / 空闲 50 Hz（**但 PID 按视觉帧推进，dt≈1/30**） | `Control()` L1684 |
| 参数生效方式 | **只在启动时 `get_parameter` 读一次**，无参数回调 → 每组参数必须重启节点（约 8~10 s） | L1487-1493 |
| 命令通道 | `CameMo_Conl` = `[yaw_tick, pitch_tick, speed_y, speed_p]`（**位置+速度**协议） | L1701-1710 |
| 反馈通道 | `camemo_feedback` = `[Pos0, Pos1, Speed0, Speed1, Load0, Load1]` | L1105-1115 |
| 进 TRACK | 发 `/nav/scan_request = 2` | `scan_req.py` 实测可用 |

**关键推论**：a 是相机常数（`a = px/deg ÷ ticks/deg`），**与靶距无关**——量一次，换场地不用重量（除非换相机/改分辨率）。

## 2. 分四个阶段（P0 安全 → P1 辨识 → P2 扫参 → P3 闭环验收）

### P0 · 安全基线（每次都做，30 s）

1. 备份 `~/dzrobot/config/robot.yaml`；
2. 强制 `gimbal.max_shots = 0`（**整定全程一发都打不出去**，与 fire_gate 无关）；
3. `use_external_fire_gate` 保持当前值，不动；
4. 记录原始 kp/ki/kd，`trap` 保证异常也回滚。

### P1 · 开环辨识（`autotune_pid.py id`，约 60 s）

做三件事：
1. 读 `camemo_feedback` 拿到当前刻度 (yaw0, pitch0)；
2. **杀掉自瞄节点**（独占 `CameMo_Conl`，同时因为节点不在 → LaserShot 不可能发）；
3. 给 yaw 轴若干阶跃 `+60 / +120 / -60 / -120 tick`，每个保持 1.5 s 再回位；
   同步记录 `camemo_feedback`（实际刻度）和 `offset_center`（dx）。

量出三个数：
- **a** = Δdx / Δtick（稳态段求差）——直接读脚本打印；
- **伺服时间常数 τ**（64% 上升时间）；
- **延迟 θ**（命令发出 → dx 首次变化的滞后；若与 0.26 s 差得多，以实测为准）。

> 校验：a 应在 0.2~3 px/tick 量级；若某个阶跃回传的 Δdx 符号相反 → `yaw_deg_sign` 或轴序有问题，先修配置再谈调参。

### P2 · 离线扫参（`autotune_pid.py sweep`，10 s，不动云台）

用 P1 的 a/τ/θ 搭模型，扫 kp×ki×kd 网格（10×5×6=300 组），评分 = 调节时间 + 0.02·IAE + 0.02·超调 + 0.08·过零次数 + 0.05·稳态 RMS，硬约束（超调>25%、不收敛、过零>6）加大罚分。

输出**前 5 组候选**，进 P3。模型只用来"缩小候选集"，**不作为最终结论**。

### P3 · 闭环验收（`autotune_pid.py verify --sets "k1;c2;..."`，每组约 12 s）

对每组候选：
1. 改 yaml（kp/ki/kd，`max_shots=0`）→ 重启节点（8 s）；
2. 发 `/nav/scan_request=2` → 等 `/aim/status == 2 (TRACK)`；
3. **静止靶**，从初始偏移（建议 60~80 px）开始，连续采 6 s 的 `offset_center`；
4. 算指标：调节时间 / 超调 / IAE / 过零次数 / 稳态 RMS；
5. 结果追加写 `~/robot_logs/pid_autotune.json`；无论成败都回滚参数。

前三组若都不达标，按 P2 排序继续下一批（最多 9 组，总时长控制在 15 min 内）。

### P4 · 落盘与回归

1. 取综合最优组写回 yaml（保留备份）；
2. 用**同一静止靶**复测一次，指标与 P3 一致才算收口；
3. 记录：a/τ/θ、最终参数、指标表、试验次数、日期——写进 `docs/` 与提交信息；
4. 若最优组与当前手工值差距 >30%，**先跑一次完整循迹再看**，防止瞄准环变好但带动云台抖。

## 3. 判定标准（可量化，不靠"看着差不多"）

| 指标 | 阈值 | 说明 |
|---|---|---|
| 调节时间（初始 60 px → ±5 px） | **≤ 1.0 s** | 约 4 倍延迟，低于此值在 0.26 s 延迟下不现实 |
| 超调 | **≤ 15%** | 超过则贴靶框边会来回蹭 |
| 过零次数（0.3 s 后） | **≤ 3** | 振铃直接表现为打不准 |
| 稳态 RMS（最后 2 s） | **≤ 4 px** | 死区 5 px 决定了理论下限就在 3~4 px |
| 静止靶 `fire_ready` 占空比 | **≥ 80%** | 最终的"能不能打"指标 |

**安全中止条件**（任一触发即停并回滚）：
`|dx| > 200 px` 持续 0.5 s ｜ `offset_center` 断流 > 0.3 s ｜ 节点进程消失 ｜ 单组超 12 s ｜ 累计超 15 min ｜ 云台刻度打到 100/3995 边界。

## 4. 时间与代价

| 阶段 | 时长 | 需要动云台 | 需要靶 |
|---|---|---|---|
| P0 安全基线 | 30 s | 否 | 否 |
| P1 辨识 | ~60 s | **是**（4 次阶跃） | 是（视野内有特征即可） |
| P2 扫参 | 10 s | 否 | 否 |
| P3 验收 | 12 s × 3~9 组 = 1~2 min | 是 | 是（静止） |
| 合计 | **3~4 min** | | |

对比手工调：一次"改 yaml → 重启 → 看日志 → 再改"至少 1 min，且没有可比的指标。自动整定一轮就是 3~4 min 出**可比数字**。

## 5. 已知风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 靶被人手晃 | 指标全失真（这是上次"看着振"的最可能原因） | 整定必须**静止靶**；脚本会记录 dx 的抖动，稳态 RMS > 8 px 直接判该组无效 |
| a 量错（轴序/符号） | Kp 上界算反，越调越糟 | P1 用 +60/-60 双向阶跃自校验符号；不一致则中止 |
| 延迟比 0.26 s 大 | Kp 上界被高估 → 振荡 | 以 P1 实测 θ 重算；Kp 取算出的 70% 作起点 |
| 死区导致小误差不动 | 稳态 RMS 下不去，误判"参数差" | 阈值按 4 px 起算，不追 0 |
| 参数只在启动时读 | 每组 8 s 重启，慢 | 可接受；后续可给节点加参数回调（20 行，改完可在线换参，试验从 12 s 降到 2 s） |
| 云台撞限位 | 机械损伤 | 脚本限制单次阶跃 ≤120 tick，且读反馈确认未到 100/3995 |
