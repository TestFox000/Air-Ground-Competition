## 2. 接口表（`GET/POST /api/dzrobot-ssh/...`）

| 方法 | 路径 | 入参 | 出参 |
|---|---|---|---|
| GET | `/sim.html` | — | 页面（`text/html`） |
| GET | `/sim/root` | — | `{root, ok}` |
| GET | `/sim/map` | — | **只读场地**：`{ok,root,source,md5,grid{cols:14,rows:11,blockM:0.35},name,start,end,mines[],obstacles[],targets[],bridges[],barrier{colFrom,rowHi,rowLo},drone{takeoff,land,source},editable[],route[]}` |
| POST | `/sim/run` | JSON：`{label, overrides, inject, maxSteps, seed, field?}` | `{ok, record:{id,…,seed,route,routeSource,field?,plan?,override?,configUsed?,status,exitCode,seconds,metrics,files}, stdoutTail}` |
| GET | `/sim/history` | — | `{ok, runs:[record×≤50]}`（台账 `artifacts/sim/run_meta.jsonl`，**追加不覆盖**） |
| GET | `/sim/artifact` | `?path=<run>/<file>` | 产物（白名单 `.svg/.csv/.json/.txt`；`..`→403，非白名单→404） |
| POST | `/sim/check` | — | `{ok, results:[{id,name,exitCode,timedOut,tail}]}` |

> **台账 `run_meta.jsonl` 不可经 `/sim/artifact` 下载**（它是 run 子目录的**兄弟文件**，要台账走 `GET /sim/history`）；调用形状**只有** `?path=<run>/<file>` 一种：`?run=…&name=…`、`?id=…` → **404**（不是"文件不存在"）。
> 历史每行的「看图」（t27）取的就是 `?path=<该行 id>/traj.svg`：**按需**（打开页面 0 请求，点一次 +1，同行走缓存），
> 无产物行给可读 404 文案；深链 `sim.html#view=<run id>` 直达某次图。

## 3. 参数表（页面字段 → 请求 → `sim_cli`/规划器）

| 页面字段 | 请求字段 | 落到命令行 |
|---|---|---|
| 备注名 label | `label` | 台账 `label`（同时进 `run id`） |
| 巡航速度档 0.15/0.35/0.40/自定义 | `overrides["pursuit.cruise_speed_mps"]` | `--set pursuit.cruise_speed_mps=X` |
| 速度比例误差 / 偏航漂移 / 位置噪声 / 指令延迟 | `inject.{speed_scale_err,yaw_drift,pos_noise,latency}` | `--speed-scale-err/--yaw-drift/--pos-noise/--latency` |
| 到位吸附开关 | `inject.anchor:"on"` | `--anchor` |
| **seed（留空 = SimConfig 默认）** | `seed` | `--seed N`（留空**不传**）。★ seed 只影响**含随机源**的仿真（位置噪声/偏航漂移等）：默认无注入时结果与 seed 无关（四次跑 traj.csv 哈希相同 = t20 基线）；带 `pos_noise=0.02` 时同 seed 两次一致、异 seed 不同 |
| maxSteps（留空 = 全程） | `maxSteps` | `--max-steps N` |
| **改点位（雷/障/桥洞）** | `field.{mines,obstacles,bridges}` | 不直接进 argv：先落运行目录 override，再 `--config <副本> --route <重规划路线>` |

> 铁律：**只读 config**（改参数一律 `--set` / `--config 副本`），产物只落 `<root>/artifacts/sim/<run id>/`（gitignore 内）。
> 改点位三步：① 写 `map_override/map.yaml`（只替换 mines/obstacles/bridges 三行）+ `robot.yaml`（真源逐字副本）；② `python tools/plan_route.py --config 副本 --map override图 --emit json --check --quiet` **只读**重规划；
> ③ sim 用 `--config 副本` + `ROBOT_MAP=override图` 运行。**仓库 `config/**` 与 `src/dzbrain/**` 零写入**。

## 6. 已知边界

1. **页面刷新由用户执行**：面板第 5 行/图标在 `client.js` 里，浏览器刷新后可见 —— **待用户刷新验证**（t21/t25/t27 都不声称"打开即生效"）。
2. **指标键集与形状**：`record.metrics` = `finished`(bool) + `time_s`/`rms_m`/`length_ratio`/`out_of_bounds`（数值，出现时必须为 0）；`exitCode`/`status` 在 `record` **顶层**。**历史对比勿把缺键当 0**（首条历史无 `out_of_bounds` 键，页面按缺键显示 `—`、不参与 Δ）；`maxSteps` 冒烟 ≠ 全程。
3. **历史看图是"按需取图"（t27）**：打开/刷新页面**不发任何** `/sim/artifact` 请求（前端计数器 `#fetchCount` 实时可见）；点某行「看图」才发 1 次（同行走 `shotCache`，0 次）；无产物行（如 `plan-failed`）modal 给「该次运行没有生成轨迹图（traj.svg 不存在）」+ HTTP 状态。计数器也统计"结果预览 traj.svg"与"本局轨迹 traj.csv"这两处**本局**取图（不是历史预取）。深链 `#view=<run id>` 可直达某次图（属显式动作）。

4. **两个现场陷阱（t25 实测踩过）**：① sim_cli 的路线**文件**解析按空格/逗号切词 ⇒ 末点后缀 `N5,y` 被切成独立 token 报 `❌ 无法解析的 token: 'y'`，故 `route.tokens.txt` 已剥后缀（原样 token 另存 `route.tokens.planner.txt`，实测剥与不剥 traj.csv 逐字节相同）；② 现场 YAML 是 CRLF，解析前必须归一换行，否则 `$` 锚点与 `- item` 块序列全匹配不上。

5. **`sim-root.json` 指权威真源**（`比赛存档\v1\dzrobot_v2`）：两份 `robot.yaml`/`map.yaml` 逐位相同，跑错副本**不会自我暴露**；pnpm 重装会丢该文件（届时 `/sim/root` 如实 `ok:false`）；`DZROBOT_SIM_ROOT` 优先级最高；**改指针须队长明确指令**。
6. **改点位只覆盖雷/障/桥洞**（验收范围）：靶/起终/隔板/网格保持现场值；规划/校验不过时 `status=plan-failed` + HTTP 422 + **不进仿真**，原因入台账。**非法格名不再静默丢弃（t26-L1）**：整类都是非法格名时页面**拦下不发请求**并列出条目；部分非法则在提示与完成消息里写明"已忽略"。宿主侧 `record.fieldDropped` 归口未做（`src/simbench.js` 不在 t27 边界，可另开卡）。
7. **部署对账口径 = 「6 文件 × 3 处」（t26-L3）**：`scripts/` **不**进 `package.json#files` —— 试过加白名单，自带 `test-package-files.mjs` 会**立刻 FAIL**（该测试把"scripts 不被声明"当判别力负样本），故维持原状：安装副本里的 `scripts/` 是历史手工同步产物，`check-divergence.mjs` 只在源树/来源树（归档树跑 exit=1 = 4 条"profile/pnpm-lock 声明的是原树"，原树 exit=0；未改 profile/pnpm-lock，不在边界内）。

## 8. 2026-10-18 更新：压测两种模式 + 引擎选择 + 补图（规划器压测）

> 背景：64 图压测 `64/64 plan-failed`，根因不是随机图，而是 `planner.engine=tracker-safe` 与现役 68-token 路线的 3 个 `:PIVOT` 结构性冲突（tracker-safe 明确禁 180°/禁紧凑 U）。详见 `docs/项目现状_20261018.md` 与 `test-sim-stress-plan.mjs` A 组。

| 项 | 内容 |
|---|---|
| 页面 | 压测面板新增 **模式**（跟踪 / 规划）、**引擎**（跟随 robot.yaml / tour / tracker-safe）、**补图** + 重试上限；结果统计新增 planned / plan-failed / generator-unsolvable / 成功率 / token 均值 / 引擎分布 / 失败主因 |
| 新语义 | **规划压测**：每张图只跑一次 `plan_route`，不进入仿真；`plan-failed` 即规划器真实失败率（不补图，避免选择偏差）。**跟踪压测**：规划 + 完整仿真；勾「补图」时先 `checkPlan` 预筛，失败换图，耗尽记 `generator-unsolvable`（单列，不并入规划失败率） |
| 新宿主函数 | `src/simbench.js`：`checkPlan({field, engine})` —— 只写系统临时目录（用完即删），`config/` 与 `artifacts/` 零写入；`plannerEngineChoices` 导出供压测校验（非法引擎 400，不静默回落） |
| API | 沿用 `POST /sim/stress`，新增 body 字段 `mode: 'track'|'plan'`、`engine?: string`、`resample?: boolean`、`maxAttempts?: 1..20`；summary.batch 记录 mode/engine/resample/maxAttempts |
| 新守卫 | `node scripts/test-sim-stress-plan.mjs` → **27/27**：官方图 tour 68 token / tracker-safe 无解；规划模式只产 planned/plan-failed；非法引擎 400；`stressStats` 三分计数；label 含下划线的 batchId 可回读；压测输入与「场地来源」解耦；页面接线 |

| 引擎冲突提示 | 页面在 `tracker-safe + 本图有 :PIVOT` 时红字提示「结构性无解，压测请显式选 tour；车端自动规划要跑通需负责人把 `planner.engine` 改 tour（本页不改配置）」 |

边界：
1. **未改 `config/robot.yaml`**：是否把车端 `planner.engine` 切 `tour`（以及 `allow_reverse`）属产品裁决，本卡只给证据与 what-if；页面显式选 tour 只影响本次运行（`engineSource=explicit`，台账可查）。
