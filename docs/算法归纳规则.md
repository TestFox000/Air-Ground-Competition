> 用户 2026-10-11 下达：**任何路线/参数修正，必须同步归纳进"车的规划器"本身**，
> 不许只改一份"验证用的路线文件"或只在报告里写结论。
> 本文是该铁律的落地说明 + 自检命令 + 历史实例。

## 1. 一句话

**一条路线只有一个真源：车上的 `plan_route(map.yaml)`。**
仿真验证过的路线、`route.tokens` 回退路线、`mission_blocks`、报告里贴的 token 串，
必须都是**同一次规划的同一条路线**（逐 token 一致）。

## 2. 四处必须一致（缺一处就会出现"仿真跑的是 A、车跑的是 B"）

| # | 位置 | 内容 | 谁在消费 |
|---|---|---|---|
| ① | `src/dzbrain/dzbrain/route/planner.py` | 算法与**默认值**（代价、惩罚、阈值等常量） | `plan_route()` 本体 |
| ② | `config/robot.yaml` 的 `planner:` 段 | 同名的可调参数（键缺失时用 ① 的默认值，**行为不变**） | 车端启动时的自动规划 |
| ③ | `tools/plan_route.py` CLI | 同名开关，**缺省 = 跟随配置**（不是各自写死一个数） | 人/CI 手动复核 |
| ④ | `config/robot.yaml` 的 `path_executor.mission_blocks` | **回退路线**（规划失败时用），必须等于 ① 对当前 `map.yaml` 的输出 | `route.tokens`（由 core.config 迁移）→ MissionTask 回退分支 |

★ ②③ 的缺省值必须写成"跟随配置/跟随模块常量"，**不要在 CLI 里另写一份数字** —— 三处各写一份，改一处就会出现静默分叉。

## 3. 自检命令（改完必须跑，全绿才算归纳完成）

```powershell
Set-Location D:\User\Desktop\dzrobot_v2
$env:PYTHONPATH='D:\User\Desktop\dzrobot_v2\src\dzbrain'
$env:PYTHONIOENCODING='utf-8'; $env:PYTHONUTF8='1'

# ① 车端规划器输出（默认跟随配置）
python tools\plan_route.py --emit tokens --quiet          > _tmp\plan_tokens.txt
# ② 回退路线（route.tokens 由 mission_blocks 迁移）
python -c "import sys;sys.path.insert(0,r'src\dzbrain');from dzbrain.core.config import Config;c=Config.load('config/robot.yaml');print(' '.join(c.get('route.tokens')))" > _tmp\cfg_tokens.txt
# ③ 逐字节比对（必须一致）
python -c "a=open(r'_tmp\plan_tokens.txt',encoding='utf-8').read().split();b=open(r'_tmp\cfg_tokens.txt',encoding='utf-8').read().split();print('IDENTICAL' if a==b else 'MISMATCH');print(len(a),len(b))"
# ④ 出车前六层校验
python tools\plan_route.py --check
```

判定：③ 打印 `IDENTICAL` 且 ④ exit 0（0 error）。

## 4. 改动一条路线时的完整清单

1. 改 `map.yaml`（地图要素）或 ① 的算法/默认值；
2. 跑 `tools/plan_route.py --emit tokens --quiet` 拿新路线；
3. 用 `_tmp_session/sim_map_auto.py` 跑仿真（**每次都要出 `route_map.png`**，见《路线图流程.md》），逐条核对验收项；
4. 把新路线写进 ④（`mission_blocks`），把调过的参数写进 ②；
5. 跑 §3 自检（IDENTICAL + 0 error）；
6. 跑 19 套测试；**因换图/换路线而红的断言**按"期望值换成新真值"重钉，**不得降低断言强度**（不许改小等式、不许加容差、不许 `or True`、不许删断言），并在报告里逐条写理由；
7. 报告里贴：命令、原始输出、逐 token 对照、route_map.png 路径。

## 6. 已知坑（归纳时别踩）

| 坑 | 现象 | 规避 |
|---|---|---|
| `--route <文件>` 读不了末点 `,x` | `❌ 无法解析的 token: 'x'`（`_read_token_file` 按 `[,\s;]+` 切分） | 文件里末点写 `N5`（默认即朝 X+），或在 config 里写 `N5,x` |
| 前视被上限钳住 | `ld = clip(1.2×v, min, max)`：提速不提 `lookahead_max_m` → 轨迹逐位相同 | 改速度必同时复核 `lookahead_max_m > 1.2×v` |
| 把"期望值"写进三处 | 改一处另两处不跟着变 | ②③ 一律"跟随配置/模块常量" |
| 静默跳过的测试 | `except Exception → check(True,"skip")` 让整段假绿 | 该模式改为失败或单列 skip 计数 |

## 10. §3 自检命令的编码坑（本轮实测）

§3 里的 `> _tmp\plan_tokens.txt` 在 **Windows PowerShell** 下会写成 **UTF-16LE（BOM 0xFF 0xFE）**，
第 ③ 步 `open(..., encoding='utf-8')` 直接抛 `UnicodeDecodeError: byte 0xff in position 0`。
等价可用写法（已实测 `IDENTICAL`）：

```powershell
python tools\plan_route.py --emit tokens --quiet | Set-Content -Encoding utf8 _tmp\plan_tokens.txt
python -c "...print(' '.join(c.get('route.tokens')))" | Set-Content -Encoding utf8 _tmp\cfg_tokens.txt
python -c "import pathlib;a=pathlib.Path('_tmp/plan_tokens.txt').read_text(encoding='utf-8-sig').split();b=pathlib.Path('_tmp/cfg_tokens.txt').read_text(encoding='utf-8-sig').split();print('IDENTICAL' if a==b else 'MISMATCH',len(a),len(b))"
```
