# 路径规划系统交接文档 — 2026-10-11

> 无人车路径规划模块移交。目标：接手人能跑通路径生成→命令编码→
> 车端执行全链路，理解场地物理约束和算法决策。

## 一、任务背景

给定场地态势（雷区/障碍/桥洞/起点终点），生成智能车从起点到终点
覆盖全部雷区的全局最优路径，编码为车端可接收的命令串。

已交付能力：
1. 全局最优路径：Held-Karp 位压 DP 求 TSP 最优解（访问全部雷格）
2. 朝向感知寻路：8 邻域 Dijkstra，考虑转向代价，起点/终点朝向约束
3. 命令编码：输出 reset:N10,y + 格号序列（* 标记射击格）
4. 路径压缩：删除同向共线中间格，保留拐点和必经点
5. 禁火保险：fire_guard 防止在非射击格误开火
6. 朝向对齐：align 模式用无人机 0x4002 真实 yaw 闭环转向

## 三、算法核心

### 3.1 Held-Karp 位压 DP（TSP 全局最优）

访问全部雷格的最短路径。雷格数 <= 15 时位压 DP 可承受。

### 3.2 朝向感知 Dijkstra

- 8 邻域移动，转向有代价（每 45° 转向约 0.76 格，可配）
- 状态 = (格, 航向)，航向为 8 方向（45° 粒度）
- 起点/终点有朝向约束
- 桥洞必须正交贴门通过，禁止斜穿

### 3.3 场地物理约束（mission_router.py 写死）

- 中场横向挡板：位于第 6/7 行之间的边界线（`_MID_BOUNDARY=6`，0 基 row5↔row6；上半场=行1~6、下半场=行7~11），仅覆盖 D~N 列，
  **A/B/C 列无挡板可自由穿越**
- 桥洞列不写死：由 ARROW（passable）动态推导；桥洞列内仅箭头格 + 朝向挡板
  一侧 1 格引道可通行，其余格为墙（桥洞列南北不连通）
- 穿越中线限定正交且贴可穿越格（禁止斜穿）
- ⚠️ `cross_gates` 一旦显式传入（非空），自动推导整体关闭，A/B/C 列
  自由穿越一并失效——只有列出的 gate 格可穿越中线
- 靶格不可踩：停靠正交相邻格瞄准射击
- 射击格：正对轨道端点（D8<->E8）的正交相邻格

### 3.4 命令编码格式

    reset:N10,y              # 重置到 N10，车头朝北
    N10 N9 N8 ... E1* E2,y   # 空格分隔格号，* = 在此格停车射击；
                             # 末尾 ,x/,y = 终点朝向，逗号紧贴最后一个格号

## 五、已知问题与下一步

1. 路径绕行：跨半场只能走桥洞缺口（ARROW 动态推导，示例按 L 列）或 A/B/C 列，绕行增加里程是几何必然
2. 朝向对齐依赖：align 模式需无人机 0x4002 帧提供真实 yaw；**且必须在 path_executor
   启动前完成**（dzactuator 模式仲裁：pursuitAngle 保活钉死模式2，/cmd_vel 被丢弃），
   标准流程 `tools/car_match_bringup.sh` 两阶段启动（2026-10-15 契约修复）
3. dry_run 默认开启：联调确认后手动关闭才真正发车
4. 移动靶射击时机：需 det_node 确认靶位置
5. 官方 path_executor 在 (20°,45°] 拐角有潜在停死窗口（预瞄钳顶点 + PIVOT 只覆盖 >45°，
   顶点 1cm 圆盘内停下会信念冻结）——2026-10-15 离线仿真发现，概率低；实车若停死，
   补发一条单点命令即可脱困
