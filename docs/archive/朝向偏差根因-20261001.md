# 画圆根因：定位完成（2026-10-01 实测）

结论：**车“以为”的朝向与真实朝向相差一个恒定的 68.6°，纯追踪因此永远把目标看偏，绕着目标画圆。**

不是以下任何一条（都已用实车数据排除）：

| 假设 | 实测结果 |
|---|---|
| 定位 yaw 漂移 | 排除：静止 10 s 只漂 +0.1°，官方 EKF 那一路 +0.0°，两路差 0.6° |
| angular.z 符号接反 | 排除：指令 −10.6°，车实际转 −269°，方向一致 |
| angular.z 单位（度/弧度） | 排除：峰值 24.1 → 是度，与底盘 `z+60` 约定一致 |
| 速度折算差 | 排除：linear.x 最大 0.161 m/s，与代码设计（0.3 基础、弯中 ×0.5）吻合 |
| 转向机构/轴距 | 排除：理论角速度 −17~−18.6°/s vs 实测 −17.7~−18.9°/s，模型自洽 |

## 决定性证据

发一格命令 `N9`（目标 block 坐标 (2.5, 0.5)，车在 (1.5, 0.5)）：

| 21 | +57.2° | −12.3° | +69.5° |
| 23 | +22.6° | −45.9° | +68.4° |
| 25 | −13.6° | −82.2° | +68.6° |
| 27 | −49.6° | −117.9° | +68.3° |
| 29 | −87.9° | −156.5° | +68.6° |
| 31 | −124.4° | +166.7° | +68.9° |
| 33 | −158.6° | +131.6° | +69.8° |

**差值恒定在 68.6°±1°（14 秒内不变化）**——是固定偏置，不是漂移。

后果：车绕半径约 0.43 m（1.2 格）转圈，与目标的距离从 1.00 格一路涨到 1.32 格，永远到不了。

## 偏差从哪来

按 `path_executor.py` 的复位逻辑推：

```
belief = raw_map_yaw + snap_yaw_off
raw_map_yaw = raw_yaw + 90°                (RAW_YAW_TO_MAP_YAW_OFFSET)
snap_yaw_off = tyaw − raw_map_yaw(复位时)
=> belief − true = 90° − (复位时车的真实朝向)
```

实测 `belief − true = −68.6°` → **复位时车的真实朝向是 158.6°，而 `reset:N10,y` 断言它是 90°**。

即：**车被搬到起点时的实际朝向，与 reset 断言的朝向差了 68.6°**。
这正是我们自己代码里写过的坑（route_builder.py 头注：「车是被搬到起点的，里程计不知道自己在哪，所以每局必须先发 reset」）——
只是 reset 不只是断言位置，它还**盲目断言朝向**；朝向一旦断言错，整条路线就被整体旋转，车必然绕圈。
