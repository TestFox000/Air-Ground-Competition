## 1. 现状盘点

### 1.1 能力矩阵

| 能力 | 位置 | 现状 |
|---|---|---|
| 自动规划（车上启动即算） | `route/planner.py` → `plan_route()` | 读 `config/map.yaml`：A* 铺路 + 访问顺序/朝向联合优化 → 航点与 token；`mission` 启动时调用，失败按 `planner.fallback_to_tokens` 回退 `route.tokens` |
| **无倒车模式** | `Grid(allow_reverse=False)` / `_moves` | 现场 `planner.allow_reverse: false` ⇒ 动作集不含倒车，**0 段 `R:`**；折返改写为"原地掉头" |

## 2. 修复映射机制：什么修复要动规划器？

规划器的角色是"**每次修完问题之后更新路径规划器**"。判定用**三问**，任一"是"才动规划器：

| 问 | 判据 | 动规划器？ | 归属层 |
|---|---|---|---|
| Q1 几何变了？ | 顶点/走线轴/穿越口/访问顺序/雷靶位置需要不同的**路径几何** | **要** | `route/planner.py`（+ `config/map.yaml`、`route.tokens`） |
| Q2 只是"贴着同一条路径开得更好"？ | 速度/前视/舵角限幅/停车判据/到位吸附/漂移护栏 | 不要 | `pursuit/`、`tasks/tracker.py`、`tasks/localization.py`、`tasks/mission.py` |
| Q3 只是判据/口径/文档？ | 判分口径、报告、测试期望、遥测字段 | 不要 | `tests/`、`docs/`、`tools/`（只读复核工具） |

**动规划器后的硬门槛（缺一不可）**：① `plan_route.py --emit tokens --quiet` 重出路线并把新路线落盘到 `route.tokens`+`mission_blocks`；② 恒等式复核（四处逐 token 一致）；③ `--check` 六层 0 error；④ 全套件回归；⑤ sim 复跑并出 `route_map.png`。

### 2.1 实例一（第一个映射结论）：2026-10-11 直线标定欠程 11 cm —— **不动规划器**

| 项 | 内容 |
|---|---|
| 现象 | 直线标定 `N10→A10` 实测**欠程约 11 cm**（里程计/标定链条把距离读虚，车没走到格心就认为到了） |
| 修复落点 | `tasks/localization.py` 的模块常量 **`_GOAL_STOP_M = 0.03`**：末点（路线最后一个航点）的吸附半径从 `pursuit.arrival_m`(0.12) **收紧到 0.03**；`tasks/mission.py` 有同源引用（注释写明"对齐 `tools/sim.py` 的 `_GOAL_STOP_M`"） |
| 三问判定 | Q1 **否** —— 路线几何一字未变；Q2 **是** —— 改的是"何时算到位"；Q3 否 |
| **映射结论** | **不动规划器**（不改 `planner.py`、不改 `route.tokens`） |
| 证据 | 修复前后 `plan_route` 输出**逐 token 相同**（54 点 / 19.95 m / 1 处折返）；本次复核 `★ 四处逐 token 一致 = True` |

### 2.2 反例：哪些修复**必须**动规划器

| 修复类型 | 示例 | 为什么必须动 |
|---|---|---|
| 地图要素变化 | 雷/障/靶/桥洞位置、起点终点变化（换图） | 几何变了 ⇒ 必须重算并**重新落盘** `route.tokens`/`mission_blocks`，否则"车上跑的还是旧路线" |
| 压雷不达标 | 某雷被切角擦过（如 §1.3 的 6/8） | 需要改雷的进/出点轴或**访问顺序** ⇒ 属 Q1 |
| 合法性不过 | 非法跨隔板 / 闯 K 列未开放桥室 / 越界 / 折返点声明不一致 | 属 Q1（`route_check` 会红） |
| 只想更快/更稳 | cruise、前视、舵角、吸附 | **不动**（Q2）—— 改 `config/robot.yaml` 的 pursuit/localization 段即可 |
