## 2. 缺陷一：顶点处前视点塌缩（导致 F8 跳点）

### 2.1 链路（现场路线，F10 顶点，位姿 `(0.525, 2.975)` yaw=90°）

1. `tasks/localization.py:210-242` `_anchor`：**只改位置不改 yaw**，把车钉到 F10 格心
   （`config.py:125` `arrival_m=0.12` ⇒ 车还在拐角外 0.12 m 就被拽到顶点）⇒ **"正好站在顶点上"**。
2. `pursuit/path.py` `project()`（等距裁决约 336-359 行）：F10 处 **3 条段 d² 完全相等**
   （全 = 0.015876，差 `0.00000000 < _TIE_D2_M2=1e-6`）⇒ 投影落在**已走完的 seg9 端点 `t=1.000`**
   （等距时留下先遍历到的段）。
3. `pursuit/lookahead.py:49-56`：`clamp_m=0.04`（`pursuit.lookahead_vertex_clamp_m`），
   而 `proj.dist_to_vertex = 0 < 0.04` **恒成立** ⇒ 前视点被钳到**顶点 = 车身位置**
   ⇒ `controller.py` 弦长退化 ⇒ **`steer_deg = +0.0`**。
4. 实测后果：`k0..k125`（2.5 s）`seg9 s=3.500` **不动**、`dist 0.000→0.300 m`、`steer 恒 +0.0`、
   `v 恒 +0.120`；之后跳 seg11，在 `seg10(+0.150) ↔ seg12(倒车 −0.080)` 之间**每拍翻转**、
   dist 卡 0.27 m 不收敛 → 12 s 后「拐角绕圈兜底」跳点。

### 2.2 对照实验（同一起点）

| 场景 | 结果 |
|---|---|
| 吸附后真实 yaw=96.8° | 0.5 s 时 dist 0.059 m、舵角 +30°，随后转圈 |
| **yaw=90°（正好朝下一段的反向）** | **舵角恒 0、直行 2.5 s、dist→0.300 m**，随后极限环 |
| yaw=180°（车头已朝下一段） | max dist 0.122 m，5 s 内回路线 ✅ |
| 不做吸附 | max dist 0.124 m，5 s 内回路线 ✅ |

**逐候选定量**（车在 F10 以北 0.126 m）：同一物理点，投影选 seg9 ⇒ `d2v=0.000`、**舵角 +0.0°**；
选 seg10/13/14 ⇒ 同样距离但 `d2v=0.350`、**舵角 ±30.0°**。⇒ 投影选错段是零舵角的直接原因。

### 2.3 为什么仿真没抓到

`tools/sim.py:566` 明确有"**拐角顶点不锚**"的例外（`_anchor_allowed`），而**真实 `LocalizationTask` 没有这个例外**
—— 又一次"仿真绿掩盖实车问题"。另外 `tools/sim.py:676` 把仿真自己 `window_m=1.50` 的信念投影写进
`P_ROUTE_S`，Tracker 又优先用它当 hint（`tasks/tracker.py:293-295`）⇒ **日志里的 `段N s` 被仿真侧污染，
不能当实车行为读**（这也是日志值无法用 0.60 m 窗复现的原因）。

### 2.4 修复方案（已派发实施）

1. `pursuit/path.py::project`：**顶点前瞻重投影**（最优点贴在当前段端点且有下一段时，把 hint 推到下一段再投影一次，最多一次）。
2. `pursuit/lookahead.py`：`dist_to_vertex <= 1e-6`（车已站在顶点上）时**不做顶点钳制**，把 `s_target` 抬到顶点之后，
   保证前视点到车身距离 > 0.05 m。
3. （本地化侧，另一路）拐角点不把位姿拽到顶点 / 收紧该点 `arrival_m`。

### 2.5 附带发现（未修，已记录）

`tasks/mission.py:442-458` 用 `s + arrival_m >= s_at_waypoint(i)` 判"到点"：车被钉住/绕圈时 s 从 3.50 冲到 4.20，
于是 **#11 F11、#12 E11、#13 F11 三个从未走到的点被标记为"已到达"**（所以跳过报文报的是 F8 #15）。
⇒ 判"到点"除了弧长，应当同时校验**与航点的实际距离**。

## 3. 缺陷二：`P_ROUTE_S` 三个写入者 + Localization 链永久冻结（导致遥测离群）

### 3.1 机制

`P_ROUTE_INDEX/P_ROUTE_S` 的写入者：`tasks/localization.py`（20 Hz）、`tasks/tracker.py:367-368`（50 Hz）、
`tasks/mission.py:419-427`（10 Hz）。遥测"谁最后写就显示谁"。

Localization 的调用形状 `path.project(..., s_hint=上一拍, window_m=arrival_m, allow_backward=False)`
（`localization.py:203-207`）在 `allow_backward=False` 时 `lo = hint`、`t_floor = (lo - s_start[i_first]) / seg_len`，
窗口内最近点被夹到 `t_floor` ⇒ **返回的 s 恰好等于上一拍 hint** ⇒ 下一拍 hint 不变 =
**不动点，永不自行恢复**（它每拍都用自己的上一拍当 hint）。

### 3.2 实证

- 上报投影点**距车 >0.5 m 占 20~37%**（5 份 bench 日志），**最大 3.53~3.67 m**（用 `Path` 全局投影作真值对拍）。
- 冻结值集中在**顶点吸引子**：`(12,4.41) (15,6.78) (19/20,9.10) (14,4.9) (10,3.73) (17/18,8.05)`。
- 指纹比对：用 Localization 的调用形状复算 ⇒ **逐值命中**冻结序列 `6.14/6.19/6.28/6.39/…/6.78`；
  用 Tracker 的形状（`0.6/back_m=0.15`）复算则冻在 `(16,7.70)` —— 值不对 ⇒ 陈旧写者 = **Localization**。
- `torn pair = 0`（每个 `(seg,s)` 的 s 都落在该段区间内）⇒ 排除"两键读撕裂"。

### 3.3 危害判定

| 通道 | 是否受影响 | 依据 |
|---|---|---|
| 控制回路 | **否** | Tracker 用内部 `self._seg_s`（`tracker.py:295`），黑盒值只在首拍读，`_seg_s` 全程不重置 |
| 遥测显示 | 是 | `P_ROUTE_INDEX` 全仓只有 `telemetry.py:109` 读 |
| 任务推进 | 部分（有守卫） | `mission.py:419-427` 有"与现算投影差 ≤ `arrival_m`"的一致性守卫 + 距离兜底；但它自己的链同样会冻结 |
| **误差修正（估计侧）** | **是（实证）** | `fix.py:300-321` **无守卫**、只累加 `ds>0` ⇒ 日志出现物理不可能的段比值：K9 0.23~0.46、H10 0.12~0.22、G10 1.46~1.57、E11 0.13~0.25（真值≈1）；两条被接受的段（J9 1.057、F10 1.0611）把 scale 推高 +0.005/段。所幸只写 `P_FIX_EST`，不进控制回路 |

### 3.4 修复方案（已派发实施）

1. **Localization 卡死自愈**：`proj.dist > 阈值` 且 `proj.s` 连续 ~5 拍不前进而位姿移动 > `arrival_m`
   ⇒ `self._s_hint = None`（下一拍全路线重投影）。单这一条即可消掉日志里全部冻结值。
2. **FixTask 输入守卫**：只接受物理可能的段位移（如 `0 < ds <= 位姿位移×2`），丢弃并计数。
3. （未派发，待评估）`tracker.py` 的"只在 Localization 没在写时回写 `P_ROUTE_S`"约定；`telemetry.py` 改原子取对。
