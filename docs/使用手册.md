| 停止 / 重启 | `bash ~/dzrobot/start_all.sh stop` / `restart` | 小车 |
| 起栈前静态体检（可选） | `bash ~/dzrobot/tools/healthcheck.sh --pre` | 小车 |

## 1. 出车前：车上体检（可选，人工按需）

体检是**可选**的人工工具，不在 `start_all.sh` 起栈路径上；自检本体已收敛到发车前 dzbrain 自己的 10 秒准备窗口（`mission.auto_start_delay_s`，见第 2 节）。

```bash
bash ~/dzrobot/tools/healthcheck.sh --pre    # 静态：设备/配置/模型，节点未起时用
bash ~/dzrobot/start_all.sh                  # 起全栈（见第 2 节）
bash ~/dzrobot/tools/healthcheck.sh          # 完整：含运行时参数与新核心回路
```

退出码：`0` 全过 / `1` 有 ❌ 失败项 / `2` 只有 ⚠️ 提醒。
它专门拦"**改了参数却不生效**"这类静默故障，最有价值的是第 3 节（运行时参数与配置中心逐项比对）与第 4b 节（新核心）。

## 2. 起栈 / 停栈

```bash
bash ~/dzrobot/start_all.sh            # 启动全部（7 步）
bash ~/dzrobot/start_all.sh stop       # 停止全部
bash ~/dzrobot/start_all.sh restart    # 重启
```

启动顺序（`start_all.sh` 实测输出）：`1/7 底盘 → 2/7 相机 → 3/7 定位 → 4/7 视觉检测 → 5/7 云台自瞄 → 6/7 射击驱动 → 7/7 循迹`。
原第 8 步（浏览器控制台 `:8080`）已下线，所以脚本内计数为 **7/7**。

**起栈前不再跑自检门禁**（2026-10-11 定版）：自检只在**发车前 dzbrain 自己的 10 秒准备窗口**内做
（就绪日志 / 定位与安全初始化 / 出发前路线加载校验），起栈本身不再等校验、不拖测试进度。

起栈时只剩一个**瞬时的 YAML 可解析守卫**（不算自检，只提示不拦截）：`config/robot.yaml` 解析失败会
报 ❌（各节点会静默回退内置默认值，顶层裸键还会让相机/视觉/云台三节点 abort）。
要完整自检请用 `bash ~/dzrobot/tools/healthcheck.sh --pre`（见第 1 节）。

**起栈后第一眼看这行**：

```
ROS 链路域号: ROS_DOMAIN_ID=118  ROS_LOCALHOST_ONLY=0  (车标准域 118；**仅交互 shell 生效** —— 非交互 SSH 下默认域 0，t4 实测)
```

域号由 `~/dzrobot/dzros.env` 单独钉死（不再依赖 `~/.bashrc`）。域号不对时 **ping 通、SSH 通、网页通，ROS 却看不见对方，且一个错都不报** —— 无人机侧必须跟着改 `~/dzlink_tools/dzlink.env`。

## 3. 看日志与实时监控

| 日志 | 看什么 |
|---|---|
| `~/robot_logs/7_path.log` | 循迹 ★是否自动出发、路线是否下发 |
| `~/robot_logs/5_gimbal.log` | 云台自瞄 ★最关键 |
| `~/robot_logs/4_det.log` | 视觉检测 ★模型是否加载成功 |
| `~/robot_logs/6_judgment.log` | 射击驱动 ★开火指令是否下发 |
| `~/robot_logs/1_chassis.log` | 底盘串口 |

`monitor_aim.sh` 逐行打印：`[云台状态] 目标类型 偏移 框 靶心 置信度`。
判据：`目标=无目标 且 状态=SCAN` = 视野无靶，云台在扫（正常）；`目标=蓝/红靶 且 状态=TRACK` = 已锁定。

**狙击链路自检**（激光不亮时先跑这条）：

```bash
ros2 topic info /LaserShot_Command      # Subscription 必须是 1
```

历史事故：少了 `6_judgment` 这一步，云台算好的开火指令全发进空话题，激光永远不亮且无报错。

## 4. 单节点重启（改完参数不用整车重启）

```bash
bash ~/dzrobot/tools/restart_node.sh --list    # 看可重启项
bash ~/dzrobot/tools/restart_node.sh gimbal    # 云台（改扫描/开火参数后）★最常用
bash ~/dzrobot/tools/restart_node.sh judgment  # 开火没反应先重启它
bash ~/dzrobot/tools/restart_node.sh camera / vision / loc / chassis
```

⚠️ **`restart_node.sh path` 目前仍指向旧核** `src/car_localization/car_localization/path_executor.py`，
而 `start_all.sh` 默认起的是新核 `dzbrain`。**改了路线/速度要生效，请用**
`bash ~/dzrobot/start_all.sh restart`（或 `LEGACY_PATH=1` 时反而才对）。此处已知不一致，见第 13 节。

## 5. 远程看车：SSH 终端 / VNC 桌面 / 文件

DSH 侧边栏「小车」图标 → 工具列表，均为**右栏标签页**：

| 工具 | 用途 |
|---|---|
| SSH 终端 | 原生终端，回显/Tab/Ctrl-C 都在 |
| 文件目录 | 浏览、预览、下载、上传车上文件 |
| VNC 桌面 | noVNC 桥到车上 TigerVNC `:1`（端口 **5901**，不是 5900） |
| 小车操作台 | 内嵌车上网页（图传/地图/调参/遥控器） |

排错：图标红点 = 车不可达（`ping duzhong.local`）；黄点 = 免密不成立，`ssh-copy-id -i ~/.ssh/id_rsa.pub duzhong@duzhong.local`。
VNC 输错密码会被 TigerVNC **拉黑约 1 分钟**，所以面板刻意不自动连接。

⚠️ **遥控器没有替代品了**：可视化遥控入口（网页端）已随第 8 步下线。底盘 1.0 s 无指令强制停车仍在作为最底层兜底，但"人接管"目前只能自己写节点。

## 6. 改车流程（本地优先 → 推送车端 → 车端编译）

**流程（2026-10-11 用户定版）：本地 `D:\User\Desktop\dzrobot_v2` 仍是唯一真源 —— 先本地改完并回归，再推送车端、在车端 `colcon` 编译并起栈验证。旧铁律「车端只读、由用户手动替换编译」已取消；紧急现场排障可以在车上直改，但当日必须回写本地 git。**

```powershell
cd D:\User\Desktop\dzrobot_v2
python tools\deploy_car.py status                          # 只读：车上节点/话题/门禁快照
python tools\deploy_car.py diff config/robot.yaml          # 只读：与车上同名文件 md5 对比
python tools\deploy_car.py plan                            # 只读：打印将要推什么、执行什么
python tools\deploy_car.py gate                            # 只读：在车上跑 dzbrain --dry-run
python tools\deploy_car.py --write push config/robot.yaml start_all.sh
python tools\deploy_car.py --write build                   # colcon build（默认 dzbrain）
python tools\deploy_car.py --write restart                 # start_all.sh restart
```

- **默认只读**：任何会改动车上文件/进程的子命令都必须显式加 `--write`（保留为「先预览后写入」的安全闸）。
- **常规部署一律走下面的 `deploy_to_car.py`（唯一常规入口，D-019）**；本节 `--write` 只用于现场应急单步（需 Lead 授权）。
- 备份：`python tools\deploy_car.py --write backup` → `~/dzrobot/_backups/<时间戳>/`。
- 连接参数可用环境变量覆盖：`ROBOT_SSH_HOST`（默认 `duzhong.local`）、`ROBOT_SSH_USER`、`ROBOT_WS`（默认 `/home/duzhong/dzrobot`）。

**常规部署入口**（`sha256` 逐项对账；默认**不碰**车端 `auto_start`；D-019）：

```powershell
python tools\deploy_to_car.py probe            # 解析车端 IP 与关键状态
python tools\deploy_to_car.py all --dry-run    # 只打印将执行的命令
python tools\deploy_to_car.py all              # backup → push → build（自检不再自动跑）
python tools\deploy_to_car.py verify           # 可选：想要时单独跑（dzbrain 包/入口存在性 + 云台补丁符号，瞬时）
python tools\deploy_to_car.py push --force-no-autostart   # 可选：显式把车端 auto_start 强制改回 false
```

> 分工（D-019）：`deploy_to_car.py` = **唯一常规部署执行入口**（probe/backup/push/build/verify/all）；
> `deploy_car.py` = **只读诊断**（status/gate/plan/diff/pull，交互更细）+ 现场应急单步（`--write` 需 Lead 授权）。
> 后者**默认不碰车端 `auto_start`**；只有显式加 `--force-no-autostart` 才强制改成 false（防验证阶段自动发车时用）。

## 7. 本地验证（上车前先在本机跑）

```powershell
# 全量测试（本机无 pytest，测试是纯脚本，exit 0 = 全过）
$env:PYTHONPATH='D:\User\Desktop\dzrobot_v2\src\dzbrain'; $env:PYTHONIOENCODING='utf-8'
Get-ChildItem src\dzbrain\tests\test_*.py | ForEach-Object { python $_.FullName }   # 关注 "结果：X/Y"

python tools\dzbrain.py --dry-run          # 配置 + 路线校验（本机手动；起栈前已不再跑这道门禁）
python tools\config_selfcheck.py           # 配置中心关键键自检
python tools\route_check.py                # 路线全链路校验（语法/解析/几何/任务/安全）
python tools\dzbrain.py --bench --seconds 5  # FakeBridge 联调，无 ROS 无车
$env:PYTHONPATH='...\src\dzbrain'; python -m dzbrain.tools.sim_cli   # 权威三层仿真
```

`PYTHONIOENCODING=utf-8` 别省：控制台是 GBK 时，仿真末行的 `↔` 会抛 `UnicodeEncodeError` 让进程以 exit 1 结束（其实已跑完并落盘），极易误判成崩溃。

## 8. 现场必须标定的参数（`config/robot.yaml`）

| 参数 | 段/位置 | 标定方法 |
|---|---|---|
| `px_per_m_rail` | `/dzbrain: aim:` | 靶放轨道一端记下画面 dx，再放另一端记 dx，`= |Δdx| / 0.70`。默认 140 只是估值 |
| `scan_pitch_offset_deg` | 同上 | 注释史与实测值长期冲突，**现场必须核对** |
| `ticksPerMeter` | `/dzactuator:` | 遥控低速直行 6 格（2.10 m），`= 编码器计数 / 2.10`；验收：位移误差 <3% |
| `ticksPer2PI` | `/dzactuator:` | 原地匀速转满一圈读编码器增量；验收：命令转 90° 实测 ≈90° |

`robot.yaml` 顶层只有 7 个段（`/dzrknn_dataprocess`、`/usb_cam_node`、`/dzjudgment`、`/det_node`、`path_executor`、`/dzbrain`、`/dzactuator`）。
⚠️ **顶层不允许加裸键**（如 `map:`）—— ROS params 解析会失败，相机/视觉/云台三节点同时 abort。地图等数据放 `config/map.yaml`。

路线唯一真源 = `config/robot.yaml` 的 `path_executor.mission_blocks`（新核迁移为 `route.tokens`，见 `core/config.py`）。
**本机 config 与车端 config 可以不同**（本机=规划/校验用，车端=本局发车用）——以 `python tools\route_check.py --config <该图配置>` 的输出为准，**不要在本文件里抄死路线数字**。
截至 2026-10-18 现场：车端 config = 第七张图 **50 token**（穿洞 K10/K4、停站 F9/F5/N5）；当日实跑由无人机 `/nav/waypoint` 下发 **55 token**（详见 `docs/项目现状_20261018.md`）。
> 2026-10-17 的 44 点（双停站 `D3*`/`G3*`、穿洞 K9/K5）与 34 点（`G10*`、3 段倒车）均为历史口径，**已作废**，不要再照它们发车。

## 10. 已知问题与风险（如实记录）

1. ~~`src\dzbrain\tests\test_deploy.py` 当前 3 条失败（74/77）~~ **已修（2026-10-11）**：第 ⑥ 组断言已同步到
   新契约（起栈前无门禁、`python3 -u -m dzbrain.main` 只在节点 7 出现 1 次、现场适配保留），
   不再是旧标记 `"7/8 循迹"` / `5b_aimshim` 切块问题。
2. **`restart_node.sh path` 与默认核不一致**（见第 4 节）。
3. **`pursuitAngle` 保活速率实测 40.2 Hz**（标称 50）—— 8 节点全开抢 CPU 所致。底盘看门狗 1 s 足够，
   但**现场出现顿挫优先怀疑这里，而不是参数**。体检脚本低于 40 Hz 会告警。
4. **`/HpAndHitmsg` 无数据 ≠ 车坏了** —— 该 1 Hz 心跳来自**裁判机**，不是车自己产。出车前确认裁判机已开启。
   遥测里的弹药数是锁存值，所以界面看起来仍有数据（设计使然）。
5. **浏览器控制台（原第 8 步）是否还可用未核实** —— `start_all.sh` 已不再拉起它，
   而 `tools/cam_viewer.py`、`param_spec.py`、`rc_control.py`、`aim_status_shim.py` 在工作区中已删除。
   插件「小车操作台」直连车上 `:8080`，**车端是否仍在跑该服务需上车确认**。
6. **bench 必须独占跑** —— 并发跑会抢 CPU，同一版本到点数在 9~22 间波动，数字不可横向比较。
7. **`duzhong.local` 是 mDNS，实测会抖**（一次会话 5 次查询 3 次失败），车会在网络间游走
   （同一天出现过两个不同网段地址）。连不上先 `ping`，别急着怀疑车。
8. **切角/拐角**：route_check 报「急转弯 17 处」，但设计结论是 **PIVOT 在现场路线上永不触发**
   （全是 ≤90° 直角/钝角，靠纯追踪 + 倒车段处理）。若现场某处确实需要调头，说明该处 token 该标 `R:`。
