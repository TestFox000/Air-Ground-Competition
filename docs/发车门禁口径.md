## 0. 一句话口径

**发车 = G1 ∧ G2 ∧ G3 ∧ G4 全绿 ∧ 全量回归 0 非零退出**；G5 是**记录项**，本轮不阻断，下阶段必须收口。

- 判据单位是 **error / warn 分类**，不是"退出码 0"。
  为什么：`tools/route_check.py:1228-1245`（`summarise`）与 `tools/config_selfcheck.py:101-103` 都**只在 error 时返回 1**，退出码 0 **不代表 0 warn**。
- **两层/两套 warn 分开记，不可互相豁免**（这是 G1/G2 最容易混的一点）：
  - **配置层**（`Config.validate()`，`config_selfcheck.py:83-86`）：未知配置段/未登记键/取值范围等。本快照 `[配置校验] 0 条非 info` ⇒ 配置 warn 0（W2 已收口，见文首更新块；§2-W2 仅留历史）。
  - **路线层（G1 内）**（`validate_route()`，`config_selfcheck.py:88-92`）：`dzbrain.route.validate` 的 R00x 检查（桥洞/障碍/射击窗/雷覆盖等）。本快照 `[路线校验] ✅ 路线校验通过：0 error / 0 warn`。**G1 不调用 `tools/route_check.py`**，所以这一层**不含**它的「急转弯」提示。
  - **G1 结论行** = 配置层 + G1 路线层之和（`config_selfcheck.py:94-103`，配置 warn 已显式计入）。
  - **G2 的 warn 是另一套**：`tools/route_check.py` 的独立检查层（`急转弯` 在 `route_check.py:902-911`；`summarise()` 只在 FAIL 时 rc=1，`route_check.py:1228-1245`）。本快照 WARN 1 = `急转弯 18 处` ⇒ W1。
  - ⇒ **G1 的 `error 0 / warn 0` 不能豁免 G2 的 W1**（两个程序、两套 warn）；反过来 G2 的 `WARN⊆W1` 也不覆盖配置层。**G1、G2 必须各看各的结论行。**
- **W1 白名单**是点名到具体 warn 事实的（当前只有 `急转弯`），不是"忽略所有 warn"；W1 之外任何 WARN 一律阻断。

## 2. 两条口径裁决（W1 有效 / W2 已收口）

### W1：route_check 的 `急转弯` warn 不阻断（当前唯一 warn）

- 事实：本快照 `route_check` 输出 `⚠️ 急转弯 18 处 最大 90° @航点#1（其中 0 处已声明 :PIVOT）`，退出码 0。
- 依据：`route_check.py:104` 的 `SHARP_CORNER_DEG = 45.0` 只作**提示级**；真正的 `:PIVOT` 门限是
  `PIVOT_DECL_DEG = 135.0`（`:109`），第 ⑥ 层实测"折返点 0 处 —— 无 ≥135° 的正向折返顶点，无需 :PIVOT"。
  18 处 ≤90° 急转弯是**直角路线的设计正常**，不是缺陷。
- 结论：**W1 = { `急转弯` }** 视为提示；其它任何 WARN（尤其 `桥洞…`、`障碍净空`、`倒车+转向`）一律阻断。
- ⚠️ 该 warn **只由 G2（`tools/route_check.py`）产出**；G1 的 `[路线校验]` 是 `validate_route`，看不到它。**G1 的 `0 error / 0 warn` 不能作为"W1 已豁免/不存在"的依据**；反之，G2 的 `WARN⊆W1` 也不能反推配置层干净。
