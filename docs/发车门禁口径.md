## 2. 两条口径裁决（白名单）

### W1：route_check 的 `急转弯` warn 不阻断（当前唯一 warn）

- 事实：本快照 `route_check` 输出 `⚠️ 急转弯 18 处 最大 90° @航点#1（其中 0 处已声明 :PIVOT）`，退出码 0。
- 依据：`route_check.py:104` 的 `SHARP_CORNER_DEG = 45.0` 只作**提示级**；真正的 `:PIVOT` 门限是
  `PIVOT_DECL_DEG = 135.0`（`:109`），第 ⑥ 层实测"折返点 0 处 —— 无 ≥135° 的正向折返顶点，无需 :PIVOT"。
  18 处 ≤90° 急转弯是**直角路线的设计正常**，不是缺陷。
- 结论：**W1 = { `急转弯` }** 视为提示；其它任何 WARN（尤其 `桥洞…`、`障碍净空`、`倒车+转向`）一律阻断。

### W2：配置校验的 20 条"未知配置段"不阻断，但**必须点名**

- 事实：`config_selfcheck` 打印 `[配置校验] 20 条非 info 问题`，全部形如
  `⚠️ planner.engine: 未知配置段（拼写错误？新版本未登记？）`（`planner.*` 12 条 + `vehicle.*` 4 条 + `field.*` 4 条）。
- 实测这些键**取值全部生效**（`planner.engine='tracker-safe'`、`vehicle.coverage_radius_m=0.035`、
  `field.bridge_entry_redundancy_m=0.0875`…）⇒ "未登记 ≠ 未生效"。
- ✅ **报告层已修**（2026-10-17 11:09:30，队长直改）：结论行现在计入配置 warn
  （`结论：error 0 / warn 20  ✅ 通过`），不再出现"屏幕 20 条 / 结论 warn 0"的自相矛盾。
- 结论：**W2 = { 20 条 `未知配置段`，键名逐一点名（下表）}**；G1 判据 = `error 0` ∧ 配置 warn **⊆ W2** ∧ 路线 0 error/0 warn。

```

planner.map_path / planner.fallback_to_tokens / planner.allow_reverse / planner.max_seconds /
planner.pivot_penalty / planner.mine_turn_penalty / planner.obstacle_margin_m /
field.bridge_entry_redundancy_m / field.obstacle_radius_m / field.mine_pad_m /
field.barrier_width_m / field.barrier_cols /
vehicle.length_m / vehicle.width_m / vehicle.coverage_radius_m / vehicle.ref_offset_m
```

- 根治（车侧写域，本队**未改**）：把这 20 个键登记进 `src/dzbrain/dzbrain/core/config.py` 的 `SCHEMA`；
  登记后 W2 自动消失，`warn 0` 才恢复字面意义。
