# 车朝向问题根除方案

> 问题：`reset:N10,y` 盲目断言朝向=90°，车被搬到起点时真实朝向可能不同（实测差 68.6°），导致绕圈。
> 车端只有航位推算，无法自校准。根除方案：**无人机 PnP 定位时检测车的真实朝向，下发给车端补偿**。

---

## 1. 现状

- 车端 `reset:<起点>,<朝向>` 会把 `snap_yaw_off` 设为断言朝向，车端完全信任这个值
- dzuav 的 UDP 协议（`msg_id=0x4001`）只广播目标位置，不含车的朝向
- `heading_calibration.py`（数学模块，测试全绿）已就绪，但需要独立位姿源

## 2. 方案：新增车位姿广播消息

### 2.1 协议扩展（不破坏现有 0x4001）

新增 `msg_id=0x4002`，专门广播无人机观测到的**车的真实位姿**：

```
偏移  长度  字段        说明
0     4     magic       0xefefefef
4     1     version     0x10
5     8     timestamp   uint64，机上毫秒
13    2     msg_id      0x4002
15    4     length      uint32 = 20
19    8     car_x       float64，车的世界坐标 x（米）
27    8     car_y       float64，车的世界坐标 y（米）
35    4     car_yaw     float32，车的真实朝向（弧度，场地坐标系）
39    2     crc16       uint16，覆盖 version 到 car_yaw
41    4     suffix      0xfefefefe
```

- 总长度 45 字节
- CRC 范围与 0x4001 一致：从 version 到 crc16 之前
- dzuav 每帧（或定位成功时）广播一次

### 2.2 dzuav 侧改动（代码已实现，待真机验证）

1. `HbbDetector` 已检测 `ObjectType::CAR`（type=1）
2. 新增**车朝向估计**：
   - 方法 A：用车的检测框长宽比 + 主方向（需车头方向特征）
   - 方法 B：连续帧光流跟踪车的运动方向
   - 方法 C：在车顶贴方向标记（ArUco/颜色条），dzuav 识别方向
3. `MapLocalizer.project()` 把车的像素坐标投影到世界坐标
4. `UdpBroadcaster` 新增 `sendCarPose(x, y, yaw)` 方法，发送 0x4002 帧

### 2.3 车端改动（已实现，与本节草案有出入）

`integrate_node` 参数 `heading_bias_source` 现为三档：
- `"none"`（默认）：不使用外部朝向，保持现状
- `"udp"`：监听 0x4002 消息，取观测真实朝向**最近的坐标轴**（x/y）作为
  reset 断言，残差 ≤ 45°，不挪车
- `"align"`：用 0x4002 真实朝向闭环原地转向到 `start_heading` 断言方向
  （调用 `heading_calibration.closed_loop_rate`），零残差，**当前推荐**
  （`config/match_params.yaml` 默认即 align）

> 注意：本节原草案的"调用 `heading_calibration.corrected_heading` 补偿
> snap_yaw_off"**未按此实现**——udp 模式实际是"最近轴断言"（逻辑在
> integrate_node 内，见下文修正逻辑）；`estimate_bias`/`corrected_heading`
> 的直行探测校准流程节点并未实现，`heading_calibration.py` 目前只是
> 工具函数集，节点只做 align 闭环转向。

参考修正逻辑（udp 模式，最近轴断言）：
```python
true_yaw = car_pose.yaw                      # 无人机观测的真实朝向
asserted_yaw = heading_to_yaw(start_heading) # reset 断言的朝向
bias = true_yaw - asserted_yaw               # 偏差
# 通过 reset 命令或直接话题补偿 snap_yaw_off
```

## 3. 实施顺序

| 阶段 | 内容 | 依赖 |
|---|---|---|
| 1 | 车端预留 0x4002 接收接口 + heading_calibration 接入 | 无（可现在做） |
| 2 | dzuav 增加车朝向估计（方法 A/B/C） | 无人机真机 |
| 3 | dzuav UdpBroadcaster 增加 sendCarPose | 阶段 2 |
| 4 | 端到端联调：无人机观测朝向 → 车端补偿 → 车直线行驶 | 车+无人机同时在线 |

## 4. 替代方案（如果 dzuav 加车朝向困难）

- **人工标定**：比赛前用全站仪/激光测距测车的真实朝向，手动输入 `--heading-bias` 参数
- **地面标记**：在起点贴方向标记，车端相机识别（但车端目前无此能力）

## 6. 实车注意事项（2026-10-15 仿真发现）

- `align_creep_speed` 别调大：Ackermann 几何内禀漂移 ≈ 转角×爬行半径，
  0.10 m/s 时摆正 68.6° 漂移 ~0.35m 压在阈值刀尖；0.05 m/s 时 ~0.21m 有裕度。
- 官方 path_executor 在 (20°,45°] 拐角有潜在停死窗口（预瞄点钳顶点 +
  PIVOT 只覆盖 >45°）：顶点恰为"对角↔正交"过渡且车恰好停在顶点 1cm 内时
  信念冻结、永久停车。概率低但真实存在；实车若遇停死，补发一条单点命令即可。
- reset 若抢在首帧定位前到达会引入半格偏置——两阶段启动里 serial_reader
  在阶段1就起，天然规避。
