## 一、★最大收获：车不动的答案在底盘固件里

出处：`DZVCU程序\stm32code20260602\DZCONTROL\control.c`

```c
106:  operationMode = 1;                    // ← 默认就是「航模遥控模式」
144:  if(Remote_CH[6] > 1500){ operationMode = 1; }   // 遥控模式
147:  }else if(Remote_CH[6] < 500){ operationMode = 0; }  // ★ ROS 串口控制模式
404:  if (operationMode == 1){      // 航模遥控模式分支
426:  }else if (operationMode == 0) // ROS 串口控制模式分支
```

**结论**：必须让 `Remote_CH[6] < 500`，底盘才走串口分支。
按 `Remote_CH[i]` ↔ 通道 `i+1` 对应遥控器上的标注（swa-5 / swb-6 / swc-7 / swd-8）：

| 固件变量 | 通道 | 开关 | 控制什么 | 遥控器位置 |
|---|---|---|---|---|
| `Remote_CH[4]` | ch5 | SWA | （另一路） | — |
| `Remote_CH[5]` | ch6 | **SWB** | `camera_mode` **云台**模式 | 左半边（云台控制） |
| `Remote_CH[6]` | ch7 | **SWC** | **`operationMode` 车辆 遥控↔串口** | 右半边（车辆控制） |
| `Remote_CH[7]` | ch8 | SWD | （另一路） | — |

与 `docs/raw_txt/04_遥控器控制.txt`「左半边云台、右半边车辆，左右对称各一个模式开关」完全吻合。

**两个必须记住的点**：
1. 固件**默认是遥控模式**（第 106 行），所以上电后不拨开关一定不动。
2. **关掉遥控器 ≠ 切到串口模式**——关机后接收机无 PWM，`Remote_CH[6]` 取不到有效值，
   底盘进不了第 426 行的串口分支（2026-09-29 实测过，别再试这条路）。

## 二、技术路径差异：官方主推的和我们用的不是一套

官方车端源码包 `车端香橙派ros自主导航程序\dzrobot-bisai-20260617\src` 的包清单：

```
dzactuator  dzjudgment  dzrknn_dataprocess  dztrack  fake_amcl_node
maps  navigation2  naviPointPath  rknn_pt
robot_localization-humble-devel  rplidar_ros-ros2
rviz  slam_gmapping-eloquent-devel
```

⚠️ **里面没有 `car_localization`**（也就是没有 `serial_reader` / `path_executor.py`）。
我们在车上用的那一套，不在官方这个发布包里。

| 环节 | 官方主推 | 我们当前 | 偏差影响 |
|---|---|---|---|
| 定位 | `rplidar_ros` + `amcl.launch.py` + `robot_localization`(EKF) | `car_localization/serial_reader`（IMU+里程计航位推算，日志打 `v4-dr-reset`） | **我们用的是航位推算，yaw 会漂移 → 纯追踪一直纠偏 → 疑似转圈根因** |
| 纯追踪 | `dztrack` 包，`pursuitSpeed=0.8` | `car_localization/path_executor.py`，`linear_speed=0.3`、`lookahead=0.15`（硬编码） | 我们速度只有官方的 3/8，前视距离 0.15 m 过短 |
| 导航 | Nav2（`dznavigation.launch.py`）/ 录制路径 | 自研 `ag_car/car_node` 发格号路线 | 官方是"先录路径再追踪"，我们是动态路线 |
| 路径来源 | `naviPointPath/mapping.txt`（遥控器录一遍） | 情报驱动的格号序列 | — |

### 官方纯追踪参数（`dztrack.launch.py`，可直接抄）

```python
"saveMapping": False,        # False=纯追踪控制模式；True=录制路径模式
"pursuitSpeed":   0.8,       # ★ 官方巡航速度
"minDis_param":   0.1,
"far_min_dis":    0.20,
"near_min_dis":   0.20,
"reduct_ratio":   0.6,
"target_min_dis": 1.0,
"angle_Kp":       1.8,
"diffangle_Kp":   1.15,
"global_frame": "world", "robot_base_frame": "base_link"
```

发布话题是 `/pursuitAngle`（remap 被注释掉了 → 默认），与我们的链路一致，
所以**换执行器不需要改底盘**。

补丁脚本 `tools/car_patch_executor.sh` 的默认值已按官方对齐为 **`linear_speed=0.8`**；
前视距离官方没有同名参数（`dztrack` 用的是 `minDis/far_min_dis/near_min_dis`，算法不同），
`lookahead=0.40`（≈ 一格）暂保留。

### ⚠️ 本车没有激光雷达 → 官方 AMCL 那条路走不了

官方包里有 `fake_amcl_node`，就是给这种场景准备的（**不需要雷达**）：

```
bringup.launch.py            （/odom + /imu_data）
  → ekf.launch.py            robot_localization/ekf_node，融合 IMU + 里程计 → /odometry/filtered
  → fake_amcl.launch.py      /odometry/filtered → /amcl_pose（frame_id=map）
                             + static_transform_publisher: map → odom（全零）
```

启动与对比脚本：`tools/car_align_official.sh`（只起节点、**不发速度、车不会动**）。

⚠️ **坐标系不兼容，不能直接替换**：`path_executor` 依赖 `/odom/localization` 的
**block 单位**坐标（serial_reader 提供，`x=0..10.5, y=0..13`），而 EKF 输出的是**米制**。
所以官方 EKF 只能作为**定位增强/交叉验证**，不能直接顶替 `/odom/localization`。

### ⚠️ `dztrack` 不适合本赛项，别照搬

`dztrack` 的工作方式是「`saveMapping=True` 时用**遥控器录一遍**路径写进
`naviPointPath/mapping.txt`，再 `saveMapping=False` 沿这条录制路径纯追踪」。
但本赛项的地雷与桥洞位置是**随机**的，路线必须按情报动态生成 ——
所以我们保留支持 `/nav/waypoint` 动态下发路线的 `path_executor` 是对的，
**只对齐它的参数，不换执行器**。

## 三、底盘模式机制（ROS 侧）——已核对，无遗漏

`dzactuator.cpp`（官方版 1385 行，与车上运行版一致）的两道闸：

- `modeTimerCallback()` 仲裁 `current_mode_`：只有 `cmd_vel` 活跃→1(DWA)，只有 `pursuitAngle` 活跃→2(Pursuit)
- `callback_cmd_vel_angle` 要求 `current_mode_==1`；`callback_movebase_angle` 要求 `current_mode_==2`
- 两者都只在 **`control_mode == 1`** 时才真正下发速度（`control_mode` 初始就是 1，
  只有 `/logicontrol` 且 `linear.z>1.0` 才会变 2，而变 2 反而**不发**速度）

⚠️ 执行器发的是 **`pursuitAngle`**，不是 `/cmd_vel`。`/cmd_vel` 上"发布者 0"是**正常现象**，
别拿它判断执行器死活（2026-09-29 踩过，白查一轮）。

底盘订阅：`cmd_vel` / `pursuitAngle` / `logicontrol` / `voice_switch` /
`vehicle_state` / `vehicle_Drivestate` / `CameMo_Conl` / `StopCmd`。
其中 `vehicle_state`、`voice_switch`、`vehicle_Drivestate` 的回调**只改语音播报**，
`CameMo_Conl` 只改云台 —— **都不解锁驱动**，别再往这个方向查。

## 五、对齐结论：哪些照抄、哪些保留、哪些改不了

| 环节 | 官方 | 我们的决定 | 理由 |
|---|---|---|---|
| 底盘驱动 | `dzactuator bringup.launch.py` | **照抄**（已在用） | — |
| 模式开关 | 固件 `Remote_CH[6] < 500` | **照抄**（SWC/ch7 拨低端） | 车不动的唯一解 |
| 定位（无雷达） | `ekf.launch.py` + `fake_amcl.launch.py` | **起起来做增强/交叉验证**，不顶替 | 坐标系不兼容（米制 vs block） |
| 定位（有雷达） | `rplidar` + `amcl` | **改不了** | 本车没雷达 |
| 纯追踪执行器 | `dztrack` | **保留 `path_executor`**，只对齐参数 | 赛项路线需动态，dztrack 只能跑预录路径 |
| 巡航速度 | `pursuitSpeed = 0.8` | **照抄**（补丁默认已改 0.8） | 我们原来只有 0.3 |
| 导航框架 | Nav2 / 栅格地图 | **保留自研格号规划** | 没有建图，且格号更贴合赛项 |
| 裁判 | ESP32 固件 + 上位机 | **待对齐**（用上位机离线验证） | 我们目前收不到裁判状态 |
