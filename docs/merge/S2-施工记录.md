## 2. S2 · 无人机节点接入（Host 半身）

### 2.1 `src/nodes.js` — 统一节点注册表

按 coordination-design.md §1.2：每节点 `{role, kind, label, settingsInitial, caps}`；caps.gauges 是决议①的单一真源（车 3 格 / 机 4 格），hasSim 只在车（仿真台是 Host 本地能力）。`nodeSnapshot()` 产出 NodeSnapshot 形状并给探针标 `source:'cached'`（bug#1 的 Host 半身）。`DRONE_SETTINGS_INITIAL` 按 S0 §7.3 记录的冻结 Host 配置值烘焙（host=dzsmart.local / user=duzhong / vncPort=5901 / filesRoot=/home/duzhong）。

### 2.2 `src/metrics-drone.js` — 机侧 metrics 移植

裁决 **D1（独立文件，不做能力分支）**：两侧 METRICS_COMMAND 是两套不同的远端 shell 程序（车=bash+ROS 双话题；机=dash+thermal+PX4），timeout 不同（12s/9s）、解析器不同；独立文件让机侧代码与冻结源逐行可对照（METRICS_COMMAND/parseDroneMetrics/cpuUsage 原样移植，仅日志前缀改 `dzairground-ssh`）。词汇统一在 `src/gauges.js` 完成。`collectDroneMetrics` 保留模块级 in-flight 去重（与车侧互不影响）。

### 2.3 bug#3 — 越界即 bad_value（双侧）

- 车 `src/metrics.js`：`batteryPct=` 行出现过但 `normalizeBattery` 拒绝 → `batteryNote='bad_value'`，优先于 derived（有电压也不再折算盖写）；`no_stack`（壳层在 p、v 全空时发）不受影响——现有 4 条 parser 用例语义不变。
- 机 `src/metrics-drone.js`：`batteryPercent/batteryVoltage` 行出现过但越界被拒 → `bad_value`，不再落进 `dds_silent`（话题开口说了话就不是静默）。
- 词名裁决 **D2**：任务卡示例 `battery_data_invalid`，采用设计文档 t4 §2.4 统一词表的 **`bad_value`**（任务原文是「如」举例）；UI 显示「数据异常」。

### 2.4 角色分发（index.js）

- `makeNode(spec, {settings, status, collect})`：车/机各持一份 JsonStore（`settings.json`/`status-drone.json` 等 4 份，全在 `~/.dsh/dzairground-ssh/`，见 2.5）+ 各自 runProbe/collect/shortcuts。
- handler 内 `settings/status/runProbe/collectMetrics` 全部改从 `node` 取；未加前缀的顶层路由（`/status` `/metrics` `/sim/*` `/novnc/*`）保持 S1 形状、读车节点。
- `/drone/status` 与 `/car/status` **键集合同构**（去掉 role 后 11 键全等，实测见 W 输出）。
- VNC upgrade 座位保持顶层 car-only（`/api/dzairground-ssh/vnc`）；drone VNC 隧道不在本卡（裁决 **D5**，见 §7）。

### 2.5 机侧配置默认值与写隔离

裁决 **D3**：冻结配置的值**烘焙进代码**（任务卡括号已枚举值），运行时不读 `~/.dsh/dzdrone-ssh/settings.json`——那台机器路径不可移植且属冻结只读区。**vncPassword 默认 ''**（drift-audit §3 明确警告不许把机侧密码写进默认值；空密码=noVNC 连接时弹窗问，与新装车侧行为一致）。新写入一律落 `~/.dsh/dzairground-ssh/settings-drone.json`（实测 W 输出：POST /drone/config floatOpacity=88 → 400ms 后落盘、值正确、未污染车侧文件）。

### 2.6 bug#1 — 探针诚实化（Host 半身）

`/status` 响应的 probe 一律标 `source:'cached'`（凡从持久化快照读出的）；`POST /probe` 响应标 `source:'live'` 并带 `at`。UI 侧（§3.4）只认「live 且 ≤35s」为绿。

### 2.7 顺带的诚实性修复（冻结审计遗留）

`src/ssh.js` `refusalFor`/`probe` 增加 `label` 参数（默认 '车'）：机侧掉线文案从「车还没连上 WiFi」变为「无人机还没连上 WiFi」（drift-audit §3 点名的必改项，2 处字符串参数化，车侧行为零变化）。

## 7. 发现但没修的

1. **drone VNC 隧道**：`/api/dzairground-ssh/vnc` 仍是车专用（openVncTunnel 直连 settings.vncHost:5901）；机侧桌面要走 noVNC 需第二条 upgrade 座位 + 按角色选 bridge 目标——建议 S4/S5 开卡。
2. **drift-audit 另三项机侧增量未回贴**：bridgeConnectorConfig 的 loopback→localhost 改写、/config 保存后 floatOpacity 即时下发 store、vnc-app.html 文案——不在本卡任务面，留待后续。
3. **design-doc §1.3 的 `links` 三轴（ssh/metrics/dzlink）**未落地：dzlink 数据源在设计文档 §8 自标未验证（插件侧零 dzlink 字样），本卡判据不含它。
4. **`/drone/reload|selftest|diag|graph`** 因共享 router 而可用（作用于整个插件而非节点）——语义无害但严格说不节点私有；若要收紧需新增 404 规则。
5. **test-client 对 makeCarPanel 的渲染断言**依赖 stub React 的 props.key 保留行为（现有 stub 如此）；若换 stub 需同步。
6. 真机未见：/drone/metrics 的实测形态只验证到「诚实离线」（dzsmart.local 不可达）；温度/飞控电量的**真数**渲染要等无人机上线后一次实跑。
