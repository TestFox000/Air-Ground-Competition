## 2. ★ 无人机 / 机载端（重点）★

### 2.1 职责边界：官方飞控 + 我们的侦察栈

无人机侧**没有**飞控/建图/定位/自主飞行代码——那些全部由官方 `dzpx4` 栈负责（归档在 `reference/onboard/dzpx4/`）。
我们维护的只有 **机载侦察栈 `onboard/dzuav`**（C++）。

```
[机载 Orin Nano]
  ┌─ dzpx4（官方，直接用，不改）────────────────────────┐
  │  MID360 激光 → FASTLIO2 建图/定位 → PX4 飞控          │
  │  px4_control / px4_path 执行航线（起飞/巡航/返航）     │
  └──────────────────────────────────────────────────────┘
  ┌─ dzuav（我们维护，C++）──────────────────────────────┐
  │  AR0234 下视相机 → 去畸变 → HbbDetector(7类检测)       │
  │    → CellClassifier(格号识别) → MapLocalizer(PnP定位)  │
  │    → UdpBroadcaster（二进制 UDP :50000 广播）          │
  └──────────────────────────────────────────────────────┘
                          │ UDP :50000
                          ▼
[车端香橙派] 官方 dzrobot：path_executor / dztrack / Nav2 负责开车
            我们的 ag_integrate：收 :50000 → 世界模型 → 官方车命令 + 禁火保险
```

拆解到"我们的职责"就一句话：**把相机画面变成目标世界坐标，通过 UDP 发给车。**

### 2.2 dzuav 单帧处理流水线

详见 [`docs/无人机工作流程.md`](无人机工作流程.md)。核心七步：

1. `MapLocalizer.undistort(frame)` 去畸变（映射预计算，同分辨率只算一次）
2. `HbbDetector.infer(image)` TensorRT 推理，1280×1280，7 类目标
3. 对 `CellLabel` 类目标裁剪 ROI → `CellClassifier.infer(roi)` 识别格号
4. `MapLocalizer.solve(landmarks)` **PnP 自定位**（需 ≥4 个格号，凸包面积 ≥2% 画面）
5. 定位成功 → `MapLocalizer.project(像素中心)` 投影到场地世界坐标（米）
6. `UdpBroadcaster.send(timestamp, objects)` 二进制 UDP 广播到 :50000
7. stdout 输出 `localized=1/0`

### 2.3 空地链路协议（二进制 UDP :50000）

- **二进制协议**（不是 JSON），与官方 dzuav 的 `UdpBroadcaster` 字节级对应
- 布局：`magic(0xefefefef) + version(0x10) + ts(uint64) + msg_id(0x4001) + length(uint32) + count(uint16) + objects[] + crc16 + suffix(0xfefefefe)`
- 每目标 25 字节：`type(u8) + x(f64) + y(f64) + length(f32) + width(f32)`
- CRC-16/Modbus（多项式 0xa001），覆盖 version 到最后一个目标；`"123456789"→0x4B37`
- 车端 `ag_integrate/intel_protocol.py` 做 magic/version/msg_id/length/crc/suffix 全量校验

### 2.4 PnP 自定位：不需要单应矩阵 H

**官方路径用地面格号做天然地标**，每个格号的世界坐标已知（`x = 0.065 + (col-'A')*0.35`, `y = 0.295 + (11-row)*0.35`, `z=0`）。
`cv::solvePnPRansac` 用格号的 3D-2D 对应求相机位姿，再用单应逆把任意像素点投影到世界坐标。

**这意味着**：旧的"单应矩阵 H 标定"流程已废弃，不需要标 H。

### 2.5 无人机到货后：联调顺序

一次只引入一个变量：

1. **编译**：`tools/orin_build_verify.sh`（Orin 上一键编译 + L0~L3 分层验证）
2. **相机出图**：`dzuav uvc:/dev/video0 ...` 确认相机帧正常
3. **格号识别**：离线图片跑 `dzuav test.jpg ...`，确认 CellClassifier 识别率
4. **PnP 定位**：确认 `localized=1`，格号 ≥4 个且分散
5. **UDP 广播**：车端起 `integrate_node`，确认收到并解析
6. **空地链路**：车端起 `ag_integrate`，验 `/nav/waypoint` 有命令发出

⚠️ **不要一上来就全启**——会同时引入多个未知量，出问题无法定位。

## 3. 车端现状

### 3.1 定位链与坐标系（已与车端源码逐条核对）

```
[STM32 编码器+IMU] --串口 115200--> dzactuator --/odom--> serial_reader
    --/odom/localization(block 单位)--> path_executor(纯追踪) --/pursuitAngle--> dzactuator --> 底盘
```

| 项 | 定义 | 验证方式 |
|---|---|---|
| 单位 | **格（block）**，1 格 = 0.35 m | 源码常量；官方阈值 0.157 m = 0.45 格 |
| 原点 | 场地角点 **N11 = (0.5, 0.5)** | 起点信念 `(1.50, 0.50) ↔ N10` |
| 轴向 | `x = (11 − 行号) + 0.5`，`y = (14 − 列序号) − 0.5` | N10 → (1.5,0.5) ✓ |
| 范围 | x∈[0.5,10.5]（11 行）、y∈[0.5,13.5]（14 列） | serial_reader 注释 |
| 朝向 | 板载 IMU 的 yaw；raw→map 偏移 `+90°` | — |
| 位置 | **步长 × 当前朝向**逐帧累加（航位推算） | — |

⚠️ **`/odom/localization` 是格，不是米。** 历史上所有"位移 1.741 m"的报告都因此偏大 2.86 倍，真实值是 0.61 m。

### 3.2 画圆根因（结论 + 一个必须知道的局限）

**结论**（`docs/archive/朝向偏差根因-20261001.md`，实车实测）：
车"以为"的朝向与真实朝向相差**恒定 68.6°**，纯追踪因此把目标看偏一个固定角，绕着目标画圆，永远到不了。

**偏差从哪来**：`reset:N10,y` 不只断言位置，还**盲目断言朝向 = 90°**。车被搬到起点时实际朝向不一定是 90°，实测差 68.6°。

> ⚠️ **接手必须知道这个局限**：车只有航位推算、没有绝对朝向参考，它**无法自己知道**自己在场地坐标系里朝哪。
> 人的摆车 + reset 断言就是那个参考。"让车自己反推真实朝向"在原理上不成立，除非引入外部参考（无人机 PnP）。
> **heading_calibration.py**（`src/ag_integrate/ag_integrate/heading_calibration.py`）是纯数学工具函数集：0x4002 车位姿帧落地后，节点已接入其中的 `closed_loop_rate()` 做 align 闭环转向；docstring 描述的"直行探测五步校准"（`estimate_bias()`/`corrected_heading()`）节点并未实现，勿当成现役流程。

**决定性实验（当前第一步）**：把车**原地左转约 69°（俯视逆时针）**，重跑一格命令。
- 若车直线到达 → 摆位说成立，修法是**流程 + 校验**
- 若仍绕圈 → 偏差来自 yaw 源头，要改代码

### 3.3 车的能力边界

- 车是**执行器**，不是侦察器：能"按格号走 + 精确到位 + 到位后用自带相机认蓝红并打击"
- **不能**认网格/读格号（无模型）、**不能**自己规划去哪
- 车独立天花板 ≈ 10/100（驶离起点 5 + 回终点 5）；排雷 40、桥洞 20 **必须无人机**

### 3.4 ag_integrate：我们的车端薄集成

`src/ag_integrate/` 是官方框架上的一层薄集成：

```
UDP:50000（dzuav）→ integrate_node（收包→解析→态势归并→门控→路线）→ /nav/waypoint → 官方 path_executor
```

- 线程模型：UDP 后台线程只收包/解析，放入容量 1 的最新帧队列；ROS timer 回调做决策发布
- 安全默认：`dry_run=True`（只算不发），上车验证后再置 false
- 启动：`ros2 launch ag_integrate integrate.launch.py`
- 部署：`tools/car_deploy.py --host <车IP>`（打包→上传→colcon build→验证）

## 5. 现场环境坑（血泪表）

### 5.1 SSH 密码会"静默死等"
`tools/remote_run.py` 和 `tools/car_deploy.py` 没有 `AG_CAR_PASS` 时会弹 `getpass` 死等标准输入。
已改为：没有终端就**立刻报错**并告诉你该给什么。

### 5.2 命令会"空闲超时"被掐断
`remote_run.py` 要等远端跑完才回传输出。长任务（90s+）一律后台跑 + 轮询日志：
```bash
python tools/remote_run.py --host <IP> --user duzhong --cmd \
  "cd /tmp && setsid nohup bash /tmp/xx.sh > /tmp/xx.log 2>&1 < /dev/null & sleep 2; echo STARTED"
python tools/remote_run.py --host <IP> --user duzhong --cmd "tail -20 /tmp/xx.log"
```

### 5.3 `ros2` CLI 会被搞坏
反复 kill 进程组会把 ros2 daemon 搞坏，之后所有 `ros2` 子命令抛 `xmlrpc.client.Fault` 直接崩。
**修**：`ros2 daemon stop`（下次自动重启）。采样不要用 `ros2 topic echo`，用内嵌 rclpy 订阅器。

### 5.4 QoS：这两个话题是 BEST_EFFORT
`/pursuitAngle`、`/odom/localization` 都是 BEST_EFFORT；`ros2 topic echo` 默认 RELIABLE → 一条都收不到。
订阅端一律显式 `best_effort`。

### 5.5 行尾必须是 LF
车端是 Linux，`.sh` 带 CRLF 会 `bad interpreter`。本仓库有 `.gitattributes`，但新写文件仍可能是 CRLF。
提交前统一：`python -c "p='x.sh';b=open(p,'rb').read();open(p,'wb').write(b.replace(b'\r\n',b'\n'))"`

### 5.6 Windows 控制台是 GBK
脚本里别打印 emoji → `UnicodeEncodeError`。Python 工具开头统一 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。

### 5.7 ★ 桥洞位置：K 列说法已过时，以 ARROW 识别为准 ★
> **已过时**（2026-10-14 标注）：本节"桥洞占整个 K 列"是早期按裁判图示例
> （K4/K9）的推断。现代码不写死任何列：桥洞列由无人机 ARROW 识别动态推导
> （契约/工具示例默认 L 列），中场挡板只覆盖 D~N 列、A/B/C 列可自由穿越。
> 详见 `interface_contract.md` §7。以下仅作历史背景保留。

两处桥洞占据**整个 K 列**（A 段 K1~K5、B 段 K6~K11）。
起点 N10 朝 +y 正对 M/L/K 方向，直行 3 格就是 K 列。
**选路自检三条**：① 不用 K 列；② 不用 J/L 列（留一格余量）；③ 每段 ≥1.5 m。

### 5.8 绝不同时起两套定位
`/odom/localization` 有两个发布者时位姿会来回跳。动手前先 `ros2 node list` 确认车上是干净的。

### 8.1 ⚠️ 提交之后，务必确认"到底推没推到 Gitee"

仓库装了 `post-commit` 钩子：每次提交自动推送。但钩子末尾是 `|| true` —— **推失败也不影响提交**，
所以 `git commit` 表面永远"成功"，容易误以为已经同步。

- **怎么核实**：`git rev-parse HEAD origin/main`，两行必须一致
- **典型报错 1**：`could not read Username` → 凭据没配
- **典型报错 2**：`Could not resolve host` → 网络/DNS 问题
- **凭据修复**：`.git-credentials` 写 `https://<用户名>:<Gitee令牌>@gitee.com`，
  `git config --local credential.helper store`
- **2026-10-01 状态：已修复并核实。** 此后钩子可正常自动推，但若再失败仍静默，
  养成每次提交后 `git rev-parse HEAD origin/main` 核实的习惯。
