### 阶段 B：Orin 编译脚本 + 解释"本机不能编译"

用户："本机无 TRT/CUDA 无法编译，配一下环境不就行了？powershell 不要用，清华镜像源。"

- **本机不能编译的根因**（向用户解释过）：
  1. `UdpBroadcaster.cpp` 用 POSIX 头（`arpa/inet.h`/`sys/socket.h`/`unistd.h`）
  2. CMakeLists 硬编码 aarch64-linux-gnu 路径

- **结论**：apt 能配的（编译器/OpenCV/镜像源）脚本全配；TRT/CUDA 只随 JetPack 刷机提供，apt 装不了 → 脚本第一步自检环境。

- bash（非 PowerShell），清华 `ubuntu-ports` 源（幂等、备份 `.bak`、只换域名保留 focal/jammy 代号，NVIDIA L4T 源保持官方）

### 阶段 I：无人机相机排查（本阶段核心，结论已定）

**背景**：手册确认这台无人机（SmartScout，Livox MID360 激光雷达）**原厂无可见光相机**；实机上挂了一个相机模组（Type-A，红白绿黑四线=USB2.0 标准接线：红5V/白D-/绿D+/黑GND），向下安装（适合看地面格号）。

**排查过程**（每步都有实测证据）：
1. `/dev/video*` 无 → CSI I2C 扫描 0x10/0x1a 无芯片响应 → 排除 CSI 相机
2. `lsusb` 基线：Orin 上只有 `2109:0822 VIA Labs USB3.1 Hub`、`2109:2822 USB2.0 Hub`、`0bda:c822 Realtek 蓝牙`
3. 拔插相机线 + 清空 dmesg → **无任何 hotplug 事件**
4. 用手机（HONOR AAP-AN00 `339b:107d`）Type-C 线连接 → **Orin 识别成功**（挂 2109 Hub 下游）→ 证明**蓝色 USB-A 口 → 2109 Hub → Orin 链路是好的**
5. 相机 Type-A 头插同一个蓝色口 → 2109 Hub 下游依旧空、dmesg 无事件、无 /dev/video

**决定性结论**：
| 环节 | 结果 |
|---|---|
| 蓝色口 → 2109 Hub → Orin | ✅ 通（手机验证） |
| 相机 Type-A 插蓝色口 | ❌ 无枚举 |

**问题在相机侧：红白绿黑线 D+/D- 断路，或相机模组本身故障。**

**解决方案**（推荐序）：
1. 换一根标准 USB 线（若相机模组有标准接口 Type-C/Micro）
2. **换标准 UVC 摄像头**（最稳）：插蓝色口即认，dzuav `uvc:/dev/video0` 模式零改动
3. 万用表量四线导通（绿→Type-A 引脚2=D+，白→引脚3=D-）
