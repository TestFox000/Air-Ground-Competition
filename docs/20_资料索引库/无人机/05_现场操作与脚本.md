# 现场操作与脚本

## TL;DR（给 agent 看的）

- 起机四段：**A 感知层 → B 飞控链路 → C 验证 → D 控制层（人在座才起）**。B 段两处必须手写参数：--dev /dev/ttyACM<?> 与 mode:=odom，漏一个就静默失效。
- ⚠ **P0 凭据面**：dzsmartscout 根目录存在 **15 个一次性凭据/提权脚本**（清单见本文 §3，只给类别，**本册不复述任何口令明文**），且已被 git 跟踪、历史不可撤回。处置（轮换 → 回收机端 key → 移出仓库 → 加秘密扫描）由 Lead 单独立卡。
- 每个新终端先 source 两行，否则 `Package not found` / 「消息类型无效」。
- 判活只看 Publisher count ≥ 1，别看日志、别信 topic list。

## 2. 起机顺序（A→B→C→D）

**每个终端先来两行**：

    source /opt/ros/humble/setup.bash
    source ~/dzpx4/install/setup.bash

| 阶段 | 命令 | 通过标准 |
|---|---|---|
| A1 | ros2 launch livox_ros_driver2 msg_MID360_launch.py | /livox/lidar 10 Hz |
| A2 | ros2 launch fast_lio_localization velodyne_localization.launch.py rviz:=false | /Odometry 43~45 Hz |
| A3（仅需 /localization 时） | 三 python 节点随 A2 拉起 | /localization ~44 Hz |
| B1 | MicroXRCEAgent serial --dev /dev/ttyACM<?> -b 921600 | 日志不再 init running 循环 |
| B2 | ros2 launch px4_odom_convert px4_odom_convert.launch.py **mode:=odom** | /fmu/in/vehicle_visual_odometry ~43 Hz |
| B3 | ros2 launch px4_imu_bridge sensor_combined_to_imu.launch.py | 可选，机上无消费者 |
| C | ros2 topic info -v /fmu/out/vehicle_local_position；ros2 topic hz /fmu/out/vehicle_attitude | Publisher count ≥1；attitude ~133 Hz |
| D1 | ros2 launch px4_control px4_control.launch.py | **人在座**，agent 不代跑 |
| D2 | ros2 run px4_control px4_teleop_node --params-file …/params.yaml | **必须真 TTY**（否则 tcgetattr failed，键盘静默失效） |
| D3 | ros2 launch px4_path px4_path.launch.py | 跑哪个节点由 YAML record_mode 决定，无同名 launch 参数 |

**teleop 按键**：0 Offboard · 1 ARM+起飞 · 2 DISARM · 3 LAND · WASD/QE 平移 · L/R yaw · **4 使能 GOTO** · **5 撤销 GOTO** · Ctrl+C 退出（dzsmartscout/docs/无人机项目总览.md:204-216）。

## 4. 录包与飞行科目（飞之前先看这段）

| 项 | 规范 |
|---|---|
| 落盘位置 | ~/drone_bags（eMMC）。**绝不要写 /tmp**：重启即清空，10-17 就因此丢过整套栈 |
| 体积 | 约 **5 MB/分钟**；加 /livox/lidar 则 **+180 MB/min**（默认不加） |
| 停止方式 | kill -INT（别 SIGKILL，会损坏 sqlite） |
| 录制话题 | /fmu/out 六路 + /Odometry + /fmu/in/vehicle_visual_odometry，storage sqlite3 |
| ULog | 无 MAVLink ⇒ 只能**物理拔 SD 卡**读 /log/*.ulog；分析需 pyulog（未装） |
| 科目 | F0 悬停 60 s 手离杆 / F1 单杆阶跃 ×3 / F2 半杆连续 30 s / F3 起降 ×3 |
| 分段规则 | 按 arming_state 取解锁段 → 按 control_mode 贴语境 → 按 reset_counter 切段（观测到 31 次重置） |

（出处：docs/交接_无人机飞行分析_agent技术文档.md §7、§9。）

## 5. 现场坑表（按踩到频率排序）

| # | 坑 | 对策 |
|---|---|---|
| 1 | mode:=localization 静默不发（launch 默认值就是它） | 一律 mode:=odom |
| 2 | 域号不一致 = 静默失联（ssh 单条命令/cron/systemd 都不读 .bashrc） | 每次显式 export 或 source dzlink.env |
| 3 | ros2 topic list 里有 fmu 不等于通（看门狗订阅） | 看 Publisher count |
| 4 | teleop 用 setsid/nohup/管道 ⇒ tcgetattr failed | 必须真 TTY |
| 5 | 录制 kill -9 ⇒ 整段丢失 | Ctrl+C / SIGTERM |
| 6 | 录新路径却飞旧路径（path_file 指向 _2） | 现场 grep params.yaml |
| 7 | /dev/video0 独占（预览/录制/抓帧互斥） | 先停再起；VNC 用 ximagesink |
| 8 | pkill -f 不能加 -x（节点名超 15 字符） | 用 -f 不加 -x |
| 9 | dzsmart.local 解析到过期 IP | arp -a 扫段后手连 |
| 10 | USB-C gadget 模式（Type-C 可能只做 device） | 插飞控前查 /sys/class/udc/ |
| 11 | 机载可用 RAM 仅 2~3 G | 别开 RViz + 录包 + 检测三件套 |
| 12 | 旧实例不退、新实例 FATAL（duplicate-instance 保护） | pkill -TERM 后确认干净再起 |

（出处：_tmp_session/agent_overview_20261020/drone.md:241-254；docs/交接_无人机飞行分析_agent技术文档.md §4。） 〔失效：会话过程目录已清理〕
