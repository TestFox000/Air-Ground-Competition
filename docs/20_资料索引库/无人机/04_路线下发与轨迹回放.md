# 路线下发与轨迹回放

## TL;DR（给 agent 看的）

- **两个动作别混**：①**轨迹回放**（机自己照录制轨迹飞，px4_path）②**路线下发**（机把分段路线/情报发给车，/nav/waypoint + /dzlink/*）。
- 机侧不做规划：规划在车端，机只「按侦察到的布局决定下一段给车什么」。分册 A 版/B 版口径都指向这一点（01 篇 §1）。
- 关键缺口全在**段边界**：SEGMENT_DONE 漏收（D1b）、block 与 target 差半格导致永久 WAIT_INFO（D2）、路径坏按 4 无反应（P1-2）。
- 最大坑：QoS 反向不兼容 —— RELIABLE 发 / BEST_EFFORT 收发得到，**反过来静默 0 条而两端 count 都是 1**。

## 1. 轨迹回放（机自身，px4_path）

## 2. 路线/情报下发（机 → 车）三通道

| 通道 | 话题 | 类型 | 车侧真值 QoS | 内容 |
|---|---|---|---|---|
| A 路线 | /nav/waypoint | std_msgs/String | RELIABLE / KEEP_LAST(10) / VOLATILE | 裸文本 token 串（如 N10 M10 … N5,y）；load: 装载、reset: 重锚 |
| B 情报 | /dzlink/drone_to_car | std_msgs/String(JSON) | BEST_EFFORT | heartbeat / bridge_passable / target_zone / field_verify |
| C 回传 | /dzlink/car_to_drone | std_msgs/String(JSON) | BEST_EFFORT | car_state（1~2 Hz）+ ack{of:seq} |

**QoS 兼容铁律（t4 真机 8 格矩阵）**：RELIABLE 发 → BEST_EFFORT 收**兼容**；反向**不兼容、静默 0 条，而两端端点计数仍各为 1**。VOLATILE 无补发，首包必丢一（实测 **39/40**）⇒ 情报必须周期重发（机侧 supervisor 每条 3 遍 + bridge 每 2 s）。（dzsmartscout/docs/空地路线下发契约_v2.md:28-38；dzsmartscout/tools/reports/t4-链路验证报告.md:16-27）

**分段与等待**：段长 **6~8 航点**（约 1.5~2.5 m）；等机侧新版本 **≤10 s**，超时用最后完整布局继续（D-015）；心跳超时 **3 s**、情报过期 **30 s**、桥洞等待窗口 **2.0 s**（契约:103、:137-153）。

## 3. 与车端的状态机配合（段边界是全部风险的来源）

    机：读布局/情报（10 批）→ 定段目标 → 下发 → 等 SEGMENT_DONE → 下一段
    车：WAIT_LAYOUT → PLANNING → DRIVING → SEGMENT_DONE

| 缺口 | 现象 | 证据 |
|---|---|---|
| D1b SEGMENT_DONE 漏收 | 机侧采样 1.4 Hz、车端事件窗口 1~2 拍 ⇒ **漏收约 86%**；已有完成消息闩锁/重发代码，**未在实车复验** | fixes/06-car-wait-for-drone/APPLY.md；无人机项目详细报告:271 |
| D2 block 差半格 | 机侧判 block==target，D2 未修前会**永久 WAIT_INFO** | 同上；契约:§段边界 |
| 单写者冲突 | /nav/waypoint 存在双写者风险（控制台/机/车三方下发），互斥未落地 | dzsmartscout/docs/无人机项目总览.md §11.3③ |

## 5. 规划与下发的分工（已裁决，勿翻案）

| 主张 | 结论 |
|---|---|
| 无人机算路径再下发执行 | **不采纳**：机算力优势在 GPU/NPU 而非 CPU；规划输入（belief/覆盖/弹药）在车上；错情报会被放大；断链后车无法重规划 |
| 保持「知识在机、决策在车」 | **采纳**：机下发事实（bridge_passable / field_verify / coverage / 负证据），车本地重规划 |
| 建议路线制（advisory） | 留作未来折中，当前不上 |

（依据：dzsmartscout/docs/空地路线下发契约_v2.md §分工；drone.md:126-135 降级链路：外部路线 → 车端 planner → fallback_to_tokens mission_blocks（44 点）→ 仍出发。）
