# 协议 v2 与契约（车↔机）

## TL;DR（给 agent 看的）

- 现役**两代协议并存**：v1 = 情报门控（4 种 JSON，决定「穿哪个洞」）；v2 = 步进循环（field_layout 布局 + 段目标，决定「整条怎么走」）。**v1 真机跑通；v2 未上车**。
- 车端只认 4 种 v1 type，未知 type 只记日志不崩 ⇒ **加字段安全、加类型不安全**（新增类型必须改车端白名单）。
- 布局的 known 是「我观测过哪些格」，**车端 unknown = 不可通行**；known=154 才算完整布局。
- 最大坑：known **只增不减**且没有「空域」来源 ⇒ 可通行格≈特征格，段规划恒无解（详见 02）。

## 1. 两代协议的分工

| 代 | 话题 | 作用 | 状态 | 证据 |
|---|---|---|---|---|
| v1 情报 | /dzlink/drone_to_car → /dzlink/car_to_drone | 心跳、桥洞通行格、靶/雷/障差异 | **真机验证**（t4/t12/t16/t18，ack 为硬证据） | 手册 §2；dzlink_supervisor.py |
| v2 布局 | 同话题，type=field_layout | known 格集合 + target_cell 段目标 | **离线/仿真 + 1 次段链路实车**，未成为发车路径 | step_loop.md §2；FLOW_COMPARISON.md §5 |
| A 通道 | /nav/waypoint（RELIABLE） | 整线/reset:/load:/单点 | 真机（t4/t60 干跑 + 实车） | contract.py:73-74 |

## 2. v1 报文（车端消费面，字段级）

| type | 必填 | 车侧行为 | 出处 |
|---|---|---|---|
| heartbeat | type | 刷新心跳；>3.0 s 无心跳 → online=False + 一次告警 | drone.py:228,244-253；robot.yaml:888 |
| bridge_passable | half∈{lower,upper}、block | 写 P_DRONE + 发 EV_BRIDGE_INFO；Mission 据此换穿洞格 | drone.py:273-289 |
| target_zone | blocks（非空） | 与本地 map.yaml:targets 差集 → field_diff（只报差异，不改路线） | drone.py:292-304 |
| field_verify | mines 或 obstacles（带 coverage 时可为空表） | 同上；**带 coverage 时按片内作用域核对 + 记覆盖账本** | drone.py _on_field_verify |

- 车→机两种：car_state（1~2 Hz，drone.car_state_period_s=0.7）与 ack{of:seq}。**ack 是「车真的收到了」的唯一硬证据**——BEST_EFFORT 上「发出去了」≠「收到了」（手册 §2.2）。
- 归一化：half 转小写、block 转大写；**格名是否在地图内车侧刻意不校验**（穿洞格每局随机，无人机才是权威），兜底靠 Mission 候选集合校验（drone.py:280-281）。

## 3. coverage / slice / scan_id（负证据的地基）

| 字段 | 语义 | 车侧判据 |
|---|---|---|
| coverage.cells | 本片判读范围（格名） | 按 14×11 校验，越界/重复/空串剔除 |
| coverage.complete | true=片内判读完毕（片内未报即 **ABSENT**）；false/缺键=只报看得见的，其余仍是 **UNKNOWN** | **不得**把 false 当 ABSENT（test_drone.py ⑩） |
| slice{id,index,of,route} + scan_id | 片号与扫描批次 | 幂等键 (scan_id, slice.id)，同片重发整条忽略 |
| mode | full_frame / strip / waypoint_3x3 等 | 仅记录，不参与门控 |

- 覆盖账本 CoverageLedger：只把 complete:true 的片计入「已探明」，分母 **154**；done = 某次扫描 1..of 片齐全且全 complete（手册 §2.4）。
- **报文形状是 additive**：旧报文不带这些键全部可省，走旧「全图口径」；A/B 兼容 19/19 逐位一致（_tmp_session/drone_gap/ab_legacy.py）。

## 4. field_layout v2 字段（车端消费面）

| 字段 | 必填 | 含义 | 车端用法 |
|---|---|---|---|
| type | 是 | 固定 field_layout | drone.py:759 类型分发 |
| version | 是 | 内容世代，单调递增 | < 当前拒收；==当前但内容异也拒收（drone.py:851-870） |
| ts | 是 | 机侧时间 | 仅证据，不参与同版比对 |
| start/end | 是 | N10 / N5 | 段规划起终点（main.py:471-488） |
| known | 是 | 已观测格（可含空格），**单调只增** | 未在 known 的格 = unknown = **不可通行**（main.py:531-547） |
| mines/obstacles/targets | 是 | 已发现特征（⊆ known） | 硬校验，越界整份拒收（main.py:419-423） |
| bridges | 是 | 可通行桥洞，**≥1** | 空 = 整份拒收（drone.py:241-244） |
| barrier_col_from / barrier_row_hi / barrier_row_lo | 是 | 隔板三键（现役 D / 6 / 7） | 拓扑约束（drone.py:246-264） |
| target_cell | 否 | 本段目标格；空 = 车只等不做 | 不在 known 必须发空串（main.py:538-540） |
| segment_id | 否 | 段序号；目标一换就 +1 | 车原样带回（main.py:991-1008） |

- version 与 segment_id **必须是两个号**：known 长格会让 version 涨，若混成一个号，「SEGMENT_DONE 完成的是哪一段」不可判定 ⇒ 可能重压同一颗雷或跳段（_tmp_session/t3/emitter/README.md §4）。
- 机端下发节奏：有变化即发，**另 1 Hz 心跳重发同版**（防「2 分钟停发」）；车端按版本去重（step_loop.md §4）。

## 5. 车端校验与拒收顺序

| # | 条件 | 结果 |
|---|---|---|
| 1 | 必填/格式非法 | 整份拒收，保留上一份（drone.py:842） |
| 2 | version < 当前 | 拒收，计 layout_stale（drone.py:854） |
| 3 | version == 当前且内容（除 ts）不同 | 拒收，计 layout_rejects（drone.py:861-870） |
| 4 | 特征 ⊄ known / target_cell ∉ known / bridges 空 | 拒收（drone.py:235-244,278） |
| 5 | 起终点/隔板变化 | 拒收（emitter/README.md §2） |

## 6. EV_FIELD_VERIFY 的消费语义（谁默认怎么处置）

| 档位 | 行为 | 默认 |
|---|---|---|
| off | 完全不消费，回到零订阅旧行为 | 否 |
| **record** | **只记录**（黑盒 field_verify 键 + 遥测），**不阻断** | **是（缺省）** |
| alert | 记录 + 置 alert=true，供上层/遥测可见 | 否 |
| hold | 记录 + 置 hold=true 给上层裁决，**不自动停车/改线** | 否 |

- 开关：drone.field_verify_policy（缺省 record）、drone.coverage_enabled（缺省 true）；两键**未登记 SCHEMA**，一律 cfg.get(key, default)（手册 §2.4 注）。
- 关掉新逻辑（policy=off + coverage_enabled=false）时两个新黑盒键都不写，键集合与旧版相同。
- **当前 Mission 尚未读取该键**——「雷/障/靶驱动重规划」只落地在仿真台（手册 §2.4 末；无人机全要素感知_现状与方案.md §4.3）。

## 7. QoS 与域号

| 通道 | 话题 | QoS（车侧真值） | 兼容铁律 |
|---|---|---|---|
| A 路线 | /nav/waypoint | RELIABLE / KEEP_LAST(10) / VOLATILE | RELIABLE 发→BEST_EFFORT 收可兼容 |
| B 情报 | /dzlink/drone_to_car | **BEST_EFFORT** / 10 / VOLATILE | **BEST_EFFORT 发→RELIABLE 收 = 静默 0 条**，且两端端点计数各 1 |
| C 回传 | /dzlink/car_to_drone | BEST_EFFORT | VOLATILE 无补发：首包必丢一（实测 39/40）⇒ 必须周期重发 |

**域号有两套说法，必须分清指的是哪张 ROS 图**：

| 说法 | 值 | 出处 |
|---|---|---|
| A（车端 + 链路工具） | **118** | dzros.env、dzlink.env；手册 §0；t60 队长裁断（契约 v2 §8-1） |
| B（无人机飞行栈） | **0** | docs/交接_无人机飞行分析_agent技术文档.md:23（Humble、domain 0、FastDDS 默认） |
| C（2026-10-21 盘点） | 车 118 / 机 **0（未切）** | docs/20_资料索引库/README.md:90 |

⇒ 实操：**每次跑 ROS 命令都内联或 source 域号**；非交互 SSH 默认 0，症状是「ping/SSH 全通、零报错、互相看不见」。

## 8. A 通道 token 语法（route/parser.py + validate.py）

| 写法 | 含义 |
|---|---|
| N10 | 航点（列 A–N + 行 1–11） |
| D3* | 该点**停车打靶** |
| N5,y / N5,x | 朝向后缀，**只允许挂最后一个 token** |
| R:F11 | 该段倒车（真车 allow_reverse=false ⇒ 默认不发） |
| K9:PIVOT | 180° 折返声明 |
| reset:N10,y | 复位信念位姿 + 清路线 → IDLE |
| load:文件名 | 读车侧文件并出发 |
| SHOOT@G11 | 指令非坐标：车侧算候选链整链插入 |

- 门禁：tools/plan_route.py --emit tokens --engine <config 里那个> --check，**0 error 才放行**。
- ⚠️ /nav/waypoint 有**第二写者**：车上 start_path_executor.sh:35、send_waypoint.py:20；与机侧 supervisor 同跑会让路线在两个来源间跳（手册 §6 警告）。
