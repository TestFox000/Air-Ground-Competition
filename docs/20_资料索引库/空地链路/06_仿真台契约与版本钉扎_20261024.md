# 仿真台契约与版本钉扎（sim_studio 移交包提炼）

> **一句话**：仿真台 = **界面 + 编排层在插件、内核在 `dzrobot_v2`**；能被机器相信的只有那条 `SIM_RESULT_JSON` 行，
> 文字指标表**不再是契约**。本文只写结论与判据，62 键清单原文在包内（见 §6 原文位置）。
> （本文落库 2026-10-29；同步卡 §11 五问裁决，与 05 的链路口径互不重叠。）

## TL;DR（给 agent 看的）

- **契约只有一层是硬的**：stdout **末行** `SIM_RESULT_JSON {"schema":"dzrobot-sim-result/1",...}`。文字指标表是给人看的排版，
  **可自由调整**；机器消费只认那一行。这条一破，所有指标解析都变成猜排版。
- **62 键只增不改**；UI 真正依赖的只有 `record.metrics` **五键**（`finished/time_s/rms_m/out_of_bounds/length_ratio`），其形状冻结，
  全量 62 键进 `metricsFull`。**加字段安全，改/删键名必须升 schema 版本**。
- **`--json` 只能"探测到支持才传"**：旧内核 argparse 直接 `exit 2`，仿真**根本不跑**——此时"正则回落"救不回来，
  因为进程压根没启动。这是拿一次"仿真不跑"换来的判据，不是风格偏好。
- **两代 API 前缀并存不是兼容洁癖**：旧包 `dzrobot-ssh` 与新包 `dzairground-ssh` **同时挂在同一 DSH 上**，各注册各的前缀；
  独立宿主靠**剥前缀**同时认旧前缀/新前缀/裸路径三种入口。前缀属于宿主，不属于页面。
- **`_pinnedCommit` 现在是空钉**：字段值是中文指路句（不是哈希），插件真源指针里**根本没这个键** ⇒ 钉扎只存在于文档里，
  机器上无哈希可核，四条失效条件任一成立都会静默让"同参数不同数"。

## 1 三层契约：哪一层能改、哪一层不能

| 层 | 载体 | 契约强度 | 谁能改 |
|---|---|---|---|
| 内核 | `dzrobot_v2/src/dzbrain/dzbrain/tools/sim_cli.py` + `sim.py` metrics 键 | **强**（键只增不改 + schema 号） | 冻结区，走 CONTRACT §6 提卡流程 |
| 编排 | 插件 `D:/User/Desktop/ZhiYuan/dsh_plugin/dsh-dzairground-ssh/src/simbench.js` / `D:/User/Desktop/ZhiYuan/dsh_plugin/dsh-dzairground-ssh/src/stressbench.js` / `D:/User/Desktop/ZhiYuan/dsh_plugin/dsh-dzairground-ssh/src/dronesim.js` 的解析器 | 弱（跟内核走，两级回落） | 编排层 owner（不碰内核） |
| 界面 | `D:/User/Desktop/ZhiYuan/dsh_plugin/dsh-dzairground-ssh/sim.html` | 无（随便改） | 谁做 UI 谁改 |

**结论**：改排版安全、改键名不安全；加字段安全、删字段必须升 schema。判据不是"页面还能不能显示"，
而是"换一个人拿台账能不能复算出同一个数"。

## 2 62 键的稳定边界（是规则，不是清单）

**边界三条**（缺一条契约就漏）：

1. **键名只增不改**——内核 `sim.py` 头注 §5 是键名本体真源，`sim_cli.py` 只做序列化；
2. **五键摘要形状冻结**——`record.metrics` 的五键是 UI 依赖面，新增字段一律 additive 到 `metricsFull`；
3. **非有限浮点必须序列化成 `null`**——NaN/±Inf 裸进 JSON 会让整行解析失败，等于本次跑作废。

**本次复核（可复跑）**：包 CONTRACT §2 声明 62 键，按逗号切分后去重**仍为 62**（无重复键）；
内核 `JSON_SCHEMA = "dzrobot-sim-result/1"` 在 `dzrobot_v2/src/dzbrain/dzbrain/tools/sim_cli.py:47`，
`--json` 参数在 `:97`，成功路径在 `:284` 打末行，失败路径在 `:169` 也打一行（`ok:false` + `stage`）——
**失败也有机器可读结果**，这是设计上最值钱的一条。

**两个必须写进 UI 的读法规则**（否则 62 键会被读错）：

- **场地组不是"零"是"没建模"**：`field_modeled=0` 时 `field_stopped` / `bounds_margin_m` 等整块无意义，
  显示 `0` 会被读成"场地内零越界/零停车"。必须置灰并标注 `field_modeled=0`。
- **真值 RMS 与信念 RMS 是两个键**：`cross_track_rms_m` 是**真值**横向 RMS，`belief_cross_track_rms_m` 是**信念↔真值**。
  F-5 那次事故就是正则抓串了行，把后者当成了前者——**错的数比没有数更糟**，这也是必须走契约通道的第一理由（不是性能）。

## 3 `--json` 只能探测后传（一条规则吃掉三次事故）

**事故链（真实发生过）**：旧内核没有 `--json` → 编排层硬传 → argparse 不认这个参数，直接 `exit 2` →
**仿真进程根本没启动** → stdout 为空 → 正则拿不到任何指标 → 页面显示"仿真失败"，
而真因是"参数不被识别"。注意关键处：**回落解析救不了它**，因为回落是对 stdout 做的事，而这次没有 stdout。

**正确姿势三段**（包侧已写好，P0-3 照搬即可）：

1. **从 argparse 真源探测**，而不是比版本号：读 `sim_cli.py` 源码，看有没有 `add_argument("--json")` 声明，结果缓存；
2. **声明了才 `argv.push('--json')`**；没声明就不传；
3. **取 stdout 末行**解析，按 `SIM_RESULT_JSON ` 前缀定位，**不全文扫**（全文扫会被中间日志里的同名字段带偏）。

**为什么探测源码而不是比版本号**：内核**没有版本常量**，唯一的版本号 `schema` 是跟着 `--json` 一起出现的
——"有 schema 才能告诉你 schema 是几"，等于自证，无法用来判断"支持不支持"。源码里有没有那条 `add_argument`
是**唯一可直接观测的事实**。

**两个必须留痕的点**：

- 台账记 `simJson: true|false`。否则事后看到 `metricsFull` 是空的，无法区分"内核旧"与"解析坏了"。
- 回落是**两级**：先 `parseResultJson`，失败再 `parseMetrics`（五键文本）。回落的目的不是兼容漂亮，
  而是**保证旧内核仍然能跑完一次仿真**——宁可少 57 个键，不可一次都跑不出来。

## 4 两代 API 前缀为什么并存

**事实面**（两棵树各写各的，在各自宿主下都是"对的"）：

- **插件树**：页面常量 = `/api/dzairground-ssh`（`D:/User/Desktop/ZhiYuan/dsh_plugin/dsh-dzairground-ssh/sim.html` 第 427 行）；宿主**只注册**这一个前缀（`D:/User/Desktop/ZhiYuan/dsh_plugin/dsh-dzairground-ssh/index.js` 第 517 行）。
- **包版树**：页面常量 = `/api/dzrobot-ssh`（`D:/User/Desktop/比赛存档/v1/_tmp_session/SIM-STUDIO-MERGE-20261024/incoming/sim_studio/sim.html` 第 511 行）；包自带独立宿主在派发前把它**剥掉**再匹配
  （`D:/User/Desktop/比赛存档/v1/_tmp_session/SIM-STUDIO-MERGE-20261024/incoming/sim_studio/server.mjs` 第 50 行 `replace(/^\/api\/dzrobot-ssh(?=\/)/, '')`），裸 `/sim/*` 口径不变。

**并存的三个真因（都不是设计偷懒）**：

1. **改名史**：插件原名 `dsh-dzrobot-ssh`（前缀 `api/dzrobot-ssh`），现名 `dsh-dzairground-ssh`（前缀 `api/dzairground-ssh`）。
   旧包整份留在插件仓外的 `D:/User/Desktop/ZhiYuan/dsh_plugin/_archive/dsh-dzrobot-ssh-20261024-084607/`，**页面常量没跟着改** ⇒ 同一个 UI 存在新旧两种写法。
   对齐测试把归档旧包与现插件**同时 boot** 做前缀对照（`D:/User/Desktop/ZhiYuan/dsh_plugin/dsh-dzairground-ssh/scripts/verify-s1.mjs` 第 132/133 行），并真 fetch 旧宿主页面
   断言仍 200、正文常量仍是旧前缀（同文件第 260/261 行）——"两套前缀在各自宿主里各自成立"是被测试咬住的，不是巧合。
2. **同一份 UI 要跑在两种宿主**：DSH 插件挂载（前缀由宿主决定）+ 独立宿主（裸 `/sim/*`）。页面写死任一形态，
   换宿主必有一边**全接口 404**——CHANGELOG §3.1 第 1 条那个"致命 bug"就是这么来的（桩测试全绿，因为桩根本不走浏览器 URL）。
3. **两个宿主各剥各的，且方向不对称**：插件宿主**不剥**旧前缀（`D:/User/Desktop/ZhiYuan/dsh_plugin/dsh-dzairground-ssh/index.js` 里没有 legacy 剥离逻辑），
   包宿主**只剥**旧前缀。⇒ 页面常量与宿主注册必须**配对**；把包版页面直接挂到插件前缀下就是 404
   —— 这是 F-9"包不能整包覆盖"里最容易被忽略的一条。

**解法在宿主边界，不在页面**：独立宿主在派发前剥前缀再匹配，裸路径口径不变 ⇒ 一份页面在它自己的宿主下认多种入口。
由此得出一条规矩：**页面里的 API 前缀属于宿主，不属于页面**；新增路由先问"这个前缀是谁注册的"，
别在页面里改常量去"对齐"。

## 5 `_pinnedCommit`：现在的钉是空的

**设计意图**：让"这次跑出来的数属于哪一版内核"**可被机器核验**，而不是靠人记。
字段就挂在根指针文件上（和 `root` 同文件，天然跟着工作区走）。

**实测三条（这才是当前真相）**：

1. 包 `D:/User/Desktop/比赛存档/v1/_tmp_session/SIM-STUDIO-MERGE-20261024/incoming/sim_studio/sim-root.json` 第 4 行 `_pinnedCommit` 的值是**中文指路句**「见 CONTRACT.md §5 的版本钉扎说明」，
   **不是 commit 哈希** ⇒ 机器无法比对，只能人去读文档；
2. 插件真源指针 `D:/User/Desktop/ZhiYuan/dsh_plugin/dsh-dzairground-ssh/sim-root.json` 里**没有 `_pinnedCommit` 键**（只有 `root` + `note`）⇒ 换一份指针文件，钉扎字段**直接消失**；
3. 包 `root` 烧的是打包机死路径，插件 `root` 指本机真源——两份指针**只有 `root` 被真正读取**，
   钉扎字段**全树零消费**（与 F-4"内核有 JSON 契约、消费端零引用"是同一个病：写侧有、读侧无）。

**于是"版本钉扎"实际退化为一次人工仪式**（CONTRACT §5 的三步）：`GET /sim/root` 必须 `ok:true` → 跑一次 `/sim/run` →
与移交方**同日**记录比 `completed / time_s / cross_track_rms_m` **三项数量级一致**。
注意判据只是"数量级"——它只能抓住"内核完全不同源"，抓不住"同源但物理改了"。

**失效条件（四条，任一成立则 62 键不可跨时间比较，且没有任何机器信号报警）**：

1. **换机器**（`root` 指向另一份 `dzrobot_v2` 副本）；
2. **换分支/换提交**（同路径不同 HEAD）；
3. **内核改了物理但没升 schema 号**（schema 只随"契约破坏"升，不随"数值变化"升——这是设计取舍，不是 bug）；
4. **`/sim/root` 报 `ok:false` 时仍继续跑**（前三条是"比较失真"，这条是"根本没指对"，`GET /sim/root` 是唯一闸门）。

**能机器化的最小改造（未做，需裁决）**：把 `_pinnedCommit` 填成 40 位哈希 + 台账每次记实际 HEAD 短哈希，
不一致时台账标 `pinned:false`。属**编排层**改动，不动内核、不碰冻结区。
