# 车侧话题对账（2026-10-18 审计）

## TL;DR（给 agent 看的）

- 结论一句话：**主干收敛且自洽**（双核互斥、驱动单通道、云台三信号接通、odom 中继是有意单跳），**但有一处真 P0**——决策核 dzbrain 与底盘 dzactuator 之间，除了「运动指令 + 语音开关」，其余**显式停车/使能/车辆状态信号全部错位悬空**，停车目前只靠底盘 1.0 s 看门狗兜底。
- 另有 4 类低危多余：底盘发 7 个**零订阅**诊断量；两个包**同名可执行** dzactuator_node；dzjudgment 保留已下线面板的**死镜像**话题；manual_override / manual_gimbal **无生产者**（人接管已无入口）。
- 口径：本篇对账对象是车端 **~/dzrobot 原版栈**（98 KB 云台 cpp）。**10-23 起车端还有第二套 ~/dzrobot2**（26 KB 重写版，归属未确认）——在那套上任何「已修/已通」结论都**不适用**，先确认在哪套上验的（交接_20261023 §1）。
- 与 [02_链路联调与已知缺口.md](02_链路联调与已知缺口.md) 分工：02 讲**空地链路**（D1b/D2/D3、v2 三块地基）；本篇讲**车内侧 dzbrain ↔ dzactuator ↔ 云台**。

## 1. 方法与边界

- 方法：把 start_all.sh + 各 launch + 各节点（C++/Python）的发布/订阅**全部列出**，做「生产者 → 消费者」反向对账；每行给 `文件:行`。
- 不覆盖：决策台账交叉核对（原审计明确边界）、旧核 path_executor 与 dzbrain 的逐行对称性（只确认二者互斥且 pursuitAngle 单发布者）、无人机对端（离线）。

## 4. 缺口（按优先级）

### P0 ① 决策核 ↔ 底盘的显式停车/使能信号是断的

底盘订阅、但**全代码树无生产者**（只出现在 `_archive/20261023/旧核todo_20261003/武官.json` 这类需求文档里）：

| 话题 | 底盘订阅位置 | 生产者 |
|---|---|---|
| StopCmd | dzactuator.cpp:1171 | 无 |
| logicontrol | dzactuator.cpp:1162 | 无 |
| laser_switch | dzactuator.cpp:1166 | 无 |
| vehicle_state | dzactuator.cpp:1168 | 无 |
| vehicle_Drivestate | dzactuator.cpp:1169 | 无 |
| cmd_vel | dzactuator.cpp:1160 | 无（新核发 pursuitAngle） |

而 dzbrain 实际发的是**另一套名字**：`stop_signal`（contract.py:87）、`motion_state`（contract.py:89）、`scan_request`（contract.py:80）。

**后果**：决策核与底盘之间只有 pursuitAngle（运动）+ voice_switch（音频）两条真通；**显式急停 / 激光使能 / 车辆状态全部悬空**，唯一兜底是底盘 1.0 s 看门狗（零 Twist=刹车）。现场若要「决策核主动急停」或「激光使能握手」，实际接不通。

### ② 底盘 7 个零订阅诊断量（白占 DDS 带宽）

全树无订阅：`raw`（:1149）、`imu_msg_valid`（:1150）、`PowerVoltage`（:1146）、`Battery_Percentage`（:1147）、`current_vel_state`（:1154）、`navi_cmd`（:1153）、`wakeup_signal`（:1155）。新栈只读 /odom/localization 与 /imu_data。低危，但属明确多余。

### ③ 两个包同名可执行（可读性雷）

- dzactuator 包：bringup.launch.py:55-57 `executable=dzactuator_node, name=dzactuator`
- 云台包：dzrknn_dataprocess.launch.py:43-44 `executable=dzactuator_node, name=dzrknn_dataprocess`

运行时不冲突（包不同、节点名不同，launch:32 定 NODE_NAME=dzrknn_dataprocess），但**二进制同名**，极易看错「这个 dzactuator_node 到底是底盘还是云台」。建议云台侧改专属名。

### ④ dzjudgment 的死镜像话题

`/referee_cmd`（judgment.cpp:59-60）与 `all_Material_Number` / `enemy_Material_Number` / `self_Material_Number`（:62-65）只面向**已下线的浏览器控制台**（start_all.sh:224-232）。其中 `HpAndHitmsg` 仍被 dzbrain referee.py 消费（活），其余为死镜像。建议标 deprecated 并登记台账。

### ⑤ 两条「兜底源」恒空

`/referee/hit`（contract.py:103）、`/referee/ammo`（contract.py:106）——作者自注「兜底源，referee_hp 才是真源」。当前恒空，低危。

### ⑥ 人工接管输入 orphan

`manual_override`、`manual_gimbal` 全树**无生产者**（旧生产者是已下线浏览器控制台），但 dzbrain（ros_io.py）与云台 cpp:1271 仍在订阅。与 start_all.sh:228-230 自注「遥控器没有替代品了」一致——**已知缺口**，应入台账。
