# 链路联调与已知缺口

## TL;DR（给 agent 看的）

- 三个未闭环缺口按代价排：**D1b**（SEGMENT_DONE 漏收 ≈86%，段末永久等）> **D2**（到站 block 差半格/一格）> **D3**（停站 0 发，根因在视觉与云台册）。
- 联调第一铁律：**BEST_EFFORT 发 → RELIABLE 收 = 静默 0 条**，两端端点计数仍各 1；判断「通没通」只看 **ack**。
- v2 步进循环 2026-10-18 审计结论是 **NO-GO**：缺「空域 known、段规划门禁、段末回报不丢」三块地基，且全链一次实车都没跑过。
- 域号不一致的症状是「ping/SSH 全通、ROS 零报错、互相看不见」——先怀疑域号，别怀疑代码。

## 2. D1b：SEGMENT_DONE 只活 1~2 拍

| 项 | 内容 |
|---|---|
| 现象 | 段完成事件窗口只有 1 拍（`main.py:700-713` → `859-870`），机侧 1.4 Hz 采样（`drone.py:547`）⇒ **漏收率约 86%**，段末永久 WAIT_INFO |
| 加剧 | 发射器「催版」默认关（`layout_emitter.py:568-569` `escalate_after=0`），车端 `step.wait_timeout_s=0` 无限等（`robot.yaml:730`） |
| 修法 | 完成单闩锁 + 1 Hz 重发 + 单调 `done_seq`；`escalate_after` 改非 0 |
| 状态 | 代码已提交（`238f6ce`，10-19），**未实车复验** |

## 3. D2：到站上报差半格/一格

| 项 | 内容 |
|---|---|
| 现象 | 到站 `block` 与 target 差半格/一格（例：目标 E5 报 E4），机侧 `block==target` 判据不成立 ⇒ 永久 WAIT_INFO |
| 机制 | `MissionTask._install_route()` **不复位 `_stall_last_s`** ⇒ 新段进度判据永假 → 12 s 后「拐角绕圈兜底」强跳末点（`done.block=目标 / pose_block=上一格`） |
| 修法 | 按 `segment_id/target_cell` 关联，不用 `block` 字面相等；同时在 `car_state` 带 `segment_id/target_cell/stop_kind/version` |
| 状态 | **未修**（`EMITTER_CROSSCHECK.md` E4、现场报告 D2 同签名） |

## 4. D3：射击停站 0 发 / 0 中

- 10-18 第七图实跑：F9 停站 30.10 s 硬死线 **0 发**；全轮 2 发（均在离站后的行进段）、0 中（现场日志口径，见 `docs/00_项目总览/现状快照.md` 同题记录）。
- 根因不在链路：开火 7 条 AND + 提前量只进判据不进控制环 + 类别锁被闪烁清零，见 [../视觉与云台/01_云台瞄准与开火链路.md](../视觉与云台/01_云台瞄准与开火链路.md) §6/§8。

## 5. v2 的三块地基缺口（NO-GO 理由）

| # | 缺口 | 一句话证据 |
|---|---|---|
| 1 | **known 没有「空域」来源** | 机载 13 类里 `CELL_LABEL`/`BUCKET_*` 被显式丢弃，`known` 只收「有检出物」的格（`_tmp_session/t3/perception/perception_cells.py:96-97,219`）；车端 unknown=blocked ⇒ 可通行格≈特征格，段规划恒无解 |
| 2 | **段规划完全不过门禁** | `main.py:513-570` 直接 `plan_segment_route`，无 `check_planned_route`、无物理净空（`planner.engine=tour` ⇒ `grid.move_ok`，无车体扫掠） |
| 3 | **布局没有新鲜度门** | `layout_ts` 不参与任何判据；`drone.info_stale_s` 只管桥洞情报 ⇒ 30 s 前的布局与刚采的不可区分 |
| 4 | 双写风险 | `/nav/waypoint` 命令通道仍在（`mission.py:3901-3955`），与 `field_layout` 并列成为路线写者，单写者互斥未落地 |
| 5 | 完赛判定降级 | StepLoop 只在「段完成格 == layout.end」时 FINISH，不再校验雷覆盖/射击/靶位（`main.py:859-870`） |

## 6. 机端四个必修坑（对端交叉验证得出）

| ID | 坑 | 后果/修法 |
|---|---|---|
| E1 | `known` 漏了**车当前格**（recon 批次 129 格不含 N10） | 车第一拍就 `SAFE_STOP：belief 连续落在未知格`（`main.py:1034`）。规划器对起点破例、运行期护栏**不破例** ⇒ 每份布局 known 必须含车位姿所在格 |
| E2 | 特征类别与现役真值图冲突（B7 真值是障碍，recon 报 target_blue） | `_stop_kind_with_spec()` 把 obstacles/targets 都当禁站格 ⇒ 该停的靶被当桶、该避的桶被当靶 |
| E3 | dry_full 建在**第六图**，车/机部署是**第七图** | 按第六图发的布局会漏压雷、撞桶、停错靶位；机端真值钉 `~/dzlink_tools/map7.yaml`，**不要**用仓库 `config/map.yaml` 当真值 |
| E4 | `belief` 段完成差一格（B10→B11） | 按 `segment_id` 消费，不要用 `block == target` 字符串判据 |

## 7. 仿真给出的三个硬数字（30 组合 × 4 朝向）

| 策略 | 完赛率 | 预算通过率 | 蓝面命中率 | 均等待 |
|---|---|---|---|---|
| 无无人机 | **3.3%** | 100%（n=1） | 0.8% | 0 |
| 理想揭示（权威门+桥前等待） | **100%** | 75.0% | 75.0% | 2.14 s |
| 受限（起飞晚 8 s + 朝向误判） | 100% | **57.5%** | 0% | 9.44 s |

- 无情报直冲的失败概率 **29/30 = 96.7%**；叠加靶朝向，「完赛且蓝面得分」≈ **1/120 = 0.83%**（`docs/空地联合仿真设计.md` §9a）。
- 预算不过的根因**不是等待、是路线长度**：最长 K7/K1 24.85 m，0.15 m/s 巡航 172.62 s，加驻留即超 180 s（§8 末）。⇒ 建议巡航 ≥0.25 m/s。
- 关键结论：现车采纳门（候选∩地图桥洞）使无人机**无法纠正过期地图**——B2 臂理想情报 K9 被判 rejected，车按默认 K10 直冲封死桥室 5.92 s 中断（§7 台账、§10-1）。

## 8. 现场起栈顺序与判据（T3 runbook 摘要）

| 步 | 动作 | 判据/失败动作 |
|---|---|---|
| 0 | 预检 `python preflight_t3.py` | 0 个 FAIL；SKIP 逐条看懂 |
| 0.2 | **车端 `~/dzrobot/config/map.yaml` 必须不存在** | 存在则走「规划一次」旧路，步进循环根本不启用（`main.py:1077-1087`）⇒ 先 `mv ... map.yaml.t3bak` |
| 1 | 摆场 | 雷 8 / 障 8 / 靶位 / 通口 与图一致，否则停 |
| 3 | 机端起 dzuav | `localized=1` 才算通；90 s 不出就停 |
| 4 | 机端起 bridge | `/dzlink/drone_to_car` Publisher=1；**先 export 域 118** |
| 6 | 车端起栈 | 横幅 `ROS_DOMAIN_ID=118`；布局门 **30 s**，超时 **exit 3 且不出发** |
| 7 | 确认首份布局 | `✅ 收到布局 v2（known N 格）→ 进入运行期步进循环`；特征 ⊆ known |
| 10 | 收工 | 先停车栈 → 停 bridge/dzuav → 还原 `map.yaml` 与 `auto_plan_enabled=false` |

- 已知坑：`SEGMENT_DONE` 只保持 1 拍（0.1 s）；同名异内容只有 DroneTask 拒、StepLoop 只比 version；`car_state` 不是心跳（心跳靠 DroneTask 0.7 s 周期发）。
