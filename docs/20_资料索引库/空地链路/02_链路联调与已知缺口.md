# 链路联调与已知缺口

## TL;DR（给 agent 看的）

- 三个未闭环缺口按代价排：**D1b**（SEGMENT_DONE 漏收 ≈86%，段末永久等）> **D2**（到站 block 差半格/一格）> **D3**（停站 0 发，根因在视觉与云台册）。
- 联调第一铁律：**BEST_EFFORT 发 → RELIABLE 收 = 静默 0 条**，两端端点计数仍各 1；判断「通没通」只看 **ack**。
- v2 步进循环 2026-10-18 审计结论是 **NO-GO**：缺「空域 known、段规划门禁、段末回报不丢」三块地基，且全链一次实车都没跑过。
- 域号不一致的症状是「ping/SSH 全通、ROS 零报错、互相看不见」——先怀疑域号，别怀疑代码。

## 7. 仿真给出的三个硬数字（30 组合 × 4 朝向）

| 策略 | 完赛率 | 预算通过率 | 蓝面命中率 | 均等待 |
|---|---|---|---|---|
| 无无人机 | **3.3%** | 100%（n=1） | 0.8% | 0 |
| 理想揭示（权威门+桥前等待） | **100%** | 75.0% | 75.0% | 2.14 s |
| 受限（起飞晚 8 s + 朝向误判） | 100% | **57.5%** | 0% | 9.44 s |

- 无情报直冲的失败概率 **29/30 = 96.7%**；叠加靶朝向，「完赛且蓝面得分」≈ **1/120 = 0.83%**（`docs/空地联合仿真设计.md` §9a）。
- 预算不过的根因**不是等待、是路线长度**：最长 K7/K1 24.85 m，0.15 m/s 巡航 172.62 s，加驻留即超 180 s（§8 末）。⇒ 建议巡航 ≥0.25 m/s。
- 关键结论：现车采纳门（候选∩地图桥洞）使无人机**无法纠正过期地图**——B2 臂理想情报 K9 被判 rejected，车按默认 K10 直冲封死桥室 5.92 s 中断（§7 台账、§10-1）。

## 8.1 情报三态与「半步版」（D-037）

> 台账管**否决**（哪些做法不许），本节是方法真源。

- **三态**必须显式区分：① **live**（真机在发）② **replay/回放**（历史数据重放）③ **sim/仿真**。判据：`car_state` 不是心跳、布局只有 `version` 递增才算「新」——**面板不许直发**（控制台不得绕过单写者直接下发 route/waypoint），**sim 不许画成 live**（仿真输出来源必须标注，不得在面板上冒充现场）。
- **C1 半步版**（有条件放行）：允许先在 link 侧做「半步」验证（收帧/解析/剔除），但**不得**据此宣称步进闭环通过——闭环判据仍是车端真正按布局规划并行驶。
- 为什么这么严：本册已多次出现「机制上应该通」被当成「实测通过」（D-056/D-057 现场教训：无帧即不规划、不上车即不算通）。

## 8.2 发送器参数边界与历史修复（t12/D4 · t18/F2）

> 为什么单列：这四条是**操作者会照抄**的参数边界。写错时发送器要么 exit 2 当场拒（看得见），要么**静默发出畸形格名**（看不见，等车侧拿去做 `field_diff` 才发现算错）。源码里的修订说明带历史任务号、属过程记录；现行边界与「为什么必须这么写」留在本节。代码级逐函数清单见 `docs/00_项目总览/技术全景_D_无人机.md` §2.7.2（本篇只引用，不复述）。

| 边界 | 现行可执行写法 | 写错时的真实现象 | 落地位置 |
|---|---|---|---|
| `target` 收格名 | 位置参数 `target G10 H10` 与 `--blocks G10,H10` **等价**（两者合并后再统一拆分）。**现行版本两种写法都收**：实测两种写法均 exit 0、`blocks` 输出逐字相同 `["G10","H10"]` | **只在 t12/D4 修复前（2026-10-12 之前）的历史版本**里，`target` 只吃位置参数：那时写 `target --blocks G10,H10` 会被 argparse 判 unrecognized arguments → **exit 2**，而当时两份在库文档写的正是这个错用法。**这条是历史记录，不是现行现象**，现行写法见左列 | `dzsmartscout/tools/link/dz_send_waypoint.py:301-306`（`blocks` 位置参数 + `--blocks` 别名 `dest="blocks_opt"`） |
| 格名分隔符 | 空格 / 逗号 / 分号 / 竖线 / 顿号一律拆开 → 去空 → **大写** → **按序去重**；`None` 不转成字面量 `"None"` | 不拆时 `--mines A3,B4` 原样生成**畸形格名** `"A3,B4"`，**全程不报错** | `dzsmartscout/tools/link/dz_send_waypoint.py:93-109` |
| `bridge` 单半场 | `bridge <half>=` **只收一个格名**；两个半场用位置参数并列 `bridge lower=K9 upper=K4`，或分两次调用 | `bridge lower=K9,K4` 以前**静默发畸形值**；现在明确报错，并给出本发送器可执行的两种写法 | `dzsmartscout/tools/link/dz_send_waypoint.py:353-361` |
| `--bridge` 归属 | `--bridge` 是 **`dzlink_supervisor.py` 的参数**，本发送器不认；在 sender 上照抄 → argparse unrecognized arguments（exit 2） | t18 之前，sender 的**报错提示自己在教这个错用法**（把 supervisor 的参数写成 sender 的建议） | `dzsmartscout/tools/link/dzlink_supervisor.py:1499` |

### 为什么车侧逼着发送器必须拆（局部约束，别删）

车侧情报入口 `dzrobot_v2/src/dzbrain/dzbrain/tasks/drone.py:1324` 的 `_norm_blocks()` **只做 strip + 大写**：不拆逗号，只挡空串与非字符串；并且**有意不校验格名是否在地图内**（无人机看到本地没有的格是合法的核对输入，挡掉就等于核对功能永远报不出差异）。因此畸形格名 `"A3,B4"` 会被当成**一个格名**进 `field_diff`，比对从此失真且无人报警 —— 拆分只能发生在**发送端**。

- 原始输入带逗号/分号时，发送器往 **stderr** 打一行「已按逗号/分号拆分为 N 个格名」：不静默改变用户输入。
- 只给 flag 不给格名（`target --dry-run` / `field --mines --dry-run`）是**明确报错 exit 1**，不是「空列表照发」。
- 退出码**分五类**（源码 `dzsmartscout/tools/link/dz_send_waypoint.py:45` 的 docstring 只写了 0/2/3，实测另有 1 与 130，此处据实补全）：**0** 正常；**1** 语义性拒绝（`raise SystemExit(字符串)`）：`target` 缺格名 :371、`field --mines` 缺格名 :381、`bridge <half>=` 给**多个**格名 :353-361（`if len(got) != 1` 及其报错体）；另 `bridge` **缺 half**（一个 `lower=`/`upper=` 都没给）是 :349，语义不同、勿混用；**2** 有**两个**来源 —— ① argparse 解析失败（未知参数/未知子命令，如 `target --nonsense` 实测 exit 2）+ ② **缺 ROS 环境**（`ModuleNotFoundError/ImportError` 分支 :439-442）；**3** 发出去了但**没有任何小车订阅者**；**130** Ctrl-C（:432-433）。报文构造函数、QoS、重复发送理由**仍留在源码与 `docs/00_项目总览/技术全景_D_无人机.md` §2.7.2**，本节不搬。
