# 资料索引库 = 本项目「百科全书」

## TL;DR（给 agent 看的）

- 这里是**查事实**的地方：不知道就翻这里，不要全仓 grep、不要问人。
- 三种查法：①**知道名字**（文件/模块/参数）→ §3 专题导航；②**只知道现象**（车不动、激光不亮、ROS 看不见）→ §4 症状索引；③**要数字**（多少 mm、多少 Hz、多少套）→ §2 数字速查。
- 每条事实都带出处（`路径:行号` 或「文件 + 章节」）；标「未核实」的就是**没人验证过**，别当结论用。
- 旧路径原文在 `docs/_archive/<原路径>`；正文里出现的旧路径一律按此规则取文件。

## 4. 症状索引（只知道现象时按这查）

| 症状 | 先去哪 |
|---|---|
| 车「收到了指令但不动」 | `车端/05_配置与部署.md` → cam_viewer 抢 `/pursuitAngle` |
| 传了 `--map` 却不进布局模式 | `车端/05` → 必须传**不存在**的路径 |
| ping/SSH 通，但 ROS 互相看不见、零报错 | `车端/05` + `空地链路/02` → 域号（非交互 SSH 默认 0） |
| 起栈后相机/视觉/云台三节点同时 abort | `车端/05` → `robot.yaml` 顶层裸键 |
| 激光不亮、且没有任何报错 | `视觉与云台/01` → `/LaserShot_Command` 订阅数必须 = 1 |
| 停站 30 s 一发没打 | `视觉与云台/01` + `/03` → `fire_ready` 三条件/提前量 |
| det_node 起来就崩 | `视觉与云台/02` → 必须 `draw:false`（无 X 时 GTK 崩） |
| 车半路停死、必须重启栈 | `车端/04` → `SAFE_STOP`/`yaw_untrusted` 闩锁 |
| 规划器一半的图无解 | `车端/03` → 43.75%，结构约束 |
| 到点报错差半格/一格 | `空地链路/02` → D2 `block==target` |
| 无人机起不来 / `/fmu/out` 无数据 | `无人机/02` → uXRCE 会话卡死需飞控断电 |
| 机上检测 det=0 | `无人机/03` → 相机断流 + 实拍帧未验证 |
| 验收说「你改的没生效」 | `现状快照.md` → 本地/车端版本对照表 |

## 5. 高频坑（Top 12，全量见各分册）

1. `cam_viewer` 以 20 Hz 发全零 `/pursuitAngle`，底盘每帧更新 ⇒ 车不动。跑车前必 kill。
2. 布局模式 `--map` 指向**存在的**文件即进文件模式；`start_all.sh:220` 恰好传 `config/map.yaml`。
3. 非交互 SSH 域号变 0：必须 `source dzros.env`。
4. `robot.yaml` 顶层裸键 ⇒ 三节点 abort（地图放 `config/map.yaml`）。
5. `det_node` 无 X 时 `cv::imshow` 崩 ⇒ `draw:false`。
6. `dzrknn_dataprocess` 的可执行文件叫 `dzactuator_node`，与底盘包同名。
7. BEST_EFFORT 发 → RELIABLE 收 = 静默 0 条，但端点计数各为 1。
8. 第七图有**两版识读**（差 3 雷 4 障），引用必写版本。
9. 云台 PID 有 **5 套口径**并存，调参前先 diff。
10. 仓库地图（第六图）≠ 车端地图（第七图）；部署刻意不推地图。
11. `restart_node.sh path` 指旧核；改路线/速度必须 `start_all.sh restart`。
12. `healthcheck` 不是起栈门禁（自检已收敛到发车前 10 s 窗口）。

## 6. 使用纪律

- 本篇与各分册**只写已核实的**；不确定一律写「未核实」，不许用「应该是」。
- 发现本篇与代码/现场不符 → **以代码和现场为准**，并回来改本篇（改完在 `00_索引.md` 更新日期）。
- 新增知识要**先通读再写入**（`AGENTS.md` §8.2），并登记到所属册的 `00_索引.md` 与本目录 `docs/目录索引.md`。
