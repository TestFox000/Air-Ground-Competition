# 旧核技术手册（2026-10-03）

## TL;DR（给 agent 看的）

- 这是 10-03 旧核（src_v1：path_executor + serial_reader 死推算）时代「唯一权威技术文档」的提炼。10-07 血统切到 dzbrain 后，全文不再是现行判据；本册只保留四类仍有价值的东西：①硬件与场地硬约束；②旧核话题表与双单位陷阱；③14 条坑清单（多数今天仍适用）；④当时 P0 的成因。
- 一句话概括旧核：格单位死推算 + 纯追踪 + 航段索引护桥 + 越界急停。与今天的差别不在算法思想，而在「谁做决策」——旧核是单文件 path_executor.py（≈2614 行），今天是 dzbrain 8 线程。
- 最贵的教训（今天仍适用）：ticksPer2PI 未标定 ⇒ 命令转 90° 实际只转约 38°；10-03 第八次实车第一段横偏 3.56 m，被越界急停兜住。
- 引用纪律：本篇每个数字先问「旧核还是新核」。例：ticksPer2PI 旧 3236 / 今 2680；ticksPerMeter 旧 3290 / 今 3280。

## 3. 旧核数据流与话题表（含双单位陷阱）

    相机/IMU/编码器 → dzactuator（底盘串口聚合 /odom /imu_data）
      → serial_reader（重基线）→ /odom/localization（格单位）
        → path_executor（纯追踪 / 桥洞 / 越界急停 / 射击停站）
           → pursuitAngle（度）→ dzactuator → STM32
           → scan_request / 停车 → 云台（dzrknn_dataprocess）
           → /LaserShot_Command → dzjudgment → 串口 → 裁判

| 话题 | 类型 | 生产者 → 消费者 | 单位/口径 |
|---|---|---|---|
| /odom/localization | Odometry | serial_reader → path_executor | 格单位（x=11.5-row, y=13.5-col，米 = ×0.35） |
| pursuitAngle | Twist | path_executor → 底盘 | angular.z = 舵角度数 |
| cmd_vel | Twist | 遥操作 → 底盘 | angular.z = rad/s（与上不同，C9） |
| offset_center | Int32MultiArray | det_node → 云台/网页 | 8 下标：dx, dy, cls(0/1/2), w, h, kp_x, kp_y, conf×100 |
| /nav/scan_request | UInt8 | path_executor → 云台 | 2=持续扫描；发过就不发 0 |
| /shoot_count | Int32 | 云台 → path_executor | 已发弹数 |
| /LaserShot_Command | UInt8 | 云台 → dzjudgment | 单跳，非回环 |
| HpAndHitmsg | UInt8MultiArray | dzjudgment → dzbrain referee | 命中闭环真源（今天仍在用） |

两个必须记一辈子的陷阱：① 同名 angular.z 两套单位（度 vs rad/s）；② /odom/localization 是格不是米。

## 4. 旧核算法四件

1. 定位：IMU 提供航向、轮速计提供步长，做轮式死推算；地图粒度 0.35 m，精瞄靠视觉。会漂移。
2. 循迹：纯追踪 δ = atan2(2L·sinα / Ld)，Ld 随速自适应；输出舵角（度）。
3. 桥洞保护：用航段索引（非几何距离）标记穿洞段，进入前锁航向直行——教训来自「离保护点 <2 格就锁 ⇒ 该拐不拐」（readme 第 37 条）。
4. 越界急停：信念位姿出 MAP_SAFETY_MARGIN=0.60 m 即刹车；第八次实车正是靠它兜住 3.56 m 跑偏。

云台侧：IDLE → SCAN → TRACK → 开火；scan_pitch_offset_deg=-26°；declare_parameter 必须配 get_parameter（readme 第 34 条）；offset_center 回调有 size<5 守卫。
