## 3. 六个真 bug（根因 → 修法 → 今天还在不在）

### 3.1 云台俯仰被扫描区间焊死（"只能左右跟，追着目标头顶看"）

- **现象**：水平能跟，俯仰完全不跟，总朝目标上方看。
- **根因**：跟踪分支复用 `clampPitchToScan`，允许区间 = `offset ± margin`。本车实配 `offset=6.0`、`levels=[0.0]`、`margin=6.0` → **`[0°,12°]`，换算刻度仅 `[2047,2183]`**：地面靶需低头约 40°，而 `lo=0°` 根本低不下去。
- **修法**：跟踪分支改用 **`clampPitchTick`（950~2400 ≈ -96°~+31°，下位机机械限位）**；扫描分支保留 `clampPitchToScan`（它本就该只在扫描层间走）。
- **关键补刀（10-17）**：区间打开后暴露出**俯仰修正的符号错误**——`pitch_deg_sign=+1`、tick 增大 = 低头，原式多一个负号 → 正反馈（该低头反抬头）。10-03 的修法只解了"够不着"，10-17 才解了"方向反"。代码里留着完整复盘：`dzrobot_v2/src/dzrknn_dataprocess/src/dzrknn_dataprocess.cpp:174-203`。
- **今天**：仍走 `clampPitchTick`（该文件 `:200`）。现行操作口径见 [视觉与云台/01](../视觉与云台/01_云台瞄准与开火链路.md)，**不要在本册照抄参数**（`scan_pitch_offset_deg` 已翻成 +10°）。

### 3.2 规划器把雷"静默吃掉"（最危险：不报错）

- **现象**：规划器内部算出的雷序覆盖 8/8（`I10 E7 B5 A3 C4 H1 G2 G6`），输出路线只剩 4/8，缺 `H1 G2 C4 B5`，且**无任何告警**。
- **根因**：`path_to_waypoints` 直线压缩会删中间格，`force_keep` 只放了**射击点 + 桥洞**，**雷点没进名单** → 恰好落在直线段上的 4 个雷被压掉。
- **修法**：雷点 + 起终点一并进 `must_keep`；`route_check` 复验 **雷 8/8**。
- **教训（可迁移）**：**压缩/简化类后处理必须把"任务语义要素"设为不可删**，否则越优化越丢任务。

### 3.3 障碍有两份真源（连锁误判）

| 文件 | 内容 |
|---|---|
| `config/robot.yaml`（旧） | `A1 C2 B4 G4 E6 I7 D9 H10`（**陈旧副本**） |
| `config/map.yaml`（真源） | `B1 I2 F7 C8 E8 A9 H9 D10` |

后果是**双向**的：shoot_planner 按"假障碍"算视线遮挡；校验器反过来误判"路线踩了 `H10/D9/G4`"，而那三格其实是合法格。修法：`obstacle_blocks` 对齐 map.yaml，并立铁律 **"改地图只改 map.yaml，此处同步"**。
**今天**：该铁律仍写在 `config/robot.yaml:430-433`（注释直接引用"2026-10-03 修 C8"）。

### 3.4 C1：底盘标定静默失效（最隐蔽）

- **根因**：`bringup.launch.py` 用 `LaunchConfiguration` 把 `ticksPerMeter/ticksPer2PI` 当**字符串**传给 double 型参数 → 类型不符**静默回落**到节点内置默认值（1000/3200）。里程计比例可能一直是错的，且**没有任何报错**。
- **修法**：改 **params-file** 供给（`robot.yaml` 新增 `/dzactuator` 段，10 个参数），并验证 YAML 里是 **float** 而非字符串。
- **当年的坑**：改成 `parameters=[CONFIG_FILE]` 后，**配置文件缺失会让底盘节点直接启动失败**（底盘是全车第一步）。当场加兜底并实测：正常 → 用文件；缺失 → `PARAMS=[]` + 告警，回退内置默认。
- **今天**：`ticksPerMeter=3280.0`（10-11 冻结）、`ticksPer2PI=2680.0`（`robot.yaml:930-939`）；标定方法仍写在同处注释里。

### 3.5 C4：弹药口径冲突（白等 30 s）

`SHOOT_COUNT_TARGET` **硬编码 10**（连 `declare_parameter` 都没有），而单靶上限只 3 发 → 每个射击点必然耗满 `shoot_timeout=30 s` 才走。改为可配置 `shoot_count_target: 3`，与云台 `max_shots_per_target` 对齐，"打满即走"。
**今天**：两者都是 **10**（`robot.yaml:207/421`）——数值回了 10，但"必须 ≤ 云台上限"这条约束保留在原处注释里。

### 3.6 #75：射击点评分没有朝向权重

- **根因**：`_rank_shoot_points` 只按"离雷序折线多远"排序，**既无朝向权重、也无距离上限** → 选中对角 `H10`（**0.495 m > 0.45 上限**），而同列 `G10`（0.35 m，云台几乎不用转角）被忽略。
- **修法**：新增 `shoot_alignment_penalty()`——**同列 0.0 / 同行 0.8 / 对角 2.4**，加距离硬过滤；阈值从 `robot.yaml` 读（`load_shoot_limits()`），不在代码里另写一份。
- **今天**：`tools/global_planner.py:496-512` 常量与函数**原样还在**，是现行规划器的成本项之一。
