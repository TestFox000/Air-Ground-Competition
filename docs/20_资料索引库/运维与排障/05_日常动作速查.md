# 日常动作速查（跑一趟车的固定动作）

> 本篇是**动作流**：把「连车 → 改参 → 重启 → 取证 → 自检 → 部署 → 收工」排成可照抄的顺序，每格只给命令与判据。
> 只知现象 → [01_症状索引_52条.md](01_症状索引_52条.md)；要起栈发车 → [02_起栈与发车_runbook.md](02_起栈与发车_runbook.md)；弹药/开火 → [03_弹仓与射击复位.md](03_弹仓与射击复位.md)；被拒/权限 → [04_常见拒绝与权限.md](04_常见拒绝与权限.md)。**本篇不重述它们。**
> 与代码/现场冲突时以代码和现场为准，并回来改本篇。

## TL;DR（给 agent 看的）

- **每条 SSH 的第一句是 `source ~/dzrobot/dzros.env`**：非交互 SSH 域号默认 0，不 source 时 ping/SSH 全通、ROS 互相看不见、**零报错**（[02](02_起栈与发车_runbook.md) §1）。
- **改参数 = 改文件 + 重启节点**：节点只在启动时读一次参数（无 `on_set_parameters` 回调），`ros2 param set` 改了也不生效。
- **「生效」的唯一证据是三件套**：`ros2 param get` 出新值 + 启动横幅打印新值 + 业务话题有数。只看文件 mtime 不算。
- **部署唯一入口 `tools/deploy_to_car.py`**；`all`/`push` 会**整份覆盖车端 `config/robot.yaml`**（现场调参在车上时，绝不能用它改参）。
- **收工三件**：只 add 自己的文件 → 双推 github+gitee → `ls-remote` 两端哈希 == 本地 HEAD（工作流 §11）。

## 1. 连车

```bash
cd dzrobot_v2
python tools/deploy_to_car.py probe      # 打印当前可达 IP（唯一可信来源）
ssh duzhong@<probe 给的 IP>              # 直连 IP，不用别名
```

| 坑 | 说明 |
|---|---|
| 固定 IP 会过期 | 本仓库见过的车 IP 横跨 `10.15.x` / `192.168.137.x` / `10.29.x` / `10.35.x`；**只 ping 上次的 IP 会误判「车离线」** |
| `duzhong.local` 可能被劫持 | 本机 `hosts` 里可能还写着一台旧地址（[02](02_起栈与发车_runbook.md) §1）；能解析不等于能连 |
| `ssh dzrobot` 必失败 | 该别名强制密码认证 + 关公钥；BatchMode 下 `Permission denied`（02 §1） |
| 两套工作区 | 车上并存 `~/dzrobot`（原版）与 `~/dzrobot2`（精简重写，归属未确认）⇒ 先 `ls -d ~/dzrobot*` 并确认部署目标栈（[车端/05_配置与部署.md](../车端/05_配置与部署.md) §3） |

## 2. 改一个参数（五步，最常用）

```bash
# ① 备份（带时间戳，永不覆盖旧备份）
cp ~/dzrobot/config/robot.yaml ~/dzrobot/config/robot.yaml.bak_$(date +%Y%m%d_%H%M%S)

# ② 改（只动数值，不动结构）
sed -i -E 's/^( *fire_hold_frames:).*/\1 1/' ~/dzrobot/config/robot.yaml
grep -n 'fire_hold_frames' ~/dzrobot/config/robot.yaml        # 必须回显新值

# ③ 重启受影响节点（见 §4）
~/dzrobot/tools/restart_node.sh gimbal

# ④ 取证（见 §3，别只看文件）
ros2 param get /dzrknn_dataprocess fire_hold_frames
tail -n 60 ~/robot_logs/5_gimbal.log

# ⑤ 回滚（一条命令）
cp ~/dzrobot/config/robot.yaml.bak_<时间戳> ~/dzrobot/config/robot.yaml \
  && source ~/dzrobot/dzros.env && ~/dzrobot/tools/restart_node.sh gimbal
```

三条硬知识：

1. **参数只在启动读一次**：`dzrknn_dataprocess` 用 `get_parameter` 取一次就存进成员变量，没有 `on_set_parameters` ⇒ `ros2 param set` 成功返回但下一拍就被覆盖。
2. **同名键可能散在两段**：`robot.yaml` 里同一个键可以出现在两个配置段（历史实测过），只改一处另一处不变、且两处值相同时**完全看不出没改** ⇒ 改完用 `grep -c` 数命中数，`≥2` 就两处都改。
3. **`sed -i` 可能空转**：车端 yaml 历史上出现过非 `\\n` 分隔，`sed` 只更新 mtime 不改内容 ⇒ 改完必须 `grep` 复读；不放心就用 Python 读-改-写，并核对 md5。

## 3. 取证判据（什么才算「生效」）

| 要证什么 | 命令（每条前先 `source ~/dzrobot/dzros.env`） | 判据 |
|---|---|---|
| 参数进进程了 | `ros2 param get /dzrknn_dataprocess <键>` | 返回值 = 新值；若抛 `rclpy.ok()` 异常 → `ros2 daemon stop` 后重试 |
| 参数打印进日志 | `tail -n 60 ~/robot_logs/5_gimbal.log` | 启动横幅含「保持 N 帧 / 扫描确认 N 帧 / 类别改锁 N 帧」 |
| 节点没重复 | `ros2 node list`；`ros2 topic info -v /LaserShot_Command` | 同名节点 1 个；该话题 **发布者 = 1** |
| 云台在跟踪 | `ros2 topic echo /offset_center --once` | 出现 `dx dy cls w h vx vy`；`cls=1` 为蓝 |
| 两键开火在位 | `ros2 topic info /aim/fire_gate`、`ros2 topic info /aim/fire_ready` | 两个都有发布者，否则永远不开火 |
| 真打了几发 | `ros2 topic echo /LaserShot_Command` 或 `ros2 topic echo /shoot_count` | 计数变化；不变 = 一发没打 |

> 日志文件名由 `restart_node.sh` 的槽位决定（`gimbal` → `~/robot_logs/5_gimbal.log`）；`restart_node.sh --list` 可看全部槽位。

## 4. 重启粒度（能单点就别整栈）

| 改动 | 命令 | 影响 |
|---|---|---|
| 云台 / 开火 / 扫描参数 | `~/dzrobot/tools/restart_node.sh gimbal` | 只重启自瞄 1~2 s，不动路线 |
| 激光通讯 / 记账 | `restart_node.sh judgment` | 只重启裁判驱动（弹药账本随之重置） |
| 换视觉模型 | `restart_node.sh vision` | 只重启 `det_node`（无 X 时必须 `draw:false`） |
| 路线 / 速度 | **`bash ~/dzrobot/start_all.sh`** | `restart_node.sh path` 指旧核，改路线会取到旧实现；`LEGACY_PATH=1` 是旧核回退开关 |
| 整车 | `bash ~/dzrobot/start_all.sh` | 7 步顺序起；含域号与进程组回收 |

起栈前必做三件事（域号 / `pkill -f cam_viewer` / 确认 `config/map.yaml` 是哪张图）见 [02](02_起栈与发车_runbook.md) §0，本篇不重复。

## 5. 本机自检与门禁

```bash
cd dzrobot_v2
python tools/config_selfcheck.py             # 配置 + 路线自检：0 error 才算过
python tools/dzbrain.py --dry-run            # 启动门禁：只校验不起线程
python tools/dzbrain.py --bench --seconds 5  # 无 ROS / 无车联调（FakeBridge）
python tools/route_check.py --config config/robot_car.yaml --route "N10 M10 L10"
python tools/wf/check.py                     # 收口门禁（冻结区/复用/断链）
```

文档侧（在 v1 根，按序）：

```bash
python docs/_工具/gen_index.py               # ① 重建目录索引（不要手改）
python docs/_工具/check_doc_policy.py        # ② 红线：库外新增/开新库/未登记
python docs/_工具/check_anchors.py           # ③ 只对新增红判失败
python docs/_工具/check_numbers.py           # ④ 默认只报不判红（--strict 才挡）
cd dzrobot_v2 && python tools/wf/check.py    # ⑤
python tools/wf/check_links.py               # ⑥ 断链
```

车上可选自检：`python tools/deploy_to_car.py verify`（只查包/入口存在 + 云台补丁符号，**不进 `all`**）；`bash ~/dzrobot/tools/healthcheck.sh` 是人工体检，不是起栈门禁。

## 6. 部署

```bash
cd dzrobot_v2
python tools/deploy_to_car.py probe
python tools/deploy_to_car.py all --dry-run   # 先看清单
python tools/deploy_to_car.py all             # backup → push → build
```

| 必须知道的 | 说明 |
|---|---|
| `all`/`push` 覆盖配置 | 推送清单包含 `config/robot.yaml`，会用仓库版**整份覆盖**车端；车端现场调参与仓库已分叉时，这是最大破坏面 |
| `push` 不自动 backup | 只有 `all` 先备份；单独 `push` 前自己 cp |
| 刻意不推 `config/map.yaml` | 仓库是第六图、车端是第七图，谁推谁把车弄瘸（D-019） |
| `auto_start` 默认不动 | 要强制 false 才加 `--force-no-autostart` |
| 目录推送方式 | tar 流就地替换 + sha256 对账；**禁止手写 `scp -r`**；顶层 `start_all.sh` 不在目录清单内，要单独推 |

## 7. 开火与弹药（先看 03，本篇只给命令）

```bash
# 清软件弹药账本（不用重启节点）
ros2 topic pub --once /shoot_reset std_msgs/msg/UInt8 "{data: 1}"
```

三条最容易误判：
1. `max_shots` 是**进程生命周期累计**，打满即不再放行 ⇒ 看起来像「坏了」；清零用 `/shoot_reset`（旧口径「只能重启」已过时）。
2. 红面不开火是 `fire_only_blue` 的**正确拦截**，不是故障（[03](03_弹仓与射击复位.md)）。
3. **重启云台节点会让软件计数归零**（本会话实测）——既是坑，也是复位手段。

开火 7 条 AND 与日志里的放行/拦截诊断词，以 [03](03_弹仓与射击复位.md) 与 [视觉与云台/01](../视觉与云台/01_云台瞄准与开火链路.md) 为准，别凭记忆背。

## 8. 收工：提交与双推

```bash
git status && git diff                  # 只 add 本任务文件，禁止 git add .
git add <本任务文件>
git commit -m "<摘要> [<卡号>]"
git push github main && git push gitee main
git ls-remote <github 地址> main; git ls-remote <gitee 地址> main   # 两端哈希 == 本地 HEAD
```

- 冲突 / 非快进 / 认证失败 / 远端分叉 → **硬停报告**，禁 force push、禁重写历史（[赛事与治理/03_工作流与铁律.md](../赛事与治理/03_工作流与铁律.md)）。
- 一端成功一端失败：只报失败端，不宣称「双端同步完成」。

## 9. 2026-10-24 现场新踩的五个坑

| # | 现象 | 处置 |
|---|---|---|
| 1 | 固定 IP ping 不通，以为车离线 | 先用 `deploy_to_car.py probe` / `hostname -I` 核当前 IP，别拿上次的 IP 下结论 |
| 2 | 整栈重启后 `ros2 param get` 抛 `rclpy.ok()` 异常 | `ros2 daemon stop` 后重试（daemon 缓存失效，不是节点坏了） |
| 3 | 改了帧门槛，打了几发又不打 | `max_shots` 进程累计 + 重启即清零；先用 `/shoot_reset` 排除弹药，再谈判据 |
| 4 | 两个写者同时下发路线 | `/nav/waypoint` 与 `field_layout` 不能同时发（[空地链路/02](../空地链路/02_链路联调与已知缺口.md) §8）；`cam_viewer` 是第三个隐形写者（全零 `/pursuitAngle`） |
| 5 | 仓库与车端 `robot.yaml` 已分叉 | 任何「以仓库为准」的动作前先 diff（10-24 实测差异 180+ 行：云台调参段 + 路线段）；`deploy all` 会覆盖 |
