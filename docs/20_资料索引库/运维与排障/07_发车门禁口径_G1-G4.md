### 红了怎么办

1. **`config_selfcheck` 只报 warn 却 exit 0 —— 这是设计，不是 bug**。`return 1 if errors else 0`（`dzrobot_v2/tools/config_selfcheck.py:227`）只看 error；warn 只在结论行里体现（`:226`）。G1 的口径是 **error 0 ∧ warn 0**，所以有人拿"退出码 0"当通过就是假绿。有 warn 时结论行会印 `⚠ 有条件通过（有 warn：必须逐条判读，禁止只看退出码）`。
2. **exit 3 要看清是哪种 3**：LAYOUT-MODE（缺图但 `planner.auto_plan_enabled=true`，属设计形态）或 CONFIG-ONLY（`--config-only`）。**缺图 + `auto_plan_enabled=false` 仍是 MAP_INPUT_ERROR exit 1**（反向守卫，不许把真错当形态）。
3. **check_anchors 的"新增红"和"存量红"是两回事**：只有新增红判失败（`docs/_工具/check_anchors.py` 口径），存量红进 baseline、只减不增。看到 `存量红 268` 不代表红了。
4. **`gen_index` 别顺手跑全量**：全量会把别人未提交的新文件也写进索引（幽灵条目，一个会话无法干净提交索引）。`--only` 只重扫自己写域；`--ns <ns>` 只覆盖任务卡库的该 ns，**不覆盖 20 库**。

### 红了怎么办 —— 先看退出码定位层，再动手

| 退出码 | 含义 | 现场第一动作 |
|---|---|---|
| **0** | 正常收尾（步进循环 FINISH / 被 SIGTERM 正常停） | 收工 |
| **1** | `context_dead` / `safe_stop`（步进循环） | SAFE_STOP 先看日志里的 reason |
| **3** | 无布局 / 装配失败 | 布局来源（SOP 第 5 步）；`drone.enabled=false` 也会 3 |
| **4** | 布局规划失败（v1 布局路径） | 布局报文内容 / 地图参数；**绝不回退地图文件** |
| **5** | ROS 环境 / 位姿管线未就绪 | 域号、重复实例、`/odom/localization` 首帧 |
| **6** | 启动契约不通过 | 看图：谁 pubs=0（对端没起/域不同），谁 subs=0 |
| **7** | 发车前硬拦：激光/开火联锁不在位 | `fire_interlock` 三类硬拦之一 |

**exit 5 与 exit 6 的分界**（这是本页最值钱的一句）：契约通过但**数据不来** ⇒ 5（QoS/传输/发布异常）；**端点在图上就缺** ⇒ 6（谁必须在对的图上）。所以"车一步不动"的两种完全不同的原因靠这两码分开：6 是装配/域问题，5 是链路/时序问题。

**exit 7 不在 `main.py:64` 的退出码注释里**（那里只写了 0/3/4/5/6）—— 它是 AGC-RECTIFY 之后新增的发车前硬拦（`GATE_HARD_KEYS` `main.py:421`；`assert_fire_interlock` 失败 ⇒ `return 7`）。查现场时别按老注释找。
