## 6. 发车（`mission.auto_start=false` 时到底怎么发）〔实〕

**先分清模式 —— 这是明早最容易做错的一步**：

| 模式 | 怎么进 | 谁让车动 |
|---|---|---|
| **步进模式（现场默认）** | 收到的布局带 `known` 键（v2） | `StepLoop` 按布局的 `target_cell` 逐段 `request_segment()`；`MissionTask.auto_start` 被**强制改 false**（`main.py:3037`） |
| 旧路径（v1 布局，无 `known`） | 布局不带 `known` | `MissionTask` 执行由布局算出的 `route.tokens`；`auto_start=false` 时**等外部命令**才出发 |

**所以：步进模式下 `/nav/waypoint` 不是发车手段**（发了会与步进器抢路线）。要"人工发车"只有三种正当手段：

1. **推布局**（步进模式）：让发射器发一版新 `target_cell`（`emit_step_v3` 会自动做；手推则 `version+1`）；
2. **v1/手工路线模式**：`/nav/waypoint` 文本命令（`std_msgs/String`，`contract.py:73`；消费者 `ros_io.py:353` 收、`mission.py` `_handle_command` 解析）：
   ```bash
   # 复位 belief（不出发，回 IDLE 等下一单）
   ros2 topic pub --once /nav/waypoint std_msgs/String "{data: 'reset:N10,y'}"
   # 单点出发（BLOCK,HEAD；HEAD 是 y 朝 +y）
   ros2 topic pub --once /nav/waypoint std_msgs/String "{data: 'goto N10,y'}"
   # 多点整条路线（token 列表；朝向后缀只能挂在最后一个 token）
   ros2 topic pub --once /nav/waypoint std_msgs/String "{data: '多点 N10,y M10 L10 K10,end'}"
   ```
   语法真源：`reset:BLOCK,HEAD` / `load:文件` / `单点|single|goto BLOCK,HEAD` / `多点|multi|route …` / 裸 token 列表；`goto`/`多点`/`load:` 都会立刻 `_start_mission()`（即发车），`reset:` **不会**。
3. **改配置**：把 `mission.auto_start` 改 true（`robot.yaml:713`）—— **只有在你确认站位、清场、且接受"无确认自动出发"时**才这么做；旧核回退（`LEGACY_PATH=1`）那条路还会看 `path_executor.auto_start`（`robot.yaml:337`，常态应为 false）。

**失败对号**：

| 现象 | 含义 | 处置 |
|---|---|---|
| 布局到了、契约过了、车不动 | `target_cell` 等于当前格 / 规划失败在 WAIT_INFO | 看 `phase`（第 7 步）；`plan` 失败会打原因 |
| `/nav/waypoint` 发了没反应 | 步进模式接管了路线 | 别反复发；看 `7_path` 日志是否 `unknown command` |
| 车一动就停 | 看是否 `SafetyTask` 触发（第 9 节 B 类） | 先 `clear_safety` 前先查明原因，别连续清 |

## 7. 跑图看点（这一段决定你是"知道车在干什么"还是"猜"）〔实〕

**唯一权威频道**：车 → 机的 `car_state`（`/dzlink/car_to_drone`，`std_msgs/String`，JSON，`type=car_state`，周期 `drone.car_state_period_s=0.7 s`，`config.py:570`）。发布函数 `StepLoop._publish_car_state()`。

```bash

```

**看五个字段就够**：

| 字段 | 看点 | 判据 |
|---|---|---|
| `phase` | `WAIT_LAYOUT/PLANNING/DRIVING/WAIT_INFO/SEGMENT_DONE/FINISH/SAFE_STOP/WAIT_INFO_TIMEOUT/ROS_LOST`（`main.py:374-384`） | `DRIVING` 才是真在走；`WAIT_INFO` 是在等下一份布局（**无超时**，不是卡死） |
| `segment_id` / `segments_started`/`segments_done` | 段号是否单调推进 | 长期不增 = 每段都失败 |
| `known_count` | 已知格数量 | 应在增长；恒值 = 布局不再来 |
| `stop_kind` | 本段末停站类型 `shoot/mine/path/end` | 打靶段应是 `shoot` |
| `reason` | 停机/等待原因 | 非空且 phase=SAFE_STOP 就要处置 |

**stall 判据（两条，别混）**：

1. **跳点看门狗**：`mission.stall_timeout_s` = **12 s**（`config.py:385` 默认，`robot.yaml` 未覆盖）内弧长前进 < `arrival_m`，或停滞期间累计转满 `mission.stall_yaw_deg`=360° ⇒ 把卡住的下一航点判不可达并跳过（宁可漏打不可卡死）；PIVOT 有界机动期间整体不计。
2. **静止闸**：连续 **10 拍**（10 Hz ⇒ 1 s）位移 <0.01 m/拍且速度 <0.03 m/s ⇒ **禁止跳点**并打印 `⛔ 车静止（连续 N 拍位姿几乎不动）→ 禁止跳点…如实上报 stall（不推进路线 / 不报 FINISH）`（`mission.py` `_STILL_TICKS`）。这条是防"车一步没动却跳完所有点报 FINISH"的假完赛洞。

## 8. 打靶判据（一发到底该不该出来）〔实〕

**死线与数量（两个独立预算，先到即离站）**：

**`/aim/lead_x`（提前量）怎么判**：`std_msgs/Float32`，单位 **px**（`contract.py:108`），是"预测落点相对当前框的横向偏移"，云台补丁直接消费。生效前提是 `aim.lead_time_s > 0`（现值 **0.27 s**，`robot.yaml:855`）且 `aim.lead_apply_gain`（现值 **0.5**，`robot.yaml:229`）。静止靶时它应≈0；移动靶/车在动时应随速度变号——**符号锁 +v·T**（2026-10-28 A1 复跑结论：`−T·v` 是假绿，禁用）。

**打不出来的对号表**：

## 9. 收尾（三种停机要分清，别把 SAFE_STOP 当完赛）〔实〕

### 9.1 正常完赛

- 到 `end` 格 ⇒ `phase=FINISH`（`main.py:379`）⇒ 主循环退出码 **0**。
- 归档：`artifacts/runs/<UTC ts>/`，六文件 `map/route/pose/log/trace/summary`（`run_archive.py` 顶部注释），车端即 `~/dzrobot/artifacts/runs/`。

### 9.2 三类停机 / 刹车（**只有一类叫 SAFE_STOP**）

| 类 | 触发 | 现象 | 退出码 | 出处 |
|---|---|---|---|---|
| **A. 步进 SAFE_STOP** | belief **连续 3 拍**投影落未知格 | `phase=SAFE_STOP` + 停段 + 刹车，**不再自动恢复** | **1** | `main.py:1570`（判据注释 `:387`）；rc 映射 `main.py:3127` |
| **B. SafetyTask 强制刹车** | ①定位失联 ②越界 ③任务 FAULT/心跳停滞 ④`EV_TASK_FAULT`（⑤遥控接管不算故障） | 零速指令逐拍续发 + 横幅；**条件解除也不自动恢复**，必须显式 `clear_safety()` | 不直接改退出码 | `tasks/safety.py` 模块 docstring（五道检查） |
| **C. 发车前硬拦** | 急停/开火联锁/场地边界 三条之一 | 起栈即拒绝，**不进任务组** | **7** | `GATE_HARD_KEYS` `main.py:421`；`return 7` `main.py:3098` |
