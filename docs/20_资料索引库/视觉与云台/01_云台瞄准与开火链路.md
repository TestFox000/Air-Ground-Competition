# 云台瞄准与开火链路

## TL;DR（给 agent 看的）

- **上电即扫**（v2 行为）：开机直接 `AIM_SCAN` 且 continuous，只有 `/nav/scan_request=0` 才停。
- **TRACK 期间云台几乎不动**：只要还有视觉心跳（哪怕无目标帧）TRACK 分支立即 return，重扫要等 `lost_frames_to_rescan=180` 帧 ≈ **6 s**。
- 开火是 **7 条 AND**；但真正让「停站 30 s 0 发」的是三条结构性错位：**提前量只进判据不进控制环**（P0）、**类别锁被闪烁清零**（已修）、**靶速 1 m/s 下提前量 > 开火框**（10-21 结论）。
- `max_shots` 是**进程生命周期累计**：打满即不再开火；**新版的 `/shoot_reset`（UInt8，非 0 触发）可清零并重发 `/shoot_count=0`**（`cpp:1120-1134`），不必重启节点（旧口径「只能重启」已过时）。

## 1. 拓扑与命名陷阱

| 环节 | 节点/话题 | 关键事实 |
|---|---|---|
| 视觉 | det_node → `/offset_center`（Int32MultiArray，8 字段） | 30 Hz；无目标也发全 0 心跳 |
| 云台 | dzrknn_dataprocess → `CameMo_Conl`(Int32[4]) → dzactuator → 串口 | 主循环 TRACK 100 Hz / IDLE 50 Hz，但 **PID 按视觉帧推进 dt≈1/30** |
| 开火 | `LaserShot_Command`(UInt8，1→0) → dzjudgment → 串口 | dzjudgment 必须起，否则激光不亮且无报错 |
| 状态 | `/aim/status`(0/1/2)、`/shoot_count`(Int32) | `/shoot_count` 只在开火/重置时发（事件型） |

> ⚠️ **坑**：`dzrknn_dataprocess` 编出的可执行文件叫 **`dzactuator_node`**（`CMakeLists.txt:91`、launch py:44），与底盘包 `dzactuator` 的可执行**同名**（`dzactuator/CMakeLists.txt:87`）。`ros2 run dzactuator dzactuator_node` 起的是**底盘**。install 目录分离、正常起栈不撞；危险操作三种：`--merge-install`、手工 scp 写错包目录、`ros2 run` 包名写错（`_tmp_session/gimbal-patch/REPORT.md` §5）。

## 2. `/offset_center` 8 项下标（`det_node.cc:215-222,250-258`）

| 下标 | 含义 | 备注 |
|---|---|---|
| [0] | 框中心 x − 画面中心 x（px） | 右为正 |
| [1] | 框中心 y − 画面中心 y（px） | **下为正**（决定俯仰符号） |
| [2] | **类别+1**：1=蓝靶、2=红靶、0=无目标 | `res.cls+1` |
| [3]/[4] | 框宽/框高（px） | 用于长宽比过滤 + 距离估计 + 动态开火框 |
| [5]/[6]/[7] | 靶心关键点 dx/dy、置信度×100 | **云台代码当前未使用** |

## 3. 状态机、扫描与伺服（现役值）

| 状态 | 值 | 语义 |
|---|---|---|
| `AIM_IDLE` | 0 | 不下发扫描，**主动归位**正前 + 基准俯仰（旧版直接 return 会冻结在任意姿态） |
| `AIM_SCAN` | 1 | 水平连续匀速往复，可跨俯仰层 |
| `AIM_TRACK` | 2 | 已锁定，视觉伺服持续修正；**TRACK 期间 `/nav/scan_request` 一律忽略** |

| 扫描项 | 现役值 | 出处 |
|---|---|---|
| 水平范围 | **±150°**（旧 −160~+10 已弃用） | `robot.yaml:37-38` |
| 俯仰偏移 | **+10.0°**（10-15 实测：+ 才是向下压；旧 −10 是抬头） | `robot.yaml:50` |
| 趟数 | `scan_passes=2`（一轮=左一趟+右一趟） | `robot.yaml:68` |
| 速度 | `gimbal_max_speed 3700 × patrol 0.30 = 1110` 刻度/s | `robot.yaml:81-82` |
| 一轮耗时 | ≈ 5.5 s（300°×11.378/1110×2 + dwell） | 第三趟方案 §2.2 |

| 伺服项 | 现役 | 说明 |
|---|---|---|
| 滤波 | `ema_alpha=0.45` | 10-17 移动靶提速 0.25→0.45 |
| 死区 | `track_deadzone_px=5` | 必须 < `fire_dz_far_px` |
| 精调档 | `fine_zone_px=40` | 误差 <40 px 时 kp×0.5、kd×2.0 |
| 预判 | `predict_gain=0.5` | **单位是「帧」** ≈16 ms（真实延迟 0.5~0.9 s，见 03） |
| 速度上限 | `track_speed_max=2000` 刻度/s（≈176°/s） | 快过目标；10-21 估算 1 m/s 靶需 745 刻度/s（92%） |

## 4. 开火 7 条 AND（现役 `dzrknn_dataprocess.cpp`）

| # | 条件 | 现役阈值 | 行 |
|---|---|---|---|
| 1 | 类别已确认 | `target_confirm_frames=2` | `:84` |
| 2 | 在动态开火框内（零点=**激光落点**） | far **25** / near 26 px（10-18 14→20→25） | `:299-302` |
| 3 | 瞄准稳定 | `fire_use_image_stable` ⇒ `|vx|,|vy| ≤ 1.5 px/帧`；否则电机 `<fire_real_speed_max` | `:279-281` |
| 4 | 弹药允许 | `max_shots=10` + 单目标 10 + `cls_fire_ok` | `:353-356` |
| 5 | 类别允许 | `fire_only_blue=true` ⇒ 仅 `locked_cls==1` | `:333` |
| 6 | 冷却 | `shot_cooldown_ms=500` | `:357` |
| 7 | 连续保持 | `fire_hold_frames=5` | `:363` |

射出去的动作：`data=1` 立即 `data=0`（`:367-369`），然后 `shots_fired_++`、`shots_on_target_++`、发 `/shoot_count`。任一条不满足 → `fire_hold_count_=0`。

- 弹药「加满」通道：`ros2 topic pub --once /shoot_reset std_msgs/msg/UInt8 "{data: 1}"` → 计数清零 + 重发 `/shoot_count=0` + 日志 `==> ★ 射击计数已重置`（`cpp:1120-1134`）。调参/试射每轮前发一次，避免继承「已打满」状态。

## 5. 两把钥匙与「提前量只进判据」（P0 结构错位）

| 钥匙 | 发布者 | 含义 |
|---|---|---|
| `/aim/fire_gate` | MissionTask | 任务级：已到站、停稳、FIRE 阶段 |
| `/aim/fire_ready` | AimTask | 瞄准级：目标确认 + 预测落点在框内 + 冷却/预算允许（每拍发、锁存+保活） |

- `use_external_fire_gate=true` 时：`aim_ready_effective = external_gate && external_ready`，且**不再叠加画面静止**（`:290-291` 注释：否则又要求静止，移动靶永远打不出去）。
- ⚠️ **P0**：`lead_applied` 只参与开火判据（`:299-302`），**不进控制环**（`:213-225` 只用滤波误差+速度前馈+陀螺前馈）。后果：伺服把 dx 拉回 0，判据却要求 `|dx+lead| ≤ fire_dz` ⇒ 稳态退化为 `|lead| ≤ fire_dz`。1 m/s 靶在 0.875 m 站距下 lead≈37 px > 25 px ⇒ **门在结构上关着**；把 far 抬到 25 是「用放宽判据掩盖结构错位」（瞄准对比报告 §6.1）。
- 10-21 的解法：先**拉远到 1.41 m**（lead≈23 px < 25 px）不改代码试一把；要根治得把 lead 并进控制环（约 4 行）。

## 6. 类别锁与「发 0 中 0」根因链

**根因链（四条，各自独立成立）**：

| # | 环节 | 机制 | 证据 |
|---|---|---|---|
| 1 | 类别锁被闪烁清零 | 旧行为每次「重新进入 TRACK」清 `locked_cls_/cls_streak_` ⇒ 目标闪 1~2 帧就要从 5 帧重累计，`fire_only_blue` 下永远锁不上 | `gimbal-patch/REPORT.md` §1（已修：删 3 行，保留 rescan 合法清零 `:437-445`） |
| 2 | 提前量结构错位 | 见 §5（lead 不进控制环） | 瞄准对比报告 §6.1 |
| 3 | 弹药锁存 | `max_shots=1` 只在车端 dump 里（试射遗留）⇒ 打 1 发即不再开火；`shots_fired_` 生命周期累计，需 `/shoot_reset` 或重启 | 体检报告 §7；`cpp:355`、`:1120-1134` |
| 4 | 蓝面门控 | `fire_only_blue=true` + 靶只有固定一面 ⇒ 红面朝向时整站正确不开火（**不是故障**，但会让「0 发」看起来像 bug） | `cpp:333,337-351`；第三趟方案 §3 |

**实证**：10-18 17:07 那轮（新二进制）`类别已锁定` 5 条、`pub_LaserShot_Command` **10 条**（[1/10]…[10/10]）、`诊断(不放行开火)…fire_only_blue` 4 条 ⇒ 开火链已打通、红面仍被正确拦截（`gimbal-patch/REPORT.md` §4）。

## 7. dzjudgment（串口射击驱动）

| 项 | 内容 |
|---|---|
| 开火帧 | `B5 5B 03 21 01 25`（6 字节固定；`[2]`=长度、`[5]`=校验） |
| 触发 | 订阅 `LaserShot_Command`，`data==1` 即写串口（0 忽略） |
| 成功日志 | `[dzjudgment-->] ★ 开火指令已下发 (B5 5B 03 21 01 25)` |
| 主循环 | **100 Hz**（原 10 Hz 会有 ≤100 ms 排队延迟） |
| 回传 | `HpAndHitmsg = [targethp, self_hp, Bing_hit, Shooting_Count, ammo]`，1 Hz 心跳 + 收帧即发 |
| 0x07 解析 | `[4]`对方 HP `[5]`己方 HP `[6]`**我方被击打方位** `[7]`累计射击数 `[8]`剩余弹药 |

- 命中真信号 = **对方 HP 下降量**，且必须**按状态变化计数**（1 Hz 心跳值与实帧相同，按「收到帧」计会把命中刷成天文数字）；`Bing_hit` 是「我方被打方位」，拿它判命中会「每挨一发就停火一次」。
- 纯 Python 侧解析已落地（`src/dzbrain/dzbrain/io/referee.py`），不改 C++、无需重编译。

## 8. 手动接管与两个历史缺口

- `nav/manual_gimbal=1` → `manual_override_=true` → **主循环不再发 `CameMo_Conl`**；开火/状态照常。接管只停位置下发，**扫描索引仍在推进**，释放后从推进后的位置续接。
- 历史缺口①：`/move_base/stop_signal` 老放行门**零订阅者**（`path_executor.py:2128` 发）⇒ 改用两键后作废。
- 历史缺口②：C++ **不订阅** `HpAndHitmsg` ⇒ 软件侧发数不与裁判 ammo 对账；对账已在 Python 侧做（发数三方对账：`pub_LaserShot` 计数 == `/shoot_count` == 裁判 `[3]`）。
