# 云台瞄准与开火链路

## TL;DR（给 agent 看的）

> 当前事实以[10-24空地协同接手](../../00_项目总览/交接_20261024_空地协同接手.md)为准：上午两发只证实裁判记账、命中未知；下午AimTask已实际运行，回正/租期补丁已部署。本页§5的提前量数字/「改四行」是旧本地口径，不得据此覆盖保留lead/EKF的车端版本。

- **10-24 本地修复**：停扫 0 在 TRACK 也生效并取消待开扫归位；两键各自按接收时间有 500 ms 租期，Mission 有效 FIRE 每拍续租，离站/换路撤销。C++ 真实生产函数离线编译 26/26 通过；不是完整 ROS 节点构建或实车证明。来源: CAR-HOME-20261024、CAR-GATE-20261024。

- **上电即扫**（v2 行为）：开机直接 `AIM_SCAN` 且 continuous，只有 `/nav/scan_request=0` 才停。
- **TRACK 期间云台几乎不动**：只要还有视觉心跳（哪怕无目标帧）TRACK 分支立即 return，重扫要等 `lost_frames_to_rescan=180` 帧 ≈ **6 s**。
- 开火是 **7 条 AND**；但真正让「停站 30 s 0 发」的是三条结构性错位：**提前量只进判据不进控制环**（P0）、**类别锁被闪烁清零**（已修）、**靶速 1 m/s 下提前量 > 开火框**（10-21 结论——⚠️ **已由 D-033 作废**：现场实测 0.3 m/s，提前量 11 px < 25 px 框，门不关；真瓶颈是观测连续性）。
- `max_shots` 是**进程生命周期累计**：打满即不再开火；**新版的 `/shoot_reset`（UInt8，非 0 触发）可清零并重发 `/shoot_count=0`**（`cpp:1120-1134`），不必重启节点（旧口径「只能重启」已过时）。

## 1. 拓扑与命名陷阱

| 环节 | 节点/话题 | 关键事实 |
|---|---|---|
| 视觉 | det_node → `/offset_center`（Int32MultiArray，8 字段） | 30 Hz；无目标也发全 0 心跳 |
| 云台 | dzrknn_dataprocess → `CameMo_Conl`(Int32[4]) → dzactuator → 串口 | 主循环 TRACK 100 Hz / IDLE 50 Hz，但 **PID 按视觉帧推进 dt≈1/30** |
| 开火 | `LaserShot_Command`(UInt8，1→0) → dzjudgment → 串口 | dzjudgment 必须起，否则激光不亮且无报错 |
| 状态 | `/aim/status`(0/1/2)、`/shoot_count`(Int32) | `/shoot_count` 只在开火/重置时发（事件型） |

> ⚠️ **坑**：`dzrknn_dataprocess` 编出的可执行文件叫 **`dzactuator_node`**（`CMakeLists.txt:91`、launch py:44），与底盘包 `dzactuator` 的可执行**同名**（`dzactuator/CMakeLists.txt:87`）。`ros2 run dzactuator dzactuator_node` 起的是**底盘**。install 目录分离、正常起栈不撞；危险操作三种：`--merge-install`、手工 scp 写错包目录、`ros2 run` 包名写错（`_tmp_session/gimbal-patch/REPORT.md` §5）。

## 5. 两把钥匙与「提前量只进判据」（P0 结构错位）

| 钥匙 | 发布者 | 含义 |
|---|---|---|
| `/aim/fire_gate` | MissionTask | 任务级：已到站、停稳、FIRE 阶段 |
| `/aim/fire_ready` | AimTask | 瞄准级：目标确认 + 预测落点在框内 + 冷却/预算允许（每拍发、锁存+保活） |

- `use_external_fire_gate=true` 时：两键均为 true 且各自最后接收距当前单调时间小于 500 ms 才放行（10-24 本地候选）；仍不叠加画面静止，进框、类别、预算、冷却与连续保持约束保留。false 或失联后续期会清连续保持帧数，防止继承旧帧。关闭外部门时保留原内部模式语义。
- ⚠️ **P0**：`lead_applied` 只参与开火判据（`:299-302`），**不进控制环**（`:213-225` 只用滤波误差+速度前馈+陀螺前馈）。后果：伺服把 dx 拉回 0，判据却要求 `|dx+lead| ≤ fire_dz` ⇒ 稳态退化为 `|lead| ≤ fire_dz`。**按 0.3 m/s（D-033）：0.875 m 站距 lead≈11 px、1.41 m≈7 px，均 ≤ 25 px ⇒ 门不关**（旧 1 m/s 口径的 37 px > 25 px 已作废）；但这条 P0 **依然成立**——lead 不进控制环时，判据是靠「框比 lead 大」侥幸通过，靶再快一点就崩。把 far 抬到 25 是「用放宽判据掩盖结构错位」（瞄准对比报告 §6.1）。
- 10-21 的解法「拉远到 1.41 m」**不再是必需**（0.3 m/s 下 0.875 m 已进框）；根治仍是**把 lead 并进控制环**（约 4 行）。
