# 视觉与云台 · 分册索引

## TL;DR（给 agent 看的）

- 链路：相机 → det_node(RKNN 30 Hz) → /offset_center[8 字段] → dzrknn_dataprocess(incPID + 开火判据) → LaserShot_Command → dzjudgment → 串口 B5 5B 03 21 01 25 → 激光。
- **代码是通的，打不中不是链路问题**：10-18 实车「停站 30 s 0 发 / 全场 2 发 0 中」，根因是 7 条 AND + 提前量只进判据不进控制环 + 类别锁被闪烁清零。
- 10-23 口径定案：靶速 **0.3 m/s**〔D-033，2026-10-23〕（10-21 曾由 D-031 定为 1.0，已改判）⇒ 0.875 m 站距下提前量 **11 px < 25 px 开火框**，云台仅需 ≈224 刻度/s（28% 限幅），**开火门不再是结构障碍**；1.41 m 约 7 px（≈139 刻度/s，17%）。旧「门结构上关着」的结论随速度改判失效，改由实测判定开门/命中。

- 另有一说「车端 10/0.5/2.0」：**本轮源文件未核到出处**，不要当结论（找到行号再补）。
- 口径不一的**病因**是 dx 未做距离归一化（IBVS 增益随距离变），不是「没找到魔法数字」——见 `_tmp_session/paper50/三大优化方案.md:113`。
- 整定前必读：a = px/tick 决定 Kp 上界 `Kp_max ≈ (π/2)/(a·θ)`，θ≈0.26 s；**a 已实测 5.80 / 5.89 px/tick**（10-18 两次 ±30 / ±60 刻度阶跃，与台账 D-002 的 ≈5.8 一致；旧「从未量过」作废）⇒ `Kp_max ≈ 1.57/(5.8×0.26) ≈ 1.0`，**现役 kp=12 是上界的约 12 倍** —— 这就是「PID 怎么调都晃」的算术根源（历史会话 07 §3）。
