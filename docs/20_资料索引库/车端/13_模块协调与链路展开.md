# 车端模块协调与链路展开（L3）

## TL;DR（给 agent 看的）

- **一个 Python 进程 = 8 个任务线程 + 主线程里的步进循环；此外还有 5 个外部节点**（底盘 dzactuator、云台 dzrknn_dataprocess、检测 det_node、裁判 dzjudgment、定位中继 serial_reader）。线程之间**不发 ROS 话题**，只走黑盒（Blackboard）+ 事件总线；跨进程话题只有 **21 条**（契约表 12 入 / 9 出）。
- **话题的唯一真源是 contract 表**：`dzrobot_v2/src/dzbrain/dzbrain/io/contract.py:58` 的 `TOPICS`。想知道"谁订阅谁发布"，只查这张表 + `ros_io.py` 的 `_create_subs`（`dzrobot_v2/src/dzbrain/dzbrain/io/ros_io.py:256`）与 `_create_pubs`（`dzrobot_v2/src/dzbrain/dzbrain/io/ros_io.py:386`）。
- **唯一性契约的现实版本**（比 `01_架构与线程.md` 的措辞更严格，见 §5）：
  - 「只有 Tracker 写底盘指令」→ 精确说法是**只有 Tracker 发非零驱动指令**；零 Twist 有 **4 个写者**（Safety / Tracker / Mission / StepLoop）。
  - 「只有 Localization 写 `P_POSE`」→ **不成立**：当前树里有 **3 个写者**（Localization / Mission / Drone），见 §5.2。
  - 「只有 Safety 能强制停车」→ 成立：`P_SAFETY.ok` 是 Tracker 的第一道放行门。
- **两套控制核**：新核 `dzbrain`（本文主体）与旧核 `path_executor`（2622 行）。回退开关是环境变量 `LEGACY_PATH` + `path_executor.auto_start`（`dzrobot_v2/src/dzbrain/dzbrain/main.py:3189`）；回退后 **dzbrain 压根不在场**（`main.py:3186`），本文整条链路不生效。
- 本文行号只对 **dzrobot_v2 提交 `ff231e1e`（2026-10-29，`git status --short` 为空）** 成立。代码属冻结区（D-008）：可以照着读，不代表可以照着改。

## 0. 怎么用这篇

| 你想干什么 | 从哪读 |
|---|---|
| 先建立"谁跟谁说话"的整体印象 | §1 全局图 → §3 主链图 |
| 排查「某一段为什么不动 / 不停 / 不打」 | §2 模块卡片 → 看「失败表现」→ §4 按跳次定位 |
| 要加功能，得知道动哪一层 | §2 输入/输出表 + §5 唯一性契约（动了就破约） |

三条读法纪律（都是踩过的坑）：

1. **按话题名或键名 grep，别按模块名猜**：有的模块对外一条话题都不发（FixTask 只写一个黑盒键）。
2. **黑盒键 = 事实，事件 = 通知**。Python 线程之间只靠这两样；"读不到别人的值"先查键名拼写——`dzrobot_v2/src/dzbrain/dzbrain/core/blackboard.py:21` 起是唯一拼写源。
3. **日志里的阶段名有两套**：`MissionPhase`（`dzrobot_v2/src/dzbrain/dzbrain/io/contract.py:206`）是任务调度层；`STEP_PHASE_*`（`dzrobot_v2/src/dzbrain/dzbrain/main.py:374`）是步进循环层。同一个字 `STOP` 在两层里含义完全不同。

## 2. 模块卡片（职责 / 输入 / 输出 / 黑盒键 / 失败表现）

### 2.1 Localization（20 Hz）——位姿的生产者

- **职责**：格单位坐标 + 原始车体 yaw → 米制地图 Pose；应用 `P_FIX`；有路线就投影出弧长；到点吸附；漂移/边界/航向三道护栏。
- **输入**：`bridge.pose()` 与 `bridge.pose_age()`（`dzrobot_v2/src/dzbrain/dzbrain/tasks/localization.py:383`）、`P_FIX`（`localization.py:405`）、`P_ROUTE`（`localization.py:510`）。
- **输出（黑盒）**：`P_POSE`（`localization.py:459` / `:465`）、`P_POSE_RAW`（`:411`）、`P_ODOM_AGE`（`:388` / `:394`）、`P_ROUTE_INDEX` 与 `P_ROUTE_S`（`:417`~`:418`、`:462`~`:463`）、`P_FIX`（`:1489`）、`P_MOTION_LIMIT`（`:1370`，清位在 `:864` / `:1351`）。
- **输出（事件）**：`EV_POSE_ANCHORED` / `EV_DRIFT_WARNING` / `EV_TASK_FAULT`（import 即声明，`localization.py:50`）。
- **不发任何 ROS 话题**（只读桥、写黑盒）。
- **失败表现**：
  - 收不到定位 ⇒ 每拍写 `P_ODOM_AGE=inf` 且**不写 `P_POSE`**（`localization.py:385`）⇒ Safety 判 `pose_lost` 锁存、Tracker 报「无位姿」刹车（`dzrobot_v2/src/dzbrain/dzbrain/tasks/tracker.py:349`）。日志 `定位缺失：pose=None age=inf`（`localization.py:390`）。
  - 航向不可信 ⇒ 只经 `P_MOTION_LIMIT` + `EV_TASK_FAULT` **请求**停车（`localization.py:800`），真刹车仍归 Safety。
  - 投影冻结 ⇒ `_heal_stuck` 做一次全路线重投影（`localization.py:573`），日志 `投影跟丢自愈`。

### 2.2 Safety（20 Hz）——唯一的强制停车者

- **职责**：五道检查收敛成一个布尔 `P_SAFETY.ok`（文档串见 `dzrobot_v2/src/dzbrain/dzbrain/tasks/safety.py:50`）。① 定位失联/停滞（`safety.py:235`~`:311`）② 越界（`:317`）③ 任务健康（`:323`）④ `EV_TASK_FAULT`（`:326`）⑤ 遥控接管只记录不判故障（`:224`）。
- **输入**：`P_POSE`（`safety.py:147`）、`P_ODOM_AGE`（`:240`）、`bridge.pose_age()`（`:242`）、`bridge.manual_override()`（`:226`）、任务组心跳（`:391`）、`EV_TASK_FAULT`（`:502`）。
- **输出**：`P_SAFETY`（`safety.py:174` / `:206` / `:439`）、零 Twist（`_publish_brake`，`:469`）、`EV_SAFETY_STOP` / `EV_SAFETY_CLEAR`（`:207`）。
- **失败表现**：
  - **刻意不自动恢复**（`safety.py:20` 文档串、`:155`）：条件解除后只打一条「其实已可恢复，等人 clear」，车**永久停着**。这是现场「车半路停死、必须重启栈」的第一名根因；恢复入口只有 `clear_safety()`（`:190`）。
  - 刹车发不出去时独立计数并告警（`safety.py:66` 注释、`:461`）：历史事故是「日志自证安全、实际一条零速都没出去」（`:68`）。
  - 启动期有**两处**宽限，共用同一个键 `safety.startup_grace_s`（`safety.py:76`）：①定位数据从未到达（`:275`~`:288`）②Localization 线程从未 tick（`:305`~`:309`）。日志 `启动宽限（x/3.0s）`；超期仍不满足 ⇒ `启动宽限期已过`（`:286`）+ `pose_lost`。

### 2.3 Tracker（50 Hz）——非零底盘指令的唯一写者

- **职责**：投影 → 纯追踪 → `pursuitAngle`。内含 PIVOT 三段相位（`dzrobot_v2/src/dzbrain/dzbrain/tasks/tracker.py:55`）、倒车入口闭环推车（状态组起于 `tracker.py:188`）、桥洞直行保护段集合（`:277`）、跟丢自愈（`:448`）、弧长地板（`:494`）。
- **输入**：`P_POSE` / `P_SAFETY` / `P_MISSION_PHASE` / `P_ROUTE`（`tracker.py:385`~`:388`）、`P_ROUTE_S`（只当 `s_hint`，`:400`）、`P_MOTION_LIMIT`（经 `compute_command(bb=...)`，`:512`）。
- **输出**：`pursuitAngle`（`tracker.py:687` → `dzrobot_v2/src/dzbrain/dzbrain/io/ros_io.py:499`）、`/nav/motion_state`（`tracker.py:691`）、`P_ROUTE_INDEX` 与 `P_ROUTE_S`（`:695`）、`P_PURSUIT_GEAR`（`:784`）、`PIVOT_DONE_KEY`（`:844` / `:867`）、`P_TELEMETRY` 的 `tracker_cmd` 子键（`:899`）、零 Twist（`_hold`，`:365`）。
- **放行前置门**（6 条，顺序即严重度，`tracker.py:345`~`:360`）：无位姿 → 无安全状态 → 安全不 OK → 遥控接管 → 阶段不在白名单（`ACTIVE_PHASES` = DRIVE/APPROACH，`:85`）→ 无路线。任一命中即显式 `publish_brake()`。
- **失败表现**：
  - 日志 `刹车：<原因>`（`tracker.py:373`，限流）＝ 被 Tracker 主动刹住；配合 `P_SAFETY` 能分清「安全不让动」还是「阶段不让动」。
  - `投影跟丢自愈`（`:464`）＝ 弧长曾冻结后跳变；`倒车入口推车完成`（`:559`）＝ 倒车段入口过了。
  - PIVOT 重入循环（历史坑，`tracker.py:241` 注释）现由 `_pivot_abandon_until_s`（`:247`）抑制。

### 2.4 Mission（10 Hz）——任务调度与路线装载

- **职责**：阶段机（`MissionPhase`，`dzrobot_v2/src/dzbrain/dzbrain/io/contract.py:206`）+ 航点推进 + 停站三段式 + 终点锁存 + 段请求装载。**它是 `P_ROUTE` 的唯一装载者**（`_load_tokens`，`dzrobot_v2/src/dzbrain/dzbrain/tasks/mission.py:2941`）。
- **输入**：`P_POSE` / `P_ROUTE` / `P_SAFETY` / `P_AIM_RED` / `P_STOP_POINT`（自写自读）/ `P_FIELD_LAYOUT`（起点权威，`mission.py:1950`）、`bridge.aim_status()` / `vision()` / `shoot_count()` / `take_hits()`、`EV_BRIDGE_INFO` 事件流（`:2678`）、`/nav/waypoint` 外部命令（`:4147`）。
- **输出**：`P_ROUTE`（`mission.py:3040`，清空 `:4260`）、`P_MISSION_PHASE`（`:3855`）、`P_STOP_POINT`（`:3791`）、`P_TELEMETRY` 的 `mission_state` 子键（`:3878`）、`PIVOT_DONE_KEY` 复位（`:3054`）；`/aim/fire_gate`（`:3823`）、`/nav/scan_request`（`:3845`，**lock 模式不发**）、零 Twist（`:1982` / `:2454` / `:2478` / `:2662` / `:4040`）；事件 `EV_WAYPOINT_REACHED`（`:3292`）、`EV_ARRIVED_STOP_POINT`（`:3588`）、`EV_ROUTE_LOADED`（`:2950`）。
- **停站三段式**（`_run_stop_point`，`mission.py:3596`）：到站硬死线（`:3607`）→ 红面早退（`:3621`）→ SETTLE（`:3648`）→ ACQUIRE（`:3677`）→ FIRE（`:3693`）。每段独立超时，超时即放行且先关 `fire_gate`（`:3734`）。
- **失败表现**：
  - `停站点 X Bn 放弃：<原因>`（`mission.py:3776`）＝ 该站没打成，放行下一候选；原因串自带数字（锁定超时 / 开火超时 / 硬死线 / 红面早退）。
  - `越窗待定（显式记账，不静默丢点）`（`:3312`）＝ 弧长跳过某航点但车没真到过。
  - `段完成疑似劫持`（`:3997`）＝ 段完成判据被投影异常触发，被 `mission.segment_gate_*` 挡住（`:3926`）。
  - 卡死只有两条兜底：拐角绕圈（`_detect_stall_and_skip`，`:3314`）与到站硬死线，**没有第三条**。

### 2.5 Aim（50 Hz）——开火权的第二把钥匙

- **职责**：轨道靶运动估计（`RailEstimator`，`dzrobot_v2/src/dzbrain/dzbrain/tasks/aim.py:196`）、提前量 `/aim/lead_x`、许可 `/aim/fire_ready`、云台扫描单写者（`_update_gimbal_gate`，`:1063`）、命中/弹药三路对账。
- **输入**：`bridge.vision(0.5)`（`aim.py:727`）、`/aim/status`（`:752`）、`P_SAFETY`（`:746`）、`bridge.manual_gimbal()`（`:749`）、`P_STOP_POINT` 与 `P_MISSION_PHASE`（`:1084`~`:1085`）、`shoot_count()` / `ammo()` / `take_hits()`（`_account`，`:857`）。
- **输出**：`/aim/fire_ready`（`aim.py:1132`）、`/nav/scan_request`（`:1121`）、`/aim/lead_x`（`:1000`）、`P_TARGET`（`:1165`）、`P_AIM`（`:1180`）、`P_AIM_RED`（`:1313`）、`P_TELEMETRY` 的 `aim_cmd` 子键（`:1233`）。**绝不发 `/aim/fire_gate`**（`aim.py:13` 明文，测试第 9 组断言）。
- **失败表现**：
  - 不开火看 `P_AIM.last_reason` / 遥测 `blocked_reason`，原因码表在 `aim.py:110`~`:120`：no_target / out_of_box / cooldown / estimator_warmup / safety_not_ok 等。
  - 云台不转或一直转：看 `云台起转搜索` 与 `云台回正锁止`（`:1124`）。锁止靠 C++ 的 IDLE 归位分支实现，Python 只在边沿发一次 0（`aim.py:1111`）。
  - 开火门是**两把钥匙 + 500 ms 租期**：C++ 的 `externalFireAllowed()` 要求两键同时为 1 且都未过期（`dzrobot_v2/src/dzrknn_dataprocess/src/dzrknn_dataprocess.cpp:1146`）。

### 2.6 Fix（10 Hz）——只估计，不修正

- **职责**：跨段比例误差 `scale` 与漂移汇总。
- **输入**：`P_POSE`、`P_ROUTE_S`（带输入守卫，`dzrobot_v2/src/dzbrain/dzbrain/tasks/fix.py:39`）、`EV_POSE_ANCHORED` / `EV_DRIFT_WARNING`。
- **输出**：`P_FIX_EST`（`fix.py:454`）**一个键**，**绝不改位姿**（`fix.py:10`）。
- **失败表现**：`scale` 明显偏离 1（被 `fix.scale_limit` 夹在 ±0.10）表示里程与路线几何系统性不符；⚠️ 别反用——`1/scale` 才是修正系数（`fix.py:20`）。`ds_rejected` 升高 = `P_ROUTE_S` 有写者写坏了（`fix.py:41`）。

### 2.7 Drone（5 Hz）——外部情报的唯一入口

- **职责**：`/dzlink/*` 收发 + 校验 + 落黑盒，**不做路线决策**（`dzrobot_v2/src/dzbrain/dzbrain/tasks/drone.py:5`）。
- **输入**：`bridge.take_drone_messages()`（`dzrobot_v2/src/dzbrain/dzbrain/io/ros_io.py:484`）、`P_POSE`（算 `car_state.block`，`drone.py:1412`）、`P_CAR_STATE`（步进字段，`drone.py:1390`）。

### 2.8 Telemetry（2 Hz）——只读汇总

- **职责**：黑盒快照 → `P_TELEMETRY` 的遥测子键 + 一行日志，**不做决策、不驱动物理量**（`dzrobot_v2/src/dzbrain/dzbrain/tasks/telemetry.py:4`）。
- **输入**：几乎全部黑盒键（表在 `telemetry.py:24`~`:29`）。
- **输出**：`P_TELEMETRY`（`telemetry.py:295`），read-modify-write 自己的两个子键，**不整键覆盖**（`:11`）。
- **失败表现**：缺键一律显示未知、不会崩（`:31`）。所以「遥测某字段是空」≠「那个任务没跑」，要回去看该任务自己的日志。

## 4. 一个航点的一生

> 场景：机端下发 v2 布局（带 `known`），`target_cell=K10`，车在 `N10`。"跳"＝一次跨模块传递，每跳都有锚点，可以直接跳到代码处。

### 跳 1｜机端 → 车端：一条 JSON 进邮箱

`/dzlink/drone_to_car`（`dzrobot_v2/src/dzbrain/dzbrain/io/contract.py:94`）的回调只做一件事：把字符串塞进列表（`dzrobot_v2/src/dzbrain/dzbrain/io/ros_io.py:346`~`:351`，上限 64 条、超了丢最旧）。

- **失败形态**：话题名错或域号不同（车 118 / 机 0 是历史事故）⇒ 邮箱永远空，最终表现为**启动 exit 3**。

### 跳 2｜DroneTask 消费 + 校验 + 落黑盒

5 Hz tick 取邮箱 → 按 `type` 分发 → `field_layout` 走版本裁决：版本 < 当前 ⇒ 拒收；版本相同且内容相同 ⇒ 只当心跳（`P_LAYOUT_ARRIVALS` +1，不重写不换版）；版本相同内容不同 ⇒ 拒收。接受 ⇒ `P_FIELD_LAYOUT`（`dzrobot_v2/src/dzbrain/dzbrain/tasks/drone.py:1020`）+ `P_LAYOUT_ARRIVALS`（`drone.py:1027`）。

**起点权威播种**：belief 与 `layout.start` 不一致时 DroneTask 会**直接改 `P_POSE`**（`drone.py:1160`，只播一次，`start_authority_seeded` 闩锁）。

- **失败形态**：`layout_rejects` 增长＝报文不合法（必填键缺失、格名越界、`mines` 不在 `known` 里）；一条节流告警，**旧布局保留**。

### 跳 3｜启动门：等第一份布局

`_wait_for_field_layout`（`dzrobot_v2/src/dzbrain/dzbrain/main.py:2457`）限时等，上限 `drone.field_layout_wait_s`（SCHEMA 缺省 60 s，`dzrobot_v2/src/dzbrain/dzbrain/core/config.py:576`）。超时 ⇒ **exit 3，不规划不出发**（`main.py:3026`~`:3031`）。

拿到后分叉（`main.py:3032`）：带 `known` ⇒ 步进循环；不带（v1）⇒ 一次性规划（`:3053`）。步进模式会**强制关掉 Mission 的 auto_start**（`:3037`），因为段由步进器显式下发。

### 跳 4｜StepLoop 启动：播种 belief

`StepLoop.start()`（`main.py:1189`）→ `_seed_pose()`（`:2037`）→ `mission.reset_pose(spec)`（`dzrobot_v2/src/dzbrain/dzbrain/tasks/mission.py:1911`）。

复位串优先取 `mission.reset`，没有才用 `layout.start`（`main.py:2038`~`:2040`）；但真正生效的**格名以布局为准**：`_authoritative_reset_spec()`（`mission.py:1941`）发现两者不一致就改成布局的 `start` 并打 WARNING（`:1936`）。历史事故：配置复位 N10、布局说 L7 ⇒ 段 1 四个航点横向偏差清一色 0.350 m（整格偏移，`mission.py:1916`）。

### 跳 5｜每拍先看有没有新布局（只记不换段）

`StepLoop.tick()`（`main.py:1216`）第一件事是 `_poll_layout()`（`:1381`）：`P_LAYOUT_ARRIVALS` 变了只刷新"最近一帧到达时刻"（`:1385`~`:1389`）、不换内容；`version` 大于已见版本才记新布局并停止上一条完成单重发（`:1411`）；**DRIVING 期间到达的新布局只记版本，绝不重规划**（`:1415` 的日志后缀）。

- **失败形态**：日志 `忽略旧版布局 vN（当前 vM）`（`:1400`）＝ 机端重发了旧版。不是故障，但连续刷说明机端版本号不单调。

### 跳 6｜PLANNING：布局 + 当前格 → 一次规划请求

`_plan()`（`main.py:1419`）：

1. `_sync_brain(layout)`（`:1288`）把 `known` 并进本场脑内地图（同格不换版，`map_version` 只在集合变化时 +1）；
2. 取 `target_cell`（`:1430`）与当前格 `_current_block(prefer_prev=True)`（`:1439`；允许"上一段目标格"当当前格，容差 0.5 格，`:1860`）；
3. **同格停站**（`from_cell == target_cell`）⇒ 直接判段完成、0 token（`:1443`~`:1454`）；
4. 布局过期按闸门口径处理（`:1460`）：`step.layout_ttl_s` 缺省 **0 = 关闭**（`dzrobot_v2/src/dzbrain/dzbrain/core/config.py:589`），所以正常路径不拦；只有 `hard` 口径才回 `WAIT_INFO(layout_stale)`；
5. 调规划器 `self._planner(...)`（`main.py:1483`）＝ `plan_segment_from_layout`（`:908`）；异常 ⇒ `WAIT_INFO`，**不退出循环**（`:1485`）。

- **失败形态**：`段规划失败：<error>` ⇒ `WAIT_INFO`（`:1495`）——车停着等新布局，不是崩溃。

### 跳 7｜规划器：未知格怎么算由闸门口径决定

`plan_segment_from_layout`（`main.py:908`）的 `degrade` 参数：`True`（运行面 warn 口径，当前默认）⇒ **未知格当可通行**，只记 `layout_incomplete` warn（`:916`）；`False`（旧拦停口径）⇒ `known` 为空 / 目标不在 `known` / 段路线穿未知格**都拒发**（`:919`）。

产出 `SegmentPlan`：tokens / cells / `route_len_m` / `elapsed_ms` / `stop_kind` / `warnings`。`stop_kind` 决定到站后走不走打靶三段式（`main.py:926`~`:929`）。

### 跳 8｜投递给任务线程（唯一跨线程改 route 的入口）

`mission.request_segment(...)`（`dzrobot_v2/src/dzbrain/dzbrain/tasks/mission.py:1860`）：只往 `_segment_req` 里放请求，真正载入在 MissionTask 自己的 tick 里做（`:1967` `_process_segment_requests`）——这就是"路线只由 Mission 线程改"的实现方式。

两种拒绝（`:1881`~`:1884`）：上一请求还没被取走；本段仍在执行（**换段只允许在段边界**）。被拒后 StepLoop 把 `_planned_version` 置 −1 并 `WAIT_INFO(retry=True)`（`main.py:1509`~`:1510`），下一拍立刻重试、不重复打印日志。

### 跳 9｜Mission 载入段 → 进入 DRIVE

`_process_segment_requests()`（`mission.py:1967`）→ 清终点锁存（`:1997`）→ `_load_tokens()`（`:2941`，`parse_mission` + `_install_route`）→ `_start_mission()`（`:2849`）→ 阶段 DRIVE（`_write_phase`，`:3848`）。

载入失败（坏 token / 少于 2 点）⇒ **保持 IDLE**、清路线、记 `_segment_error`（`:2008`~`:2013`）；StepLoop 的 `_drive_tick` 读到该 error 走 `_on_segment_error`（`dzrobot_v2/src/dzbrain/dzbrain/main.py:1557`）。

### 跳 10｜每拍推进：谁的"到达"算数

`_drive()`（`mission.py:3529`）→ `_advance_waypoints()`（`:3213`）。判据三选一 + 两道复核（`:3272`~`:3285`）：

1. `s_reached` 且 `near`（弧长到 + 车横向偏差 ≤ 0.30 m）；
2. `dist` ≤ `arrival`（距格心；`pursuit.arrival_m` = 0.12，`dzrobot_v2/src/dzbrain/dzbrain/core/config.py:172`）；
3. PIVOT 通知（掉头顶点，`PIVOT_DONE_KEY`）；
4. 几何复核：最近接近 ≤ `_close_m` 也算到（s 跳变放过的那一拍）；
5. 都不到但越过量很大 ⇒ 只登记**越窗待定**，不置位（`mission.py:3299`）。

末点专用更严半径 `_GOAL_STOP_M` = 0.03（同口径见 `dzrobot_v2/src/dzbrain/dzbrain/tasks/localization.py:84`）：避免「离终点 0.12 m 就判到达 → 提前刹车停在格心前 11 cm」（`mission.py:3248`~`:3252`）。到达发 `EV_WAYPOINT_REACHED`（`:3292`）。

### 跳 11｜到站：停站三段式（只有射击站才打靶）

`_should_trigger_stop`（`mission.py:3548`）→ `_enter_stop_point`（`:3569`）→ 阶段 STOP → `_run_stop_point`（`:3596`）：

| 顺序 | 判据 | 出口 | 证据 |
|---|---|---|---|
| 0 | 到站硬死线 `mission.shoot_timeout_s`（代码缺省 30 s，可用 `mission.stop_deadline_s` 覆盖） | 强制离站，**0 发也走** | `mission.py:3607` |
| 0b | 红面早退（`P_AIM_RED` 的 `confirmed` 为真且已停留 ≥ `aim.red_early_leave_s`） | 提前离站 | `mission.py:3621` |
| 1 | SETTLE：位移 ≤ `settle_eps_m` 或速度 ≤ `settle_speed_mps`，持续 `settle_time_s` | ACQUIRE | `mission.py:3658` |
| 2 | ACQUIRE：`aim_status` 为 TRACK 且有目标 | FIRE；超 `lock_timeout_s` 放弃 | `mission.py:3684` |
| 3 | FIRE：`shoot_count` 增量 ≥ `shots_per_stop`（缺省 3） | 完成；超 `shot_timeout_s` 放弃 | `mission.py:3702` |

每段切换都先 `publish_fire_gate(False)`（`:3734`）——**绝不留一个开着的放行门**。

### 跳 12｜打靶：两把钥匙在 C++ 合流

Mission 在 FIRE 段每拍续租 `fire_gate=True`（`mission.py:3716`）；Aim 独立判 `fire_ready`（`dzrobot_v2/src/dzbrain/dzbrain/tasks/aim.py:1132`）。C++ 侧 `externalFireAllowed()` 要求两键都 1 且都在 500 ms 内续租（`dzrobot_v2/src/dzrknn_dataprocess/src/dzrknn_dataprocess.cpp:1146`）。开火 ⇒ `LaserShot_Command`（`:1273`）→ `dzjudgment` 收命令（`dzrobot_v2/src/dzjudgment/src/judgment.cpp:62`）打激光 → 回 `HpAndHitmsg`（`:73`）→ 车端 `on_referee_hp`（`dzrobot_v2/src/dzbrain/dzbrain/io/ros_io.py:319`）解析 → `take_hits()`（`:456`）给 Mission 记账。

- **失败形态**：`发数增量 0/N` 一路到硬死线 ⇒ 检查顺序 ①`fire_gate` 日志有没有 True ②`P_AIM.last_reason` ③`dzjudgment` 在不在线（掉线时开火零报错、裁判不计数）。

### 跳 13｜段末：完成单的产生（带劫持闸）

`_check_finish()`（`mission.py:3971`）只在"本来要判完成"那一拍才查劫持闸 `_segment_completion_gate`（`:3926`）：段长 > `mission.segment_gate_min_m`（0.30）且 行驶 < 段长×`segment_gate_ratio`（0.5）且 用时 < `segment_gate_min_s`（2.0）⇒ 拦下（不锁存 FINISH、不报完成）。

放行后组装完成单（`:4018`~`:4034`）：segment_id / target_cell / block / pose_block / known_count / stop_kind / elapsed_s / waypoints / finished_at / finish_info，写 `_segment_done` 并清 `_segment_active`。

### 跳 14｜StepLoop 收到完成单 → 段状态迁移

`_drive_tick()`（`dzrobot_v2/src/dzbrain/dzbrain/main.py:1544`）顺序：硬拦①`hw_estop`（`:1546`）→ 硬拦③`field_boundary`（`:1549`）→ 只记不拦的 aim 观测（`:1552`）→ 位姿看门狗（`:1554`）→ 段错误（`:1557`）→ **完成单 `segment_id` 与本段一致**（`:1562`）→ 未知格（`:1567`）→ 任务线程回 IDLE 且无完成单（`:1572`）。

命中 ⇒ `_mark_segment_done()`（`:1656`）：`segments_done` +1、`done_seq` +1、闩锁 `_done_latch`、阶段 SEGMENT_DONE、立刻 `_publish_car_state`（`:1678`）。

### 跳 15｜车状态上车端链路 → 机端

`_publish_car_state()`（`main.py:1821`）把 phase / segment_id / known_count / target_cell / stop_kind / block / version / reason / done 等写进 `P_CAR_STATE`（`:1850`，**内容不变就不写**，`:1848`）。

DroneTask 按 `drone.car_state_period_s`（缺省 0.7 s，`dzrobot_v2/src/dzbrain/dzbrain/core/config.py:570`）读它（`dzrobot_v2/src/dzbrain/dzbrain/tasks/drone.py:1390`），变化判据含 segment_id / target_cell / stop_kind（`:1402`），发 `/dzlink/car_to_drone`（`:1428`）。机端据此推进检查点。

### 跳 16｜段边界：三种去向

`_after_segment_done()`（`main.py:1587`）：

1. 完成格等于 `layout.end` ⇒ `_to_finish()`（`:1727`）：阶段 FINISH、刹车、退出码 0；
2. 已见版本大于已规划版本 ⇒ 回 PLANNING 立刻重规划（`:1593`）；
3. 否则 `WAIT_INFO`（`:1600`）：停车保持位姿、**无超时**（`step.wait_timeout_s` 缺省 0，`dzrobot_v2/src/dzbrain/dzbrain/core/config.py:578`），并把上一条完成单按 `step.done_replay_s`（缺省 1 s，`core/config.py:592`）**重发**（`main.py:1687`）——这就是修「段完成只活 1~2 拍、机端漏收 86%」的闩锁（`main.py:1106`）。

## 5. 唯一性契约：文档怎么写 vs 代码实际怎么做

这一节是"防美化"的核心。`01_架构与线程.md` §2 的四条契约，在当前树上的真实状态如下。

### 5.1 「只有 Tracker 写底盘指令」→ 精确版：只有 Tracker 发非零指令

`pursuitAngle` 的写者一共 **4 个模块**（全部经 `bridge`）：

| 写者 | 调用点 | 发什么 |
|---|---|---|
| TrackerTask | `dzrobot_v2/src/dzbrain/dzbrain/tasks/tracker.py:687` | 非零驱动指令（唯一） |
| TrackerTask | `tracker.py:365` / `:907` | 零 Twist（前置门 / 收尾） |
| SafetyTask | `dzrobot_v2/src/dzbrain/dzbrain/tasks/safety.py:469` | 零 Twist（强制停车） |
| MissionTask | `mission.py:1982` / `:2454` / `:2478` / `:2662` / `:4040` | 零 Twist（停站 / 让位 / FINISH 双保险） |
| StepLoop | `main.py:1720` / `:1732` | 零 Twist（WAIT_INFO / FINISH） |

**判据**：出现「车不动」先看有没有非零指令（Tracker 是否被前置门挡住），再看零指令是不是某个模块在压着——多写者互压是真实风险（`main.py:1106` 记的"完成单只活 1~2 拍"同源问题）。

### 5.2 「只有 Localization 写 P_POSE」→ **不成立（3 个写者）**

| 写者 | 位置 | 语义 |
|---|---|---|
| LocalizationTask | `dzrobot_v2/src/dzbrain/dzbrain/tasks/localization.py:459` / `:465` | 每拍最终信念（正常路径） |
| MissionTask | `dzrobot_v2/src/dzbrain/dzbrain/tasks/mission.py:2932` | `reset:BLOCK,HEAD` 复位（启动 / 外部命令） |
| DroneTask | `dzrobot_v2/src/dzbrain/dzbrain/tasks/drone.py:1160` | 布局 `start` 起点权威播种（**只播一次**） |

三个写者都是刻意设计的（复位/播种必须先于定位链路稳定），但代价是：**「P_POSE 变了」不能直接归因给定位**。排障时用 `P_POSE_RAW`（只有 Localization 写，`localization.py:411`）对拍，差值就是修正量。

### 5.3 「只有 Safety 能强制停车」→ 成立，但要区分"强制"的两层含义

Safety 是**唯一**把 `P_SAFETY.ok` 置假的地方（`dzrobot_v2/src/dzbrain/dzbrain/tasks/safety.py:439`），而 Tracker 的第一道放行门就是 `safety.ok`（`tracker.py:352`）。所以别的模块刹车（`publish_brake`）只是"这一拍不发指令"，Safety 的锁存才是"长期不许动"。

### 5.4 「云台扫描单写者」→ 条件成立

`aim.gimbal_lock_enabled` 为真（缺省 True，`dzrobot_v2/src/dzbrain/dzbrain/tasks/mission.py:1547`）时 Mission 的 `_request_scan` **直接 return**（`:3833`~`:3839`），只有 Aim 写 `/nav/scan_request`（`dzrobot_v2/src/dzbrain/dzbrain/tasks/aim.py:1121` / `:1247`）。配成假就回到"Mission 也写"的旧行为——那时**两个写者会互压**（`mission.py:1541` 记的 run11 实证）。

### 5.5 契约表的字段错位（小坑，但会误导新代码）

`Topic` 的字段顺序是 name → msg_type → qos → **unit → note → direction**（`dzrobot_v2/src/dzbrain/dzbrain/io/contract.py:48`）。但表里大量条目按**位置**传参时把"方向"写在了第 5 个位置（写进 `note`），第 6 个位置才放备注 —— 于是：

- **8 条发布类话题**（scan_request / aim_fire_gate / aim_fire_ready / stop_signal / motion_state / voice_switch / drone_out / aim_lead）的 `topic(k).direction` 恒为默认 `"sub"`，实际是发布者；
- **3 条**（odom / offset_center / pursuit_angle）的 `direction` 里装的是备注文本；
- 只有用关键字写的那几条（如 `referee_hp` 的 `direction="sub"`，`contract.py:102`）是对的。

今天**没有逻辑依赖它**：唯一消费者是 `ContractSummary.render()`（`contract.py:467`），而它只被测试调用（`dzrobot_v2/src/dzbrain/tests/test_contract.py:88`）。所以现状是"打印/索引口径会看错"，不是运行时缺陷。**但你若按 `direction` 写判据（例如断言某话题是 pub），一定会踩**——要么改用关键字传参把全部条目补齐，要么一律以本文 §1.2 / §2 的手工核对表为准。
