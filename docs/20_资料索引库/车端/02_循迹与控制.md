# 循迹与控制

## TL;DR（给 agent 看的）
- 控制律只有一条：`δ = atan(gain · 2L·sinα / ld)`，前视 `ld = clamp(k_v·v, [min,max])`；**没有 MPC / DWA**（理由见 §4）。
- 分支优先级：前置门 → **PIVOT** → 倒车入口推一把 → 桥洞 ALIGN → 纯追踪。
- 最容易搞反的两点：① **PIVOT 判据是「车头转角 ≥135°」，不是行进夹角**；② 倒车段车头朝向 = 行进方向 +180°。
- 坑：**参数有两套历史版本**（循迹说明的快照 vs 现役 robot.yaml），照旧文抄 = 直接慢 2 倍以上；见 §3。

## 1. 数据链路

路线 token → `Path`（段表 + 弧长前缀）→ 每拍把 `/odom` 位姿**投影到路径**得 `s` 与横向偏差 → 纯追踪算舵角 → 多层限速 → `/pursuitAngle` → Safety 网关 → 底盘。

投影四件套（缺一个就会重现 4.1 m 级横偏〔档〕）：窗口搜索、等距裁决、弧长地板（不许回退）、跟丢后 relock 自愈。

## 2. 公式与限幅（与代码一致）

| 项 | 公式/值 | 出处 |
|---|---|---|
| 舵角 | `δ = atan(gain·2L·sinα/ld)`，`gain=1.0` 为教科书式 | `pursuit/controller.py`；`robot.yaml:618` `curvature_gain` |
| 前视 | `ld = clamp(k_v·v, [lookahead_min_m, lookahead_max_m])`，`k_v=1.2` | `robot.yaml:619-621` |
| 曲率限速 | `v = sqrt(a_lat/κ)`，`a_lat=0.35 m/s²` | `robot.yaml:622`（`lat_acc_max_mps2`） |
| 舵角限幅 | ±30°，速率 ≤120 °/s（防一帧跳 60°） | `robot.yaml:615-617` |
| 轴距 | 代码 `0.157 m`；手册 **150 mm** | `robot.yaml:615` vs D-027 |
| 到点 | `arrival_m = 0.12` m（schema 默认，车端未覆盖） | `config.py:155`；`robot.yaml:864` 注释确认默认等于 `pursuit.arrival_m` |
| 单段漂移告警 | `drift_warn_m = 0.30` m；判定窗口 `drift_seg_gate_m = 0.18` | `robot.yaml:632-633`、`:454` |

> **口径矛盾（必写）**：到点判据 0.12 m **远小于**漂移告警 0.30 m ⇒ 车「离格心 0.2 m 就该算到了」，却「到 0.3 m 才算漂移」。两者不是同一坐标系下的容差，改一个必须同步另一个（§6）。

## 3. 参数 A 版 / B 版（必须并列，别二选一）

| 项 | A 版：循迹算法说明快照（10-11 安全档，已过期） | B 版：现役 `robot.yaml`（10-21 实车提速档） |
|---|---|---|
| `cruise_speed_mps` | 0.15 | **0.35**（注释：0.15→0.40 三档仿真，实车暂用 0.35） |
| `lookahead_min_m` / `max` | 0.18 / 0.24 | **0.36 / 0.40** |
| 依据 | 早期安全档 | t1/t4 双复核：@0.15 隔板 352→0 拍、盖雷 3/8→8/8；@0.30 零影响 |
| `accel_up/down` | 0 | 0.0（**斜坡层本轮不参与**，跑完恢复 0.70/1.10） |

> 引用「ld = clamp(1.2·v,[0.18,0.24])」时务必注明是 A 版快照；现役 ld 范围是 **[0.36, 0.40]**，比 A 版宽一倍。

## 4. 为什么是纯追踪

- 全场最窄弯 R≈0.272 m、速度 0.1–0.35 m/s，MPC 的收益被标定误差和 50 Hz 时序吃掉。
- 单一速度出口便于「所有限速在一个出口钳位」（R1 的修法就是复用这个出口）。
- 代价：横向大偏差恢复慢，靠「弧长地板 + relock + 顶点前视重投影」补。

## 5. 三个分支

| 分支 | 进入条件 | 退出 | 坑 |
|---|---|---|---|
| **PIVOT** | 段末**车头转角** ≥135° | SETTLE 刹车 → TURN 蠕动 → DONE；**14 s 硬超时** + `abandon_until_s` 防循环 | 超时是 `abandon` 不是 done；旧代码曾不区分（D-027） |
| **倒车**（token 前缀 `R:`） | 段首带 `R:` | 段末自动切回正向 | 舵角符号翻转、速度 ×0.6；车头朝向 = 行进方向 +180° |
| **ALIGN**（桥洞） | 桥洞窗口内（洞前 2.0 s / 洞后 1.0 s 锁航向） | 对准后进洞 | 现役 `bridge_blocks: []` ⇒ 强制直行保护**关闭**，ALIGN 实际不可达（`robot.yaml:634-639` 仅保留参数） |

- PIVOT **不是原地自转**：实现是 0.08 m/s 前进弧（`config.py`/`tracker.py`；D-027/D-029），而车是标准阿克曼 ⇒ 物理前提未证。
- 规划器允许「同格改变朝向」，车做不到原地转 ⇒ 仿真绿 ≠ 实车绿（D-026）。

## 6. 限速契约（R1 的教训，**补丁未部署**）

- 缺陷：`tracker.py` 分支里对速度的赋值**覆盖**了 controller 已限速的中间命令，公共 `publish_command()` 前缺统一钳位 ⇒ ALIGN / PIVOT TURN 段绕过 `P_MOTION_LIMIT`（R0 13 例中 4 例复现）。
- 修法（D-025）：在唯一出口前复用 `motion_limit_speed_limit(self.bb)`；`abs(v) > L` → `0.0` 或 `copysign(L, v)`（保号）。单 hunk +14 行。
- 状态：本地已改并回归（`test_tracker` 136/136、`test_pivot` 55/55），**车端仍是 R1 前版本**（本地 `e9bff6f0…` / 车端 `9e9766a1…`）。

## 7. 调参纪律

1. **一次只改一个变量**：0.15↔0.3 m/s 会同时改变 `ld`、`lat_acc` 限速与停站判别，改两个就说不清谁起作用。
2. 提速前先看早到/晚到与横偏，而不是先看「有没有到」。
3. 「PIVOT 不可达」先查三件事：`pivot_penalty` 是否被静默变 0、`arrival_m` 与 abandon 阈值、冻结登记版本。
4. 改 PIVOT/到点语义前必读 D-027：阿克曼前提下这两个判据的物理意义都还没实测。

- 时间预算纠错：若原式中折返为每次14–36秒，则22.75/0.35+2×30+4×(14–36)=**181–269秒**；不是181271秒，也不能拿不建模PIVOT/射击驻留的旧sim时长替代赛时。

### 本轮验收修正（用户2026-10-25后续澄清）

0.113m 是旧折线圆弧切角的论证数字，**不是验收阈值**。新验收为：①必经点误差；②区域硬约束（矩形车体到柱表面≥0.02m、桥墙在格边界且横偏≤0.0875m）；③实际轨迹相对新参考轨迹的横向RMS。离旧普通顶点多远只作为diff，不做pass/fail。静态参考曲线的0误差不能代替实际闭环RMS。

本轮独立审查确认积分点为后轴，车体几何中心在前方 **vehicle.ref_offset_m=0.075m**。雷事件约束现作用于真实几何车心；后轴8/8不代表车心8/8。审计并列输出两者，真实车心覆盖才进入本轮硬判据。普通路线参考点/射击窗口仍按既有契约，不能混用坐标名。

已复现的控制机制：长距离曲率预瞄配当前Frenet误差，会使零误差状态也受到错误前馈；离线候选改为按同一执行延迟选前馈相位，曲率自适应距离只作预览上限。停车换向必须同时限制投影搜索区间和方向授权，不能让最近点跳到未获准的出站支路。起始朝向需显式使用真实摆位，不能在另一张图上用首段方向替代现场朝向。

范围确认：用户明确t-car尚未交还Tracker/Localization/Mission，**本轮先完成离线候选**；这三个运行链文件和PIVOT/ALIGN未修改。外测数据暂无，深度相机RMS仍未验收。全部改动以在办卡为准，不因离线结果较好而宣称已替换现役控制器。
