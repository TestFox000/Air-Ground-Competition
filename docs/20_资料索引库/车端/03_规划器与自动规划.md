## 1. 三引擎定位

| 引擎 | 状态 | 能力/限制 | 为什么不能换 |
|---|---|---|---|
| `tour` | **现役/默认** | 支持 `:PIVOT`、无倒车；最短巡回目标 | — |
| `tracker-safe` | 降级候选 | **硬禁 180° / 禁紧凑 U / 雷格转角 / 隔板紧邻行侧向 90°** ⇒ **四张真实夹具图 4/4 无解**（WB-14 实测，见 §8） |
| `global_planner` | 参考实现 | 5/5 出串 | **0/5 过 check**：射击窗 0.78–1.02 m 与 8 邻域矛盾、起点朝向不生效 |
| `hybrid`（P1 原型） | 实验，未合入 | 子集 DP 注入 `_Tour.polish` | 64 图 27/64、耗时 1.06×，无净收益（D-021） |

- 引擎选择在 **plan 阶段**决定路线形态，改引擎 = 改路线 = 改回归夹具期望值，不是「换个开关」。
- `test_planner`/`test_corner_cut`/`test_incremental_plan` 三套 CRASH 的直接原因就是仍在直调 `plan_route_tracker_safe()`（`全量回归37套_严格审查台账_20261018.md:97-106`）。

## 8. `tracker-safe` 在真实图上 4/4 无解 —— 已记账（WB-14，2026-11-01）

### 8.1 现役引擎实际值（先回答"影响面"）

`dzrobot_v2/config/robot.yaml:225` → **`planner.engine: tour`**（行内注释原文："现役 tour（tracker-safe 现役图无解）"）。

⇒ **这不是生产级风险**：`tracker-safe` 是备选引擎，现役走 `tour`。但配置注释里这句"现役图无解"以前只是**一行断言**，本节把它变成**有逐图证据的裁决条目**。

**但有一条必须同时写清（WB-14 顺带实测，比卡面原设想更严重的一层）**：
`auto_plan_enabled` 实测 = **`true`**（`:231`，2026-10-25 用户指令改的——"车端零地图 + 布局模式"），
**不是文档旧版写的 `false`**。也就是说"自动规划开关**开着**" + "备选引擎 `tracker-safe` 出不了串"
两者同时成立。影响面：
- 现役引擎是 `tour` ⇒ **今天不会有问题**（`tour` 在四张真实夹具上都出串，见 §8.2 对照）；
- 但**若有人把 `planner.engine` 切成 `tracker-safe`**，自动规划会**每次规划都失败**
  且因为 `fallback_to_tokens: false`（失败不回退手写线，回退=按旧图出车比停车危险）⇒ **直接停车报错**。
- 这条不在本卡修（改默认值属用户裁决），但必须让人**在切引擎之前就看到**。

### 8.3 死锁**不是一条机理** —— 四张图三种成因（这是本节最重要的修正）

旧说法（WB-9 口径）是"洞在隔板相邻行 → 行内 90° 进场转弯被转向禁令杀 + 进洞邻格禁换行 → 死锁"，**只对 field7 / sixth 成立**。逐图单独放宽实验给出的是三种不同形态：

| 图 | 单条放宽能否解 | 联合放宽 | 真实绞索 |
|---|---|---|---|
| field7 / sixth | 单条**全都不行** | **G2+G3+G6 三条同时**才出解（54 token、0 折返） | 「禁紧凑 U + 雷格转角 + 隔板紧邻行侧向 90°」三者叠加 |
| field | 单条全都不行 | 两两 `G3+G6` 出解 | 雷格转角与隔板行转角的**互补**约束 |
| carloop | **G2 或 G3 或 G6 单独放开即有解**（58/52/56 token，0 折返） | 全放开 52 token | 单条禁令即绞索（**这张图离可用最近**） |

**判读**：`tracker-safe` 的四条硬规则各自都有实测依据（每条注释都指向现场事件），但**它们叠在一起时在 U 形赛道上互相锁死**。这不是"算法不够聪明"（放宽任一维度立刻出解），也不是"规则写错了"（每条单独看都对）——是**规则组合的可行性问题**。

### 8.4 一个必须并列的细节：放宽后产出的解**本身不合法**

field7/sixth 把 G1..G6 全放开后，搜索确实找到路，但 `assert_legal_no_reverse` 当场拒绝：

```
折返点缺少 :PIVOT 声明：#46 G5 180°（折返角 ≥ 135° 的顶点必须显式声明 ——
该处车头要转 180°，无倒车模式下车只能原地掉头）
```

⇒ **放宽不是解**。即使把角度类禁令全开，解仍含 180° 原地掉头，而那正是 `tracker-safe` 的定义要禁止的。所以这张卡**没有任何"调参就能修好"的路径**。

### 8.5 挂账（不做的事）

- **不改 `planner.engine` 默认值**（属用户裁决范围；本节只报事实）。
- **不放宽任何一条硬规则**换绿——每条规则的依据都是现场实测（触线拍数）。
- 若要 `tracker-safe` 可用，需要的是**改赛道拓扑或改规则组合**（属结构决策，不是本卡范围）。

### 9.4 这条会不会影响下一次实车

**不会**——前提是不换隔板行。现役第六图与四张夹具的隔板行都是 6/7，两种口径数值相同。但**若用户下次换一张隔板行不同的场地图**，旧口径会让 `route_check` 用错位一整格的中心线算挡板触线余量（该红的判绿）⇒ **这正是修它的理由**。同一条缺口也影响 R003 拓扑判定。

### 9.5 不许做的事

- **不改 `core/geometry.py` 的常量值**（`BARRIER_ROW_HI/LO` 是另一条真源链，D-054/D-029 管）。
- **不改 `planner.engine` 默认值**。
- 常量仍是**缺省值**：任何未传地图的调用点行为逐字不变（向后兼容靠 `None` 回落实现，不靠改常量）。
