# 规划器与自动规划

## TL;DR（给 agent 看的）
- **生产只认 `tour`**（D-012）：`planner.engine: tour`；`tracker-safe` 仅「无折返图」候选；`global_planner` 是参考实现，**不得转正**；未知引擎名回退 tour。
- 随机图基线 **28/64 = 43.75%**（10-18 与 10-21 两次复跑同值）；失败主因是**结构约束**（穿洞次数、无可用射击停站），**不是 DP 顺序层**（D-018）。
- 11-04 前有在途改动：新目标函数口径下 **47/64 = 73.44%**，但**默认入口仍是 legacy**，必须显式 `--objective tasks` 才生效——看到 47/64 别以为车端已经变好。
- 自动规划默认**关**（`robot.yaml:777` `auto_plan_enabled: false`）；车上路线实际来自无人机 `/nav/waypoint` 或 `route.tokens` 兜底。

## 1. 三引擎定位

| 引擎 | 状态 | 能力/限制 | 为什么不能换 |
|---|---|---|---|
| `tour` | **现役/默认** | 支持 `:PIVOT`、无倒车；最短巡回目标 | — |
| `tracker-safe` | 降级候选 | **硬禁 180°** | 现役第六/七图各含 3 处 `:PIVOT` ⇒ 现役图 0/5 可用 |
| `global_planner` | 参考实现 | 5/5 出串 | **0/5 过 check**：射击窗 0.78–1.02 m 与 8 邻域矛盾、起点朝向不生效 |
| `hybrid`（P1 原型） | 实验，未合入 | 子集 DP 注入 `_Tour.polish` | 64 图 27/64、耗时 1.06×，无净收益（D-021） |

- 引擎选择在 **plan 阶段**决定路线形态，改引擎 = 改路线 = 改回归夹具期望值，不是「换个开关」。
- `test_planner`/`test_corner_cut`/`test_incremental_plan` 三套 CRASH 的直接原因就是仍在直调 `plan_route_tracker_safe()`（`全量回归37套_严格审查台账_20261018.md:97-106`）。

## 2. 64 图压测（唯一可信的求解率基线）

| 项 | 值 | 出处 |
|---|---|---|
| 图集 | 64 张同源随机图，4 worker，seed 固定 | `docs/压测_规划器64图_20261018.md:12-16` |
| tour 成功率 | **28/64 = 43.75%**（plan_failed 36） | 同上；`_tmp_session/p1_hybrid/stress_results.json` |
| hybrid | 27/64 = 42.19%（加 tour 回退仍 28/64） | 同上 |
| planned 路线质量 | 全部 `route_check` exit 0 / 0 error | `_tmp_session/p1_hybrid/STRESS_REPORT.md` |
| 失败主因 | 穿洞类 19 条（上半场 2 次 11 / 下半场 2 次 3 / 3 次 5）+ 无可用射击停站 4 条 | `summary.top_reasons` |

**判读**：43.75% 不是「算法不够聪明」，而是「约束本身无解或近似无解」。换顺序无效（hybrid 只丢 1 图、且没多赢 1 图），只能改结构约束（U 形拓扑 / 桥洞穿越 / 停站可行性）。

- 唯一共同成功的 27 图里，hybrid 只在 1 图（index55）少 2 个 PIVOT，代价是长度 23.45→26.25 m（**+2.80 m**）——「少折返换更长」，不是免费改善。
- hybrid 独有失败 1 图（index60）：上半场穿洞 2 次，与 P1 map6 代理陷阱同源。

## 3. 当前在途：T-B1 目标函数换口径（未验收）

| 项 | legacy（默认） | `--objective tasks`（新） |
|---|---|---|
| 64 图全任务覆盖 | 28/64 = 43.75% | **47/64 = 73.44%**（验收线 ≥45/64） |
| `test_autoplan` | 148/171（23 红） | **171/171 exit 0** |
| 目标 | 最短巡回，约束不满足即无解 | 先最大化成功任务数（8 雷 + 可达射击停站），再最小化时间；180 s 只作 deadline |

- 证据：`_tmp_session/TRACK-PLAN-B1-20261021/REPORT.md:8,29-36`、`docs/30_任务卡库/在办/track-1021/TRACK-PLAN-B1-20261021.md:32-35`。
- **取证等级：档/自报**。编纂时未独立复跑这两组数字（编码者在干净树用过同样命令）。
- **最大坑**：默认仍是 legacy，车端不会自动用新口径；`planner.py` 冻结登记至 **2026-11-04**，验收后才能谈合入。

## 4. 已知缺陷（必须并列「能重钉 / 不许重钉」）

| 缺陷 | 现象 | 处置 |
|---|---|---|
| **tour 只出单射击停站** | 第七图只产出 `C9*`，对侧 `C5*` 不在路线 ⇒ 靶在另一侧那局整场打不到 | **禁止重钉，必须改代码**（D-023 ⑤ L3；`test_autoplan` 6 条：12.3/12.4/12.7/12.8/12.9/12.10） |
| 外部 `/nav/waypoint` 无双停站闸 | `_load_tokens()` 只 parse+install，无 `ensure_second_shoot_stop` | 与 D1b 一起排；`mission.py:2814-2825` vs `:1011` |
| 同格旋转物理前提未证 | 规划器允许同格改朝向，车是阿克曼 | D-027：需连续轨迹 + 全车扫掠证据 |
| 停站格压靶板 | 车体压 D6 靶板 92 拍、挡板触线 131 拍（A1 真缺陷） | 独立成立，与 PIVOT 无关；改停站格或跟踪切内 |

## 5. hybrid / P3a 归档结论（别重开）

- 64 图无净收益（27 vs 28）；P3a 自进化 48 训练 / 16 留出，训练集 default 最优，留出集 hybrid 7/16 vs tour 8/16，**闸门驳回、不设 champion**（D-021）。
- P3a 只跑 2 代 × 4 个体，统计功效很低 ⇒ 它证明的是「本次没赢」，不是「进化无效」。
- 结论：**P2（把 hybrid 合入 planner.py）不开**（D-016），除非先修完执行层 + 结构约束。
