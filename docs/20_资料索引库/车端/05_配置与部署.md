# 配置与部署

## TL;DR（给 agent 看的）
- **部署唯一入口** `tools/deploy_to_car.py`（`probe/backup/push/build/verify/all`）；`deploy_car.py` 只作**只读诊断**，其 `--write` 仅现场应急且需 Lead 授权（D-019）。
- **刻意不推 `config/map.yaml`**：仓库是第六图、车上是第七图。谁推谁把车弄瘸（D-019）。
- 别把 `all` 当单文件部署：它整包推送并**覆盖 `robot.yaml`**，且单独 push 不自动 backup。
- 最大坑：**同名键散在两个配置段**（`path_executor:` 与 `/dzbrain:` 各有一份 `drift_warn_m`），改一处不会同步另一处。
- SSH 主机名失败时先用 `probe` 找当前 IP 再直连；2026-10-24 实测 `duzhong.local` 被本机旧 `hosts` 条目劫持，车端 `sshd` 与公钥实际正常。

## 5. 现场必踩的九个坑

1. **`cam_viewer` 抢 `/pursuitAngle`**：20 Hz 发全零，底盘每帧更新 ⇒ 车「收到了但不动」。跑车前必 kill。
2. **布局模式 `--map` 指向存在的文件** ⇒ 进文件模式，StepLoop 收布局也不规划；必须传**不存在**的路径。
3. **非交互 SSH 域号变 0**：ping/SSH/网页全通，ROS 互相看不见且**零报错**。
4. **`robot.yaml` 顶层裸键**（如 `camera:` 写在根）⇒ 相机/视觉/云台三节点同时 abort；地图必须放 `config/map.yaml`。
5. `restart_node.sh path` 指向**旧核**；改路线/速度必须 `start_all.sh restart`。
6. `healthcheck` **不是起栈门禁**（自检已收敛到发车前 10 s 窗口）。
7. 车 IP 随网络漂移（`192.168.137.79` → `192.168.0.197`）——以 `probe` 为准，别写死。
8. **`duzhong.local` 被旧 `hosts` 条目劫持**：2026-10-24 本机 `C:\Windows\System32\drivers\etc\hosts:24` 仍写 `192.168.137.79 duzhong.local duzhong`，但小车只读实测仅有 `wlan0=192.168.0.4/24`。症状是 `ping duzhong.local`/部分 GUI 直接超时；OpenSSH 先等旧地址超时，再回退正确地址。先用 `probe` 或 `hostname -I` 核实当前 IP，直连当前 IP 可区分“名字错”与“sshd 坏”。
9. **`ssh dzrobot` 被别名强制密码**：本机 `C:\Users\TestFox\.ssh\config:1-6` 设置 `PreferredAuthentications password` 且 `PubkeyAuthentication no`。即使网络已连到正确小车，BatchMode/自动化仍会报 `Permission denied (publickey,password)`；显式 `ssh duzhong@192.168.0.4` 已证明现有 RSA 公钥可用。修改本机配置前先由操作者确认，本次只诊断未改。

来源: `SSH-DIAG-20261024`（2026-10-24 12:37~12:41 只读复跑；小车 `ssh=active`、22 端口监听、主机密钥匹配、公钥获接受）。
