# 交互式调参实验室（sim_lab）：改之前先用仿真看一眼

> **这篇给谁看**：手里有一组想改的参数、但**不想拿车去试错**的人。它教你用 `sim_cli` 把一个键跑成一对 A/B 实测，看清「改了之后哪个指标动了、动了多少」，并且知道**什么时候这个对比根本不成立**。
> **它不是什么**：不是参数地图（「改哪个键」去 [12_可调参数速查_按场景](12_可调参数速查_按场景.md)）；不是仿真器接口契约（那是 `tools/sim.py` 头注与 `sim_cli.py:50` 的参数表）；也不是扫参找最优（那是 `tools/sim_param_sweep.py`）。

## TL;DR

1. **15 个实验**，每个 = 一个可调的键 + **A/B 两臂**（A = 出厂现值，B = 单变量改值）。一条命令跑全部：`python tools/sim_lab/run_experiments.py --all`。2026-10-29 实测 **15/15 通过、退出码 0**，全套 23 秒（30 次仿真实跑 + 15 份报告）。
2. 判据是**机器判的**，不是人眼扫表：`change`（该有变化）/ `same`（该逐位不变）/ `obs_only`（只该动观测指标）。判据不成立 → 退出码 **3**；某臂没跑完 → **4**。
3. 三条最值钱的实测在 §3：前视下限 **零差异**（被 `lookahead_max_m` 钳住）｜越界拍 74→212 **而轨迹逐位不变**（只观测）｜延迟 0.26 s **RMS 反而降 41.5%** —— 真相是只跑了 4476 拍就判发散。
4. 产物：`artifacts/sim_lab/<实验>/report.txt` + 两臂各一套 `traj.svg` / `traj.csv` / `by_segment.csv`（本轮合计约 26 MB，落在已 gitignore 的 `artifacts/` 下，不打扰 git status）。
5. 铁律照旧：**一次只改一个变量**；「改了没反应」先查**键名 / 钳位链 / 消费者**三件事，再下结论 —— §3.1 就是这条的教材。

## 0. 一分钟上手

```powershell
cd dzrobot_v2
python tools/sim_lab/run_experiments.py --list      # 15 个实验一览（实验号 / 被测键 / A→B / 想问什么）
python tools/sim_lab/run_experiments.py --exp cruise_speed_up
python tools/sim_lab/run_experiments.py --all       # 全部（实测 23 秒）
python tools/sim_lab/run_experiments.py --guide     # 怎么跑 / 看什么 / 判据（长说明）
```

跑一个实验后看三处（按优先级）：

| 看什么 | 在哪 | 为什么先看它 |
|---|---|---|
| ★ 一句话结论 | `artifacts/sim_lab/<实验>/report.txt` 底部 | 从**实测数**算出来的（不是模板话），一句话给出「旧→新」 |
| 指标全表 | 同一份 report.txt | 带 ★ 的行是本实验该看的；其余行是「顺带还发生了什么」 |
| 两张轨迹图 | 两臂目录下的 `traj.svg`（浏览器直接打开） | 文字表永远替代不了「拐角到底切没切」；两张并排看 |

> 门槛：**跑得动 `python -m dzbrain.tools.sim_cli` 的机器就能跑本实验室**（不 import rclpy、不碰车、不写 `config/robot.yaml`）。Windows 控制台必须是 UTF-8：本工具会自动把 `PYTHONIOENCODING=utf-8` 传给子进程，你自己手敲 `sim_cli` 时也要设，否则 `★` 与 `↔` 会让 GBK 控制台抛 `UnicodeEncodeError`。

## 2. 判据、退出码与三条纪律

### 2.1 三种 expect（写在 `tools/sim_lab/catalog.py` 的每个实验里）

| expect | 要求 | 用来教什么 | 判失败的典型原因 |
|---|---|---|---|
| `change` | 观测指标里**至少一个**变 | 「这个键确实被代码读到了」 | 键名拼错（点号键与 SCHEMA 不符 → `cfg.get()` 返回 None）；被钳位链吃掉；两臂命令其实一样 |
| `same` | 观测指标**逐位相同** | 「改了没反应」也是有信息量的结论 | 模型里混进了随机源；这次改动顺带带动了别的键 |
| `obs_only` | 轨迹/时长/误差逐位不变，**只有**观测指标变 | 「指标变了 ≠ 车行为变了」 | 只观测的边界被打破（例如有人把观测量接进了控制） |

判据实现：`tools/sim_lab/runner.py:310`（`check_expectation`）；「两臂能不能横比」的独立守卫在 `tools/sim_lab/runner.py:262`（`comparability_note`）。

### 2.2 退出码

| 码 | 含义 | 现场处置 |
|---|---|---|
| 0 | 全部实验：每臂退出码 0 + 产物 3/3 非空 + 判据成立 | 可以引用结论 |
| 2 | 用法 / 环境问题（实验号写错、`sim_cli` 起不来） | 看 stderr 提示，改命令 |
| 3 | 有实验**判据不成立** | **别急着报 bug**：先按 §2.1 最后一列排查，多半是键名或钳位 |
| 4 | 有实验**没跑完**（退出码非 0 / 产物缺失或空） | 先修仿真或输入，任何结论都不算 |

### 2.3 三条纪律

1. **两臂之间不许顺手改别的**：`--set` 只给被测那一个键；注入类实验（延迟/噪声/里程）走 `sim_cli` 的专用开关（`sim_cli.py:65` `--latency`、`sim_cli.py:73` `--pos-noise`、`sim_cli.py:67` `--speed-scale-err`）。
2. **不写磁盘**：所有改值只影响本次运行（`--set` 的实现见 `sim_cli.py:143` `_apply_overrides`，「只影响本次运行，不写磁盘」）。真要改车上参数走 12 的流程。
3. **结论只写实测数**：本实验室禁止占位数字 —— 报告里每个数都来自那一次 `SIM_RESULT_JSON` 行（契约见 `sim_cli.py:262`）。

### 2.4 判据自检（--selftest）：先证明判据会判错

判据最容易写成「永远返回 True」（比较写错变量、容差写成无穷大），于是实验室永远绿、永远没人发现问题。所以判据自己也得被测：

```powershell
python tools/sim_lab/run_experiments.py --selftest
```

它用 9 个**合成用例**（不跑仿真、毫秒级）把判据钉住：change 两臂相同→**必失败**、change 两臂不同→必通过、same 两臂相同→必通过、same 两臂不同→**必失败**、obs_only 只动观测→必通过、obs_only 轨迹也动→**必失败**、两臂都跑完→不打旗、B 臂发散→**必打旗**、结论里必须出现实测数。2026-10-29 实测 **9/9 OK、退出码 0**。

## 3. 三个最值钱的实测

### 3.1 零差异实验：前视下限 0.36→0.18，一个数都没动

| 观测指标 | A 默认 0.36 | B 改 0.18 | 结论 |
|---|---|---|---|
| 横向RMS | 0.1187 m | 0.1187 m | 逐位相同 |
| 横向MAX | 0.6818 m | 0.6818 m | 逐位相同 |
| 总时长 | 118.12 s | 118.12 s | 逐位相同 |
| 舵角速率P95 | 20.3 °/s | 20.3 °/s | 逐位相同 |

**为什么**：前视距离 = `clamp(k_v × |v|, [min, max])`，实现见 `core/config.py:917-922`。当前 `lookahead_k_v=1.2`（`config/robot.yaml:627`）、`cruise_speed_mps=0.35`（`config/robot.yaml:629`）⇒ `1.2×0.35=0.42`；这个值已经**被上限 0.40 钳住**（`config/robot.yaml:626`），`min` 只在 `ld` 低于它时才起作用 ⇒ 把 min 从 0.36 改到 0.18 对结果**零影响**。

**教学点**：这就是「改了没反应」的正确解释路径 —— 不是「这个参数没用」，而是「它的作用区间没被碰到」。顺带对照 `lookahead_max` 那条：改上限（0.40→0.22）**立刻有反应**（横向RMS 0.1187→0.1108 m、越界拍 74→55），因为 `ld` 变成 `clamp(0.42, [0.36, 0.22]) = 0.36`，被**下限**接住了。

### 3.2 指标变了 ≠ 车行为变了：越界拍 74→212，而轨迹逐位不变

`map_safety_margin_m` 从 0.60（`config/robot.yaml:637`）收到 0.30：

| 指标 | A 0.60 | B 0.30 |
|---|---|---|
| 越界拍数 | 74 拍 | **212 拍**（+186.5%） |
| 总时长 / 横向RMS / 横向MAX / 末点误差 | 118.12 s / 0.1187 m / 0.6818 m / 0.0300 m | **完全一样** |
| 控制拍数 | 5906 | **5906** |

**为什么**：这个键只进 `tools/sim.py:954` 的越界判定统计，**不参与控制**（`tools/sim.py` 头注的硬约束：场地要素「只观测、不改动力学」）。所以 B 臂的车走的是**同一条轨迹**，只是判定尺子变严了。

**教学点**：看到「越界拍涨了 186%」就以为「车跑坏了」是典型误读。**先问这个指标是控制量还是观测量** —— 观测量变了，车一点没变。

### 3.3 未跑完的对比不能横比：延迟 0.26 s「RMS 更好」是假象

| 指标 | A 延迟 0.06 s | B 延迟 0.26 s | 表面读法 | 真实含义 |
|---|---|---|---|---|
| 横向RMS | 0.1187 m | **0.0695 m**（-41.5%） | 「延迟有益」？ | B 臂只跑了 **4476 拍**就判**发散** |
| 总时长 | 118.12 s | 89.52 s（-24.2%） | 「更快」？ | 不是更快，是**没跑完** |
| 控制拍数 | 5906 | 4476 | — | 少跑了 1430 拍 |
| 跑完全程 | 是 | **否** | — | 判据一票否决 |
| 末点误差 | 0.0300 m | **5.2287 m** | — | 停在离终点 5 米外 |

**为什么会有这种假象**：横向RMS 与总时长都是「**越跑越差**」的累计指标。臂早停 ⇒ 样本更少 ⇒ 累计值天然更漂亮。这就是 `tools/sim_lab/runner.py:262` 的 `comparability_note` 存在的理由：只要两臂的 `completed` / `diverged` 不一致，报告就会打旗 **[⚠ 未跑完·不可横比]**，并把「早停会让累计指标变好看」写在结论下面。

### 3.4 本轮 6/15 的 B 臂跑不完（这不是 bug，是结论本身）

| 实验 | A 臂拍数 | B 臂拍数 | B 臂判发散 |
|---|---|---|---|
| max_steer_deg（30°→20°） | 5906 | 5267 | 是 |
| curvature_gain（1.0→0.5） | 5906 | 5653 | 是 |
| wheelbase（0.157→0.25） | 5906 | 5263 | 是 |
| mileage_no_anchor（ε=+18% 且关锚定） | 5906 | 3005 | 是 |
| latency（0.06→0.26 s） | 5906 | 4476 | 是 |
| pos_noise（0→0.05 m/拍） | 5906 | 2194 | 是 |

**怎么读**：「跑不完」在仿真里的含义是**投影/推进判据失效**（`tools/sim.py` 头注「投影/推进的四个关键修正」）。它比「误差大一点」严厉得多，也更接近实车的真实失败形态 —— 现场「车卡在拐角不动了」往往就是这一类。**所以这 6 条结论只能写成「这组参数/这个注入下跑不完」，不能写成「误差从 A 涨到 B」。**

## 5. 与既有工具的分工（为什么这不是第二个轮子）

| 工具 | 回答什么问题 | 不该拿它干什么 |
|---|---|---|
| `python -m dzbrain.tools.sim_cli` | 「这一组参数跑出什么指标」（单次） | 不会告诉你「两臂差在哪」——要自己抄数对比 |
| `tools/sim_param_sweep.py` | 「哪个参数组最优」（扫一组格子、**进程内** `run_sim`） | 只给一张表、不落逐臂产物、不判「该不该变」 |
| **`tools/sim_lab/`（本篇）** | 「改一个键，**我该看见什么**」+ 判据 + 逐臂产物 + 人话结论 | 不扫参、不找最优、不改磁盘配置 |
| `tools/route_check.py` | 路线是否合法（6 层校验） | 与参数无关 |
| [12_可调参数速查_按场景](12_可调参数速查_按场景.md) | 「改哪个键 / 改了会不会生效」 | 不给仿真实测数字 |

一句话：**sim_cli 是引擎，sim_lab 是实验台**。实验台只调用引擎（子进程 + `SIM_RESULT_JSON` 契约），不重写仿真 —— 这也是为什么 `sim_lab` 里没有一行物理。

## 7. 边界：仿真绿 ≠ 实车绿

`tools/sim.py` 头注（`tools/sim.py:108-113`）写得很直白，照抄三条最容易被忽略的：

1. **本仿真不建模 PIVOT**（原地转向状态机在 `tasks/tracker.py`）⇒ `pivot_*` 全部键在本实验室里**恒为 no-op**，别用它验证原地转。
2. **不建模 ALIGN / 最终限速 / Safety 强停** ⇒ 「仿真里跑完了」不代表实车不会被安全层拦下。
3. `cross_track_*` 的直段值恒为 0.0000（信念无误差 + 粘性投影 ⇒ 直段逐位贴线），**误差全部集中在拐角**；本图的横向峰值主要在 `A2` 顶点（打开 `by_segment.csv` 按峰值列排序即可看到）。

另外：仿真结论**不能替代** G1 配置自检（`python tools/config_selfcheck.py`）与 `route_check`，也不能替代实车 bench。
