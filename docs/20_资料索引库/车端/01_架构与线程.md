# 车端架构与八线程

## TL;DR（给 agent 看的）
- **一个 python 进程，八个任务线程**（不是八个 ROS 节点）：`python3 -u -m dzbrain.main`；底盘/云台/裁判/检测是另外 4 个 C++ 节点。
- 三条「唯一性」是设计骨架：**只有 TrackerTask 写底盘指令**、**只有 SafetyTask 能强制停车**、**只有 LocalizationTask 写 `P_POSE`**。
- 线程间不发 ROS 话题，只走黑盒（blackboard）+ 事件；跨进程（车↔无人机↔地面）才走 `/dzlink/*`。
- 最大坑：黑盒 `get()` 缺键**静默返回 SCHEMA 默认且不记 default-used**，删一个键不会报错，只会让行为悄悄变。

## 1. 八线程（频率逐条已核对源码）

| # | 类 | 频率 | 职责 | 证据（文件:行） |
|---|---|---:|---|---|
| 1 | `LocalizationTask` | 20 Hz | `/odom` → 投影/吸附 → 写 `P_POSE`、`P_ODOM_AGE`、漂移计 | `tasks/localization.py:162` |
| 2 | `SafetyTask` | 20 Hz | 五道看门狗 → `SAFE_STOP`；唯一强制停车者 | `tasks/safety.py:56` |
| 3 | `TrackerTask` | 50 Hz | 投影 → 纯追踪/PIVOT/倒车 → **唯一** `/pursuitAngle` 发布者 | `tasks/tracker.py:126` |
| 4 | `MissionTask` | 10 Hz | 阶段机（WAIT_INFO/PLAN/DRIVE/STOP/SHOOT…）、停站、路线装载 | `tasks/mission.py:1482` |
| 5 | `AimTask` | 50 Hz | 云台瞄准 + 开火判据 | `tasks/aim.py:514` |
| 6 | `FixTask` | 10 Hz | 尺度/系统误差估计（**不改位姿**） | `tasks/fix.py:90` |
| 7 | `DroneTask` | 5 Hz | `/dzlink/*` 收发、情报/布局采纳与 ack | `tasks/drone.py:534` |
| 8 | `TelemetryTask` | 2 Hz | 遥测快照（只读全黑盒） | `tasks/telemetry.py:212` |

注册即启动顺序：`main.py:1691-1699`（核心四线程 → aim → fix → drone → telemetry）；`SafetyTask` 额外拿 `group` 才能看别人心跳（`main.py:1684-1688`）。

## 2. 唯一性契约（违反即不可归因）

| 契约 | 实现位置 | 为什么必须唯一 |
|---|---|---|
| 底盘指令只由 Tracker 写 | `tasks/tracker.py` `publish_command()` | 两处写 `/pursuitAngle` ⇒ 现场「收到了但不动」（`cam_viewer` 20 Hz 发全零） |
| 强制停车只由 Safety 写 | `tasks/safety.py` | 谁都能急停 = 谁都不负责；Safety 非 OK 时必须仍刹车 |
| `P_POSE` 只由 Localization 写 | `tasks/localization.py` | 多处写位姿会互相覆盖，漂移归因失效 |
| 路线只由 Mission 装 | `tasks/mission.py` `_load_tokens()` | 外部 `/nav/waypoint` 与自规划共用同一入口才有单点闸 |

## 3. 黑盒（blackboard）

- 键语义与默认值只在 `config/` SCHEMA 定义一次，其余 `import`（常量单一真源）。
- **已知缺陷**：`Config.get()` 缺键返回 SCHEMA 默认且不记 `default-used`（`docs/library/流程与架构.md`「黑盒」节）。删 `pivot_penalty` 会静默变 0 ⇒ PIVOT 变「免费」，规划器行为漂移而无人发现。
- 事件总线只承载「一次性通知」（布局采纳、段完成、到点）；持续状态一律用黑盒键。

## 4. 四个 C++ 节点（colcon 编译，独立进程）

| 包 | 可执行 | 职责 | 坑 |
|---|---|---|---|
| `dzactuator` | `dzactuator_node` | 底盘串口：轮速/电压/IMU/云台负载上行 34 B | 上行**无电流**；`current_vel_state` 只是命令回显（D-029） |
| `dzrknn_dataprocess` | **也叫 `dzactuator_node`** | 云台 PID + 开火判据 | 与底盘包**同名可执行**，只能靠包名区分 |
| `dzjudgment` | — | 裁判串口 + 激光 | `/LaserShot_Command` 订阅数必须 = 1 |
| `rknn_pt` | `det_node` | RKNN 检测 → `/offset_center` | 必须 `draw:false`（无 X 时 GTK 崩，D-003） |

## 5. 数据流一行版

`/odom` → Localization(20Hz) 投影/吸附 → 黑盒 `P_POSE` → Mission(10Hz) 依 `P_ROUTE_S`/停站决定阶段 → Tracker(50Hz) 算 `/pursuitAngle` → Safety(20Hz) 网关（必要时覆盖为 0）→ 底盘节点 → 串口。

- 规划在 Mission 线程内**同步**调用（`planner` / `plan_route`）⇒ 阻塞该线程，「规划耗时」直接表现为阶段切换延迟。
- 自动规划默认**关**：`planner.auto_plan_enabled: false`（`dzrobot_v2/config/robot.yaml:777`）；路线来自无人机 `/nav/waypoint` 或 `route.tokens` 兜底。

## 6. 运行模式（决定「谁发路线」）

| 模式 | 谁给路线 | 关键开关 | 证据 |
|---|---|---|---|
| 常规 | `route.tokens`（仓库兜底 68 token） | 默认 | `robot.yaml` `route.tokens` |
| 自动规划 | 进程内 `planner` | `planner.auto_plan_enabled`（现 false） | `robot.yaml:777` |
| StepLoop 布局 | 无人机布局 → 逐段规划 → 执行 → 回报 | `cfg.override("mission.auto_start", False)` | `main.py:2080-2082` |
| bench | 立即出发 | `auto_start=True`、`delay=0.3` | `main.py:1798-1799` |

> StepLoop 下**必须**关 `auto_start`，否则车会在没有布局时按旧路线自己走（`main.py:2080` 注释原文）。

## 7. 起栈

- 车端 `~/dzrobot/start_all.sh` 七步；`start` / `stop` / `restart` 三个子命令。
- 若 `auto_start=true`，起栈后**默认 10 s 自行出发**——现场必须先确认路线再起栈。
- 改路线/速度必须 `start_all.sh restart`：`restart_node.sh path` 指向**旧核**（只重启节点，不换二进制）。
- 非交互 SSH 默认 `ROS_DOMAIN_ID=0`，必须 source `dzros.env`（域号 118），否则「全通但互相看不见且零报错」。
