# 外部资料 · 03 yb_精度对照_0x4002

## TL;DR（给 agent 看的）

- **这是什么**：外部成员（yb 队）给无人机 0x4002 车位姿帧（车 x, y, yaw）做的**精度对照采集方案**，目的是回答「0x4002 能不能用于动态重规划和打击时机判断」。
- **一句话结论**：现状 0x4002 **只用于发车前 align**、精度从未量化；方案用「已知格子+已知朝向」的真值做对照，实测约 **25 分钟**、72 组；判定标准事先定死三档（能用 / 只能 align / 不能用）。
- **关键数字**：采集矩阵 9 格 × 4 朝向 × 2 高度 ≈ 72 组；每姿态悬停 10 s（约 50 帧）；判定阈值 yaw P95 ≤ 10° 且位置 P95 ≤ 0.15 m 才算「能用」；> 20° 判「不能用」。
- **最大坑**：真值零成本的前提是「格子是现成的坐标系、朝向用场地胶带线/格线对齐」，但**无人机两个高度档要规则允许变高**；顺光/逆光各一轮会再翻倍。
- **与本项目关系**：本地 0x4002 的用途与口径见 空地链路/01（本地侧 0x4002 是 hjy 的二进制帧，非本地 JSON 部署线）。

## 2. 原理与采集矩阵

| 项 | 内容 |
|---|---|
| 目的 | 量化 0x4002 帧（车 x, y, yaw）的估计精度，回答「能否用于动态重规划与打击时机判断」 |
| 真值 | 车摆在**已知格子 + 已知朝向**（人工真值）；格子是现成坐标系，朝向用场地胶带线/格线对齐 |
| 位置 | 9 个代表格：场地四角、中心、挡板两侧贴边格、桥洞 K 列邻近格、最远离无人机悬停点的一格 |
| 朝向 | 每格 4 个（0°/90°/180°/270°），车头用格线对齐，误差控制在 **±2°** 内 |
| 每姿态 | 悬停采 10 秒（约 50 帧 0x4002），**记录全部帧而不是均值**——看抖动 |
| 变量 | 无人机两个高度档（若规则允许变高）、顺光/逆光各一轮 |
| 总计 | 9 格 × 4 朝向 × 2 高度 ≈ 72 组，每组 10 秒——**实测约 25 分钟** |

## 3. 执行方式（两步走）

1. **桌面粗测（当天就能做，不用飞）**：
   - 用 tools/capture_dataset_local.py 手持 AR0234 在车的模型/真车上方拍视频（模拟下视视角）；
   - 用机载 onboard/dzuav 的**离线视频模式**跑这段视频（main.cpp 支持视频文件输入），收集它打印的 car_pose 输出；
   - 粗测能发现「红色方向标记在 X 米外就认不出来」这类硬限制。
2. **飞行实测（联调日）**：无人机悬停，按采集矩阵走一遍。

## 4. 记录格式与判定标准（事先定死）

每组一行 CSV（runs/car_pose_probe/record.csv）：

    cell,true_yaw_deg,altitude,light,n_frames,x_err_mean_m,x_err_p95_m,y_err_mean_m,y_err_p95_m,yaw_err_mean_deg,yaw_err_p95_deg
    K5,90,high,good,48,0.08,0.15,0.06,0.12,4.2,9.5

| 档位 | 判据 | 结论 |
|---|---|---|
| **能用** | yaw 误差 P95 ≤ 10° 且位置误差 P95 ≤ 0.15 m | 0x4002 可用于动态重规划 |
| **只能 align** | yaw P95 ≤ 20° 但距离远了超差 | 维持现状只用于发车前对齐 |
| **不能用** | P95 超 20° | align 也得换方案（回到纯 serial_reader 航位推算 + 机械校准则） |

产出：docs/probe/car_pose_accuracy-YYYYMMDD.md（数据 + 结论 + 是否扩大用途的建议）。（0x4002精度对照采集方案.md:30-47〔未入库〕）
