# 外部资料 · 01 成员交接_hjy_自瞄设计（TargetAimer）

## TL;DR（给 agent 看的）

- **这是什么**：外部成员「胡锦宇（hjy）」全工程交接包里，车端 dzmission 的云台瞄准+激光打击模块 TargetAimer（src/target_aimer.cpp 约 60 KB）的设计档案。它是本项目车端演进线（dzbrain v3.x）的**直系前身**，不是可整包替换的实现。
- **一句话结论**：TargetAimer = 六态状态机（伺服层）+ 五类联锁（安全层）+ 移动靶三方案（α/β/γ 预判层）；α 已落地且量化达标（残余 3.0 cm < 靶半径 4.5 cm），β/γ 未做；其 380 ms 延迟拆解是本项目「瞄准只补 0.26~0.27 s」之外另一套 380 ms 口径的**外部旁证**。
- **最大坑**：own_gimbal=false —— 交接时云台/激光**实际由 dzrknn_dataprocess 驱动**，dzmission 只做联锁监视，两者若同时发 CameMo_Conl/LaserShot_Command 会指令打架；且 dzrknn_dataprocess **无红蓝联锁**（会误打友方）。
- **与本项目关系**：决策台账 D-001 已裁决**不整包替换，只移植开火判据（α/β）**；车端/09 已收其协议层，本篇补它没收的自瞄细节。

## 2. TargetAimer 三层拆解

| 层 | 内容 | 关键数字 | 来源（tar 内成员）〔未入库〕 |
|---|---|---|---|
| **层 1 伺服状态机** | IDLE → SCANNING → TRACKING → ALIGNED → FIRING → COOLDOWN | 六态；云台限速 **70.3 °/s**（standoff=1 时 72.0 °/s）；全局限 10 发 | 00_交接文档.md:412,444-446 |
| **层 2 安全联锁** | 红蓝面（require_blue_face/face_unknown_policy）、弹药、被击、射程、激光红点 | fire_cooldown_ms 默认 **3000 ms**（学员版用 500 ms，语义待确认）；max_local_shots 10；默认**未知面禁火** | 00_交接文档.md:414-436；方案评审与代码优化建议.md:307-318 |
| **层 3 移动靶预判** | 方案 α（换向点开火）/ β（匀速提前量）/ γ（感应区精瞄+自适应） | α 已实施；β 三标定量 lead_servo_ms/lead_fire_ms/lead_exposure_ms | MOVING_TARGET_PLAN.md:214-225,383-422〔未入库〕 |

> 层 2 的红蓝门是**本赛题最关键的安全约束**：靶标双面、朝向随机，车端相机只看到朝向自己的那面；误打友方扣 5 分/次，且友方计数到 3（6 次误击）会让**整个靶标失效**，那 15 分也拿不到（方案评审与代码优化建议.md:304-306〔未入库〕）。

## 3. α / β / γ 判据

| 方案 | 判据（怎么决定开火） | 关键数字 | 状态 |
|---|---|---|---|
| **α** | 只在靶标**经过画面中心且速度≈0（换向点）**时开火；用**中值滤波（3 帧）**估速 + 方向反转判据 + 开火窗口 | 窗口 **100 ms**；残余 **3.0 cm** < 靶半径 4.5 cm；不补偿时 11.7 cm，**降 74%** | ✅ 已实施并量化达标 |
| **β** | 在 α 上加匀速运动预测 + 穿越时刻预测 + 提前量补偿 + 红点补偿判据；换向点保留为兜底 | T_total = 380 ms；每 fire_cooldown 3 s 一发；6 次命中估 20~30 s | 🔲 未实施（依赖 target_period_s 真值） |
| **γ** | β + 感应区圆判据 + 自适应微调 + 裁判板交叉验证 | 感应区几何规则**没给**，需现场测 | 🔲 暂缓 |

**α 开发中被数据否定的两个设计**（都是坑）：
1. 一阶低通（α=0.35）**不可用**：真实速度 t=800 ms 过零时估计值仍有 66.8 px/s → 真换向一次都没识别（可开火帧 0/60）→ 残余 7.1 cm > 半径；改**中值滤波**后残余 7.1 → 5.9 cm。
2. 开火窗口 250 ms **太大** → 残余 5.9 cm 超限；收到 **100 ms** 后降到 3.0 cm。
（MOVING_TARGET_PLAN.md:301-321〔未入库〕）

**standoff 最终取 1 格**：不能太近（omega = v/d ≤ 70.3 °/s）与不能太远（轨道可能贴边界，车与轨道之间只有 1 格空间）两侧夹逼；1 格时运动段角速度 72.0 °/s **仅超 2%**，且 α 只在换向点开火天然缓解，故取 1（MOVING_TARGET_PLAN.md:323-352〔未入库〕）。

## 4. 380 ms 延迟推导

    T_total = 380 ms = 33 采集 + 267 流水线 + 60 控制 + 20 执行

- 视觉流水线 **4 帧 @ 15 fps = 267 ms**；靶标若 0.2 m/s，267 ms 内移动 **5.3 cm**，已接近靶径 8~10 cm。
- 靶速按旧固件反推 **0.44 m/s** 时，267 ms 内位移 = 0.44 × 0.267 = **11.7 cm** **> 靶径** → 不做提前量必然打偏。
- 补偿后残余 **3.0 cm < 靶半径** → 可命中。
（00_交接文档.md:439-441,959〔未入库〕；MOVING_TARGET_PLAN.md:281-286〔未入库〕）

> 口径提醒：本篇 380 ms 是 hjy 侧的**全链端到端**口径（采集→流水线→控制→执行）；本项目「瞄准只补 0.26~0.27 s」是**视觉流水线**口径（车端册 11 §5.1）。两者不可混用。

## 5. own_gimbal=false 的实证缺口

- 实配 params/dzmission.yaml 中 aim.own_gimbal: false（00_交接文档.md:753,919〔未入库〕）。
- false 的含义：云台与激光**仍由 dzrknn_dataprocess 驱动**，dzmission 只做联锁判断与状态监视（不发 CameMo_Conl/LaserShot_Command）；true 才由 dzmission 自己驱动，此时**不要**启动 dzrknn_dataprocess。
- **实证缺口**（吸收决策与待验证清单-20261018.md:35,75〔未入库〕）：
  1. dzrknn_dataprocess 是学员原版，**无红蓝联锁** → 一旦由它驱动云台开火，会打友方（扣分）。
  2. 「要全权驱动」需同时：① 改 own_gimbal: true；② 屏蔽 dzrknn_dataprocess 的云台/激光发布（其发布前判断共 3 处，见 INTEGRATION.md:116-129〔未入库〕）。
  3. 演进线云台/激光驱动权归属（dzbrain vs dzrknn_dataprocess）未确认 → 列为**待验证 V11**。
- 另一个相关坑：**车完全静止时 pose_valid_ 恒 false → 持续 ESTOP**（定位补偿的位移门槛 dr_min_step_m=0.5mm 只在检测到有效位移时置位），离线测试假传感器必须制造微小位移（--idle-v 0.05，每 tick 1.0 mm）（00_交接文档.md:386-394,707〔未入库〕）。

## 7. 三条最容易踩的坑

1. **低通滤波平滑速度**：过零点滞后 66.8 px/s，换向识别 0/60 → 用中值滤波。
2. **开火窗口贪大**：250 ms 窗口让靶标重新加速，残余回到 5.9 cm → 收到 100 ms。
3. **云台双写者**：own_gimbal=false 时 dzrknn_dataprocess 与 TargetAimer 功能重叠，二者**不能同时**发布云台/激光话题。
