# 11 · 文档纪律细则

> 起因：文档分散在根 `docs/`、`dzrobot_v2/docs/`、`dzsmartscout/docs/`、`_tmp_session/*` 等 8 处共 583 篇，同一结论三个版本，找一篇要全仓搜。本规为一次性收口后的常驻规则。
> 根 `AGENTS.md` 只留「存放地 / 禁止 / 索引义务」三条硬判断 + 指针，全部操作细则在本篇。

## 11.1 唯一存放地

**所有长期文档只能存在 `v1/docs/` 一处**，其它任何目录不得新增长期文档。

| 库 | 位置 | 放什么 |
|---|---|---|
| 项目总览 | docs/00_项目总览/ | 项目是什么、现状快照、系统架构、时间线、团队分工 |
| agent 提示词 | docs/10_agent提示词/ | 一页纸、提示词模板、角色/场景提示词、发送指南、回报模板 |
| 资料索引库 | docs/20_资料索引库/ | **项目百科全书**：车端 / 无人机 / 空地链路 / 视觉与云台 / 赛事与治理 / 历史；带数字速查表、症状索引、坑库 |
| 任务卡库 | docs/30_任务卡库/ | **作业台**：领卡 → 在卡内写报告 → 整卡归档 |
| 旧文归档 | docs/history_cache/01_旧文档归档/ | 迁移前原文，只读，按原路径保留，不再维护 |

- 已废止的落盘点：根 `docs/` 旧文、`dzrobot_v2/docs/`、`dzsmartscout/docs/`、`_tmp_session/*` 里的报告——**只出不进**。
- **例外**（被门禁工具机器读取的活文件，**必须留在原路径**）：`dzrobot_v2/docs/` 下 `决策台账.md`、`复用清单.md`、`工作流v2.md`、`目录索引.md`、`目录索引.json`、`索引标注.yaml`、`能力索引.md`、`TEAM_STATUS.md` 共 8 个。依据：`tools/wf/check.py:31-35`（REQUIRED_DOCS）、`tools/wf/repo_index.py:13`（注解源 `索引标注.yaml`）、`tools/wf/check_reuse.py:22`（复用清单/能力索引）。正文收敛为「指针 + 现行结论」，细则在 `docs/20_资料索引库/`。

## 11.2 存入三步（缺一不可）

1. **先通读**：把要存入的原文**完整读一遍**（不是只看标题、不是只 grep 片段），确认它讲什么、结论是什么、哪些已过期。
2. **再定归属**：按「主题 + 生命周期」定库；**同一主题只留一篇现行**，被取代的旧文在 `docs/history_cache/01_旧文档归档/` 留档并写「取代者」。
3. **必要时拆开存**：一篇里混了多个主题就**拆成多篇**分别入对应库；拆完在原文件写「已拆为 X/Y/Z」。

## 11.3 禁止项

- 同一内容两处各存一份（副本即债）；
- 只搬标题不写结论（索引里必须有一句话结论 + 关键数字 + 来源）；
- 把 `_tmp_session` 的原始过程稿直接搬进库（**必须先提炼**，原文留 `_tmp_session/` 或 `history_cache/`）；
- 新增文档不登记索引（未登记 = 下次找不到 = 等于没写）。

## 11.4 索引义务（三层，缺一层就白写）

1. **册级索引**：新文档必须在所属分册的 `00_索引.md` 加一行（标题 / 一句话结论 / 关键数字 / 来源）。
2. **全库索引**：跑 `python docs/_工具/gen_index.py` 重新生成 `docs/目录索引.md`（自动读 front matter 与 TL;DR，**不要手改**）。任何一次收口/归档后必须重跑。**多会话并行时用 `gen_index.py --ns <ns>`**，只重扫自己前缀、保留外部索引行（见 §12.8）。
3. **入口索引**：根入口只有一个 `docs/README.md`；新会话先读它，再由它分流到四库。

## 11.5 任务卡怎么用（作业台口径）

- **领卡**：从 `docs/30_任务卡库/在办/<ns>/` 选本 ns 的卡（**只碰自己的 ns**）→ 在卡面 `owner` 填自己 → `status` 改 `in_progress`。
- **在卡里写**：执行记录、命令输出、结论、证据全部**追加进同一张卡**，不要另起 REPORT.md（卡就是报告）。
- **归档**：`status` 改 `已归档` + 写结论判定（通过/失败/撤销）→ 先按 §12.5 落点提炼并写反向指针 → 文件移到 `docs/30_任务卡库/归档/<ns>/YYYY-MM-DD_<卡号>.md`（**按 ns 分层，平铺 = R9 红**）→ 更新归档索引与 `目录索引`。
- **历史归档命名**：`归档/_按日摘要/<日期>.md`（4 篇）是 10-21 前 24 张卡的**按日合并摘要**，不是卡面；逐卡精读见 `归档/00_索引.md`。**10-22 起新归档一律 `归档/<ns>/YYYY-MM-DD_<卡号>.md`，一卡一文件**。
- **失败也归档**，不许删卡：失败卡是最贵的教材。

## 11.6 文档守卫（机器判红 · 命令）

命令（在 v1 根）：`python docs/_工具/check_doc_policy.py` —— 退出码 1 = 有红线，不许收口。

| 红线 | 含义 | 解法 |
|---|---|---|
| **R1 库外新增 .md** | 不在 `docs/` 白名单、也不在基线里 | 移进对应库；确属代码仓自带 → `--accept <path> --reason "..."` 登记（写进 accept_log，可事后审） |
| **R2 docs 下开新库** | `docs/` 下出现白名单外的目录 | 先改 `docs/_工具/doc_policy.json`（唯一真源），说明为什么需要新库 |
| **R3 库内写了没登记** | 没进 `目录索引.json` | 跑 `python docs/_工具/gen_index.py` |

- **白名单/基线**：`docs/_工具/doc_policy.json` + `doc_policy_baseline.json`。基线记录当前库外**受管** .md，语义是**只减不增**——新增一篇库外文档必须显式 `--accept`，没有"顺手放一下"。
- **豁免区**（不进基线、只计数）：`_tmp_session/`、`backup/`、`_archive/`、`git_save/`、`dzrobot_v2/src/history/`、`artifacts/`、`docs/history_cache/`、第三方源码（mavros / px4_msgs / livox / FAST_LIO / vendor）。**豁免区里写"长期文档"同样违规**，由月度审计抓。
- **顺序**：写卡（含 §11.8 文档变更）→ `gen_index.py` → `check_doc_policy.py` → `check_anchors.py` → `check_numbers.py` → `cd dzrobot_v2 && python tools/wf/check.py` → `cd dzrobot_v2 && python tools/wf/check_links.py`。

### 11.6.1 守卫清单（全部只读、秒级）

| 守卫 | 命令 | 判据 |
|---|---|---|
| check_anchors.py | python docs/_工具/check_anchors.py | 正文里 4.6k 条 `路径:行号` 是否还指向真代码，**只对新增红判失败**（存量进 `anchor_baseline.json`，只减不增） |
| check_numbers.py | python docs/_工具/check_numbers.py | 拿 `20_资料索引库/数字速查.yaml` 的 52 条数字去代码里重算，**默认只报不判红**（`--strict` 才挡） |
| Y10 | 并入 check_doc_policy.py | 归档卡正文必须有「经验总结」段，至少含「现象」+「处置」；缺段或缺要素 = Y10 黄 |

## 11.7 生命周期（front matter status）

- **知识库（00 / 10 / 20）每篇必须有** `status: 现行|计划|历史|过程`；任务卡库（30）用卡自己的 status（pending / in_progress / 已归档），不套文档 status。
- 语义：**现行**=当结论用；**计划**=还没落地，引用必须标"计划"；**历史**=只作沿革、不作判据；**过程**=过程稿（尽量别放库内，放 `_tmp_session/`）。
- **过期**：`status: 现行` 且 `更新` 超 180 天 → 守卫提醒"过期候选"。复核后二选一：改内容并更新日期，或降级为 `历史` 并写 `取代: <新篇>`。
- 判"该降级"三信号：结论被新证据推翻 / 对应代码已删除或重写 / 同主题已有更新的一篇。

## 11.8 卡面必须有「文档变更」

- 每张卡 §10 写：本次**新增 / 修改 / 归档**了哪几篇（没有就写「无」）。没有这一行的卡不算收口。
- 这是防"文档只在会话里存在"的最后一环：卡归档时，能一眼看出它动了哪些文档、有没有漏登记。

## 11.9 月度审计（每月 1 号，或每次大收口后）

五件事，缺一不算审完：
1. 跑 `check_doc_policy.py`，红线必须为 0；
2. 抽查豁免区：`_tmp_session` 里有多少"报告"该提炼进库、`backup` 体积有没有失控；
3. 数"现行"里超 180 天的过期候选，逐条决定改/降级；
4. 指标写进 `docs/TEAM_STATUS.md`：库内篇数 / 库外受管篇数 / 红线数 / 过期候选数 / 断链数。**指标不降 = 维护断了。**
5. 打一个文档快照：`python docs/_工具/snapshot_docs.py`（zip 落 `_archive/docs_snapshots/`，保留最近 12 个）。这是 10-22 外部删除事故后的兜底——文档被误删/覆盖时从这里回滚，别指望会话记忆。

## 11.10 什么算「乱拉屎」（出现即返工）

- 在代码仓新建 README / 说明 / 报告（应进 `docs/`，或写成卡）；
- 在 `_tmp_session` 写"报告"当交付（是过程稿，必须提炼进库）；
- 新建 `docs2/`、`docs_new/`、`doc/` 等平行目录；
- 把原始过程稿整篇搬进库（必须提炼 + 写结论）；
- 写了文档不登记索引；
- 用"以后补登记"换时间（`--accept` 会记 accept_log，理由必须写实）。
