# 工作流与铁律

## TL;DR（给 agent 看的）

- 动手前读**四个真源**：决策台账 / 复用清单 / 目录索引 / 工作流 v2。
- **六条铁律**：先查账 · 先复用 · 冻结区不碰 · 写域独占 · 证不出来=没完成 · 一次只改一个变量。
- **收口门禁** `python tools/wf/check.py` 有三条判红：**冻结区未登记 / 文档断链 / 新增 .py 未登记**（另有缺 frozen.json、缺必备文档两条结构性红）。
- **门禁 ≠ 回归**：check.py **不跑** test_*.py；发车另有 G1~G4 + 全量回归门（见 [05](05_已知红与回归口径.md)）。
- **文档纪律 §8**（2026-10-21 起）：长期文档只存 v1/docs/ 一处；先通读→再定归属→必要时拆开存；三层索引缺一层等于没写。
- **文档守卫 §8.6**（2026-10-22 起，机器判红）：`python docs/_工具/check_doc_policy.py` 三条红线——**库外新增 .md / docs 下开新库 / 库内写了没登记**；库外基线**只减不增**。

## 2. 六条铁律（原文 AGENTS.md §1）

| # | 铁律 | 落到动作 |
|---|---|---|
| 1 | **先查账，再动手** | 已裁决不得重开；重开答三问（新证据/影响面/代价），结论写回台账 |
| 2 | **先复用，再造轮子** | 复用清单 → 能力索引 → 目录索引；确需新建，卡里写「为什么现有不够」 |
| 3 | **冻结区不碰** | src/dzbrain/dzbrain/** 、src/dzrknn_dataprocess/** 、config/** 、tools/deploy_to_car.py；实验进 _tmp_session 或 feature flag |
| 4 | **写域独占** | 一卡一写域；同一文件同时只一个 owner；共享文件（robot.yaml、目录索引、AGENTS.md）单写者 + 评审 |
| 5 | **证不出来 = 没完成** | 交付带可复跑命令 + 关键输出 + 回滚点 + 影响面；只说「已修复」不算 |
| 6 | **一次只改一个变量** | 一轮一个假设；连续 2 轮无提升即停并写清停因 |

## 3. 收口门禁：check.py 的三条判红（实）

命令（在 dzrobot_v2/ 下）：`python tools/wf/check.py`

| 判红项 | 代码位置 | 含义 |
|---|---|---|
| **冻结区有未登记脏文件** | check.py:145 | 必须登记进 tools/wf/frozen.json 的 in_flight，且 card/owner/expires 齐全、未过期；**无 owner = 红** |
| **文档断链** | check.py:103（调 check_links.py） | 覆盖 docs/** 与 src/history/INDEX；断链 = 文档与真源漂移 |
| **新增 .py 未登记** | check.py:120（调 check_reuse.py） | tools/ 与 src/dzbrain/dzbrain/ 下新增 .py 必须在复用清单或能力索引登记；存量只警告 |
| （结构性）缺 frozen.json | check.py:85 | 门禁配置缺失直接判红 |
| （结构性）缺必备文档 | check.py:90 | REQUIRED_DOCS 清单 |

⚠️ **门禁 GREEN 只说明工作流合规，不是回归绿、更不是实车通过**（TEAM_STATUS.md:50 原句）。

## 4. 发车门禁（与收口门禁是两件事）

**发车 = G1 ∧ G2 ∧ G3 ∧ G4 全绿 ∧ 全量回归 0 非零退出**；G5 是记录项〔档 发车门禁口径.md §0〕。

| 门 | 命令（dzrobot_v2/ 下） | 判据 |
|---|---|---|
| **G1** 配置+路线自检（桥洞正确性真源） | python tools/config_selfcheck.py --config config/robot.yaml --map config/map.yaml | exit 0 ∧ 结论行 error 0 ∧ 配置层 warn 0 ∧ 路线层（validate_route）0/0 |
| **G2** 路线全链路 | python tools/route_check.py --config config/robot.yaml | exit 0 ∧ FAIL=0 ∧ WARN ⊆ W1（W1 仅「急转弯」） |
| **G3** 页面 == 车端 | node dsh-plugin-dzrobot-ssh/scripts/test-sim-parity.mjs | 26/26 全绿（逐 token 相等 + 反证成立） |
| **G4** 插件守卫 | 5 个 test-sim-*.mjs / test-package-files.mjs | 61/61、30/30、21/21、31/31、PASSED，五个 exit 0 |
| 回归门 | python _run_full_regression.py | 套数 = 当次 test_*.py 文件数，且非零退出 0（现行基线见 05） |

**两条最容易混的口径**（发车门禁口径.md §0）：
1. 判据单位是 **error/warn 分类**，不是退出码 0（route_check.py:1228-1245 只在 FAIL 时 rc=1）。
2. **G1 的 warn 与 G2 的 warn 是两套程序、不可互相豁免**；G1 的 0/0 不能证明 W1 不存在，反之亦然。

## 6. 冻结闸与实验纪律

- **正式改动**：挂卡 → 写 frozen.json 的 in_flight → 跑回归 → **人工部署**（D-007/D-019）→ 解除登记。
- **实验改动**：**不许进冻结区**；放 _tmp_session/<卡号>/ 或用 feature flag，**默认值不动**。
- 过期登记 = 收口闸红；不允许无限期挂着。
- 部署唯一常规入口 = tools/deploy_to_car.py（D-019）；deploy_car.py 只读诊断，--write 仅现场应急且需 Lead 授权。

## 7. 什么算「开倒车」（禁例，AGENTS.md §6）

1. 重新论证已裁决的事（先看台账）；
2. 已有工具/能力索引入口还另写一个；
3. 新建前不查复用清单、不登记，事后补「说明」；
4. **信号本身坏时调参数**（先证被控对象）——D-024 据此否掉了「调 PID 救画圆」那类做法；
5. 直接改冻结区默认值做实验；
6. 报告只写「已修复/已优化」，无复跑命令与输出；
7. 一回合改多个变量，说不清哪条起作用。

## 8. 文档纪律（2026-10-21 起，全员强制）

| 条款 | 内容 |
|---|---|
| 8.1 唯一存放地 | 长期文档只存 v1/docs/：00_项目总览 / 10_agent提示词 / 20_资料索引库 / 30_任务卡库 / history_cache（历史留存，只读） |
| 8.1 例外 | 被 check.py 机器读取的活文件留在 dzrobot_v2/docs/：决策台账、复用清单、目录索引.*、能力索引、TEAM_STATUS |
| 8.2 存入三步 | ①先通读（完整读，不看标题就塞）②再定归属（一主题一篇现行）③必要时拆开存 |
| 8.3 禁止项 | 同内容两处各存（副本即债）/ 只搬标题不写结论 / 把 _tmp_session 过程稿直接搬进库 / 新增不登记索引 |
| 8.4 三层索引 | 册级 00_索引.md → 全库 docs/目录索引.md（跑 docs/_工具/gen_index.py 生成，不手改）→ 入口 docs/README.md |
| 8.5 任务卡库 | 卡即报告：在卡内追加执行记录/命令输出/结论/证据，不另起 REPORT.md |
| 8.6 文档守卫 | 机器判红：库外新增 .md / docs 下开新库 / 库内写了没登记；配置真源 `docs/_工具/doc_policy.json`（AGENTS.md §8.6） |
| 8.7 生命周期 | 知识库每篇 `status: 现行\|计划\|历史\|过程`；"现行"超 180 天提醒复核（AGENTS.md §8.7） |
| 8.8 卡面文档变更 | 每张卡 §10 写本次新增/修改/归档了哪几篇，否则不算收口（AGENTS.md §8.8） |

### 8.6 文档守卫怎么用（2026-10-22 增）

```powershell
cd D:\User\Desktop\比赛存档\v1
python docs\_工具\check_doc_policy.py                 # 体检；退出码 1 = 有红线
python docs\_工具\check_doc_policy.py --json          # 机器读
python docs\_工具\gen_index.py                        # 写库里新文档后先跑这个
python docs\_工具\check_doc_policy.py --accept <path> --reason "为什么可以留在库外"
```

- **受管范围**：除豁免区外的全部 `.md`（当前库内 74 / 库外受管 70 / 只读 118 / 豁免 57 / 第三方 102）。
- **基线只减不增**：库外受管文档在 `doc_policy_baseline.json` 里；出现基线外的新文件即红。确认是代码仓自带文档才 `--accept`，理由写实，`accept_log` 留痕。
- **实测**：造一个 `dzrobot_v2/docs2/x.md` → 守卫立刻 R1 判红；删掉 → GREEN。规则不是靠自觉。
