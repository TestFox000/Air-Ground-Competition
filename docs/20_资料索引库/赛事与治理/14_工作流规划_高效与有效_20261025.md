# 14 · 工作流规划：怎么排才高效、怎么验才有效

> 本篇回答两个问题：一轮工作怎么排（效率），一件活怎么算做完（有效性）。

> 依据：Claude Code / OpenAI Codex / Google Antigravity 官方实践 + AgentLens「假通过」论文（10.7%）+ 本项目 10-03 至 10-25 的实测。

## 14.1 一轮工作的固定序列

已固化在根 @B@AGENTS.md@B@ §0「每轮开工六步」，不在本篇重复。要点：先查账 → 再查库 → 再动手 → 跑门禁 → 落盘 → 提炼。

## 14.2 什么时候派子智能体

| 情形 | 判据 |
|---|---|
| 该派 | 多条互不依赖的线（多目录审计、多模块改造）；单线超过 ~30 分钟且步骤可拆 |
| 不该派 | 改一行、查一个值、读一个文件；需要全局上下文做裁决的收口 |
| 派谁 | 免费/flash 路由优先；需要长上下文分析用更强的 |
| 上限 | 3–5 个并行；超过 5–6 张卡才设协调员 |

## 14.3 怎么排才高效

1. **先做「解锁」动作**：阻塞所有人的（车没摆好、相机被占、门禁红）优先，不管它看起来多小。
2. **按目录/文件切，不按功能切**：功能切会产生共享文件抢写。
3. **串行依赖链不派发**：A 出结果 B 才能做 → 串行更省（派发只增加协调开销）。
4. **危险动作先停再报告**：发车、部署、改默认值 → 做完预检停一下，等人确认。
5. **一次只改一个变量**：否则说不清哪条起作用（§1.6）。

## 14.4 怎么验才有效（对应根 §11 验收纪律）

1. **验收命令必须机器可判**：退出码 / 结构化输出 / 指标表。不接受「看起来对了」。
2. **独立验证**：干活的 agent 不自己给自己打分。
3. **端到端分级**：
   - 算法/控制 → 仿真闭环（sim_cli 退出码 + 指标表）
   - 实车链路 → 实车闭环（bench 日志 + 视频）
   - 文档/配置 → §4 对应守卫
4. **验收清单结构化**：领卡时填全（全 false），收口时逐项勾。事后补的不算。
5. **门禁 GREEN ≠ 回归绿 ≠ 实车通过**：三件事三套判据，别混。

## 14.5 度量（每轮收口看）

| 指标 | 目标 | 抓手 |
|---|---|---|
| 新增红（台账外失败套件数） | 0 | 全量回归逐套表 |
| 台账翻案次数 | 每 5 轮 ≤1 | 决策台账 |
| 同能力重复实现数 | 0 | 能力索引 |
| 冻结区未登记脏文件数 | 0 | check.py |
| 文档红线数 | 0 | check_doc_policy.py |
| 「现行」过期候选数 | 逐条处置 | check_doc_policy.py |
| 验收清单事后补填数 | 0 | 卡面验收区 |

## 14.6 什么时候停

- 连续 2 轮无提升 → 停，写清停因（§1.6）。
- 需要现场/需要用户动作 → 挂 @B@⏸@B@，写清下一步和阻塞项。
- 证不出来 → 不算完成（§1.5），如实标「未验证」。

## 14.7 规则的升级路径

- 新规则先按**黄线**跑满一轮零告警，再转**红线**（2026-10-23 Y6~Y8 → R7~R9 即此路径）。
- 理由：新规则一上线就判红，会把存量噪音混进真实问题（Y10 对 10-22~10-24 归档卡误报 12 条即此教训）。
