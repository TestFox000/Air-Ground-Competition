# 13 · 提交与双远端同步细则

> **用户指令（2026-10-25 晚 · 二次修订）**：**本地 commit 由用户决定**；**远端推送一律由用户下令**——agent **不主动提交、不主动推送、不自设推送时间表**，只做提醒。本篇以下流程**只在用户明确下令后**执行。（决策台账 D-044 推翻 D-043）

> 本篇是 §2/§4/§5 的补充：不改变既有提交粒度与收口门禁；两者冲突时以本篇的双远端要求为准。

## 13.1 触发条件（"可以推送了"的定义）

- **用户下令**：用户明确说「推送」时触发，按 §13.3 六步执行（含可能的本地 commit）。**agent 不自设推送时间表、不主动推送**；
- 一张任务卡、或一项独立修复**通过规定检查**（§4 收口门禁 + 卡面验收命令）后，agent **只提醒**：报告改动摘要 + 门禁结果 + 建议的 commit 行，然后等指令；
- 每次保存文件、写草稿、跑一次测试 **不触发**，也无需提醒；
- 结论未定 / 待复核 / 门禁未过 → 不提交，**且不得报「可提交」**。

## 13.2 固定同步目标（勿擅自增删、勿覆盖）

| 远端名 | URL | 说明 |
|---|---|---|
| @B@github@B@ | https://github.com/TestFox000/Air-Ground-Competition.git | 主远端 |
| @B@gitee@B@ | https://gitee.com/yubinghuan_1/air_ground.git | 备远端 |

- @B@origin@B@（TestFox000/v2.0）与 @B@public@B@（本地裸库 public_v1.git）**保持原状**，不删、不改 URL；
- **嵌套仓 @B@dzrobot_v2@B@**：v1 之外的独立仓库（被 v1 @B@.gitignore@B@ 忽略），唯一远端 @B@origin@B@ = https://gitee.com/circle-of-joy/air_ground.git；commit / 推送**同样只等用户指令**。判「未推」先 @B@git -C dzrobot_v2 branch -vv@B@ 核对该仓自己的上游，**勿套用 v1 的 origin/main 口径**（两仓 origin 指向不同远端）；
- 分支：沿用项目约定（工作区 main；跨机协作惯用 agents/<name>/<topic>）。**没有明确约定时先问用户，禁止自行假定推 main/master。**

## 13.3 推送六步（缺一不可 · 仅用户下令时执行）

**触发**：用户明确说「推送」时（含可能的本地 commit）：

1. **看清差异**：@B@git status@B@ + @B@git diff@B@；**只 add 本次任务相关文件**，禁止 @B@git add .@B@，禁止把他人/其他卡未完成的改动带进提交；必要时用 @B@git commit --only <file>@B@；
2. **跑检查**：卡面验收命令 + §4 门禁（@B@gen_index.py@B@ → @B@check_doc_policy.py@B@ → @B@check_anchors.py@B@ → @B@check_numbers.py@B@ → @B@dzrobot_v2/tools/wf/check.py@B@ → @B@dzrobot_v2/tools/wf/check_links.py@B@）；失败或无法运行 → **不提交、先报告原因**；
3. **查暂存内容**：禁止提交口令/令牌/私钥/敏感配置/无关日志录像/构建产物；发现疑似凭据 → 暂停并报告位置，**不展示凭据值**；
4. **建本地 commit**：沿用现有格式 @B@<摘要> [<卡号>]@B@（例：@B@sim 测试三修：… [TOOLS-PLUGIN-REWORK-20261022]@B@）；**没有实际变更不建空提交**；
5. **双推**：@B@git push github <branch>@B@ + @B@git push gitee <branch>@B@；
6. **核对**：@B@git ls-remote <url> <branch>@B@ 两端哈希 == 本次本地提交哈希，写进汇报。

## 13.4 异常边界（硬停，先报告再等人定）

- **禁止** force push / 重写历史 / 删远端分支 / 绕过保护规则 / 覆盖他人修改；
- 冲突、非快进拒绝、认证失败、**远端分叉** → 停在该步，报告位置与原因，等用户决定；
- 一端成功一端失败 → 保留本地提交与已成功端，**只报失败端**，不重复制造提交，不宣称"双端同步完成"；重试前先核对实际远端状态；
- **推送 ≠ 部署授权**：推前检查是否触发自动部署（.github/workflows、webhook）；当前仓库无 CI 配置，推 GitHub 不触发部署；将来若新增 workflow，先报告再推；
- 不得自行改仓库可见性/访问权限/凭据。
