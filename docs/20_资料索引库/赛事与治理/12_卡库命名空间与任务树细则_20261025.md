# 12 · 卡库命名空间与任务树细则

> 起因：多会话/多团队同写一个 @B@在办/@B@，抢的不是卡文件，而是三张共享登记表（卡库 README、目录索引、归档索引）。规则靠人让路守不住 → 按会话隔离写域，用树表达"为什么开下一张卡"。

> 契约真源：@B@docs/30_任务卡库/_设计/00_命名空间与任务树.md@B@（含完整命令与判据）；ns 注册表：@B@_设计/01_ns登记.md@B@。

### 12.3.1 卡面里的路径引用（2026-10-25 增 · 锚点守卫契约）

卡面正文里写路径，锚点守卫（@B@check_anchors.py@B@）按**工作区相对路径**解析；解析不到的按「新增红」判失败。两条硬要求：

1. **一律写工作区全路径**，不写相对自己目录的短名：@B@rec/analyze.py@B@ 写成 @B@_tmp_session/<ns>/rec/analyze.py@B@；@B@7_path.log@B@ 写成它真正所在的全路径。
2. **还没产出的计划物**，在**同一行**标 @B@〔未实现〕@B@（守卫 @B@DEAD_MARKERS@B@ 前缀匹配：@B@〔未实现@B@ / @B@〔失效@B@ / @B@〔未入库@B@ / @B@〔已删@B@），否则被当成悬空路径判红。

> 为什么：2026-10-25 实测 13 条新增红**没有一条是真断链**——9 条是短名写法、4 条是计划物，全被守卫按「路径不存在」判红。写法不改，每张新卡都会贡献假红、把收口拖红。

## 12.4 树（N 叉）

- 根 = 会话目标；节点 = 一张卡或一个工作项；叶 = 已归档结论。
- 节点号 @B@A-1@B@ / @B@T21-3.1@B@；@B@[卡]@B@ 节点必须指向真实存在的卡（**R8 判**）。
- **树是单写点**：成员只在卡里写"请求新增节点 X"，由 ns owner 落树——树自己多人写就成了新的抢写点。
- 符号：@B@✔@B@ 成立 / @B@✘@B@ 否决 / @B@↻@B@ 进行中 / @B@⏸@B@ 挂起。未结项必须写 @B@⏸@B@ + 原因，不许留空。

## 12.5 收口 = 提炼（不许只写在卡里）

每张卡归档前必须三选一落点，**并写反向指针**：
1. **百科篇**（@B@20_资料索引库/**@B@）→ 在被改篇里加一行 @B@来源: <卡号>@B@；
2. **坑库/症状索引** → 加一行"症状 → 机制 → 位置"；
3. **决策台账** → 本卡对应 @B@D-xxx@B@。

没有落点的卡不许转 @B@已归档@B@（评审退回）。这是"结果和新经验必须入资料库"的机器可查形态。

## 12.8 为什么这么定（别简化掉）

- **隔离的是登记，不是卡**：卡本来一卡一文件；冲突全在 README / 目录索引 / 归档索引三张共享表。所以 @B@gen_index@B@ 必须支持增量（@B@--ns@B@），否则谁重生成谁把别人未入库的文档卷进索引（实测：一次全量重生成会带入 17 篇未提交文档）。
- **树必须单写点**：树是共享文件，多人写就变成新的抢写点。
- **收口必须双向指针**：只写在卡里 = 下次找不到 = 等于没写；只有正向（卡→篇）也会漂。
