### 12.3.1 卡面里的路径引用（2026-10-25 增 · 锚点守卫契约）

卡面正文里写路径，锚点守卫（@B@check_anchors.py@B@）按**工作区相对路径**解析；解析不到的按「新增红」判失败。两条硬要求：

1. **一律写工作区全路径**，不写相对自己目录的短名：@B@rec/analyze.py@B@ 写成 @B@_tmp_session/<ns>/rec/analyze.py@B@；@B@7_path.log@B@ 写成它真正所在的全路径。
2. **还没产出的计划物**，在**同一行**标 @B@〔未实现〕@B@（守卫 @B@DEAD_MARKERS@B@ 前缀匹配：@B@〔未实现@B@ / @B@〔失效@B@ / @B@〔未入库@B@ / @B@〔已删@B@），否则被当成悬空路径判红。

> 为什么：2026-10-25 实测 13 条新增红**没有一条是真断链**——9 条是短名写法、4 条是计划物，全被守卫按「路径不存在」判红。写法不改，每张新卡都会贡献假红、把收口拖红。

## 12.4 树（N 叉）

- 根 = 会话目标；节点 = 一张卡或一个工作项；叶 = 已归档结论。
- 节点号 @B@A-1@B@ / @B@T21-3.1@B@；@B@[卡]@B@ 节点必须指向真实存在的卡（**R8 判**）。
- **树是单写点**：成员只在卡里写"请求新增节点 X"，由 ns owner 落树——树自己多人写就成了新的抢写点。
- 符号：@B@✔@B@ 成立 / @B@✘@B@ 否决 / @B@↻@B@ 进行中 / @B@⏸@B@ 挂起。未结项必须写 @B@⏸@B@ + 原因，不许留空。

## 12.5 收口 = 提炼（不许只写在卡里）

每张卡归档前必须三选一落点，**并写反向指针**：
1. **百科篇**（@B@20_资料索引库/**@B@）→ 在被改篇里加一行 @B@来源: <卡号>@B@；
2. **坑库/症状索引** → 加一行"症状 → 机制 → 位置"；
3. **决策台账** → 本卡对应 @B@D-xxx@B@。

没有落点的卡不许转 @B@已归档@B@（评审退回）。这是"结果和新经验必须入资料库"的机器可查形态。

## 12.8 为什么这么定（别简化掉）

- **隔离的是登记，不是卡**：卡本来一卡一文件；冲突全在 README / 目录索引 / 归档索引三张共享表。所以 @B@gen_index@B@ 必须支持增量（@B@--ns@B@），否则谁重生成谁把别人未入库的文档卷进索引（实测：一次全量重生成会带入 17 篇未提交文档）。
- **树必须单写点**：树是共享文件，多人写就变成新的抢写点。
- **收口必须双向指针**：只写在卡里 = 下次找不到 = 等于没写；只有正向（卡→篇）也会漂。

## 12.10 写卡与写验收时的十九条机器可判判据（2026-11-01 增 · wb-1031 轮实战提炼）

> **为什么要写进细则**：以下十九条在 2026-10-31~11-01 那一轮里**每一条都对应至少一次真实事故**，
> 其中五条是 Lead 本人踩的、其余是成员踩的。**这一轮共抓到 3 次"门禁自身假绿"与 2 次"同形态的配置-消费者脱节"**。只留在会话里 = 下次重犯；写进细则才能被机器或下一个 reviewer 抓到。

### L1 声明面必须等于可用面
任何 `xxxSupport()` 探针、`--xxx` 开关、"报 supported" 的声明，必须有**一条负例证明"声称不支持时它真的不工作"**。
**事故**：`plannerIncrementalSupport()` 报 supported=2/2，现役 `tour` 引擎实跑 exit 2 ⇒ 页面 422，且台账记"参数已传" ⇒ 排障人误判为"传过去了只是规划无解"。

### L2 判据必须写在会变的东西之外
**可观测元数据（断言计数、文件名、探测结果）不许放进会随输入/负载变化的容器。**
**两起同构事故**：
- 超时断言写在 `if prod_timeout:` 里 ⇒ 断言总数随负载在 56/58 间浮动 —— 一个"检查项数量随负载变"的测试本身就是它要防的噪声；
- 卡面**描述**一条坏引用时把无效文件名原样抄进正文 ⇒ "描述缺陷的句子自己造了新缺陷"（WB-15 把上游卡里的一个**区间简写文件名**原样抄进正文，导致自己也变红）。

**更实用的表述（2026-11-01 06:1x 增，wb-doc 三次踩坑后提炼）**：要指别人的文件，**给路径前缀 + 目录归属**（"插件 `scripts` 下的某个 mjs"），**不给完整文件名**。
原因：踩坑的根因不是"没注意"，而是**写「证据引用」时下意识把文件名当锚点**——这是文体本能，靠自律压不住，只能靠改写法。

### L3 "跑完"必须与"走完"分开
`finished=1.0` 可在 **21/67 段没走过**时为真（实测 ideal 档 field7；49–55 是 A1 折返整段被跳）。
⇒ 任何用单一布尔/单一计数当"通过"的地方，都要问：**它能否被跳段骗过？** 判据应配覆盖率量。

### L4 对比两组数字前，先做量纲 / 集合 / 版本三重对账
- **量纲**：本轮 CSV 的 `t` 列是**秒**（span 118.198 ↔ `time_s` 118.2 吻合）。判成"毫秒+偏移"会把整段 118 s 当"前 8 s"。
- **集合**：契约行 `belief_error_rms_m=0.0` 与 CSV 复算 5.7 mm 是**两批拍子**（契约行只算 `loc_ran==1` 的 2365 拍；CSV 全部 59100 行里其余是"沿用上一帧旧信念"）。
- **条件**（2026-11-01 08:2x 补）：「某现象在条件 A 下不出现」**≠「该现象不存在」**。Lead 曾据「给地图 + `--force`」这一条件说「bench 闸门不触发」，实际在「无地图 + `--force`」条件下**必然触发**（wb-plant 实测：四情形 A/B/C/D 行为完全不同）。
- **版本**：Lead 曾据一份产物算出 `tour 17/13/56.7%` 并要人改卡面，而工作区**全部现存产物都是 20/10**，那份来自已被覆盖的旧版且**现已复现不出**。⇒ 引用任何产物先问「谁在改、我读的是哪版、会被覆盖吗」。

### L5 结论必须能自证，不能只写"我没改"
「我没碰那个文件」要配**可复跑命令**（如 `sha256sum` 与 preimage 对拍）。
**同族**：只跑"不带开关→没写"无法排除"代码根本没写盘能力"，必须**剔除守卫再跑一次**才能证明开关真在拦（WB-10 的 4b）。

### L6 单侧断言 = 半个判据（**带一条例外**）
**对枚举/连续量的"某值为 X"断言，必须配一条"换输入后它不为 X"的反向断言。**
两起实证：
- `--variant` 只断一处通路 ⇒ 变异测试不红（另一处 `variant=args.variant` 还在）；
- `end_seg_reached` 长跑断言恒为 1.0 ⇒ 把源码硬编码成 1.0 时 **164/164 仍全过**；补"短跑对照（末段必然到不了）"后同一变异**立刻红 1 条**。

⚠️ **例外（2026-11-01 06:1x 增，wb-doc 提）**：对**恒真量**——`field_modeled` 的 0/1、schema 号、键集相等——**不需要反向断言**。
它们取值域有限，反向断言等于把同一句写两遍，只会**稀释信号**。
⇒ L6 真正要防的是**枚举/连续量上的"某值"断言**（`route_coverage` / `pivot_count` / `end_seg_reached` 这类）。

### L7 变异与负例必须"能区分"
**植入变异或构造负例前，先证明该样本在"两种假设下会给出不同结果"。**
样本本身不足以区分时，该变异/负例无效——**它不是在测判据，是在走流程**。
两起实证（都是造的人自己抓的）：
- **伪负例**：用"回退式 patch"造负例，`replace` 命中了 docstring 里那行 `return` 而不是函数体 ⇒ 负例文件语法坏掉、仍返回原值 ⇒ 判据没变红。正解：**直接用 preimage 原始字节**当负例；
- **伪变异**：挑到一份只有 8 s 的产物，于是"8 秒"与"8000 ms"两种窗口都等于"全留" ⇒ 变异方向测不出。正解：**按跨度挑样本**（优先 >20 s）+ 判据改成"等于总行数"。

### L8 生产代码里的"已知风险注释"不是证据
`tasks/mission.py:3221` 的注释**自述**了投影跳段坑（"s 从 3.50 冲到 4.20 时 #11/#12/#13 三个从未走过的点被默默判成已到达"），写得比台架早得多。
但**只有台架能在它上面跑出一条红的断言，它才成为证据**。
⇒ **"注释里写了"从来不能算"已验证"**；这正是 D-063 判据①存在的理由。

### L9 过严与过宽同罪
判据既可能"把坏的说成好"（**假绿**），也可能"把好的说成坏"（**假红**）。
**两者都让判据失真；后者还会让人去修一个不存在的问题**，比假绿更费人力。
实证：
- **假红**①：把"CLI 没有引擎门"也归进 `engines=[]` ⇒ 判 blocked，等于把可用面判小；
- **假红**②：测试断言全过但尾段抛栈 ⇒ `pass=0/fail=0` 却 `rc=1`（应当 catch 计入 fail，不许绕过汇总）。

### L10 观测链本身也要被验证
任何"**植入-还原 / 快照-复原 / 生成-比对**"的往复操作，必须能用**独立量**（如 `sha256`）证明它真的回到了原状。**"回到原状"不能靠"看起来一样"。**
实证：
- 用 Python 做"植入→还原"，`open(...,'w')` 在 Windows 默认 LF→CRLF ⇒ 内容看着没变、字节变了；**若没要求报 sha256，"还原失败"会伪装成"通过"**；
- 生成器报"30/30 成功"而 Python `glob` 返回 0 ⇒ **空集合 == 空集合会被误判成"逐位一致 PASS"**。判据：比对前必须断言 `len(files) > 0`。
- **第二次实证（2026-11-01 08:0x，Lead 本人踩）**：把一份临时配置写到 shell 的临时目录下，bash(MSYS) 解析成一个 Windows 临时路径、Python 看到的是另一个 ⇒ `Config.load` 报「配置文件不存在」。
  ⚠️ **最危险的地方**是：那看起来像"被测对象报错"，差点被误判成被测代码的缺陷（实际是路径不存在）。
  ⇒ **写临时文件必须用同一个进程/同一条路径语义**（`os.path.abspath` 后同进程用）；**跨 bash/Python 传临时目录路径会让"文件不存在"伪装成"被测对象报错"**。

### L11 当使用者开始"绕开结构"时，先怀疑结构
出现"把 N 个值塞进 1 个字符串"这类写法，通常不是使用者懒，是**容器语义与真实世界不符**。
实证：`frozen.json` 的 `in_flight` 用 dict（同 path 只留最后一条），于是有人把 5 个卡号拼进一个 `card` 字段（`"AIM-LAT-20261022 + SHOOT-LINK-... + WB-7-..."`）来绕开覆盖。**修使用者的写法没用，要修容器。**

### L12 删除配置键之前，必须先删/改读它的代码
**"删了被读的键、没删读它的代码"**会让配置从"有效"变成"无效且日志说谎"。
判据：`grep` 该键名，**任何仍在读它的分支都必须同步处置**。
实证（两次同形）：
- `route.tokens` / `path_executor` / `mission_blocks` 随 NOLEGACY 一起删，但 `mission.py:2797/2842` 两条分支仍在读 `route.tokens` ⇒ "打开 fallback"与"关掉 auto_plan"两条**逃生门通向同一堵墙**，且日志先打印「回退并继续出发」再崩；
- WB-14 的 `barrier_row_hi/lo`：地图声明了、但 `validate.py:225`/`route_check.py:698` 读的是 `geometry` 常量。
⇒ 配置与消费者之间**没有编译期约束**，只能靠 grep + 断言。

### L13 退出码是「有预算的公开契约」
**新增或复用退出码前必须做三件事**：① 全仓 `grep` 该码有无占用；② 进官方表（头注释）；③ 配一个**可区分的归因字段**。
**"字面唯一"不等于"语义唯一"**。

**实证**：`main.py` 头注释的退出码表只到 **6**；实际 `7` 被**两个分支**返回——
- `:3209` `return 7`（开火联锁 `fire_interlock_refused`）
- `:3070` `return EXIT_ENGINE_COMBO`（常量=7，危险配置闸门）

⇒ `grep "return 7"` 只命中一处（开火联锁），**但运行时两者都返回 7** ⇒ 只靠 rc 无法区分。正解：`rc + report["reason"]` 双判据，并断言**两分支都写 reason**，否则未来新增第三个 `return 7` 忘写就再也分不开。

### L14 「缺失」不是「等于某个替代值」
当某个量当前是"空的 / 未配置的"（且**空是合法状态**），把它替换成一个"看起来像的样本"，会让所有以它为基准的判据从 SKIP 变成**假通过或假红**。

**实证**：把"车端无路线（布局模式，合法）"改成"车端路线 = 夹具路线"⇒ `test-sim-parity` 的「页面 == 车端」对账从「无对账对象 ⇒ SKIP」变成「拿夹具冒充车端 ⇒ **假红**」（22/25 → 3 FAIL）。
**正确做法**：保留"空"这一独立状态（`carRoute: []`），替代值**另立字段**（`route: <夹具>`）。

### L15 降级跳过会掩盖下游缺陷
**任何"因为前置缺失而跳过"的分支，都是一片未测区。**
修好前置时，必须把那片区域的测试一并补上，否则它只是**从"静默跳过"变成"静默崩溃"**。

**实证**：`fieldSpec()` 从恒 `ok:false` 变为 `ok:true` ⇒ `test-intel-route` 的 `if(spec.ok)` 分支**第一次被执行** ⇒ 里面 `readFileSync(已删的 MAP_FILE)` 抛 ENOENT。同一根因还藏着第二处：`runSimJob` 的 override 分支也读同一文件——**修好前置才暴露它**。

### L16 改源码做变异试验，本身需要 guard
变异实验会**故意把源码改坏**；若清理不可靠（异常中断 / 编码问题 / 脚本中途崩溃），就会**把坏状态的源码留在工作树**。

**要求**：`try/finally` + **双重 `sha256` 核对**（植入前一次、还原后一次）+ 子进程显式 `encoding`。
**"还原了"必须由独立量证明，不能靠"流程跑完了"。**

**实证**：WB-18 第一版变异脚本把还原放在末尾，中途被 Windows `GBK` 编码异常打断 ⇒ `main.py` 一度停在 `if False and ...` 短路状态，**闸门静默失效**。而 **41 条单测全绿**（它们测的是纯函数）——这正是 L1「声明面≠可用面」的极端形态。
是好的一面也在：**另一个成员只读巡检先发现**（只报事实不指控），随即还原。

### L17 `git status` 说脏 ≠ 内容脏
判"文件有没有真改"**必须同时看 blob sha**（`git hash-object` / `git ls-files -s`）。
只看 `git status` 会把 **index 的 stat 缓存失配**误判成内容改动 —— **不是看不到，是看错了方向**。

**实证**：插件根下那个 168 KB 的单页面板归一为 LF 后 `blob == HEAD`、`git diff` 空、`git diff --cached` 空，**但 `git status` 仍报 `M`**；唯一线索是 `git ls-files --debug` 里 `size: 168668`（归一前）vs 实际 `165901`。`git update-index --refresh` / `--really-refresh` 在 `core.autocrlf=true` 下都清不掉；`git read-tree HEAD` 只重置 stat 缓存、不碰工作树、不丢暂存（执行前后 `git diff --cached` 均为空可证）。

**为什么这条重要**：`git status` 是本项目所有「归属判定」与「有没有改」判据的第一手工具。**它会说谎 ⇒ 上游判据全要加压。**

### L18 恒真式是「零网」假绿
**恒真断言**（`and True or True`、自己拼的等价表达式、永真的集合比较）是**最隐蔽的假绿**：
- 跑起来绿、`PASS` 计数正常、**评审只看汇总也挑不出**；
- 它**绕过了所有自动化网** —— 机器只会问「断言是否通过」，**不会问「它是否可能不通过」**。

⇒ **唯一可能的发现方式**：① 作者主动问「它可能是假的吗」（**不独立**）；② **变异植入后它是否变红**（**这才是真网**）。

⇒ **判据：每条断言必须能被至少一次变异打红。**（wb-net 的变异敏感度正是这条的机器形态。）

**实证（2026-11-01，wb-plant）**：它在 WB-21 里写过 `4.6` 恒真表达式与 `6.4` 的 `and True or True`，**只有作者自读能发现**（当时没有任何自动化网覆盖）。同一卡里它做了「拆闸后 5b.3/5b.5 精确变红，而 5.1~5.4/5b.1/5b.2 错误变红 = []」——**那就是这条判据的执行**，只是当时没给它命名。

### L19 卡面状态与结构化字段必须同源
卡面（人读）与 `update_task` 的结构化字段（机器读）说反话时，**人会信卡面** —— 因为它更详细、带证据列。
⇒ 于是「没做的部分」会被读成「做完了」。

**交付前自查动作（这条是可执行的，不是原则）**：**逐行比对「字段里那一条的状态」与「卡面那一行的状态」**，不许只看自己刚改的那几行。

**实证（2026-11-01，WB-6）**：
- `update_task` 报 `#4 逐拍回放` / `#6 双臂并排` / `#8 删 dronesim` 共 **3 条 failed**；
- 卡面同一张表却把 #4/#6 写成 `PASS（数据层+UI）`、#8 写成 `PASS（界面诚实）`；
- Lead 靠 `grep` 页面控件只抓到 **#4/#6 两条**，**#8 是实现者通读自己写的 9 行才发现**。

⇒ **教训：逐条 grep 只能验证"我怀疑的那一条"，通读全表才能发现"我没怀疑的那一条"。**
