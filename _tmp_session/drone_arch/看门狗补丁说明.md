## 1. 行为变化（旧 → 新）

| 场景 | 旧版 | 新版 |
|---|---|---|
| 设备不在 | `continue`，不重启（只打健康行） | `DEVICE_OFFLINE`，不重启，告警降频（默认 300 s） |
| 遥测正常 | ONLINE，30 s 健康行 | 同左，健康行**显式带状态** `状态=ONLINE` |
| 遥测静默 > 15 s | 重启 agent，冷却 60 s，**无限循环** | `RECOVERING`，重启并计轮次，日志带 `（第 N/3 轮）` |
| **连续 3 轮重启后仍 0 帧** | **继续每 61 s 重启，永远** | **→ `FC_OFFLINE`：停止重启；只每 300 s 告警一次"需给飞控断电重启"** |
| FC_OFFLINE 下设备消失又出现 | —（没有此状态） | 视为"已断电重启"，复位计数器，重新允许自动恢复 |
| FC_OFFLINE 下收到遥测 | — | 自动解除 → ONLINE，日志 `FC_OFFLINE 解除` |
| Agent 进程消失 | 拉起 | 拉起，且计入轮次（防止"agent 崩溃循环"被当成健康） |
| 拉起 agent 的域号 | 继承当前 shell（cron 下 = 未设 = 0） | **显式转发本进程 `ROS_DOMAIN_ID`**；未设时启动日志直接告警 |
| 健康行内容 | `健康: 串口在 Agent活 遥测静默60s 重启7次`（看起来像在工作） | `健康: 状态=ONLINE ...` / `[需人工] 状态=FC_OFFLINE ...`（不再伪装存活） |

**核心效果**：死循环从"每 61 s 一次、无限"收敛为"最多 3 轮（约 3 min）后停手 + 每 5 min 一条明确告警"。

## 2. 新参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--max-dead-rounds` | **3** | 连续多少轮"重启后仍 0 帧"转 FC_OFFLINE；`0` = 永不放弃（旧行为，兼容用） |
| `--offline-warn-period` | **300** s | FC_OFFLINE / DEVICE_OFFLINE 下的告警间隔（降频，避免刷日志） |
| `--health-period` | 30 s | ONLINE / RECOVERING 健康行间隔（新增，原来是硬编码 30 s） |
| `--silence-sec` / `--cooldown` / `--check-every` / `--device` / `--restart-once` | 同旧版 | 不变 |

## 7. 与域号切换的耦合（重要）

- 补丁让 agent **继承看门狗的域号**。若按《域号切换单_118》执行，agent 会随看门狗自动落 118，不需要额外改 agent 启动行；
- 但**看门狗自己必须在 118**（靠 `autostart_agup.sh` 的 export）；否则会出现"看门狗 0 / agent 118"——看门狗永远收不到遥测，**3 轮后误报 FC_OFFLINE**；
- 启动日志已加域号打印与"未设置"告警，部署后第一眼就能看出这个问题。

## 8. 已知边界 / 未验证

1. 未在真实 ROS 环境跑过 `rclpy` 路径（自测用替身）；`QoSProfile(depth=5, best_effort)` 订阅行为与旧版完全一致，未改。
2. "3 轮 ≈ 3 min" 是按 `cooldown=60` + `silence=15` 推的；若现场改 `cooldown`，轮次时长随之变化。
3. FC_OFFLINE 只**停止自动重启**，不主动 `pkill` 当前 agent（保留进程便于现场看日志）；如需彻底静默，现场手工 `pkill -f "MicroXRCEAgent serial"`。
4. 设备"消失 1 次即复位"依赖 `os.path.exists` 轮询（2 s 一次）；USB 极短抖动（<2 s）可能漏检——影响仅是晚一轮进入 FC_OFFLINE。
5. 未改 `--restart-once` 的语义（仍是一键重启后退出），但会带上当前域号。
