## 0. 30 秒用法（队长只需给四要素）

```
给我：① 目标（一句话：要什么结果） ② 验收（怎么算做完） ③ 时间预算 ④ 推荐人选（可选，不给就我推荐）
我回：一张填满的任务卡（objective / inScope / outOfScope / acceptance / verify / kind / 边界 / 风险）
队长批准 → 才下发（create_task / reassign_task 是队长的动作，不是我的）
```

我**只**做三件事：① 吃透目标；② 把工作包装成结构化任务卡供队长批准；③ 队长被用户抽调时，接手其半成品工作重新包装。
我**不**做技术实现，**不**自行建任务，**不**直接指挥成员开工（解锁由调度器/队长决定）。

### A.2 结构化（最终目标 / 四层 / 硬约束）

**G（最终目标）**：无人机用摄像头读到场地**全局态势**（网格 / 雷 / 障 / 靶 / 车 / 桥顶标识），把态势变成协议报文，经空地 DDS 链路指挥小车 `dzbrain` 完赛（U 形赛道：N10 → 下桥洞 → 绕隔板 → 压雷避障打靶 → 上桥洞 → N5）。

**L1–L4（本阶段要落地的四层）**

| 层 | 内容 | 被谁实现 | 完成的判据（可判定） |
|---|---|---|---|
| **L1 感知** | 无人机摄像头读：网格格名 / 雷 / 障 / 靶 / 车（位姿）/ 桥顶标识 | t1（可行性）、t2（管线） | 像素 → 格名（A1..N11，格距 0.35 m）→ 五类目标的**结构化输出**；有确定性单测；真实图跑通并如实记录"哪些能检/哪些不能" |
| **L2 通信** | DDS 双通道：`/dzlink/drone_to_car`（情报）+ `/nav/waypoint`（路线），双向 | t3（常驻节点）、t4（真机验证） | 两端 `ROS_DOMAIN_ID=118` 下，车侧订阅端**实测收到**（原始输出+时间戳）；车栈保持冷态时用只读探针模拟并**如实标注** |
| **L3 协议** | JSON 报文：`heartbeat` / `bridge_passable{half,block,confidence}` / `target_zone{blocks}` / `field_verify{mines,obstacles}` + 车→机 `car_state`/`ack` | t2（发）、t3（转发）、t5（文档） | 报文字段与车侧解析器**逐字段一致**（真源：`dzrobot_v2/src/dzbrain/dzbrain/tasks/drone.py`）；QoS 与车侧 `io/contract.py` 声明一致 |
| **L4 车侧执行** | `dzbrain` 消费情报：桥洞情报 → 选穿洞格；靶区/雷障 → 核对告警 | t6（接线）、t7（审查）、t5（E2E） | 情报新鲜 → 换洞生效；过期/离线 → 回落默认**且行为与接线前一致**；三场景测试全绿；29 套回归 = 27 绿 + 2 红台账 |

**C（硬约束）**

1. **不发车**：不动车、不启动小车 ROS 栈、不推进任何"上路"验证。
2. **不改车上配置**：`config/*.yaml` 一个字节都不碰（含"顺手对齐默认值"）。
3. **验证只走三条路**：离线单测/仿真（本机 Windows 可跑）→ 台架 → **只读**真机探针（探针只落 `/tmp`）。
4. **本阶段不飞**：无人机侧同理——不启动有执行能力的飞控链（见 §D.2）。

### A.3 明确不在本阶段范围（防止范围蔓延）

| 不做的 | 为什么 |
|---|---|

| 真机摄像头标定（外参/内参） | 摄像头未插（`/dev/video*` 为空），硬件决策待用户（见 §F） |

> ★ **`kind` 选择的硬规则（2026-10-12 队长口述 + 我用历史卡实测归纳）**：
> **`kind=review` 只能挂"被审对象是 `implementation` / `repair` 卡"的场合。

> **写卡时的自查句**：先问"被审/被复核的那张卡是什么 kind？"——不是 implementation/repair 就**不要**写 `kind=review`。

**kind 选择规则**：写代码→`implementation`（必填 `acceptanceResults` + `commandsRun` + `changedPaths`）；审别人的代码→`review`（必须给 `verdict`；`needs_revision`/`reject` 必须 `fail` 并给 `findings`）；只读评估/文档/真机探针→`work`；E2E 拼装→`integration`（`acceptanceResults`+`commandsRun`）。

> **本手册相对原文的增量**（实读得出，派发时必须一并给存档员）：§I.2 可照抄命令、§I.4 版本口径的**判定真源与陷阱**、§I.6 三条现状（镜像落后 / 工作树脏 / gitignore 覆盖）、§I.7 六条验收判据。

| # | 要素 | 内容 |
|---|---|---|

### I.2 照抄命令（工作目录 = `D:\User\Desktop\比赛存档\v1\dzrobot_v2`；PowerShell）

**Step 0 · 存档前取证（原始输出必须贴进报告）**

```powershell
Set-Location 'D:\User\Desktop\比赛存档\v1\dzrobot_v2'
git status --short | Measure-Object -Line   # 脏路径数快照（本手册实测 51 = 41 M + 10 ??）
git log --oneline -1                        # 实测应 = d2e4da1 v1.1_多线程构造完毕（★ 注意：该标签是历史存档，不是主线版本）
git tag -l 'v2.*' --sort=-v:refname         # ★ 版本口径真源：系列内最大 = v2.4 ⇒ 下一版 v2.5（§I.4）
git -C backup\dzrobot_v2.git show-ref       # ★ 推前对账：--mirror 会 prune 目标端独有 ref
```

**Step 1 · 归纳要点（只读四源，见 §I.3）** ⇒ 得一句话要点，例：`空地指挥链路感知层落地`

**Step 2 · commit**

```powershell
git add -A
git status --short | Measure-Object -Line   # 复核：不应出现 backup/、_tmp_session/（已忽略，见 §I.6③）
git commit -m "v2.5_<一句话要点>"            # 历史风格：commit 标题与 tag 名同名（v2.4_…、v1.1_…）
git log --oneline -1
```

> 工作树若已干净 → `nothing to commit`：**只打标签**，并在报告里写明「本次为纯打标签，无新提交」。

**Step 3 · tag（用 annotated，对齐最近一次 `v1.1_多线程构造完毕`）**

```powershell
git tag -a v2.5_<一句话要点> -m "<一句话要点>"
# 可选：-m 之后再补 body 分条要点（v1.1 tag 的既有做法：subject「v1.1: …」+ body 分层要点 + 变更规模）
git tag -l 'v2.*' --sort=-v:refname         # 第一行应为 v2.5_<一句话要点>（系列内最大 = 新标签）
```

**Step 4 · mirror push（目标 = 本地裸库，**必须用路径形式**）**

```powershell
git push --mirror backup\dzrobot_v2.git
git -C backup\dzrobot_v2.git show-ref        # 应出现 refs/tags/v2.5_…，refs/heads/master 前移到新 HEAD
git -C backup\dzrobot_v2.git cat-file -t <新HEAD短sha>   # 非空 ⇒ 对象确已入镜像
```

> ⚠️ 本仓库 **未配置任何 remote**（`git remote -v` 为空，实测）⇒ 写成 `git push --mirror origin` 会失败；**唯一正确目标 = 路径 `backup\dzrobot_v2.git`**。

**Step 5 · bundle + verify**

```powershell
git bundle create backup\dzrobot_v2-v2.5_<一句话要点>.bundle --all
git bundle verify backup\dzrobot_v2-v2.5_<一句话要点>.bundle      # 期望 ok
# 强校验（既有做法已验证 clone 可恢复）：
git clone --quiet backup\dzrobot_v2-v2.5_<一句话要点>.bundle "$env:TEMP\bundlecheck"
git -C "$env:TEMP\bundlecheck" rev-parse "HEAD^{tree}"
git rev-parse "HEAD^{tree}"                  # ★ 两值必须一致
Remove-Item -Recurse -Force "$env:TEMP\bundlecheck"
```

> `git bundle create` **会覆盖同名文件** ⇒ bundle 名必须带版本号，历史 bundle（现存 5 个）一律保留。

### I.4 版本口径（④ 的判定真源）★★ **已按用户澄清更正**
