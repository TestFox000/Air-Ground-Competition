# 标靶锁定增强补丁说明 — 2026-10-17

> 现象：车上识别到标靶后，云台不能很好地锁定标靶进行瞄准（在靶附近反复点头、锁不死；锁上后也容易"锁一下就丢"；移动靶基本打不中）。
> 本补丁分两期，覆盖"锁定"到"打中"全链路：
> **一期（C++ 伺服层 5 项修复）**：动量抑制 / px_per_tick 换算真源 / 延迟补偿 / 死区钳位 / 丢帧微找——治"识别到却锁不住"（§一~§四）。
> **二期（移动靶运动预测器）**：target_motion_predictor.py 挂载式节点，用实测运动模型（匀速 3.4s 单程/端停 0.2s/周期 7.2s）做超前瞄准与开火决策——治"锁住了也打不中移动靶"（§五）。
> 所有修改**默认参数下行为可回退**（`momentum_comp_on: false` + `micro_search_on: false` + 预测器 `enable: false` 即完全恢复旧行为）。

## 一、根因分析（按严重性排序）

### 根因 1【最致命】：SCAN→TRACK 切换瞬间的"动量甩靶"

锁定链路时间线：

```
扫描速度 = 3700 × 0.35 ≈ 114°/s（patrol_speed_ratio 可配）
视觉帧率 ≈ 30fps（33ms/帧），RKNN 推理+传输延迟 ≥ 2 帧

横扫中检出目标（报告的还是 2 帧前的画面，云台已多转 7°+）
   → 切 TRACK，常规伺服第一拍指令 = 反馈位置 + 偏差/2
   → 下位机带着 114°/s 减速，制动期间云台沿原方向滑行 8~20°
   → 相机视野总共才 60~70° ⇒ 目标直接被甩出画面
   → 丢 10 帧 + 400ms 去抖（rescan_min_frames/rescan_debounce_ms）
   → 接续扫掠 → 又高速掠过 → 又甩出 ……（永远锁不死）
```

**修复 1**：锁定后前 `lock_brake_frames`（默认 1）拍不发常规伺服，改发
"反馈位置 + 实际转速 × 制动时间常数"——把减速滑行量提前算进目标位置，
云台刹停后正好停在检出时刻的视角附近，下一拍起正常收敛。

### 根因 2：像素→刻度换算是"盲标定"

旧代码 `inc = eff_px / 2` 硬编码假设"2 像素 = 1 刻度"，真实比例取决于
相机 FOV 与分辨率：

| 相机配置 | 实际 px/tick | 旧代码每帧修正量 | 后果 |
|---|---|---|---|
| 60°FOV / 640px | ~0.94 | 实际偏差的 47% | 欠修，收敛 6+ 帧（200ms+） |
| 120°广角 / 640px | ~1.88 | 实际偏差的 24% | 严重欠修，收敛 10+ 帧 |
| 25°长焦 / 640px | ~0.30 | 实际偏差的 150% | **过修，来回振荡发散** |

**修复 2**：暴露 `px_per_tick` 参数（现场标定，见 §三），换算有物理真源。
另附带修复：旧代码预瞄项 `vx × predict_gain_` 把像素直接当刻度混算，
等效提前量是名义值的 2 倍；新代码统一在像素域做预瞄后再换算，量纲严格。

### 根因 3：视觉链路延迟无补偿

`predict_gain_=0.5` 名义只提前 0.5 帧（16ms），而项目内自测链路延迟
200~300ms（曝光→推理→发布→伺服）——修正永远追着 6~9 帧前的历史位置，
车体一动/靶一走就持续滞后。

**修复 3**：新增 `vision_latency_ms`（毫秒口径），预瞄总帧数 =
`predict_gain_ + vision_latency_ms / 33.3`。

### 根因 4【附带发现】：跟踪死区 > 开火死区的逻辑矛盾

跟踪死区（默认 12px）内云台完全不动，而开火要求 `aim_err ≤ fire_dz`
（远距 3.5px）——云台会"稳稳停在死区里却永远进不了开火框"，是
"瞄上了却打不出去"的隐藏原因。

**修复 4**：构造函数自动钳位 `track_deadzone_px = min(track_deadzone_px, 开火死区下限)`，
矛盾出现时打 WARN 日志。

### 根因 5：丢帧期云台"纯冻结"，浪费边缘丢靶的重捕窗口

旧逻辑：跟踪中丢帧 1~9 帧（未达重扫条件）期间云台**完全冻结**在最后
指令上；等满 10 帧 + 400ms 去抖才接续全速扫掠。目标只是被甩出画面
边缘一点（车体晃动/伺服超调/动量残余）时：

- 冻结的 200~400ms 里目标就在视野外几度处，白白错过；
- 随后的全速扫掠（114°/s）又容易再次高速掠过 —— 表现为"**锁一下就丢**"。

**修复 5**：丢帧 ≥ `micro_search_after_frames`（默认 3）帧后启动**微找**——
按"最后偏差方向"（目标最后在画面哪一侧就往哪找；EMA 冻结值在死区内则
取最后扫描方向）低速小幅往复，行程 ±`micro_search_span_ticks`（默认 75
刻度 ≈ ±6.6°）：

- 偶发漏检（1~2 帧）不受影响：微找不启动，EMA 状态保持连续；
- 微找启动即标记 EMA 重建：重捕第一帧直接采信新偏差，不带陈旧状态；
- 找到立即恢复正常伺服；找不到不恋战（往返 2 段封顶后停在原地），
  由既有重扫去抖自然接管——**微找只填补冻结期的空白，不改任何旧语义**；
- 俯仰不动：丢靶多为水平甩出，垂直微找反而引入新扰动。

## 三、现场标定流程（一次性，约 10 分钟）

### 3.1 px_per_tick 标定（最重要）

1. 车静止，画面里放一个固定参照物（靶/胶带均可）
2. 手动模式（`/nav/manual_gimbal=1` 遥控）把云台水平转 100 刻度
   （可用 `ros2 topic echo /camemo_feedback` 读前后 Position_1 差值）
3. 量画面里参照物移动的像素数 N（截图比对）
4. `px_per_tick = N / 100`，写入 `robot.yaml`

> 没条件量像素时的估算：`px_per_tick ≈ 画面宽px / (FOV° × 11.378)`
> 例：640px / (60° × 11.378) ≈ 0.94

### 3.2 momentum_sign 方向确认（第一次锁定时看日志）

锁定诊断日志会打印：

```
[lock#1 刹车] raw=(120,-35) filt=(36,-10) fbV=(0,1295) slide=(0,155) fbP=(2432,2500)
[lock#2 伺服] raw=(-15,-30)  filt=... inc=(-8) ...
```

- **第 2 帧 `raw` 显著小于第 1 帧** → 外推方向正确，保持 `momentum_sign: 1.0`
- **第 2 帧 `raw` 反而变大 / 目标丢了** → 方向反了，改 `momentum_sign: -1.0`
  （下位机速度反馈可能不带符号，恒正；此参数就是为这种情况准备的）

### 3.3 momentum_brake_s 制动时间标定

看 `[lock#1 刹车]` 的 `fbV`（锁定瞬间的实际转速 tick/s）与第 2 帧 `raw`：

- 第 2 帧 raw 很小（< 50px）→ 0.12s 合适
- 第 2 帧 raw 仍同向偏大 → 减速比预期慢，加大到 0.15~0.20
- 第 2 帧 raw 反向偏大 → 刹过头了，减小到 0.08~0.10

### 3.4 robot.yaml 配置示例（加在 dzrknn_dataprocess 参数段）

```yaml
dzrknn_dataprocess:
  ros__parameters:
    # ===== 锁定增强（2026-10-17）=====
    momentum_comp_on: true       # 动量抑制总开关（false = 完全旧行为）
    momentum_brake_s: 0.12       # 制动时间常数，按 §3.3 标定
    momentum_sign: 1.0           # 按 §3.2 确认，反了改 -1.0
    lock_brake_frames: 1         # 刹车拍数，一般不用动
    px_per_tick: 0.94            # ★按 §3.1 实测，这是收敛速度的命门
    vision_latency_ms: 230.0     # 链路延迟实测值（视觉帧时刻戳与伺服拍时间差）
    lock_diag_frames: 8          # 收敛诊断日志帧数（0 = 关闭）
    predict_gain: 2.0            # 旧默认 0.5 太小；量纲修复后建议 2~4 起步
    # ----- 微找：丢帧早期短程回找 -----
    micro_search_on: true        # false = 旧行为（纯冻结等重扫）
    micro_search_after_frames: 3 # 丢 3 帧后启动（避开偶发漏检）
    micro_search_step_ticks: 15  # 每视觉帧推进 ~1.3°
    micro_search_span_ticks: 75  # 单方向最大 ~6.6°，覆盖边缘甩出
    micro_search_speed: 500      # 执行速度上限（刻度/s）
```

### 3.5 验证判据（一次实测）

1. 开机横幅出现两行：
   - `锁定增强(★2026-10-17): 动量抑制 已启用 ...`
   - `微找(★2026-10-17): 已启用（丢帧早期按最后偏差方向短程回找）...`
2. 扫描→锁定瞬间：日志 `[lock#1 刹车]` 有 `slide` 值（非 0）
3. `[lock#2..6 伺服]` 的 `raw` 单调缩小、无同号反向跳大 → 收敛正常
4. 锁定后遮一下相机（模拟丢靶）→ 日志出现
   `==> 短暂丢失(N 帧)，启动微找：方向 tick± 起点 ... 行程 ±75`
   → 松开后云台应在微找行程内重捕（不再需要等全速扫掠）
5. 云台现象：锁定后不再"点头"，靶稳定停在画面中心附近；边缘丢靶能快速找回
6. 站定打靶：`扫描确认目标，允许射击` → `pub_LaserShot_Command` 连贯出现

## 五、移动靶运动预测器（二期交付，target_motion_predictor.py）

### 5.1 为什么修复 5 项之后还需要它

标靶运动实测（2026-10-17 视频逐帧分析）：**匀速 0.14 m/s、单程 3.4s、
端部停 0.2s、往返周期 7.2s、行程 0.46m、无变速段**。代进瞄准链路：

| 量 | 0.5m 打击距离 | 1m 打击距离 |
|---|---|---|
| 标靶画面速度 | ~170 px/s（5.7 px/帧） | ~85 px/s（2.8 px/帧） |
| 链路延迟 0.26s 需要的提前量 | **~44 px** | ~22 px |
| C++ 差分预瞄的实际提前量（旧版量纲混算等效 1 帧） | ~6 px | ~3 px |
| 开火框 | 3.5 px | 3.5 px |

死结：差分预瞄只能提前 1 帧，稳态滞后 22~44px（开火框的 6~12 倍）——
匀速段锁不死也打不中；且**链路延迟 0.26s > 停顿时长 0.2s**，停顿窗口
物理上也不可命中。出路只有一个：**利用运动完全可预测的事实**，用运动
模型外推替代单帧差分。

### 5.2 架构（挂载式，零侵入 C++ 主干）

```
target_motion_predictor.py（车端独立 Python 节点）
  订阅：/offset_center（视觉偏差）+ /camemo_feedback（云台角）
  观测合成：θ_target = 云台角 + dx×像素转角（px_per_tick 与 C++ 共用标定真源）
  在线拟合：0.6s 长窗最小二乘估角速度（匀速段抗噪）
            5 帧短窗判停顿（延迟 ~0.17s，能追上 0.2s 端停）
            折返点滑动平均学习两端端点（≈1° 精度）
  三段式模型：匀速 → 到端 → 停 0.2s → 反向（先验来自实测数据）
  发布：/aim/lead_x（超前瞄准量 px）
        /aim/fire_ready（目标确认 + 运动模型可信）
        ——正好接在原方案预留的"两键开火"补丁接口上
```

**优雅之处**：超前瞄准后云台角速度 ≈ 靶角速度，靶在画面里相对静止——
C++ 的"画面稳定 ≤1.5px/帧"开火判据自然满足，匀速段即可开火。
停顿窗口期预测"靶将反向"（lead 指向反向）→ in_fire_zone 不满足 →
不浪费弹药（物理上本就打不中），云台提前转向下一段。

### 5.3 离线仿真验证（12 项全过，test_predictor_offline.py）

以实测参数合成三周期标靶运动流（±3px 观测噪声），stub 掉 rclpy 驱动真代码：

| 项 | 断言 | 结果 |
|---|---|---|
| T1 | 速度拟合 ≈ 真值 ±10% | 11.74 vs 11.76 °/s（误差 0.2%）✔ |
| T2 | 两端端点学习误差 < 1° | 0.02° / 0.13° ✔ |
| T3 | 匀速段超前 ≈ v×延迟×px_per_deg（69.6px） | +65.5 / -68.2 px ✔ |
| T4 | 停顿外推方向正确（反向外推） | 16/16 样本 ✔ |
| T5 | 折返外推覆盖（近端提前预瞄端点） | 8 样本 ✔ |
| T6 | fire_ready 时序（INIT 不放行/DWELL 放行/匀速后放行） | 全过 ✔ |
| T7 | 折返计数 = 理论 6 次 | 精确 6 次 ✔ |

仿真中发现并修复的四个坑（已固化到代码注释）：
① 停顿方向判定误用速度绝对值（端点全记成同一侧）
② 长窗判停顿迟滞 0.6s 追不上 0.2s 停顿 → 独立 5 帧短窗
③ 失速阈值 0.3°/s 压不住短窗噪声斜率 ±1°/s（端点被污染）→ 2.0°/s
④ DWELL 记账后起步瞬间兜底重复计数（12 vs 理论 6）→ 记账后清零符号速度

### 5.4 部署与 C++ 联动（robot.yaml 关键配置）

```yaml
dzrknn_dataprocess:
  ros__parameters:
    # ---- 两键开火（预测器输出才生效）----
    use_external_fire_gate: true    # fire_gate(MissionTask) + fire_ready(预测器) 双钥匙
    lead_apply_gain: 0.6            # 先 0.6 看命中分布，稳了升 1.0
    # ---- ★预测器接管后，C++ 差分预瞄必须归零（防双重补偿过冲）----
    predict_gain: 0.0
    vision_latency_ms: 0.0

target_motion_predictor:
  ros__parameters:
    enable: true
    px_per_tick: 0.94               # 与 C++ 同一标定值（§3.1 流程）
    latency_ms: 260.0               # 全链路延迟（含 EMA 拖尾与伺服拍）
    dwell_s: 0.20                   # 实测端停先验
    stall_v_deg_s: 2.0              # 失速阈值（>噪声斜率 ~1°/s，<< 真速度 ~12°/s）
```

车上启动：`python3 target_motion_predictor.py`（需已 source ROS2 环境）。

### 5.5 现场验证判据（一次实测）

1. 启动横幅：`预测器启动: enable=True px/tick=... latency=260ms dwell先验=0.2s`
2. 锁定靶后 ~3.6s 出第一条 `[折返] 端点=...° 半周期实测=3.6x s（先验 3.6s）`
3. `[状态]` 日志：`v=±12°/s v_px≈280px/s`（速度合理），`ready=1`
4. 云台现象：匀速段云台**匀速同向转动**（相对画面静止），不再"点头追不上"
5. 弹着：匀速段命中（超前瞄准生效），端停段不开火（物理不可中，省弹药）

### 5.6 回退

预测器：`enable=false` 或停节点；C++：`use_external_fire_gate: false`
即回旧的画面静止判据 + `predict_gain/vision_latency_ms` 恢复原值。
