## 三、dznav 架构与五项拔高点

新包 `src/dznav/`（纯 Python，无需 colcon，六模块）：
`contract`（场地/契约常量）→ `servo`（舵机-曲率模型）→ `refpath`（参考路径）→
`pursuit`（跟踪控制器）→ `fusion`（定位融合）→ `executor_node`（ROS 节点）。

| # | 原版机制（发学员/legacy） | dznav 机制 | 收益 |
|---|---|---|---|
| 1 | 直道/弯道**模式机** + 开环满舵弧 + 弯后**硬吸附** | 曲率受限**圆角 fillet + 全程闭环**：曲率前馈（含左右不对称舵机档案）+ Stanley 型反馈 + 前窗曲率限速；>125° 掉头弯才回落 ARC 机动（原机制收编为兜底） | 弯道精度与直道统一，无模式切换毛刺 |
| 2 | 终点朝向 = **回退插点**（图缘钳位 → PIVOT 过冲 → 出图越界急停，SIL xfail） | **顶点 ARC 机动 + 图缘可行性预检**，不可行保持朝向收车并告警 | xfail 主证明场景通过（见下） |
| 3 | serial_reader 与 executor **双节点 reset 语义分裂**（画圆双重误差的结构性根因） | 融合+控制**单节点单状态**；锚点**软校准**替代硬吸附，锚点残差喂给编码器尺度/航向偏差**自学习器**（一趟路线自校准） | 画圆机理结构上不存在；系统漂移被估计掉 |
| 4 | 到点半径 15.7cm > 排雷触发半径 6cm（雷格到点可能不判分） | 收紧至 **12cm**；雷格走途经语义（SIL 实证 8 雷格全过心 ≤6cm） | 排雷判分可靠性 |
| 5 | 目标在身后 → 纯追踪几何死角 → 越界急停兜底 | **REBUILD** 直连重建 + 首段身后**对齐弧**，出界前自救；重建限 3 次 | 消灭"越开越远"失败形态 |

**契约完全兼容**（ag_integrate / track_diag / dzactuator 零改动）：
`/nav/waypoint` 语法（reset:/load:/路线串/`*` 射击格）、`pursuitAngle`（舵机角制，BEST_EFFORT）、
`/odom/localization`（格单位，yaw+π/2=地图航向）、`/move_base/stop_signal`、`/shoot_count`。
额外改进：待命静默（无路线不发保活）——align 不再受"启动即钉死模式2"约束，两阶段启动不再是硬前提。

## 四、SIL 量化验证（同底盘/同协议/同理想传感器，发学员真码对照）

| 指标 | dznav | 发学员基线 |
|---|---|---|
| S 弯（净起步，R/L/R/R/L 五弯）RMS / 峰值 | **3.2cm / 9.4cm** | 6.4cm / 15.3cm |
| 雷格过心（8 个直段雷，判分半径 6cm） | **全部 ≤6cm** | — |
| 主证明场景（N10 起步 68.6° 偏差→align→E9* 停站→N11,x 图缘终点） | **到点、真值不出图、射击停站全流程** | 现役版：出图 1.7m+ → 越界急停（docs/SIL发现-PIVOT过冲） |
| 主路线（斜线+直角+135° 掉头混合）RMS / 峰值 | 18.2 / 37.2cm | 21.1 / 52.5cm |

注：主路线数字被 align 弧线漂移主导（68.6° 物理旋转弧长 ≈0.27m，legacy 同场景历史口径 0.26m）——
reset 应断言**无人机观测格**而非固定起点格，属任务协议层待优化项。
净起步场景（无漂移污染）才是控制架构的净度量。

## 五、调试实锤的三个设计缺陷（已修复并固化进测试/注释）

1. **锚点目标误用格心顶点**：fillet 弧对顶点有设计内偏差（R≈0.27m 时 ~12cm），
   锚顶点逐弯注入信念误差——实测 5 弯累积 **0.4m**。修正：锚到"路径上该弧长处的点"。
2. **航向锚被跟踪滞后污染**：弯中航向残差混有控制误差（非传感器偏差），
   高增益航向锚（blend 0.6）会把滞后"学"进信念航向。修正：位置/航向分离增益
   （0.5/0.25）+ **延迟锚点**（出弯 +0.35m 收敛区再锚）。
3. **过期锚点 × ARC 航向不连续区**：射击停站/ARC 机动使进度冻结后一次跳过锚点目标，
   过期目标恰落在 ARC 顶点（入腿/出腿方向跳变区）——实测注入 **−33° 假航向修正**，
   导致真值发散 1.4m。修正：新鲜度窗口（跳过 >0.2m 丢弃）+ 目标避开 ARC 顶点 ±0.35m。
4. （测试基建）SIL 用例必须 teardown `BUS.disable()+SIM.disable()`，
   否则 SIM 时钟冻结污染后续测试的 FakeClock（曾致 test_integrate_node align 超时假失败）。
